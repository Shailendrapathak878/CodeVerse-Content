Introduction to File Handling

📌 What is File Handling?

File handling refers to the mechanisms and functions provided by Python to create, open, read, modify, append, and close persistent files stored on secondary storage (such as a Hard Disk Drive or SSD).

Whenever your Python program executes, all standard variables, lists, and dictionaries reside inside RAM (Random Access Memory). RAM is volatile: the exact microsecond your script finishes or the computer reboots, every variable in memory is completely lost.

📝 Volatile Variables (Sticky Note)

Variables like score = 95 exist only while the program is running. When the process exits, that memory is freed by the operating system.

📚 Persistent Storage (Notebook)

Files like records.txt or database.json retain their data indefinitely on disk, allowing future script runs to reload state seamlessly.

Real-World Use Cases of Persistent Files:

  • Student Records & Academic Scores: Storing roll numbers, course registrations, and grade transcripts across semesters.
  • Audit & Server Logs: Recording user logins, API response latency, and system error events for diagnostic debugging.
  • E-Commerce Inventories: Tracking warehouse stock counts, product SKUs, and transaction ledgers.
  • Application Configurations: Storing API tokens, database connection URLs, and UI preference settings (e.g., config.json).
📄 Text Files vs. Binary Files

At the operating-system level, files fall into two fundamental categories:

  • Text Files (.txt, .csv, .json, .py): Sequences of human-readable characters mapped using an encoding like UTF-8. Lines end with standard line delimiters (\n or \r\n).
  • Binary Files (.png, .jpg, .pdf, .exe, .bin): Raw streams of raw bytes (0 to 255) designed for application interpreters rather than direct text viewing.

Understanding File Paths

A file path is the unique string address that tells the operating system where a file or directory lives within the disk storage tree.

🗺️ Absolute Path

The complete, full route starting from the filesystem root:

Windows: C:\Projects\app\data.txt
Linux/macOS: /home/user/app/data.txt
📍 Relative Path

A path relative to the Current Working Directory (CWD) from where the Python script was launched:

data/students.txt
../config/settings.json
⚠️ The Windows Backslash & Escape Character Trap

In Windows, file paths use backslashes (\). However, inside Python string literals, backslash acts as an escape character (e.g., \n is newline, \t is tab). Writing "C:\notes\test.txt" causes Python to interpret \n and \t as special formatting commands!

Two safe solutions:

  1. Use raw strings: r"C:\notes\test.txt"
  2. Use standard forward slashes (Python translates them automatically): "C:/notes/test.txt"
🚀 The Modern Standard: Cross-Platform pathlib.Path

Python 3 introduces the built-in pathlib module, which handles path concatenation, slashes, parent directories, and file checks cleanly across Windows, macOS, and Linux:

PYTHON: Modern Path Inspection with pathlib
from pathlib import Path

# Portable path composition using the slash (/) operator
file_path = Path("data") / "students.txt"

print("File name    :", file_path.name)
print("File suffix  :", file_path.suffix)
print("Parent folder:", file_path.parent)
print("Path exists? :", file_path.exists())
print("Is a file?   :", file_path.is_file())
► OUTPUT (Running in a project folder containing data/students.txt)
File name : students.txt File suffix : .txt Parent folder: data Path exists? : True Is a file? : True

Opening and Closing Files

To access any file in Python, you invoke the built-in open() function. It requests an operating-system file descriptor and returns a file object (also called a stream).

📝 Anatomy of the open() Function
file_object = open(file, mode="r", encoding=None)
  • file: A string path or Path object pointing to target file.
  • mode: A string specifying what operations you want to perform (e.g. "r" for read, "w" for write). Defaults to "r".
  • encoding: The character encoding standard (e.g. "utf-8"). Always specify UTF-8 explicitly for text files!
PYTHON: Manual File Open and Close
# 1. Open file for writing
file = open("sample.txt", "w", encoding="utf-8")

# 2. Write text content
file.write("CodeVerse File Handling Tutorial\n")

# 3. Explicitly close the file to flush buffer to disk
file.close()

print("File created and closed successfully.")
► OUTPUT
File created and closed successfully.
⚠️ Why Closing Files Matters Critically
  • Unflushed Buffers: Python holds writes in an internal memory buffer for performance. If you forget to close and the program halts abruptly, data in the buffer may never be written to disk.
  • Resource Leaks: Operating systems limit the number of open file handles any single process may hold (often 1024). Leaving files open in loops will eventually cause OSError: Too many open files.
  • Windows File Locking: On Windows, an open file cannot be renamed, moved, or deleted by other processes until closed.

Reading Files Thoroughly

Consider a text file named courses.txt with exactly three lines:

Python Core Data Structures Web Development

Python provides four distinct techniques for reading file contents:

📄 1. read() and read(size)

read() slurps the entire file into memory as one single string. Passing an integer read(size) reads up to size characters. 

with open("courses.txt", "r", encoding="utf-8") as f:
    chunk = f.read(6)       # Reads first 6 characters
    remaining = f.read()     # Reads remainder of file
print("Chunk    :", repr(chunk))
print("Remaining:", repr(remaining))
► OUTPUT
Chunk : 'Python' Remaining: ' Core\nData Structures\nWeb Development'
📄 2. readline()

Reads characters until it encounters a newline (\n), returning that single line including the trailing \n. Returns an empty string "" when End of File (EOF) is reached. 

with open("courses.txt", "r", encoding="utf-8") as f:
    line1 = f.readline()
    line2 = f.readline()
print("Line 1:", repr(line1))
print("Line 2:", repr(line2))
► OUTPUT
Line 1: 'Python Core\n' Line 2: 'Data Structures\n'
📄 3. readlines()

Reads the entire file into a Python list of strings, where each element corresponds to one line. 

with open("courses.txt", "r", encoding="utf-8") as f:
    all_lines = f.readlines()
print("List of lines:", all_lines)
print("Total lines  :", len(all_lines))
► OUTPUT
List of lines: ['Python Core\n', 'Data Structures\n', 'Web Development'] Total lines : 3
✅ 4. Iterating Line-by-Line (The Gold Standard for Large Files)

Instead of loading 10 gigabytes into RAM at once with read() or readlines(), iterating over the file object directly processes one line at a time on demand. Memory consumption remains virtually constant regardless of file size! 

with open("courses.txt", "r", encoding="utf-8") as f:
    for line_no, line in enumerate(f, start=1):
        # Strip trailing newline so print() doesn't add double blank lines
        clean_text = line.rstrip("\r\n")
        print(f"{line_no}: {clean_text}")
► OUTPUT
1: Python Core 2: Data Structures 3: Web Development

Writing and Appending to Files

Python provides two main methods to stream data onto disk:

✏️ write(string)

Writes a single string to the file stream. Returns the exact number of characters written. It does not append a newline automatically!

📝 writelines(iterable)

Accepts a sequence (e.g., list or tuple of strings) and writes them sequentially. It does not add newlines between elements automatically.

PYTHON: Writing and Appending Demo
# Part 1: Writing a fresh file with write() and writelines()
languages = ["Python\n", "Java\n", "C++\n"]

with open("languages.txt", "w", encoding="utf-8") as f:
    chars_written = f.write("# Top Programming Languages\n")
    f.writelines(languages)
    print(f"Header wrote {chars_written} characters.")

# Part 2: Appending a new line with mode "a"
with open("languages.txt", "a", encoding="utf-8") as f:
    f.write("Rust\n")

# Verification: Read back and display
with open("languages.txt", "r", encoding="utf-8") as f:
    print("\n--- Final File Content ---")
    print(f.read().strip())
► OUTPUT
Header wrote 29 characters. --- Final File Content --- # Top Programming Languages Python Java C++ Rust

The with Statement and Context Managers

👑 What is a Context Manager?

A context manager is a Python construct that automatically allocates a resource upon entering a code block (via __enter__) and guarantees release of that resource upon leaving the block (via __exit__), even if an unexpected exception occurs inside the block!

❌ Manual Open/Close Anti-Pattern
f = open("data.txt", "w")
f.write("Score: " + 100) # TypeError!
f.close() # NEVER EXECUTES! File leak!
✅ Pythonic with Statement
with open("data.txt", "w") as f:
    f.write("Score: " + 100) # TypeError!
# File is GUARANTEED closed automatically!
Context Manager Lifecycle Flow
with open(...) as f:
Calls __enter__()
→
Execute Block Body
Read / Write Operations
→
Block Ends or Exception
Calls __exit__()
→
File Closed Automatically
Safe & Clean!

File Pointer and File Position (tell & seek)

Every open file object maintains an internal cursor called the file pointer. When you read 10 characters, the pointer advances 10 bytes forward.

  • file.tell(): Returns an integer indicating the current byte position of the file pointer.
  • file.seek(offset, whence=0): Repositions the file pointer to a new byte offset. Setting file.seek(0) rewinds back to the very start of the file.
PYTHON: Demonstrating tell() and seek()
# Create a sample text file
with open("alphabet.txt", "w", encoding="utf-8") as f:
    f.write("ABCDEFGHIJ")

# Inspect pointer movement
with open("alphabet.txt", "r", encoding="utf-8") as f:
    print("Initial pointer :", f.tell())
    print("Read 3 chars    :", f.read(3))
    print("Pointer now at  :", f.tell())
    print("Read next 3     :", f.read(3))
    print("Pointer now at  :", f.tell())
    
    # Rewind back to the beginning
    f.seek(0)
    print("After seek(0)   :", f.tell())
    print("Read 3 again    :", f.read(3))
► OUTPUT
Initial pointer : 0 Read 3 chars : ABC Pointer now at : 3 Read next 3 : DEF Pointer now at : 6 After seek(0) : 0 Read 3 again : ABC
☝ Text Mode Offset Warning

In Python text mode, positions returned by tell() are opaque byte offsets rather than character indexes. Because multi-byte encodings (such as UTF-8) use between 1 and 4 bytes per character, never perform arbitrary math on text offsets (e.g., seek(tell() - 2)) — you may land in the middle of a multi-byte sequence and raise a UnicodeDecodeError! Always seek to 0 or to a value previously returned by tell().

Exception Handling in File Operations

Filesystem operations interact directly with hardware and OS permissions. Never assume a file is available!

⚠️ Common File Exceptions Hierarchy
  • FileNotFoundError: File or directory does not exist.
  • PermissionError: Lacking read/write permissions or file is locked by another OS process.
  • IsADirectoryError: Attempted to open a directory as if it were a flat file.
  • FileExistsError: Raised in mode "x" when target already exists.
  • UnicodeDecodeError: Bytes on disk could not be converted using the specified encoding.
  • OSError: The base class for all file and system-level I/O errors.
PYTHON: Robust try-except-else-finally File Handling
def safe_read_file(filename):
    try:
        with open(filename, "r", encoding="utf-8") as f:
            content = f.read()
    except FileNotFoundError:
        print(f"❌ Error: The file '{filename}' was not found on disk.")
    except PermissionError:
        print(f"🔒 Error: Access denied for '{filename}'.")
    except UnicodeDecodeError:
        print(f"⚠️ Error: Could not decode '{filename}' using UTF-8.")
    else:
        print(f"✅ Successfully read {len(content)} characters:")
        print(content)
    finally:
        print("• File operation attempt finished.")

# Test with a nonexistent file
safe_read_file("nonexistent_archive.txt")
► OUTPUT
❌ Error: The file 'nonexistent_archive.txt' was not found on disk. • File operation attempt finished.

Working with File Encodings & UTF-8

🌐 What is Character Encoding?

Computers store only binary bits (0s and 1s). An encoding is a lookup table that maps characters to bytes. UTF-8 (Unicode Transformation Format - 8 bit) is the universal worldwide standard capable of encoding all 150,000+ characters from every human language, math symbols, and emojis.

⚠️ Why Omitting encoding="utf-8" Breaks Windows Programs

When you don't specify encoding, Python falls back to the operating system's default locale. On Linux and macOS, this is almost always UTF-8. On Windows, it often defaults to legacy Windows-1252 (CP1252) or CP936! If your file contains international text (e.g. Hindi, Tamil, Japanese, or emojis), opening it on Windows without encoding="utf-8" triggers an immediate crash: UnicodeDecodeError: 'charmap' codec can't decode byte...

PYTHON: Reading and Writing Bilingual (English + Hindi) Text
# Bilingual string containing English, Hindi, and an Emoji
bilingual_text = "Welcome to CodeVerse • कोडवर्स में आपका स्वागत है 🚀\n"

# Save with explicit UTF-8 encoding
with open("bilingual.txt", "w", encoding="utf-8") as f:
    f.write(bilingual_text)

# Read back with explicit UTF-8 encoding
with open("bilingual.txt", "r", encoding="utf-8") as f:
    loaded = f.read()

print(loaded.strip())
► OUTPUT
Welcome to CodeVerse • कोडवर्स में आपका स्वागत है 🚀

Understanding CSV (Comma-Separated Values)

📊 What is CSV?

A CSV (Comma-Separated Values) file is a plain text file that represents a two-dimensional grid of rows and columns. Each row is a single line, and fields within that row are separated by a delimiter (commonly a comma ,). The first row typically acts as the header.

Consider this sample file named students.csv:

name,age,branch,marks Aman,20,CSE,85 Riya,19,AI,92 Neha,20,CSE,78
⚠️ The split(",") Anti-Pattern

Beginners often try to parse CSV using line.split(","). This breaks the moment a field contains commas enclosed in quotes, such as "Sharma, Aman",20,CSE,85. Using line.split(",") splits the student's name into two invalid tokens! Always use Python's built-in csv module, which correctly implements RFC 4180 quoting rules.

14

Reading CSV with csv.reader & DictReader

The csv module provides two primary readers: csv.reader() (returns lists) and csv.DictReader() (returns dictionaries).

☝ The newline="" Parameter Requirement

Whenever opening CSV files for reading or writing in Python, always specify newline="". This informs Python's universal newline parser to let the csv module control row terminators directly, preventing phantom blank lines from appearing on Windows systems.

PYTHON: Reading CSV with csv.DictReader
import csv

# Reading students.csv using DictReader
with open("students.csv", "r", newline="", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    print("Header fields:", reader.fieldnames)
    
    for row in reader:
        # Note: CSV values are strings; explicit type casting is mandatory for math!
        name = row["name"]
        marks = int(row["marks"])
        print(f"Student: {name:<6} | Marks: {marks}")
► OUTPUT
Header fields: ['name', 'age', 'branch', 'marks'] Student: Aman | Marks: 85 Student: Riya | Marks: 92 Student: Neha | Marks: 78

Writing CSV with csv.writer & DictWriter

To output tabular records, use csv.DictWriter, which maps Python dictionaries cleanly to designated column headers.

PYTHON: Writing and Appending CSV with DictWriter
import csv

fieldnames = ["id", "product", "price", "stock"]
inventory = [
    {"id": 101, "product": "Keyboard", "price": 1200, "stock": 15},
    {"id": 102, "product": "Mouse, Wireless", "price": 650, "stock": 30}
]

# 1. Write headers and records
with open("inventory.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()
    writer.writerows(inventory)

# 2. Append a new record safely without writing header again
new_item = {"id": 103, "product": "Monitor", "price": 8500, "stock": 8}
with open("inventory.csv", "a", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writerow(new_item)

# 3. Read back raw file to observe auto-quoting
with open("inventory.csv", "r", encoding="utf-8") as f:
    print(f.read().strip())
► OUTPUT (Notice automatic quoting around 'Mouse, Wireless')
id,product,price,stock 101,Keyboard,1200,15 102,"Mouse, Wireless",650,30 103,Monitor,8500,8

CSV Data Analysis Mini Example

Let's build a practical analysis script that reads academic results from CSV, validates numeric marks, and generates descriptive statistics:

PYTHON: Complete CSV Statistical Analyzer
import csv

def analyze_marks(csv_filepath):
    total_marks = 0
    count = 0
    highest = ("", float("-inf"))
    lowest = ("", float("inf"))

    with open(csv_filepath, "r", newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        for row in reader:
            try:
                mark = float(row["marks"])
            except (ValueError, KeyError):
                continue  # skip malformed row
            
            name = row.get("name", "Unknown")
            total_marks += mark
            count += 1
            
            if mark > highest[1]: highest = (name, mark)
            if mark < lowest[1]:  lowest = (name, mark)

    if count == 0:
        print("No valid student records found.")
        return

    average = round(total_marks / count, 2)
    print("=== Academic Performance Summary ===")
    print(f"Total Students Evaluated: {count}")
    print(f"Class Average Score    : {average}%")
    print(f"Highest Marks Achieved : {highest[1]} (by {highest[0]})")
    print(f"Lowest Marks Recorded  : {lowest[1]} (by {lowest[0]})")

analyze_marks("students.csv")
► OUTPUT
=== Academic Performance Summary === Total Students Evaluated: 3 Class Average Score : 85.0% Highest Marks Achieved : 92.0 (by Riya) Lowest Marks Recorded : 78.0 (by Neha)

⚠️ Why Appending to a JSON File Fails

A valid JSON file must contain exactly one root object or array. If you open a JSON file in mode "a" and dump another dictionary, the file becomes {...}{...}. This is syntax error for any standard JSON parser! To add records, you must load the existing list, append to the Python list, and re-dump the entire list using mode "w".

Handling JSON Errors and Data Validation

Always anticipate malformed JSON from external web APIs or manual user edits:

PYTHON: Safe JSON Parsing with Validation
import json

malformed_raw_json = '{ "name": "Aman", "score": 90, }'  # illegal trailing comma

def parse_and_validate_user(json_string):
    try:
        payload = json.loads(json_string)
    except json.JSONDecodeError as err:
        print(f"❌ JSON Syntax Error at line {err.lineno}, col {err.colno}: {err.msg}")
        return None

    # Schema Validation: check required keys
    required_keys = ["name", "score"]
    missing = [k for k in required_keys if k not in payload]
    if missing:
        print(f"⚠️ Missing required fields: {missing}")
        return None

    return payload

result = parse_and_validate_user(malformed_raw_json)
print("Validated Payload:", result)
► OUTPUT
❌ JSON Syntax Error at line 1, col 30: Expecting property name enclosed in double quotes Validated Payload: None

Binary File Handling (rb, wb)

💻 What is Binary Mode?

In binary mode ("rb", "wb", "ab"), Python reads and writes raw bytes objects instead of str strings. No character decoding or newline translation occurs.

PYTHON: Writing and Reading Raw Binary Bytes
# Bytes literal denoted by the b prefix
binary_payload = b"Python\x00\xFF\x42"

# 1. Write raw bytes
with open("sample.bin", "wb") as f:
    f.write(binary_payload)

import csv
import json
from pathlib import Path

def process_student_data(csv_path, txt_out, json_out):
    csv_file = Path(csv_path)
    txt_file = Path(txt_out)
    json_file = Path(json_out)
    
    # Ensure destination folders exist
    txt_file.parent.mkdir(parents=True, exist_ok=True)
    json_file.parent.mkdir(parents=True, exist_ok=True)
    
    students = []
    with open(csv_file, "r", newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        for row in reader:
            try:
                m = float(row["math"])
                s = float(row["science"])
                e = float(row["english"])
            except ValueError:
                continue
            
            avg = round((m + s + e) / 3, 2)
            students.append({
                "roll": row["roll_no"],
                "name": row["name"],
                "dept": row["department"],
                "average": avg
            })

    if not students:
        print("No valid student records found.")
        return

    class_avg = round(sum(s["average"] for s in students) / len(students), 2)
    top_student = max(students, key=lambda x: x["average"])
    low_student = min(students, key=lambda x: x["average"])

    # 1. Generate Formatted TXT Report
    with open(txt_file, "w", encoding="utf-8") as f:
        f.write("=" * 44 + "\n")
        f.write("      CODEVERSE ACADEMIC PERFORMANCE REPORT\n")
        f.write("=" * 44 + "\n")
        f.write(f"Total Students : {len(students)}\n")
        f.write(f"Batch Average  : {class_avg}%\n")
        f.write(f"Top Performer  : {top_student['name']} ({top_student['average']}%)\n")
        f.write(f"Lowest Score   : {low_student['name']} ({low_student['average']}%)\n")
        f.write("-" * 44 + "\n")
        for s in students:
            f.write(f"[{s['roll']}] {s['name']:<14} | {s['dept']:<4} | Avg: {s['average']}%\n")
        f.write("=" * 44 + "\n")

    # 2. Generate Structured JSON Metrics
    metrics_payload = {
        "batch_size": len(students),
        "batch_average": class_avg,
        "top_student": top_student,
        "lowest_student": low_student,
        "records": students
    }
    with open(json_file, "w", encoding="utf-8") as f:
        json.dump(metrics_payload, f, indent=2, ensure_ascii=False)

    print("✅ Academic report generated at:", txt_file.name)
    print("✅ Class metrics exported at    :", json_file.name)

process_student_data(
    "data/students_input.csv",
    "output/academic_report.txt",
    "output/class_metrics.json"
)

  1. Always wrap file I/O inside a with context manager block.
  2. Always pass explicit encoding="utf-8" for text operations.

15 Practice Questions & Detailed Solutions

Test your understanding. Expand each card to view verified answers and code solutions:

Q1 (Beginner): What is the difference between file mode "w" and mode "a"?

Answer: Mode "w" (write) immediately truncates (erases) all existing content in the file or creates a new file if it doesn't exist. Mode "a" (append) preserves existing content, sets the file pointer to the very end of the file, and writes all new data after existing content.

Q2 (Beginner): Why is the with statement preferred over manually calling file.close()?

Answer: The with statement implements the context manager protocol. It guarantees that file.close() is called automatically when leaving the block, even if an unexpected exception (such as ValueError or TypeError) crashes the code inside the block.

Q3 (Beginner): What value does file.readline() return when it reaches the End of File (EOF)?

Answer: An empty string "". (Note that a blank line in a file returns "\n", not an empty string).

Q4 (Beginner): What parameter should always be added when opening CSV files in Python, and why?

Answer: newline="". It prevents Python's universal newline parser from inserting unintended blank rows between records on Windows systems.

Q5 (Beginner): What is the difference between json.load() and json.loads()?

Answer: json.load(file_object) reads directly from an open disk file stream. json.loads(json_string) parses an in-memory Python string containing JSON text (the s in loads stands for String).

Q6 (Intermediate): Why does file.writelines(["Apples", "Bananas"]) write "ApplesBananas" on a single line?

Answer: Unlike print(), writelines() does not append newline characters automatically between items. You must explicitly include \n in each string, e.g., ["Apples\n", "Bananas\n"].

Q7 (Intermediate): How does iterating over a file (for line in f:) conserve memory compared to f.readlines()?

Answer: f.readlines() reads the entire file into RAM at once as a list of strings, which can exhaust memory on multi-gigabyte files. Iterating over f uses an internal buffer to yield one line at a time on demand, maintaining low and constant memory usage.

Q8 (Intermediate): What happens if you try to open a missing file in mode "r" vs mode "w"?

Answer: Mode "r" raises a FileNotFoundError exception. Mode "w" automatically creates a new empty file with that filename on disk.

Q9 (Intermediate): Why does appending to a JSON file with mode "a" produce invalid JSON?

Answer: Valid JSON requires a single root value (an object {...} or array [...]). Appending another object results in {...}{...}, which standard JSON parsers cannot parse. To add items, you must read the list, append the item in Python, and write back with mode "w".

Q10 (Intermediate): Write a Python snippet to safely verify if a file exists before attempting to open it. 
from pathlib import Path
p = Path("report.txt")
if p.is_file():
    with open(p, "r", encoding="utf-8") as f:
        print(f.read())
else:
    print("File does not exist!")
Q11 (Intermediate): What does ensure_ascii=False do in json.dump()?

Answer: By default, ensure_ascii=True escapes non-ASCII characters into Unicode sequences (e.g., \u0928\u092e...). Setting ensure_ascii=False writes the actual characters (such as Hindi, Arabic, or emojis) natively into the file as UTF-8.

Q12 (Challenge): What is the result of executing f.seek(0) followed by f.readline()?

Answer: f.seek(0) rewinds the file pointer back to the first byte of the file. Calling f.readline() immediately reads and returns the first line of the file, regardless of where the pointer was previously positioned.

Q13 (Challenge): How do you handle a CSV file where numeric marks contain missing or invalid string entries? 
import csv
valid_marks = []
with open("data.csv", "r", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        try:
            valid_marks.append(float(row["marks"]))
        except (ValueError, TypeError):
            continue  # skip corrupt entries safely
print("Valid entries:", len(valid_marks))
Q14 (Challenge): Explain the difference between text mode ("rt") and binary mode ("rb").

Answer: In text mode, Python decodes bytes into Python str objects using a character encoding (like UTF-8) and automatically translates platform newline characters (e.g. converting \r\n to \n). In binary mode, Python deals strictly with raw bytes (0-255), without performing character decoding or newline manipulation.

Q15 (Challenge): How can you safely update a single setting inside a config.json file without losing other keys?

    config = json.load(f)

# 3. Write back entire dictionary
