Introduction to Modules

📊 Figure 12.1: Python Code Organization Hierarchy
Python scales code organization through four nesting tiers: individual functions/classes live inside module files (`.py`), multiple modules assemble into packages (directories with `__init__.py`), and packages package into distributable libraries published on PyPI.
Visual Summary & Trace:

A module is simply a single Python file ending in .py that contains reusable definitions, functions, variables, and runnable statements. The name of the file (excluding the .py extension) becomes the module's name inside Python.

What is a Package?

📦 What is a Python Package?

A package is a directory containing multiple related Python module files. It establishes a hierarchical, dot-separated module namespace (e.g., mathematics.arithmetic) so module names from different libraries never collide.

Package Directory Structure:

my_project/ ├── main.py └── mathematics/ ├── __init__.py ├── arithmetic.py └── geometry.py

Role of Each Component:

  • main.py: Application entry point that imports and coordinates the package.
  • mathematics/: The package folder grouping math modules together.
  • __init__.py: Marks the directory as a regular Python package and can execute initialization code.
  • arithmetic.py: Submodule containing basic arithmetic helpers.
  • geometry.py: Submodule containing area/perimeter logic.
💡 Modern Python Note: Namespace Packages

In modern Python (3.3+), directories without an __init__.py can act as namespace packages spread across multiple directories. However, including __init__.py remains the standard, explicit convention for regular application packages.

Importing Modules: The 5 Core Styles

📊 Figure 12.2: The 5 Core Python Import Syntaxes Comparison
Python supports modular imports via five syntaxes. Qualified `import module` and targeted `from module import func` are recommended by PEP 8, while wildcard `from module import *` is discouraged because it clutters the local namespace.
Visual Summary & Trace:
Import Variations: 1. import mod → 2. import mod as m → 3. from mod import func → 4. from mod import func as f → 5. from mod import * (discouraged).

Python offers five distinct syntax patterns to bring external functionality into your script:

📍 Style A: Import the Complete Module

Keeps the imported module in its own namespace. Access functions using module.function().

PYTHON • COMPLETE MODULE IMPORT
import math

print("Square root of 25:", math.sqrt(25))
print("Value of pi       :", round(math.pi, 4))
► OUTPUT
Square root of 25: 5.0 Value of pi : 3.1416
📍 Style B: Import a Specific Name

Brings only the named identifier directly into your current script's namespace.

PYTHON • SPECIFIC NAME IMPORT
from math import sqrt

# Call sqrt directly without 'math.' prefix!
print("Square root of 36:", sqrt(36))
► OUTPUT
Square root of 36: 6.0
📍 Style C: Import Multiple Specific Names
PYTHON • MULTIPLE NAMES IMPORT
from math import sqrt, factorial

print("sqrt(49)  :", sqrt(49))
print("5!        :", factorial(5))
► OUTPUT
sqrt(49) : 7.0 5! : 120
📍 Style D: Import Module with an Alias (as)

Shortens lengthy module names for clean, readable code (common with data libraries).

PYTHON • MODULE ALIAS
import math as m

print("sqrt(64) via alias m:", m.sqrt(64))
► OUTPUT
sqrt(64) via alias m: 8.0
📍 Style E: Import Specific Name with an Alias

Renames a specific imported function to prevent naming conflicts with local functions.

PYTHON • FUNCTION ALIAS
from math import factorial as fact

print("fact(5):", fact(5))
► OUTPUT
fact(5): 120
Syntax Style How to Call Namespace Impact Best Used When
import math math.sqrt(x) Clean; only math added to local scope. General use; keeps code clear and explicit.
from math import sqrt sqrt(x) Only sqrt placed into local scope. Frequently calling one specific helper.
import math as m m.sqrt(x) Only m placed into local scope. Standard abbreviations (np, pd).
from math import * sqrt(x) Pollutes scope with hundreds of names. Avoid! Masks origins and causes collisions.

How Imports Work & Module Caching

📊 Figure 12.4: Module Import Execution Lifecycle and Bytecode Caching
Python imports each module only once per session. It checks the `sys.modules` dictionary; if absent, it compiles the `.py` source to `.pyc` in `__pycache__`, executes its top-level definitions, and records the module in `sys.modules`.
Visual Summary & Trace:
Import Lifecycle: Check sys.modules → If new, compile to __pycache__/.pyc → Execute module statements → Store in sys.modules.
⚙️ Behind the Scenes: The Import Lifecycle
  1. Check Cache (sys.modules): Python checks if the requested module was already imported earlier in the running process.
  2. Find File: If not cached, Python searches directories listed in sys.path for a matching file.
  3. Compile & Execute: Python compiles the code to bytecode (.pyc) and runs all top-level statements from top to bottom.
  4. Bind to Namespace: The resulting module object is added to sys.modules and bound to the variable name in the caller.
💡 Why Repeating Imports Does Not Re-execute Code

Because Python caches loaded modules in sys.modules, importing the same module 100 times in different functions only executes its top-level definitions once. Subsequent imports simply grab the cached reference instantly!

Creating a Custom Module

Creating your own reusable module in Python is remarkably simple: just write standard Python functions in a file and save it.

custom_module_demo/ ├── calculator.py # Module file defining functions └── main.py # Consumer file that imports calculator

# calculator.py
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

    return a * b

The __name__ Variable & Execution Guard

🔍 What is __name__?

Whenever Python executes a script, it automatically assigns a special built-in variable called __name__:

  • If the file is being run directly by the user (python script.py), Python sets __name__ = "__main__".
  • If the file is being imported by another file (import script), Python sets __name__ = "script" (its module name).
Direct Run vs Imported Execution Flow
python greetings.py
Ran directly
→
__name__ == "__main__" is True
Runs test code block
import greetings
Imported by main.py
→
__name__ == "greetings"
Skips test code; exports functions only
FILE: greetings.py • GUARD DEMONSTRATION 
# greetings.py
def say_hello(name):
    return f"Hello, {name}!"

# This block ONLY runs when running greetings.py directly!
if __name__ == "__main__":
    print("[TEST RUN] Running greetings.py standalone:")
    print(say_hello("Aman"))
► OUTPUT WHEN RUNNING DIRECTLY: python greetings.py
[TEST RUN] Running greetings.py standalone: Hello, Aman!
► OUTPUT WHEN IMPORTED IN main.py: import greetings
(Nothing printed from the guard! Only imported functions become accessible.)

Absolute vs Relative Imports

📊 Figure 12.8: Absolute vs. Explicit Relative Import Syntax
Absolute imports specify the full path from the project root (`from app.models import User`) and are preferred by PEP 8. Relative imports use leading dots (`.models` for current package, `..utils` for parent package) for internal package cohesion.
Visual Summary & Trace:
Import Paths: Absolute imports trace from project root; relative imports use dot syntax (. = current package, .. = parent package).

Inside complex multi-folder packages, you can reference sibling or parent submodules using two styles:

project/ ├── main.py └── utilities/ ├── __init__.py ├── formatting.py └── calculations.py
🌍 Absolute Imports (Recommended)

Specifies the complete path from the project root directory. Unambiguous and clear.

# From inside formatting.py:
from utilities.calculations import add
📍 Relative Imports

Uses leading dots to specify relative location within the current package.

# . = current package (utilities)
from .calculations import add
# .. = parent package
from ..common import config
⚠️ Warning: ImportError: attempted relative import with no known parent package

If you directly execute a file containing relative imports (python formatting.py), Python has no package context and throws an error! To run package modules as scripts, execute from the project root using the -m flag:

TERMINAL COMMAND
$python -m utilities.formatting

pip install requests: Run in terminal once to download and store package files on your hard drive.

Virtual Environments (venv)

🔐 Why Do We Need Virtual Environments?

Imagine Project A needs requests==2.25.0, while Project B needs requests==2.31.0. If you install packages globally on your operating system, one project will inevitably break the other!

A virtual environment creates an isolated, self-contained directory containing its own Python executable and independent site-packages folder.

🛠️ VIRTUAL ENVIRONMENT LIFECYCLE COMMANDS

# 1. Create a virtual environment named .venv

$python -m venv .venv


# 2A. Activate on Windows (PowerShell)

$.venv\Scripts\Activate.ps1


# 2B. Activate on macOS / Linux (Bash/Zsh)

$source .venv/bin/activate


# 3. Install dependencies safely inside environment

(.venv) $pip install requests


# 4. Deactivate when finished

(.venv) $deactivate

The Module Search Path (sys.path)

📊 Figure 12.3: The Module Search Path Resolution Sequence (sys.path)
When an `import` statement executes, Python searches directories in `sys.path` sequentially: current script directory first, followed by `PYTHONPATH`, standard library directories, and finally third-party `site-packages`.
Visual Summary & Trace:
Module Search Order: 1. Current Script Dir (sys.path[0]) → 2. PYTHONPATH → 3. Standard Library (Lib/) → 4. site-packages (pip / venv).

When you type import my_module, Python searches through a specific list of directories stored in sys.path in strict order:

The sys.path Search Order
1. Current Script Directory
Where running script lives
→
2. PYTHONPATH
Environment variable directories
→
3. Standard Library
Built-in Python modules
→
4. site-packages
Third-party pip packages
❌ The Deadly Module Shadowing Trap!

Because the current script directory is searched first, if you name your file math.py or random.py, Python will import your file instead of the official standard library! 

# If you save a file as 'math.py' and write:
import math
print(math.sqrt(16))  # AttributeError: module 'math' has no attribute 'sqrt'!

Fix: Never name custom scripts after standard-library modules or popular packages.

Circular Imports & Architecture Solutions

📊 Figure 12.7: Circular Import Deadlock and Architecture Solutions
Circular imports occur when module A imports B while B simultaneously imports A. Because module A is only partially initialized, B cannot find A's functions. Resolve this by extracting shared logic into a third module or importing inside functions.
Visual Summary & Trace:
Circular Imports: Module A and Module B mutually depend on each other, causing partially initialized module errors; solve by extracting shared code to a third module.
🔁 The Circular Dependency Dilemma

A circular import occurs when Module A imports Module B, but Module B also imports Module A. When Module A runs, it pauses at the import to run Module B; Module B then attempts to import Module A before Module A has finished defining its functions, raising an ImportError: cannot import name 'X' from partially initialized module.

✅ How to Fix Circular Imports
  • Extract Shared Logic: Move the common functions or models into a third independent module (e.g., models.py or common.py) that both A and B import.
  • Deferred Import (Inside Function): Place the import statement inside the specific function that needs it rather than at top-level.

Common Import Errors & Troubleshooting

Error Message Likely Root Cause How to Resolve
ModuleNotFoundError: No module named 'xyz' File name typo, package not installed, or running from wrong folder. Check spelling, verify pip install xyz in active venv, check current directory.
ImportError: cannot import name 'abc' Name doesn't exist in module, or circular import deadlock. Check function spelling in source file; refactor circular imports.
AttributeError: module 'math' has no attribute 'sqrt' Local script shadows standard library (e.g. named math.py). Rename your local file and delete any generated math.pyc / __pycache__.
ImportError: attempted relative import with no known parent package Ran a package submodule directly with python file.py. Run from root using python -m package.file or use absolute imports.

Mini Project: Student Management Package

🎓 Architecture Layout

A multi-file application separating data storage, calculation logic, and report formatting:

student_management/ ├── main.py └── student_app/ ├── __init__.py ├── records.py ├── results.py └── reports.py
FILE: student_app/records.py
# student_app/records.py
students_db = {}

def add_student(student_id, name, marks_dict):
    if student_id in students_db:
        raise ValueError(f"Student {student_id} already exists.")
    students_db[student_id] = {"name": name, "marks": marks_dict}

def get_student(student_id):
    return students_db.get(student_id)
FILE: student_app/results.py
# student_app/results.py
def compute_average(marks_dict):
    if not marks_dict:
        return 0.0
    return round(sum(marks_dict.values()) / len(marks_dict), 2)

def compute_grade(average):
    if average >= 90: return "A+"
    if average >= 80: return "A"
    if average >= 70: return "B"
    return "C"
FILE: student_app/reports.py
# student_app/reports.py
from .results import compute_average, compute_grade

def format_student_card(student_id, student_info):
    avg = compute_average(student_info["marks"])
    grade = compute_grade(avg)
    return f"[{student_id}] {student_info['name']} - Avg: {avg}% (Grade: {grade})"
FILE: student_app/__init__.py
# student_app/__init__.py
from .records import add_student, get_student
from .reports import format_student_card
FILE: main.py
# main.py
from student_app import add_student, get_student, format_student_card

add_student("S101", "Aman Sharma", {"Math": 88, "Physics": 92})
add_student("S102", "Riya Verma", {"Math": 95, "Physics": 90})

s1 = get_student("S101")
s2 = get_student("S102")

print(format_student_card("S101", s1))
print(format_student_card("S102", s2))
► TERMINAL OUTPUT
[S101] Aman Sharma - Avg: 90.0% (Grade: A+) [S102] Riya Verma - Avg: 92.5% (Grade: A+)

Q1 (Beginner): What is the difference between a module and a package in Python?

Answer: A module is a single Python source file (.py) containing functions and definitions. A package is a directory containing multiple modules and typically an __init__.py file, providing a hierarchical namespace.

Q2 (Beginner): What value does __name__ hold when a file is executed directly from the terminal?

Answer: The string "__main__".

Q3 (Beginner): Write an import statement to import only the pi constant from the math module. 
from math import pi
print(pi)  # 3.141592653589793
Q4 (Beginner): Why is writing from math import * discouraged in professional software?

Answer: It imports hundreds of names into the local namespace, which risks silently overwriting existing variables/functions and makes it impossible for developers reading the code to identify where imported functions originated.

Q5 (Beginner): Where should pip install requests be executed?

Answer: In the operating system's terminal or command prompt (PowerShell, CMD, Bash), never inside a Python script or Python interactive prompt.

Q6 (Intermediate): What happens if you name your file random.py and then type import random inside it?

Answer: Python searches the current script directory first, so it imports your file itself instead of the standard library module. When you subsequently try to call random.randint(), Python raises an AttributeError because your script lacks that attribute.

Q7 (Intermediate): How does Python avoid re-running top-level module code when a module is imported repeatedly?

Answer: Python caches every imported module in the internal dictionary sys.modules. On subsequent import statements, Python checks sys.modules first and immediately returns the cached module object without re-executing its code.

Q8 (Intermediate): What terminal command creates a virtual environment named .venv? 
python -m venv .venv
Q9 (Intermediate): What is the difference between json.dumps() and json.loads()?

Answer: json.dumps(obj) serializes a Python dictionary/list into a JSON formatted string. json.loads(s) parses a JSON string back into native Python data structures (dicts, lists, etc.).

Q10 (Intermediate): In a relative import within a package, what do . and .. represent?

Answer: A single dot . represents the current package/directory, while two dots .. represent the parent package/directory.

Q11 (Intermediate): Why does running a file with relative imports directly as python file.py fail?

Answer: When run directly as the main script, the file has no parent package context assigned (its __name__ is "__main__"). Relative imports require a defined package anchor. It must be run with python -m package.file from the root.

Q12 (Challenge): Explain what a circular import is and describe two distinct ways to resolve it.

Answer: A circular import occurs when Module A imports Module B and Module B imports Module A, causing a partially initialized import deadlock. Solutions: (1) Extract the shared classes or functions into a separate third module (e.g., common.py) that both import; (2) Move the import statement inside the specific function where it is used (deferred import).

Q13 (Challenge): How can you use collections.Counter to find the two most common elements in [1, 2, 2, 3, 3, 3]? 
from collections import Counter
counts = Counter([1, 2, 2, 3, 3, 3])
print(counts.most_common(2))  # [(3, 3), (2, 2)]
Q14 (Challenge): Write a Python snippet to print all directories that Python checks when searching for imported modules. 
import sys
for directory in sys.path:
    print(directory)
Q15 (Challenge): How does __init__.py allow developers to control what is imported when a user types from my_package import *?

Answer: Developers can define the special list variable __all__ = ["func1", "ClassA"] inside __init__.py. Only the names explicitly listed in __all__ will be exported when wildcard imports are performed.
