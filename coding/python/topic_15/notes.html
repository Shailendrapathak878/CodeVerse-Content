What Is Object-Oriented Programming?

💡 Simple Definition

Object-Oriented Programming (OOP) is a way of designing computer programs where related data (attributes) and actions (methods) are bundled together into self-contained units called objects.

Instead of thinking of code as a long grocery list of step-by-step instructions operating on scattered variables, OOP lets you model your software around real-world entities like users, bank accounts, cars, or shopping carts.

To truly understand OOP, let us break down programming fundamentals from the ground up:

  • What is a program? At its core, every program does two things: it stores data (numbers, text, lists) and runs operations (functions, loops, calculations) on that data.
  • What is a programming paradigm? A paradigm is an architectural mindset or style of organizing code. Procedural programming focuses on functions executing sequentially. Object-Oriented Programming focuses on objects that own their data and know how to manipulate it.
  • Why is it called "Object-Oriented"? Because the entire design revolves around objects that simulate real entities with properties and capabilities.
🚗 Real-Life Analogy: The Car

Consider an ordinary car on the road:

  • Data (State / Attributes): What the car has — brand = "Toyota", color = "Midnight Blue", speed = 0, fuel_level = 45.
  • Actions (Behavior / Methods): What the car does — start_engine(), accelerate(), brake(), honk().

In the real world, a car's speed and its accelerator pedal are permanently connected inside the same vehicle. You cannot press the accelerator of a Toyota and expect a Honda next to you to speed up! OOP mirrors this natural connection in software.

⚖️ Procedural Approach vs. Object-Oriented Approach

Let us write code for a car accelerating by 10 km/h in both styles to see the clear difference in structure:

procedural_car.py • Loose Variables & Function 
# Procedural Style: Data and functions live completely apart

speed = 0

    return current_speed + 10

speed = accelerate(speed)
print(brand)

▶ OUTPUT
Toyota 10
oop_car.py • Bundled Data & Method 
# Object-Oriented Style: Data and behavior are bundled inside Car
class Car:
    def __init__(self, brand):
        self.brand = brand
        self.speed = 0

    def accelerate(self):
        self.speed += 10

car = Car("Toyota")
car.accelerate()

print(car.brand)
print(car.speed)
▶ OUTPUT
Toyota 10

⚠️ Balanced Mindset: Is OOP Always Better?

No! Do not fall into the trap of believing OOP is always superior to procedural code. Python is a multi-paradigm language. For a 15-line script parsing a CSV file or running a mathematical formula, a clean procedural script with functions is often faster and simpler. OOP shines when managing complex state across dozens of cooperating entities.

What Is a Class?

📊 Figure 15.1: Class Blueprint vs. Instantiated Objects in Memory
A class is a structural template loaded once into memory containing method bytecodes and class-level attributes. Instantiation constructs independent object instances on the heap, each having its own unique memory address (`id()`) and private attribute dictionary (`__dict__`).
Visual Summary & Trace:
OOP Fundamentals: A class acts as a single blueprint; every instantiated object maintains its own distinct heap identity and state dictionary.
💡 Definition of a Class

A class is a user-defined blueprint, template, or prototype from which individual objects are created. It specifies what attributes (data) and methods (functions) any object made from it will possess.

Three classic real-life analogies to make this crystal clear:

🏠 House Blueprint vs. Actual House

An architect draws a blueprint on paper showing 3 bedrooms, 2 bathrooms, and a kitchen. You cannot sleep inside the blueprint! But construction workers can use that single blueprint to build 50 real physical houses on a street.

📝 Blank Form vs. Filled Application

A college admission form has empty fields: Name, Roll Number, Marks. That blank form is the class. When Aman and Riya fill in their personal information, each completed sheet is an object.

🔧 Python Syntax for Defining a Class

In Python, you define a class using the class keyword followed by the class name in PascalCase (also known as CapWords, per PEP 8 style guide):

class_syntax.py • Minimal Class Definition 
# An empty class using the pass keyword
class Student:
    pass

# Creating an instance of Student
s = Student()
print(s)
print(type(s))
▶ OUTPUT
<__main__.Student object at 0x7f9a1c0b3a90> <class '__main__.Student'>
💬 What is the pass keyword?

Python relies on indentation to define code blocks. A class cannot have an empty body — leaving it blank causes a SyntaxError: unexpected EOF while parsing. The pass statement acts as an intentional no-op placeholder, telling Python: "This class body exists, but has no statements yet." It is invaluable for sketching high-level architecture before writing implementation details.

What Is an Object?

💡 Definition of an Object

An object (also called an instance) is a concrete, living realization of a class allocated in computer memory. If the class is the cake recipe, the object is the delicious cake you can actually eat!

Key properties of an object:

  • State: Represented by its instance attributes (e.g., name = "Aman", marks = 85).
  • Behavior: Represented by its methods (e.g., introduce()).
  • Identity: Every object occupies a unique memory address returned by id(obj).
student_instances.py • One Class, Multiple Objects 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def introduce(self):
        print(f"My name is {self.name} and I scored {self.marks} marks.")

# Instantiate two separate objects from the same Student blueprint
student1 = Student("Aman", 85)
student2 = Student("Riya", 92)

student1.introduce()
student2.introduce()

# Inspect memory addresses
print("student1 id:", id(student1))
print("student2 id:", id(student2))
print("Are they the same object?", student1 is student2)

Constructor and __init__()

📊 Figure 15.2: Two-Phase Object Instantiation Lifecycle & self Binding
Python creates objects in two distinct steps: first, `__new__()` allocates raw heap memory and returns the uninitialized instance reference. Second, `__init__()` receives this reference as the first argument (`self`), populating instance attributes with custom values before returning control to the caller.
Visual Summary & Trace:
Instantiation Lifecycle: __new__ creates the raw memory shell; __init__ receives it as 'self' to populate its attributes.
💡 What is __init__()?

In Python, __init__() is the initializer method (commonly called the constructor). It is automatically invoked by Python the instant a new instance of a class is created. Its purpose is to give the newly born object its initial starting state (setting attributes).

Why do objects need an initializer? In real life, a baby cannot exist without a name, date of birth, or parents. Similarly, a bank account cannot exist without an account holder name and account number. __init__() guarantees that every object is born fully initialized and ready for use.

init_params.py • Constructor with Positional and Default Arguments 
class Student:
    def __init__(self, name, roll_no, course="Python"):
        self.name = name
        self.roll_no = roll_no
        self.course = course

# Using default course parameter
student1 = Student("Aman", 101)
print(student1.name)
print(student1.roll_no)
print(student1.course)

# Overriding default parameter
student2 = Student("Riya", 102, "Flutter")
print(student2.course)
▶ OUTPUT
Aman 101 Python Flutter
⚠️ What Happens If You Omit a Required Argument?

If an argument has no default value and you fail to pass it when creating an object, Python halts execution immediately with a TypeError:

>>> s = Student("Karan")
TypeError: Student.__init__() missing 1 required positional argument: 'roll_no'

This is a protective design: it prevents broken, half-formed objects from circulating in your program.

🔬 Deep Dive: __new__() vs. __init__()

Many beginners think __init__() actually creates the object. In reality, Python's object creation is a 2-step dance:

  1. __new__(cls, ...) (The Creator): This is the true constructor! It allocates raw memory on the heap and returns the empty instance. You rarely need to override __new__ unless building singletons or immutable subclasses (like subclassing tuple or int).
  2. __init__(self, ...) (The Initializer): Takes the newly created instance from __new__ and populates its attributes (assigning self.name = ...). It must always return None.

Understanding self

💡 What is self?

self represents the specific instance of the class that is currently calling the method. Through self, Python knows which object's attributes to read or update.

When you call student1.introduce(), how does Python know to print "Aman" instead of "Riya"?

Under the hood, Python automatically translates:

student1.introduce()  ↠  Student.introduce(student1)

Python passes the calling object as the very first argument! That is why every ordinary instance method in Python MUST list self as its first parameter.

self_demo.py • Explicit Instance Binding 
class Student:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        print(f"I am {self.name}, stored at memory address {hex(id(self))}")

student1 = Student("Aman")
student2 = Student("Riya")

student1.introduce()
student2.introduce()

# Prove that Student.introduce(student1) is completely identical:
Student.introduce(student1)
▶ OUTPUT
I am Aman, stored at memory address 0x7f9a1c0b3a90 I am Riya, stored at memory address 0x7f9a1c0b3b20 I am Aman, stored at memory address 0x7f9a1c0b3a90
⚠️ Critical Pitfall: self.name vs. Local name

A huge stumbling block for beginners is assuming that writing name = "New" inside a method modifies the object's attribute. It does not!

class BadExample:
    def __init__(self, name):
        self.name = name

    def update_name_wrong(self, new_name):
        name = new_name        # ERROR IN INTENT: Only creates a temporary local variable!
                               # self.name remains completely unchanged!

    def update_name_correct(self, new_name):
        self.name = new_name   # CORRECT: Explicitly targets the object attribute!

Without the self. prefix, Python treats any variable assignment as a temporary local variable that vanishes the moment the method finishes executing.

🤔 Is self a Keyword in Python?

No! self is not a reserved Python keyword (unlike this in Java, C++, or JavaScript). You could technically write def __init__(this, name): this.name = name and Python would execute it without complaint. However, PEP 8 strictly mandates using self. Any Python programmer writing anything other than self will face immediate rejection in code reviews.

The __str__() and __repr__() Methods

When you print an ordinary Python object without custom string methods, Python outputs an ugly string like: <__main__.Student object at 0x7f9a1c0b3a90>. Special methods __str__() and __repr__() let you customize exactly how your objects are displayed.

Method Target Audience Main Goal Triggered By
__str__() End users & customers Readable, friendly summary print(obj), str(obj), f-strings f"{obj}"
__repr__() Developers & maintainers Unambiguous, explicit debugging details REPL interactive output, repr(obj), logging
str_repr_demo.py • Implementing Readable String Representations 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    # User-friendly representation
    def __str__(self):
        return f"{self.name} scored {self.marks} marks"

    # Developer debugging representation
    def __repr__(self):
        return f"Student(name='{self.name}', marks={self.marks})"

student = Student("Riya", 92)

# Triggers __str__
print(student)
print(str(student))

# Triggers __repr__
print(repr(student))

💡 Professional Tip: Fallback Behavior

If a class defines __repr__() but does not define __str__(), Python automatically falls back to using __repr__() for print() calls! Therefore, if you only have time to implement one, always implement __repr__() first.

Instance Attributes

💡 Definition of Instance Attributes

An instance attribute is a variable that belongs exclusively to a single, specific object. Any changes made to one object's instance attributes have zero effect on any other object created from the same class.

Instance attributes are conventionally defined inside the __init__() method prefixed with self., and are physically stored in the object's internal dictionary: self.__dict__.

instance_attrs.py • Creation, Modification & Dynamic Assignment 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

s1 = Student("Aman", 85)
s2 = Student("Riya", 92)

# Modifying an instance attribute
s1.marks = 89
print("s1 marks:", s1.marks)
print("s2 marks (unaffected):", s2.marks)

# Dynamically adding an attribute to s1 at runtime
s1.grade = "A"
print("s1 dict:", s1.__dict__)
print("s2 dict:", s2.__dict__)
▶ OUTPUT
s1 marks: 89 s2 marks (unaffected): 92 s1 dict: {'name': 'Aman', 'marks': 89, 'grade': 'A'} s2 dict: {'name': 'Riya', 'marks': 92}
⚠️ Dynamic Attribute Warning

Notice that adding s1.grade = "A" only added grade to s1! If you attempt to access s2.grade, Python raises an AttributeError: 'Student' object has no attribute 'grade'. Dynamically tacking on attributes outside __init__ can make code unpredictable; best practice is to initialize all allowed attributes inside __init__ (setting default values to None if unknown).

Class Attributes & Shadowing

📊 Figure 15.3: Instance vs. Class Attribute Lookup & Variable Shadowing
When accessing `obj.attr`, Python first checks `obj.__dict__`. If absent, it searches `Class.__dict__`. However, assigning `obj.attr = val` always writes to `obj.__dict__`, accidentally creating an instance-level shadow that masks the shared class attribute for that specific instance.
Visual Summary & Trace:
Attribute Resolution: Reads search instance dict then class dict; writes directly to instance dict, creating a shadow.
💡 Definition of Class Attributes

A class attribute is defined directly inside the class body (outside any method). It is shared equally by all instances of that class. Modifying a class attribute on the class updates the value for all instances that look it up.

class_attrs.py • Shared Class State 
class Student:
    # Class attribute
    school_name = "CodeVerse Academy"

    def __init__(self, name):
        self.name = name

s1 = Student("Aman")
s2 = Student("Riya")

# Accessed via instances and via the class
print(s1.school_name)
print(s2.school_name)
print(Student.school_name)

# Updating class attribute via class name updates it for all!
Student.school_name = "CodeVerse Global University"
print(s1.school_name)
print(s2.school_name)
▶ OUTPUT
CodeVerse Academy CodeVerse Academy CodeVerse Academy CodeVerse Global University CodeVerse Global University
⚠️ Trap 1: The Shadowing Trap

What happens if you assign a class attribute through an instance like: s1.school_name = "Tech School"?

Python does NOT update the class attribute! Instead, it quietly creates a new instance attribute named school_name on s1 that shadows (hides) the class attribute. s2 and Student remain completely unchanged:

s1.school_name = "Private Institute"  # Creates instance attribute on s1!
print(s1.school_name)       # Output: "Private Institute"
print(s2.school_name)       # Output: "CodeVerse Global University" (Unchanged!)
print(Student.school_name)  # Output: "CodeVerse Global University" (Unchanged!)
💣 Trap 2: The Dangerous Mutable Class Attribute Trap

Never put mutable collections (lists, sets, dicts) as class attributes unless you deliberately want a shared global pool!

❌ Fatal Bug (Shared Mutable List): 
class BadStudent:
    hobbies = []  # CLASS ATTRIBUTE!

    def __init__(self, name):
        self.name = name

s1 = BadStudent("Aman")
s2 = BadStudent("Riya")
s1.hobbies.append("Chess")
print(s2.hobbies)  # ['Chess']! Mutated for Riya too!
✅ Corrected Fix (Instance List): 
class GoodStudent:
    def __init__(self, name):
        self.name = name
        self.hobbies = []  # INSTANCE ATTRIBUTE!

s1 = GoodStudent("Aman")
s2 = GoodStudent("Riya")
s1.hobbies.append("Chess")
print(s2.hobbies)  # [] Clean & isolated!

Instance Methods, Class Methods, and Static Methods

Python provides three distinct categories of methods inside a class. Knowing when to use each is an essential software engineering skill.

Method Type Decorator 1st Parameter Access to State Primary Purpose How Called
Instance Method None (Default) self Full access to instance & class Read/update individual object state obj.method()
Class Method @classmethod cls Access to class, NO instance Alternative constructors, factory methods Class.method()
Static Method @staticmethod None (No self/cls) Isolated utility; NO state access Independent helper logically grouped Class.helper()
three_methods.py • Complete Demonstration of All 3 Types 
class Student:
    total_students = 0

    def __init__(self, name, marks):
        self.name = name
        self.marks = marks
        Student.total_students += 1

    # 1. Instance Method: Receives self, operates on instance state
    def get_percentage(self, total_max=100):
        return (self.marks / total_max) * 100

    # 2. Class Method: Receives cls, acts as an alternative constructor
    @classmethod
    def from_csv_string(cls, data):
        name, marks = data.split(",")
        return cls(name.strip(), int(marks.strip()))

    # 3. Static Method: Self-contained utility function
    @staticmethod
    def is_passing_mark(marks):
        return marks >= 40

# Regular instantiation via __init__
s1 = Student("Aman", 85)
print("s1 percentage:", s1.get_percentage())

# Alternative instantiation via @classmethod
s2 = Student.from_csv_string("Riya, 92")
print("s2 name & marks:", s2.name, s2.marks)

# Calling @staticmethod without creating an instance
print("Is 35 passing?", Student.is_passing_mark(35))
print("Is 75 passing?", Student.is_passing_mark(75))
print("Total enrolled:", Student.total_students)
▶ OUTPUT
s1 percentage: 85.0 s2 name & marks: Riya 92 Is 35 passing? False Is 75 passing? True Total enrolled: 2
💡 Why use cls(...) in class methods instead of Student(...)?

Using cls(name, marks) ensures inheritance friendliness! If someone creates a subclass class GraduateStudent(Student): pass and calls GraduateStudent.from_csv_string(...), cls will refer to GraduateStudent, returning an instance of the subclass rather than hardcoding the parent class.

What Is Encapsulation?

💡 Definition of Encapsulation

Encapsulation is the practice of bundling data (attributes) and the methods that operate on that data inside a single unit (class), while restricting direct external access to prevent unintended or corrupted states.

Think of encapsulation as a protective medical capsule. The active medicinal ingredients are enclosed safely inside the gel coating. You take the capsule through its proper interface (swallowing it with water). You do not crack the capsule open, spill powder all over your table, and guess the dose!

🏦 Real-Life Analogy: The Bank ATM

Imagine if banks allowed customers to walk into the back office, open the master ledger book with a pencil, erase their balance of ₹5,000, and write ₹50,00,000! The bank would collapse in 10 minutes.

Instead, the bank keeps the balance strictly private. You interact only through guarded operations: deposit() and withdraw(). The bank verifies your balance, ensures amounts are positive, logs the transaction, and only then updates the balance. That is encapsulation in action!

Public, Protected, and Private Naming Conventions

📊 Figure 15.4: Encapsulation Tiers & Python Name Mangling Mechanics
Python offers three visibility levels: public attributes (`self.name`) have unrestricted access; protected attributes (`self._rate`) signify internal usage by convention without interpreter enforcement; private attributes (`self.__balance`) trigger automatic runtime name mangling to `_ClassName__attribute` to prevent accidental subclass override.
Visual Summary & Trace:
Encapsulation Levels: Public is free; single underscore is a convention; double underscore triggers name mangling by the interpreter.

Unlike languages like Java or C++ that enforce strict access modifiers via compiler keywords (public, protected, private), Python follows a philosophy popularized by creator Guido van Rossum: "We are all consenting adults here." Python uses naming conventions rather than rigid compiler firewalls.

Access Level Syntax Convention Enforcement Level Intended Meaning
Public self.name No restriction Safe for anyone to read and write directly.
Protected self._balance (Single underscore) Convention only (Gentleman's agreement) Internal implementation detail! Subclasses can use it, but external callers should avoid touching it.
Private self.__balance (Double underscore) Name Mangling by interpreter Mangled to _ClassName__balance to prevent accidental overrides in subclasses. NOT cryptographic security!
access_levels.py • Public, Protected and Name Mangling 
class Account:
    def __init__(self, holder, branch, balance):

Method Resolution Order (MRO)

📊 Figure 15.6: C3 Linearization & Diamond Problem Resolution (MRO)
When classes inherit from multiple ancestors sharing a common base (the diamond problem), Python computes a strict linear search sequence using the C3 Linearization algorithm. This guarantees that children precede parents, sibling declaration order is maintained, and common bases are visited exactly once.
Visual Summary & Trace:
MRO C3 Algorithm: Resolves diamond inheritance so every class is visited in strict linear order without duplicate executions.
💡 What is MRO?

Method Resolution Order (MRO) is the deterministic search order Python follows when looking for a method or attribute in a class hierarchy. Python computes this order using the sophisticated C3 Linearization Algorithm.

You can inspect any class's MRO using either the ClassName.mro() method (returns a list) or the ClassName.__mro__ attribute (returns a tuple):

mro_inspection.py • Unraveling the C3 Linearization Order 
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

# Print MRO order
print("MRO for D:", [cls.__name__ for cls in D.mro()])
▶ OUTPUT
MRO for D: ['D', 'B', 'C', 'A', 'object']
🧐 How C3 Linearization Decides:

Notice the order: D → B → C → A → object.

  1. Children are always searched before their parents (D before B and C).
  2. Left parents are searched before right parents (B before C because class D(B, C) listed B first).
  3. Shared base classes are visited only after all their subclasses have been examined (A is visited after both B and C).
  4. Every class in Python ultimately terminates at the universal root base: object.

Abstract Classes and Abstract Methods

💡 What is an Abstract Base Class (ABC)?

An Abstract Base Class (ABC) is a class that cannot be instantiated on its own. It acts as an enforceable contract, defining a blueprint of methods that all concrete subclasses MUST implement.

Python provides the abc standard library module containing the ABC base class and the @abstractmethod decorator:

abstract_shapes.py • Enforcing Method Implementation via abc.ABC 
from abc import ABC, abstractmethod

# Abstract Base Class
class Shape(ABC):
    @abstractmethod
    def area(self):
        """Subclasses must calculate and return the area."""
        pass

    @abstractmethod
    def perimeter(self):
        """Subclasses must calculate and return the perimeter."""
        pass

# Concrete Subclass implementing the contract
class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)

rect = Rectangle(5, 4)
print("Rectangle Area:", rect.area())
print("Rectangle Perimeter:", rect.perimeter())
▶ OUTPUT
Rectangle Area: 20 Rectangle Perimeter: 18
⚠️ What Happens If You Break the Contract?

If you attempt to instantiate an abstract class directly, or if a subclass fails to implement even one abstract method, Python refuses to create the object and raises a TypeError at instantiation time:

SOLID Principles — Beginner Introduction

🛡️ What are the SOLID Principles?

Introduced by Robert C. Martin ("Uncle Bob"), the SOLID principles are five architectural guidelines for designing maintainable, understandable, and flexible object-oriented software.

Letter Principle Name Simple Explanation Real-Life Analogy
S Single Responsibility Principle (SRP) A class should have one, and only one, reason to change. A specialized chef's knife vs. a bulky 40-tool Swiss knife.
O Open/Closed Principle (OCP) Open for extension, closed for modification. Add new features without editing working code. Plugging new USB accessories into a laptop without redesigning the motherboard.
L Liskov Substitution Principle (LSP) Subtypes must be substitutable for their base types without altering program correctness. Replacing a AA battery with another brand's AA battery without the remote malfunctioning.
I Interface Segregation Principle (ISP) Clients should not be forced to depend on methods they do not use. Prefer small interfaces. A TV remote should not have microwave oven buttons on it.
D Dependency Inversion Principle (DIP) High-level business logic should depend on abstractions, not low-level concrete details. Lamps plug into universal wall sockets, not hardwired directly to the city power grid.

Common OOP Design Mistakes

Watch out for these 15 frequent beginner and intermediate anti-patterns:

❌ Mistake 1: Forgetting self

Writing def get_name(): inside a class. When invoked via obj.get_name(), Python passes the instance as an argument, causing a TypeError: takes 0 positional arguments but 1 was given.

❌ Mistake 2: Forgetting super().__init__()

Creating a child class that overrides __init__ without invoking super().__init__(). The parent attributes are never created, causing runtime AttributeErrors.

❌ Mistake 3: The "God Class" Anti-Pattern

Creating a single monstrous AppManager class with 3,000 lines handling users, payments, database queries, and GUI rendering. Violates SRP!

❌ Mistake 4: Overusing Inheritance

Inheriting just to borrow one helper function (e.g. Car(Engine)). A car is NOT an engine; use composition (car.engine) instead!

🔹 Beginner Level (Questions 1 to 10)

Q1: What is the difference between a class and an object?

Answer: A class is a blueprint or template in source code describing attributes and methods. An object is an allocated instance in computer memory with real state values.

Q2: What is the purpose of the __init__() method in Python?

Answer: It serves as the initializer constructor, automatically invoked upon object instantiation to initialize its instance attributes.

Q3: Why must ordinary instance methods accept self as their first parameter?

Answer: Because Python automatically passes the calling instance as the first argument when you invoke instance.method(). self allows the method to access that specific object's attributes.

Q4: Predict the output:
class A: x = 10
a1 = A(); a2 = A()
a1.x = 20
print(a1.x, a2.x, A.x)

Answer: 20 10 10. Assigning a1.x = 20 creates an instance attribute on a1 that shadows the class attribute without changing it for a2 or A.

Q5: Is self a reserved keyword in Python?

Answer: No. It is a universal PEP 8 naming convention, not a Python keyword. However, deviating from it is considered terrible practice.

Q6: How does print(obj) determine what text to display?

Answer: It first searches for the __str__() dunder method. If not found, it falls back to __repr__(). If neither is defined, it displays the default <ClassName object at 0x...>.

Q7: Write a minimal class Book with title and author. 
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author
Q8: What error occurs if you call a method without passing required constructor parameters?

Answer: TypeError: __init__() missing required positional argument: ...

Q9: How do you inspect an object's instance attributes as a dictionary?

Answer: By reading obj.__dict__.

Q10: What does the pass keyword do inside an empty class?

Answer: It serves as a placeholder no-op statement so Python's indentation parser does not throw a syntax error.

🔸 Intermediate Level (Questions 11 to 20)

Q11: How does Python's double-underscore __attribute enforce privacy?

Answer: Through Name Mangling. Python renames __attribute to _ClassName__attribute to prevent naming collisions in subclasses. It is not cryptographic encryption.

Q12: What is the main benefit of using @property instead of traditional getter/setter methods?

Answer: It provides validation while preserving clean, natural attribute access syntax (obj.temp = 25) without breaking existing caller code.

Q13: What is the difference between single and multilevel inheritance?

Answer: Single inheritance has one direct parent (A → B). Multilevel inheritance has a vertical chain of inheritance (A → B → C).

Q14: Predict the output:
class P: def f(self): return "P"
class C(P): def f(self): return super().f() + "C"
print(C().f())

Answer: PC. The child delegates to the parent method first and appends "C".

Q15: What is Duck Typing in Python?

Answer: The philosophy that an object's suitability is determined by the presence of certain methods and attributes at runtime, rather than its inheritance hierarchy.

Q16: Which dunder method is called when using the + operator between two objects?

Answer: __add__(self, other).

Q17: Why does Python NOT support traditional method overloading with duplicate method names?

Answer: Because Python is dynamically typed; defining a method binds the name in the class dictionary. A second definition with the same name simply overwrites the first.

Q18: What is an Abstract Base Class (ABC)?

Answer: A class subclassing abc.ABC containing one or more @abstractmethods. It cannot be instantiated directly and serves as a contract for subclasses.

Q19: Explain the difference between Aggregation and Composition.

Answer: In Aggregation ("has-a"), the child object can exist independently of the parent. In Composition ("owns-a"), the child's lifecycle is bound to the parent; destroying the parent destroys the component.

Q20: Why is "Favor Composition Over Inheritance" recommended?

Answer: Because deep inheritance trees create tight coupling and the Fragile Base Class problem. Composition allows swapping behavior dynamically at runtime.

🔺 Advanced Level (Questions 21 to 30)

Q21: What is Method Resolution Order (MRO) and how is it calculated in Python?

Answer: MRO is the order in which Python searches for attributes/methods in inheritance hierarchies. It is computed using the C3 Linearization Algorithm.

Q22: Predict the MRO for: class A: pass; class B(A): pass; class C(A): pass; class D(B, C): pass

Answer: [D, B, C, A, object].

Q23: How do you make an instance of a class callable like a function?

Answer: By implementing the __call__(self, ...) dunder method.

Q24: What are the two methods required to implement the Python Iterator Protocol?

Answer: __iter__(self) (returning the iterator itself) and __next__(self) (returning items or raising StopIteration).

Q25: Why does @dataclass forbid tags: list = []?

Answer: Because a mutable default list would be shared by all instances, causing accidental state pollution. You must use field(default_factory=list).

Q26: Explain the Single Responsibility Principle (SRP) with an example.

Answer: A class should have only one reason to change. For example, a User class should store profile data, while a separate UserSerializer handles JSON encoding.

Q27: Explain the Liskov Substitution Principle (LSP).

Answer: Any subclass must be substitutable for its parent class without breaking client expectations or causing errors.

Q28: What is the relationship between __eq__ and __hash__?

Answer: If a class overrides __eq__, Python sets __hash__ = None by default to prevent mutable objects with custom equality from corrupting hash-based collections (sets and dict keys).

Q29: What is the difference between __getattr__ and __getattribute__?

Answer: __getattribute__ is called unconditionally for every attribute access. __getattr__ is only called as a fallback when the attribute is NOT found in the normal dictionary lookup.

Q30: How do you create an immutable dataclass in Python?

Answer: By passing @dataclass(frozen=True), which raises a FrozenInstanceError if anyone attempts to assign or modify attributes after creation.
