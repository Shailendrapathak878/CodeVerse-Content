Imagine you are building a school app. It must store 500 students. Each one has a name, marks, a city and a phone number.

02

Why Do We Need OOPS?

Before OOPS, most programs were procedural. They were a long list of steps, with data in one place and functions in another.

Concept

In procedural programming, data and the functions that use it are separate. Anyone can change any data from anywhere.

Example
Python
# Procedural style: data and functions live apart
names = ["Riya", "Aman"]
marks = [88, 72]

def show(i):
    print(names[i], "scored", marks[i])

show(0)
show(1)
Output
Riya scored 88
Aman scored 72
Easy Explanation
  • names and marks are two separate lists.
  • show() must trust that index i matches in both lists.
  • It works for 2 students. Now think about 500 students and 10 details each.

What goes wrong as the program grows

😵 Too many loose variables

Add city, phone and email, and you need 3 more lists. Nothing ties them to one student.

🔓 No protection

Any line of code can write marks[0] = -500. Nobody stops it.

🧩 Out of sync

Delete a name but forget the marks, and every student after it gets the wrong data.

🔁 Hard to reuse

To model a second kind of thing (a Teacher), you copy-paste and change everything.

The object-oriented idea

Put each student's data and actions inside one package called an object. Ask the object to do its own work.

Preview
Python
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def show(self):
        print(self.name, "scored", self.marks)

s1 = Student("Riya", 88)
s2 = Student("Aman", 72)
s1.show()
s2.show()
Output
Riya scored 88
Aman scored 72
Easy Explanation
  • Each Student carries its own name and marks.
  • Data and the function that uses it now live together.
  • Do not worry about every line yet. You will learn each part step by step.
🧠 Remember this
OOPS does not make code run faster. It makes big programs easier to organise, protect, reuse and change.
03

What is OOPS?

OOPS
Object-Oriented Programming System. A way of writing programs where we model things as objects that hold data and behaviour together.
Example: a Student, a Car, a BankAccount are all objects.
💡 Real-life analogy

Look around you. A phone has data (brand, battery %) and actions (call, take photo). You do not think in loose variables. You think in things. OOPS lets code think the same way.

From real world to code
Real things become classes. Classes create objects.

The 4 pillars of OOPS

🔐
EncapsulationHide data, control access
🧬
InheritanceReuse a parent's code
🔄
PolymorphismOne name, many forms
🎭
AbstractionShow what, hide how

Advantages

  • Reusability through inheritance and classes
  • Security through encapsulation
  • Easy maintenance: fix a class in one place
  • Real-world modelling: code looks like the problem
  • Teamwork: people build different classes separately

Limitations

  • More planning needed than a small script
  • Can be slower and heavier for tiny programs
  • Bad design (deep inheritance, huge classes) creates confusing code
  • Beginners need time to think in objects

Where OOPS is used

  • Games: Player, Enemy, Weapon
  • Banking and payment apps: Account, Transaction
  • Web frameworks: Django models, Flask extensions
  • GUI apps: Button, Window, Menu
  • Almost every big company codebase
🧠 Remember this
Python is multi-paradigm. You can write procedural code or OOPS code. Also, in Python everything is an object: numbers, strings, lists and even functions.
04

What is a Class?

CLASS
A blueprint (template) that describes what an object will have (data) and what it can do (actions).
Example: class Car says every car has a brand and can start.
💡 Real-life analogy

An architect draws one house plan. From that one plan, builders can make 100 houses. The plan is the class. Each house is an object. The plan itself is not a house you can live in.

One class, many objects
The class is written once. Objects are made from it.

Class members

🧾
AttributesVariables inside a class: brand, speed
⚙️
MethodsFunctions inside a class: start()
Concept

Use the keyword class, then a name, then a colon. Everything inside is indented.

Syntax
class ClassName:
    # attributes
    # methods
Example
Python
class Car:
    wheels = 4               # attribute

    def start(self):         # method
        print("Car started")

car1 = Car()
car2 = Car()
car1.start()
print(car1.wheels, car2.wheels)
Output
Car started
4 4
Easy Explanation
  • class Car: creates the blueprint. No car exists yet.
  • Car() builds a new car object. We built two.
  • Both cars share the same blueprint, so both have 4 wheels.
⚠️ Naming rule

Class names use PascalCase: BankAccount, StudentRecord. Variables and methods use snake_case.

What is an Object?

OBJECT
A real, usable thing created from a class. It has its own data and can perform actions.
Example: car1 = Car() creates one actual car.

Every object has three things:

State
The data it holdsname = 'Riya', marks = 88
Behaviour
What it can dointroduce(), study()
Identity
A unique IDno two objects are the same one
Creating and using an object

Write the class name with brackets. Use a dot to reach an object's data and methods.

Syntax
object_name = ClassName()
object_name.attribute
object_name.method()
Example
Python
class Student:
    def introduce(self):
        print("Hi, I am", self.name)

s1 = Student()
s1.name = "Riya"      # state
s1.marks = 88
s1.introduce()        # behaviour

s2 = Student()
s2.name = "Aman"
s2.introduce()
Output
Hi, I am Riya
Hi, I am Aman
Easy Explanation
  • s1 and s2 are two different objects of one class.
  • Each has its own name. Riya's data does not touch Aman's.
  • Setting data one line at a time is clumsy. The constructor (next sections) fixes that.

Object identity

Two objects can hold identical data and still be different objects.

Example
Python
class Student:
    pass

a = Student()
b = Student()
c = a

print(a is b)
print(a is c)
print(type(a))
print(isinstance(a, Student))
Output
False
True
<class '__main__.Student'>
True
Easy Explanation
  • a is b is False. They are two separate objects.
  • c = a does not copy. It gives the same object a second name, so a is c is True.
  • type(a) shows which class made it. isinstance checks that.
🧠 Remember this
Class ≠ Object. The class is the plan. The object is the real thing built from the plan.

📐 Class

The blueprint. Written once. Defines what objects will have and do. Takes no space for object data.

🏠 Object

A real instance built from the class. Created many times. Each one stores its own data in memory.

Real life vs programming

Recipe
ClassCake = object
Mobile model
ClassYour phone = object
Student form
ClassFilled form = object
One class → three objects
Example
Python
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

s1 = Student("Riya", 88)
s2 = Student("Aman", 72)

print(vars(s1))
print(vars(s2))
print(s1.name == s2.name)

{'name': 'Riya', 'marks': 88}

07

Constructor: __init__

CONSTRUCTOR
A special method that runs automatically the moment an object is created. It sets up the object's starting data.
In Python it is named __init__.
💡 Why do we need it?
  • Without it, every object starts empty. You must set each attribute by hand.
  • You can forget a line and get an AttributeError later.
  • A constructor guarantees every object starts complete and valid.
💡 Real-life analogy

When a new student joins a school, the school immediately asks for name and class and issues an ID card. Nobody enters without this setup. The constructor is that admission desk.

Syntax
class ClassName:
    def __init__(self, param1, param2):
        self.attr1 = param1
        self.attr2 = param2
Example
Python
class Student:
    def __init__(self, name, marks):
        print("Constructor running...")
        self.name = name
        self.marks = marks

s1 = Student("Riya", 88)
print(s1.name, s1.marks)
Output
Constructor running...
Riya 88
Easy Explanation
  • We never wrote s1.__init__(...). Python calls it for us.
  • Student("Riya", 88) sends the two arguments into the constructor.
  • The constructor stores them as the object's own data.
What happens when you create an object

Default constructor

If you do not write __init__, Python quietly gives your class an empty default constructor. It takes no arguments and sets nothing.

Example
Python
class Dog:
    pass            # no __init__ written

d = Dog()           # works fine
print(type(d).__name__)
Output
Dog
Easy Explanation
  • Python used its built-in empty constructor, so Dog() worked.

Parameterized constructor

A constructor that accepts values so each object can start with different data. This is the one you will use most.

Example
Python
class Book:
    def __init__(self, title, price=100):
        self.title = title
        self.price = price

b1 = Book("Python Basics", 250)
b2 = Book("Maths")             # uses default price
print(b1.title, b1.price)
print(b2.title, b2.price)
Output
Python Basics 250
Maths 100
Easy Explanation
  • price=100 is a default value. It is used when no price is given.
  • That makes the argument optional.

Constructor overloading in Python

⚠️ Python is different from Java

Java and C++ let you write many constructors with different parameters. Python allows only one __init__. If you write two, the last one wins. Use default values instead.

Example
Python
class Rectangle:
    def __init__(self, w=1, h=None):
        self.w = w
        self.h = w if h is None else h   # one arg = square

    def area(self):
        return self.w * self.h

print(Rectangle().area())
print(Rectangle(4).area())
print(Rectangle(4, 5).area())
Output
1
16
20
Easy Explanation
  • One constructor handles three styles of creation.
  • No argument: 1x1. One argument: a square. Two arguments: a rectangle.
  • For more styles, you can add class-method constructors (see the Static Members section).

Constructor rules

  • The name must be exactly __init__ (two underscores each side).
  • The first parameter must be self.
  • It runs once per object, automatically.
  • It should not return a value. It returns None by itself.
  • Only one __init__ per class.
  • Constructor chaining across classes uses super().__init__(). See Inheritance.

Constructor vs normal method

🏗️ Constructor (__init__)

Runs automatically at object creation. Used for setup. Cannot return a value. Runs once.

⚙️ Normal method

Runs only when you call it. Used for actions. Can return values. Can run many times.

🧠 Remember this
__init__ is often called the constructor, but strictly it is the initializer. Python first creates the empty object with __new__, then __init__ fills it. You almost never write __new__.
08

The self Keyword

SELF
A name that refers to the current object, the one that is calling the method right now.
Other languages call it this.
💡 Why does it exist?

A class has many objects. When you call s1.show(), Python must know whose name and marks to use. self is how the method knows which object it is working on.

💡 Real-life analogy

A teacher says, "Open your own notebook." The word "your" means a different notebook for each child. self works the same way. It means "my own".

Example
Python
class Student:
    def __init__(self, name):
        self.name = name

    def show(self):
        print("My name is", self.name)

s1 = Student("Riya")
s2 = Student("Aman")
s1.show()
s2.show()
Output
My name is Riya
My name is Aman
Easy Explanation
  • When s1.show() runs, self is s1.
  • When s2.show() runs, self is s2.
  • Same method. Different object. Different result.

What Python really does

Example
Python
class Student:
    def __init__(self, name):
        self.name = name

    def show(self):
        print(self.name)

s1 = Student("Riya")
s1.show()               # what you write
Student.show(s1)        # what Python does behind the scenes
print(s1.show.__self__ is s1)
Output
Riya
Riya
True
Easy Explanation
  • s1.show() is shortcut for Student.show(s1).
  • That is why the method has one extra parameter. Python passes the object in for you.

Instance variable vs local variable (naming conflict)

Parameters often have the same name as attributes. self. tells them apart.

Example
Python
class Student:
    def __init__(self, name):
        self.name = name     # self.name = attribute, name = parameter

s = Student("Riya")
print(s.name)
Output
Riya
Easy Explanation
  • Left side self.name is the attribute stored in the object.
  • Right side name is the local parameter that disappears after the constructor ends.

Calling one method from another

Example
Python
class Calculator:
    def __init__(self, a, b):
        self.a = a
        self.b = b

    def add(self):
        return self.a + self.b

    def show(self):
        print("Sum is", self.add())    # self.add(), not just add()

Calculator(3, 4).show()
Output
Sum is 7
Easy Explanation
  • To use another method of the same object, write self.method_name().
  • Writing only add() would fail, because Python looks for a normal function named add.

Step-by-step: how self travels

  1. s1 = Student("Riya") creates an empty object.
  2. Python calls __init__(s1, "Riya"). So self is s1.
  3. self.name = name stores "Riya" inside s1.
  4. s1.show() runs show(s1). It reads self.name and finds "Riya".
🧠 Remember this
self is only a naming convention, but every Python programmer uses it. Always write it as the first parameter of instance methods.
09

Instance Variables vs Class Variables

👤 Instance variable

Belongs to one object. Created with self.x = .... Every object has its own copy.

👥 Class variable

Belongs to the class. Written directly in the class body. Shared by all objects.

💡 Real-life analogy

In a school, each student has their own roll number (instance variable). But the school name is the same for everyone (class variable).

Example
Python
class Student:
    school = "CodeVerse School"        # class variable (shared)

    def __init__(self, name):
        self.name = name               # instance variable (own)

s1 = Student("Riya")
s2 = Student("Aman")
print(s1.name, s1.school)
print(s2.name, s2.school)

Student.school = "New School"          # change once, everyone sees it
print(s1.school, s2.school)
Output
Riya CodeVerse School
Aman CodeVerse School
New School New School
Easy Explanation
  • school lives in the class, so all objects see the same value.
  • Changing Student.school updates it for every object.

A tricky case

Example
Python
class Student:
    school = "CodeVerse School"

s1 = Student()
s2 = Student()
s1.school = "Other School"     # creates a NEW instance variable on s1 only

print(s1.school)
print(s2.school)
print(Student.school)
Output
Other School
CodeVerse School
CodeVerse School
Easy Explanation
  • Assigning through an object (s1.school = ...) does not change the class variable.
  • It creates a new instance variable on s1 that hides the shared one.
  • To change the shared value, assign through the class: Student.school = ....
⚠️ Shared list trap

A mutable class variable such as a list is shared by every object. Appending in one object changes it for all. Create lists inside __init__ with self.items = [] instead.

Static Members: Class and Static Methods

In Java you write static. In Python the same idea has three kinds of methods.

self
Instance methodWorks with one object's data
cls
@classmethodWorks with the class itself
—
@staticmethodPlain function that just lives inside the class

Static (class-level) variable and a class method

Things that belong to the whole class

Use class-level members for data or actions that belong to the whole class, such as counting how many objects exist.

class ClassName:
    @classmethod
    def method(cls):
        ...

    @staticmethod
    def helper(x):
        ...
Example
Python
class Student:
    count = 0                       # static / class variable

    def __init__(self, name):
        self.name = name
        Student.count += 1

    @classmethod
    def total(cls):
        return cls.count

    @staticmethod
    def is_valid_marks(m):
        return 0 <= m <= 100

Student("Riya")
Student("Aman")
print(Student.total())
print(Student.is_valid_marks(105))
print(Student.is_valid_marks(88))
Output
2
False
True
Easy Explanation
  • count is shared. Each new student adds 1 to the same counter.
  • @classmethod gets cls (the class). It can read class data.
  • @staticmethod gets nothing automatically. It is just a utility that belongs to the topic.
  • Both are called with the class name. No object is needed.

Class method as an alternative constructor

Because Python has only one __init__, @classmethod is the clean way to create objects from different inputs.

Example
Python
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    @classmethod
    def from_string(cls, text):
        name, marks = text.split("-")
        return cls(name, int(marks))

s = Student.from_string("Riya-88")
print(s.name, s.marks)
Output
Riya 88
Easy Explanation
  • The text "Riya-88" is split into a name and a number.
  • cls(name, ...) builds a new Student. Using cls also works for subclasses.

When to use what

  • Instance method: needs the object's own data.
  • Class method: needs class data, or builds objects in a special way.
  • Static method: needs neither. It is a helper that fits the class topic.
❌ Wrong: Calling an instance method on the class
class Dog:
    def bark(self):
        print("Woof")

Dog.bark()
Error
TypeError: Dog.bark() missing 1 required positional argument: 'self'
✅ Correct: create an object first
Dog().bark()

An instance method needs an object to fill self.

Special (Dunder) Methods

Methods with double underscores on both sides, like __init__, are called dunder (double underscore) or magic methods. Python calls them for you in special situations.

The problem: printing an object

Example
Python
class Dog:
    def __init__(self, name):
        self.name = name

d = Dog("Tommy")
print(d)
Output
<__main__.Dog object at 0x7f3a1c2b4d10>
Easy Explanation
  • Python does not know how to describe your object, so it prints a memory address.
  • The address part changes on every run.

The fix: __str__

Example
Python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"Dog(name={self.name}, age={self.age})"

d = Dog("Tommy", 3)
print(d)
print(str(d))
Output
Dog(name=Tommy, age=3)
Dog(name=Tommy, age=3)
Easy Explanation
  • print() calls __str__ automatically.
  • It must return a string. Do not print inside it.

Other useful special methods

__str__
Friendly text for print()print(obj)
__repr__
Developer text, used in lists[obj1, obj2]
__len__
Makes len(obj) worklen(cart)
__eq__
Defines what == meansa == b
__lt__
Defines < for sortinga < b
__add__
Defines + for objectsa + b
Example
Python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

a = Point(1, 2)
b = Point(1, 2)
print(a == b)
print(a is b)
print([a, b])
Output
True
False
[Point(1, 2), Point(1, 2)]
Easy Explanation
  • Without __eq__, a == b would be False (different objects).
  • With it, Python compares the data. Same x and y means equal.
  • is still checks identity, so it stays False.
  • __repr__ controls how the object appears inside a list.
🧠 Remember this
__str__ is for users. __repr__ is for programmers. If you write only one, write __repr__. Python uses it as the fallback for print.

Encapsulation

ENCAPSULATION
Keeping data and the methods that use it together in one class, and protecting the data from direct, careless changes.
Example: you cannot touch the money inside an ATM. You must use its buttons.
🗣️ In simple words

Encapsulation means: "Do not touch my data directly. Ask my methods, and they will decide if it is safe."

💡 Why do we need it?
  • Without protection, any code can put a wrong value in your data (negative balance, age = -5).
  • When data is protected, all changes pass through one gate. The gate checks the value first.
  • If the rules change later, you fix one place, not the whole program.
💡 Real-life analogy

A medical capsule keeps the medicine inside a shell. You swallow the capsule, you do not touch the powder. In the same way, a class wraps its data in a shell and lets you use it only through methods.

Data is hidden, methods are the doorway
Outside code talks to the methods, never to the data.

Step 1: Bad design (no encapsulation)

Bad design
Python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

acc = BankAccount("Riya", 5000)
acc.balance = -99999          # anyone can do this!
print(acc.balance)
Output
-99999
Easy Explanation
  • Nothing stops us from setting a negative balance.
  • In a real bank this would be a disaster. The class cannot defend itself.
❌ The problem
  • Data is open to everyone.
  • No validation: negative money, wrong types, anything goes.
  • Bugs can come from any line in the program, so they are very hard to find.

Step 2: Encapsulated design

Better design
Python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance        # private (hidden)

    def deposit(self, amount):
        if amount <= 0:
            print("Deposit must be positive")
            return
        self.__balance += amount

    def withdraw(self, amount):
        if amount > self.__balance:
            print("Not enough balance")
            return
        self.__balance -= amount

    def get_balance(self):
        return self.__balance

acc = BankAccount("Riya", 5000)
acc.deposit(1000)
acc.withdraw(200)
acc.withdraw(99999)
acc.deposit(-50)
print(acc.get_balance())
Output
Not enough balance
Deposit must be positive
5800
Easy Explanation
  • __balance (two underscores) marks the data as private.
  • Money moves only through deposit and withdraw. Both check the rules first.
  • get_balance() lets outside code read the value safely.
  • 5000 + 1000 - 200 = 5800. The bad requests were refused.

What happens if outside code tries to cheat?

Example
Python
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

acc = BankAccount(5000)
print(acc.__balance)
Error
Error
AttributeError: 'BankAccount' object has no attribute '__balance'
Easy Explanation
  • Python hides the name, so direct access fails.
  • Now the only way to change money is through the safe methods.

❌ Without encapsulation

Open data. No checks. Bugs everywhere.

✅ With encapsulation

Protected data. Rules enforced. One place to fix.

🧠 Remember this
Encapsulation = bundle data and methods + protect the data. It is about safety.

Access Control in Python

ACCESS CONTROL
Rules that decide who is allowed to see or change a variable or method.
Java has the keywords public, protected, private.
🗣️ In simple words

Python does not have these keywords. It uses underscores in names instead. This is a mix of real protection and polite agreement between programmers.

name
PublicAnyone can use it
_name
ProtectedPlease use only inside class and child classes
__name
PrivateName is changed so outside access fails
💡 Real-life analogy

Public: the front gate of a school, anyone can enter. Protected: the staff room, meant for teachers only (but the door is not locked). Private: the principal's locked cupboard.

Example
Python
class Employee:
    def __init__(self):

Getters, Setters and @property

GETTER / SETTER
A getter is a method that reads a private value. A setter is a method that changes it, after checking it is valid.

🗣️ In simple words

Getter = "show me the value". Setter = "let me change the value, but I will check it first".

The classic way

Example

    def __init__(self, age):
        self.__age = age

        return self.__age

        if 0 < new_age < 120:
            self.__age = new_age
        else:
            print("Invalid age")

s.set_age(-5)
print(s.get_age())
Output
Invalid age
20
Easy Explanation
  • The setter validates before saving. -5 is refused.
  • This works, but calling s.set_age(20) feels long. Python has something nicer.

The Pythonic way: @property

@property lets you use a method like a normal variable, while the checks still run in the background.

Syntax
@property

    return self.__age

@age.setter

    ...

  • s.age = 20 calls the setter, which checks the value.

super() and Constructors in Inheritance

super()
A built-in that lets a child class use the parent class's methods, mainly its constructor.
Example: super().__init__(name, age)
🗣️ In simple words

super() means "ask my parent to do its part first".

💡 Why do we need it?

When a child has its own __init__, Python stops using the parent's one. The parent's setup never runs, and its attributes are missing. super().__init__() brings the parent's setup back.

The problem

Problem
Python
class Person:
    def __init__(self, name):
        self.name = name

class Student(Person):
    def __init__(self, name, school):
        self.school = school      # forgot the parent!

s = Student("Riya", "CodeVerse")
print(s.name)
Error
Error
AttributeError: 'Student' object has no attribute 'name'
Easy Explanation
  • school was set, but Person.__init__ never ran.
  • So name was never created.

The solution

Constructor chaining
The child calls the parent's constructor, then adds its own data.
Example
Python
class Person:
    def __init__(self, name):
        print("Person constructor")
        self.name = name

class Student(Person):
    def __init__(self, name, school):
        print("Student constructor")
        super().__init__(name)      # call the parent first
        self.school = school

s = Student("Riya", "CodeVerse")
print(s.name, s.school)
Output
Student constructor
Person constructor
Riya CodeVerse
Easy Explanation
  • Student(...) runs the Student constructor first.
  • super().__init__(name) jumps to the Person constructor and sets name.
  • Then Student sets its own school.
  • This parent-then-child flow is called constructor chaining.

Step-by-step order

  1. Student("Riya", "CodeVerse") creates the object.
  2. Student's __init__ starts and prints "Student constructor".
  3. super().__init__(name) runs Person's __init__, which prints "Person constructor".
  4. Control returns to Student, which sets school.
🧠 Remember this
If the child has no __init__, the parent's is used automatically. If the child has one, call super().__init__() yourself.

Method Overriding

METHOD OVERRIDING
When a child class writes its own version of a method that the parent already has, using the same name.
Example: both Animal and Dog have sound().
🗣️ In simple words

The parent says, "Here is the default way." The child says, "Thanks, but I will do it my own way."

💡 Why do we need it?

Every animal makes a sound, but a dog barks and a cat meows. The general method is not right for each child. Overriding lets each child give its own behaviour.

Example
Python
class Animal:
    def sound(self):
        print("Some sound")

class Dog(Animal):
    def sound(self):
        print("Woof!")

class Cat(Animal):
    def sound(self):
        print("Meow!")

Animal().sound()
Dog().sound()
Cat().sound()
Output
Some sound
Woof!
Meow!
Easy Explanation
  • Dog and Cat override sound().
  • Python looks in the object's own class first. If it finds the method there, it uses it.
  • Only if not found does it go up to the parent.

Extending the parent version with super()

Sometimes you want to keep the parent's work and add more.

Example
Python

    def info(self):
        print("This is a bank account")

    def info(self):
        super().info()                  # parent's version first
        print("It earns interest")

Output
This is a bank account
It earns interest
Easy Explanation
  • super().info() runs the parent's info.
  • Then the child's own line runs. The child adds to the parent instead of replacing it.
  • Same method name and same parameters are expected.
  • It needs inheritance. No parent, no overriding.
  • Decided at runtime, by looking at the real object.

Multiple Inheritance and MRO

Polymorphism

POLYMORPHISM
Poly = many, Morph = forms. The same method name can behave differently for different objects.
Example: speak() gives "Woof" for a dog and "Meow" for a cat.
🗣️ In simple words

You give one command, and each object does it in its own way. You do not need to know which kind of object it is.

💡 Why do we need it?
  • Without it, you write if dog ... elif cat ... elif cow ... everywhere.
  • Adding a new animal means editing old code in many places.
  • With polymorphism, you just call speak(). A new animal works without changing the calling code.
💡 Real-life analogy
  • The word "play": a child plays football, a musician plays guitar, an actor plays a role. One word, many meanings.
  • A power button turns on a TV, a fan and a phone, each in its own way.
One call, many behaviours

Without polymorphism (the messy way)

Messy way

make_sound("cat")

Meow
Easy Explanation
  • Every new animal forces us to edit this function.
  • The more animals, the longer and messier it gets.

With polymorphism (the clean way)

Clean way
Python
class Dog:
    def speak(self):
        print("Woof")

class Cat:
    def speak(self):
        print("Meow")

class Cow:
    def speak(self):
        print("Moo")

    a.speak()          # same call, different result

Woof
Meow
Moo
Easy Explanation
  • The loop does not care what kind of animal it is.
  • Each object runs its own speak().
  • To add a Duck, write class Duck with speak(). The loop needs no change.

Runtime polymorphism (using inheritance)

This is the most common type. The child classes override a parent method, and Python picks the right version while the program runs. This is also called dynamic dispatch.

Example
Python

    def area(self):
        return 0

class Rectangle(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h
    def area(self):
        return self.w * self.h

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r * self.r

shapes = [Rectangle(4, 5), Circle(2), Shape()]
for s in shapes:
    print(type(s).__name__, "area =", s.area())
Output
Rectangle area = 20
Circle area = 12.56
Shape area = 0
Easy Explanation
  • The list holds different shapes, but all are treated as Shape.
  • For each item, Python checks the real object and runs its own area().
  • Rectangle: 4 × 5 = 20. Circle: 3.14 × 2 × 2 = 12.56. Plain Shape: 0.
  • The choice was made at runtime, not before. That is dynamic dispatch.

Why this output? Step by step

  1. Loop takes the first item: a Rectangle object.
  2. s.area() → Python checks the Rectangle class → finds area → returns 20.
  3. Next item: Circle → its own area → 12.56.
  4. Last item: plain Shape → parent's area → 0.

Method Overloading in Python

METHOD OVERLOADING
Writing several methods with the same name but different parameters, in the same class.
Example (Java): add(int, int) and add(int, int, int).
🗣️ In simple words

Same name, different inputs. In Java, the compiler picks the right one by counting the arguments. This is called compile-time polymorphism.

⚠️ Python does NOT support it directly

In Python, a class stores methods by name. If you write two methods with the same name, the second one replaces the first.

What really happens
Python
class Calc:
    def add(self, a, b):
        return a + b

    def add(self, a, b, c):      # replaces the first add
        return a + b + c

c = Calc()
print(c.add(1, 2, 3))
print(c.add(1, 2))
Output
6
TypeError: Calc.add() missing 1 required positional argument: 'c'
Easy Explanation
  • Only the last add survived.
  • So the 3-argument call works, and the 2-argument call fails.

Python's alternatives

Way 1: default values

Example
Python
class Calc:
    def add(self, a, b, c=0):
        return a + b + c

c = Calc()
print(c.add(1, 2))
print(c.add(1, 2, 3))
Output
3
6
Easy Explanation
  • c=0 makes the third value optional. One method handles both calls.

Way 2: *args (any number of values)

Example
Python
class Calc:
    def add(self, *numbers):
        return sum(numbers)

c = Calc()
print(c.add(1, 2))
print(c.add(1, 2, 3, 4, 5))
Output
3
15
Easy Explanation
  • *numbers collects all arguments into a tuple.
  • Works for 2, 3 or 100 values.

Way 3: check the type

Example
Python
class Printer:
    def show(self, value):
        if isinstance(value, int):
            print("Number:", value)
        elif isinstance(value, str):
            print("Text:", value)
        else:
            print("Something else:", value)

p = Printer()
p.show(10)
p.show("hello")
p.show([1, 2])
Output
Number: 10
Text: hello
Something else: [1, 2]
Easy Explanation
  • One method, different behaviour for different types.
  • Python has also functools.singledispatchmethod for this, but you can skip it for now.
🧠 Remember this
Python has no compile-time polymorphism like Java. It gets the same result using default arguments, *args, type checks, and duck typing.

Abstraction

ABSTRACTION
Showing only the important, useful parts to the user and hiding the complicated details behind them.

  • The inside can change later, and nobody using it is affected.
💡 Real-life analogy

ATM machine. You insert the card, press buttons, and get cash. You never see the bank servers, the security checks or the note-counting machine. Only the essential steps are shown.

ATM: simple outside, complex inside

Essential vs non-essential details

✅ Essential (show)

Things the user needs: withdraw(), deposit(), check_balance().

🙈 Non-essential (hide)

Things the user does not need: how the balance is stored, how fraud is checked, how logs are written.

Example
Python
class Car:

Encapsulation vs Abstraction

🔐 Encapsulation

Protects data. Question: "Who can touch my data?" Done with private variables and methods.

🎭 Abstraction

Hides complexity. Question: "What does the user need to know?" Done with abstract classes and simple methods.

🧠 Remember this
Easy trick: Encapsulation hides DATA. Abstraction hides IMPLEMENTATION.

Abstract Classes

ABSTRACT CLASS
A class that is only a template. You cannot create objects from it. It forces its children to write certain methods.
Python tool: the abc module (Abstract Base Classes).
ABSTRACT METHOD
A method that is declared but has no body in the parent. Every child must write its own body.
Marked with @abstractmethod.
🗣️ In simple words

The parent says: "I do not know how to do this, but every child of mine MUST do it."

💡 Why do we need it?
  • "Payment" is an idea, not something you can really pay with. So an object of plain Payment makes no sense.
  • Yet we want every payment type (UPI, Card, Cash) to definitely have a pay() method.
  • Abstract classes guarantee that rule. Forget it, and Python gives an error.
💡 Real-life analogy

A company rule says: "Every employee must submit a monthly report." The rule does not say how. Each employee does it their own way, but nobody can skip it.

Abstract parent, concrete children
Children must fill in what the parent left empty.
Syntax
from abc import ABC, abstractmethod

class ClassName(ABC):
    @abstractmethod
    def method(self):
        pass
Example
Python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class UPI(Payment):
    def pay(self, amount):
        print("Paid", amount, "using UPI")

class Card(Payment):
    def pay(self, amount):
        print("Paid", amount, "using Card")

for method in [UPI(), Card()]:
    method.pay(500)
Output
Paid 500 using UPI
Paid 500 using Card
Easy Explanation
  • Payment(ABC) makes it an abstract class.
  • @abstractmethod says: every child must write pay.
  • UPI and Card do so, so they can create objects.
  • The loop calls pay without knowing which payment it is. That is polymorphism and abstraction working together.

You cannot create an object of an abstract class

Example
Python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

p = Payment()
Error
Error
TypeError: Can't instantiate abstract class Payment without an implementation for abstract method 'pay'
Easy Explanation
  • The class is incomplete, so Python refuses to build it.

A child that forgets the abstract method

Example
Python
from abc import ABC, abstractmethod

    @abstractmethod
    def pay(self, amount):
        pass

    pass            # forgot pay()

Error

Easy Explanation
  • A child stays abstract until it writes all the abstract methods.

Abstract classes can also have normal methods

Example
Python

class Vehicle(ABC):
    def __init__(self, name):

    @abstractmethod
    def fuel(self):

Nexon EV uses electricity

  • info() is written once in the parent and reused by all children.
  • fuel() is abstract. Each child gives its own answer.
  • An abstract class mixes shared code and required rules.

Interfaces in Python

INTERFACE
A contract: a list of methods that a class promises to provide. It says what must exist, never how.
Example: anything that is "Flyable" must have fly().
🗣️ In simple words

An interface is like a job requirement list. It does not do the job. It only says what the person must be able to do.

💡 Real-life analogy

A USB port is an interface. Any device with a USB plug (pen drive, mouse, keyboard) works with it. The port does not care what is inside the device. It only needs the plug shape to match.

🐍 Python has no `interface` keyword

Java has interface. Python does not. Python uses an abstract class with only abstract methods as the interface. That is the equivalent.

Example
Python
from abc import ABC, abstractmethod

class Flyable(ABC):             # interface
    @abstractmethod
    def fly(self):
        pass

class Swimmable(ABC):           # interface
    @abstractmethod
    def swim(self):
        pass

class Duck(Flyable, Swimmable):
    def fly(self):
        print("Duck flies")

    def swim(self):
        print("Duck swims")

class Airplane(Flyable):
    def fly(self):
        print("Airplane flies")

for thing in [Duck(), Airplane()]:
    thing.fly()
Duck().swim()
Output
Duck flies
Airplane flies
Duck swims
Easy Explanation
  • Flyable and Swimmable are pure contracts. They contain no real code.
  • Duck signs both contracts, so it must write fly and swim.
  • Airplane signs only Flyable.
  • This is how Python handles multiple interfaces: inherit from many.
  • The loop treats Duck and Airplane the same, because both can fly.

Interface vs abstract class vs normal class

📜 Interface (Python style)

Only abstract methods. No data. A pure promise. A class can follow many.

🧩 Abstract class

Mix of abstract methods and normal code or data. Cannot create objects.

🏠 Normal class

All methods are complete. You can create objects.

When to pick which

  • Interface: you only want to enforce "these methods must exist".
  • Abstract class: you also want to share some code with all children.
  • Normal class: you want actual objects.
💡 Bonus: duck typing as an informal interface

Often in Python you skip all this. You just write quack() in each class, and it works. Abstract classes are for when you want Python to force the rule.

Object Relationships: IS-A and HAS-A

Real programs have many classes. These classes must connect to each other. There are two basic kinds of connection.

IS-A
The child is a special type of the parent. Built with inheritance.
Example: a Dog IS-A Animal.
HAS-A
An object contains or uses another object. Built by keeping one object inside another.
Example: a Car HAS-A Engine.
Two kinds of relationship
💡 How to decide
  • Say the sentence out loud.
  • "A Dog is an Animal" sounds right → inheritance.
  • "A Car is an Engine" sounds wrong, but "A Car has an Engine" is right → HAS-A.
Example
Python
class Engine:
    def start(self):
        print("Engine started")

class Car:
    def __init__(self):
        self.engine = Engine()      # HAS-A: Car holds an Engine object

    def start(self):
        self.engine.start()         # Car asks its Engine to work
        print("Car is ready")

Car().start()
Output
Engine started
Car is ready
Easy Explanation
  • self.engine is an object stored inside another object. That is HAS-A.
  • The Car does not inherit from Engine. It just uses one.
🧠 Remember this
IS-A = inheritance. HAS-A = association, aggregation or composition.

Association

ASSOCIATION
A simple relationship where one object knows about or uses another. Both can live on their own.
Example: a Doctor treats a Patient.
🗣️ In simple words

"I know you, I use you, but I do not own you." It is the weakest link.

💡 Real-life example

A teacher teaches a student. If the teacher leaves, the student still exists. If the student leaves, the teacher still exists.

Association
Example
Python
class Patient:
    def __init__(self, name):
        self.name = name

class Doctor:
    def __init__(self, name):
        self.name = name

    def treat(self, patient):          # only uses the patient for a moment
        print(f"Dr. {self.name} is treating {patient.name}")

p = Patient("Aman")
d = Doctor("Sharma")
d.treat(p)
Output
Dr. Sharma is treating Aman
Easy Explanation
  • The Doctor does not store the patient. It just receives one when needed.
  • Both objects were created separately and stay independent.

Aggregation

AGGREGATION
A weak HAS-A. The whole contains parts, but the parts can exist without the whole.
Example: a Department has Teachers.
🗣️ In simple words

"I hold you, but I did not create you, and you survive without me."

💡 Real-life example

A football team has players. If the team is dissolved, the players still exist and can join another team.

Aggregation
Parts are created outside and passed in.
Example
Python
class Teacher:
    def __init__(self, name):
        self.name = name

class Department:
    def __init__(self, name):
        self.name = name
        self.teachers = []

    def add(self, teacher):          # teacher is created OUTSIDE
        self.teachers.append(teacher)

t1 = Teacher("Riya")
dept = Department("Science")
dept.add(t1)

print("Teachers in dept:", len(dept.teachers))
del dept
print("Department deleted. Is t1 alive?", t1.name)
Output
Teachers in dept: 1
Department deleted. Is t1 alive? Riya
Easy Explanation
  • The Teacher is created before and outside the department.
  • The department only keeps a reference to it.
  • After del dept, the teacher is still alive. We can still read t1.name.
  • That is the sign of aggregation: parts outlive the whole.

Composition

COMPOSITION
A strong HAS-A. The whole creates and owns its parts. If the whole is destroyed, the parts are destroyed too.
Example: a House has Rooms.
🗣️ In simple words

"I create you, I own you, and when I am gone, you are gone."

💡 Real-life example

A house and its rooms. Rooms are built as part of the house. Demolish the house, and the rooms do not exist anymore. A room cannot live alone.

Composition
The whole creates the parts inside itself.
Example
Python
class Room:
    def __init__(self, name):
        self.name = name
    def __del__(self):
        print(self.name, "destroyed")

class House:
    def __init__(self):
        self.rooms = [Room("Kitchen"), Room("Bedroom")]   # created INSIDE

h = House()
print("House built with", len(h.rooms), "rooms")
del h
print("House demolished")
Output
House built with 2 rooms
Bedroom destroyed
Kitchen destroyed
House demolished
Easy Explanation
  • Room objects are created inside House.__init__. Nobody outside owns them.
  • When del h removes the house, its rooms lose their only owner and are destroyed. The messages prove it.
  • Compare with aggregation, where the Teacher stayed alive.
💡 Where does composition appear later?

In the banking project, every Account creates its own Transaction records. Those records have no life outside the account. That is composition.

Association vs Aggregation vs Composition

🤝 Association

Just knows or uses. No ownership. Both independent. Doctor – Patient

🧺 Aggregation

Holds parts, but parts live on their own. Weak ownership. Team – Player

🧱 Composition

Creates and owns parts. Parts die with the whole. Strong ownership. House – Room

Test questions to ask

  1. Does the whole create the part inside itself? Yes → Composition.
  2. Is the part created outside and just stored? Yes → Aggregation.
  3. Is the object only used for a moment, not stored? Yes → Association.
Association→uses → no ownership
Aggregation→has → part survives
Composition→owns → part dies too

Beginners overuse inheritance. A good rule: prefer HAS-A when IS-A is not 100% true.

❌ Inheritance used wrongly

class Car(Engine). A car is not an engine. If you change Engine, Car breaks.

✅ Composition

Car has an engine. You can swap the engine type easily.

Object Lifecycle and Cleanup

Every object has a life: it is born, used, and finally removed from memory.

  1. Created: Student() builds the object, then __init__ sets it up.
  2. Used: you call methods and read data.
  3. Destroyed: when nothing refers to it anymore, Python frees its memory.
GARBAGE COLLECTION
Python automatically removes objects that nobody uses any more. You do not delete memory by hand.
Python counts how many names point to an object. At zero, it is removed.
Example
Python
class Demo:
    def __init__(self, name):
        self.name = name
        print(self.name, "created")

    def __del__(self):
        print(self.name, "destroyed")

a = Demo("A")
b = a                    # two names, one object
del a
print("a deleted, b still points to it")
del b
print("end")
Output
A created
a deleted, b still points to it
A destroyed
end
Easy Explanation
  • __del__ is the destructor. Python calls it just before removing the object.
  • After del a, the object lives on, because b still points to it.
  • Only after del b does the count reach zero, and the object is destroyed.
⚠️ Do not depend on __del__

Timing is not guaranteed in every situation. For cleanup such as closing files or connections, use a with statement instead.

Example
Python
class Connection:
    def __enter__(self):
        print("Connection opened")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("Connection closed")

with Connection() as c:
    print("Working...")
print("Done")
Output
Connection opened
Working...
Connection closed
Done
Easy Explanation
  • __enter__ runs at the start of with, and __exit__ runs at the end, even if an error happens.
  • This is the reliable way to clean up resources.

Good Design: Coupling, Cohesion and SOLID

OOPS gives you tools. These ideas tell you how to use the tools well.

Coupling: how tied are two classes?

❌ Tight coupling

Class A depends on the exact details of class B. Change B, and A breaks.

✅ Loose coupling

Class A depends only on a simple promise (like a method name). B can change freely.

Example
Python
class EmailSender:
    def send(self, msg):
        print("Email:", msg)

class SMSSender:
    def send(self, msg):
        print("SMS:", msg)

class Order:

Order(SMSSender()).place()

Email: Order placed!
SMS: Order placed!
Easy Explanation
  • Order only needs something with send().
  • We switch from Email to SMS without touching Order.

Cohesion: does a class do one clear job?

❌ Low cohesion

One class does billing, emailing, printing and saving. Hard to understand.

✅ High cohesion

Each class has one focused purpose. Easy to read and test.

🧠 Remember this
Aim for loose coupling and high cohesion.

SOLID: five famous design rules

S
Single ResponsibilityA class should have one job
O
Open / ClosedAdd new features by adding classes, not editing old ones
L
Liskov SubstitutionA child must work wherever its parent works
I

D
Dependency InversionDepend on abstract ideas, not concrete classes

  • Open/Closed: adding a Duck to the animal loop needed no old code change.

Step 2: The abstract Account (encapsulation + abstraction)

Account is the parent of all account types. It holds the common rules once.

Code
Python
class Account(ABC):
    total_accounts = 0

    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance
        self.__history = []
        Account.total_accounts += 1

    @property
    def balance(self):
        return self.__balance

    def _change(self, kind, amount):
        self.__balance += amount
        self.__history.append(Transaction(kind, abs(amount)))

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive")
        self._change("Deposit", amount)

    def withdraw(self, amount):
        if not self.can_withdraw(amount):
            raise ValueError("Withdrawal not allowed")
        self._change("Withdraw", -amount)

    def can_withdraw(self, amount):
        return 0 < amount <= self.__balance

    def show_history(self):
        for t in self.__history:
            print("  ", t)

    @abstractmethod
    def account_type(self):
        pass

    @abstractmethod
    def monthly_update(self):
        pass

    def __str__(self):
        return f"{self.account_type()} | {self.owner} | Rs.{self.balance}"
Easy Explanation
  • class Account(ABC): an abstract class. Nobody can create a plain Account.
  • __balance and __history are private. Outside code cannot touch them (encapsulation).
  • @property balance lets others read the balance, but not set it.
  • _change() is a protected helper. Only the class and its children use it to move money and record a Transaction.
  • deposit and withdraw validate first. Withdraw asks can_withdraw(), which children can override.
  • account_type and monthly_update are abstract. Every child must define them.
  • total_accounts is a class variable shared by all accounts.
Test it: abstract class cannot be created
Python

    Account("Riya")

Step 3: Savings and Current accounts (inheritance + overriding + polymorphism)

Both children inherit everything from Account and only add what is different.

Code

class SavingsAccount(Account):
    MIN_BALANCE = 500
    RATE = 0.04

    def account_type(self):
        return "Savings"

    def can_withdraw(self, amount):
        return 0 < amount <= self.balance - self.MIN_BALANCE

    def monthly_update(self):
        interest = round(self.balance * self.RATE / 12, 2)
        self._change("Interest", interest)


class CurrentAccount(Account):
    OVERDRAFT = 2000
    FEE = 100

    def account_type(self):
        return "Current"

    def can_withdraw(self, amount):
        return 0 < amount <= self.balance + self.OVERDRAFT

    def monthly_update(self):
        self._change("Fee", -self.FEE)
Easy Explanation
  • Both classes override can_withdraw() with their own rule. Savings must keep Rs.500. Current may go Rs.2000 below zero.
  • Both implement the abstract methods account_type and monthly_update.
  • self._change(...) reuses the parent's protected helper. No code is repeated.
  • Class constants like MIN_BALANCE are class variables, same for all objects.
  • Result: Riya's savings had 10000, withdrew 9000, so 1000 remains. Withdrawing 900 more would break the Rs.500 rule, so it is refused.
  • Aman's current account: 1000 - 2500 = -1500, allowed because of the overdraft.

Step 4: Customer and Bank (aggregation) and the full run

A customer holds accounts. A bank holds customers. These accounts are created outside and passed in, so this is aggregation.

Code
Python
class Customer:
    def __init__(self, name):
        self.name = name
        self.accounts = []

    def add_account(self, account):
        self.accounts.append(account)

    def total_balance(self):
        return sum(a.balance for a in self.accounts)


class Bank:
    def __init__(self, name):
        self.name = name
        self.customers = []

    def add_customer(self, customer):
        self.customers.append(customer)

    def month_end(self):
        for customer in self.customers:
            for account in customer.accounts:
                account.monthly_update()
Easy Explanation
  • Customer.accounts is a list of Account objects (HAS-A).
  • Bank.month_end() loops over every account and calls monthly_update() without checking the type.
  • That one call does interest for savings and a fee for current accounts. That is polymorphism.
  • Riya's savings: 12000 + 3000 = 15000, then interest 15000 × 0.04 ÷ 12 = 50.
  • Riya's current: 3000 - 4000 = -1000, then fee 100 gives -1100.
  • Aman's savings: 800 plus interest of 2.67 = 802.67.

Best Practices

  • One class, one job. Do not build giant classes that do everything.
  • Use PascalCase for classes and snake_case for methods and variables.
  • Make data private by default. Expose only what is needed.
  • Use @property for validation instead of old-style get_x() and set_x().
  • Always write __str__ or __repr__ so objects print clearly.
  • Call super().__init__() in a child's constructor.
  • Use inheritance only for a true IS-A relationship. Otherwise use composition.
  • Keep inheritance chains short (2 or 3 levels).
  • Create lists and dictionaries inside __init__, never as shared class variables.
  • Use abstract classes when children must follow a rule.
  • Give small methods clear names. A good method does one thing.

❌ Over-engineering

Making 10 classes for a 20-line script. OOPS is a tool, not a rule.

✅ Right-sized design

Use classes when you have things with data and behaviour. Use plain functions for simple tasks.

Interview Questions

Tap a question to see its answer. Try answering in your own words first. Questions go from basic to tricky.

🟢 Beginner

Q1 What is OOPS and why do we use it?

OOPS is a way of programming where we model real-world things as objects, each holding data and behaviour together.

We use it for reusability, security (encapsulation), easy maintenance and because code that mirrors real things is easier to understand.

Q2 What is the difference between a class and an object?

A class is a blueprint. It describes what data and methods will exist. An object is a real instance created from that blueprint. One class can produce many objects, and each object has its own data.

Example: the house plan is the class. Each built house is an object.

Q3 What is a constructor? Does Python have default constructors?

A constructor sets up an object when it is created. In Python it is __init__.

Yes. If you do not write one, Python provides an empty default constructor that takes no arguments.

Q4 What is self?

self refers to the current object that is calling the method. It lets a method read and change that object's own data. It is the first parameter of every instance method, and Python passes it automatically.

Q5 Name the four pillars of OOPS.
  • Encapsulation: bundle data + methods and protect the data.
  • Inheritance: a child class reuses a parent's features.
  • Polymorphism: one name, many behaviours.
  • Abstraction: show what, hide how.
Q6 What is encapsulation? How do you do it in Python?

Wrapping data and the methods that use it in one class, and restricting direct access to the data.

In Python: use _name (protected, by convention) and __name (private, name-mangled), and provide access through methods or @property.

Q7 What is inheritance? Which types does Python support?

Inheritance lets a child class get the attributes and methods of a parent class (IS-A relationship).

Python supports single, multilevel, hierarchical, multiple and hybrid inheritance.

Q8 What is polymorphism? Give an example.

Polymorphism means "many forms". The same method call behaves differently depending on the object.

Example: speak() prints "Woof" for Dog and "Meow" for Cat, even when called in one loop.

Q9 What is abstraction? How is it achieved in Python?

Hiding complex implementation details and exposing only what is needed.

Python achieves it with abstract classes (ABC + @abstractmethod) and by hiding helper logic in private methods.

Q10 What are IS-A and HAS-A?

IS-A is inheritance (Dog IS-A Animal). HAS-A means an object contains another object (Car HAS-A Engine). HAS-A includes association, aggregation and composition.

🟡 Intermediate

Q11 What is the difference between method overloading and overriding? Does Python support overloading?
  • Overloading: same method name, different parameters, in the same class.
  • Overriding: a child class gives its own version of a parent's method with the same name and parameters.
  • Python does not support overloading directly. The last definition replaces earlier ones. We use default arguments, *args or type checks instead.
  • Overriding works normally and is decided at runtime.

Q14 Explain instance method, class method and static method.

  • @classmethod: gets cls. Works with class-level data. Often used as an alternative constructor.
  • @staticmethod: gets nothing automatically. A utility function placed inside the class for organisation.
Q15 What is the difference between abstraction and encapsulation?
  • Abstraction hides implementation complexity and decides what to show (design level).
  • Encapsulation hides data and controls who can access it (implementation level).
  • Example: ATM buttons show only the needed actions (abstraction). The balance variable is private (encapsulation).

No. __name triggers name mangling: Python renames it to _ClassName__name. This prevents accidents but a determined programmer can still reach it. Single underscore _name is only a convention.

Q18 Differentiate association, aggregation and composition.
  • Association: one object uses another. No ownership.
  • Aggregation: weak HAS-A. The part can exist without the whole (Team has Players).
  • Composition: strong HAS-A. The whole creates and owns the part, and the part dies with it (House has Rooms).
Q19 Can an abstract class have a constructor and normal methods?

Yes. An abstract class can have __init__, normal methods and data. The only rules: it has at least one abstract method, and you cannot create an object of it directly. Its children use the constructor through super().__init__().

Q20 What are dunder (magic) methods? Name a few.

Methods with double underscores that Python calls automatically in special situations: __init__ (creation), __str__ (print), __len__ (len), __eq__ (==), __add__ (+).

Q24 Why is "composition over inheritance" a popular rule?
  • Inheritance tightly couples the child to the parent. A change in the parent can break all children.
  • Deep trees become hard to understand.
  • Composition lets you swap parts at runtime (a Car can take a PetrolEngine or an ElectricEngine).
  • Use inheritance only when the IS-A relation is truly valid.
Q25 Explain the Liskov Substitution Principle with an example.

A child object must be usable wherever the parent is expected, without breaking the program's behaviour.

A classic bad example: Square inheriting from Rectangle. Code that sets only the width and expects area = width × height gets a surprise when it receives a Square.

        self.w, self.h = w, h
    def set_width(self, w):
        self.w = w
    def area(self):
        return self.w * self.h

class Square(Rectangle):
    def __init__(self, s):
        super().__init__(s, s)
    def set_width(self, w):
        self.w = self.h = w      # keeps it a square

s.set_width(4)

The rectangle area changed to 20 as expected, but the square gave 16. A caller expecting rectangle behaviour is surprised. The design hints that Square should not be a Rectangle child.

Q26 What is duck typing? How is it different from using an interface?

Duck typing means Python cares only whether an object has the needed method, not what its class is. Interfaces/abstract classes force the rule and fail early if a method is missing. Duck typing is flexible but trusts the programmer.

Q27 What is the difference between __new__ and __init__?

__new__ creates the empty object and returns it. __init__ initializes that object. __new__ runs first. It is rarely overridden (used for singletons and immutable types).
