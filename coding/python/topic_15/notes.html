Part A · Why Do We Need OOP?
02

The Problem: Life Without OOP

Imagine you are building a banking app. You have only variables and functions. So you store data in parallel lists.

Python (procedural style)
names = ["Riya", "Aman"]
balances = [5000, 3000]

def deposit(index, amount):
    balances[index] += amount

def show(index):
    print(names[index], "has", balances[index])

deposit(0, 1000)
show(0)
Output
Riya has 6000

It works. But now the app grows. Watch what can go wrong.

Python (a silent bug)
names.remove("Riya")   # Riya closes her account...
show(0)                 # ...but we forgot balances!
Wrong output (no error!)
Aman has 6000

Aman now "has" Riya's money. Python gave no error. The bug is silent.

What goes wrong as the app grows

  • Data about one person is scattered across many lists.
  • Lists must stay in sync by hand. One slip causes wrong data.
  • Data and the functions that use it are separate. Nothing links them.
  • Anyone can write balances[0] = -999. Nothing protects the data.
  • Adding account type, history or interest means more lists and more functions.
💡 The big question

What if one account kept its own name, balance and actions together, in one package?

03

The OOP Idea and Its 4 Pillars

The answer is simple: group related data and behavior together.

OOP (Object-Oriented Programming)
A way of writing programs where you build them from objects. Each object holds its own data and its own actions.
Example: a BankAccount object holds a balance and can deposit or withdraw.
💡 Real life → Programming → Code
  • Real life: a real bank account has a holder, a balance and actions like deposit.
  • Programming: we model it as an object.
  • Code: we write a class as the blueprint, then create objects from it.

The journey you will follow in this chapter:

  1. Class → the blueprint
  2. Object → a thing built from it
  3. Constructor → sets up each object
  4. Then the 4 pillars below
The 4 Pillars of OOP
04

Procedural vs OOP

📜 Procedural programming

  • Built around functions that work on separate data.
  • Data is usually open to everyone.
  • Great for small, simple programs.
  • Gets messy as the program grows.

🧩 Object-oriented programming

  • Built around objects that hold data and actions together.
  • Data can be protected.
  • Easy to reuse and extend.
  • Best for medium and large programs.
🧠 Important

OOP is not "better" for everything. A 10-line script does not need classes. OOP shines when programs get big.

Part B · Class and Object
05

Class

CLASS
A blueprint (template) that describes what data and actions an object will have.
Example: a Student class says every student has a name, an age, and can study.
💡 Real-life analogy

A house blueprint. It shows rooms and doors, but you cannot live in a blueprint. It only describes what a house will look like.

Why do we need a class?

  • To describe a kind of thing once.
  • To create many similar objects from that one description.
  • To keep related data and actions in one place.
Syntax 
class ClassName:
    # data and methods go here
Example 1 · Very basic
Python
class Dog:
    pass

d1 = Dog()
print(type(d1).__name__)
Output 
Dog
How It Works
  • class Dog: defines a new type called Dog.
  • pass means "empty for now".
  • Dog() builds an object. d1 holds it.
Example 2 · A class with behavior
Python
class Dog:
    def bark(self):
        print("Woof!")

d = Dog()
d.bark()
Output 
Woof!
How It Works
  • A function inside a class is called a method.
  • We call it with a dot: d.bark().
  • The self in the brackets is explained in Section 9.
One class, many objects

The class is written once. Each object has its own data.

06

Object

OBJECT
A real thing created from a class. It has its own state (data) and behavior (actions).
Example: Rahul is an object made from the Student class.
💡 Real-life analogy

The actual house built from the blueprint. You can build many houses from one blueprint, and each house has its own colour and owner.

  • State = what the object knows (name, balance).
  • Behavior = what the object does (deposit, bark).
  • The act of making an object is called instantiation.
Example · Many objects, one class
Python
class Dog:
    def bark(self):
        print("Woof!")

dog1 = Dog()
dog2 = Dog()

dog1.name = "Tommy"
dog2.name = "Bruno"

print(dog1.name)
print(dog2.name)
print(dog1 is dog2)
dog1.bark()
Output 
Tommy
Bruno
False
Woof!
How It Works
  1. Dog() is called twice, so two separate objects are made.
  2. Each gets its own name. Changing one does not change the other.
  3. dog1 is dog2 is False. They are different objects.
  4. Both share the same bark behavior from the class.
⚠️ This works, but it is clumsy

Setting name one object at a time is easy to forget. The next idea, the constructor, fixes that.

07

Class vs Object

📐 Class

  • A blueprint or template.
  • Written once with the class keyword.
  • Takes no space for individual data.
  • Example: Student

🏠 Object

  • A real thing built from the blueprint.
  • Created many times: Student().
  • Holds its own values in memory.
  • Example: Rahul, Riya
🧠 One-line memory trick

Class = cookie cutter. Object = cookie. One cutter makes many cookies.

08

Constructor (__init__)

CONSTRUCTOR
A special method that runs automatically when an object is created. Its job is to set up the object's starting data.
In Python it is named __init__ (two underscores on each side).
💡 Real-life analogy

Opening a bank account. The bank asks for your name and starting deposit right at the start. You cannot have an account without them.

Why do we need it?

  • Every object starts with correct values.
  • No forgetting to set the name or age.
  • Creating an object takes one line.
Syntax 
class ClassName:
    def __init__(self, parameters):
        self.attribute = parameters
Example 1 · Runs automatically
Python
class Student:
    def __init__(self):
        print("Constructor called!")

s = Student()
Output 
Constructor called!
How It Works

We never wrote s.__init__(). Python called it for us the moment Student() ran.

Example 2 · Parameterized constructor
Python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

s = Student("Rahul", 20)
print(s.name, s.age)
Output 
Rahul 20
What happens when you write Student("Rahul", 20)

Default values

Give a parameter a default value to make it optional.

Python
class Student:
    def __init__(self, name="Unknown", age=18):
        self.name = name
        self.age = age

a = Student()
b = Student("Riya")
print(a.name, a.age)
print(b.name, b.age)
Output
Unknown 18
Riya 18

Default constructor

If you write no __init__, Python quietly gives your class an empty one. That is why Dog() worked earlier.

Constructor overloading? Not in Python

Java and C++ allow many constructors with different parameters. Python allows only one __init__. A second one replaces the first.

Python (Expected Error)
class A:
    def __init__(self):
        print("no args")

    def __init__(self, x):     # replaces the first
        print("one arg", x)

A(5)
A()
Output, then Expected Error
one arg 5
TypeError: A.__init__() missing 1 required positional argument: 'x'

Why? Only the second __init__ survived. It needs x, so A() fails. (Older Python versions print __init__() without the A..)

Python's way: use default values, or a class method as an alternative constructor (Section 11).

Constructor vs Method

🏗️ Constructor (__init__)

  • Called automatically once, when the object is created.
  • Sets up the starting data.
  • Name is fixed: __init__.
  • Returns nothing.

⚙️ Normal method

  • Called by you, as many times as you want.
  • Performs an action.
  • Any name you choose.
  • Can return a value.
💡 Think Before You Code

How many times does "Created!" print?

class Box:
    def __init__(self):
        print("Created!")

a = Box()
b = Box()
c = a
Show Answer

Twice. Box() ran two times, so two objects were made. c = a makes no new object. It only gives the same object a second name.

⚠️ Silent trap: a typo in the name

If you misspell __init__ (say, __int__), Python does not complain. It just treats it as a normal method.

Python (Expected Error)
class Student:
    def __int__(self, name):   # typo!
        self.name = name

Student("Rahul")
Expected Error
TypeError: Student() takes no arguments
09

self

self
The object itself, passed automatically as the first parameter of every instance method.
It answers: "Which object's data am I using right now?"
💡 Real-life analogy

A student saying "my". "My name is Rahul" only makes sense because "my" points to the person speaking. self is the object saying "my".

Why do we need it?

Many objects share one class. When s1.greet() runs, Python must know to use s1's name, not s2's.

Example · Using self
Python
class Student:
    def __init__(self, name):
        self.name = name            # save data on the object

    def greet(self):
        print("Hi, I am", self.name)

    def greet_twice(self):
        self.greet()                # call another method
        self.greet()

s = Student("Rahul")
s.greet_twice()
Student.greet(s)                    # same as s.greet()
Output 
Hi, I am Rahul
Hi, I am Rahul
Hi, I am Rahul
How It Works
  1. Student("Rahul") runs __init__. self is the new object.
  2. self.name = name stores the name inside that object.
  3. s.greet_twice() passes s in as self.
  4. self.greet() calls another method on the same object.
  5. Student.greet(s) proves it: s.greet() is just shorthand for this.

Proof that self really is the object:

Python
class Demo:
    def who(self):
        return self

d = Demo()
print(d.who() is d)
Output
True

The naming conflict

In self.name = name, the left side is the object's attribute. The right side is the parameter. They have the same name but are different things.

Python (Expected Error)
class Student:
    def __init__(self, name):
        name = name            # forgot self.!

s = Student("Rahul")
print(s.name)
Expected Error
AttributeError: 'Student' object has no attribute 'name'

Why? name = name only changes a temporary local variable. Nothing is saved on the object.

self in Python vs this in Java/C++

  • In Java and C++, this is a keyword. It is automatic. You never write it in the method's parameter list.
  • In Python, self is not a keyword. It is a normal first parameter that you must write.
  • Python fills it in for you when you call obj.method().
  • You could name it anything, but always use self. Everyone expects it.
Python (Expected Error)
class Student:
    def greet():              # forgot self
        print("hi")

Student().greet()
Expected Error
TypeError: Student.greet() takes 0 positional arguments but 1 was given

Why? Python passed the object in automatically, but the method had no parameter to receive it.

10

Instance vs Class Variables

Data can belong to one object or to the whole class.

🧍 Instance variable

  • Belongs to one object.
  • Made with self.name = ....
  • Each object has its own copy.

🏫 Class variable (static)

  • Belongs to the class, shared by all objects.
  • Written directly inside the class.
  • One copy only.
Python
class Student:
    school = "CodeVerse School"   # class variable
    count = 0                      # class variable

    def __init__(self, name):
        self.name = name              # instance variable
        Student.count += 1

s1 = Student("Rahul")
s2 = Student("Riya")

print(Student.count)
print(s1.school)
print(s2.school)

Student.school = "New School"
print(s1.school)
Output
2
CodeVerse School
CodeVerse School
New School
  • count grows each time any student is created. It is shared.
  • Changing Student.school changes it for everyone.
💡 Think Before You Code

Continuing from above, what prints?

s1.school = "X"
print(s1.school, s2.school, Student.school)
Show Answer

X New School New School

Writing s1.school = "X" does not change the class variable. It creates a new instance variable on s1 that hides the shared one. The others still see the class value.

11

Class Methods and Static Methods

Not every method needs self. Python has three kinds of methods.

instance
Normal method. First parameter self. Works on one object.
@classmethod
First parameter cls (the class). Works on the class.
@staticmethod
No self or cls. Just a helper placed inside the class.
Python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, text):
        name, age = text.split("-")
        return cls(name, int(age))

    @staticmethod
    def is_adult(age):
        return age >= 18

s = Student.from_string("Riya-19")
print(s.name, s.age)
print(Student.is_adult(20))
print(Student.is_adult(15))
Output
Riya 19
True
False

How it works

  • from_string is an alternative constructor. It builds a Student from text like "Riya-19". This is Python's answer to constructor overloading.
  • cls(name, int(age)) is the same as Student(...).
  • is_adult needs no object data, so it is a static method.

Static vs Instance members

🏫 Static / class-level

  • Shared by all objects.
  • Use for counters, settings, helpers.
  • Can be used without creating an object.

🧍 Instance-level

  • Different for every object.
  • Use for personal data (name, balance).
  • Needs an object.
⚠️ When NOT to use static

Do not make something static just to avoid creating objects. If it needs one object's data (like a balance), it must be an instance member.

Part C · Encapsulation
12

Encapsulation

ENCAPSULATION
Bundling data and the methods that use it into one class, and controlling who can touch the data.
Example: you change a balance only through deposit() and withdraw().
💡 Real life → Programming → Code
  • Real life: an ATM. You press buttons (deposit, withdraw). You cannot reach inside and grab the cash.
  • Programming: keep data private. Offer safe public methods.
  • Code: see below.

Why exposing everything is dangerous

Python (no protection)
class BadAccount:
    def __init__(self, balance):
        self.balance = balance

acc = BadAccount(1000)
acc.balance = -5000        # anyone can do this!
print(acc.balance)
Output (invalid data accepted)
-5000

A bank balance of -5000 set directly, with no checks. That is a real bug waiting to happen.

The fix: private data + public methods

Python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance      # private

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
        else:
            print("Invalid amount")

    def withdraw(self, amount):
        if amount > self.__balance:
            print("Insufficient funds")
        else:
            self.__balance -= amount

    def get_balance(self):
        return self.__balance

acc = BankAccount("Riya", 1000)
acc.deposit(500)
acc.withdraw(2000)
print(acc.get_balance())
acc.deposit(-10)
Output
Insufficient funds
1500
Invalid amount

How it works

  1. The balance __balance is private. Outside code should not touch it.
  2. deposit and withdraw are the only doors. Each door has a guard (the if checks).
  3. Withdrawing 2000 from 1500 is rejected. The balance stays 1500.
  4. A negative deposit is rejected too.
Encapsulation: safe doors, locked data

Green: allowed route. Red: blocked direct access.

Benefits

  • Safety — data cannot be set to nonsense.
  • Validation — every change goes through checks.
  • Freedom to change — you can rewrite the inside without breaking outside code.
  • Simple use — others only learn the public methods.
13

Access Levels and @property

Other languages have keywords like private and public. Python uses naming conventions instead.

name
Public. Anyone can use it.
_name
"Protected" by convention. Means: internal use, please don't touch. Not enforced.
__name
"Private". Python renames it to make accidental access hard.
⚠️ Be honest about Python

Python does not truly lock data. It trusts programmers to follow the rules. A double underscore makes access awkward, not impossible.

Python
acc = BankAccount("Riya", 1500)

print(acc._BankAccount__balance)   # the renamed name
print(acc.__balance)                # the plain name
Output, then Expected Error
1500
AttributeError: 'BankAccount' object has no attribute '__balance'

Why? Python secretly renames __balance to _BankAccount__balance. This is called name mangling. The plain name no longer exists, but the mangled one does. Do not use it in real code. It is only to show how it works.

@property: the Pythonic getter and setter

A property looks like a normal attribute, but runs your code behind the scenes. You get validation without ugly get_x() calls.

Python
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks          # goes through the setter

    @property
    def marks(self):
        return self.__marks

    @marks.setter
    def marks(self, value):
        if 0 <= value <= 100:
            self.__marks = value
        else:
            raise ValueError("Marks must be between 0 and 100")

s = Student("Riya", 85)
print(s.marks)
s.marks = 90
print(s.marks)
s.marks = 150
Output, then Expected Error
85
90
ValueError: Marks must be between 0 and 100

How it works

  1. s.marks (reading) runs the getter method.
  2. s.marks = 90 (writing) runs the setter method.
  3. The setter checks the range. 150 is invalid, so it raises an error.
  4. Even __init__ uses the setter, so a bad starting value is caught too.
📌 Note on raise

raise stops the program with an error. You will study errors in detail in the exception-handling topic.

Part D · Inheritance
14

Inheritance

INHERITANCE
A new class gets all features of an existing class automatically, and can add its own.
Example: Car inherits from Vehicle.
💡 Real life → Programming → Code
  • Real life: a child inherits traits from parents.
  • Programming: a child class inherits from a parent class.
  • Code: class Car(Vehicle):

Why does inheritance exist?

  • Avoid copy-pasting shared code.
  • Fix a bug once, in the parent.
  • Model real "kind of" relationships.

Words you must know

  • Parent = base class = superclass.
  • Child = derived class = subclass.
Syntax 
class Child(Parent):
    # extra features of the child
Example
Python
class Vehicle:
    def __init__(self, brand):
        self.brand = brand

    def start(self):
        print(self.brand, "is starting")

class Car(Vehicle):
    def open_trunk(self):
        print("Trunk opened")

car = Car("Toyota")
car.start()
car.open_trunk()
Output 
Toyota is starting
Trunk opened
How It Works
  1. Car(Vehicle) says: Car inherits from Vehicle.
  2. Car has no __init__, so Python uses Vehicle's. That sets brand.
  3. car.start() is not in Car. Python looks in the parent and finds it there.
  4. open_trunk exists only in Car. It is the child's own extra.
Inheritance: Car IS-A Vehicle

The hollow arrow points from child to parent.

Benefits

  • Reuse — shared code lives in one place.
  • Extend — children add new features.
  • Organize — classes form a clear family tree.

Limitations

  • Child and parent become tightly linked. Changing the parent can break children.
  • Deep family trees get hard to follow.
  • It is easy to misuse. See Section 19.
15

Method Overriding

METHOD OVERRIDING
A child class writes its own version of a method that the parent already has. The child's version wins.
💡 Real-life analogy

Every animal can "make a sound". A parent says "some sound". A dog replaces that with "Woof". The action name is the same, the behavior differs.

Python
class Animal:
    def speak(self):
        print("Some sound")

class Dog(Animal):
    def speak(self):
        print("Woof!")

class Cat(Animal):
    def speak(self):
        print("Meow!")

Animal().speak()
Dog().speak()
Cat().speak()
Output
Some sound
Woof!
Meow!

How it works

  1. Dog().speak() → Python looks in Dog first.
  2. It finds speak there and stops. The parent's version is never used.
  3. If Dog had no speak, Python would go up to Animal.
🧠 Rule

Python searches child first, then parent, then grandparent. The first match wins.

16

super()

super()
A way for the child to reach the parent: to call the parent's constructor or the parent's version of a method.

Why do we need it?

  • The child has its own __init__, but the parent's __init__ still has setup to do.
  • You want to add to the parent's method, not throw it away.
Python
class Person:
    def __init__(self, name):
        print("Person constructor")
        self.name = name

    def intro(self):
        print("I am", self.name)

class Student(Person):
    def __init__(self, name, roll):
        super().__init__(name)
        print("Student constructor")
        self.roll = roll

    def intro(self):
        super().intro()
        print("My roll number is", self.roll)

s = Student("Rahul", 101)
s.intro()
Output
Person constructor
Student constructor
I am Rahul
My roll number is 101
Execution trace: who calls what

How it works, step by step

  1. The child's __init__ runs first.
  2. super().__init__(name) jumps to the parent's __init__.
  3. The parent finishes ("Person constructor" prints), then control comes back.
  4. The child continues ("Student constructor" prints).
  5. In intro(), super().intro() runs the parent's version first, then the child adds one more line.
🧠 Order to remember

The parent part runs where you write super().__init__(). Usually that is the first line, so the parent sets up first.

💡 Think Before You Code

What happens if the child forgets to call super().__init__()?

class Student2(Person):
    def __init__(self, name, roll):
        self.roll = roll        # no super() call

t = Student2("Rahul", 1)
print(t.roll)
print(t.name)
Show Answer

Output: 1, then an Expected Error:

AttributeError: 'Student2' object has no attribute 'name'

The parent's __init__ never ran, so name was never created. Python does not call the parent constructor for you once the child defines its own.

17

Types of Inheritance

The shape of the family tree gives the inheritance a name.

Five shapes (top = parent, bottom = child)

Python supports all five directly. Some languages (like Java) do not allow multiple inheritance of classes.

1. Single: one parent, one child

You already saw it: Car(Vehicle).

2. Multilevel: a chain

Python
class Animal:
    def eat(self):
        print("Eating")

class Dog(Animal):
    def bark(self):
        print("Barking")

class Puppy(Dog):
    def weep(self):
        print("Weeping")

p = Puppy()
p.eat()
p.bark()
p.weep()
Output
Eating
Barking
Weeping

Puppy gets everything from Dog and from Animal above it.

3. Hierarchical: one parent, many children

Python
class Vehicle:
    def move(self):
        print("Moving")

class Car(Vehicle):
    def honk(self):
        print("Honk!")

class Bike(Vehicle):
    def ring(self):
        print("Ring!")

Car().move()
Car().honk()
Bike().move()
Bike().ring()
Output
Moving
Honk!
Moving
Ring!

Both children share move(). Each adds its own extra.

4 and 5: Multiple and Hybrid

These get their own section next, because they bring a new question: which parent wins?

18

Multiple Inheritance and MRO

MULTIPLE INHERITANCE
A class has more than one parent.
Example: class Child(Father, Mother)
Python
class Father:
    def skills(self):
        print("Gardening")

class Mother:
    def skills(self):
        print("Cooking")

class Child(Father, Mother):
    pass

Child().skills()
print([c.__name__ for c in Child.__mro__])
Output
Gardening
['Child', 'Father', 'Mother', 'object']

What is MRO?

MRO = Method Resolution Order. It is the exact order in which Python searches classes for a method.

  • Search order here: Child → Father → Mother → object.
  • Father is listed first, so its skills() wins.
  • Every class ends with object, Python's ultimate parent.

The diamond problem

What if two parents share the same grandparent, and both override a method?

Python
class A:
    def show(self):
        print("A")

class B(A):
    def show(self):
        print("B")

class C(A):
    def show(self):
        print("C")

class D(B, C):
    pass

D().show()
print([c.__name__ for c in D.__mro__])
Output
B
['D', 'B', 'C', 'A', 'object']

How it works

  1. Python builds the MRO: D, B, C, A, object.
  2. It searches left to right. D has no show.
  3. Next is B. It has show. Python stops and prints "B".
  4. Python's rule guarantees a class always comes before its own parents. So A is checked last.
💡 Think Before You Code

If we change the line to class D(C, B):, what prints?

Show Answer

C. The order of parents decides the MRO. Now it is D, C, B, A, object, so C.show is found first.

📌 Interview Tip

Python solves the diamond problem with MRO (the C3 linearization rule). You can always check it with ClassName.__mro__.

⚠️ Use carefully

Multiple inheritance is powerful but confusing. For beginners, prefer single inheritance or composition (Section 28). Use multiple inheritance mainly for small "mixin" or interface-style classes.

IS-A, isinstance and When Not to Inherit

IS-A RELATIONSHIP
If you can say "X is a Y" and it is truly correct, X can inherit from Y.
A Car is a Vehicle. A Dog is an Animal.

Python lets you test it:

Python
car = Car("Toyota")
print(isinstance(car, Car))
print(isinstance(car, Vehicle))
print(isinstance(car, Animal))
print(issubclass(Car, Vehicle))
print(issubclass(Vehicle, Car))
Output

False

  • isinstance(obj, Class) → is this object of that class, or a child of it?
  • issubclass(A, B) → is class A a child of class B?
  • The relationship goes one way. A Car is a Vehicle, but a Vehicle is not necessarily a Car.

When NOT to use inheritance

❌ Wrong: Car inherits Engine

A Car is not an Engine. A Car has an Engine. That is composition (Section 28).

❌ Wrong: inherit just to copy a method

If there is no real "is a" link, do not inherit. Share code another way.

✅ Good: Dog inherits Animal

A Dog really is an Animal. It reuses and extends animal behavior.

🧠 The test

Say it aloud: "Child IS-A Parent". If it sounds silly, do not inherit.

Part E · Polymorphism

Polymorphism

POLYMORPHISM
"Poly" = many, "morph" = forms. One action, many forms. The same method name behaves differently for different objects.
💡 Real life → Programming → Code
  • Real life: press the "play" button. On a music app it plays a song. On a video app it plays a movie. Same button, different result.
  • Programming: call speak() on any animal. Each animal does its own thing.
  • Code: see below.

Why do we need it?

You write one loop that works for every type. No giant if dog... elif cat... chains. Adding a new animal needs no change to the loop.

Python
# Animal, Dog, Cat from Section 15
animals = [Dog(), Cat(), Animal()]

for a in animals:
    a.speak()
Output
Woof!
Meow!
Some sound

How it works

  1. The loop sees each item only as "something with speak()".
  2. For the first item, Python checks its real class (Dog) and runs Dog.speak.
  3. The same line a.speak() runs a different method each time.
  4. This is decided while the program runs, so it is called runtime polymorphism.
Same call, different behavior
💡 Think Before You Code

We add a new class. What will the loop print now?

class Cow(Animal):
    def speak(self):
        print("Moo!")

for a in [Cow(), Dog()]:
    a.speak()
Show Answer

Moo! then Woof!

The loop code did not change at all. That is the power of polymorphism: new types plug in without editing old code.

Two kinds of polymorphism

⏱️ Runtime (dynamic)

Decided while running. Done by overriding and duck typing. Python does this fully.

🛠️ Compile-time (static)

Decided before running, mainly by method overloading (Java, C++). Python has no compile step for this, so it works differently (Section 22).

Duck Typing

💡 The saying

"If it walks like a duck and quacks like a duck, it is a duck." Python cares about what an object can do, not what class it came from.

Overloading vs Overriding

These two sound alike. They are completely different.

🔁 Overriding

  • Happens between parent and child classes.
  • Same name, same parameters.
  • The child replaces the parent's version.
  • Decided at runtime.
  • Fully supported in Python.

🧮 Overloading

  • Happens inside one class.
  • Same name, different parameters.
  • Many versions exist side by side.
  • Decided at compile time (Java, C++).
  • Not built in to Python. Use defaults or *args.
🧠 Memory trick

Over-RIDE = ride over the parent's method. Over-LOAD = load many versions into one class.

Part F · Abstraction and Interfaces
25

Abstraction

ABSTRACTION
Showing only the essential features of something, and hiding the complicated details behind it.
Example: you call pay(). You don't care how a card network works inside.
💡 Real life → Programming → Code
  • Real life: driving a car. You use the steering wheel and pedals. You don't need to understand the engine.
  • Programming: define what an object must do, and leave how to each class.
  • Code: an abstract class with abstract methods.

Why do we need it?

  • Code that uses an object only needs its simple promise (pay()).
  • You can swap the inside without breaking the outside.
  • It forces every child class to implement the required methods.

Abstract classes in Python

  • Import ABC and abstractmethod from the abc module.
  • Inherit from ABC.
  • Mark required methods with @abstractmethod.
  • You cannot create an object of an abstract class.
Python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

    def receipt(self):                # a normal method, shared
        print("Thank you for your payment!")

class CreditCard(Payment):
    def pay(self, amount):
        print("Paid", amount, "using Credit Card")

class UPI(Payment):
    def pay(self, amount):
        print("Paid", amount, "using UPI")

def checkout(method, amount):
    method.pay(amount)
    method.receipt()

checkout(CreditCard(), 500)
checkout(UPI(), 250)
Output
Paid 500 using Credit Card
Thank you for your payment!
Paid 250 using UPI
Thank you for your payment!

How it works

  1. Payment is the promise: "every payment method can pay()".
  2. CreditCard and UPI keep the promise in their own way.
  3. checkout() knows only about Payment. It never needs to know which kind it got.
  4. Adding a new method (say, Wallet) needs no change to checkout().
  5. receipt() is shared code. Abstract classes can mix required and ready-made methods.
Abstraction: one promise, many ways

What Python protects you from

Python (Expected Error)
p = Payment()
Expected Error
TypeError: Can't instantiate abstract class Payment without an implementation for abstract method 'pay'

Why? An abstract class is only a plan. It has nothing real to run, so Python refuses to build an object from it. (The wording is slightly different in older Python versions.)

💡 Think Before You Code

A child forgets to write pay(). What happens?

class Cash(Payment):
    pass

Cash()
Show Answer

Expected Error:

TypeError: Can't instantiate abstract class Cash without an implementation for abstract method 'pay'

The child must implement every abstract method before objects can be created. This catches mistakes early.

Encapsulation vs Abstraction

Students mix these up all the time. They are different ideas with different goals.

🔒 Encapsulation

  • Goal: protect and control the data.
  • How: private attributes, validation in methods.
  • Question it answers: "Who may change this value?"
  • Example: __balance with deposit().

🎭 Abstraction

  • Goal: expose only the essential behavior.
  • How: abstract classes, interfaces, simple method names.
  • Question it answers: "What does this do, without the details?"
  • Example: Payment.pay().
🧠 One-line memory trick

Encapsulation hides data. Abstraction hides complexity. A car's locked fuel tank is encapsulation. The steering wheel that hides the engine is abstraction.

Interfaces in Python

INTERFACE
A contract: a list of methods that a class promises to provide. It says what, never how.

Python has no interface keyword

Java has interface. Python does not. Python offers these alternatives instead:

  • ABC with only abstract methods → the closest match to a Java interface.
  • Duck typing → no formal contract. Just "have the method".
  • typing.Protocol → a contract checked by type-checking tools (advanced, optional).

An interface using ABC

Python
from abc import ABC, abstractmethod

class Flyable(ABC):
    @abstractmethod
    def fly(self):
        pass

class Swimmable(ABC):
    @abstractmethod
    def swim(self):
        pass

class Duck(Flyable, Swimmable):
    def fly(self):
        print("Duck flies")

    def swim(self):
        print("Duck swims")

d = Duck()
d.fly()
d.swim()
print(isinstance(d, Flyable), isinstance(d, Swimmable))
Output
Duck flies
Duck swims
True True

How it works

  • Each interface is a tiny contract with one method.
  • Duck signs both contracts by listing both parents.
  • This is how Python gives you "multiple interfaces" safely.
  • A Fish class could implement only Swimmable.

Abstract class vs Interface

🧱 Abstract class

  • Mix of abstract and ready-made methods.
  • Can hold data (attributes) and a constructor.
  • Best for a family of related classes sharing code.
  • Example: Payment with receipt().

📜 Interface

  • Only abstract methods. No shared code.
  • A pure ability contract.
  • Unrelated classes can share it.
  • Example: Flyable.
📌 Honest note

In Python this difference is a design habit, not a language rule. Both use ABC. The decision is: "does it share code (abstract class) or only a promise (interface)?"

Part G · Relationships Between Objects
28

Association, Aggregation, Composition

Objects rarely live alone. They connect to other objects. There are three main kinds of "uses" and "has" links.

Relationship map (UML-style)

1. Association: "uses" or "knows"

Two independent objects work together. Neither owns the other.

💡 Real life

A teacher teaches a student. Both exist before and after the lesson.

Python
class Student:
    def __init__(self, name):
        self.name = name

class Teacher:
    def __init__(self, name):
        self.name = name

    def teach(self, student):
        print(self.name, "is teaching", student.name)

Teacher("Mr. Sharma").teach(Student("Rahul"))
Output
Mr. Sharma is teaching Rahul

The student is passed in to a method. The teacher does not keep or own it.

2. Aggregation: weak HAS-A

One object holds others, but the parts can exist without it.

💡 Real life

A department has teachers. If the department closes, the teachers still exist and can join another one.

Python
class Department:
    def __init__(self, name, teachers):
        self.name = name
        self.teachers = teachers          # created OUTSIDE, passed in

t1 = Teacher("Mr. Sharma")
t2 = Teacher("Ms. Rao")

cs = Department("CS", [t1, t2])
print(len(cs.teachers))

del cs                                # department is gone
print(t1.name)                          # teacher still exists
Output
2
Mr. Sharma

The teachers were created outside and handed in. Deleting the department does not delete them.

3. Composition: strong HAS-A

One object owns its parts. It creates them, and they live and die with it.

💡 Real life → Programming → Code
  • Real life: a car has an engine built into it.
  • Programming: Car contains an Engine object it created itself.
  • Code: self.engine = Engine() inside Car.__init__.
Python
class Engine:
    def start(self):
        print("Engine started")

class Car:
    def __init__(self, brand):
        self.brand = brand
        self.engine = Engine()            # Car CREATES its own Engine

    def start(self):
        print(self.brand, "starting...")
        self.engine.start()

car = Car("Toyota")
car.start()
Output
Toyota starting...
Engine started

How it works

  1. Car("Toyota") runs __init__.
  2. Inside it, Engine() is created. The car owns that engine.
  3. car.start() asks its engine to start. This is delegation.
  4. When the car object is gone, its engine goes too.

The quick test

Association

Is the other object only passed in temporarily? → association.

Aggregation

Is it stored, but created outside and able to live alone? → aggregation.

Composition

Is it created inside and meaningless without the owner? → composition.

📌 Interview Tip

The key difference between aggregation and composition is lifetime and ownership. In Python this shows up as "created outside and passed in" vs "created inside __init__".

29

IS-A vs HAS-A

🧬 IS-A (inheritance)

  • "A Car is a Vehicle."
  • Written as class Car(Vehicle).
  • Child gets the parent's features.

🧩 HAS-A (composition / aggregation)

  • "A Car has an Engine."
  • Written as self.engine = Engine().
  • One object holds another as a part.

Inheritance vs Composition

Inheritance

  • Tight link between parent and child.
  • Fixed at the time you write the class.
  • Use for a true "kind of" relationship.

Composition

  • Loose link. Parts can be swapped.
  • Can change while the program runs.
  • Use for a "made of" relationship.
🧠 A famous design rule

"Favor composition over inheritance." When unsure, build objects from smaller parts. Use inheritance only when the IS-A sentence is clearly true.

Special (Dunder) Methods

DUNDER METHOD
A method with double underscores on both sides, like __init__. Python calls it automatically in special situations.

You never call them directly. Python does it for you when you use print(), len(), + and so on.

class Book:
    def __init__(self, title):

Object Lifecycle

Every object goes through three stages.

  1. Creation — Python makes the object, then runs __init__.
  2. Use — you call methods and read attributes.
  3. Destruction — when nothing refers to it any more, Python frees its memory.

This cleanup is called garbage collection. You do not free memory by hand in Python.

Python
class Temp:
    def __init__(self):
        print("Created")

    def __del__(self):
        print("Destroyed")

t = Temp()
del t
print("End")
Output (standard CPython)
Created
Destroyed
End

How it works

  1. Temp() creates the object. "Created" prints.
  2. del t removes the name t. No names point to the object now.
  3. Python counts references. At zero, it destroys the object and calls __del__.
⚠️ Do not depend on __del__

Exact timing can differ between Python versions and implementations. Use it only to learn, or for rare cleanup. For files and connections, prefer with blocks.

Dataclasses

Some classes only store data. Writing __init__, __repr__ and __eq__ every time is boring. A dataclass writes them for you.

Python
from dataclasses import dataclass

@dataclass
class Student:
    name: str
    age: int

s = Student("Riya", 19)

  • You get __init__, a nice print and == for free.

💡 Think Before You Code

Savings starts at 5000 and gets +1000. Current starts at 2000, has a 1000 overdraft limit. We withdraw 7000 from savings, 2500 from current, then 100 from each. Predict the final balances.

Show Answer

  • Current: 2000. Withdrawing 2500 is allowed (limit is balance + 1000 = 3000) → -500. Then -100 → -600.

The complete code

Show complete code (bank_system.py)
bank_system.py
from abc import ABC, abstractmethod


class Account(ABC):
    bank_name = "CodeVerse Bank"
    total_accounts = 0

    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance
        Account.total_accounts += 1

    @property
    def balance(self):
        return self.__balance

    def deposit(self, amount):
        if amount <= 0:
            print("Deposit must be positive")
        else:
            self.__balance += amount

    def _reduce(self, amount):
        self.__balance -= amount

    @abstractmethod
    def withdraw(self, amount):
        pass

    def __str__(self):
        return f"{type(self).__name__}({self.owner}): Rs. {self.__balance}"


class SavingsAccount(Account):
    def withdraw(self, amount):
        if amount > self.balance:
            print("Insufficient funds")
        else:
            self._reduce(amount)


class CurrentAccount(Account):
    overdraft_limit = 1000

    def withdraw(self, amount):
        if amount > self.balance + self.overdraft_limit:
            print("Overdraft limit exceeded")
        else:
            self._reduce(amount)


class Customer:
    def __init__(self, name):
        self.name = name
        self.accounts = []

    def open_account(self, account_type, amount=0):
        account = account_type(self.name, amount)
        self.accounts.append(account)
        return account


class Bank:
    def __init__(self, name):
        self.name = name
        self.customers = []

    def add_customer(self, customer):
        self.customers.append(customer)

    def total_money(self):
        return sum(acc.balance for c in self.customers for acc in c.accounts)


bank = Bank("CodeVerse Bank")
riya = Customer("Riya")
bank.add_customer(riya)

savings = riya.open_account(SavingsAccount, 5000)
current = riya.open_account(CurrentAccount, 2000)

savings.deposit(1000)
savings.withdraw(7000)
current.withdraw(2500)

for acc in riya.accounts:
    acc.withdraw(100)

for acc in riya.accounts:
    print(acc)

print("Total money:", bank.total_money())
print("Accounts opened:", Account.total_accounts)
print("Bank:", Account.bank_name)
Output
Insufficient funds
SavingsAccount(Riya): Rs. 5900
CurrentAccount(Riya): Rs. -600
Total money: 5300
Accounts opened: 2
Bank: CodeVerse Bank

How it works

  1. The Account base class keeps __balance private and exposes it read-only through a property.
  2. Children cannot touch __balance directly. They use the protected helper _reduce(). This keeps one safe door.
  3. Each child writes its own withdraw() rule. That is overriding.
  4. for acc in riya.accounts: acc.withdraw(100) is polymorphism. One call, two behaviors.
  5. Customer.open_account() creates the account inside, so the customer owns it.
  6. Bank.total_money() adds up balances through nested loops over customers and accounts.
🧠 Notice

No single idea made this design good. It is the combination: abstraction for the contract, inheritance for sharing, encapsulation for safety, polymorphism for flexibility, composition for structure.

Common Beginner Mistakes

❌ Wrong: Using the class instead of an object
class Dog:
    def bark(self):
        print("Woof")

Dog.bark()
Expected Error
TypeError: Dog.bark() missing 1 required positional argument: 'self'
✅ Correct: create an object first: Dog().bark()

Why? bark needs an object to be self. The blueprint alone has none.

❌ Wrong: A shared list as a class variable
class Cart:
    items = []          # shared by ALL carts!

c1 = Cart()
c2 = Cart()
c1.items.append("pen")
print(c2.items)
Surprising output
['pen']
✅ Correct: create it per object in __init__: self.items = []

Why? One list belongs to the class, so every object sees the same one.

❌ Wrong: A mutable default argument
class Cart:
    def __init__(self, items=[]):
        self.items = items

a = Cart()
a.items.append(1)
b = Cart()
print(b.items)
Surprising output
[1]
✅ Correct: def __init__(self, items=None): then self.items = items or []

Why? Python builds the default [] once and reuses it for every call.

❌ Wrong: Expecting == to compare contents
class P:
    def __init__(self, x):
        self.x = x

print(P(1) == P(1))
Output
False
✅ Correct: define __eq__, or use a @dataclass

Why? By default, == asks "are these the very same object?"

❌ Wrong: Printing an object with no __str__
print(P(1))
Output (address differs)
<__main__.P object at 0x7f...>
✅ Correct: add a __str__ method

More mistakes, already covered

  • Forgetting self in a method or in self.name = name (Section 9).
  • Misspelling __init__ (Section 8).
  • Forgetting super().__init__() (Section 16).
  • Expecting method overloading or constructor overloading in Python (Sections 8 and 22).
  • Breaking encapsulation with public data and no checks (Section 12).
  • Inheriting when it is really HAS-A, such as Car(Engine) (Section 19).
  • Creating an object of an abstract class (Section 25).

Interview Preparation

Tap a question to see a short, interview-ready answer.

🟢 Basic

1. What is OOP?

A way of programming where software is built from objects, each bundling data and the methods that work on it. It helps organize, reuse and protect code in big programs.

2. What are the four pillars of OOP?
  • Encapsulation — bundle and protect data.
  • Inheritance — reuse and extend classes.
  • Polymorphism — same action, different behavior.
  • Abstraction — expose essentials, hide details.
3. What is a class? What is an object?

A class is a blueprint. An object is an instance created from it, with its own data. One class can make many objects.

4. Why do we need OOP?

It keeps related data and behavior together, protects data, allows code reuse through inheritance, and makes large programs easier to change and understand.

5. What is self in Python?

The object itself, passed automatically as the first parameter of instance methods. It lets a method reach that object's data. It is a convention, not a keyword.

Interview Tip

Mention that obj.method() is shorthand for Class.method(obj).

🟡 Intermediate

6. Constructor vs method?

A constructor (__init__) runs automatically once when an object is created, to set up its data. A method runs when you call it, any number of times, to perform an action.

7. Does Python support constructor overloading?

No. Only one __init__ is kept. Use default arguments, *args, or a @classmethod alternative constructor instead.

8. Encapsulation vs abstraction?

Encapsulation controls access to data (private attributes, validation). Abstraction hides complexity and exposes only essential behavior (abstract classes, interfaces).

9. What types of inheritance exist?

Single, multilevel, hierarchical, multiple and hybrid. Python supports all of them directly.

10. Overloading vs overriding?

Overriding: a child replaces a parent's method (same name and parameters). Runtime. Supported in Python. Overloading: same name, different parameters in one class. Not built into Python; use defaults or *args.

11. What does super() do?

It gives access to the parent class, so the child can call the parent's constructor or methods, for example super().__init__(name).

Interview Tip

Add that Python does not auto-call the parent constructor once the child defines its own __init__.

12. Does Python have private variables?

Not truly. A single underscore means "internal, by convention". A double underscore triggers name mangling, which makes accidental access harder but not impossible.

🔴 Advanced

13. Composition vs inheritance?

Inheritance models IS-A with a tight link. Composition models HAS-A with a looser link and swappable parts. Prefer composition unless the IS-A sentence is clearly true.

14. Association vs aggregation vs composition?
  • Association: objects use each other, independent.
  • Aggregation: weak HAS-A. Parts exist without the whole.
  • Composition: strong HAS-A. Parts are owned and die with the whole.
15. What is runtime polymorphism?

The exact method that runs is chosen while the program runs, based on the object's real class. In Python it comes from method overriding and duck typing.

16. Abstract class vs interface?

An abstract class can mix abstract and ready-made methods and hold data. An interface is a pure contract of abstract methods. Python has no interface keyword, so interfaces are written as ABCs with only abstract methods.

17. What is MRO and the diamond problem?

MRO (Method Resolution Order) is the order Python searches classes for a method. The diamond problem is when two parents share a grandparent. Python solves it with the C3 order, viewable by Class.__mro__.

18. @classmethod vs @staticmethod vs instance method?

Instance: gets self, works on one object. Class method: gets cls, works on the class (often alternative constructors). Static method: gets neither, just a helper placed in the class.

19. __str__ vs __repr__?

__str__ is readable text for users (used by print). __repr__ is precise text for developers (used in lists and debugging).

20. What is duck typing?

Python cares about what an object can do, not its class. If it has the needed method, it works. It gives polymorphism without inheritance.

Important differences

  • Class vs object: blueprint vs thing made from it.
  • Constructor vs method: automatic once vs called by you.
  • Overriding vs overloading: parent-child replace vs same name different parameters.
  • Encapsulation vs abstraction: protect data vs hide complexity.
  • IS-A vs HAS-A: inheritance vs composition.
  • Abstract class vs interface: shared code allowed vs pure contract.
  • Instance vs class variable: per object vs shared.

Top mistakes to avoid

  • Forgetting self or super().__init__().
  • Putting a list as a class variable or default argument.
  • Using the class instead of an object.
  • Inheriting when it should be HAS-A.

Key Points to Remember

  • OOP groups data and behavior into objects, so large programs stay organized.
  • A class is a blueprint. Objects are built from it, each with its own data.
  • __init__ sets up a new object. self is that object.
  • Encapsulation protects data with private attributes and validated methods.
  • Inheritance models IS-A. super() reaches the parent. MRO decides the search order.
  • Polymorphism lets one call behave differently. Python does it by overriding and duck typing.
  • Python has no true overloading. Use default arguments or *args.
  • Abstraction defines what (ABC, abstract methods). Classes decide how.
  • Composition (HAS-A) is often better than inheritance. Prefer it when unsure.
  • Python's privacy is by convention. Name mangling only discourages access.
  • Add __str__ to classes you print, and use dataclasses for simple data holders.

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance
        self.__history = []
    def deposit(self, a):
        if a > 0:
            self.__balance += a
            self.__history.append(("deposit", a))
    def withdraw(self, a):
        if 0 < a <= self.__balance:
            self.__balance -= a
            self.__history.append(("withdraw", a))
        else:
            print("Not allowed")
    def get_balance(self):
        return self.__balance
    def get_history(self):
        return list(self.__history)   # a copy

Start 100, deposit 50, withdraw 500 (prints "Not allowed"), withdraw 30 → balance 120, history [('deposit', 50), ('withdraw', 30)]. Returning a copy stops outsiders from changing the real list.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): pass
    def describe(self):
        print(type(self).__name__, "with area", self.area())

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return round(3.14159 * self.r ** 2, 2)

class Rect(Shape):
    def __init__(self, w, h): self.w = w; self.h = h
    def area(self): return self.w * self.h
