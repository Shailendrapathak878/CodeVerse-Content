Topic Introduction

Your program asks for a number, and the user types "abc". What happens?

Without a plan, Python crashes and shows a scary red message. With exception handling, you catch the problem and respond politely.

Good programs do not stop when something goes wrong. They expect problems and handle them.

💡 What you'll learn
  • The difference between errors and exceptions
  • Read an error message (traceback)
  • Catch errors with try and except
  • Use else and finally
  • Create your own errors with raise
  • Build custom exceptions
Part A · Catching Errors
03

Types of Errors

Beginners meet three kinds of problems in code.

✏️ Syntax Error

You broke the grammar of Python. The program does not even start. Example: a missing colon.

💥 Runtime Error (Exception)

The code is valid, but something goes wrong while running. Example: dividing by zero.

🧮 Logical Error

The program runs, but gives the wrong answer. Python cannot warn you. Example: using + instead of *.

if 5 > 3
    print("Yes")
Syntax error: found before running
SyntaxError: expected ':'
🧠 Remember this

Exception handling is for runtime errors. You fix syntax and logical errors by correcting your code.

04

What is an Exception?

EXCEPTION
An event that stops the normal flow of your program when something goes wrong while it is running.
Example: 10 / 0 raises a ZeroDivisionError.
💡 Real-life analogy

You are driving to college and the road is blocked. You can crash, or you can take another road. Exception handling is your "another road".

Normal flow vs exception
print("Start")
print(10 / 0)
print("End")
Output
Start
Then the program stops with
ZeroDivisionError: division by zero
  • "Start" printed because it came before the error.
  • "End" never printed. The program stopped at the error.
05

Reading a Traceback

When an exception is not handled, Python prints a traceback. It is a map that shows where the error happened.

Python
def divide(a, b):
    return a / b

def calc():
    print(divide(10, 0))

calc()
Error
Traceback (most recent call last):
  File "main.py", line 7, in <module>
    calc()
  File "main.py", line 5, in calc
    print(divide(10, 0))
  File "main.py", line 2, in divide
    return a / b
ZeroDivisionError: division by zero

How to read it

  1. Start at the bottom. The last line has the error type and message.
  2. Look at the line just above it. That is where it happened.
  3. Go upward to see who called whom.
  • Here the error type is ZeroDivisionError.
  • It happened in divide, line 2.
  • divide was called by calc, which was called from the main program.
📌 Note

Newer Python versions also draw small ^ marks under the exact part of the line that failed.

Common Built-in Exceptions

Python has many ready-made exceptions. These are the ones you will see most.

ZeroDivisionError→Dividing by zero: 10 / 0
ValueError→Right type, wrong value: int("abc")
TypeError→Wrong type used: "5" + 3
NameError→Variable not defined: print(x)
IndexError→List position too big: [1, 2][5]
KeyError→Dictionary key missing: d["age"]
AttributeError→Thing has no such method: 5.append(1)
FileNotFoundError→File does not exist: open("x.txt")
ModuleNotFoundError→Module is not installed: import abc123
print(int("abc"))
print("5" + 3)
print([1, 2, 3][5])
print({"a": 1}["b"])
The error each line raises (one at a time)
ValueError: invalid literal for int() with base 10: 'abc'
TypeError: can only concatenate str (not "int") to str
IndexError: list index out of range
KeyError: 'b'
07

try and except

Concept

Put risky code inside a try block. If an error happens, Python jumps to the except block instead of crashing.

Syntax
try:
    # risky code
except ErrorType:
    # what to do if that error happens
Example
Python
print("Start")

try:
    result = 10 / 0
    print(result)
except ZeroDivisionError:
    print("You cannot divide by zero")

print("End")
Output
Start
You cannot divide by zero
End
Easy Explanation
  • 10 / 0 raised an error inside try.
  • Python skipped the rest of the try block. print(result) never ran.
  • It jumped to except and printed our message.
  • The program continued and printed "End".
🧠 Remember this

If no error happens, the except block is simply skipped.

08

Catching a Specific Exception

An except block only catches the exact type you write. Other errors pass through.

try:
    number = int("abc")
except ZeroDivisionError:
    print("Divide error")
Not caught! The program crashes
ValueError: invalid literal for int() with base 10: 'abc'

We were ready for ZeroDivisionError, but a ValueError happened. So it was not caught.

The bare except

You can write except: with no type. It catches everything.

Python
try:
    number = int("abc")
except:
    print("Something went wrong")
Output
Something went wrong
⚠️ Avoid the bare except

It also hides real bugs and even stops Ctrl+C from working. Always name the exception you expect.

09

Multiple except Blocks

One try can have many except blocks. Python runs the first one that matches.

Python
def convert(value):
    try:
        return 100 / int(value)
    except ValueError:
        return "Not a number"
    except ZeroDivisionError:
        return "Cannot divide by zero"

print(convert("5"))
print(convert("abc"))
print(convert("0"))
Output
20.0
Not a number
Cannot divide by zero
  • "5" worked, so no except ran.
  • "abc" caused a ValueError.
  • "0" caused a ZeroDivisionError.

One except for several errors

Put the types inside brackets to handle them the same way.

Python
for item in ["10", None, "x"]:
    try:
        print(int(item))
    except (ValueError, TypeError):
        print("Bad value:", item)
Output
10
Bad value: None
Bad value: x
  • int(None) raises a TypeError.
  • int("x") raises a ValueError.
  • Both are handled by the same line.
10

Getting the Error Message

Use as e to store the exception in a variable. Then you can print it or study it.

Python
try:
    int("abc")
except ValueError as e:
    print("Error:", e)
    print(type(e).__name__)
Output
Error: invalid literal for int() with base 10: 'abc'
ValueError
Python
student = {"name": "Riya"}

try:
    print(student["age"])
except KeyError as e:
    print("Missing key:", e)
Output
Missing key: 'age'
  • e holds the exception. e is just a habit, any name works.
  • type(e).__name__ gives the name of the error type.
  • Showing e helps you and your users understand what went wrong.
📌 Tip

To catch any normal error and still see its message, use except Exception as e:. It is better than a bare except:.

11

The else Block

Concept

The else block runs only when the try block finishes with no error.

Syntax
try:
    # risky code
except ErrorType:
    # runs if there was an error
else:
    # runs if there was NO error
Example
Python
for text in ["42", "abc"]:
    try:
        n = int(text)
    except ValueError:
        print(text, "is not a number")
    else:
        print("Great, you entered", n)
Output
Great, you entered 42
abc is not a number
Easy Explanation
  • "42" converted fine, so else ran.
  • "abc" failed, so except ran and else was skipped.
  • Keeping try short and putting the "success" code in else makes the code cleaner.
12

The finally Block

Concept

The finally block runs always: with an error, without an error, even if the error is not caught. Use it for cleanup, like closing a file.

Example
Python
try:
    print("Working...")
    x = 1 / 0
except ZeroDivisionError:
    print("Caught the error")
finally:
    print("Cleanup done")
Output
Working...
Caught the error
Cleanup done
Easy Explanation
  • The error was caught by except.
  • finally ran after that.
  • It would also run if there was no error.
🧠 Remember this

In Chapter 13 you used with open(...). It does the same job as a finally that closes the file for you.

13

The Complete Flow

Here is the full try structure. Follow the arrows.

try → except → else → finally
Python
def safe_divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("Cannot divide by zero")
        return None
    else:
        print("Division worked")
        return result
    finally:
        print("Done")

print(safe_divide(10, 2))
print(safe_divide(1, 0))
Output
Division worked
Done
5.0
Cannot divide by zero
Done
None
  • safe_divide(10, 2): try worked, then else, then finally.
  • safe_divide(1, 0): except ran, then finally.
  • finally printed "Done" before each result was printed.
Part B · Raising and Custom Exceptions
15

Raising Exceptions with raise

Concept

So far Python raised the errors. With raise, you raise an error when your own rule is broken.

Syntax
raise ExceptionType("your message")
Example
Python
def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

try:
    set_age(-5)
except ValueError as e:
    print("Error:", e)
Output
Error: Age cannot be negative
Easy Explanation
  • Python does not mind a negative age. Our rule does.
  • raise ValueError(...) stops the function and sends the error out.
  • The caller catches it with except and reads the message.

Re-raising an error

A bare raise inside except passes the same error upward after you do something with it.

Python
try:
    int("x")
except ValueError:
    print("Logging the error")
    raise
Output
Logging the error
Then the error continues upward
ValueError: invalid literal for int() with base 10: 'x'
16

The assert Statement

assert checks that something is True. If it is False, Python raises an AssertionError.

assert condition, "message if it fails"
Python
def average(nums):
    assert len(nums) > 0, "List is empty"
    return sum(nums) / len(nums)

print(average([2, 4, 6]))
print(average([]))
Output
4.0
Then
AssertionError: List is empty
⚠️ assert is for developers

Use assert to catch your own mistakes while building. Do not use it to check user input. Python can switch asserts off, so use if and raise for real checks.

17

Custom Exceptions

Sometimes the built-in names do not describe your problem well. You can make your own exception type.

📌 A small preview

This uses a class. You will learn classes later. For now, just copy this pattern.

class MyError(Exception):
    pass
  • Write class, then a name that ends with Error.
  • Put (Exception) in brackets. This makes it an exception.
  • Write pass because we need nothing else.
Python
class InsufficientFundsError(Exception):
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError("Not enough money")
    return balance - amount

try:
    print(withdraw(500, 200))
    print(withdraw(500, 800))
except InsufficientFundsError as e:
    print("Error:", e)
Output
300
Error: Not enough money
  • The first withdrawal worked and printed 300.
  • The second one raised our own InsufficientFundsError.
  • The name tells the reader exactly what went wrong.
18

The Exception Hierarchy

Exceptions are arranged like a family tree. A parent exception also catches all its children.

A small part of the family tree
Python
try:
    items = [1, 2, 3]
    print(items[10])
except LookupError:
    print("Lookup problem")
Output
Lookup problem
  • IndexError is a child of LookupError, so the parent caught it.
  • except Exception catches almost every normal error.
  • KeyboardInterrupt (Ctrl+C) is not under Exception, so it is not caught by it.
⚠️ Order matters

Python checks except blocks from top to bottom. Put specific exceptions first and general ones (like Exception) last. Otherwise the specific block never runs.

Real Examples

1. Ask until the input is valid

Python
while True:
    text = input("Enter a number: ")
    try:
        number = int(text)
        break
    except ValueError:
        print("That is not a number. Try again.")

print("You entered", number)
Sample run
Enter a number: abc
That is not a number. Try again.
Enter a number: 7
You entered 7
  • The loop repeats until int() works.
  • break leaves the loop only after a good value.

2. A safe file reader

Python
def read_file(name):
    try:
        with open(name) as f:
            return f.read()
    except FileNotFoundError:
        return "File not found"
    except PermissionError:
        return "No permission to open this file"

print(read_file("missing.txt"))
Output
File not found

3. Bad JSON data

Python
import json

try:
    data = json.loads("{bad json}")
except json.JSONDecodeError:
    print("Invalid JSON")
Output
Invalid JSON

This links back to Chapter 13. Data from files and websites can be broken, so always be ready.

Best Practices

❌ Hiding the problem

Writing except: pass. The error vanishes and you never learn about it.

✅ Handling it well

Catch a specific exception and print a helpful message or fix the problem.

  • Catch specific exceptions like ValueError, not everything.
  • Keep try blocks short. Only the risky line goes inside.
  • Write clear messages so the user knows what to do.
  • Never ignore errors silently.
  • Use finally or with for cleanup.
  • Do not catch an error you cannot handle. Let it go up.
Python
# Good: short try, specific error, helpful message
text = "12a"
try:
    age = int(text)
except ValueError:
    print("Please type digits only, like 25")
Output
Please type digits only, like 25
21

Common Beginner Mistakes

❌ Wrong: Using a bare except that hides bugs
try:
    total = 10 / int(text)
except:
    pass
✅ Correct: catch a specific error and show a message

A silent pass makes bugs very hard to find.

❌ Wrong: Putting the general except first
try:
    int("x")
except Exception:
    print("General")
except ValueError:
    print("Specific")
✅ Correct: put except ValueError above except Exception

The ValueError block can never run, because Exception catches it first.

❌ Wrong: Using the error variable without "as"
try:
    int("x")
except ValueError:
    print(e)
Error
NameError: name 'e' is not defined
✅ Correct: except ValueError as e:
❌ Wrong: Using a variable that was never created
try:
    value = int("abc")
except ValueError:
    print("Bad input")

print(value * 2)
Error
NameError: name 'value' is not defined
✅ Correct: give value a default, or use it only inside else

The error happened before value was created.

❌ Wrong: Raising a plain string
raise "Something went wrong"
Error
TypeError: exceptions must derive from BaseException
✅ Correct: raise ValueError("Something went wrong")
❌ Wrong: Putting too much code inside try
try:
    name = input("Name: ")
    age = int(input("Age: "))
    print("Hello", name)
    print(age + 1)
except ValueError:
    print("Error")
✅ Correct: keep only int(input("Age: ")) inside try

A big try makes it hard to know which line failed.

Quick Revision

Exception→An error that happens while the program runs
Traceback→The error report. Read it from the bottom up
try→Holds the risky code
except→Handles the error if one happens
except A as e→Stores the error in e
except (A, B)→Handles several error types together
else→Runs only when there was no error
finally→Runs always. Used for cleanup
raise→Creates an exception on purpose
assert→Raises AssertionError if a condition is False
Custom exception→class MyError(Exception): pass
Bare except→Catches everything. Avoid it
Hierarchy→A parent exception also catches its children
Order→Specific except blocks first, general last
23

Key Points to Remember

  • An exception stops the program unless you handle it.
  • Read a traceback from the bottom: error type, then the line.
  • Put risky code in try. Handle problems in except.
  • Catch specific exceptions. Avoid the bare except:.
  • Use as e to see the error message.
  • else runs when there is no error.
  • finally runs every time.
  • Use raise to create an error when your own rule is broken.
  • Custom exceptions give clear names to your own problems.
  • Put specific except blocks above general ones.
  • Never hide errors with except: pass.
