The process on a tiny problem

🧩 Problem: does the list contain any duplicate?
  • Input: a list of numbers. Output: True or False.
  • Constraints: imagine up to 1 lakh numbers.
  • Brute force: compare every pair. Correct, but 1 lakh numbers means about 5 billion comparisons.
  • Data structure: a set remembers what we have seen and answers "seen before?" quickly.
  • Algorithm: walk once; if the number is already in the set, return True; else add it.
Brute force → set
Python
def has_duplicate_brute(nums):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return True
    return False

def has_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False

print(has_duplicate_brute([4, 7, 2, 7]), has_duplicate([4, 7, 2, 7]))
print(has_duplicate_brute([1, 2, 3]), has_duplicate([1, 2, 3]))
print(has_duplicate([]))
Output
Output
True True
False False
False
Easy Explanation
  • Both give the same answers. The second is far faster on big input (you will prove this with Big-O later).
  • We also tested the empty list, an edge case. It returns False, which is correct.

Data Structure vs Algorithm

DATA STRUCTURE
A way of organising and storing data so that useful operations on it are easy and efficient.
Examples: list, stack, queue, set, dictionary, tree.
ALGORITHM
A clear, finite list of steps that solves a problem.
Examples: linear search, binary search, bubble sort.
💡 Real-life analogy
Data structure = kitchen arrangement (where spices, plates and vessels are kept). Algorithm = recipe (the steps to cook). A good arrangement makes the recipe quick; a messy kitchen makes even a simple recipe slow.

🧱 Data structure

Answers how is the data kept? e.g. a stack keeps items so only the top is reachable.

👨‍🍳 Algorithm

Answers what steps do we follow? e.g. binary search repeatedly halves a sorted list.

🔗 They work together

Binary search (algorithm) needs a sorted, indexable structure like a list. Choosing the wrong structure can make a good algorithm impossible or slow.

ARRAY
A collection of items stored one after another, each reached by its index (position number starting at 0).

Strings as a DSA Structure

A string is an ordered, immutable sequence of characters. You can index and slice it like a list, but you cannot change a character in place.

⚠️ Immutable
s[0] = 'X' raises a TypeError. To "change" a string you build a new one. Building a long string by repeated += in a loop can be slow; collect pieces in a list and use ''.join(...).

1. Reverse a string

Two ways
Python
s = "python"
print(s[::-1])                         # slicing

chars = list(s)                        # two-pointer way
l, r = 0, len(chars) - 1
while l < r:
    chars[l], chars[r] = chars[r], chars[l]
    l += 1
    r -= 1
print("".join(chars))

  • The two-pointer way swaps from both ends toward the middle. You will meet this pattern again.

2. Palindrome check

Palindrome
Python
def is_palindrome(s):
    s = s.lower()
    l, r = 0, len(s) - 1
    while l < r:
        if s[l] != s[r]:
            return False
        l += 1
        r -= 1
    return True

Easy Explanation

Stack: Last In, First Out

STACK
A collection where you can only add or remove at one end, called the top. The last item pushed is the first item popped.
LIFO: Last In, First Out
💡 Real-life analogy

A stack of plates. You put a new plate on top and take a plate from the top. You never pull from the middle.

A stack
       ┌───────┐
TOP →  │   30  │   ← last pushed, first out
       ├───────┤
       │   20  │
       ├───────┤
       │   10  │
       └───────┘
push(x)
Add x on topO(1)
pop()
Remove and return the topO(1)
peek()
Look at the top without removingO(1)
is_empty()
Is the stack empty?O(1)
Operation → Stack → Result
push(10)  → [10]            top = 10
push(20)  → [10, 20]        top = 20
push(30)  → [10, 20, 30]    top = 30
pop()     → [10, 20]        returned 30
peek()    → [10, 20]        returned 20
The right end of the list is the top.

Implementing a stack with a Python list

A list's append and pop() both work at the end in O(1) on average, so a list is a good stack.

Stack class
Python
class Stack:
    def __init__(self):
        self._items = []

    def push(self, x):
        self._items.append(x)

    def pop(self):
        if self.is_empty():
            raise IndexError("pop from empty stack")
        return self._items.pop()

    def peek(self):
        if self.is_empty():
            raise IndexError("peek from empty stack")
        return self._items[-1]

    def is_empty(self):
        return len(self._items) == 0

    def size(self):
        return len(self._items)

s = Stack()
s.push(10); s.push(20); s.push(30)
print(s.pop())
print(s.peek())
print(s.size(), s.is_empty())
Output
Output
30
20
2 False
Easy Explanation
  • The list is kept private (_items); callers use only stack operations. That is encapsulation from the OOP chapter.
  • Popping an empty stack raises a clear error. Handling the empty case is an edge case.
⚠️ Common confusion

Stack = LIFO (one end). Queue = FIFO (two ends). Do not mix them up.

🧩 Problem: Valid Parentheses

Given a string of ()[]{}, decide whether every bracket is closed by the right type in the right order.

Understand the Problem
  • Every opener needs a matching closer of the same type.
  • Order matters: the innermost opener closes first.
Example
Input / Output
Input:  "{[()]}"   Output: True
Input:  "([)]"     Output: False
Input:  "(("       Output: False
Better Approach

Push openers. On a closer, the top of the stack must be its matching opener; pop it. At the end the stack must be empty.

Python
def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return len(stack) == 0

for t in ["{[()]}", "([)]", "((", "", ")"]:
    print(repr(t), is_valid(t))

Queue with a list
Python
class Queue:
    def __init__(self):
        self._items = []

    def enqueue(self, x):
        self._items.append(x)

    def dequeue(self):
        if self.is_empty():
            raise IndexError("dequeue from empty queue")
        return self._items.pop(0)

    def front(self):
        if self.is_empty():
            raise IndexError("front of empty queue")
        return self._items[0]

    def is_empty(self):
        return len(self._items) == 0

q = Queue()
q.enqueue("Riya"); q.enqueue("Aman"); q.enqueue("Neha")
print(q.dequeue())
print(q.front())
print(q.is_empty())

  • This simple version uses pop(0), which has a hidden cost. The next section fixes it.
⚠️ Hidden cost
list.pop(0) shifts every remaining item left, so each dequeue is O(n). For a big queue that is slow. Python has a better tool: deque.

Linked List: The Idea

An array keeps items side by side in memory. A linked list keeps items anywhere, and each item holds a reference to the next one.

NODE
One box of a linked list. It holds data and a next reference.
HEAD
The reference to the first node. If you lose the head, you lose the list.
Singly linked list
HEAD
 ↓
┌──────┐    ┌──────┐    ┌──────┐
│  10  │ →  │  20  │ →  │  30  │ → None
└──────┘    └──────┘    └──────┘
 data|next   data|next   data|next
💡 Real-life analogy

A treasure hunt. Each clue tells you where the next clue is. You must follow clues in order; you cannot jump to clue number 5 directly.

💡 Why does it exist?

Inserting or deleting in the middle of an array shifts many items. In a linked list you only change a couple of references, if you already hold the node before the spot.

Insert 15 between 10 and 20
Before:  10 → 20 → 30

1) new.next = 10.next        (15 → 20)
2) 10.next  = new            (10 → 15)

After:   10 → 15 → 20 → 30

Array / Python list

Fast access by index O(1). Items contiguous. Middle insert/delete shifts items O(n).

Linked list

No access by index: reach item i by walking i steps O(n). Insert/delete after a known node is O(1). Search is O(n).

🐍 Honest note

In everyday Python you will use list and deque far more than hand-made linked lists. Linked lists matter because they teach references, and trees and graphs are built on the same idea.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def insert_front(self, data):            # O(1)
        node = Node(data)
        node.next = self.head
        self.head = node

    def insert_end(self, data):              # O(n): walk to the last node
        node = Node(data)
        if self.head is None:
            self.head = node
            return
        cur = self.head
        while cur.next is not None:
            cur = cur.next
        cur.next = node

    def delete(self, value):                 # O(n)
        if self.head is None:
            return False
        if self.head.data == value:          # deleting the head
            self.head = self.head.next
            return True
        cur = self.head
        while cur.next is not None:
            if cur.next.data == value:
                cur.next = cur.next.next     # skip the node
                return True
            cur = cur.next
        return False

    def to_list(self):
        out, cur = [], self.head
        while cur is not None:
            out.append(cur.data)
            cur = cur.next
        return out

Dictionary as a Hash Map: Two Sum

💡 Think Before You Code
  • What do you know when you look at one number x? (the partner you need is target - x)
  • How can you check quickly whether the partner was already seen?
  • Can you avoid nested loops?
👉 Reveal the thinking
For each number, its partner is target - x. Remember each seen number and its index in a dictionary. Then "have I seen the partner?" is a hash lookup, so one pass is enough.
🧩 Problem: Two Sum

Given a list nums and a target, return the indices of the two numbers that add up to the target. Exactly one pair exists; do not use the same element twice.

Understand the Problem
  • We want indices, not the numbers.
  • Each number pairs with exactly one possible partner: target - number.
Example
Input / Output
Input:  nums = [2, 7, 11, 15], target = 9
Output: [0, 1]   (because 2 + 7 = 9)
Brute Force

Try every pair with two nested loops.

Python
def two_sum_brute(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

print(two_sum_brute([2, 7, 11, 15], 9))
Output
Output
[0, 1]
Complexity
Time:  O(n²)  (n × n pair checks, about n²/2)
Space: O(1)
Better Approach

Walk once. For each number, look in a dictionary for target - x. If found, done. Otherwise store x → index.

Python
def two_sum(nums, target):
    seen = {}                        # value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []

print(two_sum([2, 7, 11, 15], 9))
print(two_sum([3, 2, 4], 6))
print(two_sum([3, 3], 6))
print(two_sum([1, 2], 10))

Output
[0, 1]
[1, 2]
[0, 1]
[]
Complexity
Time:  O(n)  (one pass, O(1) average per lookup)
Space: O(n)  (the dictionary)

More memory → less time. The dictionary costs O(n) space but removes the inner loop, turning O(n²) into O(n).

    return [] if n is None else inorder(n.left) + [n.val] + inorder(n.right)

        if n.right: q.append(n.right)
    return out

Binary Search Tree (Introduction)

BINARY SEARCH TREE (BST)
A binary tree where, for every node: all values in the left subtree are smaller, and all values in the right subtree are larger.

💡 Search idea

To find 6: start at 8. 6 < 8, go left. At 3: 6 > 3, go right. At 6: found. Each step discards a whole subtree, like binary search on a sorted list.

Insert and search
Python
class TreeNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

def insert(root, val):
    if root is None:
        return TreeNode(val)
    if val < root.val:
        root.left = insert(root.left, val)
    elif val > root.val:
        root.right = insert(root.right, val)
    return root

def search(root, target):
    while root is not None:
        if target == root.val:
            return True
        root = root.left if target < root.val else root.right
    return False

def inorder(n):
    return [] if n is None else inorder(n.left) + [n.val] + inorder(n.right)

root = None
for v in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    root = insert(root, v)

print(search(root, 6), search(root, 5))
print(inorder(root))

[1, 3, 4, 6, 7, 8, 10, 13, 14]
Easy Explanation
  • Inorder traversal of a BST always gives sorted order. This is a famous property.
  • Insert follows the same left/right decisions as search.
⚠️ Accuracy note

Search, insert in a BST take O(h) where h is the height. For a balanced tree h ≈ log n, so about O(log n). If values arrive already sorted (1,2,3,4...) the tree becomes a line and operations degrade to O(n). Self-balancing trees (AVL, Red-Black) fix this and are a future topic.

Binary search

BINARY SEARCH
On sorted data, compare the target with the middle item and throw away the half that cannot contain it. Repeat.
💡 Real-life analogy

Finding a word in a dictionary. You open the middle, see whether your word is before or after, and keep halving. You never read every page.

⚠️ Requirement

The data must be sorted and you must be able to jump to the middle (index access). On unsorted data the "discard half" logic is simply wrong.

Array: [10, 20, 30, 40, 50, 60, 70]

 [10, 20, 30, 40, 50, 60, 70]
   L           M           H
 40 < 60 → throw away left half, low = mid+1 = 4

Step 2: low=4, high=6, mid=5 → 60
 [10, 20, 30, 40, 50, 60, 70]
                L   M   H
 60 = 60 → FOUND at index 5
Each step removes half of the remaining search space.
Binary search
Python
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

Sorting

Sorting arranges items in order. It is a problem by itself and a tool that makes other problems easier: binary search, duplicates, merging, two pointers all like sorted data.

1. Bubble sort

💡 Idea

Compare neighbours and swap if out of order. After each pass the largest remaining item "bubbles" to the end.

Bubble sort on [5, 3, 8, 1]
Pass 1: [5,3,8,1] → [3,5,8,1] → [3,5,8,1] → [3,5,1,8]   (8 is placed)
Pass 2: [3,5,1,8] → [3,5,1,8] → [3,1,5,8]               (5 is placed)
Pass 3: [3,1,5,8] → [1,3,5,8]                           (done)
Bubble sort
Python
def bubble_sort(arr):
    arr = arr[:]                          # work on a copy
    n = len(arr)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        if not swapped:                   # already sorted: stop early
            break
    return arr

print(bubble_sort([5, 3, 8, 1]))
print(bubble_sort([1, 2, 3]))
print(bubble_sort([]), bubble_sort([7]))
Output
Output
[1, 3, 5, 8]
[1, 2, 3]
[] [7]
Easy Explanation
  • Inner loop shrinks by i because the last i items are already in place.
  • The swapped flag gives a fast exit on sorted input.
Complexity
Time:  O(n²) worst/average; O(n) best (with the swapped flag)
Space: O(1) extra

Useful for: learning only. Common mistake: forgetting n - 1 - i and re-checking sorted items, or going out of range with j + 1.

2. Selection sort

💡 Idea

Find the smallest item in the unsorted part and swap it to the front. Repeat for the next position.

Selection sort on [64, 25, 12, 22]
[64,25,12,22] min=12 → swap with 64 → [12,25,64,22]
[12,25,64,22] min=22 → swap with 25 → [12,22,64,25]
[12,22,64,25] min=25 → swap with 64 → [12,22,25,64]
Selection sort
Python
def selection_sort(arr):
    arr = arr[:]
    n = len(arr)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if arr[j] < arr[m]:
                m = j
        arr[i], arr[m] = arr[m], arr[i]
    return arr

print(selection_sort([3, 3, 1]))

Easy Explanation
  • Only n − 1 swaps in total, which is good when swapping is expensive.
  • It always scans the rest to find the minimum, so it is O(n²) even on sorted input.
Complexity
Time:  O(n²) in all cases
Space: O(1) extra

3. Insertion sort

💡 Idea (like sorting playing cards in hand)

Take the next item and insert it into its correct place among the already-sorted items on its left, shifting larger ones right.

Insertion sort on [5, 2, 4, 1]
[5 | 2, 4, 1]  insert 2 → [2, 5 | 4, 1]
[2, 5 | 4, 1]  insert 4 → [2, 4, 5 | 1]
[2, 4, 5 | 1]  insert 1 → [1, 2, 4, 5]
( | separates sorted part from unsorted part )
Insertion sort
Python
def insertion_sort(arr):
    arr = arr[:]
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]           # shift right
            j -= 1
        arr[j + 1] = key
    return arr

  • On nearly-sorted input it barely shifts anything, so it is very fast there.

Brute Force vs Optimized Solutions

The healthy order
1. Find a CORRECT solution (brute force)
        ↓
2. ANALYSE it (time and space)
        ↓
3. IMPROVE it (better structure or idea)
        ↓
4. Re-check correctness

Brute force

Try everything. Easy to write, easy to trust. Often O(n²) or worse.

Optimized

Use a better structure or idea to avoid repeated work. Needs more thought, sometimes more memory.

Race them
Python
import time

def two_sum_brute(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]

def two_sum_hash(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i

nums = list(range(1, 4001))
target = 7999                   # last two numbers: worst case for brute force

t = time.perf_counter(); a = two_sum_brute(nums, target); t1 = time.perf_counter() - t
t = time.perf_counter(); b = two_sum_hash(nums, target);  t2 = time.perf_counter() - t
print(a == b, "hash map faster:", t2 < t1)

Two Pointers

TWO POINTERS
Use two indices that move through the data (often from both ends toward the middle) so one pass replaces nested loops.
Sorted array: find a pair that sums to 10
[1, 2, 4, 6, 8, 9]

💡 Why does moving a pointer make sense?

The array is sorted. If the current sum is too small, only a bigger left value can help, so move left right. If it is too big, move right left.

🧩 Problem: Pair with a given sum in a sorted array

Better Approach

Place pointers at both ends. Sum too small → move left up. Sum too big → move right down.

Python
def pair_sum(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return (nums[left], nums[right])
        elif s < target:
            left += 1
        else:
            right -= 1
    return None

print(pair_sum([1, 2, 4, 6, 8, 9], 14))
print(pair_sum([1, 2, 4, 6, 8, 9], 100))
print(pair_sum([], 5), pair_sum([5], 5))

def merge_sorted(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            out.append(a[i]); i += 1
        else:
            out.append(b[j]); j += 1
    out.extend(a[i:])        # leftovers (at most one is non-empty)
    out.extend(b[j:])
    return out

Sliding Window (Introduction)

SLIDING WINDOW
Keep a moving range (window) over the data and update its result as it slides, instead of recalculating from scratch.
Window of size k = 3
[2, 1, 5, 1, 3, 2]
 [2  1  5]  sum 8
    [1  5  1]  sum 7
       [5  1  3]  sum 9
          [1  3  2]  sum 6
💡 Think Before You Code
  • Two neighbouring windows share most of their items. How much really changes when the window moves one step?
  • What can you reuse instead of re-adding all k numbers?
👉 Reveal the thinking
Moving the window drops one item on the left and adds one on the right. So new_sum = old_sum - leaving + entering, a single step instead of k additions.
🧩 Problem: Maximum sum of k consecutive elements

Given a list and a number k, find the largest sum of any k consecutive items.

Understand the Problem
  • Windows must be consecutive.
  • Edge: if k is bigger than the list there is no valid window.
Example

Brute Force

For every start index, add k numbers again.

def max_sum_brute(nums, k):
    if k > len(nums) or k <= 0:
        return None
    best = sum(nums[0:k])
    for i in range(1, len(nums) - k + 1):
        best = max(best, sum(nums[i:i + k]))
    return best

Compute the first window once. Slide: add the entering item, subtract the leaving item.

def max_sum_window(nums, k):
    if k > len(nums) or k <= 0:

    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]     # enter - leave
        best = max(best, window)
    return best

Prefix Sum (Introduction)

PREFIX SUM
An array where each position holds the running total of all items up to there. It answers "sum of items i to j" instantly.
Build it
Array:   [2,  4,  1,  5]

Prefix:  [2,  6,  7,  12]
          │   │   │   └ 2+4+1+5
          │   │   └ 2+4+1
          │   └ 2+4
          └ 2
💡 The logic

Sum of items from index i to j = prefix[j] − prefix[i−1]: take the total up to j, remove the part before i. Use a leading 0 to avoid special-casing i = 0.

Range sums

    return prefix[j + 1] - prefix[i]

print(range_sum(2, 2))               # one item

  • Build once in O(n). Then every range-sum query is O(1).
  • Without prefix sums, each query would loop over the range: O(n) per query.

Data Structure Comparison and When to Use What

Comparison at a glance

List
Items in order, by indexStrong: index access O(1), append. Weak: front insert/delete, search O(n).
Linked list
Nodes linked by referencesStrong: insert/delete after a known node O(1). Weak: no index access, search O(n).
Stack
One open end (top)Strong: push/pop O(1). Weak: only the top is reachable. LIFO.
Queue (deque)
Two endsStrong: enqueue/dequeue O(1). Weak: no fast middle access. FIFO.
Set
Unique items, hashedStrong: membership average O(1). Weak: no order, no index.
Dict / Hash map
Key → value, hashedStrong: lookup/insert/delete average O(1). Weak: extra memory, hashable keys.
Tree (BST)
Hierarchy, left/rightStrong: ordered data, search about O(log n) if balanced. Weak: can become a line.
Heap
Smallest at the topStrong: min in O(1), push/pop O(log n). Weak: no fast search.
Graph
Vertices and edgesStrong: models any network. Weak: more complex algorithms.

Fast?

Key Points to Remember

  • A data structure organises data; an algorithm is the steps that solve a problem.
  • Follow the process: understand → input/output → constraints → brute force → structure → algorithm → dry run → complexity → optimise.
  • Choose the structure by the operation you do most often.
  • List: fast index access; slow front/middle insert and delete. x in list is O(n).
  • Stack = LIFO, queue = FIFO. Use deque for queues, never repeated list.pop(0).
  • Linked lists trade index access for cheap insert/delete after a known node.
  • Need fast lookup? Think dict or set (average O(1)).
  • Binary search needs sorted data and halves the search space each step: O(log n).
  • Bubble, selection and insertion sort are O(n²). Python's sorted() / sort() are O(n log n) and optimised; use them in real code.
  • Recursion needs a base case and a smaller recursive case; depth costs stack space.
  • Big-O describes growth, not exact time. Nested loops multiply; sequential loops add.
  • More memory can buy less time (Two Sum with a dict).
  • Always test edge cases: empty, one item, duplicates, negatives, missing target.
  • Learn patterns: hashing, two pointers, sliding window, prefix sum, stack, binary search.

A data structure answers how data is kept; an algorithm answers what steps process it. Analogy: kitchen arrangement vs recipe.

Q4 What is Big-O?

A notation describing how an algorithm's time or space grows with input size n (upper bound), ignoring constants. Example: a single loop is O(n).

Q5 What are time and space complexity?

Time: how the number of steps grows with n. Space: how extra memory grows with n (input not counted; recursion stack counts).

🟡 Data structures

Q6 List vs linked list?

List: O(1) index access, front/middle insert O(n). Linked list: no index access (O(n) to reach an item), but O(1) insert/delete after a known node. In Python you usually use list or deque.

Q7 Stack vs queue?

Stack is LIFO: push/pop at the top (undo, brackets). Queue is FIFO: enqueue at rear, dequeue at front (printer, BFS).

Q8 Set vs dictionary?

Both are hash-based. A set stores unique items (membership). A dict stores key → value pairs (lookup, counting). Both average O(1).

Q9 Array vs linked list?

Arrays store items contiguously and give O(1) index access; linked lists store scattered nodes joined by references and give cheap insert/delete when you hold the node.

Q10 What is hashing? Is dict lookup always O(1)?

Hashing converts a key to a number to jump directly to its slot. Average lookup is O(1); in the worst case (many collisions) it can degrade to O(n).

Q11 What is a tree?

A hierarchical structure of nodes with one root and parent-child links, no cycles. A binary tree has at most two children per node.

Q12 What is a graph?

Vertices connected by edges (directed/undirected, weighted/unweighted). Stored as an adjacency list (dict of lists) or an adjacency matrix.

Q13 Why is deque better than a list for a queue?

deque.popleft() is O(1). list.pop(0) shifts all other items, so it is O(n).

🔴 Algorithms

Q14 Linear vs binary search?

Linear: check one by one, works on unsorted data, O(n). Binary: needs sorted data, halves the range each step, O(log n).

Q15 Why must binary search use sorted data?

It discards half the range by comparing with the middle. That is only valid if everything on one side is smaller and the other side larger.

Q16 What is recursion?

A function calling itself on a smaller input. Needs a base case to stop; each call uses stack space.

Q17 What is brute force?

The simplest approach that tries all possibilities. Usually correct but slow; a good starting point to then optimise.

Q18 How can an O(n²) solution sometimes be improved?

Remove the inner loop by remembering information: a hash map/set (Two Sum), sorting + two pointers, a sliding window or prefix sums. It often trades memory for time.

Q19 What is the two-pointer technique?

Using two indices moving through data (often from both ends of a sorted array) so one O(n) pass replaces nested loops.

Q20 What is sliding window?

Maintain a moving range and update its result by adding the entering item and removing the leaving item, avoiding recomputation. Example: max sum of k consecutive items in O(n).

Q21 Complexity of Python's sorted()?

O(n log n) time (Timsort), O(n) extra space. Sorting a list in place with .sort() returns None.

Q22 Insertion sort vs selection sort?

Both O(n²). Insertion sort is O(n) on nearly sorted input and stable; selection sort always scans the rest but does at most n − 1 swaps.
