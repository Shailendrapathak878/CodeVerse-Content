What Is Advanced Python?

In basic Python, you learn how to tell the computer what to do step by step: declaring variables, running loops, handling conditionals, and calling standard functions. Advanced Python shifts your mental model from merely writing instructions to architecting elegant, expressive, memory-efficient, and reusable software systems.

💡 Core Concept: The Pythonic Mindset
Advanced Python is not about obscure syntax tricks or unnecessary complexity. It is about understanding Python's underlying object model, execution semantics, and protocols—allowing you to write code that is clean, lazy, decoupled, and exceptionally resource-efficient.

The Four Pillars of Advanced Python

🔄 1. Iterators & Iterables

The standard protocol behind every for loop, comprehension, and sequence traversal in Python. Enables lazy iteration one item at a time.

🎨 3. Decorators

Higher-order functions that dynamically extend or alter the behavior of existing functions or methods without modifying their source code.

Functions that remember and capture variables from their enclosing lexical scope even after that outer scope has finished executing.

Functions as First-Class Objects

📊 Figure 16.1: Functions as First-Class Citizens in Python
In Python, functions are first-class objects residing in heap memory. They can be assigned to variables, passed into other functions as callbacks, stored inside lists or dictionaries, and returned dynamically from enclosing scopes, forming the foundation for decorators and functional pipelines.
Visual Summary & Trace:
First-Class Functions: Functions possess the same capabilities as standard data types (numbers, strings, lists).

In Python, everything is an object—including functions. A function is an instance of the function class. Because functions are first-class citizens, they enjoy all the rights of numbers, strings, and lists:

  • They can be assigned to variables.
  • They can be stored in data structures (lists, dictionaries, sets).
  • They can be passed as arguments to other functions.
  • They can be returned as the result of another function.
📝 First-Class Citizen Properties in Action
Notice the critical difference between referencing a function: func (an object in memory) and calling it: func() (triggering execution).
first_class_functions.py 
# 1. Assigning a function to a variable
def shout(text):
    return text.upper() + "!"

yell = shout  # yell now points to the same function object in memory
print(yell("python is amazing"))

# 2. Storing functions in a dictionary (Dispatch Table)
def add(a, b): return a + b
def sub(a, b): return a - b
def mul(a, b): return a * b

operations = {
    "add": add,
    "subtract": sub,
    "multiply": mul
}

op = operations["multiply"]
print("Result of 6 * 7:", op(6, 7))

# 3. Passing a function as an argument (Higher-Order Function)
def apply_transformer(numbers, transformer):
    return [transformer(x) for x in numbers]

def square(n):
    return n ** 2

nums = [1, 2, 3, 4, 5]
print("Squared:", apply_transformer(nums, square))

# 4. Returning a function from another function
def get_greeting_function(language):
    def greet_en(name): return f"Hello, {name}!"
    def greet_es(name): return f"¡Hola, {name}!"
    
    if language == "es":
        return greet_es
    return greet_en

saludo = get_greeting_function("es")
print(saludo("Sofia"))

Function Scope & the LEGB Rule

📊 Figure 16.2: Python LEGB Scope Resolution Ladder & Keywords
Python resolves variable names following the strict LEGB precedence: Local (current function body), Enclosing (nested outer defs), Global (current module level), and Built-in (`builtins`). The `nonlocal` keyword allows writing to enclosing variables, while `global` binds assignment directly to module-level scope.
Visual Summary & Trace:
LEGB Rule: Names are resolved sequentially through Local, Enclosing, Global, and Built-in namespaces.

Whenever Python resolves a variable name, it follows a strict search hierarchy called the LEGB Rule. Understanding this rule is indispensable before mastering closures and decorators.

Scope Name Description Example Variable
L Local Variables defined inside the currently executing function. x = 10 inside foo()
E Enclosing Variables in the outer enclosing function of a nested function. Outer function's parameter or variable
G Global Variables defined at the module top level or marked global. Module constants, global flags
B Built-in Names pre-assigned in Python's standard builtins module. len, range, print, int
🔍 LEGB Search Direction
1. Local (Inside current func)
→
2. Enclosing (Outer nested func)
→
3. Global (Module level)
→
4. Built-in (Python internals)
legb_scope_demo.py 
# Global scope
message = "Global Level"

def outer():
    # Enclosing scope
    message = "Enclosing Level"
    
    def inner():
        # Local scope
        # If uncommented, message = "Local Level" would resolve here
        print("Resolved message inside inner:", message)
        print("Built-in len of message:", len(message))
    
    inner()

outer()
print("Outside outer:", message)
🖥 Output
Resolved message inside inner: Enclosing Level
Built-in len of message: 15
Outside outer: Global Level
⚠ Common Pitfall: Shadowing Built-ins
Never name your variables list, str, dict, min, or max. If you write list = [1, 2, 3], Python creates a local or global variable list, hiding the built-in constructor. Any subsequent call like list("abc") will raise a TypeError: 'list' object is not callable!

What Is an Iterable?

An iterable is any Python object capable of returning its members one at a time. Put simply, if you can pass an object to a for loop, it is an iterable.

💡 Formal Python Definition of an Iterable
An object is an iterable if it implements the __iter__() dunder method that returns an iterator, OR if it implements __getitem__() with sequence index support starting from 0.

Common Built-in Iterables

Lists, tuples, strings, dictionaries, sets, ranges, and open file objects are all iterables.

checking_iterables.py 
from collections.abc import Iterable

sample_list = [10, 20, 30]
sample_str = "CodeVerse"
sample_int = 42

print("Is list iterable?", isinstance(sample_list, Iterable))
print("Is str iterable?", isinstance(sample_str, Iterable))
print("Is int iterable?", isinstance(sample_int, Iterable))

# Checking via hasattr for __iter__
print("Does list have __iter__?", hasattr(sample_list, "__iter__"))
print("Does int have __iter__?", hasattr(sample_int, "__iter__"))
🖥 Output
Is list iterable? True
Is str iterable? True
Is int iterable? False
Does list have __iter__? True
Does int have __iter__? False

What Is an Iterator?

An iterator is a stateful stream object that produces the next item in a sequence upon demand when passed to the built-in function next().

💡 The Iterator Protocol
To qualify as an iterator, an object must implement two dunder methods:
  1. __iter__(): Returns the iterator object itself (return self).
  2. __next__(): Returns the next item from the container. If there are no further items, it must raise StopIteration.
iterator_demo.py 
colors = ["crimson", "teal", "amber"]

# Step 1: Create an iterator from the iterable list using iter()
color_iter = iter(colors)
print("Iterator object:", color_iter)

# Step 2: Fetch items one by one using next()
print("1st:", next(color_iter))
print("2nd:", next(color_iter))
print("3rd:", next(color_iter))

# Step 3: What happens when the sequence is exhausted?
try:
    print("4th:", next(color_iter))
except StopIteration:
    print("Caught StopIteration: The iterator is completely exhausted!")
🖥 Output
Iterator object: <list_iterator object at 0x...>
1st: crimson
2nd: teal
3rd: amber
Caught StopIteration: The iterator is completely exhausted!
💡 Safe Extraction with Default Value
The next() function takes an optional second argument: next(iterator, default_value). If provided, Python returns the default value instead of raising StopIteration when exhausted!
val = next(color_iter, "END") # returns "END" cleanly

The difference between an iterable and an iterator is one of the most frequently asked interview questions in Python. Let us compare them across all structural dimensions:

Feature Iterable Iterator
Analogy A book on a library shelf. A bookmark tracking the current page.
Required Methods __iter__() (or __getitem__) Both __iter__() and __next__()
Can call next()? No (raises TypeError) Yes (fetches next element)
State Awareness Stateless. Does not remember current position. Stateful. Remembers exactly where it is.

How a for Loop Works Internally (Under the Hood)

📊 Figure 16.3: Iterable vs. Iterator Protocol & Internal Loop Mechanics
An iterable is any container implementing `__iter__()` that can yield new iterators. An iterator is a stateful cursor implementing `__next__()` that advances item-by-item until exhaustion, signaling completion via `StopIteration`. Under the hood, Python's `for` loops manage this protocol silently.
Visual Summary & Trace:
Iteration Protocol: iter() retrieves the cursor; next() advances it until StopIteration signals loop termination.

Many beginners assume Python's for loop is like a C-style index counter: for (int i=0; i<n; i++). It is not! In Python, every for loop is syntactic sugar for a while True loop operating on the Iterator Protocol.

⚙ Python's Internal for Loop Mechanics
1. iter(iterable) gets iterator
→
2. next(iterator) called in loop
→
3. StopIteration raised & caught
→
4. Loop cleanly terminates
for_loop_under_the_hood.py 
# High-level Python for loop
fruits = ["Apple", "Banana", "Cherry"]
print("Standard for loop:")
for f in fruits:

print("\nReconstructed manual while loop:")
# EXACT manual equivalent of the for loop
iterator = iter(fruits)
while True:
    try:
        item = next(iterator)
        print(item)
    except StopIteration:
        # Loop finishes silently when StopIteration is raised

Creating a Custom Iterator Class

To create your own custom iterator, build a class with both __iter__() and __next__() methods. Let us build a Countdown iterator that counts down from a given start number to 1.

custom_countdown_iterator.py 
class Countdown:
    """A custom iterator that counts down from start to 1."""
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        # An iterator must return self from __iter__
        return self

    def __next__(self):
        if self.current <= 0:
            # Signal exhaustion
            raise StopIteration
        val = self.current
        self.current -= 1
        return val

# Using Countdown in a standard for loop
print("Testing Countdown(5):")
for num in Countdown(5):
    print(f"T-minus {num}...")
print("Blastoff! 🚀")

# Using next() manually
timer = Countdown(3)
print("\nManual next calls:")
print(next(timer))
print(next(timer))
print(next(timer))
# print(next(timer))  # would raise StopIteration

T-minus 1...
Blastoff! 🚀

Infinite Iterators & Loop Safety

Because iterators generate items on demand rather than storing everything in memory, an iterator can be infinite! Python's standard library module itertools provides powerful infinite iterators such as count, cycle, and repeat.

⚠ Warning: Unbounded Loops on Infinite Iterators
If you pass an infinite iterator to a standard for x in infinite_iter: without a break condition, your program will enter an infinite loop that locks the CPU until interrupted! Always guard infinite loops with an iteration counter or limit check.
infinite_iterators_safety.py 
import itertools

# 1. itertools.count(start, step)
print("1. itertools.count:")
counter = itertools.count(start=100, step=10)
for _ in range(4):
    print(next(counter), end=" ")
print()

# 2. itertools.cycle(iterable)
print("2. itertools.cycle (traffic lights):")
traffic_light = itertools.cycle(["RED", "GREEN", "AMBER"])
for i in range(6):
    print(f"Tick {i+1}: {next(traffic_light)}")

# 3. Custom Infinite Fibonacci Iterator with break safeguard
class InfiniteFibonacci:
    def __init__(self):
        self.a, self.b = 0, 1

    def __iter__(self):
        return self

    def __next__(self):
        val = self.a
        self.a, self.b = self.b, self.a + self.b
        return val

print("\n3. First 7 Fibonacci numbers:")
fib = InfiniteFibonacci()
for i, num in enumerate(fib):
    if i >= 7:
        break
    print(num, end=" ")
print()

Practical Real-World Uses of Iterators

Why should software engineers master iterators when simple lists exist? In production environments, datasets regularly exceed available physical RAM (e.g. 50GB database dumps or log streams). Iterators solve these real-world challenges:

💾 Constant Memory Footprint (O(1) Space)

Iterators process items one by one. Whether traversing 10 items or 100,000,000 items, the memory consumption remains constant at a few bytes.

⏱ Immediate First Response (Low Latency)

You do not have to wait for the entire dataset to be loaded, parsed, or calculated before handling the first record. Processing begins instantly.

chunk_iterator_pattern.py 
# Practical Pattern: Batch/Chunk Processor Iterator
class BatchLoader:
    """Simulates loading rows in batches from a large dataset."""
    def __init__(self, data_source, batch_size=3):
        self.data = data_source
        self.batch_size = batch_size
        self.index = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.index >= len(self.data):
            raise StopIteration
        batch = self.data[self.index : self.index + self.batch_size]
        self.index += self.batch_size
        return batch

# Emulating database records
all_records = [f"User_{i}" for i in range(1, 11)]
batcher = BatchLoader(all_records, batch_size=4)

print("Processing database batches:")
for batch_idx, chunk in enumerate(batcher, start=1):
    print(f"Batch #{batch_idx}: {chunk}")
🖥 Output
Processing database batches:
Batch #1: ['User_1', 'User_2', 'User_3', 'User_4']
Batch #2: ['User_5', 'User_6', 'User_7', 'User_8']
Batch #3: ['User_9', 'User_10']

What Is a Generator?

Writing custom iterator classes with __iter__(), __next__(), and manual StopIteration handling can be verbose and error-prone. Generators are Python's elegant, lightweight solution: they allow you to write iterators using standard function syntax!

💡 Definition: Generator Function vs Generator Object
A generator function is any function that contains one or more yield statements. When called, a generator function does not execute its body immediately; instead, it returns a generator iterator object that produces values on demand.
first_generator.py 
def simple_count():
    print("-> Generator started")
    yield 1
    print("-> Resumed after first yield")
    yield 2
    print("-> Resumed after second yield")
    yield 3
    print("-> Generator finished")

# Calling the function returns a generator object
gen = simple_count()
print("Generator object created:", gen)

# Executing step by step
print("First call to next():", next(gen))
print("Second call to next():", next(gen))
print("Third call to next():", next(gen))

try:
    print("Fourth call:", next(gen))
except StopIteration:
    print("Caught StopIteration: Generator cleanly ended.")
🖥 Output
Generator object created: <generator object simple_count at 0x...>
-> Generator started
First call to next(): 1
-> Resumed after first yield
Second call to next(): 2
-> Resumed after second yield
Third call to next(): 3
-> Generator finished
Caught StopIteration: Generator cleanly ended.

The yield Keyword In-Depth

📊 Figure 16.4: Generator Execution State Machine & yield Suspension
A generator function differs fundamentally from standard functions: encountering `yield` yields an intermediate value to the consumer and suspends its execution frame, preserving all local variables and instruction pointers in memory until the caller requests the next item via `next()`.
Visual Summary & Trace:
Generator Lifecycle: yield pauses and freezes execution state; next() unfreezes and resumes execution immediately after the yield statement.

The magic of a generator lies in the yield keyword. While return permanently terminates a function and destroys its local stack frame, yield temporarily pauses (freezes) execution and sends a value back to the caller.

⏸ Anatomy of the Pause and Resume Cycle
1. Caller runs next(gen)
→
2. Code runs until yield x
→
3. Value x returned; Frame frozen
→
4. Next call unfreezes at next line

When a generator is frozen at yield, Python saves its entire state:

  • All local variables and their current values.
  • The instruction pointer (the exact line where execution paused).
  • The exception state and try/finally blocks.
yield_state_preservation.py 
def accumulator():
    total = 0
    step = 1
    while step <= 3:
        total += step * 10
        print(f"[Inside Generator] step={step}, total={total}. Freezing...")
        yield total
        print(f"[Inside Generator] Unfrozen! Continuing to next iteration...")
        step += 1

gen = accumulator()
print("Main program: requesting value 1...")
v1 = next(gen)
print("Main received:", v1)

print("\nMain program doing some other work in between...")

print("Main program: requesting value 2...")
v2 = next(gen)
print("Main received:", v2)

Generator Functions vs Normal Functions

Understanding how generator functions differ from standard functions across lifecycle, memory, and return mechanisms is critical for systems architecture:

Dimension Normal Function Generator Function
Exit Keyword return yield (can have empty return to stop)
Calling Mechanism Runs immediately to completion; returns value. Returns a generator object without running code yet.
Execution Multiplicity Single entry, single exit. Single entry, multiple pause and resume points.
Stack Frame Lifecycle Frame created on call, destroyed on return. Frame retained on heap between yields; destroyed on exhaustion.
Memory Consumption Must build full collection in RAM before returning. Generates one element at a time (O(1) memory).
normal_vs_generator.py 
# 1. Normal Function: Builds full list in RAM
def get_squares_normal(n):
    results = []
    for i in range(1, n + 1):
        results.append(i ** 2)
    return results

# 2. Generator Function: Yields one at a time
def get_squares_gen(n):
    for i in range(1, n + 1):
        yield i ** 2

# Comparison
normal_data = get_squares_normal(5)
gen_obj = get_squares_gen(5)

print("Normal function result:", normal_data, type(normal_data))
print("Generator function result:", gen_obj, type(gen_obj))
print("Consuming generator into list:", list(gen_obj))

Lazy Evaluation: Memory and Performance Benchmarks

📊 Figure 16.5: Memory Footprint: Eager List vs. Lazy Generator Stream
Eager data structures such as lists construct and store every element simultaneously in heap RAM, causing explosive memory usage with large datasets (`O(N)`). Generators produce items lazily on demand, requiring only a constant `~112 bytes` of pointer state (`O(1)`), making them ideal for processing large log files or streaming real-time events.
Visual Summary & Trace:
Lazy Evaluation: Consumes O(1) constant RAM (~112 bytes) compared to O(N) multi-megabyte allocations in eager lists.

Lazy evaluation means delaying the evaluation of an expression until its value is actually needed. In contrast, eager evaluation computes everything upfront. Let us measure the physical RAM impact of 10 million integers using Python's sys.getsizeof().

memory_benchmark.py 
import sys

# 1. Eager: List with 1,000,000 integers
list_mem = [i for i in range(1_000_000)]
list_bytes = sys.getsizeof(list_mem)

# 2. Lazy: Generator expression for 1,000,000 integers
gen_mem = (i for i in range(1_000_000))
gen_bytes = sys.getsizeof(gen_mem)

print(f"Memory used by List (1,000,000 ints): {list_bytes / (1024 * 1024):.2f} MB ({list_bytes} bytes)")
print(f"Memory used by Generator (1,000,000 ints): {gen_bytes} bytes")
print(f"Memory Reduction Factor: ~{list_bytes // gen_bytes:,}x smaller!")
🖥 Output
Memory used by List (1,000,000 ints): 8.15 MB (8552712 bytes)
Memory used by Generator (1,000,000 ints): 208 bytes
Memory Reduction Factor: ~41,118x smaller!
✔ The Million-Item Lesson
A list holding 1,000,000 items consumes ~8.5 Megabytes of RAM. A generator doing the exact same computation takes only 208 bytes—regardless of whether it processes 10,000, 1,000,000, or 1,000,000,000 items!

File-Processing Streaming Generator

If you attempt to load a 10 GB server log file into Python using f.readlines(), your operating system will run out of memory (OOM Crash). Using a streaming generator, you can parse gigabytes of data cleanly in constant RAM!

streaming_log_reader.py 
# Demonstrating a file streaming generator pattern
def stream_error_logs(log_lines):
    """
    Generator that processes a log stream and yields only formatted ERROR events.
    In real code, log_lines would be open('server.log')
    """
    for line in log_lines:
        line = line.strip()
        if "ERROR" in line:
            parts = line.split(" - ")
            yield {
                "timestamp": parts[0],
                "level": "ERROR",
                "message": parts[1].replace("ERROR: ", "")
            }

# Simulated server log entries
sample_logs = [
    "2026-10-24 10:00:01 - INFO: Server started successfully",
    "2026-10-24 10:01:14 - ERROR: Database connection timeout on port 5432",
    "2026-10-24 10:02:30 - WARNING: High memory usage: 88%",
    "2026-10-24 10:04:45 - ERROR: Authentication failed for user 'admin'",
    "2026-10-24 10:05:00 - INFO: Health check passed"
]

print("Parsing log stream via generator:")
for err in stream_error_logs(sample_logs):
    print(f"[{err['timestamp']}] CRITICAL ALERT: {err['message']}")

Generator Pipelines (Data Pipeline Architecture)

One of the most powerful paradigms in Python is generator pipelining—chaining multiple generator stages together like Unix pipes (cat log | grep ERROR | awk ...). Each stage does one focused task and yields directly into the next stage.

🔄 Multi-Stage Generator Pipeline Flow
Stage 1: Generate Numbers (0..9)
→
Stage 2: Filter Evens (0, 2, 4..)
→
Stage 3: Square Values (0, 4, 16..)
→
Stage 4: Format with Prefix
generator_pipeline.py 
# Stage 1: Data Producer
def number_stream(limit):
    for i in range(limit):
        yield i

# Stage 2: Filter (Even numbers only)

Mistake Symptoms The Correct Fix
1. Forgetting to return wrapper Function becomes NoneType. Calling it raises TypeError: 'NoneType' object is not callable. Ensure the outer decorator function ends with return wrapper.
2. Forgetting to return result Decorated function executes, but returns None instead of its computation. Inside wrapper(), do res = func(*args, **kwargs) and return res.

What Is a Closure?

Late Binding in Closures: The Infamous Loop Trap & Fix

This is arguably the most famous tricky question in Python technical interviews. Why does creating a list of functions inside a loop produce identical numbers instead of 0, 1, 2, 3?

⚠ The Trap: Late Binding

Performance & Architectural Design Guidelines

✅ When to Use Generators
  • When processing large or infinite datasets.
  • When memory efficiency is paramount (e.g. Docker containers with tight limits).
  • When you only need to iterate over the dataset once.
  • When downstream consumers can process records incrementally.
❌ When to Use Standard Lists Instead
  • When you need random access by index (e.g. data[5]).
  • When you need to know the total length upfront (len(data)).
  • When you need to make multiple passes over the same dataset.
  • When using functions that require full lists (e.g. json.dump).
⚖ Closures vs Object-Oriented Classes
Rule of Thumb: If your component has only one public method (e.g. a callable action or calculation) and encapsulates a few variables, a closure is faster, more concise, and more Pythonic. If your component needs multiple methods (e.g. reset(), save(), undo()) or inheritance, build an OOP Class.

24 Multi-Level Practice Questions with Solutions

Test your mastery of advanced Python concepts with these 24 interview questions ranging from beginner to advanced. Click any question to reveal the complete explanation and runnable solution:

🔵 Beginner Level Questions (1–8)

Q1: What is the exact difference between an iterable and an iterator in Python?

Answer: An iterable is any object capable of returning an iterator (implements __iter__() or sequence __getitem__()), such as a list or string. An iterator is the actual stream object that tracks current position and implements both __iter__() and __next__().

Q2: What happens when next() is called on an exhausted iterator?

Answer: Python raises a StopIteration exception. If you pass a second argument to next(it, default), it returns the default value instead of raising the exception.

Q3: How does yield differ from return?

Answer: return terminates the function permanently and destroys its local stack frame. yield sends a value back to the caller, freezes the function's execution state, and allows it to resume from the exact same line on the next next() call.

Q4: Write a one-line generator expression to generate the cubes of even numbers from 1 to 20. 
even_cubes = (x**3 for x in range(1, 21) if x % 2 == 0)
print(list(even_cubes))
Q5: Why is memory consumption of a generator constant regardless of dataset size?

Answer: Because generators utilize lazy evaluation. They calculate and produce only one item in memory at a time upon request, rather than instantiating and holding the entire collection in RAM.

Q6: What is a first-class function?

Answer: A language has first-class functions when functions are treated like any other object. They can be assigned to variables, stored in data structures, passed as arguments, and returned from other functions.

Q7: What does the @ symbol do when placed above a function definition?

Answer: It is syntactic sugar for passing the function to a decorator and reassigning the function name to the returned wrapper: @dec def f(): pass is identical to f = dec(f).

Q8: What does the LEGB rule stand for?

Answer: Local → Enclosing → Global → Built-in. It defines the order in which Python searches for variable names.

🟢 Intermediate Level Questions (9–16)

Q9: Why should you always use @functools.wraps inside a decorator?

Answer: Without @wraps(func), the decorated function inherits the wrapper's name ('wrapper') and docstring, obliterating introspection, debugging stack traces, and API documentation.

Q10: Write a custom iterator class `EvenRange` that iterates through even numbers from start to stop. 
class EvenRange:
    def __init__(self, start, stop):
        self.current = start if start % 2 == 0 else start + 1
        self.stop = stop

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.stop:
            raise StopIteration
        val = self.current
        self.current += 2
        return val

print(list(EvenRange(1, 10)))  # [2, 4, 6, 8]
Q11: How do you pass arguments to a decorator itself (e.g. @repeat(num=3))?

Answer: Create a Decorator Factory—an outer function that takes the arguments and returns the decorator, resulting in 3 nested levels: factory → decorator → wrapper.

Q12: What is a closure and what are its three necessary conditions?

Answer: A closure is a nested function that retains access to variables in its enclosing scope. The 3 conditions: 1. Must be a nested function, 2. Must reference an enclosing variable, 3. Enclosing function must return the nested function.

Q13: Why does modifying an outer variable inside a closure without nonlocal raise UnboundLocalError?

Answer: When Python compiles a function and sees an assignment (e.g. x = x + 1), it classifies x as local. At runtime, evaluating x + 1 fails because the local x has not yet been assigned a value.

Q14: Explain the difference between nonlocal and global.

Answer: nonlocal binds a variable to the nearest enclosing function scope (excluding module globals). global binds a variable to the top-level module scope.

Q15: What will `[f() for f in [lambda: i for i in range(3)]]` print, and why?

Answer: It prints [2, 2, 2] because of late binding. The lambda functions look up i when called, by which time the loop has completed and i equals 2.

Q16: How do you fix the late-binding loop issue using default arguments? 
# Use default argument to bind value early at definition time:
funcs = [lambda x=i: x for i in range(3)]
print([f() for f in funcs])  # [0, 1, 2]

🔴 Advanced Level Questions (17–24)

Q17: How does Python store closure variables internally?

Answer: Python stores them inside the function's __closure__ attribute as a tuple of cell objects. Each cell object has a cell_contents attribute pointing to the captured heap object.

Q18: What is the purpose of the generator .send() method, and why must you prime it first?

Answer: gen.send(val) sends a value into the generator that becomes the result of the current yield expression. You must prime it with next(gen) or gen.send(None) so that execution advances to the first yield; otherwise Python raises a TypeError.

Q19: What is the difference between generator.throw() and generator.close()?

Answer: gen.throw(ExcType) raises an arbitrary exception inside the generator at its suspension point. gen.close() raises a specific GeneratorExit exception to gracefully terminate the generator.

Q20: Explain the wrapping order versus execution order when stacking decorators @A above @B.

Answer: Wrapping order is bottom-up: @B wraps func first, then @A wraps the resulting wrapper (equivalent to A(B(func))). Execution order is top-down: A's wrapper runs first, calls B's wrapper, which calls func.

Q22: What happens if a generator function uses both `yield` and `return value`?

Answer: In Python 3, a return value inside a generator raises StopIteration(value). The return value is attached as the exception's argument (used in advanced coroutine handling).

def custom_cache(func):

        if args not in cache:

Q24: Can an iterator be used in more than one for-loop?

Answer: No. Once an iterator is exhausted, its state is consumed. A second loop over the same iterator terminates immediately with 0 iterations. To iterate again, you must create a new iterator from the underlying iterable.
