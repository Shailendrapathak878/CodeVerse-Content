Combinators & Pseudo-classes

Unlock the full expressive power of CSS. Master DOM hierarchy targeting using the four combinators, and dynamically respond to user interaction, structural positions, and form states with precision pseudo-classes.

1 Technical Definitions & Conceptual Foundations

In simple CSS, selectors match individual elements in isolation (e.g., p or .card). Real-world web documents, however, are complex nested hierarchical trees of nodes. To style elements based on their spatial relationships or transient user states, CSS provides two crucial mechanisms:

  • Combinators: Special syntactic symbols (or whitespace) placed between simple selectors to express a structural relationship (parent, direct child, descendant, or sibling) between them in the DOM tree.
  • Pseudo-classes: Keywords preceded by a single colon (:) appended to a selector that targets an element only when it satisfies a specific dynamic state (e.g. hovered, focused, checked, or occupying a specific numeric position among siblings).
💡 Specificity Impact

Combinators have zero specificity weight: div > p carries the exact same specificity as div p: (0, 0, 2).
Pseudo-classes carry the specificity of a Class Selector: :hover or :nth-child() adds (0, 1, 0) to the selector!

2 The Four CSS Combinators

Figure 4.1: DOM hierarchy illustrating parent, direct child, adjacent sibling, and nested descendant relationships.
Combinator Name Syntax Example Exact DOM Matching Rule
(space) Descendant Combinator article p Matches any <p> that is anywhere inside <article>, including nested children and grandchildren at arbitrary depth.
> Child Combinator article > p Matches only <p> elements that are direct, immediate children of <article>. Grandchildren inside wrappers are excluded.
+ Adjacent Sibling Combinator h2 + p Matches the <p> that appears immediately after an <h2>, sharing the identical parent element.
~ General Sibling Combinator h2 ~ p Matches all <p> siblings that follow an <h2> under the same parent, regardless of intervening elements.

3 Pseudo-Classes Categorized Reference

1. User Interaction Pseudo-Classes

  • :hover — Activates when the user hovers over an element with a pointer device (mouse, trackpad).
  • :active — Activates during the physical press or click (between mousedown and mouseup).
  • :focus — Activates when an element receives keyboard focus or clicks into a form field.
  • :focus-visible — Activates only when focus is initiated via keyboard navigation (Tab key). Critical for preserving focus rings for accessible users without annoying mouse clickers!
  • :focus-within — Activates on a parent container when any of its descendants currently has focus. Perfect for highlighting an entire form card while typing.
⚠️ The Mandatory "LVHA" Rule for Hyperlinks

When styling anchor tags, pseudo-classes MUST be declared in this strict chronological order:
Link → Visited → Hover → Active
Mnemonic: "LoVe HAte". Declaring :hover before :visited will cause visited links to never show hover colors due to the cascade!

2. Structural & Tree-Order Pseudo-Classes

Pseudo-Class Description & Formula Concrete Example
:first-child Matches if the element is the very first child of its parent. li:first-child
:last-child Matches if the element is the very last child of its parent. li:last-child
:only-child Matches if the element has no siblings whatsoever under its parent. p:only-child
:nth-child(an+b) Matches elements according to an algebraic formula or keyword (even, odd). tr:nth-child(even)
:first-of-type Matches the first occurrence of that specific tag under the parent. p:first-of-type
:nth-of-type(n) Calculates index counting only siblings of the exact same tag type. p:nth-of-type(2)
🚨 Crucial Distinction: :nth-child vs :nth-of-type

Consider a container with: <h1> followed by <p>Paragraph 1</p>.
• p:first-child fails to match because the first child is an <h1>!
• p:first-of-type successfully matches Paragraph 1 because it is the first <p> among the siblings!

3. Form State & Validation Pseudo-Classes

  • :checked — Matches radio buttons, checkboxes, or options in a <select> that are checked.
  • :disabled / :enabled — Matches form controls based on presence of the disabled attribute.
  • :required / :optional — Matches inputs that mandate user entry.
  • :valid / :invalid — Dynamically styles inputs based on browser constraint validation (e.g. valid email patterns).
  • :placeholder-shown — Matches inputs whose placeholder is currently visible (i.e. input is empty).

4 Progressive Code Examples

Level 1: Basic Dropdown Menu using Child Combinator & Hover

Level 1: Navigation Menu CSS 
.nav-menu {
  list-style: none;
  display: flex;
  gap: 1rem;
}

/* Direct child links only; avoids altering nested dropdown links */
.nav-menu > li > a {
  color: #1e293b;
  font-weight: 600;
  text-decoration: none;
}

.nav-menu > li > a:hover {
  color: #4f46e5;
}

Level 2: Alternating Data Table with :nth-child

Level 2: Zebra Striped Table CSS 
.data-table {
  width: 100%;
  border-collapse: collapse;
}

/* Alternating zebra row backgrounds */
.data-table tbody tr:nth-child(even) {
  background-color: #f8fafc;
}

/* Highlight on hover */
.data-table tbody tr:hover {
  background-color: #f1f5f9;
}

/* Target the very first and very last column headers */
.data-table th:first-child { border-top-left-radius: 8px; }
.data-table th:last-child  { border-top-right-radius: 8px; }

Level 3: Custom Toggle Switch with :checked and Adjacent Sibling (+)

Building fully accessible, custom styled switches using pure CSS without JavaScript:

Level 3: Pure CSS Custom Toggle HTML & CSS 
/* Hide native checkbox visually while keeping keyboard accessibility */
.toggle-input {
  position: absolute;
  opacity: 0;
}

/* Track styling via adjacent sibling combinator */
.toggle-input + .toggle-slider {
  display: inline-block;
  width: 48px;
  height: 26px;
  background-color: #cbd5e1;
  border-radius: 13px;
  cursor: pointer;
  transition: background-color 0.25s ease;
}

/* When checkbox is checked, update track */
.toggle-input:checked + .toggle-slider {
  background-color: #4f46e5;
}

/* Focus visible for accessibility */
.toggle-input:focus-visible + .toggle-slider {
  outline: 2px solid #4f46e5;
  outline-offset: 2px;
}

Level 4: Real-World Interactive Accordion (Zero JS)

Using the checkbox-hack with General Sibling (~) to expand and collapse panels:

Level 4: Production Pure CSS Accordion CSS 
.accordion-card {
  border: 1px solid #e2e8f0;
  border-radius: 8px;
  margin-bottom: 0.75rem;
  overflow: hidden;
}

.accordion-toggle {
  display: none;
}

.accordion-label {
  display: flex;
  justify-content: space-between;
  padding: 1rem 1.25rem;
  background: #f8fafc;
  font-weight: 700;
  cursor: pointer;
}

.accordion-content {
  max-height: 0;
  overflow: hidden;
  transition: max-height 0.3s ease, padding 0.3s ease;
  padding: 0 1.25rem;
}

/* When toggle is checked, open the sibling content! */
.accordion-toggle:checked ~ .accordion-content {
  max-height: 200px;
  padding: 1rem 1.25rem;
}

5 Common Mistakes & DevTools Inspection

Mistake 1: Violating the Link State Order (LVHA)

Writing a:hover { color: red; } before a:visited { color: purple; } causes all previously visited links to stay purple when hovered! The browser applies the last matched rule in cascade order.

Mistake 2: Missing Focus Indicators for Accessibility

Incorrect vs Accessible Focus CSS 
/* ❌ INACCESSIBLE: Destroys keyboard navigation visibility */
button:focus {
  outline: none;
}

/* ✅ ACCESSIBLE: Shows focus rings only when navigating via keyboard */
button:focus:not(:focus-visible) {
  outline: none;
}

button:focus-visible {
  outline: 3px solid #4f46e5;
  outline-offset: 2px;
}

How to Force Pseudo-Class States in DevTools

  1. Inspect the target element in Chrome DevTools.
  2. In the Styles panel, click the :hov toggle button in the top right bar.
  3. Check the boxes for :hover, :active, :focus, or :focus-within to lock the element into that visual state for inspecting and tweaking styles without keeping your mouse physically pressed!

6 Knowledge Assessment & Exercises

1. Which combinator selects an element only if it immediately follows another element under the same parent?
  • A) General Sibling (~)
  • B) Adjacent Sibling (+)
  • C) Child (>)
  • D) Descendant (space)
Answer: B) Adjacent Sibling (+) — The plus symbol matches strictly the immediately adjacent following sibling.
2. Which pseudo-class triggers when ANY descendant element inside a container receives focus?
  • A) :focus
  • B) :focus-visible
  • C) :focus-within
  • D) :active
Answer: C) :focus-within — It bubbles focus state up to parent containers.

Hands-On Coding Exercise

Task: Given an unordered list of articles, write CSS to:

  • Target every <li> that has at least one sibling preceding it and add a margin-top: 1rem (The "Lobotomized Owl" sibling pattern).
  • Target every third table row using :nth-child() formula.
Exercise Solution CSS 
/* 1. Add top margin to every list item that has a preceding sibling */
li + li {
  margin-top: 1rem;
}

/* 2. Target every 3rd row: 3, 6, 9, 12... */
tr:nth-child(3n) {
  background-color: #f1f5f9;
}

7 Quick Reference Cheat Sheet

Descendant A B

Matches B at any depth inside A.

Child A > B

Matches B only if it is a direct child of A.

Adjacent A + B

Matches B if immediately preceded by sibling A.

General Sibling A ~ B

Matches all B siblings following A.

LVHA Order

:link → :visited → :hover → :active.

:focus-within

Container responds when any child gets focus.
