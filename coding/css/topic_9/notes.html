Typography, Fonts & Text Formatting

More than 90% of the Web is information presented through typography. Master the anatomy of digital type, system font stacks, the @font-face rule with modern WOFF2, unitless line-height mechanics, and advanced text truncation.

1 Digital Typography & Font Anatomy

In web architecture, there is a fundamental distinction between a Typeface and a Font:

  • Typeface (Font Family): The overarching aesthetic design and visual system of letterforms (e.g. Inter, Helvetica, Merriweather).
  • Font: The physical or digital delivery file embodying that typeface at a specific weight, style, and width (e.g. Inter-Bold.woff2).

2 Modern Native System Font Stacks

Before downloading external multi-megabyte font files over the network, top-tier engineering organizations (GitHub, Stripe, Vercel) deploy System Font Stacks.

A system font stack instructs the browser to utilize whatever modern, high-grade font is already pre-installed directly into the user's operating system:

Production Modern System Font Stack CSS 
body {
  font-family: 
    -apple-system,                  /* Safari & macOS / iOS (San Francisco) */
    BlinkMacSystemFont,             /* Chrome on macOS */
    "Segoe UI",                     /* Windows 10 & 11 */
    Roboto,                         /* Android & ChromeOS */
    Helvetica, Arial,               /* Legacy fallbacks */
    sans-serif;                     /* Generic family catch-all */
}
⚡ Advantages of System Fonts

Zero HTTP requests: 0 milliseconds font download latency. Eliminates Cumulative Layout Shift (CLS) and Flash of Invisible Text (FOIT) entirely, while feeling naturally native on whatever operating system the user runs!

3 Custom Web Fonts with @font-face

When custom branding demands unique typefaces, use the CSS @font-face at-rule:

Production @font-face Declaration CSS 
@font-face {
  font-family: "CustomBrand";
  src: url("fonts/custom-brand.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;               /* Crucial for web performance! */
}

The font-display Performance Property

  • swap (Recommended): Gives the font face an extremely short block period (100ms) and an infinite swap period. The browser renders fallback text immediately so the user can read the content without delay, then seamlessly swaps in the custom web font once loaded.
  • block: Hides text completely for up to 3 seconds waiting for the font (Flash of Invisible Text — harms Core Web Vitals!).
  • optional: If the web font doesn't load within 100ms, the browser permanently uses the fallback for that page session. Ideal for mobile connections!

4 Core Typographic Properties

Property Accepted Values Critical Best Practices
font-family Comma-separated priority list Always wrap multi-word font names in quotes (e.g. "Baloo 2") and end with generic sans-serif or serif.
font-size rem, clamp() Avoid raw px for body text to preserve user zoom accessibility preferences.
font-weight 100 to 900 (400=Normal, 700=Bold) Ensure your font file actually includes the weights you specify.
line-height Unitless numbers (1.5, 1.6) Never use fixed px or percentages! Unitless values inherit proportionally across child headings.
letter-spacing -0.02em, 0.05em Use negative tracking for big headings (tighter punch); use positive tracking for uppercase text.
🚨 The Unitless line-height Rule Explained

If a parent has font-size: 16px; line-height: 24px; (or 150%), that exact 24px height is inherited by child elements! If a child heading inside has font-size: 32px;, its lines will collide and overlap because 24px is shorter than the 32px letters!
Conversely, with unitless line-height: 1.5;, the child heading multiplies its OWN font size by 1.5 (32px × 1.5 = 48px), maintaining perfect proportional breathing room!

5 Text Truncation & Overflow Formatting

In web dashboards and card grids, dynamic database text frequently overflows containers. CSS provides two distinct truncation techniques:

1. Single-Line Ellipsis Truncation

The classic 3-property formula to truncate overflowing text with an ellipsis (...):

Single-Line Truncation Formula CSS 
.truncate-single {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

2. Multi-Line Clamping (-webkit-line-clamp)

Truncates text after an exact number of lines (e.g. 2 or 3 lines of preview text):

Multi-Line Clamp Formula CSS 
.truncate-multiline {
  display: -webkit-box;
  -webkit-line-clamp: 2;          /* Clamp after exactly 2 lines */
  -webkit-box-orient: vertical;
  overflow: hidden;
}

7 Common Mistakes & DevTools Inspection

Mistake 1: Missing the Generic Fallback Family

Declaring font-family: "MyCustomFont"; without an ending generic fallback (like sans-serif) causes browsers to revert to default Times New Roman if the web font fails to download! Always finish your stack with sans-serif, serif, or monospace.

How to Verify Rendered Fonts in Chrome DevTools

  1. Inspect any text element in Chrome DevTools.
  2. In the right-hand panel, select the Computed tab.
  3. Scroll to the very bottom to find the Rendered Fonts box!
  4. Chrome will tell you exactly which local or network font file was rasterized to paint those letters on screen.

8 Knowledge Assessment & Exercises

1. Why is unitless line-height (e.g. 1.5) preferred over fixed line-height (e.g. 24px)?
  • A) Unitless line-height renders faster in WebKit.
  • B) Unitless line-height scales proportionally with each child element's unique font size.
  • C) Fixed units are deprecated in CSS3.
  • D) Unitless values prevent bold fonts from rendering.
Answer: B) Unitless values scale proportionally with each child's own font-size, preventing text collisions.
2. Which font format offers modern Brotli compression and maximum web performance?
  • A) TTF (TrueType)
  • B) SVG
  • C) WOFF2
  • D) EOT
Answer: C) WOFF2 — WOFF2 offers state-of-the-art compression, saving ~30% byte size compared to original WOFF.
