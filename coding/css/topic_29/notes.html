01

The Critical Rendering Path

CSS is a render-blocking resource: browsers will not render any pixels until the external stylesheet is fully downloaded and parsed into the CSSOM. Optimizing CSS directly improves Core Web Vitals (LCP, INP, and CLS).

02

Minimizing Reflows and Repaints

Understanding the performance cost of CSS properties:

  • Layout (Reflow - Most Expensive): Properties that affect geometry (width, height, padding, margin, top, left). Changes force the browser to recalculate the positions of all surrounding elements.
  • Paint (Medium Cost): Properties that affect appearance without geometry (color, background-color, box-shadow). Requires repainting pixels.
  • Composite (Cheapest - 60/120fps): Properties that run directly on the GPU (transform and opacity). Never triggers layout or paint!
03

Modern Performance Superpowers: content-visibility and will-change

CSS provides bleeding-edge optimization controls:

  • content-visibility: auto;: Skips rendering off-screen elements until the user scrolls near them, cutting initial page rendering times by up to 70% on long, image-heavy feeds!
  • contain-intrinsic-size: 1px 500px;: Provides estimated height to prevent scrollbar jumping when using content-visibility.
  • will-change: transform;: Warns the browser GPU ahead of time to allocate a composite layer. Use sparingly!
EX

Interactive Code & Live Examples

Example

Blazing Fast Rendering with content-visibility and Hardware Acceleration:

CSS 
/* Supercharge long scrollable feeds */
.feed-post {
  content-visibility: auto;
  contain-intrinsic-size: 0 450px; /* Estimated placeholder height */
  margin-bottom: 24px;
  background: #ffffff;
  border-radius: 12px;
  padding: 24px;
}

/* High-performance GPU button transition */
.btn-cta {
  will-change: transform;
  transition: transform 0.2s cubic-bezier(0.16, 1, 0.3, 1);
}
.btn-cta:hover {
  transform: translateY(-2px);
}

WARN

Common Mistakes & Pro Tips

⚠️ Common Trap: Overusing will-change on hundreds of elements

Problem: Setting will-change: all forces the browser to consume excessive GPU memory, degrading mobile performance.

Fix: Apply will-change only on active animated elements, and remove it after animation completes.

⚠️ Common Trap: Animating top/left for tooltips and sliders

Problem: Animating top and left triggers CPU layout recalculations 60 times per second.

Fix: Always animate with transform: translate() instead.
