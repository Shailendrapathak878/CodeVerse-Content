Absolute vs Relative Units

Choosing the correct unit is the foundation of responsive design:

  • Pixels (px): Absolute unit. 1px = 1 device-independent pixel. Good for thin borders and shadows, but bad for accessible font sizing because it ignores user browser font-size preferences.
  • rem (Root EM): Relative to the font-size of the root <html> element (browser default is typically 16px). 1rem = 16px, 2rem = 32px. Industry standard for scalable typography and layout.
  • em: Relative to the font-size of the current element (compounds down nested trees). Excellent for component-relative padding.
  • Percentage (%): Relative to the parent element's dimensions.
02

Viewport Units: vh, vw, and Modern dvh

Viewport units are percentages of the browser window:

  • 100vw: 100% of viewport width.
  • 100vh: 100% of viewport height.
  • The Mobile Safari 100vh Trap: On mobile devices, 100vh causes content to be hidden behind the browser's dynamic bottom URL bar.
  • Dynamic Viewport Units (dvh, svh, lvh): 100dvh automatically adjusts its height as the mobile URL navigation bar shrinks or expands!

Interactive Code & Live Examples

Example

Scalable Typography and Fullscreen Mobile Layout:

CSS 
/* Root setup */
html {
  font-size: 16px;
}

/* Typography scales with rem */
h1 {
  font-size: 2.5rem; /* 40px */
  margin-bottom: 1rem; /* 16px */
}

/* Button padding scales with em (scales if font-size changes) */
.btn {
  font-size: 1rem;
  padding: 0.5em 1.2em;
}

/* True mobile-friendly full height section */
.hero-fullscreen {
  min-height: 100dvh;
  display: flex;
  align-items: center;
  justify-content: center;
}

WARN

Common Mistakes & Pro Tips

⚠️ Common Trap: Using pixels (px) for all font sizes

Problem: When visually impaired users increase default text size in their browser settings, pixel-based fonts refuse to scale.

Fix: Always use rem for typography so text scales with user accessibility preferences.

⚠️ Common Trap: Using 100vh on mobile layouts without fallback

Problem: Bottom navigation bars on iOS Safari and Android Chrome overlap the bottom of 100vh elements.

Fix: Use min-height: 100dvh (with 100vh fallback for legacy browsers).
