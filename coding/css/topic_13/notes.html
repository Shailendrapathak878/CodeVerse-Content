Z-Index & Stacking Contexts

Solve the mystery of overlapping elements. Understand the browser's default 7-layer painting order, why high z-index values still get trapped behind lower elements, and how modern Stacking Contexts and isolation: isolate end z-index wars forever.

1 The 3D Z-Axis & Default Stacking Order

While standard CSS layout operates along a two-dimensional grid (X-axis horizontally, Y-axis vertically), web browsers also project an invisible Z-axis perpendicular to the monitor screen, extending directly towards the user's eyes.

Whenever two elements overlap on screen, the browser must decide which element is painted in front and which is buried behind. Without any z-index properties declared, the browser follows the strict Default Painting Order:

Layer Level Painting Category (From Furthest Back to Forefront)
Layer 1 (Back) Background and borders of the root <html> element
Layer 2 Descendant non-positioned block elements in normal document source order
Layer 3 Non-positioned floating elements (float: left / right)
Layer 4 Non-positioned inline elements, text runs, and child images
Layer 5 (Front) Positioned elements (relative, absolute, fixed, sticky) in source order
💡 The Positioned Priority Axiom

Notice that Layer 5 paints all positioned elements in front of normal document text and blocks, even if the positioned element has no z-index set!

2 The z-index Property & Its Golden Prerequisite

The z-index property accepts an integer (positive, zero, or negative) representing its explicit elevation along the Z-axis.

🚨 The Golden Rule: z-index DOES NOT WORK on Static Elements!

If an element has default position: static;, setting z-index: 999999; has zero visual effect! To activate z-index, the element must be:
1. Explicitly positioned (position: relative, absolute, fixed, or sticky), OR
2. A direct child item of a Flexbox (display: flex) or Grid (display: grid) container!

3 Stacking Contexts: Why z-index: 9999 Still Loses

Every junior developer experiences this confounding bug: they assign z-index: 9999 to a dropdown menu, yet it stays trapped underneath an adjacent header that only has z-index: 1!

Why does this happen? The answer is Stacking Contexts.

Figure 13.1: The Atomic Stacking Context Rule: A child element's z-index only operates within its parent's local stacking context.

What Spawns a New Stacking Context?

An element creates a new independent Stacking Context if it satisfies ANY of these conditions:

  • Root element of the document (<html>).
  • position: relative or absolute with a numerical z-index (other than auto).
  • position: fixed or sticky.
  • opacity strictly less than 1.
  • transform, filter, backdrop-filter, or perspective not set to none.
  • isolation: isolate (explicit modern stacking context boundary!).

4 Ending the Z-Index War: Design Token Scales

In chaotic codebases, developers blindly type z-index: 9999999 whenever something doesn't show up. To end this anti-pattern forever, establish a centralized Design Token Scale using CSS variables:

Systematic Z-Index Architecture CSS 
:root {
  --z-below:     -1;     /* Decorative background graphics */
  --z-base:      0;      /* Standard document flow content */
  --z-card:      10;     /* Elevated cards on hover */
  --z-dropdown:  100;    /* Navigation dropdown menus */
  --z-sticky:    200;    /* Sticky headers & navbars */
  --z-modal:     1000;   /* Fullscreen dialog overlays & modals */
  --z-toast:     2000;   /* Floating push alert notifications */
}

.avatar-group img {

Level 3: Using isolation: isolate to Scope Component Layers

Level 3: isolation: isolate CSS 
.widget-card {
  /* Establishes a fresh, sealed stacking context without requiring position/z-index hacks! */
  isolation: isolate;
  position: relative;
  padding: 1.5rem;
}

/* Negative z-index on background graphic stays contained inside this card! */
.widget-card::before {
  content: "";
  position: absolute;
  inset: 0;
  background: radial-gradient(circle, #eef2ff 0%, transparent 70%);
  z-index: -1;                 /* Stays behind card text, but DOES NOT vanish behind body! */
}

6 Common Mistakes & DevTools Inspection

Mistake 1: The Accidental Stacking Context

Adding opacity: 0.99; or transform: translate(0, 0); to a parent container instantly turns it into a brand new Stacking Context! If that container had child tooltips that previously hovered above outside elements, those tooltips now become trapped inside the parent's boundary.

How to Inspect 3D Stacking Contexts in Chrome DevTools

  1. Press F12 to open Chrome DevTools.
  2. Click the three dots (⋮) in the top-right corner of DevTools → More tools → Layers.
  3. The Layers panel presents an interactive 3D rotatable view of your webpage, visualizing every single compositor layer and stacking context physically stacked in space!

7 Knowledge Assessment & Exercises

1. On which element will z-index FAIL to have any effect?
  • A) position: relative
  • B) position: static
  • C) position: absolute
  • D) Direct child of a flex container
Answer: B) position: static — Static elements do not honor z-index offsets.
2. Which modern CSS property explicitly isolates a component to create a clean stacking context?
  • A) z-index: 0
  • B) overflow: hidden
  • C) isolation: isolate
  • D) display: flow-root
Answer: C) isolation: isolate — It was designed specifically to create a local stacking context cleanly.

Hands-On Coding Exercise

Task: Create a decorative background pseudo-element with z-index: -1 that stays behind the card's text, but guarantee it doesn't disappear behind the webpage's body background.

Exercise Solution CSS 
.hero-card {
  position: relative;
  isolation: isolate;           /* Traps the negative z-index inside the card! */
  padding: 2.5rem;
}

.hero-card::before {
  content: "";
  position: absolute;
  inset: 0;
  background: linear-gradient(135deg, #eef2ff, #f8fafc);
  z-index: -1;
}
