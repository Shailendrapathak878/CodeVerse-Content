Display, Visibility & Positioning

Control how elements participate in the Normal Document Flow. Master the behavioral differences between block, inline, and inline-block, the critical showdown between display: none and visibility: hidden, and the five CSS positioning paradigms.

1 Normal Flow & The display Property

By default, web browsers render HTML elements according to the Normal Document Flow:

  • Block-level elements (div, p, h1, article): Begin on a fresh new line, stack vertically from top to bottom, and naturally expand horizontally to fill 100% of their parent container.
  • Inline elements (span, a, strong, em): Sit side-by-side along the text baseline, wrapping onto subsequent lines only when horizontal space runs out. They do NOT honor explicit width or height, and their vertical margins do not push adjacent text away!

The Big Three Display Modes

Display Value Starts New Line? Honors Width / Height? Honors Margins & Padding? Primary Usage
block Yes Yes Yes (All 4 sides) Structural layout cards, wrappers, sections, paragraphs.
inline No (Sits inline) No (Ignored!) Horizontal only (Left/Right) Text highlights, anchor links, editorial emphasis.
inline-block No (Sits inline) Yes! Yes (All 4 sides!) Buttons, badge pills, navigation items needing custom padding.

2 Showdown: display: none vs. visibility: hidden vs. opacity: 0

Hiding elements is a daily frontend task. However, choosing the wrong property causes major visual glitches and broken accessibility:

Property Consumes Layout Space? Clickable / Interactive? Screen Reader Accessible? Animatable with Transition?
display: none; No (Completely removed from flow) No No (Ignored by assistive tech) No (Instant jump)
visibility: hidden; Yes (Blank invisible box remains) No No Can transition visibility delay
opacity: 0; Yes (Consumes full space) Yes! (Still clickable!) Yes Yes! (Smooth fades)
🚨 The Ghost Click Bug: opacity: 0 Trap

If you fade out a modal or popup using only opacity: 0, the invisible button or backdrop is still physically sitting on the screen and intercepting mouse clicks! Always combine opacity: 0 with pointer-events: none; or visibility: hidden; to prevent ghost clicks.

3 The Five Positioning Paradigms

The position property breaks an element out of standard flow, allowing precise coordinate offsets using top, right, bottom, and left.

Figure 12.1: Spatial anchor comparison across the five CSS position property values.

1. position: static

The browser default. The element lives entirely in normal document flow. Offsets like top or left are ignored.

2. position: relative

The element remains in normal flow, but can be shifted visually using offsets without altering the layout of surrounding siblings. Crucially, declaring position: relative turns the element into an anchor container for any position: absolute children inside it!

3. position: absolute

The element is ripped out of normal document flow (consuming zero space). It anchors itself to the nearest ancestor that has a non-static position. If no positioned ancestor exists, it anchors to the initial viewport.

4. position: fixed

Ripped out of normal flow and anchored directly to the browser viewport window. Even when the user scrolls down 10,000 pixels, a fixed element stays pinned on the screen.

5. position: sticky

A dynamic hybrid. It acts as relative until the user scrolls past its coordinate threshold (e.g. top: 0;), at which point it pins like fixed. It remains pinned until reaching the bottom of its parent container!

⚠️ Why Sticky Breaks

If ANY ancestor element has overflow: hidden, overflow: auto, or overflow: scroll, sticky positioning will fail to activate because the scroll context is trapped inside the ancestor!

5 Common Mistakes & Fixes

Mistake 1: The Missing Positioned Ancestor

You write position: absolute; top: 10px; right: 10px; on a close button, but forget to add position: relative; on the parent card. The close button shoots straight to the top right of the whole webpage! Always remember: Absolute elements anchor to the nearest non-static ancestor.

Mistake 2: Thinking top Works on position: static

Offsets (top, left, etc.) and z-index are completely ignored on static elements. You must specify position: relative, absolute, fixed, or sticky.

6 Knowledge Assessment & Exercises

1. Which property completely removes an element from the document layout flow so it consumes zero space?
  • A) visibility: hidden
  • B) opacity: 0
  • C) display: none
  • D) position: static
Answer: C) display: none — It removes the element completely from the layout tree.
2. To anchor a position: absolute child inside a parent card, what must be added to the parent?
  • A) display: block
  • B) position: relative (or any non-static position)
  • C) overflow: hidden
  • D) z-index: 1
Answer: B) position: relative — It establishes a containing block for absolute children.

7 Quick Reference Cheat Sheet

inline-block

Sits inline with text, yet honors width, height & padding.

display: none

Removes element from layout. Zero space consumed.

relative

Offsets from self. Preserves original layout space.

absolute

Anchors to nearest positioned ancestor.

fixed

Anchors strictly to the browser viewport.

sticky

Pins when scrolling reaches defined threshold (e.g. top: 0).
