Polymorphism & Virtual Functions in C++

Master compile-time and runtime polymorphism in C++, function overloading, dynamic virtual dispatch, and abstract classes.

A What Is Polymorphism?

Polymorphism means "one interface, different behaviors." Instead of writing separate code for every scenario, a single interface triggers specific actions depending on the object handling the request.

Think of a store payment terminal: the machine exposes a single checkout interface, but tapping a debit card, credit card, or digital wallet runs each method's own payment logic.

C++ organizes polymorphism into two main categories:

  • Compile-Time (Static Binding): Resolved during compilation using function overloading and operator overloading.
  • Runtime (Dynamic Binding): Resolved during execution using inheritance, base pointers, and virtual functions.

B Function Overloading — Compile-Time Polymorphism

Function overloading allows multiple functions in the same scope to share the same name with different parameter counts or types.

The compiler matches the correct version at compile time based on arguments. Changing only the return type does not create an overload.

Function Overloading Example (main.cpp) C++ 
#include <iostream>
using namespace std;

class Calculator {
public:
    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
};

int main() {
    Calculator c;

    cout << c.add(2, 3) << '\n';
    cout << c.add(2, 3, 4) << '\n';

    return 0;
}

C Function Overriding & Runtime Polymorphism

Function overriding occurs when a derived class provides its own implementation of a virtual function inherited from a base class.

When diverse animals respond to sound(), each produces its own call. Calling through a base pointer routes execution dynamically to the derived object:

Runtime Polymorphism with Virtual Functions (main.cpp) C++ 
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal makes a sound" << '\n';
    }

    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << '\n';
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << '\n';
    }
};

int main() {
    Dog dog;
    Cat cat;

    Animal* a = &dog;
    a->sound();

    a = &cat;
    a->sound();

    return 0;
}
✓ Program Output
Dog barks
Cat meows
  • virtual enables dynamic runtime dispatch instead of static binding.
  • override tells the compiler to verify the inherited signature matches.
  • A base pointer (Animal* a) can reference derived objects, invoking the actual overridden method.
  • A virtual destructor ensures proper derived cleanup when deleting through base pointers.

D What Are Virtual Functions?

A virtual function is a base-class member function that derived classes can override. Calling it through a base pointer or reference triggers runtime dispatch based on the actual memory object.

Without virtual, C++ uses static binding based on the pointer type, executing the base function and ignoring derived overrides. A base pointer alone does not create polymorphism.

E Abstract Classes & Pure Virtual Functions

Sometimes a base class represents an abstract interface that should never be instantiated. Declaring a virtual function with = 0 creates a pure virtual function, making the class abstract.

Concrete derived classes must implement all pure virtual functions before they can be instantiated.

Abstract Class Interface (main.cpp) C++ 
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing a circle" << '\n';
    }
};

int main() {
    Circle c;
    c.draw();

    return 0;
}

Drawing a circle

F Quick Comparison & Common Mistakes

Feature Compile-time Runtime
Common example Function overloading Virtual function overriding
Selection During compilation During execution
Typical mechanism Different parameter lists Base pointer/reference & virtual dispatch

Common pitfalls to avoid in polymorphic designs:

  • Overloading vs. Overriding: Overloading happens in the same scope with different parameters; overriding replaces a base virtual function using the exact same signature.
  • Omitting Virtual: Forgetting virtual triggers static binding, calling the base class function.
  • Override Mismatches: Using override with mismatched parameters fails compilation, catching typos.
  • Instantiating Abstract Classes: Abstract classes cannot be directly instantiated.
  • Missing Virtual Destructors: Deleting derived objects via base pointers without virtual destructors causes memory leaks.
