Dynamic Memory Management

Understand runtime memory allocation, the new and delete operators, dynamic arrays, memory safety, and modern smart pointers.

A What Is Dynamic Memory Management?

Ordinary local variables have an automatic lifetime: the compiler allocates their memory upon block entry and frees it upon exit. However, programs often need storage whose size or lifetime cannot be predicted before runtime.

Think of seating reservations: ordinary variables are like reserving a fixed row of seats before a show starts. Dynamic allocation lets your program request seats on demand during the event as needed.

Dynamic memory is allocated from system memory commonly called the free store (or heap). Unlike automatic variables, dynamically allocated objects persist until your code explicitly releases them or an automated owner destroys them.

B The new and delete Operators

In C++, you request dynamic memory using the new operator, which allocates the requested type and returns its memory address. When the data is no longer needed, you must release it using the delete operator:

Allocating and Freeing a Single Integer (main.cpp) C++ 
#include <iostream>

int main() {
    int* ptr = new int(25); // Allocates dynamic int with value 25

    std::cout << "Value: " << *ptr << '\n';

    delete ptr;       // Releases allocated memory
    ptr = nullptr;    // Prevents retaining a dead address

    return 0;
}
✓ Program Output
Value: 25

The pointer ptr is a local variable storing the dynamic object's address. Calling delete ptr ends the object's lifetime. Setting ptr = nullptr prevents retaining a dead address, though other pointers sharing the address remain unaffected.

C Dynamic Arrays: new[] and delete[]

When an array size is determined at runtime, fixed arrays cannot suffice. C++ allocates dynamic arrays using new[] and releases them using delete[]:

Dynamic Array Allocation (main.cpp) C++ 
#include <iostream>

int main() {
    int size = 3;
    int* numbers = new int[size]{10, 20, 30};

    for (int i = 0; i < size; i++) {
        std::cout << numbers[i] << ' ';
    }
    std::cout << '\n';

    delete[] numbers;   // Must use delete[] for arrays
    numbers = nullptr;

    return 0;
}
✓ Program Output
10 20 30

Pairing rules are strict: single objects allocated with new require delete, while arrays allocated with new[] require delete[]. Never use single delete on an array.

D Memory Leaks and Dangling Pointers

Two classic hazards occur when pointers and dynamic memory lose synchronization:

  • Memory Leak: Dynamically allocated memory loses its owning pointer without being deleted. The memory remains occupied and unusable until the program terminates.
  • Dangling Pointer: A pointer retains an address after the pointed-to object has been deallocated. Dereferencing a dangling pointer causes crashes or memory corruption.
◆ Visual 6: Memory Leak Architecture (Lost Pointer)
⚠ Memory Leak Scenario
ptr = new int(25); ptr = nullptr; // Memory at 0x5000 is now orphaned!

The pointer was reassigned or went out of scope without calling delete. The allocation remains stranded in RAM and can never be reclaimed.

◆ Visual 7: Dangling Pointer Hazard (Dead Address)
☠ Dangling Pointer Scenario
delete ptr; // Object freed, but ptr still holds 0x5000! *ptr = 90; // CRASH!

The memory was released back to the OS, but the pointer still points to that dead address. Dereferencing invokes undefined behavior.

E Dynamic Memory with Functions

You can pass a pointer to a dynamic object into a function. The function accesses the data without taking ownership.

The caller that allocated the object remains responsible for calling delete. Never return a pointer to a local stack variable.

F Safer Modern C++: Smart Pointers

Modern C++ dramatically reduces manual memory bugs by providing smart pointers in the <memory> header:

  • std::unique_ptr: Enforces exclusive ownership. Automatically deallocates the object as soon as the pointer goes out of scope.
  • std::make_unique: The recommended, exception-safe function for creating unique pointers.
  • std::shared_ptr: Allows shared ownership across multiple holders using reference counting.
Automatic Cleanup with std::unique_ptr (main.cpp) C++ 
#include <iostream>
#include <memory>

int main() {
    // Automatically allocated and freed upon scope exit
    auto ptr = std::make_unique<int>(50);

    std::cout << *ptr << '\n';
    return 0; // No delete needed!
}
✓ Program Output
50

In modern C++, standard containers like std::vector replace raw dynamic arrays, while smart pointers replace manual new and delete.

◆ Visual 8: Raw Pointer vs. Smart Pointer Management
Raw Pointers (Manual)

Requires manual delete. Susceptible to memory leaks, dangling pointers, and double-free errors if mismanaged.

Smart Pointers (Automated RAII)

Automatically invokes cleanup upon leaving scope. Guaranteed zero leaks with clean, safe ownership semantics.

G Common Pitfalls & Best Practices

  • Forgetting to Delete: Unreleased allocations cause memory leaks. Always pair new with delete.
  • Mismatched Freeing: Calling delete on an array or delete[] on a single object corrupts memory.
  • Dangling Pointer Dereference: Never read or write through a pointer whose target has been deleted.
  • Double Deletion: Calling delete twice on the same address leads to undefined behavior. Assign ptr = nullptr after deletion.
  • Prefer Modern Constructs: Favor std::vector and std::make_unique over raw dynamic allocations.
⚠ Critical Rule: Neutralize Pointers After Deletion
Always set a raw pointer to nullptr immediately after calling delete. Calling delete nullptr; is completely safe in C++, whereas deleting a dangling pointer crashes your program.

H Practical Example: Dynamic Array Calculation

The following complete program allocates a dynamic array to calculate the sum of values and safely frees the allocation:

Dynamic Array Sum (main.cpp) C++ 
#include <iostream>

int main() {
    int size = 4;
    int* values = new int[size]{5, 10, 15, 20};

    int total = 0;
    for (int i = 0; i < size; i++) {
        total += values[i];
    }

    std::cout << "Total: " << total << '\n';

    delete[] values;    // Frees array memory
    values = nullptr;   // Prevents dangling pointer

    return 0;
}
✓ Program Output
Total: 50

Here, delete[] values frees the array and values = nullptr prevents dangling pointers. In modern C++, std::vector<int> is usually the safer, simpler choice.
