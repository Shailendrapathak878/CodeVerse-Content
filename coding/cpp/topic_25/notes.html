Smart Pointers & Modern C++

Master modern C++ memory ownership with unique_ptr, shared_ptr, and weak_ptr, and write clean, leak-free software using RAII and modern language idioms.

A Part A — Why Smart Pointers?

Dynamic memory in classic C++ relies on manual new and delete. While powerful, manually tracking heap addresses invites severe memory bugs: memory leaks when a programmer forgets delete, dangling pointers when accessing freed addresses, and double deletion crashes when deleting the same address twice.

In production applications, manual cleanup frequently fails because an unexpected exception, early return statement, or branching logic bypasses the delete line entirely. Modern C++ solves this architectural flaw by tying dynamic memory directly to stack object lifetimes.

♦ Visual 1: Three Manual Memory Hazards
1. Memory Leak Allocated heap memory is never freed, exhausting RAM over time.
2. Dangling Pointer Pointer still references an address after it was freed elsewhere.
3. Double Deletion Calling delete twice on one address corrupts the heap and crashes.

A smart pointer is a lightweight class wrapper around a raw pointer that automates deallocation through RAII (Resource Acquisition Is Initialization). The resource is acquired during construction and released automatically in the destructor when the wrapper exits scope.

Think of renting an apartment with a smart lease caretaker: the moment your lease duration ends, the caretaker cleans up and returns the keys automatically. You never risk forgetting to hand in the keys. Smart pointers provide that exact automatic cleanup and are available through the standard <memory> header.

Example 1: Scoped Automatic Cleanup via RAII C++ 
#include <iostream>
using namespace std;

class Resource {
public:
    Resource() { cout << "Resource acquired\n"; }
    ~Resource() { cout << "Resource destroyed automatically\n"; }
    void work() { cout << "Resource in use\n"; }
};

int main() {
    {
        // Inner scope: object destroyed automatically on scope exit
        Resource r;
        r.work();
    }
    cout << "Scope exited safely.\n";
    return 0;
}
Output

Resource in use
Resource destroyed automatically
Scope exited safely.

B Part B — The Three Essential Smart Pointers

Modern C++ provides three standardized smart pointers, each expressing clear ownership semantics:

  • std::unique_ptr: Exclusive ownership. Exactly one pointer owns the heap object. Its copy constructor is explicitly deleted to prevent duplicate owners, but ownership can be transferred using std::move. Prefer std::make_unique (C++14) because it guarantees exception safety and avoids raw new expressions.
  • std::shared_ptr: Shared ownership. Multiple pointers reference the same object alongside an internal control block tracking the active reference count. Memory is freed only when the last owner releases ownership. The use_count() method inspects the active reference tally for demonstration, though production logic should avoid branching on it.
  • std::weak_ptr: Non-owning observer. Observes a shared_ptr target without incrementing the ownership count. In cyclic graphs or parent-child trees, two shared_ptr objects pointing to each other prevent the count from ever reaching zero; substituting one link with weak_ptr breaks the cycle and eliminates silent leaks.
♦ Visual 3: The Three Ownership Models
std::unique_ptr Sole owner (1:1). Private locker key. Cannot be duplicated.
std::shared_ptr Shared owners (N:1). Shared family account with ref-count.
std::weak_ptr Non-owning observer. Guest spectator observing status.
Example 2: Exclusive Ownership with unique_ptr C++ 
#include <iostream>
#include <memory>
using namespace std;

class Device {
public:
    string name;
    Device(string n) : name(n) { cout << name << " connected\n"; }
    ~Device() { cout << name << " disconnected\n"; }
};

int main() {
    {
        auto dev = make_unique<Device>("Sensor-A");
        cout << "Active: " << dev->name << "\n";
    } // dev destroyed automatically here
    cout << "Main continues.\n";
    return 0;
}

Active: Sensor-A
Sensor-A disconnected
Main continues.
♦ Visual 4: Ownership Transfer via std::move
Before: ptr1 (Owner) → Heap [100] ptr2 (nullptr)
After move: ptr1 (nullptr) → Heap [100] ptr2 (New Owner)
Example 3: Transferring unique_ptr with std::move C++ 
#include <iostream>
#include <memory>
using namespace std;

int main() {
    auto ptr1 = make_unique<int>(100);
    cout << "ptr1 value: " << *ptr1 << "\n";

    // Transfer ownership: ptr1 becomes null
    auto ptr2 = move(ptr1);

    cout << "ptr2 value: " << *ptr2 << "\n";
    if (ptr1 == nullptr) {
        cout << "ptr1 is now null!\n";
    }
    return 0;
}
Output
ptr1 value: 100
ptr2 value: 100
ptr1 is now null!
♦ Visual 5: Reference Counting in std::shared_ptr
Multiple Owners (use_count > 0) sp1 and sp2 point to one object. Control block ref-count = 2. Object remains alive.
Final Owner Leaves (use_count == 0) When the last owner goes out of scope, ref-count hits 0 and memory is deallocated.
Example 4: shared_ptr & Reference Counting C++ 
#include <iostream>
#include <memory>
using namespace std;

int main() {
    auto sp1 = make_shared<int>(42);
    cout << "Initial count: " << sp1.use_count() << "\n";

    {
        auto sp2 = sp1; // Increments count to 2
        cout << "Inner scope count: " << sp1.use_count() << "\n";
        cout << "sp2 value: " << *sp2 << "\n";
    } // sp2 exits scope: count decrements to 1

    cout << "After inner scope count: " << sp1.use_count() << "\n";
    return 0;
}
Output
Initial count: 1
Inner scope count: 2
sp2 value: 42
After inner scope count: 1
♦ Visual 6: Safe Observation with std::weak_ptr
Alive Object: observer.lock() → temporary shared_ptr (Safe Access)
Freed Object: observer.expired() == true → returns nullptr (Prevents Crash)
Example 5: Observing with weak_ptr and lock() C++ 
#include <iostream>
#include <memory>
using namespace std;

int main() {
    weak_ptr<int> observer;
    {
        auto sharedObj = make_shared<int>(250);
        observer = sharedObj;
        cout << "Shared count: " << sharedObj.use_count() << "\n";

        if (auto locked = observer.lock()) {
            cout << "Observed value: " << *locked << "\n";
        }
    } // sharedObj destroyed here

    if (observer.expired()) {
        cout << "Resource expired! Cannot lock.\n";
    }
    return 0;
}
Output
Shared count: 1
Observed value: 250
Resource expired! Cannot lock.

C Part C — Modern C++ Features

Modern C++ (introduced in C++11 and expanded in C++14) fundamentally modernized language idioms. While C++11 introduced move semantics, nullptr, auto, and shared_ptr, C++14 completed the model by providing std::make_unique and relaxed constexpr functions evaluated entirely at compile time.

  • auto (C++11): Deduces variable types at compile time, eliminating redundant type declarations.
  • nullptr (C++11): Strongly-typed pointer literal replacing ambiguous 0 and NULL macros.
  • Range-based for (C++11): Traverses collections cleanly without manual iterator indices.
  • Move Semantics & std::move (C++11): Enables transferring expensive resources between objects instead of deep copying. Note that std::move does not move data itself; it casts an lvalue to an rvalue reference to enable move constructors.
  • std::make_unique (C++14): Allocates heap memory cleanly with exception safety.
♦ Visual 8: Modern C++ Core Toolkit

Deduces types at compile time cleanly without typing overhead.

Type-safe null pointer preventing ambiguous function overloads.
Range-based for:
Iterates through containers safely without index boundaries.
std::move:
Casts to rvalue reference to enable efficient ownership theft.
Example 6: Modern C++ Features Combined C++ 
#include <iostream>
#include <memory>
#include <vector>
#include <algorithm>
using namespace std;

struct Student {
    string name;
    int score;
};

int main() {
    // Vector of unique_ptr managing Student objects
    vector<unique_ptr<Student>> roster;
    roster.push_back(make_unique<Student>(Student{"Alice", 95}));
    roster.push_back(make_unique<Student>(Student{"Bob", 72}));
    roster.push_back(make_unique<Student>(Student{"Charlie", 88}));

    cout << "Class Roster:\n";
    for (const auto& s : roster) {
        cout << "  " << s->name << ": " << s->score << "\n";
    }

    // Lambda with STL count_if
    int passed = count_if(roster.begin(), roster.end(),
        [](const unique_ptr<Student>& s) { return s->score >= 75; });

    cout << "Students scoring >= 75: " << passed << "\n";
    return 0;
}
Output
Class Roster:
  Alice: 95
  Bob: 72
  Charlie: 88
Students scoring >= 75: 2
♦ Visual 9: Common Smart Pointer Mistakes
1. Copying unique_ptr unique_ptr cannot be copied. Use std::move to transfer ownership explicitly.
2. Circular shared_ptr Cycles Two objects holding shared_ptr to each other leak memory. Break cycles with weak_ptr.
3. Direct weak_ptr Access weak_ptr has no -> operator. Always call .lock() before reading.
4. Dereferencing nullptr Always check if (ptr != nullptr) before dereferencing moved or reset pointers.
☆ Which Pointer Would You Choose?
Managing an exclusive rendering engine or database handle? Use std::unique_ptr as your default. Sharing a cached texture asset across multiple sprites? Choose std::shared_ptr. Tracking active enemies in a game without keeping dead ones alive? Use std::weak_ptr.
