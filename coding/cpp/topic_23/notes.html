STL Containers & Iterators

Master C++ sequence, associative, and unordered containers, and explore iterators as the universal bridge connecting data structures to algorithms.

A STL Containers — The Big Picture

An STL container is a pre-built, template-based data structure that stores and organizes collections in memory. Instead of managing raw pointers and manual memory buffers, STL containers handle their own memory, provide strict type safety, and offer uniform interfaces.

C++ STL containers divide into three primary families:

  • Sequence Containers: Elements maintain linear sequential order by position. Key examples: vector, array, deque, list, and forward_list.
  • Associative Containers: Elements are sorted by keys in balanced search trees, providing logarithmic O(log n) search. Key examples: set, multiset, map, and multimap.
  • Unordered Associative Containers: Elements are hashed into bucket tables for average O(1) lookup without order guarantees. Key examples: unordered_set and unordered_map.

Select sequence containers when sequential order or indexing matters. Choose associative containers when you need elements sorted by key. Choose unordered containers when maximum key lookup speed is needed.

☆ Think About It
Why doesn't C++ have a single universal container? Every data structure embodies distinct architectural trade-offs: vector provides instant indexed reads but slow middle insertions, whereas list enables instant node insertions anywhere but sacrifices indexed access.

B Understanding Common Containers

C++ provides specialized containers tailored for different performance profiles:

  • vector: Contiguous dynamic array with fast O(1) index access via [] and fast amortized insertion at the end. The default choice in C++.
  • array: Fixed-size contiguous stack sequence with zero heap overhead and compile-time bounds.
  • deque: Double-ended queue providing fast O(1) push/pop at both front and back, alongside indexed access.
  • list: Doubly linked list enabling O(1) insertion and removal at any iterator position without indexed access.
  • forward_list: Singly linked list with forward-only iteration, minimizing memory per node.
  • set & unordered_set: Store unique elements. set stays sorted; unordered_set uses hash buckets for fast lookup. multiset permits duplicates.
  • map & unordered_map: Store key-value pairs. map sorts by key; unordered_map offers average O(1) lookup. multimap permits duplicate keys.

Example 1: vector Growth & Traversal C++ 
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> scores = {85, 92, 78};
    scores.push_back(95);

    // 1. Range-based for loop
    for (int s : scores) {
        cout << s << " ";
    }
    cout << "\n";

    // 2. Explicit iterator traversal
    for (auto it = scores.begin(); it != scores.end(); ++it) {
        cout << *it << " ";
    }
    cout << "\n";
    return 0;
}

Example 3: set vs unordered_set C++ 
#include <iostream>
#include <set>
#include <unordered_set>
using namespace std;

int main() {
    // std::set stores unique values in sorted order
    set<int> uniqueSorted = {50, 10, 50, 30, 20};
    cout << "std::set (sorted): ";
    for (int val : uniqueSorted) {
        cout << val << " ";
    }
    cout << "\n";

    // std::unordered_set provides fast O(1) hash lookup
    unordered_set<int> fastLookup = {50, 10, 30, 20};
    if (fastLookup.find(30) != fastLookup.end()) {
        cout << "Found 30 in unordered_set!\n";
    }
    return 0;
}
Output
std::set (sorted): 10 20 30 50
Found 30 in unordered_set!
Example 4: map & unordered_map Key-Value Storage C++ 
#include <iostream>
#include <map>
#include <unordered_map>
#include <string>
using namespace std;

int main() {
    // std::map sorts pairs automatically by key
    map<int, string> students;
    students[103] = "Alice";
    students[101] = "Bob";
    students[102] = "Charlie";

    for (const auto& pair : students) {
        cout << pair.first << ": " << pair.second << "\n";
    }

    // std::unordered_map provides fast O(1) avg lookup
    unordered_map<string, int> ages;
    ages["Alice"] = 20;
    cout << "Alice's age: " << ages["Alice"] << "\n";
    return 0;
}
Output
101: Bob
102: Charlie
103: Alice
Alice's age: 20

C Iterators — The Bridge to Container Elements

An iterator is a pointer-like object that traverses container elements without exposing internal memory layouts. Iterators serve as the universal bridge connecting containers to algorithms: functions like std::find() or std::sort() interact solely through iterators, operating seamlessly across arrays, vectors, or trees.

STL traversal relies on a half-open range [begin(), end()). begin() points directly to the first valid element. Crucially, end() points to the past-the-end marker immediately following the final element. Dereferencing *end() causes undefined behavior!

For read-only traversal, use cbegin() and cend(). These return const iterators that prevent accidental element modification at compile time.

Iterators are categorized by movement capabilities:

  • Forward: Steps forward one element at a time (++). Example: forward_list.
  • Bidirectional: Steps forward and backward (++, --). Examples: list, set, map.
  • Random Access: Jumps to any element in O(1) time (++, --, +, -, []). Examples: vector, array, deque.

Because std::sort() requires random-access iterators, it compiles seamlessly on vector and array, but fails on list. For linked lists, use the container's built-in list::sort() member method instead.

A range-based for loop is clean syntax sugar over begin() and end(). Use explicit iterators when you need backward iteration, custom stepping, or element deletion while iterating.

Iterator Invalidation: Modifying a container while holding iterators can invalidate them. Appending elements to a vector with push_back() may trigger memory reallocation, invalidating all active iterators. Conversely, list insertions preserve all other existing iterators.

Example 5: Const vs Mutable Iterators C++ 
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> numbers = {10, 20, 30};

    // cbegin() and cend() enforce read-only safety
    cout << "Read-only: ";
    for (auto it = numbers.cbegin(); it != numbers.cend(); ++it) {
        cout << *it << " ";
    }
    cout << "\n";

    // begin() and end() permit in-place modifications
    for (auto it = numbers.begin(); it != numbers.end(); ++it) {
        *it += 5;
    }
    cout << "Modified first: " << numbers[0] << "\n";
    return 0;
}
Output
Read-only: 10 20 30
Modified first: 15
Example 6: find() Algorithm with Safe Dereference C++ 
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    vector<int> ids = {101, 204, 308, 412};

    int target = 308;
    auto it = find(ids.begin(), ids.end(), target);

    // Crucial: Always check it != end() before dereferencing
    if (it != ids.end()) {
        cout << "Found: " << *it << "\n";
    } else {
        cout << "Not found\n";
    }
    return 0;
}
Output
Found: 308
