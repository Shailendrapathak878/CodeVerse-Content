Exception Handling & File I/O

Build resilient C++ applications using structured exception handling with try, throw, and catch, and establish persistent data storage through standard file streams.

A Part A — Exception Handling in C++

An exception is an anomalous runtime condition that disrupts normal program execution. Without exception handling, unexpected inputs—such as dividing by zero, missing files, or exhausted memory—cause programs to terminate abruptly. C++ provides a structured mechanism to catch and resolve runtime anomalies without crashing.

Think of an online food delivery payment: if your card transaction fails, the app does not crash or erase your shopping cart. Instead, it catches the payment error, informs you, and offers an alternative payment method like cash or UPI. Exception handling provides that exact recovery net.

Exception handling is organized around three keywords:

  • try: Encloses code that might encounter a runtime error.
  • throw: Signals an error and sends an exception object out of the current scope.
  • catch: Intercepts the thrown exception and executes recovery logic.

Example 1: Division-by-Zero Prevention C++ 
#include <iostream>
using namespace std;

double safeDivide(double num, double den) {
    if (den == 0.0) {
        throw "Division by zero is not allowed!";
    }
    return num / den;
}

int main() {
    try {
        cout << "10 / 2 = " << safeDivide(10, 2) << "\n";
        cout << "10 / 0 = " << safeDivide(10, 0) << "\n";
    } catch (const char* msg) {
        cout << "Caught exception: " << msg << "\n";
    }
    cout << "Program resumes safely.\n";
    return 0;
}
Output
10 / 2 = 5
Caught exception: Division by zero is not allowed!
Program resumes safely.

Crucial Distinctions in Error Handling:

  • Syntax Error vs. Exception: Syntax errors prevent compilation entirely. In contrast, exceptions occur at runtime and must be explicitly thrown; C++ does not automatically convert hardware faults into catchable exceptions.
  • Throw vs. Catch: throw signals failure and bails out of current execution, whereas catch receives the error object and executes recovery.
  • Specific Catch vs. Catch-All: Specific handlers catch matching types (like int or string); catch(...) serves as an untyped fallback for any unexpected error.

C++ matches catch blocks by data type. Multiple handlers allow tailored responses for distinct errors. A catch-all handler catch(...) intercepts any unhandled exception type, serving as an ultimate safety net.

Example 2: Multiple Catch Handlers & Catch-All C++ 
#include <iostream>
#include <string>
using namespace std;

void checkScore(int score) {
    if (score < 0) throw -1;
    if (score > 100) throw string("Score exceeds 100!");
    cout << "Valid score: " << score << "\n";
}

int main() {
    int tests[] = {92, -5, 105};
    for (int s : tests) {
        try {
            checkScore(s);
        } catch (int errCode) {
            cout << "Error code: " << errCode << "\n";
        } catch (const string& msg) {
            cout << "String error: " << msg << "\n";
        } catch (...) {
            cout << "Unknown error caught!\n";
        }
    }
    return 0;
}
Output
Valid score: 92
Error code: -1
String error: Score exceeds 100!

The <stdexcept> header defines standard exception classes derived from std::exception, such as std::runtime_error and std::out_of_range. Calling .what() returns an explanatory C-string describing the error.

Basic Exception Safety: Exception handling should never leave data corrupted or leak dynamic memory. Always ensure objects remain in valid, consistent states when an error occurs, leveraging modern RAII resource managers to release resources automatically during stack unwinding.

Example 3: Standard runtime_error & .what() C++ 
#include <iostream>
#include <stdexcept>
using namespace std;

void verifyAge(int age) {
    if (age < 18) {
        throw runtime_error("Access denied: Age must be at least 18.");
    }
    cout << "Access granted for age: " << age << "\n";
}

int main() {
    try {
        verifyAge(20);
        verifyAge(15);
    } catch (const runtime_error& e) {
        cout << "Runtime error: " << e.what() << "\n";
    }
    return 0;
}
Output
Access granted for age: 20
Runtime error: Access denied: Age must be at least 18.
♦ Visual 4: Common Exception Traps
1. Inverted Catch Order Placing base catch(exception&) before derived classes shadows specific handlers.
2. Catching by Value Always catch by const& to prevent object slicing and unnecessary copying.
3. Silent Swallowing Empty catch(...) {} hides bugs and leaves data corrupted. Always log or recover.

B Part B — File I/O in C++

Variables in memory vanish when a program finishes execution. File I/O (Input/Output) enables non-volatile persistence by storing data on physical disk drives. The <fstream> header provides specialized stream classes to read and write files reliably.

C++ categorizes file streams into three primary roles:

  • ofstream: Output stream used to create and write files.
  • ifstream: Input stream used to open and read files.
  • fstream: Bidirectional stream capable of simultaneous reading and writing.
♦ Visual 6: Stream Class Specializations

Creates files & saves data.

fstream Read & Write (Both)
Dual-direction processing.
♦ Visual 7: File Modes Comparison Table
Mode Flag Behavior Practical Use
ios::out Opens for writing (truncates existing data) Creating fresh configuration files
ios::in Opens for reading only Inspecting saved database records
ios::app Appends new content to the end Recording server access logs
ios::trunc Discards previous file contents Clearing out old cache data
ios::binary Reads/writes raw unformatted bytes Image, audio, or archive files

Always verify file operations using .is_open() before reading or writing. When a file stream variable goes out of scope, its destructor automatically flushes buffers and closes the file descriptor through RAII (Resource Acquisition Is Initialization), preventing resource leaks.

Text Files vs. Binary Files: Text files store human-readable characters organized into lines, making them ideal for configuration, logs, and CSV exports. In contrast, binary files (opened with ios::binary) store raw unformatted bytes directly as represented in memory, delivering faster I/O and compact storage for images, compiled assets, or structured records.

Example 4: Writing Records with ofstream C++ 
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    ofstream outFile("students.txt");

    if (!outFile.is_open()) {
        cout << "Failed to open file!\n";
        return 1;
    }

    outFile << "Alice 92\n";
    outFile << "Bob 85\n";
    outFile.close();

    cout << "Records saved to students.txt\n";
    return 0;
}
Terminal Output

Example 5: Reading File Safely with getline() C++ 
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    ifstream inFile("students.txt");

    if (!inFile.is_open()) {
        cout << "Could not open file!\n";
        return 1;
    }

    string line;
    while (getline(inFile, line)) {
        cout << "  " << line << "\n";
    }
    inFile.close();
    return 0;
}
Terminal Output
  Alice 92
  Bob 85

Do not use while (!file.eof()) to control read loops. The eof flag is only set after an attempted read past the end, causing the final line to print twice. Controlling the loop directly with while (getline(file, line)) ensures clean termination.

Example 6: Appending with ios::app C++ 
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    // Append mode preserves existing data
    ofstream appFile("students.txt", ios::app);
    if (appFile.is_open()) {
        appFile << "Charlie 88\n";
        appFile.close();
    }

    ifstream readFile("students.txt");
    string line;
    while (getline(readFile, line)) {
        cout << "  " << line << "\n";
    }
    readFile.close();
    return 0;
}
Terminal Output
  Alice 92
  Bob 85
  Charlie 88
Example 7: Combining File Handling & Exceptions C++ 
#include <iostream>
#include <fstream>
#include <string>
#include <stdexcept>
using namespace std;

void loadConfig(const string& filename) {
    ifstream file(filename);
    if (!file.is_open()) {
        throw runtime_error("File not found: " + filename);
    }
    cout << "File opened successfully.\n";
}

int main() {
    try {
        loadConfig("missing_config.txt");
    } catch (const runtime_error& e) {
        cout << "Caught error: " << e.what() << "\n";
    }
    cout << "System fallback initiated.\n";
    return 0;
}
Terminal Output
Caught error: File not found: missing_config.txt
System fallback initiated.
♦ Visual 9: File I/O Diagnostics & Troubleshooting
File Not Found:
Verify relative path to working directory or provide absolute path.
Accidental Overwrite:
ios::out wipes existing data; switch to ios::app to preserve.
Duplicated Final Line:
Caused by !file.eof(); loop directly over getline() instead.
Stream State Bits:
Inspect file.fail(), file.bad(), or file.eof() for issues.
☆ Which Approach Would You Choose?
Need to log server activity continuously? Choose ios::app to append without erasing past history. Need to export an updated student summary report from scratch? Use default ofstream (ios::out) to overwrite old records.
