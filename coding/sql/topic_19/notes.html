Window Functions & Real-World Database Queries

Calculate rankings, running totals, and partitioned aggregates across rows without collapsing records into single summary lines.

A What Is a Window Function?

A window function calculates a value across related rows while keeping individual rows in the output. Unlike GROUP BY, it does not collapse each group into one row.

Real-Life Example: A teacher wants to show every student's marks along with their class rank and branch average without hiding individual student names.

Standard aggregate functions like AVG() summarize records by collapsing multiple rows into a single output row. Window functions avoid this loss of detail by computing results across an independent window of rows while preserving each record in the final result set.

Example 1 — Rank Students

The RANK() function assigns positions according to marks:

Rank Students by Marks RANK() 
SELECT name, marks,
       RANK() OVER (
         ORDER BY marks DESC
       ) AS class_rank
FROM Students;

Expected output:

name marks class_rank
Priya 90 1
Neha 85 2
Rahul 80 3
Arjun 75 4
Aman 70 5

RANK() assigns positions according to marks. If marks tie, ranks can be skipped after the tie. This example has no ties.

B Partitioning & Group Comparisons

Example 2 — Compare Marks with Branch Average

Compute an average separately for each branch while keeping all rows:

Branch Average Window OVER 
SELECT name, branch, marks,
       AVG(marks) OVER (
         PARTITION BY branch
       ) AS branch_avg
FROM Students
ORDER BY branch, name;

Expected output:

name branch marks branch_avg
Priya AI 90 87.5
Neha AI 85 87.5
Rahul CSE 80 75
Aman CSE 70 75
Arjun IT 75 75

Key window concepts:

  • OVER() defines the window used for the calculation.
  • PARTITION BY branch calculates an average separately for each branch.
  • Every student's row remains visible.

The final ORDER BY branch, name sorts the output for clear readability without altering the underlying window calculation.

Window-function support and syntax depend on the database system and version.
