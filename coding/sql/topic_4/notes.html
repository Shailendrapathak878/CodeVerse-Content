CREATE, ALTER & DROP

Learn the primary Data Definition Language (DDL) commands to create new tables, modify existing schemas, and safely remove database objects.

A CREATE — Building Table Structure

The CREATE command builds a new database object from scratch, such as an entire database or a structured table.

In our college example, the administration creates a new Students table to store records for all enrolled students:

Create Students Table Schema SQL 
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    branch VARCHAR(30)
);

Essential Schema Elements:

  • CREATE TABLE Students tells the database engine to establish a new table named Students.
  • Column Names: Define the structured fields (student_id, name, age, branch).
  • Data Types: Specify what values can enter each column (INT for numbers, VARCHAR for text).
  • PRIMARY KEY uniquely identifies each student record and forbids duplicate IDs or empty values.
Empty Schema Created (0 Rows)
student_id [PK] name age branch
No rows inserted yet. Schema structure is defined and waiting for data.

Schema vs. Data: CREATE TABLE only defines the empty blueprint (columns, constraints, and data types). It does not insert student records — records are added later using INSERT.

B ALTER — Modifying Existing Tables

The ALTER TABLE command changes the structure of an existing table without destroying its current records or requiring you to recreate it from scratch.

College Example: After enrolling students, the college decides to record each student's official email address. We add a new email column:

Add New Column to Students Table SQL 
ALTER TABLE Students
ADD email VARCHAR(100);
1. BEFORE ALTER: 4 Columns Original Schema
student_id name age branch
101 Rahul 19 CSE
102 Priya 20 AI
2. AFTER ALTER: 5 Columns + Added email column
student_id name age branch email [NEW]
101 Rahul 19 CSE NULL
102 Priya 20 AI NULL
★ Why NULL for Existing Records?

The new email column exists, but holds NULL (no value) for existing rows because email addresses have not yet been provided. SQL expands the schema structure without fabricating data.

Note: Syntax for modifying data types, renaming columns, or dropping columns varies slightly across database systems (e.g., MySQL uses MODIFY COLUMN, while PostgreSQL uses ALTER COLUMN ... TYPE).

C DROP — Removing Database Objects

The DROP TABLE command permanently removes an entire table definition along with all rows stored inside it from the database.

Context: A temporary test table created during campus workshop exercises is no longer needed and can be safely deleted:

Demonstration Only — Destructive Command DDL 
DROP TABLE Students;
✖ Table Dropped & Destroyed

Table "Students" No Longer Exists

Both the schema blueprint and all stored student records have been permanently erased from disk.

⚠ Critical Safety Warning

DROP TABLE is permanent and irreversible: Unlike deleting a file to a desktop Recycle Bin, DROP TABLE immediately purges table data and metadata. Never run this query on a production database to "test" it!

D Command Comparison & Key Takeaways

To master Data Definition Language (DDL), understand the distinct purpose of each command:

Command Core Purpose College Real-Life Example
CREATE Creates a new database object from scratch. Create the Students table schema.
ALTER Modifies the structure of an existing object. Add an email column to Students.
DROP Permanently deletes an object and its data. Remove a temporary workshop table.

3 Essential Takeaways:

  • Structure vs. Data: CREATE, ALTER, and DROP manipulate the table's structural architecture, not individual row values.
  • Safe Schema Evolution: ALTER TABLE allows schemas to expand gracefully without losing existing student records.
  • Irreversible Deletion: DROP TABLE completely erases the table; exercise extreme caution before running it.
★ Remember This

DDL vs. DML: CREATE, ALTER, and DROP are DDL (Data Definition Language) commands that manage table structure. Commands like INSERT, UPDATE, and DELETE are DML (Data Manipulation Language) commands that manage records inside the table!
