SQL Security & Real-World Database Queries

Protect sensitive data, prevent SQL injection with parameterized queries, apply permissions, and build real-world shopping queries.

A SQL Security Fundamentals

Database security protects confidential records from unauthorized access, accidental tampering, and malicious cyberattacks.

Authentication vs. Authorization

Access control relies on two distinct security layers:

  • Authentication: Verifies identity (who you are, such as through a username and password).
  • Authorization: Determines permissions (what actions you are permitted to perform, such as reading or updating specific tables).
Managing Permissions: GRANT & REVOKE

The principle of least privilege states that users, applications, and services should only receive the minimum permissions necessary for their duties:

Standard Permission Commands SECURITY 
-- Grant read access
GRANT SELECT ON Customers
TO analyst_user;

-- Revoke write access
REVOKE INSERT, UPDATE ON Customers
FROM analyst_user;
SQL Injection & Parameterized Queries

SQL injection occurs when untrusted user input is directly concatenated into a query string, allowing attackers to manipulate SQL syntax. Parameterized queries treat user input strictly as literal values rather than executable code, completely neutralizing injection risks.

◆ Visual 1: Database Security Access Flow
1. User Login
Client submits username and password credentials.
2. Authentication
Database verifies identity (Who are you?).
3. Permission Check
Database checks table privileges via GRANT/REVOKE (What can you do?).
4. Access Decision
Authorized Access granted to requested rows, or Access Denied with security error.
◆ Visual 2: SQL Injection vs. Parameterized Query
⚠ Vulnerable Concatenation
SELECT * FROM Users WHERE id = '' + input
Malicious input (' OR '1'='1) alters query syntax and bypasses password checks.
✔ Safe Parameterized Query
SELECT * FROM Users WHERE id = ?
Database engine treats user input strictly as a literal value, preventing unintended query execution.

B Real-World Shopping Queries

Real-world online shopping systems combine multiple related tables to track customers, purchases, and payments.

1. Recent Orders for a Customer (JOIN & ORDER BY)
Customer Order History JOIN 
SELECT c.name, o.order_id,
       o.order_date, o.status
FROM Customers c
JOIN Orders o
  ON c.customer_id = o.customer_id
WHERE c.name = 'Rahul'
ORDER BY o.order_date DESC;

Expected output:

name order_id order_date status
Rahul 102 2026-10-15 Pending
Rahul 101 2026-10-01 Delivered
2. Total Spending Per Customer (SUM & GROUP BY)
Customer Spending Summary AGGREGATE 
SELECT c.name,
       SUM(i.amount) AS total_spent
FROM Customers c
JOIN Orders o
  ON c.customer_id = o.customer_id
JOIN OrderItems i
  ON o.order_id = i.order_id
GROUP BY c.customer_id, c.name;

Expected output:

name total_spent
Rahul 3500
Priya 2500
3. Finding Pending Orders (WHERE)
Pending Orders Query FILTER 
SELECT order_id,
       customer_id, order_date
FROM Orders
WHERE status = 'Pending';
4. Safe Parameterized Order Lookup

Application-level code safely binds parameter placeholders (such as ? or $1) rather than concatenating values directly into raw SQL strings:

Application Parameterized Query PREPARED 
-- Safe parameter placeholder (?)
SELECT order_id,
       customer_id, status
FROM Orders
WHERE order_id = ?;
