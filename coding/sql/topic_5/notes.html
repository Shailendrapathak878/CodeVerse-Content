CREATE, INSERT, UPDATE & DELETE

Master the fundamental CRUD commands in SQL to create table structures, insert student records, update values safely, and delete unneeded data.

A CREATE — Define a New Table

The CREATE TABLE statement defines the structural blueprint for a new database table. It specifies the table name, column names, allowed data types, and primary key constraints.

In our college database, the administration needs a dedicated table to record enrolled student details:

Create Students Table Schema DDL 
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    branch VARCHAR(30)
);

Essential Command Elements:

  • CREATE TABLE Students creates the named relational container on storage.
  • Column Definitions specify each attribute (student_id, name, age, branch) and constrain what types of data may be stored.
  • PRIMARY KEY uniquely identifies every student record and ensures no two students can share the same ID number.

Empty Students table ready. Structure established with 0 records.

Structure vs. Data: CREATE TABLE only builds the empty structural blueprint. It does not insert student records. Rows must be added using INSERT.

B INSERT — Adding Student Records

The INSERT INTO command adds new data rows into an existing table. Values must be provided in the matching column order and satisfy table constraints.

Step 1: Register Rahul's Record:

Insert Student 101 DML 
INSERT INTO Students
  (student_id, name, age, branch)
VALUES
  (101, 'Rahul', 19, 'CSE');
Table State: 1 Record Inserted + 1 Row
student_id name age branch
101 Rahul 19 CSE

Step 2: Register Priya's Record:

Insert Student 102 DML 
INSERT INTO Students
  (student_id, name, age, branch)
VALUES
  (102, 'Priya', 20, 'AI');
Table State: 2 Records Present Both Rows Stored
student_id name age branch
101 Rahul 19 CSE
102 Priya 20 AI

Each successful INSERT permanently stores an additional row on disk, provided the primary key is unique and values match column data types.

C UPDATE — Modifying Existing Records

The UPDATE command modifies existing values in a table. It uses SET to assign new values and WHERE to target specific rows.

College Example: Rahul submitted an approved branch transfer request. We update his branch from CSE to AI without altering his ID, name, or age:

Update Rahul's Branch DML 
UPDATE Students
SET branch = 'AI'
WHERE student_id = 101;
◆ Visual 3: Cell Value Modification (CSE → AI)
1. BEFORE UPDATE Original Branch: CSE
student_id name age branch
101 Rahul 19 CSE
102 Priya 20 AI
↓ SET branch = 'AI' WHERE student_id = 101 ↓
2. AFTER UPDATE Updated Branch: AI
student_id name age branch
101 Rahul 19 AI
102 Priya 20 AI
⚠ Caution: Always Include WHERE

If you run UPDATE Students SET branch = 'AI'; without a WHERE clause, the database will change the branch of every single student in the table to AI!

D DELETE — Removing Records

The DELETE command removes specific records from a table while leaving the table structure, column definitions, and primary keys intact.

College Example: Student 102 was a temporary test entry created during registration practice and must now be removed from the practice table:

Delete Student 102 DML 
DELETE FROM Students
WHERE student_id = 102;
◆ Visual 4: Row Removal While Schema Structure Remains
1. BEFORE DELETE: 2 Records Targeting student_id = 102
student_id name age branch
101 Rahul 19 AI
102 Priya 20 AI [TARGET]
↓ DELETE FROM Students WHERE student_id = 102 ↓
2. AFTER DELETE: 1 Record Remaining Table Structure Intact
student_id name age branch
101 Rahul 19 AI

DELETE Specific Row vs. All Rows:

  • DELETE FROM Students WHERE student_id = 102; — Deletes only the single row matching the condition.
  • DELETE FROM Students; — Deletes every record in the table, leaving an empty table structure on disk.
⚠ Critical Safety Reminder

Always double-check your WHERE condition before executing UPDATE or DELETE. In real applications, unintended data deletions cannot easily be undone!

E Command Comparison & Key Takeaways

Together, these four commands form the foundation of relational database operations:

DDL Structure

DML Remove

Removes matching rows while keeping the table structure.
Command Core Purpose College Real-Life Example
CREATE Creates a table Create the Students table
INSERT Adds records Register a new student
UPDATE Modifies records Correct a student's branch
DELETE Removes records Remove a duplicate practice record

3 Essential Takeaways:

  • DDL vs. DML: CREATE TABLE manages table architecture (DDL). INSERT, UPDATE, and DELETE manage rows inside the table (DML).
  • WHERE Protects Your Data: In both UPDATE and DELETE, the WHERE clause prevents changes from affecting the entire table.
  • Structure Persists: Running DELETE removes data records, but the table schema remains intact and ready to accept new rows.
★ Remember This

CRUD Mapping: CREATE = Schema Create, INSERT = Create Row, UPDATE = Modify Row, DELETE = Remove Row. Paired with SELECT (Read), you now know all core CRUD database operations!
