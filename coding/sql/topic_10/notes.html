SQL JOINs

Combine related records from multiple database tables using common key columns to construct unified relational queries.

A Real-Life Example: College Database

In relational databases, storing student names and department details in a single table leads to duplicate text and data entry errors. Instead, a college stores student profiles and branch definitions in separate tables.

A JOIN brings related records back together at query time using a shared column (branch_id):

B Three Essential JOIN Types

1. INNER JOIN — Overlapping Matches Only

Returns only rows where the join condition finds a matching value in both tables. Unmatched rows from either table are omitted.

INNER JOIN Query INNER 
SELECT s.name, b.branch_name
FROM Students s
INNER JOIN Branches b
    ON s.branch_id = b.branch_id;
◆ Visual 1: INNER JOIN (Only Overlapping Region Included)
name branch_name
Rahul CSE
Priya AI
Aman CSE

Relatable Explanation: Shows only students with an assigned branch that matches an existing department. Neha (no branch) and IT (no students) are excluded.

2. LEFT JOIN — All Left Rows + Matching Right Rows

Returns every row from the left table (Students). If a student has no matching branch, right-table attributes appear as NULL.

LEFT JOIN Query LEFT 
SELECT s.name, b.branch_name
FROM Students s
LEFT JOIN Branches b
    ON s.branch_id = b.branch_id;
◆ Visual 2: LEFT JOIN (Entire Left Circle Highlighted)
name branch_name
Rahul CSE
Priya AI
Aman CSE
Neha NULL

Relatable Explanation: Lists every student in college records, even if their branch has not been assigned yet (Neha displays with NULL).

3. RIGHT JOIN — All Right Rows + Matching Left Rows

Returns every row from the right table (Branches) and matching rows from Students. Departments with no students display NULL.

RIGHT JOIN Query RIGHT 
SELECT s.name, b.branch_name
FROM Students s
RIGHT JOIN Branches b
    ON s.branch_id = b.branch_id;
◆ Visual 3: RIGHT JOIN (Entire Right Circle Highlighted)
name branch_name
Rahul CSE
Aman CSE
Priya AI
NULL IT

Relatable Explanation: Lists every college branch, including IT even though no student is currently enrolled in it.

Database System Note: Standard SQL supports INNER, LEFT, and RIGHT JOINs. Some database engines (like SQLite) natively support LEFT JOIN but achieve RIGHT JOIN by simply reversing table positions.

C Quick Comparison & Takeaways

JOIN Type Core Purpose College Example
INNER JOIN Only rows matching in both tables Students with confirmed branches
LEFT JOIN All left rows + matching right rows All students (even unassigned)
RIGHT JOIN All right rows + matching left rows All branches (even empty ones)

3 Concise Takeaways:

  • Keys Form the Bridge: Always match the foreign key with the primary key inside the ON clause.
  • Table Aliases Simplify Queries: Short aliases like Students s and Branches b prevent ambiguous column errors.
  • Unmatched Rows Produce NULL: Outer joins preserve unmatched records by inserting NULL into missing counterpart columns.
★ Remember This

INNER = Overlap only, LEFT = Keep all Left, RIGHT = Keep all Right. Pick the JOIN that preserves the exact records your business report requires!
