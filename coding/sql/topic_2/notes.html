Database & Tables Structure

Understand how databases organize data into structured tables, how primary keys guarantee row uniqueness, and how to define tables with proper data types.

A What Is Database Structure?

A relational database is not a single flat list. Instead, it is an organized container that houses multiple distinct tables, each dedicated to a specific type of information.

Consider a College Management System. Instead of mixing student addresses, faculty salaries, and exam scores into one massive file, the database separates them into dedicated tables:

B Understanding Table Structure

A table arranges data into vertical columns and horizontal rows. Let us examine the structure of our Students table:

student_id [PK] name age branch
101 Rahul 19 CSE
102 Priya 20 AI
103 Aman 19 IT
Table

The complete two-dimensional container (Students) storing related records.

Row (Record / Tuple)

A single horizontal entry (e.g., Row 2: 102 | Priya | 20 | AI) representing one student.

Column (Field / Attribute)

A vertical category holding one specific property, such as branch or age.

Data Type

The rule that dictates what kind of data (number, text, date) each column is allowed to store.

Primary Key (PK): A primary key is a column (or combination of columns) that uniquely identifies every row in a table. In Students, student_id is the primary key. Two students may share the same name or age, but no two students can ever have the same student_id, and it cannot be empty (NULL).

C Essential SQL Data Types

Before storing data, every column must have an assigned data type that defines the format of allowable values.

Data Type Purpose Example Value
INT Stores whole numbers (integers without decimals). 101, 19
VARCHAR(50) Variable-length text up to 50 characters long. 'Rahul', 'CSE'
DATE Stores calendar dates in YYYY-MM-DD format. '2026-10-26'
DECIMAL(10,2) Exact numbers with 10 total digits and 2 decimals. 45000.50
★ Database Variation Note

Specific data types can vary slightly across database engines. For example, Oracle often uses VARCHAR2, while SQLite dynamically types values. However, INT, VARCHAR, and DATE are standard across nearly all modern SQL systems.

D Creating a Database & Table

To start storing data, we first create the database container, select it, and then define our table schema.

Step 1: Create Database SQL 
CREATE DATABASE CollegeDB;

In MySQL and MariaDB, you activate the newly created database with USE CollegeDB; before creating tables. In other systems like PostgreSQL, you select the database during connection.

Step 2: Define Students Table Schema SQL 
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    branch VARCHAR(30)
);
CREATE TABLE

The DDL command that creates a new empty table structure in the active database.

student_id INT

Declares an integer column to store the student's roll number.

PRIMARY KEY

Enforces that every student_id must be unique and cannot be empty (NULL).

VARCHAR(50)

Allocates variable-length text storage for student names up to 50 characters.

E Insert and View Real Data

Creating a table sets up the schema, but leaves it empty. We populate it using the INSERT statement:

Insert a Record SQL 
INSERT INTO Students
  (student_id, name, age, branch)
VALUES
  (101, 'Rahul', 19, 'CSE');

Now verify that the student record was stored by running a SELECT query:

Query Table Data SQL 
SELECT * FROM Students;
✔ Illustrative Query Output (1 Row Returned)
student_id name age branch
101 Rahul 19 CSE

INSERT adds the record to disk, and SELECT retrieves it. Additional INSERT statements populate rows for Priya (102) and Aman (103).

F Practical Tips & Quick Revision

4 Best Practices for Table Design:

  • Choose Appropriate Data Types: Use INT for counts and IDs, VARCHAR for variable text, and DECIMAL for currency to avoid rounding errors.
  • Always Define a Primary Key: Every table should have a primary key column to ensure reliable, unique row identification.
  • Use Clear, Plural Names: Name tables after the entity they store (e.g., Students, Courses) and columns cleanly (e.g., student_id, name).
  • Follow System Conventions: Check your database engine's specific keywords and syntax rules (e.g., MySQL vs. PostgreSQL).

Quick Revision: A database holds multiple tables. A table is structured into columns (defined with data types) and rows (records). A primary key uniquely distinguishes every row.

★ Remember This

Primary Key Rule: A primary key cannot contain duplicate values and can never be NULL. If you attempt to insert another student with student_id = 101, the database will reject the query to protect data integrity!
