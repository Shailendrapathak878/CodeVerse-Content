Indexes & Query Performance

Accelerate data retrieval, understand execution plans with EXPLAIN, and balance read speed against write overhead.

A Finding a Student with an Index

A database index is a specialized lookup structure that helps the database find matching rows more efficiently, especially in large tables.

Real-Life Analogy: Finding a student's name in an alphabetically ordered book index is far faster than reading through every page one by one. Actual performance gains depend on table size, data distribution, and available indexes.

Create an Index INDEX 
CREATE INDEX idx_students_name
ON Students(name);

Querying the indexed column:

Search Indexed Column SELECT 
SELECT student_id, name, branch
FROM Students
WHERE name = 'Rahul';
student_id name branch
101 Rahul CSE

The index helps with name-based lookups, but the query optimizer ultimately decides whether to use it based on table size and cost estimates.

◆ Visual 1: Search Comparison (Scan vs. Index)
Full Table Scan (Without Index)
Scans every row sequentially from start to end until all records are inspected.
Index Lookup (With Index)
Jumps directly to 'Rahul' via sorted index tree pointers without examining irrelevant rows.
* Conceptual illustration — actual execution depends on data distribution and optimizer decisions.
◆ Visual 2: Index Lookup Execution Flow
1. User Query
SELECT ... WHERE name = 'Rahul';
2. Index Lookup
idx_students_name locates key 'Rahul' → finds row pointer #101.
3. Matching Row Retrieved
Fetches matching student row (101, Rahul, CSE) from table storage.

B Query Performance & EXPLAIN

Query performance measures how efficiently the database retrieves or modifies records. While indexes can speed up queries by reducing scanned data, they consume extra storage and can slow down INSERT, UPDATE, and DELETE operations because index trees must be updated.

Inspect Execution Plan EXPLAIN 
EXPLAIN
SELECT student_id, name, branch
FROM Students
WHERE name = 'Rahul';

The EXPLAIN command reveals the database execution plan, indicating whether an index or full table scan is planned. Plan structures and field names vary by database engine.

◆ Visual 3: Performance Trade-offs (Reads vs. Writes)
✔ Read Advantages
Fast lookups on selective WHERE clauses, joins, and ORDER BY sorting.
⚠ Write & Storage Costs
Consumes additional disk/RAM space; slows down inserts and updates due to index maintenance.
★ Good Indexing Practices
  • Index columns frequently used for selective searches or joins.
  • Avoid creating unnecessary indexes on rarely queried columns.
  • Use EXPLAIN to inspect and verify query execution plans.
  • Measure performance on representative, production-like datasets.
