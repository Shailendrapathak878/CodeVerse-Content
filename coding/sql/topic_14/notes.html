Constraints & Data Integrity

Protect database accuracy and prevent invalid entries using PRIMARY KEY, NOT NULL, UNIQUE, CHECK, and FOREIGN KEY.

A College Student Registration & Constraints

Constraints are validation rules attached to table columns. They act as automated guardrails to maintain data accuracy, consistency, and reliability. For example, during student registration, every student needs a unique ID, their name cannot be missing, and their exam marks must fall within a valid range.

SQL enforces five essential integrity constraints:

  • PRIMARY KEY: Uniquely identifies each student record and cannot contain NULL values.
  • NOT NULL: Prevents missing required data, ensuring an entry is always provided.
  • UNIQUE: Ensures all values in a column or column group are distinct, blocking duplicate values.
  • CHECK: Validates that inserted or updated values satisfy a specific logical condition.
  • FOREIGN KEY: Guarantees that a referenced value exists in a parent table, preserving relational integrity.
◆ Visual 1: Student Table Constraint Map
Column Constraint Integrity Rule Enforced
student_id PRIMARY KEY Unique identifier for every student; cannot be NULL.
name NOT NULL Student name is mandatory; cannot be left blank.
email UNIQUE Prevents duplicate email registrations across accounts.
marks CHECK Enforces valid score range (marks BETWEEN 0 AND 100).
branch_id FOREIGN KEY Must match an existing branch_id in the Branches table.

B Table Definitions & Valid Record

First, create the parent Branches table and child Students table with enforced rules:

Table Creation with Integrity Constraints DDL 
CREATE TABLE Branches (
    branch_id INT PRIMARY KEY,
    branch_name VARCHAR(30) NOT NULL UNIQUE
);

CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    marks INT CHECK (marks BETWEEN 0 AND 100),
    branch_id INT,
    FOREIGN KEY (branch_id)
        REFERENCES Branches(branch_id)
);

Next, insert a valid branch and an eligible student record:

Valid Insert Operations INSERT 
INSERT INTO Branches (branch_id, branch_name)
VALUES (1, 'CSE');

INSERT INTO Students
    (student_id, name, email, marks, branch_id)
VALUES
    (101, 'Rahul', 'rahul@example.com', 85, 1);

Expected Valid Student Record:

student_id name email marks branch_id
101 Rahul rahul@example.com 85 1

C Enforcing Data Validation

When an INSERT statement violates a constraint, the database rejects the query and keeps existing data safe:

Invalid Example 1: Out-of-Bounds Marks
Violates CHECK Constraint REJECTED 
-- Invalid: marks cannot exceed 100
INSERT INTO Students
VALUES (102, 'Priya',
        'priya@example.com', 120, 1);

Expected Validation Result: Rejected: CHECK constraint — Marks (120) exceed the allowed upper boundary of 100.

Invalid Example 2: Non-Existent Branch Reference
Violates FOREIGN KEY Constraint REJECTED 
-- Invalid: branch_id 99 does not exist
INSERT INTO Students
VALUES (103, 'Aman',
        'aman@example.com', 75, 99);

Expected Validation Result: Rejected: FOREIGN KEY constraint — branch_id 99 is not found in parent table Branches.

◆ Visual 2: Data Validation Flowchart
Record 1: Rahul (Marks 85, Branch 1) ✔ SAVED TO DATABASE
All rules satisfied → Marks (0–100) valid • Branch 1 exists in Branches table.
Record 2: Priya (Marks 120, Branch 1) ✘ INSERT REJECTED
Failed CHECK constraint → Score 120 is strictly outside allowed range [0–100].
Record 3: Aman (Marks 75, Branch 99) ✘ INSERT REJECTED
Failed FOREIGN KEY constraint → Referenced parent branch 99 does not exist.
⚙ Database Engine Notice

Exact error numbers and diagnostic messages vary across database engines (PostgreSQL, MySQL, SQLite, Oracle, SQL Server), but all compliant engines halt the transaction to prevent corrupt data.
