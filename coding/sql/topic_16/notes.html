Views & Stored Procedures

Simplify data access and encapsulate business logic using virtual views and server-side stored procedures.

A Views — A Saved Query

A view is a named query stored in the database that acts like a virtual table. Rather than duplicating physical table data, a view dynamically executes its underlying query definition whenever queried.

We use our college Students table throughout this lesson:

student_id name branch marks
101 Rahul CSE 80
102 Priya AI 90
103 Aman CSE 70

Real-Life Scenario: A teacher frequently needs to view student names and exam marks without exposing unrelated internal columns or rewriting the query repeatedly:

Create View VIEW DDL 
CREATE VIEW StudentResults AS
SELECT name, marks
FROM Students;

Query the view exactly like a normal table:

Query View SELECT 
SELECT * FROM StudentResults;
name marks
Rahul 80
Priya 90
Aman 70

The view makes recurring queries clean and reusable. In practice, permissions and direct updateability depend on the specific database engine and whether the view includes aggregations or joins.

◆ Visual 1: View Execution Workflow
1. Define View (CREATE VIEW)
CREATE VIEW StudentResults AS SELECT name, marks FROM Students;
2. Stored Query Definition
Database saves query logic as a virtual schema object (no duplicated table rows).
3. Query View & Deliver Output
SELECT * FROM StudentResults; dynamically pulls Rahul (80), Priya (90), Aman (70).

B Stored Procedures — Reusable Logic

A stored procedure is a prepared set of SQL statements stored directly on the database server. It can accept parameters, execute complex logic, and be invoked on demand.

Real-Life Scenario: A college administrator repeatedly needs to fetch all student records for a specific branch by passing the branch name dynamically.

MySQL Stored Procedure Example PROCEDURE 
DELIMITER //

CREATE PROCEDURE GetStudentsByBranch(
    IN selected_branch VARCHAR(30)
)
BEGIN
    SELECT student_id, name, branch, marks
    FROM Students
    WHERE branch = selected_branch;
END //

DELIMITER ;

Invoke the procedure using CALL:

Call Stored Procedure CALL 
CALL GetStudentsByBranch('CSE');
student_id name branch marks
101 Rahul CSE 80
103 Aman CSE 70

The parameter IN selected_branch receives 'CSE', and the procedure returns matching students. Creation and execution syntax vary across MySQL (CALL), PostgreSQL (CALL or functions), and SQL Server (EXEC); this syntax is MySQL-specific.

◆ Visual 2: Stored Procedure Workflow
1. Supply Input Parameter
Administrator passes argument value 'CSE' into procedure.
2. Invoke Routine (CALL)
CALL GetStudentsByBranch('CSE'); triggers precompiled routine on the server.
3. Filter & Return Records
Applies WHERE branch = 'CSE' and returns Rahul (101) & Aman (103).

C Views vs. Stored Procedures

Both objects encapsulate SQL logic on the server, but serve different architectural purposes:

View Stored Procedure
Reusable named query Reusable database routine
Queried using SELECT Invoked using CALL in MySQL
Commonly used to simplify data access Can encapsulate multiple SQL operations
★ Quick Revision & Takeaways

1. Views for Presentation: Use views to expose curated, read-only slices of tables without duplicating data.
2. Procedures for Workflows: Use stored procedures to automate multi-step tasks with parameters.
3. Portability Note: Stored procedure syntax is engine-dependent and requires adjustments across database vendors.
