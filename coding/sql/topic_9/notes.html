HAVING & Conditional Expressions

Filter aggregated groups using HAVING and implement dynamic conditional evaluation with CASE expressions in SQL queries.

A HAVING — Filter Groups

In SQL, the WHERE clause filters individual rows before grouping takes place. In contrast, the HAVING clause filters entire groups after GROUP BY has aggregated them.

Throughout this lesson, we use our college Students table:

student_id name branch marks
101 Rahul CSE 80
102 Priya AI 90
103 Aman CSE 70
104 Neha AI 85
105 Arjun IT 75

College Example: First calculate each branch's average exam marks, then display only departments whose average score is at least 80:

Filter Branch Averages >= 80 HAVING 
SELECT branch, AVG(marks) AS average_marks
FROM Students
GROUP BY branch
HAVING AVG(marks) >= 80
ORDER BY branch;
branch average_marks
AI 87.5
◆ Visual 1: WHERE vs. HAVING Execution Order
1. Raw Records Individual student rows on disk (5 students).
2. WHERE (Row Filter) Filters single rows before grouping occurs.
3. GROUP BY Forms branch buckets (AI, CSE, IT).
4. HAVING (Group Filter) Filters calculated group summaries (Avg ≥ 80).
◆ Visual 2: Why Only AI Passes HAVING AVG(marks) >= 80
Branch Group Branch Avg HAVING Test (≥ 80) Status
AI (Priya: 90, Neha: 85) 87.5 87.5 ≥ 80 → True ✔ Retained
CSE (Rahul: 80, Aman: 70) 75.0 75.0 ≥ 80 → False ✘ Excluded
IT (Arjun: 75) 75.0 75.0 ≥ 80 → False ✘ Excluded

Only the AI branch has an average of 87.5, satisfying the HAVING condition. Both CSE (average 75) and IT (average 75) fall below 80 and are excluded.

B Conditional Expressions — CASE

The CASE expression brings conditional if-then-else logic into SQL queries. It inspects values row-by-row and returns custom categories or computed labels based on specific criteria.

College Example: Categorize each student's exam performance:

Assign Performance Category CASE 
SELECT name, marks,
       CASE
           WHEN marks >= 85 THEN 'Excellent'
           WHEN marks >= 75 THEN 'Good'
           ELSE 'Needs Improvement'
       END AS performance
FROM Students
ORDER BY student_id;
name marks performance
Rahul 80 Good
Priya 90 Excellent
Aman 70 Needs Improvement
Neha 85 Excellent
Arjun 75 Good
◆ Visual 3: CASE Top-to-Bottom Decision Hierarchy
1. WHEN marks ≥ 85
Excellent
Priya (90), Neha (85)
2. WHEN marks ≥ 75
Good
Rahul (80), Arjun (75)
3. ELSE (Default)
Needs Improvement
Aman (70)

How CASE Operates:

  • Top-to-Bottom Evaluation: SQL evaluates conditions sequentially and returns the value for the first condition that matches.
  • The ELSE Fallback: If no WHEN condition evaluates to true, the ELSE value is returned (such as Aman with 70 marks).
  • END Clause: Every conditional block concludes with the END keyword.
★ Quick Revision & Takeaways

WHERE vs. HAVING: WHERE filters rows before aggregation; HAVING filters group summaries after aggregation.
CASE Evaluates In Order: The first matching condition wins; unmatched values fall back to ELSE.
