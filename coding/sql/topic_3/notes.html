A Basic SQL Syntax

An SQL statement is built from distinct clauses that instruct the database engine which columns to show, which table to search, and which rows to match.

Target Query: Filter Students by Age SQL 
SELECT name, branch
FROM Students
WHERE age = 19;

Clause Breakdown:

  • SELECT name, branch specifies the exact output columns to display.
  • FROM Students indicates the source table holding the records.
  • WHERE age = 19 defines the filtering condition: only rows with age 19 are kept.

B Essential SQL Syntax Rules

SQL syntax is flexible, but following established industry conventions makes your code readable, professional, and easy to debug.

  • Uppercase Keywords: SQL keywords (SELECT, FROM, WHERE) are written in UPPERCASE by convention. While SQL is case-insensitive, uppercase makes keywords stand out immediately.
  • Semicolon Terminator: Statements end with a semicolon (;) in most database systems. It tells the engine that the instruction is complete.
  • Single Quotes for Text: Text strings and dates are enclosed in single quotes (e.g., 'Rahul', '2026-10-26').
  • Numbers Without Quotes: Numeric values (e.g., 19, 85.50) are written as bare numbers without quotes.
  • Whitespace & Indentation: SQL ignores extra spaces and line breaks. Breaking clauses across multiple lines dramatically improves readability.
✔ Standard & Readable
SELECT name
FROM Students
WHERE age = 19;

Each clause occupies its own line. Keywords are capitalized for instant clarity.

⚠ Valid But Poorly Formatted
select name from Students where age=19;

Crammed into one line with lowercase keywords. Valid SQL, but harder to read and audit.

C What Are Data Types?

A data type defines the kind of values that a column is permitted to store, preventing invalid data from entering the database.

Data Type Used For Example Value
INT Whole numbers (integers without decimals). 101, 19
VARCHAR(50) Variable-length text up to 50 characters long. 'Rahul', 'CSE'
DATE Calendar dates in YYYY-MM-DD format. '2007-05-12'
DECIMAL(8,2) Exact numbers with 8 total digits and 2 decimal places. 85.50
BOOLEAN Logical true/false values, where supported. TRUE, FALSE
★ Engine Variation Note

Data type support varies by database system. For example, MySQL treats BOOLEAN as a synonym for TINYINT(1), while PostgreSQL has a native boolean type. Oracle uses VARCHAR2 instead of VARCHAR.

D Defining Columns with Appropriate Types

When creating a table, each column must be paired with an appropriate type that mirrors its real-world format:

Create Students Table Schema SQL 
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    branch VARCHAR(30),
    admission_date DATE,
    percentage DECIMAL(5,2)
);
student_id → INT PRIMARY KEY Unique numeric roll number (e.g., 101). PRIMARY KEY is a constraint.
name → VARCHAR(50) Text string storing up to 50 characters (e.g., 'Rahul').
age → INT Whole number for age in years (e.g., 19).
branch → VARCHAR(30) Academic department code (e.g., 'CSE').
admission_date → DATE Calendar enrollment date (e.g., '2026-08-01').
percentage → DECIMAL(5,2) Score with up to 3 digits before decimal, 2 after (e.g., 85.50).

E Practical Query: Text vs. Numeric Literals

In SQL queries, quotes communicate data types to the parser. Always quote text and dates, but never quote bare numbers:

Text String
'Rahul'
Enclosed in single quotes
Number
19
No quotes required
Calendar Date
'2026-10-26'
Enclosed in single quotes
Filtering Text vs Numeric Columns SQL 
-- 1. Filter by text: quotes are mandatory
SELECT * FROM Students WHERE name = 'Rahul';

-- 2. Filter by number: no quotes
SELECT * FROM Students WHERE age = 19;

If you write WHERE name = Rahul; without quotes, SQL treats Rahul as another column name and returns an error.

F Common Mistakes & Quick Revision

3 Common Beginner Mistakes:

✖ Common Mistake

1. Missing Comma in Schema:

name VARCHAR(50)
age INT

Causes syntax error: each column definition requires a separating comma.

✔ Correct Syntax

Proper Separation:

name VARCHAR(50),
age INT

Include commas between column lines (omit comma after the last column).

  • Unquoted Text Literals: Writing WHERE branch = CSE triggers an unknown column error. Always write WHERE branch = 'CSE'.
  • Unsuitable Data Types: Storing numbers as text (e.g., age VARCHAR(10)) prevents numeric sorting (where '100' sorts before '2') and disables math functions.

Quick Revision: SQL queries follow the SELECT ... FROM ... WHERE ... structure. Keywords are capitalized by convention, and statements end with semicolons. Text and dates use single quotes, while numbers do not. Data types ensure data integrity.

★ Remember This

Syntax vs. Formatting: SQL syntax is case-insensitive, but writing keywords in UPPERCASE and indenting clauses makes queries readable for teams and maintainers!
