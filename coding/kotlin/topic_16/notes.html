Inheritance & Polymorphism in Kotlin

Build scalable, reusable software architectures. Understand how Inheritance reuses code through Parent and Child classes, why Kotlin requires the open keyword, how to customize behavior with override and super, and how Runtime Polymorphism powers flexible "one name, many forms" execution.

1 Introduction to Inheritance

In programming, writing the same properties and functions repeatedly for similar entities leads to messy, duplicate code. Inheritance is an Object-Oriented Programming (OOP) mechanism where a new class inherits properties and functions from an existing class.

The primary benefit is Code Reusability: you write common features once in a shared base class, and specialized classes inherit and reuse those features automatically without rewriting them.

🚗
Real-Life Analogy: Think of a general Vehicle. Both a Car and a Bike are vehicles. They share common features like speed and a start() action. Instead of defining speed and start from scratch for every vehicle, Car and Bike inherit them from Vehicle, and add their own unique parts (e.g., Car adds airConditioner, Bike adds kickStand).
Diagram 1.1: Vehicle Inheritance Hierarchy
🏛️ Parent Class (Superclass / Base)

The general class whose properties and functions are inherited by another class. Example: Vehicle, Animal, Person.

👶 Child Class (Subclass / Derived)

The specialized class that inherits from the parent and can add its own new features or modify existing ones. Example: Car, Dog, Student.

2 The open Keyword: Why Kotlin Classes are Final by Default

In many languages like Java, all classes can be inherited by default. However, Kotlin takes a safer, modern approach: By default, all classes in Kotlin are final!

A final class cannot be inherited. To allow a class to be used as a parent class, you must explicitly mark it with the open keyword.

Diagram 2.1: Final by Default vs Open Inheritance
Kotlin ParentClassDeclaration.kt
KOTLIN Script
KOTLIN 
// The 'open' keyword permits other classes to inherit from Animal
open class Animal {
    fun eat() {
        println("Animal is eating food")
    }
}
⚠️
What happens without open? If you write class Animal and then try to create class Dog : Animal(), the Kotlin compiler halts with an error: "This type has a constructor, and thus must be initialized here / This type is final, so it cannot be inherited from". Kotlin enforces this design rule to protect against unintended subclassing (the "fragile base class" problem).

3 Creating a Child Class with the : Colon Syntax

In Kotlin, inheritance is specified using the colon (:) symbol followed by the parent class name and its constructor call parentheses ().

Kotlin BasicChildClass.kt
KOTLIN Script
KOTLIN 
open class Animal {
    fun eat() {
        println("Animal is eating")
    }
}

// Dog inherits from Animal using ': Animal()'
class Dog : Animal()

fun main() {
    val myDog = Dog()
    myDog.eat() // Inherited from Animal!
}
Terminal Output Animal is eating
💡
Single Class Inheritance Rule: A Kotlin class can directly inherit from only one parent class (Kotlin does not allow multiple class inheritance like C++). However, a parent can have multiple children, and classes can form chains (e.g., Puppy inherits Dog, which inherits Animal).

4 Inherited Features vs Child-Specific Features

A child class inherits all accessible properties and member functions from its parent class, while also being free to add its own brand new properties and functions.

Diagram 4.1: Inherited Features + Child-Specific Features
Kotlin FeaturesDemo.kt
KOTLIN Script
KOTLIN 
open class Animal {
    val species = "Canine"

    fun eat() {
        println("This animal eats food.")
    }
}

class Dog : Animal() {
    val breed = "Labrador" // Child-specific property

    fun bark() {            // Child-specific function
        println("Dog barks: Woof! Woof!")
    }
}

fun main() {
    val dog = Dog()
    println("Species: ${dog.species}") // From Parent
    dog.eat()                          // From Parent
    println("Breed: ${dog.breed}")     // From Child
    dog.bark()                         // From Child
}
Terminal Output Species: Canine
This animal eats food.
Breed: Labrador
Dog barks: Woof! Woof!

5 Function Overriding & open fun

Sometimes the general behavior provided by a parent class is not specific enough for a child. Function Overriding allows a child class to provide its own custom implementation of a function already declared in its parent class.

🔑
Two Requirements for Overriding in Kotlin:
1. The parent function must be declared with the open keyword (functions are final by default).
2. The child function must be declared with the override keyword.
Diagram 5.1: Function Overriding in Child Classes
Kotlin OverridingDemo.kt
KOTLIN Script
KOTLIN 
open class Animal {
    // 'open' allows this function to be overridden
    open fun sound() {
        println("Animal makes a general sound")
    }
}

class Dog : Animal() {
    // 'override' replaces parent's implementation
    override fun sound() {
        println("Dog barks: Woof! Woof!")
    }
}

class Cat : Animal() {
    override fun sound() {
        println("Cat meows: Meow! Meow!")
    }
}

fun main() {
    val dog = Dog()
    val cat = Cat()

    dog.sound() // Calls Dog's overridden sound
    cat.sound() // Calls Cat's overridden sound
}
Terminal Output Dog barks: Woof! Woof!
Cat meows: Meow! Meow!
⚖️
Overriding vs Overloading: Overriding means a child class changes the implementation of an inherited function with the exact same name and parameters. Overloading means writing multiple functions within the same class that share the same name but have different parameter lists (e.g. print(x: Int) vs print(x: String)).

6 Overriding Properties

Just like member functions, class properties can also be overridden by child classes if they are marked open in the parent class.

Kotlin PropertyOverriding.kt
KOTLIN Script
KOTLIN 
open class Animal {
    open val category: String = "Wild or Domestic Animal"
}

class Dog : Animal() {
    // Overriding the property value
    override val category: String = "Loyal Pet Companion"
}

fun main() {
    val animal = Animal()
    val dog = Dog()

    println(animal.category)
    println(dog.category)
}
Terminal Output Wild or Domestic Animal
Loyal Pet Companion
💡
Property Mutability Rule: You can override an open val property with a var in a child class (widening mutability), but you cannot override an open var with a val (restricting mutability is disallowed).

7 The super Keyword: Calling Parent Behavior

When a child class overrides a function, it often wants to extend the parent class behavior rather than discarding it completely. The super keyword refers to the direct parent class instance.

Diagram 7.1: super.sound() Execution Flow
Kotlin SuperKeywordDemo.kt
KOTLIN Script
KOTLIN 
open class Animal {
    open fun sound() {
        println("Animal produces generic sound.")
    }
}

class Dog : Animal() {
    override fun sound() {
        super.sound() // Step 1: Run parent's code
        println("Dog barks enthusiastically: Woof!") // Step 2: Add child code
    }
}

fun main() {
    val dog = Dog()
    dog.sound()
}
Terminal Output Animal produces generic sound.
Dog barks enthusiastically: Woof!

8 Constructors in Inheritance

When a parent class has a parameterized primary constructor, the child class must initialize the parent by passing the required arguments during inheritance header declaration.

Diagram 8.1: Passing Parameters to Parent Constructor
Kotlin ConstructorInheritance.kt
KOTLIN Script
KOTLIN 
// Parent class with primary constructor properties
open class Person(val name: String, val age: Int)

// Child class receives name & age, passes them to Person(name, age),
// and introduces its own property: val rollNumber
class Student(
    name: String,
    age: Int,
    val rollNumber: Int,
    val branch: String
) : Person(name, age)

fun main() {
    val s = Student("Aman", 20, 101, "Computer Science")

    println("Name: ${s.name}")         // Inherited from Person
    println("Age: ${s.age}")           // Inherited from Person
    println("Roll No: ${s.rollNumber}") // Student's own property
    println("Branch: ${s.branch}")     // Student's own property
}
Terminal Output Name: Aman
Age: 20
Roll No: 101
Branch: Computer Science
⚠️
Important Syntax Rule: Notice that in Student(name: String, age: Int, ...), we do NOT write val or var before name and age! Because name and age are already declared as properties in Person, declaring them again with val would cause a redeclaration error. Only child-specific properties (like val rollNumber) need val/var.

9 What is Polymorphism?

The word Polymorphism is derived from Greek: Poly (many) + Morph (forms) → "One Name, Many Forms".

In programming, Polymorphism is the ability of a single interface, function call, or parent type reference to perform different operations depending on the actual underlying object being manipulated.

Diagram 9.1: Polymorphism: Single Action, Different Behaviors

When you press the start button on a machine, you issue the single command start(). How it starts internally differs whether you are in a car or on a motorcycle. That is polymorphism in action!

10 Runtime Polymorphism & Parent References

In Kotlin, Runtime Polymorphism (also called Dynamic Method Dispatch) is achieved when:

  1. A variable is declared with a Parent Class reference type (e.g., val a: Animal).
  2. The variable actually points to a Child Class instance in heap memory (e.g., Dog() or Cat()).
  3. When an overridden function is invoked, Kotlin inspects the actual runtime object and executes the child's implementation!
Diagram 10.1: Reference Type vs Actual Heap Object
Kotlin RuntimePolymorphismDemo.kt
KOTLIN Script
KOTLIN 
open class Animal {
    open fun sound() {
        println("Generic animal sound")
    }
}

class Dog : Animal() {
    override fun sound() {
        println("Dog barks: Woof! Woof!")
    }
}

class Cat : Animal() {
    override fun sound() {
        println("Cat meows: Meow! Meow!")
    }
}

fun main() {
    // Both variables have the static type Animal
    val a1: Animal = Dog()
    val a2: Animal = Cat()

    // At runtime, Kotlin invokes the function of the ACTUAL object
    a1.sound() // Output: Dog barks
    a2.sound() // Output: Cat meows
}
Terminal Output Dog barks: Woof! Woof!
Cat meows: Meow! Meow!

11 Polymorphism with Collections

The greatest superpower of Polymorphism is storing different child objects inside a single uniform collection of the parent type. You can iterate through the list and call the common method without knowing or checking each object's exact child class.

Diagram 11.1: Iterating a Polymorphic List<Shape>
Kotlin PolymorphicShapes.kt
KOTLIN Script
KOTLIN 
open class Shape {
    open fun draw() {
        println("Drawing a generic shape")
    }
}

class Circle : Shape() {
    override fun draw() {
        println("Drawing a Circle ⭕")
    }
}

class Rectangle : Shape() {
    override fun draw() {
        println("Drawing a Rectangle ▭")
    }
}

class Triangle : Shape() {
    override fun draw() {
        println("Drawing a Triangle 🔺")
    }
}

fun main() {
    // A list of Shape holding diverse child objects
    val shapeList: List = listOf(
        Circle(),
        Rectangle(),
        Triangle()
    )

    for (s in shapeList) {
        s.draw() // Polymorphic invocation!
    }
}
Terminal Output Drawing a Circle ⭕
Drawing a Rectangle ▭
Drawing a Triangle 🔺

12 Inheritance vs Polymorphism

While Inheritance and Polymorphism work closely together in Object-Oriented design, they solve two different architectural challenges:

Characteristic Inheritance Polymorphism
Core Purpose Code reusability (is-a relationship) Flexibility ("one name, many forms")
How it Works Child class inherits properties & methods from Parent Parent reference invokes overridden child methods at runtime
Kotlin Syntax class Child : Parent() val ref: Parent = Child() with override
Primary Advantage Eliminates code duplication Allows writing code that handles future new subclasses effortlessly
Dependency Can exist without polymorphism Runtime polymorphism relies on inheritance & overriding

13 Important Kotlin Keywords Quick Reference

Keyword Usage Target Effect & Meaning in Kotlin
open class, fun, val Removes default final restriction, permitting inheritance or overriding.
override fun, val, var Explicitly marks a member as redefining an inherited open member.
super Method calls, constructors References the immediate parent class implementation.
: Class header declaration Specifies inheritance or constructor delegation in Kotlin.
final fun in child class Default for all classes; stops further overriding in subsequent subclasses.

Program D: Shape Drawing & Area Calculation (Runtime Polymorphism)

Loops through a polymorphic list to calculate area and draw geometric shapes dynamically.

Kotlin ProgramD_ShapePolymorphism.kt
KOTLIN Script
KOTLIN 
open class Shape(val name: String) {
    open fun area(): Double = 0.0

    fun printSummary() {
        println("$name has an area of ${area()} sq units")
    }
}

class Circle(val radius: Double) : Shape("Circle") {
    override fun area(): Double = 3.14159 * radius * radius
}

class Rectangle(val width: Double, val height: Double) : Shape("Rectangle") {
    override fun area(): Double = width * height
}

fun main() {
    val shapes: List = listOf(
        Circle(5.0),
        Rectangle(4.0, 6.0)
    )

    for (s in shapes) {
        s.printSummary() // Calls s.area() polymorphically!
    }
}
Terminal Output Circle has an area of 78.53975 sq units
Rectangle has an area of 24.0 sq units

15 Common Beginner Mistakes & How to Fix Them

❌ 1. Inheriting a class without 'open'

class Animal
class Dog : Animal() // Error: Animal is final

Fix: Mark parent class with open: open class Animal.

❌ 2. Overriding a function without 'open'

fun sound() { ... }
override fun sound() // Error: cannot override final

Fix: Add open to parent function: open fun sound().

❌ 3. Forgetting the 'override' keyword

fun sound() { ... } in Dog
// Error: 'sound' hides member of supertype

Fix: Kotlin mandates override keyword: override fun sound().

❌ 4. Duplicate val in Child Constructor

class Student(val name: String) : Person(name)
// Error: 'name' hides supertype member

Fix: Remove val: class Student(name: String) : Person(name).

❌ 5. Forgetting constructor parentheses

class Dog : Animal // Error: Animal() must be initialized

Fix: Always call parent constructor: class Dog : Animal().

❌ 6. Multiple class inheritance

class Amphibian : Car(), Boat() // Error: Only one superclass

Fix: Kotlin allows only single class inheritance. Use Interfaces for multi-role design.

❌ 7. Accessing child-only methods via Parent ref

val a: Animal = Dog()
a.bark() // Error: Unresolved reference 'bark'

Fix: Parent reference can only access members declared in Animal.

❌ 8. Overriding open val with var vs val

open var count = 1
override val count = 2 // Error: cannot override var with val

Fix: A mutable var property cannot be restricted to read-only val.

❌ 9. Confusing super with this

override fun sound() { this.sound() } // Infinite recursion loop!

Fix: Use super.sound() to invoke the parent class method.

❌ 10. Thinking Parent method runs automatically

override fun draw() { ... } // Parent code replaced completely

Fix: If you want the parent's logic to execute, call super.draw() explicitly.

❌ 11. Confusing Overriding with Overloading

Changing parameter types in a child class is function overloading, not overriding.

Fix: Overriding requires the exact identical function signature.

❌ 12. Unused Constructor parameters

Declaring class Student(val name: String) without passing to Person(name) leads to uninitialized parent state.

Fix: Always pass common parameters to parent constructor invocation.

16 Quick Revision & Takeaways

  • Inheritance: Reusing code where a child class inherits properties and functions from a parent class using : Parent().
  • Final by Default: In Kotlin, all classes and functions are final by default for safety.
  • The open Keyword: Required before class or fun to enable inheritance or overriding.
  • Function Overriding: Redefining a parent function using the mandatory override keyword.
  • The super Keyword: Used inside a child class to call the parent's original function or constructor.
  • Single Class Inheritance: A Kotlin class can have only one direct superclass.
  • Polymorphism: "One Name, Many Forms". A parent reference variable (e.g. val v: Vehicle = Car()) dynamically executes the child's overridden code at runtime.
  • Polymorphic Collections: Storing diverse child objects in a List<Parent> allows clean, modular, extensible loops.

✖ B) Because Dog must be declared before Animal
✖ C) Because Kotlin requires the extends keyword instead of colon :

Explanation: In Kotlin, all classes are final by default to prevent unintended subclassing. You must write open class Animal.
2. Which keyword is mandatory in Kotlin when a child class implements an inherited open function?
✔ A) override
✖ B) virtual
✖ C) super
✖ D) implements
Explanation: Kotlin strictly enforces the override keyword to avoid accidental name collisions and typos.
3. What is the role of the super keyword inside an overridden child function?
✔ A) It allows invoking the parent class's original implementation of that function
✖ B) It terminates the child class function execution immediately
✖ C) It re-initializes all local stack variables
✖ D) It converts a child instance into a parent instance in memory
Explanation: super.functionName() calls the parent class's version of the function, allowing the child to extend rather than replace it.
4. Consider val v: Vehicle = Car(). When calling v.start(), which implementation executes?
✔ A) Car's overridden start() method, determined at runtime via dynamic dispatch
✖ B) Vehicle's start() method, because the variable type is Vehicle
✖ C) Both methods execute simultaneously in parallel coroutines
✖ D) A compilation error occurs because types do not match exactly
Explanation: This is Runtime Polymorphism. Kotlin checks the actual heap object instance (which is Car) at runtime and executes Car's overridden method.
5. Can a Kotlin class inherit directly from more than one parent class (e.g. class C : A(), B())?
✔ A) No, Kotlin enforces single class inheritance (only one superclass)
✖ B) Yes, as long as both parent classes are marked open
✖ C) Yes, but only if neither class has any properties
✖ D) Yes, provided the secondary constructor is marked open
Explanation: Kotlin supports single class inheritance only to avoid multiple-inheritance ambiguity (the diamond problem). Multiple interfaces can be implemented, but only one class can be inherited.
