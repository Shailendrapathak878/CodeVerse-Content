Arrays & Collections in Kotlin

Master multi-value data storage. Learn fixed-size Arrays, ordered Lists, unique Sets, and key-value Maps, with read-only vs. mutable collections.

1 Introduction to Arrays: Storing Multiple Values

An Array is a container object that holds a fixed number of values of a single type. Instead of declaring separate variables like mark1, mark2, and mark3, you store them inside a single array variable.

Real-Life Analogy: Think of a row of school lockers. Every locker has a number starting at 0 and holds one student's bag. In Kotlin, each item is called an element, and its numbered location is called an index.

Visual 1: Array Structure — Index vs Value Mapping (marks)
Kotlin FirstArray.kt
KOTLIN Script
KOTLIN 
fun main() {
    // Create an array of student marks
    val marks = arrayOf(85, 90, 78, 95, 88)

    println(marks[0])  // First element at index 0
    println(marks[2])  // Third element at index 2
}
Execution Output: 85
78

3 Accessing & Updating Array Elements

Arrays allow direct read and write access using square brackets [index]. You can change any existing element, but you cannot change the total count of elements.

    println(fruits[1])      // Orange

4 Looping Through Arrays

You can iterate through an array by item value directly, by index using indices, or with both using withIndex():

6 Introduction to Collections: List, Set, and Map

While Arrays are fixed in size, Kotlin Collections are dynamic, expressive data structures. Kotlin divides collections into Read-Only interfaces (viewing data without mutation methods) and Mutable interfaces (methods to add, remove, and update elements).

Visual 5: Kotlin Collections Architecture — The 3 Core Pillars
&info;
Important Clarification: A Kotlin List provides a read-only interface (it does not have .add() or .remove()). MutableList inherits from List and adds modification methods.

7 Lists in Kotlin (listOf)

A List is an ordered collection that stores elements by zero-based index and preserves the exact insertion order. Duplicate items are completely legal.

8 MutableList: Dynamic Growth & Modifications

Created using mutableListOf(), a MutableList acts like a real-world shopping cart: you can add items, remove items, or clear everything at runtime.

Visual 7: MutableList Operations — add(), update, and remove()
Kotlin MutableListDemo.kt
KOTLIN Script
KOTLIN 
fun main() {
    val cart = mutableListOf("Apple", "Mango")

    cart.add("Banana")      // Appends to end
    cart[0] = "Orange"       // Updates index 0
    cart.remove("Mango")     // Removes element

    println(cart)            // [Orange, Banana]
    println(cart.size)       // 2
}
Execution Output: [Orange, Banana]
2

9 Sets in Kotlin: Ensuring Uniqueness

A Set is a collection that stores unique elements only. If you attempt to add an item that already exists in the set, the duplicate is ignored automatically.

Real-Life Analogy: Student Roll Numbers in an exam hall or user email accounts. Every roll number or email must exist only once.

Visual 8: Set Automatically Discards Duplicate Elements
Kotlin SetDemo.kt
KOTLIN Script
KOTLIN 
fun main() {
    val numbers = setOf(10, 20, 30, 20, 10)
    println(numbers)                 // [10, 20, 30]
    println(numbers.size)            // 3
    println(numbers.contains(20))    // true

    // MutableSet
    val rollNumbers = mutableSetOf(101, 102)
    rollNumbers.add(103)
    rollNumbers.add(101)             // Duplicate 101 rejected
    println(rollNumbers)             // [101, 102, 103]
}
Execution Output: [10, 20, 30]
3
true
[101, 102, 103]

10 Maps in Kotlin: Key-Value Associations

A Map stores data as key-value pairs. Keys are unique identifiers used to fetch values quickly, just like looking up a person's name in your phone contact book to find their phone number.

11 MutableMap: Adding, Updating, & Removing Keys

Use mutableMapOf() when you need to insert new key-value pairs or update existing ones. If a key already exists, re-assigning it overwrites the old value:

Visual 10: MutableMap Re-assignment Overwrites Key's Value
Kotlin MutableMapDemo.kt
KOTLIN Script
KOTLIN 
fun main() {
    val user = mutableMapOf("name" to "Aman", "city" to "Lucknow")

    user["age"] = "18"        // Add new pair
    user["city"] = "Kanpur"   // Update existing key
    println(user)

12 Iterating Through Collections (Destructuring Maps)

Iterating through a List or Set provides each element directly. When iterating through a Map, Kotlin supports elegant destructuring of each entry into (key, value):

KOTLIN Script
KOTLIN

    val student = mapOf("name" to "Aman", "city" to "Lucknow")

    for ((key, value) in student) {
        println("$key: $value")

city: Lucknow

15 Common Beginner Mistakes & How to Fix Them

✗ Mistake 1: Trying to grow an Array size

val arr = arrayOf(1, 2); arr.add(3) // Error!

Fix: Array size is fixed. Use mutableListOf(1, 2) instead.

✗ Mistake 2: Mutating a read-only List

val list = listOf("A", "B"); list.add("C")

Fix: listOf() is read-only. Use mutableListOf("A", "B").

✗ Mistake 3: Off-by-one Index Crash

val last = items[items.size] // Crashes!

Fix: Indices end at size - 1. Use items.last() or items.getOrNull(index).

✗ Mistake 4: remove() vs removeAt() on Ints

list.remove(1) // Removes index 1, not number 1!

Fix: For MutableList<Int>, removeAt(i) removes by index; remove(Integer.valueOf(1)) removes by value.

✗ Mistake 5: Expecting Set to store duplicates

val s = setOf(1, 1, 2) // size is 2, not 3!

Fix: Sets discard duplicates. If duplicate count matters, use a List.

✗ Mistake 6: Accessing Map like an Array

map[0] // Returns null if "0" is not a key!

Fix: Maps are indexed by keys, not numerical slot positions: map["name"].

16 Quick Revision & Takeaways

  • Arrays have fixed size: Created with arrayOf(); cannot add or remove elements after creation.
  • Collections are versatile: Grouped into read-only interfaces (List, Set, Map) and mutable versions (MutableList, MutableSet, MutableMap).
  • Lists preserve order: Zero-based indexed access; duplicate elements are allowed.
  • Sets enforce uniqueness: Discards duplicates automatically; ideal for IDs, roll numbers, or unique badges.
  • Maps store key-value pairs: Fast lookup by key; keys must be unique.
  • Safe Access: Always consider getOrNull() to gracefully handle unknown indices without crashing.
  • Looping: Iterate collections cleanly with for (item in col) or destructure maps with for ((k, v) in map).
