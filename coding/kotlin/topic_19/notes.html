Generics & Variance in Kotlin

Write flexible, type-safe code that eliminates duplication. Master Generic Classes and Generic Functions with <T>, enforce safety with Type Constraints, and conquer subtyping rules with Invariance, Covariance (out), and Contravariance (in).

1 Introduction: Why Do We Need Generics?

In beginner code, if you want a box to hold a String, you write StringBox. If you then want to hold an Int, you write IntBox. If you want a Double, you write DoubleBox.

This causes massive, frustrating code duplication! Generics allow you to write a single, reusable class or function that works safely with any data type using a Type Parameter (usually written as <T> for "Type").

📦
Real-Life Analogy: The Universal Storage Box.
Imagine a factory making cardboard boxes. The factory doesn't design a "shoe-only box" that cannot hold books. It manufactures a universal box. You can put shoes in it, books in it, or laptops in it. In Kotlin, Box<T> is that universal box design, where T is whatever item you place inside!

3 Generics in Action (Examples 1 – 14)

Examples 1 – 4: Generic Box Storing Different Types

The same single class storing String, Int, and Double safely with zero casting.

Kotlin GenericBoxDemo.kt
KOTLIN Script
KOTLIN 
class Box(val item: T) {
    fun open(): T = item
}

fun main() {
    val strBox = Box("Kotlin Book")
    val intBox = Box(101)
    val dblBox = Box(99.5) // Type inference automatically knows Box!

    println("String box: ${strBox.open()}")
    println("Int box: ${intBox.open()}")
    println("Double box: ${dblBox.open()}")
}
Terminal Output String box: Kotlin Book
Int box: 101
Double box: 99.5

Examples 5 – 8: Generic Functions

Functions can declare their own type parameter before the function name: fun <T> name(...).

Kotlin GenericFunctionsDemo.kt
KOTLIN Script
KOTLIN 
// Example 5: Generic function printing any type
fun  printItem(item: T) {
    println("Item: $item (Type: ${item!!::class.simpleName})")
}

// Example 6: Returning the passed value
fun  echo(value: T): T = value

// Example 7: Swapping two elements in a list
fun  swapFirstTwo(list: MutableList) {
    if (list.size >= 2) {
        val temp = list[0]
        list[0] = list[1]
        list[1] = temp
    }
}

// Example 8: Finding first item matching a predicate
fun  findFirst(items: List, match: (T) -> Boolean): T? {
    for (i in items) if (match(i)) return i
    return null
}

fun main() {
    printItem("Android")
    printItem(42)

    val nums = mutableListOf(1, 2, 3)
    swapFirstTwo(nums)
    println("Swapped nums: $nums")

    val found = findFirst(listOf(10, 25, 30)) { it > 20 }
    println("First > 20: $found")
}
Terminal Output Item: Android (Type: String)
Item: 42 (Type: Int)
Swapped nums: [2, 1, 3]
First > 20: 25

Examples 11 & 12: Generic Type Constraints (Upper Bounds)

Sometimes you only want a generic function to accept numbers or comparable items. Use <T : Number> to set an upper bound constraint.

Kotlin TypeConstraintsDemo.kt
KOTLIN Script
KOTLIN 
// Example 11: Only subclasses of Number (Int, Double, Float) are permitted!
fun  sumToDouble(a: T, b: T): Double {
    return a.toDouble() + b.toDouble()
}

// Example 12: Constraint using Comparable for ordering
fun > findMax(a: T, b: T): T {
    return if (a > b) a else b
}

fun main() {
    println("Sum: ${sumToDouble(10, 20.5)}") // Allowed: Int & Double are Numbers
    println("Max: ${findMax("Apple", "Zebra")}")
    // sumToDouble("A", "B") -> Compile Error: String is not a Number!
}
Terminal Output Sum: 30.5
Max: Zebra

4 Introduction to Variance: Subtyping Safety

In Kotlin, a Dog is a subtype of Animal. This means you can assign a Dog to an Animal variable: val a: Animal = Dog().

The Big Question: Can you assign a Box<Dog> to a variable of type Box<Animal>? In Kotlin, the default answer is NO!

Diagram 4.1: The Invariance Rule by Default

Why does it fail by default? Because if Box<Animal> allowed you to insert a Cat into it, you would accidentally put a Cat into a Box that someone else expects to only hold Dogs! That would crash your app at runtime.

⚖️
The Golden Rule of Variance: Producer vs. Consumer
• Covariance (out): If your class only PRODUCES (returns) values of type T and never takes them in, it is safe to assign Producer<Dog> to Producer<Animal>.
• Contravariance (in): If your class only CONSUMES (takes as parameter) values of type T and never outputs them, it is safe to assign Consumer<Animal> to Consumer<Dog>.

5 Variance in Action (Examples 15 – 23)

Example 15: Default Invariance

Neither in nor out is specified. The class both consumes and produces T.

Kotlin Example15_Invariance.kt
KOTLIN Script
KOTLIN 
open class Animal
class Dog : Animal()

class InvariantBox(var item: T)

fun main() {
    val dogBox: InvariantBox = InvariantBox(Dog())
    // val animalBox: InvariantBox = dogBox // Compile Error: Type mismatch!
    println("InvariantBox works safely without automatic subtype conversion.")
}
Terminal Output InvariantBox works safely without automatic subtype conversion.

Examples 16 & 17: Covariance with out (Producer)

By marking <out T>, T can only appear in out-position (return types). This makes Producer<Dog> a valid subtype of Producer<Animal>.

Kotlin Example16_17_Covariance.kt
KOTLIN Script
KOTLIN 
open class Animal(val name: String)
class Dog(name: String) : Animal(name)

// 'out T' means this class only PRODUCES T
class Shelter(private val animal: T) {
    fun adopt(): T = animal // Allowed: 'out' position!
}

fun main() {
    val dogShelter: Shelter = Shelter(Dog("Buddy"))
    // Fully legal because of 'out'!
    val animalShelter: Shelter = dogShelter
    println("Adopted: ${animalShelter.adopt().name}")
}
Terminal Output Adopted: Buddy

Examples 18 & 19: Contravariance with in (Consumer)

By marking <in T>, T can only appear in in-position (function arguments). This inverts the subtyping relationship: a consumer of Animal can be used where a consumer of Dog is needed!

Kotlin Example18_19_Contravariance.kt
KOTLIN Script
KOTLIN 
// 'in T' means this class only CONSUMES T
interface Trainer {
    fun train(target: T) // Allowed: 'in' parameter position!
}

class GeneralAnimalTrainer : Trainer {
    override fun train(target: Animal) {
        println("Training animal: ${target.name}")
    }
}

fun main() {
    val animalTrainer: Trainer = GeneralAnimalTrainer()
    // Contravariance: Trainer can safely act as Trainer!
    val dogTrainer: Trainer = animalTrainer
    dogTrainer.train(Dog("Bruno"))
}
Terminal Output Training animal: Bruno

Examples 20 & 21: Use-Site Variance (Type Projections)

When a class like Array<T> is invariant, you can still apply variance at the specific function calling site where it is used.

Kotlin Example20_21_UseSiteVariance.kt
KOTLIN Script
KOTLIN 
// Use-site 'out': from is restricted to only producing elements (read-only)
fun  copyElements(from: Array, to: Array) {
    for (i in from.indices) {
        to[i] = from[i]
    }
}

fun main() {
    val ints: Array = arrayOf(1, 2, 3)
    val anyList: Array = arrayOf(0, 0, 0)

    copyElements(ints, anyList)
    println("Copied elements: ${anyList.joinToString()}")
}
Terminal Output Copied elements: 1, 2, 3

Example 22: Star Projection <*>

When you don't know or care about the exact type, use * to safely read elements as Any?.

Kotlin Example22_StarProjection.kt
KOTLIN Script
KOTLIN 
fun printListLength(list: List) {
    println("List size is ${list.size}, first item is: ${list.firstOrNull()}")
}

fun main() {
    printListLength(listOf("A", "B", "C"))
    printListLength(listOf(100, 200))
}
Terminal Output List size is 3, first item is: A
List size is 2, first item is: 100

Kotlin Example23_Pipeline.kt

interface DataProvider {

class TextProvider : DataProvider {

6 Variance Matrix & Key Concepts Summary

Concept Keyword Role Subtyping Rule Position Restriction
Invariance (None) Producer & Consumer Box<Dog> has no relation to Box<Animal> Can appear in both in and out positions
Covariance out Producer Only Producer<Dog> is a subtype of Producer<Animal> Only allowed in out (return) position
Contravariance in Consumer Only Consumer<Animal> is a subtype of Consumer<Dog> Only allowed in in (argument) position
Star Projection * Unknown Type Can point to any generic specialization Read-only as Any?, cannot write into it

7 Common Beginner Mistakes & How to Fix Them

❌ 1. Expecting Box<Dog> to be Box<Animal>

val b: Box<Animal> = Box<Dog>() // Error: Type mismatch

Fix: Classes are invariant by default. Mark as class Box<out T> if read-only.

❌ 2. Using 'out' on a function parameter

class Box<out T> { fun set(item: T) } // Error: Type parameter T is declared as 'out' but occurs in 'in' position

Fix: out classes can only produce/return values, not accept them as parameters.

❌ 3. Forgetting type parameter in function

fun printVal(item: T) // Error: Unresolved reference 'T'

Fix: Declare the type parameter first: fun <T> printVal(item: T).

❌ 4. Writing into a Star-projected collection

val list: MutableList<*> = ...; list.add("Hi") // Error: Prohibited

Fix: Star projections are strictly read-only since the exact type is unknown.

❌ 5. Misunderstanding constraint bounds

fun <T : Number> doMath(a: T) // Calling with "String" fails compilation

Fix: Pass arguments that are actually subtypes of the specified constraint.

❌ 6. Confusing 'in' and 'out' directions

Remember: PECS → Producer Out, Consumer In.

Tip: If it returns T → out. If it takes T as an argument → in.

8 Quick Revision: 12 Key Takeaways

  • 1. Generics: Writing reusable, type-safe components without code duplication.
  • 2. Type Parameter: The placeholder <T> representing an actual type supplied during instantiation.
  • 3. Generic Class: Declared with class Box<T>(val item: T).
  • 4. Generic Function: Declared with fun <T> printItem(item: T).
  • 5. Multiple Parameters: Classes can accept multiple parameters like Pair<K, V>.
  • 6. Type Constraints: Using <T : Number> restricts allowed types to numbers only.
  • 7. Invariance: By default, Box<Dog> is NOT a subtype of Box<Animal> to prevent unsafe writes.
  • 8. Covariance (out): Safe for producers. Allows Shelter<Dog> to be treated as Shelter<Animal>.
  • 9. Contravariance (in): Safe for consumers. Allows Trainer<Animal> to be treated as Trainer<Dog>.
  • 10. Use-Site Variance: Applying out or in at the function parameter level (type projection).
  • 11. Star Projection (*): Represents an unknown type safely readable as Any?.
  • 12. Stage 5 Kickoff: Generics and Variance lay the groundwork for high-performance collections and architectural pipelines!
