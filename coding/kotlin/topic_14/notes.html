Data Classes & Destructuring in Kotlin

Eliminate boilerplate code. Learn how Kotlin's data class automatically generates toString(), equals(), hashCode(), and copy(), and unpack multi-value objects effortlessly using Destructuring Declarations.

1 Classes & Objects: Quick Revision

In Kotlin, a Class is a blueprint or template, while an Object is a concrete instance created from that blueprint. A class groups related properties (data variables) together.

Real-Life Analogy: A student admission form is a Class. When a student named Aman fills out his specific name and age on the form, that completed form is an Object.

Visual 1: Blueprint (Class) to Concrete Instance (Object)

KOTLIN Script
KOTLIN 
class Student(val name: String, val age: Int)

fun main() {
    val s = Student("Aman", 18)
    println(s.name)  // Aman
    println(s.age)   // 18
}
Execution Output: Aman
18

2 What is a Data Class?

In software development, we frequently create classes whose sole purpose is to hold data. In older languages like Java, developers had to write dozens of lines of repetitive boilerplate code (getters, setters, toString(), equals(), hashCode()).

In Kotlin, prefixing a class with the data keyword automatically generates all standard data-handling methods behind the scenes!

Visual 2: Anatomy of a Kotlin Data Class
Kotlin StudentDataClass.kt
KOTLIN Script
KOTLIN 
data class Student(
    val name: String,
    val age: Int,
    val branch: String
)

fun main() {
    val student = Student("Aman", 18, "CSE")
    println("Name   : ${student.name}")
    println("Age    : ${student.age}")
    println("Branch : ${student.branch}")
}
Execution Output: Name : Aman
Age : 18
Branch : CSE

3 Rules for Creating a Data Class

The Kotlin compiler enforces specific requirements to guarantee safety and consistency for data classes:

  • Rule 1: The primary constructor must have at least one parameter.
  • Rule 2: All primary constructor parameters must be explicitly marked with val or var.
  • Rule 3: Data classes cannot be abstract, open, sealed, or inner.
  • Rule 4: Primary constructor parameters can specify default values (e.g. price: Double = 100.0).
✓ Valid Data Class

data class Product(val id: Int, val name: String, val price: Double = 100.0)

Has constructor parameters marked with val and optional default values.

✗ Invalid Data Class

data class User(name: String) // Compile Error!

Compiler error: Data class primary constructor must have only property (val / var) parameters.

6 toString(), equals(), & hashCode()

In a data class, == checks whether the properties of two objects match. Even if they are two distinct instances in heap memory, they are considered equal if their data is identical.

Visual 5: Value Equality (==) vs Referential Identity (===)
Kotlin DataClassEquality.kt
KOTLIN Script
KOTLIN 
data class Student(val name: String, val age: Int)

fun main() {
    val s1 = Student("Aman", 18)
    val s2 = Student("Aman", 18)
    val s3 = Student("Rahul", 20)

    // 1. Automatic toString()
    println(s1)                 // Student(name=Aman, age=18)

    // 2. Value equality (==)
    println(s1 == s2)           // true (Data matches!)
    println(s1 == s3)           // false

    // 3. Hash code contract
    println(s1.hashCode() == s2.hashCode())  // true (Equal objects have identical hash codes)
}
Execution Output: Student(name=Aman, age=18)
true
false
true

7 The copy() Function: Safe Modifications

Modern functional programming favors immutable data. When you need to update one property of an object, you shouldn't mutate it in-place. Instead, use the generated copy() function to duplicate the object while altering only the properties you specify!

Visual 6: The copy() Function Creates a New Object with Updates
Kotlin CopyDemo.kt
KOTLIN Script
KOTLIN 
data class Student(val name: String, val age: Int, val branch: String)

fun main() {
    val student1 = Student("Aman", 18, "CSE")
    
    // Create student2 with updated age, keeping name and branch identical
    val student2 = student1.copy(age = 19)

    println("Original : $student1")
    println("Updated  : $student2")
}
Execution Output: Original : Student(name=Aman, age=18, branch=CSE)
Updated : Student(name=Aman, age=19, branch=CSE)

8 Destructuring Declarations: Unpacking Data

Destructuring allows you to unpack an object into multiple individual variables in a single, elegant declaration.

Instead of writing val name = student.name, val age = student.age, and val branch = student.branch on separate lines, you write:
val (name, age, branch) = student

Visual 7: Destructuring Unpacks an Object into Separate Variables
Kotlin DestructuringDemo.kt
KOTLIN Script
KOTLIN 
data class Student(val name: String, val age: Int, val branch: String)

fun main() {
    val student = Student("Aman", 18, "CSE")

    // Destructuring declaration:
    val (name, age, branch) = student

    println("Extracted Name   : $name")
    println("Extracted Age    : $age")
    println("Extracted Branch : $branch")
}
Execution Output: Extracted Name : Aman
Extracted Age : 18
Extracted Branch : CSE

9 Under the Hood: componentN() Functions & _

How does destructuring actually work? The Kotlin compiler converts val (a, b) = student into calls to generated operator functions: student.component1() and student.component2().

Visual 8: componentN() Order Mapping & Ignoring Fields with _
Kotlin ComponentAndIgnore.kt
KOTLIN Script
KOTLIN 
data class Student(val name: String, val age: Int, val branch: String)

fun main() {
    val s = Student("Aman", 18, "CSE")

    // Direct component function access:
    println(s.component1())  // Aman
    println(s.component2())  // 18

    // Ignoring the age component using an underscore (_):
    val (name, _, branch) = s
    println("Student $name is enrolled in $branch.")
}
Execution Output: Aman
18
Student Aman is enrolled in CSE.
&warning;
Order Matters, Not Variable Names! Destructuring assigns variables purely by position: the first variable gets component1(), the second gets component2(). If you write val (age, name) = s, the variable age will contain the String "Aman"!

10 Destructuring with Pair, Triple, & Map Entries

Kotlin's built-in Pair (stores 2 items) and Triple (stores 3 items) already have built-in component functions. They can be destructured instantly without defining a new data class.

Visual 9: Destructuring Built-In Types — Pair, Triple, and Map Entries
Kotlin PairAndMapDestructure.kt
KOTLIN Script
KOTLIN 
fun main() {
    // 1. Destructuring a Pair
    val (city, pinCode) = Pair("Lucknow", 226028)
    println("City: $city, PIN: $pinCode")

    // 2. Destructuring Map Entries
    val scores = mapOf("Math" to 95, "Physics" to 88)
    for ((subject, mark) in scores) {
        println("$subject Score: $mark")
    }
}
Execution Output: City: Lucknow, PIN: 226028
Math Score: 95
Physics Score: 88

12 Common Beginner Mistakes & How to Fix Them

✗ Mistake 1: Forgetting val/var in constructor

data class User(name: String) // Compile Error!

Fix: All primary constructor parameters must have val or var: (val name: String).

✗ Mistake 2: Destructuring by variable name

val (age, name) = Student("Aman", 18)

Fix: Destructuring is positional! age gets component1() ("Aman"). Follow constructor order strictly.

✗ Mistake 3: Body properties in generated functions

data class S(val id: Int) { var name = "" }

Fix: name is excluded from equals() and toString(). Place all comparison properties in primary constructor.

✗ Mistake 4: Assuming copy() mutates in-place

student.copy(age = 20); println(student.age) // Still 18!

Fix: copy() returns a new object. Assign it: val updated = student.copy(age = 20).

✗ Mistake 5: Zero-parameter data class

data class Empty() // Compile Error!

Fix: Data classes must have at least one primary constructor parameter.

✗ Mistake 6: Confusing == with ===

s1 === s2 // false even if properties match!

Fix: === checks if references point to identical memory addresses. Use == for data equality.

13 Quick Revision & Takeaways

  • Data classes hold data: Declared with data class Name(...); primary constructor must have at least one property marked val or var.
  • Auto-generated methods: Generates toString(), equals(), hashCode(), copy(), and componentN().
  • Value equality (==): Evaluates whether the underlying properties of two objects match.
  • Immutable cloning with copy(): Duplicates an object while allowing specific named properties to change without altering the original.
  • Destructuring declarations: Syntax val (a, b) = object maps variables positionally to component1(), component2().
  • Skip fields with _: Ignore unwanted destructured components safely: val (name, _, branch) = student.
  • Built-in tuples: Pair and Triple support destructuring out of the box.

Explanation: Data classes automatically generate `equals()` based on primary constructor properties. Since both `x` and `y` match, `p1 == p2` is `true`.

A. Modifies student.age in-place directly
✓ B. Creates and returns a new Student object with age 20, leaving the original student object untouched
C. Deletes all other properties except age
D. Throws an UnsupportedOperationException
Explanation: The `copy()` method is non-destructive. It instantiates a new data class object with the modified properties, preserving immutability.
4. In the declaration val (first, second) = user, what determines the values assigned to first and second?
A. Matching variable names against property names
✓ B. Positional component functions: component1() and component2() corresponding to constructor order
C. Alphabetical order of properties
D. Random selection by the compiler
Explanation: Destructuring is purely positional. `first` receives `user.component1()` (first constructor parameter) and `second` receives `user.component2()`.
5. How do you ignore the second component when destructuring an object with 3 properties?
