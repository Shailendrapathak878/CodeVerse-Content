1 Introduction to Conditional Statements

Normally, a computer executes code sequentially from top to bottom, one line after another. But real-world programs cannot execute identical actions every time. They must make decisions based on user input, system states, or data calculations.

☂ Real-Life Analogy: The Umbrella Decision

Before leaving home, you check the weather:

  • If it is raining: Take an umbrella with you.
  • Otherwise (not raining): Go outside without an umbrella.

A conditional statement checks whether an expression evaluates to true or false, and branches execution accordingly.

Visual 1: Real-Life Decision-Making Flowchart
DecisionMaking.kt
KOTLIN Script
KOTLIN 
fun main() {
    val isRaining = true

    if (isRaining) {
        println("Take an umbrella with you!")
    } else {
        println("Leave the umbrella at home.")
    }
}
Output:
Take an umbrella with you!

2 The if Statement

The if statement executes a block of code only when its condition evaluates to true. If false, Kotlin bypasses the block and proceeds to subsequent code.

✔ Crucial Kotlin Rule: Conditions Must Be Boolean
In Kotlin, conditions inside if (...) must produce a Boolean (true or false). Non-zero integers or non-empty strings are not booleans.
Visual 2: Basic if Statement Flowchart
IfEligibility.kt
KOTLIN Script
KOTLIN 
fun main() {
    val marks = 78

    if (marks >= 40) {
        println("Eligibility Status: PASSED")
    }
    println("Audit Completed.")
}
Output:
Eligibility Status: PASSED
Audit Completed.

3 The if-else Statement

When you have two mutually exclusive alternatives, an if-else statement ensures exactly one branch executes. If the condition is true, the if block runs; otherwise, the else block runs.

Visual 3: if-else Two-Way Decision Flowchart
IfElseVoting.kt
KOTLIN Script
KOTLIN 
fun main() {
    val age = 16

    if (age >= 18) {
        println("Status: Adult (Eligible to vote)")
    } else {
        println("Status: Minor (Not eligible to vote)")
    }
}
Output:
Status: Minor (Not eligible to vote)

4 The if-else-if Ladder

When you need to test multiple conditions in a sequence, use an if-else-if ladder. Kotlin evaluates conditions top to bottom and immediately halts evaluation as soon as the first matching condition executes.

⚠ Condition Order Matters!
Arrange conditions from most restrictive to least restrictive (e.g., checking >= 90 before >= 80). If you placed >= 60 at the top, a score of 95 would match the 60 check first and incorrectly receive Grade D.
Visual 4: Sequential if-else-if Evaluation Ladder
StudentGrading.kt
KOTLIN Script
KOTLIN 
fun main() {
    val marks = 84

    if (marks >= 90) {
        println("Result: Grade A")
    } else if (marks >= 80) {
        println("Result: Grade B")
    } else if (marks >= 70) {
        println("Result: Grade C")
    } else if (marks >= 60) {
        println("Result: Grade D")
    } else {
        println("Result: Needs Improvement")
    }
}
Output:
Result: Grade B

5 Nested if Statements

A nested if is an if statement placed inside another if statement. It is used when an inner check should only occur after the outer prerequisite condition has succeeded.

🎓 Exam Hall Entrance Check
Security checks: 1. Does the student have an Admit Card? 2. Only if yes, is their Photo ID valid?
Visual 5: Nested If Decision Flow
ExamHallEntry.kt
KOTLIN Script
KOTLIN 
fun main() {
    val hasAdmitCard = true
    val hasValidId = true

    if (hasAdmitCard) {
        if (hasValidId) {
            println("Security Check Passed: Welcome to the Exam Hall!")
        } else {
            println("Entry Denied: Valid Photo ID is missing.")
        }
    } else {
        println("Entry Denied: Admit card is required.")
    }
}
Output:
Security Check Passed: Welcome to the Exam Hall!

6 The when Expression in Kotlin

Kotlin replaces Java/C's error-prone switch with the cleaner, safer when construct.

💡 No Switch Fall-Through!
In Kotlin, only the matching branch executes. You do not write break after each branch.
Visual 6: Kotlin when Branch Selection Flow

A. when with a Subject

KOTLIN Script
KOTLIN 
fun main() {
    val day = 3
    when (day) {
        1 -> println("Monday")
        2 -> println("Tuesday")
        3 -> println("Wednesday")
        else -> println("Other day")
    }
}
Output:
Wednesday

B. when with Multiple Values

KOTLIN Script
KOTLIN 
val day = 6
when (day) {
    1, 2, 3, 4, 5 -> println("Weekday")
    6, 7 -> println("Weekend")
    else -> println("Invalid day")
}

C. when with Ranges

Visual 7: when Range Matching Partitions
KOTLIN Script
KOTLIN 
val score = 74
when (score) {
    in 90..100 -> println("Excellent")
    in 60..89  -> println("Good")
    in 40..59  -> println("Pass")
    else        -> println("Fail")
}

D. when without a Subject

KOTLIN Script
KOTLIN 
val temp = 32
when {
    temp >= 35 -> println("Scorching hot")
    temp >= 25 -> println("Pleasant & warm")
    else       -> println("Cool/Cold")
}

E. when as an Expression

KOTLIN Script
KOTLIN 
val marks = 92
val result = when (marks) {
    in 90..100 -> "A"
    in 75..89  -> "B"
    in 40..74  -> "C"
    else        -> "Fail"
}
println("Awarded Grade: $result")
Output:
Awarded Grade: A

8 Conditional Statements as Expressions

In Kotlin, if and when are expressions that return a value. This eliminates the need for a separate ternary operator (? :).

Visual 9: Conditional Expression Value Flow
KOTLIN Script
KOTLIN 
fun main() {
    val age = 20
    val category = if (age >= 18) "Adult" else "Minor"
    
    val ticketPrice = if (age >= 18) {
        println("Applying standard rate")
        150 // Last statement in block returned
    } else {
        80
    }
    println("Category: $category, Price: ₹$ticketPrice")
}
Output:
Applying standard rate
Category: Adult, Price: ₹150

    val n1 = 20.0; val n2 = 4.0; val op = '/'

    val calc = when (op) {
        '+' -> "$n1 + $n2 = ${n1 + n2}"
        '-' -> "$n1 - $n2 = ${n1 - n2}"

10 Common Beginner Mistakes & Fixes

❌ 1. = Instead of ==

if (x = 5) tries to assign instead of compare.

Fix: Use if (x == 5).

❌ 2. Missing Braces

Without { }, only 1 statement is inside the if block.

Fix: Enclose multi-statement blocks with { }.

❌ 3. Wrong Condition Order

Checking >= 60 before >= 90 matches prematurely.

Fix: Order from strictest to broadest.

❌ 4. Inverted Ranges

10..1 is an empty range and never matches.

Fix: Write 1..10 (min..max).

❌ 5. Missing else in Expression

Expression-based when must be exhaustive.

Fix: Always supply an else branch.

❌ 6. Non-Boolean in if

if (count) fails to compile in Kotlin.

Fix: Use if (count > 0).

❌ 7. Over-Nesting

Deep nested ifs create unreadable arrow code.

Fix: Combine with logical && or when.

❌ 8. Division by Zero

Dividing by zero throws an unhandled exception.

Fix: Guard denominators with if (denom != 0).

❌ 9. Expecting Switch Fall-Through

Kotlin does not need break and never falls through.

Fix: Use comma-separated values: 1, 2 ->.

❌ 10. Confusing Nested with Ladder

Using nested ifs for flat alternative options.

Fix: Use flat if-else-if or when.

11 Quick Revision

  • if Statement: Runs a block strictly when its condition evaluates to true.
  • if-else: Chooses between two mutually exclusive paths.
  • if-else-if Ladder: Evaluates sequentially; executes first true branch and skips the rest.
  • Nested if: Secondary check dependent on outer check passing.
  • when Expression: Pattern matches against subjects, comma-separated lists, or ranges (in ..); no break needed.
  • Expressions: Both if and when return values, replacing the ternary operator.

12 Practice & Assessment

MCQ 1
1. In Kotlin, what type of value MUST an `if (condition)` expression evaluate to?
Answer: Boolean (true/false) • Numbers or strings are not auto-coerced into booleans in Kotlin.
MCQ 2
2. What happens in an `if-else-if` ladder when the first condition evaluates to true?
Answer: First block executes; all remaining `else if` and `else` blocks are skipped immediately.
MCQ 3
3. Does Kotlin's `when` require a `break` statement to prevent fall-through?
Answer: No • Kotlin executes only the matching branch and never falls through.
MCQ 4
4. When is the `else` branch mandatory in a `when` construct?
Answer: When used as an expression assigning a value and cases are not proven exhaustive by the compiler.
MCQ 5
5. Which syntax tests if `score` is between 50 and 100 in a `when (score)` branch?
Answer: in 50..100 -> println("Pass").
