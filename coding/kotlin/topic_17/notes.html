Interfaces & Abstract Classes in Kotlin

Design robust, loosely coupled software contracts. Learn how Interfaces define common standards that multiple classes can implement, and how Abstract Classes combine shared state with partial blueprints to power scalable object architectures.

1 Introduction: Why Contracts Matter in OOP

In beginner programming, we create concrete classes with fully written functions. But as software grows, multiple different classes need to perform similar tasks (like charging a battery, making a payment, or printing a document) in completely different ways.

If we had no standard way to group these actions, our code would become messy and rigid. In Kotlin, we solve this with two powerful tools:

  • Interfaces: A pure contract defining what actions must be done, without caring how each class does them. A class can implement multiple interfaces!
  • Abstract Classes: A partial blueprint defining shared base state and common code while forcing child classes to fill in specific missing pieces.
Diagram 1.1: The Two Architectural Tools in Kotlin

2 Understanding Interfaces

An Interface in Kotlin is a custom type that defines a group of abstract functions and properties. Think of it as a formal contract or promise: "Any class that implements me promises to provide implementations for these functions!"

🔌
Real-Life Analogy: The USB-C Port Standard.
A smartphone, a tablet, and a laptop all have a USB-C port. The USB-C specification is an interface: it defines the shape, pinout, and protocol. Each device internally handles the electricity differently, but any standard USB-C cable plugs in and works universally!
Diagram 2.1: Interface as a Universal Standard (USB-C)
📝 Declaring an Interface

Use the interface keyword. Functions without a body are automatically abstract by default (no open or abstract keyword needed).

🔗 Implementing an Interface

Use the colon : symbol followed by the interface name (no constructor parentheses () because interfaces have no constructors!).

A basic contract with an abstract function implemented by a class.

Example 5: Interface with Default Function Body

Unlike older languages, Kotlin interfaces can provide default implementations for functions. Implementing classes can use the default or override it!

Kotlin Example5_DefaultMethodInterface.kt
KOTLIN Script
KOTLIN 
interface Logger {
    // Abstract function (must be implemented)
    fun log(msg: String)

    // Default implementation (optional to override)
    fun logError(err: String) {
        println("[ERROR ALERT]: $err")
    }
}

class ConsoleLogger : Logger {
    override fun log(msg: String) {
        println("[LOG INFO]: $msg")
    }
    // Uses default logError() automatically!
}

fun main() {
    val logger = ConsoleLogger()
    logger.log("App started successfully.")
    logger.logError("Network connection lost!")
}
Terminal Output [LOG INFO]: App started successfully.
[ERROR ALERT]: Network connection lost!

4 Understanding Abstract Classes

An Abstract Class is a class marked with the abstract keyword. It represents an incomplete concept or conceptual blueprint.

🚗
Real-Life Analogy: The Concept of a Vehicle.
You cannot buy "just a vehicle" from a dealership. You can buy a Car, a Motorcycle, or a Truck. "Vehicle" is an abstract idea: it has a brand and engine, but how it specifically drives or steers is left to real concrete vehicles. That is an Abstract Class!
Diagram 5.1: Abstract Class Vehicle Hierarchy
🚫
Direct Instantiation is Prohibited: You cannot create an object directly from an abstract class (e.g. val v = Vehicle() triggers a compilation error: "Cannot create an instance of an abstract class"). You can only instantiate non-abstract child classes that extend it.

5 Practical Abstract Class Examples (Examples 7 – 11)

Example 7: Abstract Function in an Abstract Class

An abstract function has no body. Any child class inheriting this class is strictly required to implement it.

Kotlin Example7_AbstractFunction.kt
KOTLIN Script

    abstract fun makeSound()
}

class Dog : Animal() {
    override fun makeSound() {
        println("Dog barks: Woof! Woof!")
    }
}

fun main() {
    val dog = Dog()
    dog.makeSound()
}
Terminal Output Dog barks: Woof! Woof!

Example 9: Regular (Concrete) Functions in Abstract Classes

An abstract class can contain both abstract functions AND normal concrete functions with full bodies that subclasses inherit directly.

Kotlin Example9_ConcreteFunctionInAbstract.kt
KOTLIN Script
KOTLIN 
abstract class CoffeeMachine {
    // Abstract function
    abstract fun brew()

    // Concrete function (shared by all subclasses!)
    fun boilWater() {
        println("Heating water to 95 degrees Celsius... Done!")
    }
}

class EspressoMachine : CoffeeMachine() {
    override fun brew() {
        println("Extracting rich espresso shot under 9 bars of pressure. ☕")
    }
}

fun main() {
    val machine = EspressoMachine()
    machine.boilWater() // Inherited normal function
    machine.brew()      // Overridden abstract function
}
Terminal Output Heating water to 95 degrees Celsius... Done!
Extracting rich espresso shot under 9 bars of pressure. ☕

Example 11: Multiple Child Classes Extending an Abstract Class

A single abstract superclass serving as the shared foundation for multiple diverse subclasses.

Kotlin Example11_MultipleSubclasses.kt
KOTLIN Script
KOTLIN 
abstract class BankCard(val cardNumber: String) {
    abstract fun swipe(amount: Double)
}

class DebitCard(cardNumber: String, var balance: Double) : BankCard(cardNumber) {
    override fun swipe(amount: Double) {
        if (balance >= amount) {
            balance -= amount
            println("Debit approved: Paid \$$amount. Remaining: \$$balance")
        }
    }
}

class CreditCard(cardNumber: String, val creditLimit: Double) : BankCard(cardNumber) {
    override fun swipe(amount: Double) {
        println("Credit approved: Paid \$$amount from \$creditLimit limit.")
    }
}

fun main() {
    val debit = DebitCard("4111-2222", 500.0)
    val credit = CreditCard("5500-3333", 2000.0)

    debit.swipe(150.0)
    credit.swipe(350.0)
}
Terminal Output Debit approved: Paid $150.0. Remaining: $350.0
Credit approved: Paid $350.0 from $2000.0 limit.

6 Interface vs Abstract Class: Complete Comparison

Both interfaces and abstract classes define abstraction in Kotlin, but they serve different architectural roles. Choosing the right one is easy once you understand their differences:

Feature Interface Abstract Class
Declaration interface MyInterface abstract class MyClass
Purpose Defines capabilities / actions (can-do) Defines identity & core state (is-a)
Constructors ❌ No constructors allowed ✅ Can have constructors
Stored State ❌ Cannot store state (no backing fields) ✅ Can store state (val/var properties)
Inheritance Limits A class can implement many interfaces A class can inherit only one class
Function Bodies ✅ Can have default implementations ✅ Can have concrete & abstract functions
Colon Syntax class C : MyInterface (no ()) class C : MyClass() (must call constructor ())
Instantiable? ❌ Cannot be instantiated directly ❌ Cannot be instantiated directly

7 Practical Systems & Polymorphism (Examples 12 – 18)

Example 12: Runtime Polymorphism with an Interface

Holding diverse objects under an interface reference and processing them uniformly.

Kotlin Example12_InterfacePolymorphism.kt
KOTLIN Script
KOTLIN 
interface SoundMaker {
    fun sound()
}

class Bell : SoundMaker {
    override fun sound() = println("Bell: Ding Dong! 🔔")
}

class Drum : SoundMaker {
    override fun sound() = println("Drum: Boom Boom! 🥁")
}

fun main() {
    // Interface list holding diverse objects
    val instruments: List = listOf(Bell(), Drum())
    for (inst in instruments) {
        inst.sound() // Polymorphic dispatch!
    }
}
Terminal Output Bell: Ding Dong! 🔔
Drum: Boom Boom! 🥁

8 Common Beginner Mistakes & How to Fix Them

❌ 1. Trying to instantiate an Abstract Class

val a = Animal() // Error: Cannot create instance of abstract class

Fix: Create an instance of a non-abstract subclass: val a = Dog().

❌ 2. Forgetting to implement an abstract function

class Dog : Animal() // Error: Dog must be declared abstract or implement makeSound()

Fix: Implement all abstract functions with override fun makeSound() { ... }.

❌ 3. Adding parentheses () to Interface declaration

class Car : Drivable() // Error: Drivable has no constructors

Fix: Remove parentheses: class Car : Drivable.

❌ 4. Forgetting the 'override' keyword

fun play() { ... } in Guitar // Error: hides member of supertype

Fix: Always prepend override: override fun play() { ... }.

❌ 5. Thinking interfaces cannot have function bodies

Assuming interfaces only hold abstract signatures without implementations.

Truth: Kotlin interfaces can have default function implementations with full bodies!

❌ 6. Expecting interface properties to store state

interface User { var count = 0 } // Error: Property initializers not allowed

Fix: Interface properties cannot have backing fields; use custom getters or implement in subclasses.

❌ 7. Inheriting multiple abstract classes

class Duck : Bird(), Swimmer() // Error: Only one class may appear in supertype list

Fix: Turn secondary roles into interfaces: class Duck : Bird(), Swimmable.

❌ 8. Using an Abstract Class when an Interface suffices

Creating an abstract class with no state or constructor blocks other inheritance paths.

Fix: If there is no shared stored state or constructor, prefer an interface.

9 Quick Revision: 10 Key Takeaways

  • 1. Interface: A pure contract defining abstract functions and properties without storing state.
  • 2. Abstract Class: An incomplete class blueprint that cannot be instantiated directly and can maintain stored state via constructors.
  • 3. Multiple Interfaces: A single class can implement multiple interfaces separated by commas: class A : Interface1, Interface2.
  • 4. Single Superclass: A class can inherit from only one class (concrete or abstract).
  • 5. No Constructor Parentheses for Interfaces: Implementing an interface uses : InterfaceName without ().
  • 6. Constructor Parentheses for Abstract Classes: Extending an abstract class requires invoking its constructor: : AbstractClass(args).
  • 7. Default Function Bodies: Interfaces can provide default implementations that classes inherit or override freely.
  • 8. Mandatory Override: Subclasses must use the override keyword when implementing interface or abstract class members.
  • 9. Runtime Polymorphism: Variables of interface or abstract class types dynamically dispatch to concrete child implementations at runtime.
  • 10. The Decision Rule: Use an Interface for behavioral capabilities across unrelated classes; use an Abstract Class for shared code and state in a strict is-a hierarchy.
