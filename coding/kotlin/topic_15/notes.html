Classes and Objects in Kotlin

Master the foundation of Object-Oriented Programming (OOP). Learn how to create blueprints (Classes), instantiate real entities (Objects), configure Properties and Member Functions, and initialize state with Constructors and init blocks.

1 Introduction to Object-Oriented Programming (OOP)

Object-Oriented Programming (OOP) is a programming paradigm based on modeling software around real-world entities. Instead of creating scattered, unrelated variables, OOP allows you to bundle state (data) and behavior (functions) together into clean, reusable structures.

Real-Life Analogy: A college manages thousands of students. Each student has a name, age, and roll number, and performs actions like attending classes or taking exams. OOP lets us model a single unified concept: a Student!

Visual 1: Blueprint (Class) to Real-World Entity (Object)

2 What is a Class & What is an Object?

A Class is a user-defined blueprint. It specifies what properties (data) an entity will have and what member functions (actions) it can execute.

An Object is a physical instance created from that class. Calling Student() creates a new object in computer memory. You access its properties using the dot operator (.).

Visual 2: Class vs Object Architecture
Kotlin FirstClass.kt
KOTLIN Script
KOTLIN 
class Student {
    var name = "Aman"
    var age = 18
}

fun main() {
    // Create an instance of the Student class:
    val student1 = Student()

    println(student1.name)  // Access name via dot operator
    println(student1.age)   // Access age
}
Execution Output: Aman
18

4 Class Properties: val vs var

Variables declared inside a class are called Properties:

  • var properties: Can be modified and reassigned at any time.
  • val properties: Read-only properties that cannot be reassigned once initialized.
Visual 3: Updating Object var Properties
Kotlin PropertiesDemo.kt
KOTLIN Script
KOTLIN 
class Student {
    var name = "Aman"       // var: mutable property
    val college = "BBDU"    // val: read-only property
}

fun main() {
    val student = Student()
    student.name = "Rahul"  // Allowed!
    // student.college = "IIT" // ✗ COMPILE ERROR: Val cannot be reassigned

    println("Student: ${student.name}, College: ${student.college}")
}
Execution Output: Student: Rahul, College: BBDU
&info;
Important Rule: Even if a variable holding an object reference is declared with val (e.g., val student = Student()), you CAN still modify its internal var properties! The val only prevents reassigning the variable reference to point to another object entirely.

5 Member Functions in a Class

Functions defined inside a class body are called Member Functions (or methods). They represent the behaviors and actions that objects created from that class can perform.

Visual 4: Invoking a Member Function via an Object Reference
Kotlin MemberFunctionDemo.kt
KOTLIN Script
KOTLIN

    var name = "Aman"

    // Member function
    fun introduce() {
        println("Hello, my name is $name!")
    }
}

fun main() {
    val student = Student()
    student.introduce()  // Calls member function
}
Execution Output: Hello, my name is Aman!

7 Constructors & Primary Constructors

In previous examples, we created an empty object and manually set each property on subsequent lines. A Constructor allows you to pass initial values directly when creating the object!

In Kotlin, the Primary Constructor is written right in the class header after the class name. Marking parameters with val or var turns them into class properties automatically.

Visual 6: Primary Constructor Header Declaration
Kotlin PrimaryConstructor.kt
KOTLIN Script
KOTLIN 
// Primary constructor with val properties and a default parameter:
class Student(
    val name: String,
    val age: Int,
    var branch: String = "CSE"
)

fun main() {
    val s1 = Student("Aman", 18)             // Uses default branch "CSE"
    val s2 = Student("Priya", 19, "IT")      // Overrides branch

    println("${s1.name}: ${s1.branch}")
    println("${s2.name}: ${s2.branch}")
}
Execution Output: Aman: CSE
Priya: IT

8 The init Block: Initialization Logic

Since the primary constructor cannot contain custom code, Kotlin provides the init block. The init block executes immediately upon object creation during constructor execution.

Visual 7: Object Initialization Lifecycle Timeline
Kotlin InitBlockDemo.kt
KOTLIN Script
KOTLIN 
class Student(val name: String, val age: Int) {
    init {
        println("Student object created for: $name")
        if (age < 16) {
            println("Note: Student is under 16 years old.")
        }
    }
}

fun main() {
    val s = Student("Aman", 15)
}
Execution Output: Student object created for: Aman
Note: Student is under 16 years old.

9 Secondary Constructors (constructor & this(...))

Sometimes you need alternate ways to instantiate an object. You can define a Secondary Constructor using the constructor keyword. If the class has a primary constructor, each secondary constructor must delegate to it using : this(...).

Visual 8: Secondary Constructor Delegating to Primary with : this(...)
Kotlin SecondaryConstructor.kt
KOTLIN Script
KOTLIN 
class Student(val name: String, val age: Int) {
    // Secondary constructor providing default age 18:
    constructor(name: String) : this(name, 18)
}

fun main() {
    val s1 = Student("Aman", 20)  // Uses primary constructor
    val s2 = Student("Rahul")      // Uses secondary constructor (age defaults to 18)

    println("${s1.name} is ${s1.age}")
    println("${s2.name} is ${s2.age}")
}
Execution Output: Aman is 20
Rahul is 18

10 The this Keyword: Current Object Reference

The this keyword refers to the current object instance. It is primarily used to resolve naming ambiguities when a member function parameter shares the exact same name as a class property.

Visual 9: Resolving Shadowing with this.name = name
Kotlin ThisDemo.kt
KOTLIN Script
KOTLIN 
class Student {
    var name: String = "Aman"

    fun updateName(name: String) {
        // this.name refers to the class property; name refers to the parameter:
        this.name = name
    }
}

fun main() {
    val s = Student()
    s.updateName("Rahul")
    println(s.name)  // Rahul
}
Execution Output: Rahul

11 Class Property vs Local Variable

Characteristic Class Property Local Variable
Location Declared directly inside the class body or constructor Declared inside a function or loop block
Scope Accessible throughout the entire class by any member function Accessible only within the enclosing function/block
Lifetime Lives as long as the parent object exists in heap memory Created when function executes; destroyed upon return

13 Common Beginner Mistakes & How to Fix Them

✗ Mistake 1: Accessing property through Class name

println(Student.name) // Compile Error!

Fix: You must create an object instance first: val s = Student(); println(s.name).

✗ Mistake 2: Missing val/var in constructor

class Student(name: String) { ... }; s.name // Error!

Fix: Without val or var, a constructor parameter does not become a property: class Student(val name: String).

✗ Mistake 3: Secondary constructor delegation

constructor(name: String) { ... } // Error!

Fix: If a primary constructor exists, secondary constructors must delegate: constructor(name: String) : this(name, 18).

✗ Mistake 4: Shadowed property assignment

fun setAge(age: Int) { age = age } // Self-assignment!

Fix: Use this keyword to clarify the class property: this.age = age.

✗ Mistake 5: Assuming multiple objects share state

s1.name = "Aman"; println(s2.name) // Expects "Aman"!

Fix: Each instance has completely independent heap memory. Modifying s1 has zero effect on s2.

✗ Mistake 6: Reassigning a val property

val id: Int = 101; s.id = 102 // Error!

Fix: Properties declared with val are immutable. Use var if mutation is required.

14 Quick Revision & Takeaways

  • Class is a Blueprint: Declares properties (state) and member functions (behavior).
  • Object is an Instance: Allocated in memory using constructor invocation: val s = Student().
  • Properties: Variables declared inside a class; val for immutable, var for mutable.
  • Primary Constructor: Placed in class header; prefix parameters with val/var to make them properties.
  • The init block: Executes automatically upon object creation to handle initialization logic.
  • Secondary Constructor: Defined in class body; must delegate to primary constructor with : this(...).
  • The this keyword: Points to the current object instance; disambiguates parameter shadowing.
  • Independent State: Every object maintains its own private copy of instance properties in memory.

✓ B. Because name lacks `val` or `var`, making it only a constructor parameter and not a class property
C. Because String cannot be a property type
D. Because age comes after name
Explanation: In Kotlin primary constructors, only parameters declared with val or var become class properties. Plain parameters are only accessible in the constructor and `init` blocks.
3. When does the init block execute?
✓ A. Automatically during object creation as part of the constructor execution
B. Only when explicitly invoked using `object.init()`
C. When the application terminates
D. Only if an error occurs
Explanation: The init block is the initialization body of the primary constructor. It executes automatically whenever an instance of the class is created.
4. Why must a Secondary Constructor use : this(...) when a Primary Constructor exists?
✓ A. To delegate initialization to the primary constructor and ensure all primary properties are properly configured
B. To make the class open for inheritance
C. To convert the class into a Data Class
D. To make the constructor private
Explanation: Kotlin requires that all secondary constructors delegate directly or indirectly to the primary constructor to ensure consistent object initialization.
5. What is the role of the this keyword in fun setAge(age: Int) { this.age = age }?
✓ A. It disambiguates between the class property (this.age) and the local parameter (age)
B. It restarts the application
