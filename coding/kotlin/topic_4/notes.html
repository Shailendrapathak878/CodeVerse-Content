Variables, Constants & Type Inference

Learn how Kotlin stores and manages data in memory — master mutable variables (var), read-only references (val), compile-time constants (const val), and Kotlin's intelligent static type inference.

⏱️ Estimated Reading: 14 mins 🎯 Core Kotlin Memory Model ⚡ var vs val • Static Typing

1 Introduction to Variables

At its core, all software exists to process information — names, scores, prices, temperatures, or bank balances. A variable is a named storage container in your computer's memory (RAM) used to hold and retrieve data while your program runs.

📦 The Labelled Storage Box Analogy

Imagine you have a row of storage boxes on a warehouse shelf:
• The Label on the Box: The variable's name (e.g. studentName).
• The Physical Box: The reserved memory space in RAM.
• The Item Placed Inside: The stored value (e.g. "Alex").
Whenever your program needs the value, it simply looks for the box with that label!

BasicVariable.kt
KOTLIN Script
KOTLIN 
fun main() {
    // Store data in a variable and print it
    var studentName = "Alex"
    println(studentName)
}
Output:
Alex

2 Declaring & Initializing Variables

Programmers distinguish between four related actions in a variable's life cycle:

1. Declaration

Telling the compiler that a variable exists and what type of data it will store (e.g. var age: Int).

2. Initialization

Assigning a value to the variable for the very first time.

3. Assignment

Storing any value into a variable using the assignment operator (=).

4. Reassignment

Replacing an existing stored value with a new value of the same compatible type.

Full Explicit Syntax vs. Type Inference Syntax

SyntaxComparison.kt
KOTLIN Script
KOTLIN 
// Format A: Explicit Type Declaration
var score: Int = 100

// Format B: Inferred Type (Compiler determines Int automatically!)
var points = 100

// Format C: Declare first, initialize before reading
var age: Int
age = 20  // Valid! Initialized before use
⚠️ Definite Assignment Rule

If you declare a variable without giving it an initial value (like var age: Int), Kotlin strictly requires that you initialize it before attempting to read it or print it. Reading an uninitialized variable triggers a compile-time error: "Variable 'age' must be initialized".

3 The `var` Keyword (Mutable Variables)

The var keyword (short for variable) declares a mutable variable. "Mutable" means the value stored inside the box can be changed or updated later in the program.

VarDemo.kt
KOTLIN Script
KOTLIN 
fun main() {
    var score = 50
    println("Initial Score: $score")

    // Reassigning a new value
    score = 80
    println("Updated Score: $score")
}
Output:
Initial Score: 50
Updated Score: 80

When to use var: Use var only when a value naturally changes over time, such as loop counters, game scores, shopping cart balances, or user input fields.

4 The `val` Keyword (Read-Only References)

The val keyword (short for value) declares a read-only reference. Once initialized with a value, it cannot be reassigned.

ValDemo.kt
KOTLIN Script
KOTLIN 
fun main() {
    val collegeName = "CodeVerse University"
    println(collegeName)

    // UNCOMMENTING THE LINE BELOW CAUSES A COMPILER ERROR:
    // collegeName = "Tech Academy" // Error: Val cannot be reassigned!
}
Output:
CodeVerse University
🏆 Idiomatic Kotlin: Prefer `val` by Default!

Experienced Kotlin developers declare everything as `val` first. Only change it to var if you specifically discover that the value needs to be reassigned. This prevents accidental bugs and makes code safer and easier to reason about.

Deferred Initialization with `val`

A val does not have to be initialized on the exact line it is declared, provided the compiler can mathematically prove it is initialized exactly once before being read:

KOTLIN Script
KOTLIN 
val userRole: String
val isAdmin = true

if (isAdmin) {
    userRole = "Administrator"
} else {
    userRole = "Standard Member"
}
println(userRole) // Fully valid! Initialized exactly once.

6 Constants in Kotlin (`const val`)

While val represents a runtime read-only reference, Kotlin provides a special keyword modifier for compile-time constants: const val.

ConstantsDemo.kt
KOTLIN Script
KOTLIN 
package com.codeverse.constants

// 1. COMPILE-TIME CONSTANT: Known at compile time, inlined directly
const val APP_NAME = "CodeVerse"
const val MAX_ATTEMPTS = 3

fun main() {
    // 2. RUNTIME VAL: Value determined while program is running
    val currentTime = System.currentTimeMillis()

    println("App: $APP_NAME")
    println("Launch Time: $currentTime")
}
Output:
App: CodeVerse
Launch Time: 1730324100234

Rules for `const val`:

  • Location: Must be declared at the top level (outside functions) or inside an object declaration.
  • Types Allowed: Only primitive types (Int, Double, Boolean, etc.) and String.
  • Value: Must be a literal value or a pure constant expression computable at compile-time (e.g. const val SECONDS = 60 * 60). Cannot hold function calls like System.currentTimeMillis().

7 Type Inference in Kotlin

In older programming languages like Java or C, you were required to specify the type of every variable:

KOTLIN Script
KOTLIN 
// Verbose traditional syntax
String studentName = "Alex";
int studentAge = 20;

In Kotlin, the compiler is smart enough to determine the data type automatically from the value assigned to it. This mechanism is called Type Inference:

TypeInferenceDemo.kt
KOTLIN Script
KOTLIN 
fun main() {
    val name = "Alex"        // Compiler infers: String
    val age = 20             // Compiler infers: Int
    val price = 99.5         // Compiler infers: Double
    val isEnrolled = true    // Compiler infers: Boolean

    println("$name is $age years old.")
    println("Course Price: ₹$price | Enrolled: $isEnrolled")
}
Output:
Alex is 20 years old.
Course Price: ₹99.5 | Enrolled: true
💡 Critical Understanding: Kotlin is NOT Dynamically Typed!

Some beginners assume that because they don't write Int or String, Kotlin is dynamically typed like Python or JavaScript. This is false! Kotlin is 100% statically typed. The compiler assigns the type once during compilation, and that type is permanently locked.

8 Explicit Type Declaration vs. Type Inference

Approach Code Syntax When to Use
Type Inference val score = 95 Default choice when the assigned value makes the type obvious to human readers. Keeps code clean.
Explicit Type val score: Int = 95 When declaring without an initial value, or when choosing a specific type like Long, Float, or an Interface type.

9 Type Stability & Incompatible Reassignment

Once a variable's type is established (either explicitly or inferred), it cannot be reassigned a value of an incompatible type:

KOTLIN Script
KOTLIN 
fun main() {
    var age = 20  // Inferred as Int
    age = 21      // &check; Valid! 21 is an Int

    // THIS PRODUCES A COMPILATION ERROR:
    // age = "Twenty" 
    // Error: Type mismatch: inferred type is String but Int was expected
}

10 Variable & Constant Naming Conventions

  • camelCase for variables & values: Start with a lowercase letter, and capitalize each subsequent word (e.g. studentName, totalMarks, currentPrice).
  • UPPER_SNAKE_CASE for compile-time constants: All uppercase with underscores (e.g. MAX_USERS, DATABASE_NAME, API_KEY).
  • Descriptive and meaningful: Avoid cryptic one-letter names like x or temp, except for quick loop indices. Use studentCount instead of sc.

11 Common Beginner Mistakes & Fixes

Mistake 1 • Reassigning val
Attempting to change a val

val count = 5; count = 6

Fix: Change val to var if the value must be updated: var count = 5; count = 6.
Mistake 2 • Type Mismatch
Assigning wrong data type

var price = 50; price = "Fifty"

Fix: Keep types compatible: price = 60.
Mistake 3 • Uninitialized Read
Reading before initialization

var age: Int; println(age)

Fix: Assign a value before printing: age = 20; println(age).
Mistake 4 • Local const val
Writing const val inside main()

fun main() { const val PI = 3.14 }

Fix: Move const val to top level outside the function, or use normal val inside main().

12 Real-World Mini Project: Student Card

Here is a complete program putting all variable declarations to work appropriately:

StudentCard.kt
KOTLIN Script
KOTLIN 
const val COLLEGE_NAME = "CodeVerse Institute"

fun main() {
    // val: Student's name and ID do not change
    val studentName = "Meera Sharma"
    val studentId = 1042

    // var: Marks and attendance percentage can be updated
    var currentMarks = 84.5
    var attendancePercentage = 92

    println("=== $COLLEGE_NAME ===")
    println("Student: $studentName (ID: #$studentId)")
    println("Initial Marks: $currentMarks% | Attendance: $attendancePercentage%")

    // Update student's marks after bonus exam
    currentMarks = 89.0
    println("Final Updated Marks: $currentMarks%")
}
Output:

Initial Marks: 84.5% | Attendance: 92%
Final Updated Marks: 89.0%

13 Quick Revision

  • Variables: Named memory storage slots for application data.
  • `var` (Mutable): Can be reassigned with new values of the same type.
  • `val` (Read-only): Cannot be reassigned once initialized. Preferred default in Kotlin.
  • `const val`: Compile-time constant for top-level primitives/Strings.
  • Type Inference: The compiler automatically detects variable types from initial values.
  • Static Typing: Types are fixed at compile time and cannot change dynamically.
  • Naming: Use camelCase for variables, UPPER_SNAKE_CASE for constants.

14 Practice & Assessment

Test your understanding of variables, constants, and type inference:

Concept Q1
1. What is the fundamental difference between declaration and initialization?
Answer: Declaration introduces a variable name and type to the compiler (e.g. var x: Int). Initialization is the very first assignment of a value to that declared variable (e.g. x = 10).
Concept Q2
2. Does Kotlin's type inference mean Kotlin is dynamically typed?
Answer: No! Kotlin is statically typed. Type inference simply saves keystrokes by letting the compiler analyze the value and lock in the static type at compile time.
var vs val Q3
3. Why do experienced Kotlin developers prefer `val` over `var`?
Answer: val prevents unintended side-effects and accidental reassignments, making code much safer, more predictable, and easier to debug.
var vs val Q4
4. Can a `val` be declared on one line and initialized on a later line?
Answer: Yes! As long as the type is declared explicitly (e.g. val score: Int) and the compiler can prove it is assigned exactly once before use.
Constants Q5
5. Can you write `const val time = System.currentTimeMillis()`? Why or why not?
Answer: No! const val values must be known at compile time. System.currentTimeMillis() is a runtime function call, so it must be declared using regular val.
Output Prediction Q6
6. What will be the output of this code?
KOTLIN Script
KOTLIN 
fun main() {
    var count = 10
    count = count + 5
    println(count)
}
Answer: 15. The expression count + 5 evaluates to 15 and updates the mutable variable count.
Output Prediction Q7
7. What type does the compiler infer for `val rate = 75.0`?
Answer: Double. Numeric literals with decimals default to 64-bit floating-point Double in Kotlin.
Find the Error Q8
8. Why does this code fail to compile?
KOTLIN Script
KOTLIN 
fun main() {
    var name = "CodeVerse"
    name = 100
    println(name)
}
Answer: Type mismatch error! name was inferred as String. Even though it is a var, it can only hold String values, not an Int (100).
