A Section A: Exception Handling in Kotlin

In computer programming, unexpected runtime issues inevitably occur — users enter letters when asked for numbers, server networks disconnect, or files disappear from storage. Exception handling is the technique that allows your program to intercept these errors gracefully instead of crashing abruptly.

¡
Real-Life Analogy: The Spare Tire
Imagine driving a car and getting a flat tire. A program with no exception handling would crash completely into a ditch. A program with exception handling safely detects the flat tire, pulls over to the shoulder, mounts the spare tire, and continues driving to the destination.
Diagram 1.1: Basic Exception Handling Flow

Error vs Exception: Beginner Understanding

Error Fatal System Failures

Caused by catastrophic hardware or JVM limitations (e.g., OutOfMemoryError, StackOverflowError). The application cannot recover.

Exception Recoverable Application Issues

Caused by logical conditions or bad input (e.g., bad format, divide by zero). The application can catch, recover, and continue.

✓
Kotlin Technical Fact: Unchecked Exceptions Only!
In Java, checked exceptions force developers to declare throws IOException on function signatures. Kotlin has NO checked exceptions! All exceptions in Kotlin are unchecked. You can catch any exception you wish, but the compiler never forces tedious boilerplate declarations.

Common Kotlin Runtime Exceptions

Exception Class Trigger Cause Typical Example
ArithmeticException Mathematical violations such as dividing an integer by zero. val x = 10 / 0
NullPointerException Attempting to invoke methods or fields on a null reference. val length = text!!.length
NumberFormatException Attempting to parse a non-numeric string into a number. "abc".toInt()
IndexOutOfBoundsException Accessing an index outside list/array boundaries. val item = list[99]
IllegalArgumentException Passing an illegal or inappropriate argument to a method. require(age >= 0)

Keywords: try, catch, finally, throw, and Expression Returns

Kotlin's exception syntax is clean and supports using try-catch as an expression (assigning its result directly to a variable).

Kotlin Examples 1 & 2: Basic try-catch & try as an Expression
KOTLIN Script
KOTLIN 
// Example 1: Standard try-catch with finally block
fun divideSafely(numerator: Int, denominator: Int) {
    try {
        val result = numerator / denominator
        println("Result: $result")
    } catch (e: ArithmeticException) {
        println("Caught ArithmeticException: Cannot divide by zero!")
    } finally {
        println("Cleanup: Division operation finished.")
    }
}

// Example 2: Using try as an expression to parse user input safely
fun parseAge(rawInput: String): Int {
    return try {
        rawInput.toInt()
    } catch (e: NumberFormatException) {
        -1 // Default fallback value when parsing fails
    }
}

fun main() {
    divideSafely(20, 4)
    divideSafely(15, 0)
    
    val validAge = parseAge("25")
    val badAge = parseAge("twenty-five")
    println("Valid age: $validAge, Bad input fallback: $badAge")
}
Expected Output Result: 5

fun safeCalculate(list: List, index: Int) {
    try {
        val raw = list[index]

}

Custom Exceptions: Domain-Specific Error Handling

A custom exception is a user-defined class inheriting from Exception. They give domain-specific names to business rule violations (such as InsufficientBalanceException or InvalidCredentialsException) rather than relying on generic strings.

Kotlin Examples 5 & 6: Bank Withdrawal & Login Custom Exceptions

// Example 5: Custom exception for banking balance rules
class InsufficientBalanceException(message: String) : Exception(message)

class BankAccount(val accountNumber: String, var balance: Double) {
    fun withdraw(amount: Double) {
        if (amount > balance) {
            throw InsufficientBalanceException("Cannot withdraw \$$amount. Available balance: \$$balance")
        }
        balance -= amount
        println("Successfully withdrew \$$amount. Remaining: \$$balance")
    }
}

// Example 6: Custom exception for User Authentication
class InvalidCredentialsException(message: String) : Exception(message)

fun loginUser(username: String, password: String) {
    if (username != "admin" || password != "secret123") {
        throw InvalidCredentialsException("Incorrect credentials for username: $username")
    }
    println("Welcome, $username! Authentication successful.")
}

fun main() {
    val myAccount = BankAccount("ACC-9812", 350.0)
    try {
        myAccount.withdraw(100.0)
        myAccount.withdraw(500.0)
    } catch (e: InsufficientBalanceException) {
        println("Bank Alert: ${e.message}")
    }

    try {
        loginUser("admin", "wrongPassword")
    } catch (e: InvalidCredentialsException) {
        println("Security Warning: ${e.message}")
    }
}
Expected Output Successfully withdrew $100.0. Remaining: $250.0

B Section B: Scope Functions

Kotlin's standard library provides five specialized functions — let, run, with, apply, and also — whose sole purpose is to execute a block of code within the context of an object. Inside the lambda, you can access the object without repeating its variable name over and over.

¡
Real-Life Analogy: The Crafting Workbench
Imagine you have a smartphone in your hand. Instead of repeatedly announcing "Take phone out of pocket, press phone power button, enter phone passcode, swipe phone screen", you place the phone directly onto your workbench. Within that workbench workspace (scope), every action refers directly to that phone without repeating its name!
Diagram 2.1: The 5 Scope Functions Matrix

1. The 'let' Function: Transformation & Null-Safety

let refers to the context object as it and returns the result of the lambda. Its most common use case is executing code only when an object is not null via safe call ?.let { ... }.

Diagram 2.2: Safe Null-Check Flow with ?.let
Kotlin Examples 7 & 8: 'let' for Null Safety & Transformation
KOTLIN Script
KOTLIN 
// Example 7: Null-safe username check using ?.let
fun printGreeting(username: String?) {
    username?.let {
        // 'it' is guaranteed to be non-null String inside this block
        println("Hello, ${it.uppercase()}! Profile length: ${it.length}")
    } ?: println("Guest visitor detected.")
}

// Example 8: Transforming values using let
fun transformNumbers() {
    val numbers = listOf(1, 2, 3, 4, 5)
    val squaredSum = numbers.let { list ->
        // Can rename 'it' to meaningful name 'list'
        list.map { it * it }.sum()
    }
    println("Sum of squares: $squaredSum")
}

fun main() {
    printGreeting("alex_kotlin")
    printGreeting(null)
    transformNumbers()
}
Expected Output Hello, ALEX_KOTLIN! Profile length: 11
Guest visitor detected.
Sum of squares: 55

2. The 'run' Function: Scoped Computation with 'this'

run accesses the receiver object via this (which can be omitted) and returns the result of the lambda. It is ideal when you need to configure an object and compute a returned value in one step.

Kotlin Examples 9 & 10: 'run' for Object Execution & Standalone Block
KOTLIN Script
KOTLIN 
data class Rectangle(val width: Double, val height: Double)

fun main() {
    val box = Rectangle(12.0, 5.0)

    // Example 9: run on an object instance (uses 'this' implicitly)
    val perimeterDescription = box.run {
        val p = 2 * (width + height) // 'this.width' and 'this.height'
        "Box (${width}x${height}) has perimeter: $p"
    }
    println(perimeterDescription)

    // Example 10: Non-extension run block (for limiting temporary variable scope)
    val discountCode = run {
        val rawPrefix = "WINTER"
        val year = 2026
        "${rawPrefix}_$year"
    }
    println("Generated promo: $discountCode")
}
Expected Output Box (12.0x5.0) has perimeter: 34.0
Generated promo: WINTER_2026

3. The 'with' Function: Non-Extension Object Grouping

with is NOT an extension function. It takes the context object as an explicit argument: with(target) { ... }. Inside the block, it uses this and returns the lambda result. It reads naturally: "With this object, do the following operations."

Diagram 2.3: Syntax Structure: run vs with
Kotlin Example 11: Grouping operations with 'with'
KOTLIN Script
KOTLIN 
class StringBuilderHelper {

fun main() {

        append("--- Monthly Report ---\n")

        append("Uptime: 99.98%\n")
        toString() // Lambda result returned

Uptime: 99.98%

apply refers to the context object as this and returns the original object itself. It is the gold standard in Kotlin for configuring properties on newly created objects (Builder pattern without boilerplate).

5. The 'also' Function: Side Effects, Auditing & Logging

also refers to the context object as it and returns the original object itself. It reads: "Do this main work, and ALSO do this logging/validation side-effect."

// Example 14: Auditing object creation without breaking fluent method chaining
fun createOrder(orderId: String, total: Double): Map {
    return mapOf("id" to orderId, "total" to total).also {
        println("[AUDIT LOG] Order ${it["id"]} created with total: \$${it["total"]}")
    }
}

// Example 15: Idiomatic variable value swap using also
fun swapValues() {
    var a = 10
    var b = 20
    println("Before swap: a = $a, b = $b")

    a = b.also { b = a }
    println("After swap: a = $a, b = $b")
}

fun main() {
    val order = createOrder("ORD-771", 89.99)
    println("Processing order in main: ${order["id"]}")
    swapValues()
}

C Section C: Delegation in Kotlin

Delegation is an object-oriented design pattern where an object passes responsibility for a task to another helper/specialist object. Kotlin provides first-class language support for delegation using the concise by keyword — eliminating dozens of repetitive forwarding methods.

¡
Real-Life Analogy: The Business Owner & The Accountant
A bakery owner doesn't personally calculate quarterly corporate income taxes. When tax season arrives, the owner delegates tax preparation to a certified accountant. To the tax authority, the bakery submitted its taxes; under the hood, the specialist accountant did the heavy lifting!
Diagram 3.1: Interface Delegation Architecture with 'by'

Interface Delegation: Replacing Rigid Inheritance

Traditional inheritance locks classes into rigid parent-child relationships. Kotlin's class Manager(worker: Worker) : Worker by worker implements the interface by forwarding every call to worker automatically.

Kotlin Examples 16 & 17: Payment & Notification Interface Delegation
KOTLIN Script
KOTLIN 
// Example 16: Payment Gateway Interface Delegation
interface PaymentGateway {
    fun processPayment(amount: Double)
    fun refundPayment(transactionId: String)
}

class StripeGateway : PaymentGateway {
    override fun processPayment(amount: Double) = println("Stripe: Charged \$$amount to customer.")
    override fun refundPayment(transactionId: String) = println("Stripe: Refunded transaction $transactionId.")
}

// CheckoutManager delegates all PaymentGateway calls to 'gateway'
class CheckoutManager(gateway: PaymentGateway) : PaymentGateway by gateway {
    // Can optionally override specific methods to add business logic
    override fun processPayment(amount: Double) {
        println("[Checkout Security Check] Verifying fraud risk before charging...")
        gateway.processPayment(amount) // Delegates to actual gateway
    }
}

// Example 17: Notification Service Delegation
interface Notifier {
    fun sendNotification(message: String)
}

class EmailNotifier : Notifier {
    override fun sendNotification(message: String) = println("Sending Email: $message")
}

class CustomerSupport(notifier: Notifier) : Notifier by notifier

fun main() {
    val checkout = CheckoutManager(StripeGateway())
    checkout.processPayment(149.99)
    checkout.refundPayment("TX-9901") // Handled automatically by StripeGateway!

    val support = CustomerSupport(EmailNotifier())
    support.sendNotification("Your ticket #402 has been resolved.")
}
Expected Output [Checkout Security Check] Verifying fraud risk before charging...
Stripe: Charged $149.99 to customer.
Stripe: Refunded transaction TX-9901.
Sending Email: Your ticket #402 has been resolved.

class StockTracker {
    var sharePrice: Double by Delegates.observable(150.0) { prop, oldValue, newValue ->
        println("Stock ticker update: ${prop.name} changed from \$$oldValue to \$$newValue")
    }
}

// Example 20: Rejecting invalid values with vetoable
class Thermostat {
    var temperatureCelsius: Int by Delegates.vetoable(20) { prop, oldValue, newValue ->
        val isValid = newValue in 15..30
        if (!isValid) {
            println("VETOED! Temperature $newValue&deg;C is outside safe range (15 - 30&deg;C). Keeping $oldValue&deg;C")
        }
        isValid // If false, new value is rejected and property keeps oldValue
    }
}

fun main() {

    println("DatabaseConnector instance created (notice no connection yet).")
    println("First access: ${db.connectionString}")
    println("Second access: ${db.connectionString} (cached, no connection print!)")

    // Test Observable
    val stock = StockTracker()
    stock.sharePrice = 154.5
    stock.sharePrice = 162.0

    // Test Vetoable
    val ac = Thermostat()
    ac.temperatureCelsius = 24
    println("Current AC temp: ${ac.temperatureCelsius}&deg;C")
    ac.temperatureCelsius = 45 // Attempt invalid value
    println("Current AC temp: ${ac.temperatureCelsius}&deg;C")
}

⚡ Quick Revision: 15 Key Takeaways

  1. Exceptions are runtime events that disrupt normal instruction execution; handling them prevents sudden application crashes.
  2. Kotlin has NO checked exceptions — unlike Java, functions never require throws declarations and try-catch is optional.
  3. Error vs Exception: Errors (e.g. OutOfMemoryError) are fatal JVM issues; Exceptions are recoverable application scenarios.
  4. try-catch as an expression: Kotlin's try block can return a value directly into a variable or function return.
  5. finally block always executes for cleanup (closing files, releasing locks), regardless of whether an exception was thrown.
  6. throw statement explicitly creates and triggers an exception, interrupting execution and unwinding the call stack.
  7. Custom exceptions inherit from Exception to represent clear domain-specific business rule violations.
  8. Scope functions (let, run, with, apply, also) execute code blocks within an object's context.
  9. apply returns the original object and uses this — best for object initialization and builder configuration.
  10. also returns the original object and uses it — best for logging, auditing, and side effects.
  11. let returns the lambda result and uses it — best for null safety (?.let) and value transformation.
  12. run and with return the lambda result and use this — best for computing values from an object.
  13. Interface delegation (by delegate) automatically forwards all interface methods to a helper object without boilerplate.
  14. by lazy initializes a val property only upon its first read, caching the result thread-safely for all subsequent reads.
  15. Delegates.observable tracks property updates, while Delegates.vetoable can reject invalid property assignments.

✗ D) A Boolean indicating whether an error occurred.
Explanation: In Kotlin, try is an expression. The returned value is the last statement of the try block (on success) or the catch block (on exception). Notice the finally block does NOT affect the return value!

✗ D) 'also' terminates execution if an exception is thrown.
