Conditional Statements

Learn how programs make dynamic, real-time decisions. Master if, if...else, multi-branch else if ladders, nested conditions, the switch statement, truthy and falsy values, and write clean, dependable decision logic.

1 Welcome to Decision Making

In everyday life, our choices depend entirely on conditions. If it rains, you carry an umbrella; otherwise, you leave it at home. If you have enough money in your bank account, an online purchase succeeds; otherwise, the transaction is declined.

In software development, conditional statements allow a program to evaluate a Boolean expression and select which branch of code to execute.

First Conditional Program JS 
const marks = 75;

if (marks >= 40) {
  console.log("You passed!");
}
Expected Output
You passed!
◆ Visual 1: The Decision Flow
Condition: marks >= 40 (75 >= 40 → true)
→ YES
Action: Print "You passed!"

Note: If marks were less than 40, the condition evaluates to false, and this specific program produces no output at all.

The statement begins with the if keyword, followed by the test condition inside parentheses (...). The code inside the curly braces { ... } is the body block that runs exclusively when the condition evaluates to true.

2 The Single if Statement

The basic if statement represents a one-way fork in your code. When the condition evaluates to a truthy value, the enclosed block executes. When false, the engine completely skips the block and continues with the next statement:

Voting Eligibility Check JS 
const age = 19;

if (age >= 18) {
  console.log("You are eligible to vote.");
}
Expected Output
You are eligible to vote.

If we changed age to 16, the condition 16 >= 18 evaluates to false. Because there is no alternative branch specified, the block is ignored and nothing is printed.

E-Commerce Free Shipping Threshold JS 
const cartTotal = 120;

if (cartTotal > 100) {
  console.log("You qualified for free shipping!");
}
Expected Output
You qualified for free shipping!

3 The Two-Way Choice: if...else

In many situations, you need an explicit fallback action when the initial check fails. The else keyword creates an alternate branch that executes whenever the if condition is false:

Pass or Fail Outcome JS 
const marks = 32;

if (marks >= 40) {
  console.log("Pass");
} else {
  console.log("Fail");
}
Expected Output
Fail
◆ Visual 2: Two-Way Fork (if...else)
Condition: marks >= 40 (32 >= 40 → false)
→ NO
Fallback: Print "Fail"
Account Balance Verification JS 
const balance = 50;
const itemCost = 80;

if (balance >= itemCost) {
  console.log("Purchase successful.");
} else {
  console.log("Insufficient balance.");
}
Expected Output
Insufficient balance.

4 The else if Decision Ladder

When a problem involves more than two possibilities, chain multiple checks using else if. JavaScript evaluates each condition from top to bottom, executes the very first block whose condition is true, and skips all remaining branches:

Grade Calculator Ladder JS 
const marks = 82;

if (marks >= 90) {
  console.log("Grade A+");
} else if (marks >= 80) {
  console.log("Grade A");
} else if (marks >= 70) {
  console.log("Grade B");
} else if (marks >= 40) {
  console.log("Grade C");
} else {
  console.log("Fail");
}
Expected Output
Grade A
◆ Visual 3: Top-to-Bottom Ladder Evaluation
1. marks >= 90 82 >= 90 is false → proceed down
2. marks >= 80 82 >= 80 is true → execute "Grade A" & exit ladder!
3. marks >= 70 Skipped automatically
4. marks >= 40 Skipped automatically
5. else Skipped automatically
💡 Boundary Testing & Scale Notice
Always test boundary edge values in your ladders: 90 yields Grade A+, 80 yields Grade A, 70 yields Grade B, 40 yields Grade C, and 39 yields Fail. This grading scale is purely illustrative for teaching programming logic.

5 Nested if Statements

A conditional block can reside inside another conditional block. This is called a nested condition. The inner condition evaluates only after the outer check evaluates to true:

Campus Security Access JS 
const age = 20;
const hasStudentId = true;

if (age >= 18) {
  if (hasStudentId) {
    console.log("Entry allowed.");
  } else {
    console.log("Please show your student ID.");
  }
} else {
  console.log("You are not eligible for entry.");
}
Expected Output
Entry allowed.

While nested checks are powerful, nesting more than two levels deep can make code difficult to read. In many cases, combining conditions with logical operators (&&) produces cleaner code.

6 The switch Statement

When you need to compare a single variable against many discrete, exact values (such as days of the week, user roles, or menu options), the switch statement offers an organized alternative to long else if chains:

Day of Week Selector JS 
const day = 2;

switch (day) {
  case 1:
    console.log("Monday");
    break;
  case 2:
    console.log("Tuesday");
    break;
  case 3:
    console.log("Wednesday");
    break;
  default:
    console.log("Unknown day");
}
Expected Output
Tuesday

The switch statement matches cases using strict equality (===). The break keyword halts execution and jumps out of the switch block. If you omit break, JavaScript continues executing subsequent cases even if their labels do not match—a behavior known as fall-through.

7 Truthy and Falsy Values in Conditions

In JavaScript, a condition does not have to be an explicit comparison like x === 5. Any value placed inside if (...) is automatically coerced into a Boolean:

◆ Visual 4: Falsy Values vs Truthy Values
❌ The 8 Falsy Values

JavaScript treats only these eight values as false:

  • false
  • 0, -0, and 0n
  • "" (empty string)
  • null and undefined
  • NaN (Not a Number)
✔ Truthy Values

Everything else evaluates to true, including:

  • Non-empty strings (e.g. "CodeVerse", "0")
  • Any non-zero numbers (e.g. 42, -10)
  • Empty arrays ([]) → Truthy!
  • Empty objects ({}) → Truthy!
Truthy & Falsy Demonstration JS 
if ("CodeVerse") {
  console.log("This string is truthy.");
}

if (0) {
  console.log("This message will not appear."); // 0 is falsy!
}

if ([]) {
  console.log("An empty array is truthy.");
}
Expected Output
This string is truthy.
An empty array is truthy.

8 Combining Conditions with Logical Operators

Real-world business rules frequently require multiple conditions to be met simultaneously (&&) or offer several acceptable pathways (||):

Multi-Condition Access Rule JS 
const age = 20;
const hasID = true;

if (age >= 18 && hasID) {
  console.log("Access granted.");
} else {
  console.log("Access denied.");
}
Expected Output
Access granted.

Remember the core rules: && requires both conditions to be truthy, || requires at least one condition to be truthy, and ! inverts the truth value of a condition.

9 The Ternary Operator: A Quick Comparison

As introduced in Topic 4, the ternary operator (? :) provides a compact expression for assigning one of two values:

Ternary Expression JS 
const age = 17;
const result = age >= 18 ? "Adult" : "Minor";

console.log(result);
Expected Output
Minor

When to use which: Use the ternary operator when you need to quickly return or assign a value based on a condition. Use if...else when your decision involves multiple lines of logic, variable reassignments, or complex branching.

10 Common Beginner Mistakes & Fixes

❌ Mistake 1: Accidental Assignment Inside Condition
Writing if (marks = 40) accidentally assigns 40 to marks, which evaluates to truthy!
✔ Fix: Use comparison operators: if (marks >= 40).
❌ Mistake 2: Ladder Conditions in Reverse Order
Writing if (marks >= 40) { ... } else if (marks >= 90) { ... } traps all A+ students in the 40 check.
✔ Fix: Always order ladder conditions from most specific (highest) to general.
❌ Mistake 3: Forgetting break in Switch Cases
Omitting break causes unwanted fall-through into following cases.
✔ Fix: Add break; at the conclusion of each case block.
❌ Mistake 4: Assuming [] or {} is Falsy
Testing if (usersList) passes even if the array is empty: [] is an object, hence truthy.
✔ Fix: Test the length property: if (usersList.length > 0).
❌ Mistake 5: Confusing && with ||
Writing if (role === "admin" && role === "editor") can never be true!
✔ Fix: Use OR: if (role === "admin" || role === "editor").
❌ Mistake 6: Excluding Boundary Values
Writing if (marks > 40) marks a student scoring exactly 40 as failed.
✔ Fix: Use greater-than-or-equal: if (marks >= 40).
❌ Mistake 7: Omitted Braces on Multi-Line Code
Omitting braces around if blocks causes subsequent lines to execute unconditionally.
✔ Fix: Always wrap statement bodies in explicit curly braces { ... }.
❌ Mistake 8: Unmatched Final Else Logic
Assuming else only catches one specific case rather than all remaining possibilities.
✔ Fix: Ensure the final else message accurately represents every unhandled case.

11 Hands-On Mini Project: Student Result System

Combine conditional ladders, logical operators, and state evaluation into a cohesive, realistic decision system:

★ Project Requirements
  1. Evaluate marks (85) using an if...else if...else ladder to assign a letter grade.
  2. Combine passing threshold (marks >= 40) with assignmentSubmitted using logical AND (&&).
  3. Log the verified status and grade.
✔ Complete Solution Code 
const marks = 85;
const assignmentSubmitted = true;

let grade;

if (marks >= 90) {
  grade = "A+";
} else if (marks >= 80) {
  grade = "A";
} else if (marks >= 70) {
  grade = "B";
} else if (marks >= 40) {
  grade = "C";
} else {
  grade = "Fail";
}

if (marks >= 40 && assignmentSubmitted) {
  console.log("Result: Pass");
  console.log("Grade:", grade);
} else {
  console.log("Result: Needs Review");
}
Solution Terminal Output
Result: Pass
Grade: A
Secondary Example: Role-Based Access with Switch JS 
const role = "editor";

switch (role) {
  case "admin":
    console.log("Full system control.");
    break;
  case "editor":
    console.log("Can create and edit content.");
    break;
  case "viewer":
    console.log("Read-only access.");
    break;
  default:
    console.log("Role not recognized.");
}
Expected Output
Can create and edit content.

12 Quick Recap & Self-Reflection

1. Single & Two-Way Choices Use if for optional execution; add else when an explicit fallback action is needed.
2. Order Matters in Ladders Conditions in an else if ladder evaluate from top to bottom. Order checks from most specific to general.
3. Switch for Discrete Matching Use switch when matching a single value against exact constants. Always include break and default.
4. Truthy Awareness Remember the 8 falsy values: false, 0, -0, 0n, "", null, undefined, and NaN.
🤔 Quick Output-Prediction Questions
  1. What is logged by if ([]) { console.log("Yes"); } else { console.log("No"); }? (Answer: "Yes", because empty arrays are truthy objects!)
  2. If let score = 85; and we check if (score >= 70) console.log("B"); else if (score >= 80) console.log("A");, which grade prints? (Answer: "B", because 85 >= 70 matches first!)
  3. Why does omitting break; inside a matching case cause subsequent cases to execute? (Answer: JavaScript falls through to the next statement until a break or block end is reached.)
