Intro How Do Websites Get Real Data?

Imagine opening a weather application on your phone. Does that web page have tomorrow's temperature in Tokyo, London, and New Delhi hardcoded directly into its JavaScript file? Of course not! Likewise, when a student opens the CodeVerse Dashboard, the browser does not store thousands of student profiles in its source files. Instead, it asks a remote server: "Please send me the latest exam results for Aarav Sharma."

The server computes the records, packages them into a lightweight text format called JSON, and sends back an HTTP Response. The browser receives this data and uses JavaScript DOM methods to render student cards, scores, and status badges onto the screen.

01 What Is an API?

An API (Application Programming Interface) is a defined bridge that allows two software systems to communicate with each other. In web development, a Web API is a server that listens for incoming HTTP requests at specific web addresses called Endpoints.

When you visit an endpoint like https://jsonplaceholder.typicode.com/posts/1, the server looks up the requested record and sends back a response containing the data. It is important to remember:

  • Frontend vs. Backend: Your JavaScript code runs in the user's browser. The API server runs in a remote data center.
  • Responses are Temporary: Data sent over the network is a snapshot in time; it should not be assumed to remain unchanged forever.
  • Authentication & Limits: Many production APIs require API keys, bearer tokens, or enforce rate limits (maximum requests per minute) to prevent abuse.
Example 1.1 — Inspecting an API Resource Endpoint URL JavaScript 
// An API endpoint is an absolute URL pointing to a remote resource
const endpoint = "https://jsonplaceholder.typicode.com/posts/1";

// Simply storing or logging an endpoint URL does NOT make a network request!
console.log(endpoint);
Expected Output
https://jsonplaceholder.typicode.com/posts/1

Explanation: A URL string by itself is just text. A network request only happens when you pass this URL to a browser networking method like fetch().

Example 1.2 — Understanding a Structured API Response Entity JavaScript 
// A local object representing the structured data returned by a REST API
const post = {
  userId: 1,
  id: 1,
  title: "Learning JavaScript APIs",
  body: "Fetch data and display it in a web application."
};

// Accessing properties on the structured record
console.log(post.title);
console.log(post.body);
Expected Output
Learning JavaScript APIs Fetch data and display it in a web application.

Explanation: When APIs respond, they typically structure their entities with numeric IDs and string values, which JavaScript can read directly through standard dot notation.

02 What Is JSON?

JSON stands for JavaScript Object Notation. It is the universal standard format used across the internet for transmitting structured data between servers and web clients.

Although JSON is derived from JavaScript object syntax, it is plain text. Programming languages like Python, Java, C#, and Go can all read and produce JSON text effortlessly.

Allowed in JSON ✅ FORBIDDEN in JSON ❌
Strings in double quotes only: "name" Single quotes or backticks: 'name' or `name`
Numbers (integers, floats): 42, 98.6 Functions or methods
Booleans: true, false undefined values
Null values: null JavaScript comments (// or /* */)
Arrays: ["HTML", "CSS"] Trailing commas: {"a": 1,}
Example 2.1 — A Standard JSON Document JSON 
{
  "name": "Aarav",
  "course": "JavaScript",
  "marks": 92,
  "passed": true
}

Breakdown: Notice that every single property key ("name", "course", "marks", "passed") is enclosed in double quotes. Numeric and boolean values do not have quotes.

Example 2.2 — Nested JSON Data Structure JSON 
{
  "student": {
    "name": "Priya",
    "course": "JavaScript"
  },
  "skills": ["HTML", "CSS", "JavaScript"],
  "active": true
}

Breakdown: JSON supports nested child objects ("student") and arrays ("skills"). Once parsed into JavaScript, you access nested items with chained dot notation (e.g. data.student.name) and array indices (e.g. data.skills[0]).

03 JSON.stringify() and JSON.parse()

JavaScript provides a built-in global object named JSON with two essential methods:

  • JSON.stringify(value): Converts a JavaScript object or array into a valid JSON text string (Serialization).
  • JSON.parse(text): Converts a valid JSON text string back into a real JavaScript object or array (Deserialization).

04 Introduction to the Fetch API

The Fetch API provides a modern, clean JavaScript interface for accessing and manipulating HTTP requests and responses. The global fetch(url, options) function initiates a network request and returns a Promise that resolves to a Response object.

Working with fetch() is a two-step asynchronous process:

  1. Step 1: Fetching Headers: const response = await fetch(url) resolves as soon as the server returns the HTTP headers and status code (e.g. 200 OK or 404 Not Found). The body content has not finished downloading yet!
  2. Step 2: Parsing Body Stream: Calling await response.json() or await response.text() asynchronously reads the full response stream to completion and parses it.
Example 4.1 — Making a Basic GET Request and Inspecting Status JavaScript 
async function loadPost() {
  // 1. Initiate the network request
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts/1"
  );

  // 2. Inspect the HTTP status code and .ok boolean flag
  console.log("HTTP status:", response.status);
  console.log("Request successful:", response.ok);
}

loadPost().catch((error) => {
  console.error("Request failed:", error.message);
});
Expected Output (When Network Connected)
HTTP status: 200 Request successful: true
Example 4.2 — Complete Safe Fetch with Status Guard and JSON Parsing JavaScript 
async function loadPostData() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/posts/1"
  );

  // ALWAYS guard against HTTP failures before parsing the body!
  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  // Step 2: Read and parse the JSON stream
  const post = await response.json();

  console.log("Title:", post.title);
  console.log("Body:", post.body);
}

loadPostData().catch((error) => {
  console.error("Could not load post:", error.message);
});
Expected Output
Title: sunt aut facere repellat provident occaecati excepturi optio reprehenderit Body: quia et suscipit suscipit recusandae consequuntur expedita et cum reprehenderit molestiae ut ut quas totam nostrum rerum est autem sunt rem eveniet architecto

05 Understanding HTTP Methods & Status Codes

Every HTTP request specifies a Method (or verb) indicating what action the client wishes to execute on the resource:

Method Purpose Has Request Body? Student Example
GET Retrieve an existing resource No fetch("/api/students/1")
POST Submit data to create a new resource Yes fetch("/api/students", { method: "POST", ... })
PUT Completely replace an existing resource Yes fetch("/api/students/1", { method: "PUT", ... })
PATCH Partially update an existing resource Yes fetch("/api/students/1", { method: "PATCH", ... })
DELETE Remove a resource from the server Optional fetch("/api/students/1", { method: "DELETE" })

Common HTTP Status Codes

HTTP status codes are 3-digit numbers categorizing the outcome of a request:

  • 2xx Success (response.ok === true): 200 OK (standard success), 201 Created (new item saved), 204 No Content (success with no body to parse).
  • 4xx Client Errors (response.ok === false): 400 Bad Request (invalid inputs), 401 Unauthorized (missing login), 403 Forbidden (not allowed), 404 Not Found (resource does not exist), 429 Too Many Requests (rate limited).
  • 5xx Server Errors (response.ok === false): 500 Internal Server Error (server crash or database failure).
Example 5.1 — Standard GET Request JavaScript 
async function getPost() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts/1");
  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }
  const post = await response.json();
  console.log(post.title);
}
getPost().catch(console.error);
Example 5.2 — Making a POST Request to Submit JSON Data JavaScript 
async function createPost() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      title: "My JavaScript Project",
      body: "Learning Fetch API",
      userId: 1
    })
  });

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }

  const createdPost = await response.json();
  console.log("Created Post ID:", createdPost.id);
}
createPost().catch((err) => console.error("Could not create post:", err.message));
Expected Output
Created Post ID: 101

06 Sending JSON Data to an API

When submitting data to an API via POST, PUT, or PATCH, you must configure three critical options:

  • method: Explicitly set to "POST", "PUT", or "PATCH".
  • headers: { "Content-Type": "application/json" }: Informs the server's parser that incoming payload bytes represent JSON text.
  • body: JSON.stringify(data): Serializes your JavaScript object into JSON text. (Passing a raw object directly without JSON.stringify() causes silent failures or invalid payload errors!).
Example 6.1 — Submitting Student Records to an API JavaScript 
async function submitStudent() {
  const student = {
    name: "Aarav",
    course: "JavaScript",
    marks: 90
  };

  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(student)
  });

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  const result = await response.json();
  console.log("Server response status:", response.status);
  console.log("Server assigned ID:", result.id);
}

submitStudent().catch(console.error);
Expected Output
Server response status: 201 Server assigned ID: 101
Example 6.2 — Submitting Course Configuration Object JavaScript 
async function submitCourse() {
  const course = {
    title: "JavaScript Fundamentals",
    level: "Beginner",
    published: true
  };

  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(course)
  });

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  console.log("Status:", response.status);
}

submitCourse().catch(console.error);

08 Error Handling: Network Errors vs. HTTP Errors

This is the most critical lesson in API engineering! Beginners often write: 

try {
  const res = await fetch("/missing-page");
  // BUG: Beginners assume a 404 jump directly to catch! It DOES NOT!
} catch (err) { ... }
🚨 The Golden Fetch Rule:
fetch() only rejects when a network-level failure occurs (e.g. user is offline, DNS cannot resolve the server, or browser CORS security blocks the request). An HTTP error status (such as 404 Not Found or 500 Internal Server Error) is still a valid HTTP transmission! fetch() resolves successfully with response.ok === false. You must explicitly check if (!response.ok) throw new Error(...)!
Example 8.1 — Handling HTTP Error Statuses Explicitly JavaScript 
async function loadPostSafely(postId) {
  try {
    const response = await fetch(
      `https://jsonplaceholder.typicode.com/posts/${postId}`
    );

    // 1. Intercept HTTP error status explicitly
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const post = await response.json();
    console.log(post);
  } catch (error) {
    console.error("Could not load post:", error.message);
  }
}

// Requesting a non-existent post triggers a 404
loadPostSafely(999999);
Expected Output
Could not load post: HTTP error: 404
Example 8.2 — Handling Malformed JSON Syntax Errors JavaScript 
async function parseStudentResponse() {
  try {
    // Invalid JSON containing an illegal trailing comma
    const invalidJson = '{"name":"Aarav",}';
    const student = JSON.parse(invalidJson);
    console.log(student);
  } catch (error) {
    console.log("Invalid JSON:", error.message);
  }
}

parseStudentResponse();
Expected Output

09 Loading, Success, Empty, and Error States

Professional web applications must never leave users staring at a frozen, blank screen. A production user interface transitions cleanly across four essential states:

🔄 The Four Fundamental UI States
1. Loading
Spinner / skeleton screen while awaiting server network response.
2. Success
Populated data cards and interactive controls displayed.
3. Empty
Friendly notice when query yields 0 matching records.
4. Error
Helpful alert banner with a "Retry" button for failure recovery.
Example 9.1 — Managing the Full UI Lifecycle with try...catch...finally JavaScript 
async function loadStudentData() {
  // 1. Enter Loading State
  setLoading(true);
  setError("");

  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/users/1");
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    const student = await response.json();
    
    // 2. Enter Success State
    renderStudent(student);
  } catch (error) {
    // 3. Enter Error State
    setError("Unable to load student data. Please try again.");
    console.error(error);
  } finally {
    // 4. Guaranteed Cleanup: Always hide loading spinner!
    setLoading(false);
  }
}
Example 9.2 — Handling Empty Results Gracefully JavaScript 
function renderPosts(posts) {
  if (!Array.isArray(posts)) {
    throw new Error("Expected an array of posts.");
  }

  // Empty state check
  if (posts.length === 0) {
    console.log("No posts found.");
    return;
  }

  posts.forEach((post) => console.log(post.title));
}

renderPosts([]);
Expected Output
No posts found.

10 Dynamic DOM Rendering from API Data

Once API data is fetched and parsed, we must render it into the browser DOM. Always adhere to web security best practices:

  • Use textContent: Never use innerHTML with untrusted remote text, as malicious users could inject <script> tags (Cross-Site Scripting / XSS). textContent treats all strings strictly as harmless text.
  • Clear Old Nodes: Use container.replaceChildren() before appending new elements to avoid duplicate cards on repeated fetches.
Example 10.1 — Safely Rendering a Single Student Card JavaScript 
function renderStudentCard(student) {
  const container = document.querySelector("#student-container");
  if (!container) return;

  // Clear previous contents safely
  container.replaceChildren();

  const heading = document.createElement("h3");
  heading.textContent = student.name;

  const course = document.createElement("p");
  course.textContent = `Course: ${student.course}`;

  container.append(heading, course);
}
Example 10.2 — Rendering Multiple Posts into List Items JavaScript 
function renderPostList(posts) {
  const list = document.querySelector("#post-list");
  if (!list) return;

  list.replaceChildren();

  posts.forEach((post) => {
    const item = document.createElement("li");
    item.textContent = post.title; // Safe from HTML injection
    list.appendChild(item);
  });
}

11 Async/Await and Fetch API Together

Building scalable web applications requires separating data-fetching services from UI presentation logic. Furthermore, when an interface needs data from two independent endpoints (e.g., student profile and recent notifications), awaiting them sequentially doubles the wait time! Using Promise.all() coordinates multiple requests in parallel.

Example 11.1 — Reusable Async Service Function JavaScript 
async function getUser(userId) {
  try {
    const response = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    return await response.json();
  } catch (error) {
    console.error("User loading failed:", error.message);
    throw error; // Rethrow so caller can handle UI feedback
  }
}

getUser(1)
  .then((user) => console.log("User Name:", user.name))
  .catch(() => console.log("Please try again later."));
Expected Output
User Name: Leanne Graham
Example 11.2 — Parallel Requests with Promise.all() JavaScript 
async function loadDashboardData() {
  // 1. Dispatch both network requests simultaneously!
  const [userRes, postsRes] = await Promise.all([
    fetch("https://jsonplaceholder.typicode.com/users/1"),
    fetch("https://jsonplaceholder.typicode.com/posts?userId=1")
  ]);

  if (!userRes.ok || !postsRes.ok) {
    throw new Error("One or more requests failed.");
  }

  // 2. Parse both JSON response bodies concurrently
  const [user, posts] = await Promise.all([
    userRes.json(),
    postsRes.json()
  ]);

  return { user, posts };
}

loadDashboardData()
  .then(({ user, posts }) => {
    console.log("User:", user.name);
    console.log("Posts Count:", posts.length);
  })
  .catch(console.error);
Expected Output
User: Leanne Graham Posts Count: 10

12 Query Parameters and URL Construction

APIs frequently allow clients to filter, sort, or paginate results using query parameters appended to the URL (e.g. ?userId=1&limit=5).

Never concatenate query parameters using manual string formatting like url + "?name=" + name! Special characters, spaces, and punctuation will break the URL. Modern JavaScript provides the URL and URLSearchParams classes to construct encoded queries safely.

13 Request Cancellation and Timeouts

What happens if a user navigates away from a page, or a remote server takes 60 seconds to respond? Modern JavaScript provides the AbortController API to programmatically cancel an ongoing fetch request and enforce client-side timeouts.

Example 13.1 — Aborting a Request with a Timeout JavaScript 
async function loadWithTimeout() {
  const controller = new AbortController();
  
  // Set 5-second automatic timeout
  const timeoutId = setTimeout(() => controller.abort(), 5000);

  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/posts/1", {
      signal: controller.signal
    });

    if (!response.ok) throw new Error(`HTTP error: ${response.status}`);
    const data = await response.json();
    console.log("Data received:", data.id);
  } catch (error) {
    if (error.name === "AbortError") {
      console.log("The request was cancelled due to timeout.");
    } else {
      console.error("Request failed:", error.message);
    }
  } finally {
    clearTimeout(timeoutId);
  }
}
Example 13.2 — Deterministic Immediate Cancellation JavaScript 
async function cancelImmediately() {
  const controller = new AbortController();
  controller.abort(); // Abort signal triggered immediately

  try {
    await fetch("https://jsonplaceholder.typicode.com/posts/1", {
      signal: controller.signal
    });
  } catch (err) {
    console.log("Error Name:", err.name);
  }
}

cancelImmediately();
Expected Output
Error Name: AbortError

14 Common Fetch API & JSON Mistakes

❌ Mistake 1: Forgetting to Await response.json()

Incorrect: Treating response.json() as a synchronous method.

const res = await fetch(url);
const data = res.json(); // Returns Promise { <pending> }, NOT the object!
console.log(data.title); // undefined!

Correct: Always await the stream parser.

const data = await res.json(); // Correct!
❌ Mistake 2: Assuming HTTP Errors Reject fetch()

Incorrect: Relying on catch() to handle 404 or 500 status codes.

Correct: Always check if (!response.ok) throw new Error(...).

❌ Mistake 3: Passing Raw Object in POST Body Without JSON.stringify()

Incorrect: body: { title: "Test" } (transmits as "[object Object]").

Correct: body: JSON.stringify({ title: "Test" }).

❌ Mistake 4: Omitting the Content-Type: application/json Header

Incorrect: Sending a JSON string without headers; backend parser fails to recognize JSON.

Correct: Always supply headers: { "Content-Type": "application/json" }.

❌ Mistake 5: Rendering Untrusted Remote Data with Unsafe innerHTML

Incorrect: card.innerHTML = post.body; (vulnerable to XSS script injection).

Correct: card.textContent = post.body; (safely treats characters as text).

❌ Mistake 6: Forgetting Loading State Cleanup in finally

Incorrect: Hiding spinner only inside the successful try block (spinner freezes forever on errors!).

Correct: Place setLoading(false) inside a guaranteed finally { ... } block.

❌ Mistake 7: Attempting to Parse a 204 No Content Response as JSON

Incorrect: Calling await response.json() on a DELETE or PUT response that returns empty bytes.

if (response.status === 204) {
  const data = await response.json(); // SyntaxError: Unexpected end of JSON input!
}

Correct: Check for status 204 and return early without parsing.

if (response.status === 204) return null; // Correct!
❌ Mistake 8: Assuming API Response Is Always an Array Without Validation

Incorrect: Calling data.forEach(...) directly when an error response might return { "message": "Rate limit exceeded" }.

Correct: Guard with if (!Array.isArray(data)) throw new Error("Expected array of items");.

❌ Mistake 9: Exposing Secret API Keys or Tokens in Frontend JavaScript

Incorrect: Hardcoding private master keys like const API_KEY = "sk_live_secret123"; in public client files.

Correct: Keep secret keys securely on a backend server or proxy route. Only expose public anonymous endpoints to the browser.

❌ Mistake 10: Forgetting Browser CORS Security Restrictions

Incorrect: Assuming any random web page on the internet can be fetched directly via client-side JavaScript.

Correct: The browser blocks cross-origin requests unless the target server includes an Access-Control-Allow-Origin header. For unconfigured third-party servers, use a backend proxy.

Q1: What will this JSON.parse() snippet output? 
const str = '{"score": 95}';
const obj = JSON.parse(str);
console.log(typeof str, typeof obj);

Answer: string object

Explanation: str is primitive text, while JSON.parse() creates a genuine JavaScript object in memory.

const user = { name: "Aarav", role: undefined };
console.log(JSON.stringify(user));

Answer: {"name":"Aarav"}

Explanation: In JSON serialization, properties whose values are undefined are omitted completely.

Q3: What does response.ok return for status 201? 
// Assuming response.status === 201
console.log(response.ok);

Answer: true

Explanation: response.ok evaluates to true for all HTTP status codes in the range 200–299.

Q4: What will this catch block output on a 404 response? 
try {
  const res = await fetch("https://example.com/missing-404");
  console.log("Stage 1");
} catch (e) {
  console.log("Stage 2");
}

Answer: Stage 1

Explanation: HTTP 404 does not cause fetch() to reject. The promise resolves normally with res.status === 404.

const p = new URLSearchParams({ topic: "APIs & JSON" });

Exercise 7: Timeout Fetch with AbortController

Task: Implement fetchWithTimeout(url, ms) using AbortController.

async function fetchWithTimeout(url, ms = 3000) {
  const controller = new AbortController();
  const id = setTimeout(() => controller.abort(), ms);
  try {
    const res = await fetch(url, { signal: controller.signal });
    if (!res.ok) throw new Error(`HTTP error: ${res.status}`);
    return await res.json();
  } finally {
    clearTimeout(id);
  }
}

Part C: 6 Debugging Challenges

Bug 1: Missing await on response.json()

Broken Code: const data = response.json(); console.log(data.title);

Fix: Add await: const data = await response.json();.

Bug 2: Sending un-stringified object in body

Broken Code: body: { name: "Aarav" }

Fix: Wrap with JSON.stringify(): body: JSON.stringify({ name: "Aarav" }).

Bug 3: Assuming fetch rejects on 500 status

Broken Code: Catch block doesn't run when server returns 500.

Fix: Add if (!response.ok) throw new Error(...) after await fetch().

Bug 4: XSS Vulnerability with innerHTML

Broken Code: element.innerHTML = apiText;

Fix: Use element.textContent = apiText;.

Bug 5: Single quotes in JSON string

Broken Code: JSON.parse("{'id': 1}") throws SyntaxError.

Fix: Use double quotes: JSON.parse('{"id": 1}').
