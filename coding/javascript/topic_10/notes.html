JavaScript Foundations • Topic 10

JavaScript Objects

Learn how objects model real-world entities using key-value properties and methods. Master dot and bracket access, nested structures, the this keyword, destructuring, spread cloning, and memory references.

1 What Is an Object?

If you want to store a student's name, age, course, and marks, should you keep these details in four unrelated variables scattered across your program?

In Topic 9, we saw that arrays are ordered lists of items. However, an array like ["Aarav", 20, "JavaScript", 88] relies on numbers (indexes 0, 1, 2, 3) to remember what each value means. If someone reads index 1, they have to guess whether 20 is an age, roll number, or score!

An Object is an unordered collection of related data represented as key-value pairs. Instead of numeric indexes, each piece of data is stored under an explanatory, labeled name called a property key.

💡 Real-World Analogy: An Official Identity Card
Imagine a student ID card or passport. It does not just show random numbers; each field has a clear label on the left (Key: Name, Age, Course) and the corresponding information on the right (Value: "Aarav", 20, "JavaScript").
◆ Conceptual Representation of an Object
Object: student Type: { Key: Value }
name : "Aarav"
age : 20
course : "JavaScript"
isEnrolled : true

Example 1: Separate Variables vs. A Unified Object

Unrelated Bindings vs. An Organized Object JS 
// Clunky: 3 disconnected variables
const studentName = "Aarav";
const studentAge = 20;
const studentCourse = "JavaScript";

// Clean: A unified object holding all related student data
const student = {
  name: "Aarav",
  age: 20,
  course: "JavaScript"
};

console.log(student);
Expected Terminal Output
{ name: 'Aarav', age: 20, course: 'JavaScript' }

Step-by-Step Trace: Instead of managing three separate variable bindings that have no formal connection in JavaScript memory, the student object groups them into a single descriptive record.

Example 2: An E-Commerce Product Object

Modeling a Store Item with Key-Value Pairs JS 
const product = {
  name: "Wireless Headphones",
  price: 1499,
  inStock: true
};

console.log("Product:", product.name);
console.log("Price (INR):", product.price);
console.log("Available:", product.inStock);
Expected Terminal Output
Product: Wireless Headphones Price (INR): 1499 Available: true

Step-by-Step Trace: We access specific properties using their named keys (product.name, product.price). In contrast to arrays where position determines identity, object properties are referenced directly by name.

2 Creating Objects with Literal Syntax

The most common, expressive, and idiomatic way to create an object in JavaScript is using object literal syntax with curly braces {}.

  • Curly braces: {} denotes the start and end of the object.
  • Key-value separator: A colon : separates the property name from its value.
  • Property separator: A comma , separates each property pair. (A trailing comma after the last property is valid and encouraged in modern JavaScript).
  • Values of any type: An object property can hold strings, numbers, booleans, arrays, functions, or even other objects!

Example 1: Basic Student Object Literal

Declaring a Student Profile JS 
const student = {
  name: "Priya",
  age: 19,
  course: "Computer Science"
};

console.log(student);
Expected Terminal Output
{ name: 'Priya', age: 19, course: 'Computer Science' }

Example 2: Objects Containing Diverse Value Types

Strings, Numbers, Booleans, Arrays, and Nested Objects JS 
const user = {
  name: "Rohan",
  isStudent: true,
  skills: ["Python", "JavaScript"],
  address: {
    city: "Lucknow",
    country: "India"
  }
};

console.log("User Name:", user.name);
console.log("First Skill:", user.skills[0]);
console.log("City:", user.address.city);
Expected Terminal Output
User Name: Rohan First Skill: Python City: Lucknow

Step-by-Step Trace: user.skills points to an Array, so we index into it with [0]. user.address points to a child Object, so we chain another dot to access .city.

◆ Structural Hierarchy of the Mixed User Object
user (Object)
├── name: "Rohan"
├── isStudent: true
├── skills: [ "Python", "JavaScript" ]
└── address: (Child Object)
    ├── city: "Lucknow"
    └── country: "India"

3 Accessing Properties: Dot vs. Bracket Notation

JavaScript provides two ways to read property values from an object:

1. Dot Notation (object.property)

The standard, cleanest, and most concise syntax. Use it when the property key is a valid JavaScript identifier (no spaces, doesn't start with a number, no hyphens).

2. Bracket Notation (object["property"])

Required when the property key has spaces or special characters, starts with a digit, or is evaluated dynamically from a variable.

Example 1: Clean Property Access with Dot Notation

Reading Valid Identifiers JS 
const student = {
  name: "Aarav",
  age: 20
};

console.log(student.name);
console.log(student.age);
Expected Terminal Output
Aarav 20

Example 2: Dynamic Keys, Keys with Spaces, and Missing Keys

Bracket Notation with Variables & Multi-Word Keys JS 
const student = {
  name: "Priya",
  age: 19,
  "favorite subject": "JavaScript"
};

const key = "age";

// 1. Reading through a variable key
console.log(student[key]);

// 2. Reading a multi-word key with spaces
console.log(student["favorite subject"]);

// 3. Reading a nonexistent property
console.log(student.grade);
Expected Terminal Output
19 JavaScript undefined

Key Takeaway on Missing Properties: Notice that accessing student.grade does not throw an error; JavaScript simply returns undefined.

⚠ Critical Beginner Trap: Dot Notation with Variables
Writing student.key looks for a literal property called "key" on the object. If you want to use the string stored inside the variable key, you must use brackets: student[key].

4 Adding, Updating, and Deleting Properties

Objects are mutable collections. You can add new properties, update existing values, and remove properties after creation.

Example 1: Adding and Updating Properties

Dynamic Modification JS 
const student = {
  name: "Aarav",
  age: 20
};

// Adding a new property
student.course = "JavaScript";

// Updating an existing property
student.age = 21;

console.log(student);
Expected Terminal Output
{ name: 'Aarav', age: 21, course: 'JavaScript' }
◆ Before & After Property Modification
Initial Object
name:"Aarav"
age:20
→
Updated Object
name:"Aarav"
age:21
course:"JavaScript"

Example 2: Deleting Properties and Checking with the in Operator

Using delete and the in Operator JS 
const product = {
  name: "Keyboard",
  price: 999,
  inStock: true
};

// Completely removes the property and its key from the object
delete product.inStock;

console.log(product);
console.log("price in product?", "price" in product);
console.log("inStock in product?", "inStock" in product);
Expected Terminal Output
{ name: 'Keyboard', price: 999 } price in product? true inStock in product? false

Delete vs. Assigning undefined: Setting product.inStock = undefined leaves the key inStock present on the object with value undefined. Using delete product.inStock removes the key entirely.

5 Object Methods: Giving Objects Behavior

An object represents not only state (data properties) but also behavior (actions). When a function is stored as a property of an object, it is called a Method.

Example 1: A Greeting Method

Traditional Function Expression as a Method JS 
const student = {
  name: "Aarav",
  greet: function () {
    console.log("Hello, " + this.name + "!");
  }
};

student.greet();
Expected Terminal Output
Hello, Aarav!

Example 2: Concise ES6 Method Syntax and Returning Values

Modern Calculator Object with Shorthand Methods JS 
const calculator = {
  // Concise method definition: no 'function' keyword or colon needed!
  add(a, b) {
    return a + b;
  },

  multiply(a, b) {
    return a * b;
  }
};

console.log("5 + 3 =", calculator.add(5, 3));
console.log("5 * 3 =", calculator.multiply(5, 3));
Expected Terminal Output
5 + 3 = 8 5 * 3 = 15

Why Methods Matter: Methods allow related behavior to live right alongside related data, keeping your codebase organized and intuitive.

6 Understanding this in Object Methods

Inside an object's method, the keyword this refers to the object that called the method (known as the method's receiver).

When you run student.greet(), JavaScript looks to the left of the dot. Because student called the method, this inside greet() points to student.

Example 1: Accessing Object Properties with this

Self-Referencing with this JS 
const person = {
  name: "Priya",
  city: "Bengaluru",

  introduce() {
    console.log(`My name is ${this.name} from ${this.city}.`);
  }
};

person.introduce();
Expected Terminal Output
My name is Priya from Bengaluru.

Example 2: Normal Methods vs. Arrow Functions (Why Arrow Methods Fail)

Comparing Normal Methods and Arrow Functions JS 
const person = {
  name: "Aarav",

  // 1. Normal method: 'this' dynamically binds to person
  normalMethod() {
    return this.name;
  },

  // 2. Arrow function: does NOT have its own 'this'!
  // It captures 'this' lexically from the surrounding scope.
  arrowMethod: () => this.name
};

console.log("Normal method:", person.normalMethod());
console.log("Arrow method:", person.arrowMethod());
Expected Terminal Output (Node.js / Global Scope)
Normal method: Aarav Arrow method: undefined
🚨 Best Practice Rule for Object Methods
Never write top-level object methods as arrow functions. Always use standard concise method syntax (methodName() { ... }) so this correctly binds to the calling object.

7 Property Shorthand and Computed Property Names

Modern JavaScript introduces clean shortcuts to avoid redundant syntax when creating objects.

Example 1: Property Shorthand

When the property key name matches an existing variable name, you don't need to write name: name; just write name.

Concise Object Literal Shorthand JS 
const name = "Priya";
const age = 20;

// Shorthand syntax automatically assigns variable name as key
const student = {
  name,
  age
};

console.log(student);
Expected Terminal Output
{ name: 'Priya', age: 20 }

Example 2: Computed Property Names

Using square brackets [expression] inside an object literal allows property names to be computed dynamically at creation time.

Dynamic Keys in Object Literals JS 
const propertyName = "score";

const result = {
  [propertyName]: 95,
  ["exam_" + 1]: "Passed"
};

console.log("Score:", result.score);
console.log("Exam 1:", result.exam_1);
Expected Terminal Output
Score: 95 Exam 1: Passed

8 Nested Objects & Optional Chaining

In real applications, data is often hierarchical. Objects can be nested inside other objects to model complex relationships.

Example 1: Reading Chained Nested Properties

Accessing Child Objects JS 
const student = {
  name: "Aarav",
  address: {
    city: "Lucknow",
    state: "Uttar Pradesh"
  }
};

console.log("City:", student.address.city);
console.log("State:", student.address.state);
Expected Terminal Output
City: Lucknow State: Uttar Pradesh

Example 2: Updating Nested Data & Safe Optional Chaining (?.)

Mutating Nested Properties and Preventing Crash on Missing Keys JS 
const user = {
  name: "Priya",
  profile: {
    course: "JavaScript",
    level: "Beginner"
  }
};

// 1. Updating a nested property
user.profile.level = "Intermediate";
console.log("Updated Level:", user.profile.level);

// 2. Optional chaining avoids runtime TypeError if property is missing
const twitterHandle = user.social?.twitter;
console.log("Twitter:", twitterHandle);
Expected Terminal Output
Updated Level: Intermediate Twitter: undefined

Why Optional Chaining Matters: Without ?., calling user.social.twitter crashes your entire program with: TypeError: Cannot read properties of undefined. Optional chaining safely evaluates to undefined instead of throwing!

9 Looping Through Objects

Because objects are not indexed by sequential integers, traditional for loops do not work directly. JavaScript provides four primary techniques to inspect and iterate over object properties:

Iteration Technique What It Returns Ideal Use Case
for...in Property keys (strings) Quick property scanning
Object.keys(obj) Array of all property keys Counting properties or iterating keys with array methods
Object.values(obj) Array of all property values Summing, filtering, or checking values directly
Object.entries(obj) Array of [key, value] pairs Best for looping through both key and value simultaneously

Example 1: The for...in Loop

Scanning Keys and Values JS 
const student = {
  name: "Aarav",
  age: 20,
  course: "JavaScript"
};

for (const key in student) {
  console.log(`${key}: ${student[key]}`);
}
Expected Terminal Output
name: Aarav age: 20 course: JavaScript

Example 2: Modern Object Static Utilities (keys, values, entries)

Working with Object.entries and Array Utilities JS 
const product = {
  name: "Mouse",
  price: 799,
  inStock: true
};

console.log("Keys:", Object.keys(product));
console.log("Values:", Object.values(product));

// Destructuring key and value in for...of loop
for (const [k, v] of Object.entries(product)) {
  console.log(`Entry -> ${k} = ${v}`);
}
Expected Terminal Output
Keys: [ 'name', 'price', 'inStock' ] Values: [ 'Mouse', 799, true ] Entry -> name = Mouse Entry -> price = 799 Entry -> inStock = true

10 Objects and Arrays Working Together

In modern web development, almost all datasets (from REST APIs, databases, or local state) are organized as Arrays of Objects. The array provides the ordered list, while each object inside represents an individual record.

Example 1: A Roster of Student Objects

Accessing Data in an Array of Objects JS 
const students = [
  { name: "Aarav", marks: 82 },
  { name: "Priya", marks: 95 },
  { name: "Rohan", marks: 74 }
];

// Accessing first student's name
console.log("First student:", students[0].name);

// Accessing second student's marks
console.log("Second student marks:", students[1].marks);
Expected Terminal Output
First student: Aarav Second student marks: 95

Example 2: Combining Array Methods with Objects

Filtering and Mapping Object Collections JS 
const students = [
  { name: "Aarav", marks: 82 },
  { name: "Priya", marks: 95 },
  { name: "Rohan", marks: 74 }
];

// Find high achievers
const toppers = students.filter(student => student.marks >= 90);
console.log("Topper:", toppers);

// Extract an array of student names using map()
const namesList = students.map(student => student.name);
console.log("Names:", namesList);
Expected Terminal Output
Topper: [ { name: 'Priya', marks: 95 } ] Names: [ 'Aarav', 'Priya', 'Rohan' ]

11 Object Destructuring

Destructuring allows you to unpack properties from an object into distinct standalone variables using a clean, symmetrical syntax.

Example 1: Basic Property Destructuring

Unpacking Properties by Name JS 
const student = {
  name: "Aarav",
  age: 20,
  course: "JavaScript"
};

// Extracts 'name' and 'age' directly into local variables
const { name, age } = student;

console.log("Name:", name);
console.log("Age:", age);
Expected Terminal Output
Name: Aarav Age: 20

Example 2: Renaming Variables & Providing Fallback Default Values

Custom Aliasing and Missing Property Defaults JS 
const product = {
  name: "Headphones",
  price: 1499
};

// Renames 'name' to 'productName', extracts 'price', and sets default 'category'
const {
  name: productName,
  price,
  category = "Electronics"
} = product;

console.log("Product Title:", productName);
console.log("Price:", price);
console.log("Category:", category);
Expected Terminal Output
Product Title: Headphones Price: 1499 Category: Electronics

12 Object Spread and Shallow Copies

The object spread operator (...) copies all own enumerable properties from one object into a new object literal. This enables non-mutating updates and object merging.

Example 1: Immutably Updating an Object

Cloning and Overriding Top-Level Properties JS 
const original = {
  name: "Priya",
  age: 19
};

// Creates a brand new object, copies 'original', then overrides 'age'
const updated = {
  ...original,
  age: 20
};

console.log("Original:", original);
console.log("Updated:", updated);
Expected Terminal Output
Original: { name: 'Priya', age: 19 } Updated: { name: 'Priya', age: 20 }

Notice that original.age remains safely untouched at 19!

Example 2: Merging Objects (Later Properties Win)

Merging Defaults and User Overrides JS 
const defaults = {
  theme: "light",
  notifications: true,
  fontSize: 14
};

const userPreferences = {
  theme: "dark",
  fontSize: 16
};

const finalSettings = {
  ...defaults,
  ...userPreferences
};

console.log(finalSettings);
Expected Terminal Output
{ theme: 'dark', notifications: true, fontSize: 16 }
⚠ Critical Notice: Spread is Shallow!
The spread operator only copies one level deep. If your object contains nested child objects or arrays, the spread operator copies only their memory references. Modifying a nested child in the copy will unexpectedly alter the original object!

13 Object References and Equality

In JavaScript, primitive types (numbers, strings, booleans) are copied by value. Objects, arrays, and functions are reference types.

When you assign an object to a variable, you are not copying the object data; you are merely copying the memory address pointer to that object in the heap.

◆ Memory Architecture: Reference vs Separate Objects
Call Stack (Variables)
let first → #0x9A40
let second = first → #0x9A40
Heap Memory (Actual Objects)
Address #0x9A40
{ name: "Aarav", score: 95 }
Both variables point here!

Example 1: The Shared Reference Pitfall

Mutating Through an Alias Affects Both Bindings JS 
const first = {
  name: "Aarav",
  score: 80
};

// 'second' is NOT a copy; it's another reference to the same memory slot!
const second = first;

second.score = 95;

console.log("first.score:", first.score);
console.log("second.score:", second.score);
Expected Terminal Output
first.score: 95 second.score: 95

Example 2: Comparing Separate Objects with ===

Comparing Identity vs Content JS 
const objA = { name: "Priya" };
const objB = { name: "Priya" };
const objC = objA;

// false: Different memory addresses, even though properties match
console.log("objA === objB:", objA === objB);

// true: Both variables point to the exact same reference
console.log("objA === objC:", objA === objC);
Expected Terminal Output
objA === objB: false objA === objC: true

14 Common Object Mistakes and Debugging

Here are 10 common mistakes beginners make when working with JavaScript objects, paired with clean corrections:

✕ 1. Using Dot Notation with a Variable Key
const user = { name: "Aarav" };
const key = "name";
console.log(user.key); // undefined! Searches for literal property 'key'
✓ Correct Fix: Use bracket notation: console.log(user[key]); // "Aarav"
✕ 2. Crash When Accessing Nested Property on Undefined
const student = { name: "Priya" };
console.log(student.address.city); // TypeError: Cannot read properties of undefined
✓ Correct Fix: Use optional chaining: console.log(student.address?.city); // undefined
✕ 3. Writing Methods as Arrow Functions
const user = {
  name: "Rohan",
  sayHi: () => "Hi " + this.name // 'this' is undefined or global, not user!
};
✓ Correct Fix: Use standard concise method syntax: sayHi() { return "Hi " + this.name; }
✕ 4. Forgetting Parentheses When Calling a Method
const calc = { pi() { return 3.1415; } };
console.log(calc.pi); // Prints [Function: pi] instead of 3.1415!
✓ Correct Fix: Invoke with parentheses: console.log(calc.pi()); // 3.1415
✕ 5. Thinking 'const' Makes Object Properties Read-Only
const student = { name: "Aarav" };
student.name = "Rohan"; // Allowed! 'const' only prevents reassigning the 'student' identifier.
✓ Correct Fix: If you need true runtime immutability, call Object.freeze(student);
✕ 6. Assuming '=' Creates an Independent Copy
const a = { x: 10 };
const b = a;
b.x = 99; // Modifies a.x as well!
✓ Correct Fix: Create a shallow copy with spread: const b = { ...a };
✕ 7. Assuming Spread Syntax Clones Nested Objects
const orig = { info: { score: 50 } };
const copy = { ...orig };
copy.info.score = 100; // Mutates orig.info.score as well!
✓ Correct Fix: Spread nested levels explicitly: const copy = { ...orig, info: { ...orig.info } };
✕ 8. Comparing Content with === Instead of Properties
console.log({ id: 1 } === { id: 1 }); // false! Evaluates reference memory addresses
✓ Correct Fix: Compare primitive fields: a.id === b.id
✕ 9. Setting a Property to undefined Instead of Deleting
user.role = undefined;
console.log("role" in user); // true! The key still exists
✓ Correct Fix: Use the delete operator: delete user.role;
✕ 10. Iterating Objects with for...of Directly
const car = { brand: "Tata", year: 2024 };
for (const x of car) { } // TypeError: car is not iterable
✓ Correct Fix: Use Object.entries(car): for (const [key, val] of Object.entries(car)) { ... }

Part A: Output-Prediction Challenges

Analyze each snippet carefully before revealing the solution:

1. Missing property access 
const car = { brand: "Tesla", model: "Model 3" };
console.log(car.year);

Predicted Output: undefined

Explanation: Accessing a property that does not exist on an object evaluates to undefined without throwing an error.

2. Variable key with dot notation 
const user = { name: "Aarav", role: "Admin" };
const prop = "name";
console.log(user.prop);

Predicted Output: undefined

Explanation: user.prop looks for a literal key named "prop", not the variable's value "name". To use the variable, use bracket notation: user[prop].

3. Object spread merge precedence 
const a = { x: 1, y: 2 };
const b = { y: 99, z: 3 };
const c = { ...a, ...b };
console.log(c.y);

Predicted Output: 99

Explanation: When spreading objects, later properties overwrite earlier ones with the same key name.

4. Destructuring with default values 
const item = { title: "Book", price: 299 };
const { title, discount = 10 } = item;
console.log(discount);

Predicted Output: 10

Explanation: Because discount is absent from item, destructuring applies the fallback default value 10.

5. Object reference equality 
const p1 = { x: 10 };
const p2 = { x: 10 };
console.log(p1 === p2);

Predicted Output: false

Explanation: Strict equality === on objects compares memory addresses, not property values. Because p1 and p2 are separate objects in memory, the comparison returns false.

6. delete operator return and check 
const obj = { a: 1, b: 2 };
delete obj.a;
console.log("a" in obj);

Predicted Output: false

Explanation: The delete operator completely deletes the property key, so "a" in obj returns false.

7. Object method 'this' invocation 
const counter = {
  count: 0,
  inc() { this.count++; return this.count; }
};
console.log(counter.inc());

Predicted Output: 1

Explanation: this points to counter, so this.count++ increments 0 to 1 and returns it.

8. Object.keys length check 
const phone = { brand: "Samsung", model: "S24", price: 79999 };
console.log(Object.keys(phone).length);

Predicted Output: 3

Explanation: Object.keys() returns an array of keys ['brand', 'model', 'price'] whose length is 3.

Part C: Debugging Challenges

Challenge 1: Fix Lost Method Context

Buggy Code:

const user = {
  name: "Priya",
  getName() { return this.name; }
};
const fn = user.getName;
console.log(fn()); // undefined

Explanation: Storing user.getName in variable fn detaches it from the user object receiver. When invoked as fn(), this is lost!

Fix: Bind the method: const fn = user.getName.bind(user); or call it directly as user.getName().

Challenge 2: Fix Nested Mutation Bug

Buggy Code:

const config1 = { app: "CodeVerse", flags: { beta: true } };
const config2 = { ...config1 };
config2.flags.beta = false;
console.log(config1.flags.beta); // false! Unintended mutation

Explanation: Object spread is shallow. config1.flags and config2.flags point to the same nested object in memory.

Fix: Clone nested levels: const config2 = { ...config1, flags: { ...config1.flags, beta: false } };

Challenge 3: Fix Overwriting in Property Shorthand

Buggy Code:

const score = 80;
const report = { score: 100, score };
console.log(report.score); // 80

Explanation: The duplicate key score defined second overwrote the earlier score: 100.

Fix: Ensure keys are intentional or alias variables properly.

Challenge 4: Fix Optional Chaining Function Call

Buggy Code:

const service = {};
service.cleanup(); // TypeError: service.cleanup is not a function

Explanation: Calling a missing method throws a TypeError.

Fix: Use optional call syntax: service.cleanup?.();
