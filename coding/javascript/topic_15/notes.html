Events & Event Handling

Transform static web pages into responsive, living applications. Master event-driven programming, register handlers using addEventListener(), capture pointer and keyboard interactions, process forms safely with preventDefault(), inspect the event object, leverage event delegation, and navigate bubbling and capturing with absolute precision.

1 What Are Events?

Have you ever wondered: How does a website know the instant you click a “Like” button, type your password into an input field, press Enter to post a comment, or move your mouse over a dropdown menu?

In modern web browsers, an event represents a signal that something notable occurred. The browser is continually watching the document. Whenever a user moves the mouse, strikes a key, taps a touchscreen, submits a form, or resizes the viewport—or whenever the browser finishes loading a stylesheet or encounters a network error—an internal notification called an event is dispatched.

Event handling is the art and engineering of writing JavaScript functions that stand on standby, listen for specific events on specific elements, and execute meaningful logic whenever those events fire. Without event handling, the web would be a static document viewer like a printed paper sheet. With event handling, web pages become fully interactive software applications.

The Five-Stage Event Lifecycle Architecture
1. User Action
User clicks button or presses Enter
→
2. Browser Event
Browser packages a “click” Event object
→
3. Event Listener
Monitors element for matching event type
→
4. Callback Function
JavaScript runs custom handler logic
→
5. Updated UI
DOM updates, state changes, feedback

Let’s look at two foundational examples showing how event listeners are wired up and how they bridge the gap between user gestures and code execution.

Example 1.1: A Simple Click Event Listener HTML + JS 
<!-- HTML markup -->
<button id="hello-button">Say Hello</button>

<script>
  // 1. Select the button element from the DOM
  const helloBtn = document.querySelector("#hello-button");

  // 2. Attach an event listener for the "click" event type
  helloBtn.addEventListener("click", () => {
    console.log("Hello, CodeVerse!");
  });
</script>
Expected Browser Console Output (After Clicking Button)
Hello, CodeVerse!

Line-by-line step analysis:

  • Line 2: Renders a button with the unique identifier id="hello-button".
  • Line 6: document.querySelector("#hello-button") queries the DOM tree and returns a reference to that specific button node.
  • Line 9: We invoke addEventListener() on the button reference, supplying two essential arguments: the event type string "click" and an arrow function callback () => { ... }.
  • Line 10: When the user clicks the button, the browser immediately activates the callback function, outputting Hello, CodeVerse! into the developer console.
Example 1.2: Updating the DOM in Response to an Event HTML + JS 
<!-- Initial HTML markup -->
<button id="welcome-button">Welcome</button>
<p id="message">Waiting for your action...</p>

<script>
  const button = document.querySelector("#welcome-button");
  const message = document.querySelector("#message");

  button.addEventListener("click", () => {
    message.textContent = "Welcome to CodeVerse!";
  });
</script>
• Initial Page State (Before Click)

Waiting for your action...

• Updated Page State (After Click)

Welcome to CodeVerse!

Notice how the webpage feels “awake”! The paragraph text did not change on load; it changed in direct response to the user gesture. That is the fundamental premise of event-driven programming.

2 addEventListener() Explained

The standard, modern, and production-grade method for listening to events in JavaScript is EventTarget.addEventListener(). Almost all DOM nodes (such as elements, document, and window) implement the EventTarget interface.

General Method Signature SYNTAX 
target.addEventListener(type, listener [, optionsOrUseCapture]);
Argument 1: type (string)

A case-sensitive string specifying the event name to observe, such as "click", "keydown", "input", or "submit".

Argument 2: listener (function)

The callback function to run when the event occurs. It automatically receives the Event object as its first parameter.

Argument 3: options (optional object/bool)

Optional configuration object specifying characteristics like { once: true }, { capture: true }, or { passive: true }.

⚠ CRITICAL RULE: Pass the Function, Do NOT Call It Immediately!

A common beginner mistake is writing button.addEventListener("click", saveChanges()) with parentheses. Adding parentheses executes the function immediately when the script loads, and passes the function's return value (often undefined) to the listener! You must pass the function reference without parentheses: button.addEventListener("click", saveChanges) or pass an anonymous arrow function () => saveChanges().

Example 2.1: Registering a Named Function Handler JavaScript 
const saveBtn = document.querySelector("#save-button");

// Define a dedicated, reusable event handler function
function handleSaveClick(event) {
  console.log("Save button clicked");
  console.log("Event timestamp:", event.timeStamp);
}

// Pass the function reference (WITHOUT parentheses!)
saveBtn.addEventListener("click", handleSaveClick);
Expected Console Output
Save button clicked Event timestamp: 1428.5999999940395
Example 2.2: Registering Multiple Listeners on the Same Element HTML + JS 
<button id="action-button">Perform Action</button>

<script>
  const actionBtn = document.querySelector("#action-button");

  // First event listener
  actionBtn.addEventListener("click", () => {
    console.log("Action started");
  });

  // Second event listener on the exact same button
  actionBtn.addEventListener("click", () => {
    console.log("Action completed");
  });
</script>
Expected Console Output (In Order of Registration)
Action started Action completed

Why addEventListener() beats legacy inline HTML attributes:

  • Supports Multiple Listeners: Legacy property assignments like button.onclick = f1; button.onclick = f2; overwrite earlier handlers, so only f2 runs. addEventListener() allows dozens of independent modules to listen to the same element without collisions.
  • Clean Separation of Concerns: Keeps HTML files purely structural and avoids mixing inline scripting (e.g. onclick="doSomething()") with markup.
  • Fine-Grained Propagation Control: Allows advanced configuration options like capturing phase handling, one-time execution ({ once: true }), and passive performance flags.

3 Click and Double-Click Events

The most common user interaction on the web is the click. JavaScript provides two primary click events:

  • click: Dispatched when a primary pointing device button (typically the left mouse button) is pressed and released on a single element, or when a focused button is triggered with the Space or Enter key.
  • dblclick: Dispatched when an element is clicked twice rapidly in succession within a small threshold of time and physical screen distance.
ℹ Crucial UX Insight: The Double-Click Dilemma

When a user performs a double-click, the browser fires two separate click events before it fires the dblclick event! Therefore, if you attach both single-click and double-click listeners to the same element, the single-click listener will run twice before the double-click listener triggers. In modern responsive web design, reserve dblclick for desktop-specific shortcuts (such as renaming a file or zooming an image), and never make primary workflow actions dependent on double-clicks since touchscreens lack native double-click gestures.

Example 3.1: Building an Interactive Click Counter HTML + JS 
<button id="counter-button">Click Me</button>
<p id="counter">Clicks: 0</p>

<script>
  let count = 0;
  const counterBtn = document.querySelector("#counter-button");
  const counterDisplay = document.querySelector("#counter");

  counterBtn.addEventListener("click", () => {
    count++;
    counterDisplay.textContent = `Clicks: ${count}`;
  });
</script>
Example 3.2: Responding to a Double-Click Event HTML + JS 
<p id="double-message">Double-click this message.</p>

<script>
  const msgEl = document.querySelector("#double-message");

  msgEl.addEventListener("dblclick", () => {
    msgEl.textContent = "You double-clicked successfully!";
    msgEl.style.color = "#059669";
    msgEl.style.fontWeight = "bold";
  });
</script>

4 Mouse Events

JavaScript provides rich pointer event capabilities to track cursor boundaries and coordinate movements. Understanding the subtle distinctions between boundary-based and bubbling mouse events is essential for creating polished user experiences.

Event Name Bubbles? Behavior & Trigger Condition
mouseenter No Fires once when the pointer moves inside the element boundaries. Does NOT fire when moving between internal descendant children.
mouseleave No Fires once when the pointer leaves the element boundaries and all its descendants.
mouseover Yes Fires when the pointer moves onto the element OR onto any of its child descendants. Bubbles up the DOM.
mouseout Yes Fires when the pointer moves off the element OR off any child element. Bubbles up the DOM.
mousemove Yes Fires continuously whenever the pointer shifts position by even a single pixel over the element.

Recommendation: For hover effects like card highlights, tooltips, and dropdown panels, prefer mouseenter and mouseleave over mouseover and mouseout because they prevent unwanted jitter caused by bubbling between child elements.

Example 4.1: Highlighting a Course Card on Hover HTML + JS 
<div id="course-card" class="card">Hover over this course card</div>

<script>
  const card = document.querySelector("#course-card");

  // Add class when cursor enters
  card.addEventListener("mouseenter", () => {
    card.classList.add("highlight");
  });

  // Remove class when cursor exits
  card.addEventListener("mouseleave", () => {
    card.classList.remove("highlight");
  });
</script>
Example 4.2: Tracking Pointer Movement and Coordinates HTML + JS 
<div id="tracking-area">Move your mouse here</div>
<p id="coordinates">X: —, Y: —</p>

<script>
  const area = document.querySelector("#tracking-area");
  const coordinates = document.querySelector("#coordinates");

  area.addEventListener("mousemove", (event) => {
    // offsetX and offsetY are relative to the padding edge of the target node
    coordinates.textContent = `X: ${event.offsetX}, Y: ${event.offsetY}`;
  });
</script>
Expected Coordinate Display (While Moving Pointer)

5 Keyboard Events

Keyboard interactions are vital for application usability, rapid power-user workflows, and accessibility for individuals who navigate without a mouse.

  • keydown: Fires immediately when a key is first pressed down. Repeats automatically if the key remains held down. This is the modern, recommended event for capturing key shortcuts (like Enter or Escape).
  • keyup: Fires once when the user releases a physical key.
  • keypress: OBSOLETE AND DEPRECATED! Do NOT use keypress in modern code. It has been removed from official web specifications due to inconsistent cross-browser support and international layout issues.

The event object provides two key properties:

  • event.key: Returns the readable string representation of the character generated, taking modifier keys (Shift, CapsLock) into account (e.g. "Enter", "Escape", "a", "A", "ArrowUp"). Always prefer event.key!
  • event.code: Returns the physical position of the key on the keyboard hardware (e.g. "KeyA", "Digit1"), regardless of keyboard layout (QWERTY, AZERTY, or Dvorak).
Example 5.1: Detecting Any Pressed Key HTML + JS 
<input id="keyboard-input" placeholder="Press any key">
<p id="key-result">Key: —</p>

<script>
  const input = document.querySelector("#keyboard-input");
  const result = document.querySelector("#key-result");

  input.addEventListener("keydown", (event) => {
    result.textContent = `Key: ${event.key} (Code: ${event.code})`;
  });
</script>
Example 5.2: Handling Enter Key for Instant Submission HTML + JS 
<input id="task-input" placeholder="Type a task and press Enter">
<p id="task-result"></p>

<script>
  const taskInput = document.querySelector("#task-input");
  const taskResult = document.querySelector("#task-result");

  taskInput.addEventListener("keydown", (event) => {
    if (event.key === "Enter") {
      const task = taskInput.value.trim();
      taskResult.textContent = task || "Please enter a task.";
    }
  });
</script>

6 Input, Change, and Submit Events

HTML forms and text controls are the primary bridge for receiving user-submitted data. Understanding the difference between input, change, and submit is crucial for building smooth forms:

  • input: Fires synchronously on every single keystroke, paste, cut, or drag-and-drop modification. Perfect for live character counters, real-time search filtering, and instant validation indicators.
  • change: Fires only when the value change is committed. For text inputs, this occurs when the input loses focus (the user clicks outside or presses Tab). For checkboxes, radio buttons, and select dropdowns, it fires immediately upon selection.
  • submit: Fires when a <form> element is submitted. Always attach this listener to the <form> itself, NOT the submit button! This guarantees that both clicking the submit button AND pressing Enter inside any input field will be cleanly captured.
Example 6.1: Live Real-Time Character Counter HTML + JS 
<textarea id="bio" maxlength="100"></textarea>
<p id="character-count">Characters: 0 / 100</p>

<script>
  const bio = document.querySelector("#bio");
  const count = document.querySelector("#character-count");

  // Fires instantly on every keystroke or text modification
  bio.addEventListener("input", () => {
    count.textContent = `Characters: ${bio.value.length} / 100`;
  });
</script>
Example 6.2: Handling Form Submission with Validation HTML + JS 
<form id="login-form">
  <label>
    Username
    <input id="username" required>
  </label>
  <button type="submit">Continue</button>
</form>

<p id="form-message"></p>

<script>
  const form = document.querySelector("#login-form");
  const username = document.querySelector("#username");
  const message = document.querySelector("#form-message");

  form.addEventListener("submit", (event) => {
    // 1. Halt default browser page reload
    event.preventDefault();

    // 2. Sanitize and validate input value
    const name = username.value.trim();
    message.textContent = name
      ? `Welcome, ${name}!`
      : "Please enter your username.";
  });
</script>
💡 HTML5 Native Form Validation Notice

Notice the required attribute on the #username input. If the user clicks Continue while the input is empty, the browser's native constraint validation system blocks the submit event from ever firing in JavaScript and shows a built-in tooltip prompt (“Please fill in this field”). Only when native requirements pass will our JavaScript submit callback execute.

7 The Event Object

Whenever an event fires, the browser automatically constructs an Event (or a specialized subclass like MouseEvent, KeyboardEvent, or SubmitEvent) and supplies it as the first argument to the callback function.

By convention, developers name this parameter event or e. It contains complete metadata describing what happened, where it happened, and which buttons or keys were pressed.

Property / Method Type Description & Purpose
event.type string The name of the event (e.g. "click", "keydown").
event.target Element The exact originating element where the event initiated (the actual clicked node).
event.currentTarget Element The element currently handling the event (where addEventListener was attached). Equal to this.
event.key string The character value of the pressed key during keyboard events.
event.preventDefault() function Cancels default browser behavior without stopping DOM propagation.
event.stopPropagation() function Halts further bubbling or capturing up/down the DOM tree.
Example 7.1: Inspecting an Event Object HTML + JS 
<button id="inspect-button">Inspect Event</button>

<script>
  document.querySelector("#inspect-button").addEventListener("click", (event) => {
    console.log("Event type:", event.type);
    console.log("Target id:", event.target.id);
    console.log("CurrentTarget id:", event.currentTarget.id);
  });
</script>
Console Output (When Button Itself Is Clicked)
Event type: click Target id: inspect-button CurrentTarget id: inspect-button
Example 7.2: Target vs CurrentTarget with Nested Elements HTML + JS 
<button id="outer-button">
  Outer Button
  <span id="inner-text" style="color: #D97706; font-weight: bold;">Click this text</span>
</button>

<script>
  document.querySelector("#outer-button").addEventListener("click", (event) => {
    console.log("Target:", event.target.id);
    console.log("Current target:", event.currentTarget.id);
  });
</script>
Console Output (When User Clicks Directly On The Nested <span>)
Target: inner-text Current target: outer-button
🔍 The Core Mental Model: Target vs currentTarget

event.target is the “who got touched” element (the inner span).
event.currentTarget is the “who is listening” element (the outer button where addEventListener was registered).
Confusing these two properties is the cause of hundreds of real-world bugs, especially when buttons contain icons, badges, or nested spans!

8 Preventing Default Browser Behavior

Web browsers come pre-configured with built-in default behaviors for several native HTML elements:

  • Clicking an anchor tag <a href="..."> navigates the tab to a new URL.
  • Submitting a <form> causes the browser to assemble form data, send a GET/POST HTTP request, and perform a full page reload.
  • Right-clicking opens the browser context menu.
  • Typing into an input field prints characters into the box.

In modern Single Page Applications (SPAs) and dynamic web interfaces, we often want JavaScript to handle user submissions via asynchronous requests (like fetch) without reloading the page. Calling event.preventDefault() halts the browser’s default action while allowing JavaScript code to execute cleanly.

Example 8.1: Form Submission Without Page Reload HTML + JS 
<form id="demo-form">
  <input id="demo-input" placeholder="Type something">
  <button type="submit">Submit</button>
</form>

<p id="demo-output"></p>

<script>
  document.querySelector("#demo-form").addEventListener("submit", (event) => {
    // Prevent the browser from refreshing the page
    event.preventDefault();

    document.querySelector("#demo-output").textContent =
      document.querySelector("#demo-input").value;
  });
</script>
Example 8.2: Preventing Anchor Link Navigation HTML + JS 
<a id="demo-link" href="https://example.com">Demo link</a>
<p id="link-status"></p>

<script>
  document.querySelector("#demo-link").addEventListener("click", (event) => {
    event.preventDefault();
    document.querySelector("#link-status").textContent =
      "Navigation was prevented for this demonstration.";
  });
</script>
• Default Behavior (No preventDefault)

Browser refreshes the page, clears all input states, resets JavaScript memory variables to zero, and appends query strings to the URL bar.

• Prevented Behavior (With preventDefault)

Page stays in place, JavaScript keeps running seamlessly in memory, and the application displays immediate inline feedback.

9 Event Bubbling and Capturing

When you click a button nested deep inside three <div> containers, you aren’t just clicking the button—you are physically clicking the parent containers and the page body as well! How does the browser decide the exact sequence in which handlers run?

The official W3C DOM event specification divides event propagation into three distinct phases:

Phase 1: Capturing Trickles DOWN from Window → Document → <html> → <body> → Parent ↓
Phase 2: Target Reaches the actual target element clicked by user ⬤
Phase 3: Bubbling Rises BACK UP from Target → Parent → <body> → <html> → Window ↑

Default Behavior: By default, addEventListener(type, listener) registers handlers for the Bubbling Phase (Phase 3). If you wish to capture an event on its way down (Phase 1), pass { capture: true } or true as the third argument.

Example 9.1: Observing Natural Event Bubbling HTML + JS 
<div id="parent-box">
  Parent
  <button id="child-button">Click Child</button>
</div>

<script>
  document.querySelector("#parent-box").addEventListener("click", () => {
    console.log("Parent listener");
  });

  document.querySelector("#child-button").addEventListener("click", () => {
    console.log("Child listener");
  });
</script>
Expected Console Output (When Child Button Is Clicked)
Child listener Parent listener

Notice that the child listener executed first, and then the event bubbled upwards to trigger the parent listener!

Example 9.2: Comparing Capture and Bubble Listeners HTML + JS 
<div id="outer">
  Outer
  <button id="inner">Click Me</button>
</div>

<script>
  const outer = document.querySelector("#outer");
  const inner = document.querySelector("#inner");

  // 1. Outer capture listener (runs during trickling down)
  outer.addEventListener("click", () => {
    console.log("Outer capture");
  }, { capture: true });

  // 2. Inner target listener
  inner.addEventListener("click", () => {
    console.log("Inner target");
  });

  // 3. Outer bubble listener (runs during bubbling up)
  outer.addEventListener("click", () => {
    console.log("Outer bubble");
  });
</script>
Expected Console Output (When Inner Button Is Clicked)
Outer capture Inner target Outer bubble

Stopping Propagation with event.stopPropagation():
If you call event.stopPropagation() inside a handler, the event stops right there and will not travel to subsequent nodes along the propagation path.

⚠ Caution: Avoid Overusing stopPropagation()

While stopPropagation() is tempting, using it thoughtlessly breaks features that rely on bubbling, such as analytics tracking, click-outside modals, and event delegation! Always consider whether you truly need to halt propagation.

10 Event Delegation

Imagine an e-commerce website with a list of 500 products, or an interactive task manager where users continually add new tasks. Should you attach 500 separate addEventListener() handlers to each individual item?

No! Doing so wastes browser memory, slows down performance, and introduces a critical bug: any item added to the DOM dynamically after the page loads will NOT have a listener attached!

Event Delegation is an elegant design pattern made possible by event bubbling. Instead of attaching a listener to every child element, you attach a single listener to their common parent container. When an event fires on any child, it naturally bubbles up to the parent. The parent checks event.target to identify which child was clicked and executes the appropriate logic.

Architecture Comparison: Individual Listeners vs. Event Delegation
✖ Individual Listeners (Bad Practice)
  • N listeners in memory for N elements.
  • High memory overhead and garbage collection.
  • New dynamic items do NOT respond to clicks without manually attaching listeners.
✔ Event Delegation (Best Practice)
  • Only 1 listener attached to the parent container.
  • Minimal memory footprint.
  • Automatically handles all dynamically added and removed elements forever!
Example 10.1: Handling List Clicks with Event Delegation HTML + JS 
<ul id="course-list">
  <li><button data-course="JavaScript">JavaScript</button></li>
  <li><button data-course="Python">Python</button></li>
</ul>

<script>
  const courseList = document.querySelector("#course-list");

  courseList.addEventListener("click", (event) => {
    // 1. Locate the nearest matching button using .closest()
    const button = event.target.closest("button[data-course]");

    // 2. Validate that the button exists and belongs to this list
    if (!button || !event.currentTarget.contains(button)) {
      return;
    }

    console.log(`Selected: ${button.dataset.course}`);
  });
</script>
Expected Console Output (When Clicking The Python Button)
Selected: Python
Example 10.2: Handling Dynamically Added Items HTML + JS 
<button id="add-item">Add Item</button>
<ul id="item-list"></ul>

<script>
  const list = document.querySelector("#item-list");

  // Delegated listener on parent ul handles all current and future <li> elements
  list.addEventListener("click", (event) => {
    const item = event.target.closest("li");

    if (item && list.contains(item)) {
      item.classList.toggle("selected");
    }
  });

  // Dynamically add elements to the list
  document.querySelector("#add-item").addEventListener("click", () => {
    const item = document.createElement("li");
    item.textContent = `Item ${list.children.length + 1}`;
    list.append(item);
  });
</script>

11 Removing Event Listeners & Listener Options

Unneeded event listeners consume CPU cycles and memory. In long-running web applications, failing to clean up unused listeners creates memory leaks.

To remove an event listener, you call removeEventListener(type, listener). However, there is a golden rule: you must provide the EXACT SAME function reference that was passed to addEventListener().

Example 11.1: Removing an Event Listener with a Named Reference JavaScript 
const button = document.querySelector("#temporary-button");

// Named callback function
function handleClick() {
  console.log("Button clicked");
}

// 1. Attach listener
button.addEventListener("click", handleClick);

// 2. Remove listener (requires identical reference)
button.removeEventListener("click", handleClick);
⚠ Why Anonymous Functions Cannot Be Removed

If you write button.addEventListener("click", () => console.log("hi")), and later call button.removeEventListener("click", () => console.log("hi")), the listener will NOT be removed! Even though the code inside looks identical, each arrow function literal creates a completely separate function object at a different location in computer memory.

Example 11.2: Using the { once: true } Option HTML + JS 
<button id="one-time-button">Click Once</button>
<p id="one-time-message">Not clicked yet</p>

<script>
  const oneTimeBtn = document.querySelector("#one-time-button");
  const oneTimeMsg = document.querySelector("#one-time-message");

  oneTimeBtn.addEventListener("click", () => {
    oneTimeMsg.textContent = "This listener has run once and automatically detached!";
  }, { once: true });
</script>
Option Type Default Behavior & Practical Use Case
once boolean false When set to true, the listener will automatically remove itself after firing once. Ideal for initialization routines and claim-reward buttons.
capture boolean false When set to true, fires during the capturing phase (on the way down) rather than the bubbling phase (on the way up).
passive boolean false When set to true, signals to the browser that the handler will NEVER invoke event.preventDefault(). This allows the browser to perform instantaneous, buttery-smooth scrolling without waiting for JavaScript execution on the main thread.

12 Common Event Handling Mistakes

Review these 12 classic pitfalls before building interactive web applications. Understanding why each breaks will save you countless hours of debugging!

❌ Mistake 1: Invoking the Callback Immediately Instead of Passing It
// INCORRECT: Notice the () after handleClick
button.addEventListener("click", handleClick());

Why it breaks: The parentheses execute handleClick() immediately when the script runs on page load, and passes its return value (usually undefined) to addEventListener. When the button is later clicked, nothing happens!

✔ Corrected Code: button.addEventListener("click", handleClick); or button.addEventListener("click", () => handleClick());
❌ Mistake 2: Overwriting Handlers with Legacy onclick
// INCORRECT: Second assignment wipes out the first
button.onclick = () => console.log("First task");
button.onclick = () => console.log("Second task"); // Overwrites!

Why it breaks: onclick is a single property slot on the DOM object. Assigning a new function replaces the previous one completely.

✔ Corrected Code: Use button.addEventListener("click", ...); for both listeners.
❌ Mistake 3: Selecting a Nonexistent Element Without Null Check
// INCORRECT: If element is not in DOM, throws Uncaught TypeError
const btn = document.querySelector("#missing-btn");
btn.addEventListener("click", handler); // Cannot read properties of null
✔ Corrected Code: Verify the element exists first: if (btn) btn.addEventListener("click", handler);
❌ Mistake 4: Registering Duplicate Listeners in Loops or Rerenders
// INCORRECT: Attaching listener inside a repeated refresh loop
function render() {
  button.addEventListener("click", () => console.log("Clicked!"));
}

Why it breaks: Every time render() runs, another listener is attached. After 5 renders, a single button click prints “Clicked!” 5 times!

✔ Corrected Code: Attach event listeners once during initialization, outside repeated render cycles.
❌ Mistake 5: Confusing event.target with event.currentTarget
// INCORRECT: Assuming target is always the button
button.addEventListener("click", (e) => {
  const action = e.target.dataset.action; // Undefined if user clicked an inner <svg> or <span>!
});
✔ Corrected Code: Use e.currentTarget or e.target.closest("button").
❌ Mistake 6: Forgetting event.preventDefault() on Form Submit
// INCORRECT: Missing preventDefault
form.addEventListener("submit", () => {
  saveData(); // Browser immediately reloads the page before data can be saved!
});
✔ Corrected Code: Include event.preventDefault(); as the very first line in your form submit handler.
❌ Mistake 7: Overusing event.stopPropagation()
// INCORRECT: Halting propagation blindly
dropdown.addEventListener("click", (e) => {
  e.stopPropagation(); // Breaks global "click outside to close modal" listeners!
});
✔ Corrected Code: Use e.preventDefault() if you want to stop default actions, or check e.target instead of blindly cutting off bubbling.
❌ Mistake 8: Trying to Remove an Anonymous Listener Function
// INCORRECT: Different function instances in memory!
btn.addEventListener("click", () => alert("Hi"));
btn.removeEventListener("click", () => alert("Hi")); // Does NOT remove anything!

taskList.addEventListener("click", (event) => {
  // 1. Find the nearest action button
  const btn = event.target.closest("button[data-action]");
  if (!btn || !taskList.contains(btn)) return;

  // 2. Find the parent task item container

Part A: Output Prediction Challenges

Challenge 1: Event Bubbling vs Target Order

What is the exact console output when a user clicks the button inside the following markup?

<div id="container">
  <button id="btn">Click Me</button>
</div>

<script>
  document.querySelector("#container").addEventListener("click", () => {
    console.log("Container clicked");
  });
  document.querySelector("#btn").addEventListener("click", () => {
    console.log("Button clicked");
  });
</script>

Answer:

Button clicked Container clicked

Explanation: Because listeners default to the bubbling phase, the innermost target element (#btn) runs first, and then the event bubbles up to the parent (#container).

Challenge 2: The { once: true } Option

If the user clicks the button three times consecutively, how many times will “Fired!” be logged?

const btn = document.querySelector("#my-btn");
btn.addEventListener("click", () => {
  console.log("Fired!");
}, { once: true });

Answer: Exactly 1 time.

Explanation: The { once: true } option instructs the browser to automatically unregister the listener immediately after its first invocation. Clicks 2 and 3 do nothing.

Challenge 3: Anonymous removeEventListener

Will the listener be removed below?

button.addEventListener("click", () => console.log("Hello"));
button.removeEventListener("click", () => console.log("Hello"));

Answer: NO! The listener will NOT be removed.

Explanation: The two arrow functions are distinct objects in memory. To successfully remove a listener, you must pass the exact same function reference variable.
