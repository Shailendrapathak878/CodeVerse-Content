Variables & Data Types

Learn how JavaScript stores, names, and organizes information in memory. Master variable bindings with let and const, explore all seven primitive data types, discover objects, and avoid classic beginner pitfalls.

1 Welcome to Variables: Named Storage Containers

Imagine organizing your desk with labelled storage containers. One box holds pens, another stores paperclips, and a third keeps sticky notes. Whenever you need an item, you look for its label.

In JavaScript, a variable works like a labelled container in computer memory. It creates a named binding that points to a specific piece of data so your code can save, update, and reuse it anytime.

💡 Critical Concept: Assignment vs Equality
The single equals sign (=) is the assignment operator. It copies the value on the right into the named variable on the left. It does not check equality; equality comparison uses ===.

2 Declaring, Initializing, and Reassigning

Working with variables involves three distinct lifecycle stages:

  • Declaration: Registering the variable name in memory using keywords like let.
  • Initialization: Giving that variable its very first value.
  • Reassignment: Replacing the current value with a brand new value.
Lifecycle Stages in Action JS 
let score;         // 1. Declaration (value is undefined)
score = 90;        // 2. Initialization

console.log(score);

score = 95;        // 3. Reassignment
console.log(score);
Expected Output
90
95

Most frequently, developers combine declaration and initialization into a single concise statement:

3 Choosing Keywords: let, const, and var

Modern JavaScript provides three keywords for creating variables. Knowing which one to pick is a vital skill for clean coding:

Keyword Scope Reassignable? Redeclarable? Modern Recommendation
const Block No No Default choice for fixed bindings
let Block Yes No Use when values must update (counters, states)
var Function Yes Yes Avoid (legacy scoping and hoisting bugs)
Reassigning let vs Constant Binding JS 
let score = 10;
score = 20;               // Valid: let allows reassignment

const country = "India";  // Locked binding

console.log(score);
console.log(country);
Expected Output
20
India

Attempting to reassign a const variable throws a runtime error:

Const Reassignment Failure ERROR DEMO 
const age = 18;
age = 19; // ❌ Throws TypeError: Assignment to constant variable.
Runtime Error
TypeError: Assignment to constant variable.

Block Scope: Variables declared with let and const exist strictly within the curly braces { ... } where they are created:

Block Scope Demonstration JS 
if (true) {
  let message = "Inside the block";
  console.log(message); // Visible here
}

// Accessing message out here throws a ReferenceError!
Expected Output
Inside the block

4 Variable Naming Rules & Conventions

JavaScript identifiers must obey strict language rules and community conventions:

  • Allowed characters: Letters, digits, underscores (_), and dollar signs ($).
  • No leading digits: Names cannot begin with a number (e.g. 2age is invalid).
  • No reserved words: You cannot use keywords like let, const, or class as names.
  • Case sensitivity: studentName and studentname are two completely separate variables.
  • camelCase convention: Standard practice starts with a lowercase letter and capitalizes each subsequent word.
Valid Identifier Examples JS 
let studentName = "Aarav"; // Standard camelCase
let _score = 95;            // Underscore prefix allowed
let $price = 100;           // Dollar sign prefix allowed
let age2 = 20;              // Digits inside or at the end allowed
Invalid Identifiers (Do Not Write) SYNTAX ERRORS 
let 2age = 20;   // ❌ SyntaxError: Cannot begin with a digit
let let = 10;    // ❌ SyntaxError: "let" is a reserved keyword
let user-name;   // ❌ SyntaxError: Hyphen is treated as minus (-)

In JavaScript, values have specific types. A data type defines what kind of value it is and what mathematical or logical operations you can perform on it.

JavaScript classifies data into seven primitive types (immutable standalone values) and one complex reference category: Objects.

6 Working with Strings and Numbers

Strings: Represent characters, words, or sentences wrapped in matching single quotes ('...') or double quotes ("..."). The plus operator (+) joins strings together in a process called concatenation:

String Concatenation JS 
const firstName = "Aarav";
const city = "Lucknow";

console.log(firstName);
console.log(city);
console.log(firstName + " lives in " + city);
Expected Output
Aarav
Lucknow
Aarav lives in Lucknow

Numbers: Unlike C++ or Java, JavaScript does not use separate types like int or float. Both whole numbers and fractional decimals belong to the single Number type:

Number Operations JS 
const price = 100;
const quantity = 3;

console.log(price * quantity); // Multiplication (*) -> 300
console.log(10 / 2);            // Division (/) -> 5
console.log(10 % 3);            // Modulo (%): remainder of 10 / 3 -> 1
Expected Output
300
5
1

7 Boolean, Undefined, and Null

Beginners often confuse undefined and null. Understanding their exact roles eliminates confusion:

  • Boolean: Has only two values: true or false. Used for control flow and decision-making.
  • Undefined: Represents a variable that has been declared, but has not yet been initialized with any value.
  • Null: Represents an explicit, intentional absence of any object value chosen deliberately by the programmer.
Boolean, Undefined, and Null in Action JS 
const isLoggedIn = true;
const hasPaid = false;
console.log(isLoggedIn);
console.log(hasPaid);

let username;               // Not assigned
console.log(username);

const selectedCourse = null; // Intentionally set to nothing
console.log(selectedCourse);
Expected Output
true
false
undefined
null

8 Inspecting Types with the typeof Operator

The unary typeof operator evaluates a value and returns a lowercase string indicating its data type:

Using typeof on Various Types JS 
console.log(typeof "CodeVerse");             // "string"
console.log(typeof 42);                      // "number"
console.log(typeof 3.14);                    // "number"
console.log(typeof true);                    // "boolean"
console.log(typeof undefined);               // "undefined"
console.log(typeof 12345678901234567890n);    // "bigint"
console.log(typeof Symbol("id"));             // "symbol"
console.log(typeof { name: "Aarav" });       // "object"
console.log(typeof function () {});          // "function"

⚠ Famous JavaScript Quirk: typeof null

Executing console.log(typeof null); outputs "object".

This is an acknowledged bug from JavaScript's first release in 1995. Changing it today would break millions of older websites, so it remains intentionally unfixed. Null is still a primitive value, not an actual object.

9 Arrays and Objects: A First Look

While primitive types hold a single isolated value, objects and arrays store structured collections of data:

  • Array: An ordered, zero-indexed list enclosed in brackets ([...]).
  • Object: A collection of key-value properties enclosed in braces ({...}).
First Look at Collections JS 
const languages = ["JavaScript", "Python", "Java"];
const learner = {
  name: "Aarav",
  age: 18
};

console.log(languages);
console.log(learner.name);
console.log(typeof languages);
console.log(typeof learner);
Expected Output
[ 'JavaScript', 'Python', 'Java' ]
Aarav
object
object

Notice that typeof languages returns "object". In JavaScript, arrays are a specialized variety of object. In future topics, we will use Array.isArray(languages) to detect arrays reliably.

10 Type Conversion vs Type Coercion

JavaScript allows values of one type to transform into another. This happens in two distinct ways:

  • Explicit Conversion: You intentionally call a function like Number() or String().
  • Implicit Coercion: JavaScript automatically shifts a value's type during an operation behind the scenes.
Explicit Conversion vs Implicit Coercion JS 
// 1. Explicit Conversion
const input = "25";
const age = Number(input);
console.log(age);         // 25
console.log(typeof age);  // "number"

const score = 90;
console.log(String(score));        // "90"
console.log(typeof String(score)); // "string"

// 2. Implicit Coercion (Automatic)
console.log("5" + 2); // "52" (number coerced to string for +)
console.log("5" - 2); // 3 (string coerced to number for -)

// 3. Failed Conversion
console.log(Number("hello")); // NaN (Not a Number)
Expected Output
25
number
90
string
52
3
NaN

Notice how "5" + 2 produces "52" because + prefers string concatenation, while "5" - 2 produces 3 because subtraction only applies to numbers. When text cannot be parsed into a number, JavaScript yields NaN (Not a Number).

11 Common Beginner Mistakes & Fixes

❌ Mistake 1: Reassigning a const Variable
const tax = 0.15; tax = 0.18; throws TypeError.
✔ Fix: Use let if the value must be updated later, or keep it const if fixed.
❌ Mistake 2: Assuming const Freezes Object Properties
const learner = { name: "Aarav" }; learner.name = "Riya"; is completely valid!
✔ Fix: const locks the binding to the object container; it does not freeze inner properties.
❌ Mistake 3: Confusing = With ===
Using if (score = 100) overwrites the score instead of checking equality.
✔ Fix: Use = for assignment; use === for strict equality comparison.
❌ Mistake 4: Forgetting Quotes on String Values
Writing let role = developer; throws ReferenceError: developer is not defined.
✔ Fix: Always wrap text strings in matching quotes: let role = "developer";.
❌ Mistake 5: Treating "18" Identically to 18
Adding "18" + 2 gives "182" instead of 20.
✔ Fix: Convert numeric strings with Number("18") + 2 to perform addition.
❌ Mistake 6: Accessing Block-Scoped let Outside Its Block
Declaring let secret = 123; inside an if block makes it invisible outside.
✔ Fix: Declare the variable in the outer scope if needed throughout the function.
Const Object Property Mutation Demo JS 
const learner = { name: "Aarav" };

// Modifying an internal property is allowed!
learner.name = "Riya";
console.log(learner.name); // "Riya"

// But reassigning the whole variable fails:
// learner = { name: "Kabir" }; // TypeError
Expected Output
Riya

13 Quick Recap & Self-Reflection

1. Prefer const by Default Use const for variables that keep their binding, and let when reassignment is explicitly required. Avoid var.
2. Seven Primitive Types String, Number, BigInt, Boolean, Undefined, Null, and Symbol. Everything else belongs to the Object category.
3. Inspect with typeof Use typeof to check types at runtime. Remember the classic quirk: typeof null === "object".
4. Explicit Over Implicit Convert types intentionally with Number() or String() to avoid surprise string concatenation bugs.
