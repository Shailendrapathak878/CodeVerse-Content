Intro What Is Object-Oriented Programming?

Imagine you are designing a College Student Management Platform for CodeVerse. In your system, you need to track thousands of individual students. Every student has identifiable data (name, roll number, course, exam scores) and can perform specific actions (submitting an assignment, calculating their GPA, or displaying their profile).

In early programming scripts, you might have created separate independent variables like studentName1, studentScore1, studentName2, and studentScore2. As systems grow, managing loose, disconnected variables becomes an unmanageable mess. Object-Oriented Programming (OOP) is an architectural paradigm that organizes software design around entities (objects) that bundle both state (data) and behavior (functions) into cohesive units.

01 Understanding JavaScript Objects

Before diving into the class syntax introduced in ES6 (ECMAScript 2015), we must master the underlying entity: the JavaScript Object. An object is an unordered collection of related data represented as key-value pairs.

Keys are strings (or Symbols), and values can be any valid JavaScript type: numbers, strings, booleans, arrays, other objects, or even functions (which are called methods when stored on an object). Properties can be accessed using dot notation (student.name) or bracket notation (student["name"]).

Example 1.1 — Creating and Inspecting a Student Object JavaScript 
// Define a student object using object literal notation
const student = {
  name: "Aarav",
  course: "JavaScript",
  marks: 90
};

// Access properties using standard dot notation
console.log(student.name);
console.log(student.course);
console.log(student.marks);
Expected Output
Aarav JavaScript 90

Line-by-Line Explanation:

  • const student = { ... }: Allocates a new object in memory with three key-value properties.
  • student.name: Evaluates the key "name" on student, yielding "Aarav".
  • student.course: Retrieves the enrolled course string "JavaScript".
  • student.marks: Reads the numeric score 90.
Example 1.2 — Updating, Adding, and Deleting Object Properties JavaScript 
const student = {
  name: "Aarav",
  marks: 75
};

// 1. Mutate an existing property value
student.marks = 88;

// 2. Add a brand new property dynamically
student.course = "JavaScript";

console.log(student.marks);
console.log(student.course);

// 3. Remove a property using the delete operator
delete student.course;

// Attempting to read a deleted property returns undefined
console.log(student.course);
Expected Output
88 JavaScript undefined
⚠️ Crucial Beginner Insight: Why can const objects be changed?
Declaring const student = { ... } prevents you from reassigning the variable (e.g., student = "New String" throws a TypeError). However, the object itself inside memory remains mutable! You can update properties, add new keys, and delete existing properties freely.

02 What Is a Class?

While literal objects ({ ... }) work fine for one-off entities, what happens when our CodeVerse application needs 500 student records? Re-typing object literals over and over leads to typos, duplicate code, and wasted memory.

A Class serves as an architectural blueprint. It defines the structure, fields, and behavior that every created object (instance) will possess. In JavaScript, classes are declared using the class keyword and instantiated using the new operator.

Example 2.1 — Defining and Instantiating a Simple Class JavaScript 
// Define a reusable Student class blueprint
class Student {
  // Instance method shared by all instances
  greet() {
    return "Welcome to CodeVerse!";
  }
}

// Instantiate a fresh student object from the blueprint
const student = new Student();

// Invoke the instance method
console.log(student.greet());
Expected Output
Welcome to CodeVerse!

Line-by-Line Explanation:

  • class Student { ... }: Declares a new class named Student using PascalCase convention.
  • greet() { ... }: Declares an instance method directly inside the class body.
  • const student = new Student(): The new operator allocates a brand new empty object, attaches the class prototype, runs the constructor, and returns the instance reference.
  • student.greet(): Calls the method attached to the instance's prototype.
Example 2.2 — Creating Multiple Distinct Instances from One Class JavaScript 
class Course {
  describe() {
    return "This is a learning course.";
  }
}

// Create two completely separate instances
const javascriptCourse = new Course();
const pythonCourse = new Course();

console.log(javascriptCourse.describe());
console.log(pythonCourse.describe());

// Strict equality checks memory reference, not class name!
console.log(javascriptCourse === pythonCourse);
Expected Output
This is a learning course. This is a learning course. false
🔍 How JavaScript Classes Work Under the Hood: JavaScript is fundamentally a prototype-based language. The ES6 class syntax is elegant "syntactic sugar" built on top of JavaScript's prototype inheritance chain. Behind the scenes, methods defined inside class Course are placed on Course.prototype, ensuring that thousands of instances share a single memory copy of the method!

03 The constructor() Method

In our earlier example, every instance was generic. But real students have individual names, unique student IDs, and different test scores. How do we initialize customized state for each instance?

Enter the constructor() method. The constructor is a special lifecycle method that executes automatically the exact moment you call new ClassName(arg1, arg2). Its primary purpose is to receive initial arguments and assign them as instance properties attached to this.

Example 3.1 — Initializing Custom Instance State with a Constructor JavaScript 
class Student {
  // The constructor runs automatically when "new Student()" is called
  constructor(name, course) {
    // Attach incoming arguments to the current instance via "this"
    this.name = name;
    this.course = course;
  }

  introduce() {
    return `I am ${this.name}, learning ${this.course}.`;
  }
}

// Pass custom arguments into the constructor invocation
const student = new Student("Aarav", "JavaScript");

console.log(student.introduce());
Expected Output
I am Aarav, learning JavaScript.

Line-by-Line Breakdown:

  • constructor(name, course): Defines the parameter list required to configure a student.
  • this.name = name: Sets property name on the newly born object to the parameter "Aarav".
  • this.course = course: Sets property course to "JavaScript".
  • introduce(): Uses template literals to read this.name and this.course.
Example 3.2 — Multiple Students with Independent States JavaScript 
class Student {
  constructor(name, marks) {
    this.name = name;
    this.marks = marks;
  }

  displayResult() {
    return `${this.name} scored ${this.marks} marks.`;
  }
}

// Each student has its own isolated memory slot for properties
const student1 = new Student("Aarav", 92);
const student2 = new Student("Priya", 85);

console.log(student1.displayResult());
console.log(student2.displayResult());
Expected Output
Aarav scored 92 marks. Priya scored 85 marks.
💡 Constructor Rules:
  • A class can only have one constructor method. Declaring more than one throws a SyntaxError.
  • If you do not specify a constructor, JavaScript automatically supplies a default empty constructor.

04 Understanding this

The this keyword is one of the most powerful and misunderstood features in JavaScript. Inside an instance method, this refers to the specific instance that invoked the method. It provides the bridge between the general blueprint and the specific object's data.

Example 4.1 — Dynamic Binding of this Across Instances JavaScript 
class Student {
  constructor(name) {
    this.name = name;
  }

  greet() {
    // "this" points to whichever student called greet()
    return `Hello, ${this.name}!`;
  }
}

const firstStudent = new Student("Aarav");
const secondStudent = new Student("Priya");

console.log(firstStudent.greet());
console.log(secondStudent.greet());
Expected Output
Hello, Aarav! Hello, Priya!

Notice that when firstStudent.greet() runs, this.name yields "Aarav". When secondStudent.greet() runs, this.name yields "Priya".

⚠️ The Infamous Detached Callback Context Problem

In JavaScript, ordinary functions determine this based on how they are called, not where they were declared! If you detach a method from its instance and pass it as a standalone callback (such as to setTimeout or a button event listener), this is lost and becomes undefined in strict mode.

Example 4.2 — Losing and Restoring this Context JavaScript 
class Counter {
  constructor() {
    this.count = 0;
  }

  increment() {
    this.count += 1;
    return this.count;
  }
}

const counter = new Counter();

// 1. Direct invocation works perfectly
console.log(counter.increment()); // 1
console.log(counter.increment()); // 2

// 2. Detaching the method loses its "this" context!
const detachedFn = counter.increment;
try {
  detachedFn(); // Throws TypeError: Cannot read properties of undefined
} catch (err) {
  console.log("Detached call failed: " + err.message);
}

// 3. Solution A: Explicitly bind the method to the instance
const boundFn = counter.increment.bind(counter);
console.log("Bound function result:", boundFn()); // 3

// 4. Solution B: Wrap the call inside an arrow function
const arrowWrapped = () => counter.increment();
console.log("Arrow wrapper result:", arrowWrapped()); // 4
Expected Output
1 2 Detached call failed: Cannot read properties of undefined (reading 'count') Bound function result: 3 Arrow wrapper result: 4

05 Instance Methods and Shared Behavior

An instance method is a function defined inside the class body that operates on the instance's internal data. Methods allow objects to not just store static values, but perform calculations, manipulate states, and interact with other objects.

Example 5.1 — Computing Average Marks with an Instance Method JavaScript 
class Student {
  constructor(name, marks1, marks2) {
    this.name = name;
    this.marks1 = marks1;
    this.marks2 = marks2;
  }

  // Instance method performing calculation using instance state
  calculateAverage() {
    return (this.marks1 + this.marks2) / 2;
  }
}

const student = new Student("Aarav", 80, 90);

console.log(student.calculateAverage());
Expected Output
85
Example 5.2 — Mutating and Updating Internal State Through Methods JavaScript 
class Course {
  constructor(name) {
    this.name = name;
    this.completed = false;
  }

  // Method that mutates internal instance state
  completeCourse() {
    this.completed = true;
    return `${this.name} completed: ${this.completed}`;
  }
}

const course = new Course("JavaScript");

console.log(course.completed);
console.log(course.completeCourse());
Expected Output
false JavaScript completed: true
✨ Clean Architecture Tip: Instead of modifying an object's properties directly from outside (e.g. course.completed = true;), encapsulating state changes inside dedicated methods (e.g. course.completeCourse()) ensures your business logic, validation, and change notifications remain centralized and protected.

06 Getters and Setters

Often, you want a property whose value is dynamically calculated from other properties, or you want to intercept and validate property assignments before accepting them. JavaScript provides the get and set syntax for this exact purpose.

  • Getter: A method that binds an object property to a function that is called when that property is looked up (without parentheses!).
  • Setter: A method that binds an object property to a function that executes whenever an assignment is attempted.
Example 6.1 — Computed Property with a Getter JavaScript 
class Rectangle {
  constructor(width, height) {
    this.width = width;
    this.height = height;
  }

  // The "get" keyword exposes area as a property, NOT a function call!
  get area() {
    return this.width * this.height;
  }
}

const rectangle = new Rectangle(5, 4);

// Note: NO parentheses used after rectangle.area!
console.log(rectangle.area);
Expected Output
20
Example 6.2 — Input Validation Using a Setter JavaScript 
class Student {
  constructor(name) {
    // By convention, the backing storage variable is prefixed with _
    this._name = name;
  }

  get name() {
    return this._name;
  }

  set name(value) {
    // Strictly validate before allowing assignment
    if (typeof value !== "string" || value.trim() === "") {
      throw new Error("Student name cannot be empty.");
    }
    this._name = value.trim();
  }
}

const student = new Student("Aarav");

// Valid assignment triggers the setter
student.name = "Priya";
console.log(student.name);

// Invalid assignment throws an Error
try {
  student.name = "   ";
} catch (err) {
  console.log("Validation failed:", err.message);
}
Expected Output
Priya Validation failed: Student name cannot be empty.
⚠️ Avoid Infinite Recursion in Setters: Notice we stored the value in this._name, not this.name. If you write set name(val) { this.name = val; }, the setter calls itself endlessly until the JavaScript engine crashes with RangeError: Maximum call stack size exceeded!

07 Inheritance with extends

In real software systems, entities frequently share core characteristics. For example, a Teacher, a Student, and an Admin are all fundamentally Person entities. Instead of re-implementing name, email, and login() for all three, Inheritance allows a child class to inherit properties and methods from a parent class.

In JavaScript, a subclass inherits from a superclass using the extends keyword. Inheritance models an "is-a" relationship (e.g. a Dog is an Animal; a ProgrammingCourse is a Course).

Example 7.1 — Animal and Dog Inheritance Hierarchy JavaScript 
// Parent Superclass
class Animal {
  eat() {
    return "This animal is eating.";
  }
}

// Child Subclass inheriting from Animal
class Dog extends Animal {
  bark() {
    return "Woof!";
  }
}

const dog = new Dog();

// Dog inherits eat() from Animal and has its own bark() method
console.log(dog.eat());
console.log(dog.bark());
Expected Output
This animal is eating. Woof!
Example 7.2 — Specializing Courses with Inheritance JavaScript 
// Base Course Class
class Course {
  constructor(name) {
    this.name = name;
  }

  describe() {
    return `Course: ${this.name}`;
  }
}

// Specialized Programming Course
class ProgrammingCourse extends Course {
  showLanguage() {
    return `${this.name} teaches programming.`;
  }
}

const course = new ProgrammingCourse("JavaScript");

console.log(course.describe());
console.log(course.showLanguage());
Expected Output
Course: JavaScript JavaScript teaches programming.

08 The super Keyword

When a subclass declares its own constructor(), it needs a way to pass initial data up to the parent class constructor. That is the role of super().

The super keyword has two essential roles:

  1. In Subclass Constructor (super(...)): Calls the parent constructor. In JavaScript, derived classes must call super() before accessing this.
  2. In Subclass Methods (super.method(...)): Calls a method on the parent class prototype, allowing you to augment rather than overwrite parent behavior.
Example 8.1 — Delegating Constructor Initialization with super() JavaScript 
class Person {
  constructor(name) {
    this.name = name;
  }
}

class Student extends Person {
  constructor(name, course) {
    // 1. MUST call super() before accessing "this"!
    super(name);
    
    // 2. Initialize subclass-specific properties
    this.course = course;
  }

  introduce() {
    return `${this.name} is learning ${this.course}.`;
  }
}

const student = new Student("Aarav", "JavaScript");

console.log(student.introduce());
Expected Output
Aarav is learning JavaScript.
Example 8.2 — Augmenting Parent Methods with super.method() JavaScript 
class Course {
  describe() {
    return "This is a course.";
  }
}

class ProgrammingCourse extends Course {
  describe() {
    // Call the parent's describe() method and append custom text
    return `${super.describe()} It teaches programming.`;
  }
}

const course = new ProgrammingCourse();

console.log(course.describe());
Expected Output
This is a course. It teaches programming.
🚨 Critical Reference Error: Attempting to read or write this.property in a derived constructor before calling super() immediately throws: ReferenceError: Must call super constructor in derived class before accessing 'this'.

09 Method Overriding and Polymorphism

Method Overriding happens when a child class defines a method with the exact same name as a method in its parent class. The child's version supersedes the parent's version for instances of the child.

This leads directly to Polymorphism (Greek for "many shapes"). Polymorphism is the ability of different classes to respond to the same method call in their own specialized way. This allows your software to treat different objects uniformly without ugly if/else chains!

Example 9.1 — Method Overriding in Action JavaScript 
class Animal {
  speak() {
    return "The animal makes a sound.";
  }
}

class Dog extends Animal {
  // Dog overrides speak() with a specialized sound
  speak() {
    return "Woof!";
  }
}

const animal = new Animal();
const dog = new Dog();

console.log(animal.speak());
console.log(dog.speak());
Expected Output
The animal makes a sound. Woof!
Example 9.2 — Polymorphism: Uniform Interface with Varied Behaviors JavaScript 
// Base notification class
class Notification {
  send() {
    return "Sending a notification.";
  }
}

class EmailNotification extends Notification {
  send() {
    return "Sending an email.";
  }
}

class SMSNotification extends Notification {
  send() {
    return "Sending an SMS.";
  }
}

// An array containing varied notification objects
const notifications = [
  new EmailNotification(),
  new SMSNotification()
];

// Polymorphism: We invoke .send() on every object uniformly!
notifications.forEach((notification) => {
  console.log(notification.send());
});
Expected Output
Sending an email. Sending an SMS.

10 Encapsulation and Private Fields (#)

Encapsulation is the principle of bundling state and the methods that operate on it while restricting direct external access to internal implementation details. It protects your object's internal rules (invariants) from being corrupted by rogue outside code.

Historically, JavaScript developers used an underscore prefix (_balance) to signal "please don't touch this". However, this was purely an informal convention—any code could still freely write account._balance = -999999;.

In modern ECMAScript (ES2022+), JavaScript introduced true private class fields prefixed with a hash sign #. Private fields cannot be inspected, read, or modified from outside the class declaration. Attempting to do so results in a syntax error!

Example 10.1 — Protecting State with Private Field #balance JavaScript 
class BankAccount {
  // 1. Declare the private field with #
  #balance;

  constructor(initialBalance = 0) {
    if (!Number.isFinite(initialBalance) || initialBalance < 0) {
      throw new Error("Initial balance must be non-negative.");
    }
    this.#balance = initialBalance;
  }

  // Controlled public getter
  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount(1000);

console.log(account.getBalance());

// Attempting account.#balance from outside causes a SyntaxError:
// "Private field '#balance' must be declared in an enclosing class"
Expected Output
1000
Example 10.2 — Controlled Deposits and Invariant Protection JavaScript 
class BankAccount {
  #balance;

  constructor(initialBalance = 0) {
    if (!Number.isFinite(initialBalance) || initialBalance < 0) {
      throw new Error("Invalid initial balance.");
    }
    this.#balance = initialBalance;
  }

  deposit(amount) {
    // Guarantee balance cannot be corrupted by NaN, negatives, or strings
    if (!Number.isFinite(amount) || amount <= 0) {
      throw new Error("Deposit must be a positive number.");
    }
    this.#balance += amount;
    return this.#balance;
  }

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount(500);

console.log(account.deposit(200));
console.log(account.getBalance());

// Reject invalid deposit attempt
try {
  account.deposit(-50);
} catch (err) {
  console.log("Deposit rejected:", err.message);
}
Expected Output
700 700 Deposit rejected: Deposit must be a positive number.

11 Static Methods and Properties

Not all methods belong to individual object instances. Sometimes you need helper functions or factory constructors that belong to the Class itself. In JavaScript, prefixing a method or field with static binds it directly to the class constructor, rather than to instances.

Example 11.1 — Static Utility Helper JavaScript 
class MathHelper {
  // Static method belongs to MathHelper, NOT an instance
  static add(a, b) {
    return a + b;
  }
}

// Call directly on the class without using "new"!
console.log(MathHelper.add(5, 3));
Expected Output
8
Example 11.2 — Static Factory Constructor Method JavaScript 
class Student {
  constructor(name, course) {
    this.name = name;
    this.course = course;
  }

  // Static factory method provides a pre-configured instantiation
  static createBeginner(name) {
    return new Student(name, "JavaScript");
  }
}

// Create student through the factory method
const student = Student.createBeginner("Aarav");

console.log(student.name);
console.log(student.course);
Expected Output
Aarav JavaScript
⚠️ Crucial Static Rule: You cannot call a static method from an instance (e.g. student.createBeginner("Aarav") throws TypeError: student.createBeginner is not a function). Likewise, inside a static method, this points to the Class constructor, not an individual student instance!

12 Composition Versus Inheritance

A famous design guideline in object-oriented engineering states: "Favor object composition over class inheritance."

While inheritance ("is-a") is natural for true hierarchical relationships, deep inheritance trees often create brittle, rigid codebases. If a superclass method changes, multiple subclasses can break. Composition ("has-a") creates flexible entities by combining small, independent behavior objects together.

🔄 Comparing Architectural Approaches
Inheritance ("is-a")
A Dog is an Animal.
Rigid hierarchy; inherits everything.
Composition ("has-a")
A Dog has eatingAbility & barkingAbility.
Mix-and-match modular Lego blocks.
Example 12.1 — The Inheritance Approach JavaScript 
class Animal {
  eat() {
    return "Eating food.";
  }
}

class Dog extends Animal {
  bark() {
    return "Woof!";
  }
}

const dog = new Dog();
console.log(dog.eat());
console.log(dog.bark());
Expected Output
Eating food. Woof!
Example 12.2 — The Composition Approach with Behavior Modules JavaScript 
// Discrete behavior components
const canEat = {
  eat() {
    return "Eating food.";
  }
};

const canBark = {
  bark() {
    return "Woof!";
  }
};

// Compose a dog by assembling discrete behaviors
const dog = Object.assign({}, canEat, canBark);

console.log(dog.eat());
console.log(dog.bark());
Expected Output
Eating food. Woof!

13 Common OOP Mistakes & How to Fix Them

Beginners often run into specific pitfalls when writing Object-Oriented JavaScript. Study these eight real-world scenarios to debug code with confidence:

❌ Mistake 1: Forgetting the new Keyword

Incorrect: Calling a class constructor like an ordinary function.

class Student {}
const s = Student(); // TypeError: Class constructor Student cannot be invoked without 'new'

Correct: Always instantiate with new.

const s = new Student(); // Correct!
❌ Mistake 2: Accessing this Before Calling super()

Incorrect: Setting subclass properties before initializing the parent.

class Child extends Parent {
  constructor(name, age) {
    this.age = age; // ReferenceError: Must call super constructor before accessing 'this'
    super(name);
  }
}

Correct: Always place super() as the first statement in a derived constructor.

super(name);
this.age = age; // Correct!
❌ Mistake 3: Calling Instance Methods Directly on the Class Constructor

Incorrect: Confusing the class blueprint with an instantiated object.

class Student {
  greet() { return "Hi!"; }
}
console.log(Student.greet()); // TypeError: Student.greet is not a function

Correct: Call instance methods on an instance, or declare the method as static.

const s = new Student();
console.log(s.greet()); // Correct! "Hi!"
❌ Mistake 4: Forgetting this When Accessing Properties Inside Methods

Incorrect: Assuming properties are in local lexical scope.

class Student {
  constructor(name) { this.name = name; }
  show() { return name; } // ReferenceError: name is not defined
}

Correct: Explicitly use this.name.

show() { return this.name; } // Correct!
❌ Mistake 5: Assuming _property Is Truly Private

Incorrect: Relying on underscore convention for security.

class Account {
  constructor(bal) { this._balance = bal; }
}
const acc = new Account(100);
acc._balance = -999; // Oops! Nothing prevented this direct mutation!

Correct: Use modern ES2022 private fields (#balance).

class Account {
  #balance;
  constructor(bal) { this.#balance = bal; }
} // acc.#balance = -999; SyntaxError! True encapsulation.
❌ Mistake 6: Detaching Methods in Callbacks and Losing this

Incorrect: Passing a class method directly to an event handler.

button.addEventListener("click", student.displayResult); // "this" is lost!

Correct: Wrap with an arrow function or .bind().

button.addEventListener("click", () => student.displayResult()); // Correct!
❌ Mistake 7: Creating Deep, Fragile Inheritance Trees

Incorrect: Subclassing 5 levels deep: LivingThing -> Animal -> Mammal -> Canine -> WorkingDog.

Correct: Keep inheritance shallow (1–2 levels maximum) and assemble orthogonal capabilities with composition.

❌ Mistake 8: Attempting to Read #privateField on Foreign Objects

Incorrect: Assuming private fields are like ordinary properties with special visibility flags.

Correct: Private fields use hard lexical scoping tied to the class definition. They cannot even be referenced in expressions outside the class body.

16 Practice, Revision & Knowledge Challenges

Part A: 8 Output Prediction Questions

Q1: What will this code print? 
class Box {
  constructor(size) {
    this.size = size;
  }
}
const b = new Box(10);
console.log(typeof Box, typeof b);

Answer: function object

Explanation: In JavaScript, a class is syntactically a special function (its constructor function), while an instantiated instance b is of type object.

Q2: What will this code print? 
class Counter {
  count = 0;
  increment() {
    this.count++;
    return this.count;
  }
}
const c1 = new Counter();
const c2 = new Counter();
c1.increment();
console.log(c1.count, c2.count);

Answer: 1 0

Explanation: Every instance created via new holds its own independent memory allocation for instance properties. Incrementing c1 does not affect c2.

Q3: What will this inheritance code print? 
class Parent {
  constructor() {
    this.type = "Parent";
  }
}
class Child extends Parent {}
const c = new Child();
console.log(c.type);

Answer: Parent

Explanation: If a subclass does not define its own constructor, JavaScript automatically supplies a default constructor that calls super(...args), executing the parent's initialization.

Q4: What will this getter code print? 
class Circle {
  constructor(r) { this.r = r; }
  get diameter() { return this.r * 2; }
}
const c = new Circle(7);
console.log(c.diameter);

Answer: 14

Explanation: Getters are accessed as properties without trailing parentheses. c.diameter invokes the getter method and returns 14.

Q5: What happens when calling a static method on an instance? 
class Tool {
  static info() { return "v1.0"; }
}
const t = new Tool();
console.log(t.info);

Answer: undefined

Explanation: Static methods reside on the constructor function (Tool.info), not on the instance prototype. Accessing t.info yields undefined (and calling t.info() would throw a TypeError).

Q6: What will this super.method() code print? 
class Base {
  name() { return "Base"; }
}
class Sub extends Base {
  name() { return super.name() + " -> Sub"; }
}
console.log(new Sub().name());

Answer: Base -> Sub

Explanation: super.name() delegates up to the Base prototype method, receives "Base", and concatenates " -> Sub".

Q7: What will this private field snippet print? 
class Vault {
  #code = 1234;
  verify(c) { return this.#code === c; }
}
const v = new Vault();
console.log(v.verify(1234), v.verify(9999));

Answer: true false

Explanation: Internal class methods can freely read their own private #code field and compare it against the passed argument.

Q8: What will this method equality check print? 
class User {
  login() {}
}
const u1 = new User();
const u2 = new User();
console.log(u1.login === u2.login);

Answer: true

Explanation: In JavaScript classes, methods declared in the class body are placed on User.prototype. Both instances reference the exact same shared function in memory.

Part C: 5 Debugging Challenges

Bug 1: Super constructor call error

Broken Code:

class Animal { constructor(name) { this.name = name; } }
class Dog extends Animal {
  constructor(name, breed) {
    this.breed = breed;
    super(name);
  }
}

The Fix: Move super(name); to the first line before this.breed = breed;.

Bug 2: Infinite recursion in setter

Broken Code:

class Item {
  set price(val) {
    this.price = val;
  }
}

The Fix: Store in a backing property like this._price = val; or private field this.#price = val; to avoid recursive setter calls.

Bug 3: Calling static method from instance

Broken Code:

class MathOps {
  static multiply(a, b) { return a * b; }
}
const op = new MathOps();
console.log(op.multiply(4, 5)); // TypeError!

The Fix: Call on the class directly: MathOps.multiply(4, 5).

Bug 4: Missing this keyword in method

Broken Code:

class User {
  constructor(name) { this.name = name; }
  greet() { return `Hi, ${name}`; } // ReferenceError!
}

The Fix: Change ${name} to ${this.name}.

Bug 5: Detached event callback losing this

Broken Code:

btn.addEventListener("click", counter.increment);

The Fix: Wrap with an arrow function: btn.addEventListener("click", () => counter.increment());.

Project Extension 2: LocalStorage Persistence & Instance Hydration

// Save to LocalStorage
saveToDisk() {
  const data = this.students.map(s => s.toJSON());
  localStorage.setItem("codeverse_students", JSON.stringify(data));
}

// Hydrate from LocalStorage
loadFromDisk() {
  const rawData = localStorage.getItem("codeverse_students");

}

Object-Oriented JavaScript Quick Reference Cheat Sheet

OOP Concept Syntax / Keyword Core Purpose & Behavior
Class Declaration class Name { ... } Defines a reusable blueprint for instantiating objects.
Instantiation const obj = new Name(...) Allocates object in heap, sets prototype, and runs constructor.
Constructor constructor(p1, p2) { ... } Special lifecycle method that initializes instance properties on this.
Instance Method methodName() { ... } Placed on class prototype; shared across all instances.
Getters / Setters get prop() / set prop(v) Exposes computed values and validates mutations as property lookups.
Inheritance class Sub extends Super Derives a specialized child class that reuses parent methods and state.
Super Delegation super(...) / super.method() Invokes parent constructor or calls parent prototype method.
Private Fields #privateField; Language-enforced private state; cannot be accessed outside class body.
Static Methods static helper() { ... } Utility function bound directly to the class namespace, not instances.
Polymorphism Subclass overrides parent method Uniform call (e.g. item.send()) executes class-specific behavior.
