01

The Form Element ()

Forms are the primary mechanism for collecting user input and sending data to servers. The <form> element acts as an interactive container encompassing input controls, labels, and submission buttons.

02

Form Attributes: action and method

Two crucial attributes govern how forms communicate with backend servers:

  • action: Specifies the server endpoint URL where submitted form data is sent (e.g., /api/login).
  • method: Specifies the HTTP transfer method:
    • GET: Appends form values directly into the URL as query parameters (e.g., search.php?q=html). Ideal for non-sensitive data queries and search forms (can be bookmarked).
    • POST: Transmits form data inside the HTTP request body. Mandatory for passwords, credit cards, or actions modifying server state.
03

Encoding Types (enctype)

When submitting binary files or image uploads, the form must explicitly declare enctype="multipart/form-data". Without this attribute, only the file name is transmitted rather than the binary file content.

WARN

Common Mistakes & Pro Tips

⚠️ Common Trap: Sending passwords using method="GET"

Problem: The user's plaintext password appears in the browser address bar, server access logs, and web proxy history.

Fix: Always use method="POST" for authentication, registration, or confidential form submissions.

⚠️ Common Trap: Omitting the name attribute on input elements

Problem: Inputs without a name attribute are ignored during form submission and will never reach the backend server.

Fix: Always assign a meaningful name="fieldName" attribute to every input.
