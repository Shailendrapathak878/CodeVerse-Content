Best Practices, Clean Markup & Maintainability

Writing production-grade HTML that scales: indentation standards, BEM naming conventions, clean element hierarchy, semantic selection, and self-documenting code architecture.

1. The Mental Model: Writing Code for Humans

As the computer scientist Harold Abelson famously wrote:

"Programs must be written for people to read, and only incidentally for machines to execute."

A web browser will happily execute messy, chaotic, unindented HTML written on a single 10,000-character line. But when you work on a team with other software engineers, messy HTML creates catastrophic bottlenecks:

  • Team members spend hours diagnosing phantom nesting issues.
  • Refactoring becomes terrifying because no one knows which closing tag pairs with which opening tag.
  • Git pull request diffs become unreadable conflicts.

3. The 7 Golden Rules of Professional HTML

Rule Bad Practice Professional Standard
1. Indentation Inconsistent or 0 spaces: tags jumbled on left margin. Strictly 2 spaces per nesting depth level. Never mix tabs with spaces.
2. Lowercase Tags <DIV CLASS="CARD"> Always lowercase: <div class="card">.
3. Attribute Quotes <input type=text name=user> Always enclose attributes in double quotes: <input type="text" name="user">.
4. Avoid Divitis <div class="nav"><div class="links"> Choose native semantic tags: <nav><ul><li>.
5. Symmetrical Nesting <strong><em>Hello</strong></em> Close tags in exact reverse order of opening: <strong><em>Hello</em></strong>.
6. Structural Comments Zero comments; impossible to tell where sections end. Clear block dividers: <!-- /MAIN HERO SECTION -->.
7. Always Define Lang <html> without language Always include <html lang="en"> for screen reader pronunciation.

4. Scalable Class Naming: Introduction to BEM

As websites grow to thousands of lines of HTML and CSS, naming conflicts become chaotic (e.g. which .title is which?). The industry standard solution is BEM (Block, Element, Modifier):

  • Block (Standalone Component): The independent parent entity (e.g. .product-card, .site-nav).
  • Element (Child of the Block): A piece inside the block, designated by two underscores (__): 
    .product-card__title
.product-card__image
.product-card__price
.product-card__buy-button
  • Modifier (A Variation or State): Designated by two hyphens (--): 
    .product-card--featured
.product-card__buy-button--disabled

BEM makes HTML self-documenting: looking at any class instantly tells you which component it belongs to and what role it plays!

6. Topic 27 Key Takeaways & Checklist

  • Adopt strict 2-space indentation for consistent visual hierarchy across your team.
  • Write lowercase tags and quoted attributes: <div class="box">.
  • Close tags symmetrically: Last opened tag is first closed tag.
  • Adopt BEM class naming (.block__element--modifier) to make styles self-documenting and prevent naming collisions.
  • Use clear block comments to divide major layout landmarks (Header, Main, Section, Footer).
  • Never compromise on accessibility: Always declare lang="en", mobile viewports, and image alt.
