Introduction to Web Accessibility (a11y)

Web accessibility (a11y) ensures that websites, tools, and technologies are designed so people with disabilities (visual, auditory, motor, or cognitive) can perceive, understand, navigate, and interact with the web.

The international standard is the WCAG (Web Content Accessibility Guidelines), organized around the four POUR principles: Perceivable, Operable, Understandable, and Robust.

02

First Rule of ARIA

WAI-ARIA (Accessible Rich Internet Applications) provides attributes to enhance markup when HTML falls short. However, the official W3C first rule of ARIA is:

'If you can use a native HTML element or attribute with the semantics and behavior you require already built in, then do so instead of re-purposing an element and adding an ARIA role, state or property.'

Always use a native <button> instead of a <div role="button">!

03

Essential ARIA Attributes

When custom interactive UI is unavoidable, use ARIA attributes:

  • aria-label="Close modal": Provides an invisible accessible label when visual icons have no text.
  • aria-labelledby="headingId": References an existing element's ID as the label.
  • aria-hidden="true": Hides decorative elements (like SVG icons) from the accessibility tree.
  • aria-expanded="true|false": Informs screen readers whether an accordion or dropdown menu is open.
  • aria-live="polite|assertive": Announces dynamic status updates (like cart count changes) automatically.

⚠️ Common Trap: Hiding vital content with aria-hidden="true"

Problem: Placing aria-hidden on active interactive elements like links or inputs makes them completely inaccessible.

Fix: Only use aria-hidden="true" on purely visual, non-interactive decorative elements.
