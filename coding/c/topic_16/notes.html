Foundations

01. What Is Dynamic Memory Allocation?

Core Definition

Dynamic Memory Allocation (DMA) is the process in C by which a running program requests memory from the operating system's runtime heap at execution time (runtime), rather than having all data storage sizes locked in stone at compile time.

1.1 Why Do Programs Need Dynamic Memory?

In everyday computing, software does not operate in a vacuum of predictable, static quantities:

  • A photo editor does not know the dimensions (resolution) of an image until the user opens a file.
  • A web browser cannot predict how many tabs or web pages you will open today.
  • A classroom marks recorder does not know if a teacher will enter 12 students or 1,200 students until the data is entered.

If C programs only had fixed-size arrays (like int marks[100];), two major crises arise:

  1. Memory Waste: If the teacher enters only 5 students, 95 integers of RAM sit idle and wasted.
  2. Buffer Overflow / Crash: If 101 students enroll, the array is too small to hold them, causing out-of-bounds corruption or system failure.
Real-Life Analogy: Hotel Room Reservation

Static Allocation: You book a banquet hall for exactly 100 guests a month in advance. If only 6 people show up, you pay for 94 empty chairs (waste). If 150 people show up, 50 guests are stranded outside in the rain (overflow).

Dynamic Allocation: You rent a flexible modular conference room. As guests arrive, you request additional partitioned space on demand. When guests depart, you release the partitions immediately so others can use them.

Note: This is an architectural analogy to build intuition; computer memory consists of addressable byte cells managed by the OS runtime.

1.2 Understanding Storage Durations in C

The ISO C Standard strictly categorizes data objects by their storage duration (lifetime):

Storage Duration How It Is Created Where It Resides (Conceptually) Lifetime & Deallocation
Automatic Local variables declared inside functions or blocks Stack frames Created when the enclosing block starts; automatically destroyed when the block exits.
Static Global variables, file-scope variables, static locals Data segment or BSS segment Created when the program starts; persists for the entire program execution.
Allocated (Dynamic) Explicitly requested via malloc(), calloc(), or realloc() The Heap / Free Store Persists indefinitely until explicitly released using free() or until program termination.
Standard Specification Note

The C language standard defines storage duration and allocation semantics, while the terms "stack" and "heap" are ubiquitous conceptual implementation models used by contemporary computer architectures (x86-64, ARM, RISC-V). C does not mandate a specific physical hardware layout.

Comparison

02. Static Allocation vs. Dynamic Allocation

Let us contrast how an array of 5 integers is represented under static (or automatic) allocation versus dynamic heap allocation.

Syntax Comparison

Fixed-size automatic array:

int arr[5]; /* Size 5 determined at compile time; fixed on stack */

Dynamically allocated array:

int *arr = malloc(5 * sizeof *arr); /* Requested at runtime on heap */
if (arr == NULL) { /* Mandatory check */ }
Comparison Metric Fixed-Size Array (Automatic/Static) Dynamically Allocated Block (Heap)
Allocation Moment Compile-time determined declaration; allocated on entry Runtime: requested precisely when data size is known
Size Resizing Immutable: cannot grow or shrink once declared Flexible: can be resized dynamically with realloc()
Storage Lifetime Bound to enclosing function scope (automatic duration) Controlled strictly by programmer: survives function return
Memory Location Stack frame or Static Data section Runtime Heap area
Deallocation Automatic: cleaned up by compiler upon scope exit Manual: programmer must call free()
Failure Detection No allocation return value; deep stack overflow crashes silently Returns NULL on out-of-memory; easily caught in code
Access Mechanism Direct array subscript arr[i] Pointer dereference or subscript *(arr + i) / arr[i]

2.1 What About Variable-Length Arrays (VLAs)?

C99 introduced Variable-Length Arrays (VLAs), such as int arr[n]; where n is a variable. However, VLAs are fundamentally different from heap dynamic allocation:

  • VLAs are allocated on the stack, not the heap. If n is excessively large, a fatal stack overflow occurs without any safe NULL check.
  • VLAs cannot outlive their enclosing function; they cannot be returned to a caller.
  • In C11 and C23, VLAs are an optional language feature that many mission-critical and embedded compilers do not support.
  • True dynamic memory allocation (via malloc) is standard, safe, checkable, and resizable across all platforms.
System Architecture

03. Conceptual Memory Layout of a C Program

When an operating system executes a compiled C binary, it establishes a virtual address space for the process. Conceptually, this address space is organized into five distinct regions:

Memory Region What It Stores Growth Direction / Nature
Text / Code Segment Compiled machine code instructions (CPU opcodes) Fixed size; Read-Only to prevent accidental code modification
Initialized Data (.data) Global and static variables initialized with non-zero values Fixed size; Read/Write
Uninitialized Data (.bss) Global and static variables initialized to zero or uninitialized Fixed size; zero-initialized by the OS kernel on startup
Heap Segment Dynamically allocated blocks (malloc, calloc, realloc) Dynamic size; grows upwards (toward higher virtual addresses)
Stack Segment Stack frames: local variables, return addresses, function parameters Dynamic size; grows downwards (toward lower virtual addresses)

3.1 Pointer on Stack vs. Data on Heap

Consider the single line of C code: 

int *ptr = malloc(5 * sizeof *ptr);

A vital distinction every C programmer must make:

  • ptr is a local pointer variable residing on the Stack (typically consuming 4 or 8 bytes of stack memory).
  • The malloc(...) call carves out a contiguous 20-byte block (assuming 4-byte integers) inside the Heap.
  • ptr holds the starting address of that heap block. The pointer variable and the pointed-to heap memory live in two completely separate segments of memory!
Memory Allocation

04. The malloc() Function in Depth

malloc Prototype • <stdlib.h>
#include <stdlib.h>

void *malloc(size_t size);

The name malloc stands for Memory Allocation.

  • Parameter (size): The total number of contiguous bytes to request from the heap. The type is size_t, an unsigned integer type capable of representing the maximum possible object size on the target architecture.
  • Return Value: Returns a generic pointer (void *) to the first byte of the allocated block on success. If the system is out of memory or the request cannot be satisfied, it returns NULL.
  • Uninitialized Memory: malloc() does NOT initialize the allocated memory! The block contains indeterminate ("garbage") bits left over from prior memory usage. You must write to the memory before reading it.
Do Not Cast malloc() in C

In standard C, a void * implicitly converts to any object pointer type without an explicit cast. Writing int *ptr = malloc(...); is preferred over int *ptr = (int *)malloc(...);. An explicit cast is unnecessary, clutters code, and in historic C could mask the error of forgetting to include <stdlib.h>.

4.1 Complete Runnable Starter Program

Here is a complete, beginner-friendly program that allocates space for five integers, initializes them, prints them, and cleanly releases the memory:

malloc_starter.c 
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    /* Step 1: Request heap memory for 5 integers */
    int *ptr = malloc(5 * sizeof *ptr);

    /* Step 2: Always verify allocation success */
    if (ptr == NULL)
    {
        printf("Memory allocation failed.\n");
        return 1;
    }

    /* Step 3: Initialize the elements before reading them */
    for (size_t i = 0; i < 5; i++)
    {
        ptr[i] = (int)(i + 1) * 10;
    }

    /* Step 4: Access and print the stored values */
    for (size_t i = 0; i < 5; i++)
    {
        printf("%d ", ptr[i]);
    }
    printf("\n");

    /* Step 5: Release the heap block when finished */
    free(ptr);
    ptr = NULL; /* Prevent accidental dangling access */

    return 0;
}

10 20 30 40 50

4.2 What Happens with malloc(0)?

If malloc(0) is called, the behavior is implementation-defined:

  • It may return a null pointer (NULL).
  • Or it may return a unique non-null pointer that behaves as if an object of zero size had been allocated. However, such a pointer must never be dereferenced!

Never use malloc(0) to create a usable object. If an element count is 0, handle it conditionally before making an allocation call.

Best Practices

05. Calculating Memory Size & Overflow Safety

To request memory for an array of count elements, we multiply the number of elements by the size of a single element:

The Recommended C Idiom
int *ptr = malloc(count * sizeof *ptr);

5.1 Why sizeof *ptr Is Superior to sizeof(int)

Notice we wrote sizeof *ptr rather than sizeof(int). Here is why this pattern is considered the gold standard in professional C programming:

  • *ptr dereferences the pointer at compile time to evaluate its type.
  • If tomorrow you change the declaration from int *ptr; to double *ptr; or long long *ptr;, the sizeof *ptr expression automatically adapts without you having to hunt down and edit every single malloc() line!
  • It completely eliminates the catastrophic bug of allocating sizeof(int) for a pointer to a large struct.
sizeof(int) Is Implementation-Dependent

Never assume an int is always 4 bytes. While 4 bytes is common on 32-bit and 64-bit desktop architectures (ILP32 and LP64), an int is 2 bytes on many 16-bit microcontrollers, and can theoretically be 8 bytes. Always rely on sizeof.

5.2 Protecting Against Integer Multiplication Overflow

In count * sizeof *ptr, both operands are unsigned values of type size_t. If count is provided by untrusted user input or read from an external file, the product count * sizeof *ptr could exceed the maximum value representable by size_t (SIZE_MAX), causing an arithmetic wrap-around!

The Wraparound Vulnerability

Suppose an attacker requests 1,073,741,825 integers. Multiplied by 4 bytes, the true size is 4,294,967,300. On a 32-bit system where SIZE_MAX = 4,294,967,295, this wraps around to just 4 bytes! malloc(4) succeeds, but the program then tries to write 1 billion integers into a 4-byte buffer, crashing the machine or opening a severe remote code execution exploit.

The Defensive Overflow Check Pattern:

overflow_check_pattern.c 
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h> /* For SIZE_MAX */

int *allocateIntArray(size_t count)
{
    /* Step 1: Reject zero or empty allocations */
    if (count == 0) return NULL;

    /* Step 2: Check for multiplication overflow before multiplying */
    if (count > SIZE_MAX / sizeof(int))
    {
        fprintf(stderr, "Error: Requested size exceeds maximum addressable memory!\n");
        return NULL;
    }

    /* Step 3: Now completely safe to multiply and allocate */
    int *arr = malloc(count * sizeof *arr);
    return arr;
}
Zero-Initialization

06. The calloc() Function & Zero-Initialization

calloc Prototype • <stdlib.h>
#include <stdlib.h>

void *calloc(size_t num_elements, size_t element_size);

The name calloc stands for Contiguous Allocation (or Clear Allocation).

  • Parameters: Accepts two separate arguments: num_elements (how many items) and element_size (the byte size of each item).
  • Zero-Initialization: Unlike malloc(), calloc() guarantees that every single allocated byte is cleared to all-bits-zero (0) before returning.
  • Total Bytes: Computes num_elements * element_size internally. On most modern C standard libraries, calloc() includes built-in multiplication overflow detection.

6.1 Complete Runnable Program

calloc_starter.c 
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    /* Request zero-initialized space for 4 integers */
    int *ptr = calloc(4, sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Memory allocation failed.\n");
        return 1;
    }

    /* Read values immediately: guaranteed to be 0 */
    for (size_t i = 0; i < 4; i++)
    {
        printf("%d ", ptr[i]);
    }
    printf("\n");

    free(ptr);
    ptr = NULL;

    return 0;
}
Exact Expected Output
0 0 0 0

6.2 malloc() vs. calloc(): Head-to-Head Comparison

Feature malloc() calloc()
Parameters 1 parameter: (size_t total_bytes) 2 parameters: (size_t count, size_t element_size)
Initialization Uninitialized (contains indeterminate garbage bits) Zeroed (all bits initialized to 0)
Performance Slightly faster: does not spend CPU cycles zeroing memory Slightly slower: must clear memory bytes (though OS zero-pages optimize this)
Best Used For Arrays you plan to immediately overwrite with fresh data (e.g., reading from file or sensor) Counters, frequency buckets, adjacency matrices, flags that must start at 0
Architecture Nuance: All-Bits-Zero

While all-bits-zero produces 0 for integers and null pointers on virtually all modern systems (IEEE 754 & POSIX/Windows), strictly speaking on rare legacy hardware, a null pointer or 0.0f float might not have an all-bits-zero representation. For integers, it is universally guaranteed.

Dynamic Resizing

07. The realloc() Function: Safe Resizing Patterns

realloc Prototype • <stdlib.h>
#include <stdlib.h>

void *realloc(void *ptr, size_t new_size);

The name realloc stands for Re-Allocation. It modifies the size of an existing dynamically allocated memory block pointed to by ptr to new_size bytes.

7.1 How realloc() Works Internally

When you request a resize, the runtime heap manager performs one of two actions:

  1. In-Place Expansion: If there is sufficient free contiguous space directly following the existing block, the manager extends the boundary of the current block. The pointer address does not change.
  2. Relocation: If neighboring memory is already occupied, the manager allocates a brand-new block of new_size elsewhere on the heap, copies all existing data from the old block to the new block, frees the old block automatically, and returns the address of the new block!
The Lethal realloc() Beginner Trap: Immediate Overwrite

NEVER DO THIS: 

/* CATASTROPHIC BUG: */
ptr = realloc(ptr, new_count * sizeof *ptr);

If realloc() fails (e.g., system is out of memory), it returns NULL. By assigning NULL directly to ptr, you overwrite and lose the only address reference to the original memory block! The original block is still allocated on the heap, but you can no longer access it or free it. This creates an unrecoverable memory leak.

7.2 The Safe Temporary Pointer Pattern

Always assign the result of realloc() to a temporary pointer, verify that it is non-null, and only then update your permanent pointer:

Golden Idiom for realloc()
int *temp = realloc(ptr, new_count * sizeof *ptr);
if (temp == NULL) {
    /* Handle failure gracefully: original 'ptr' is still valid! */
    fprintf(stderr, "Reallocation failed. Original data preserved.\n");
} else {
    ptr = temp; /* Safe to update pointer */
}

7.3 Complete 7-Step Resizing Program

This program allocates space for 3 integers, initializes and prints them, resizes the block to hold 5 integers, initializes the two new elements, prints all 5, and frees the block:

realloc_complete.c 
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    /* Step 1: Allocate space for 3 integers */
    int *ptr = malloc(3 * sizeof *ptr);
    if (ptr == NULL)
    {
        printf("Initial allocation failed.\n");
        return 1;
    }

    /* Step 2: Initialize the original 3 elements */
    ptr[0] = 100;
    ptr[1] = 200;
    ptr[2] = 300;

    printf("Original 3 elements:\n");
    for (size_t i = 0; i < 3; i++)
    {
        printf("%d ", ptr[i]);
    }
    printf("\n");

    /* Step 3: Resize allocation to 5 integers using safe temporary pointer */
    int *temp = realloc(ptr, 5 * sizeof *ptr);
    if (temp == NULL)
    {
        printf("Reallocation failed!\n");
        free(ptr); /* Clean up original before exiting */
        return 1;
    }
    ptr = temp; /* Step 4: Safely update pointer */

    /* Step 5: Initialize ONLY the newly added elements */
    ptr[3] = 400;
    ptr[4] = 500;

    /* Step 6: Print all 5 elements to verify original data was preserved */
    printf("After resizing to 5 elements:\n");
    for (size_t i = 0; i < 5; i++)
    {
        printf("%d ", ptr[i]);
    }
    printf("\n");

    /* Step 7: Free the final block */
    free(ptr);
    ptr = NULL;

    return 0;
}

100 200 300 
After resizing to 5 elements:

Zero-Size Realloc Caveat

Do not write realloc(ptr, 0) as a shorthand for free(ptr). Across different C standards (C99, C11, C23) and POSIX revisions, the behavior of zero-size reallocation varies between returning NULL and retaining implementation-defined objects. Always use free(ptr); explicitly to release memory.

Memory Release

08. The free() Function & Dangling Pointer Prevention

free Prototype • <stdlib.h>
#include <stdlib.h>

void free(void *ptr);

Dynamically allocated heap memory does not possess automatic scope-based cleanup. It remains reserved until your code explicitly releases it with free() or the process terminates.

8.1 What free() Does & What It Does NOT Do

  • What it DOES do: It notifies the C runtime heap manager that the contiguous block of bytes starting at ptr is no longer needed. The manager marks that region as available for future allocations.
  • What it DOES NOT do:
    1. It does NOT erase or zero out the data bytes in RAM.
    2. It does NOT change or clear the value stored in the pointer variable ptr! ptr still holds the exact same numerical memory address as before.
    3. It does NOT necessarily return the pages back to the operating system kernel immediately (most allocators retain the chunk to fulfill subsequent allocation requests quickly).

8.2 The Dangling Pointer Hazard

A pointer that still stores the memory address of an object whose lifetime has ended is called a Dangling Pointer.

Dereferencing a Dangling Pointer
int *p = malloc(sizeof *p);
*p = 42;
free(p); /* Block returned to heap */

/* DISASTER: p is now dangling! */
printf("%d\n", *p); /* Undefined behavior: Use-After-Free */

Dereferencing a dangling pointer produces Undefined Behavior (UB). The memory might temporarily seem to hold 42, but as soon as another part of your program calls malloc(), that exact memory address will be overwritten, corrupting your application or crashing with a segmentation fault.

8.3 The Defensive Nullification Pattern

Always immediately reset your pointer to NULL right after freeing it: 

free(ptr);
ptr = NULL; /* Safe: ptr no longer points to invalid memory */

Why is this powerful? In C, passing NULL to free(NULL) is guaranteed to be a harmless no-op. Furthermore, attempting to dereference NULL causes an immediate, clean, predictable crash (segmentation fault) during testing, instead of silently corrupting data in production.

Important caveat: Setting ptr = NULL only clears the specific variable ptr. If your code created alias pointers pointing to that same heap address (e.g., int *alias = ptr;), those aliases remain dangling!

Memory Safety

09. Essential Memory Safety Concepts (The 8 Pitfalls)

In C, you have direct, unmitigated control over the machine's memory. With that power comes the responsibility to avoid the 8 classical memory bugs that plague real-world software.

A. Memory Leak

A Memory Leak occurs when dynamic memory is allocated on the heap, but all pointer references to that memory are lost before calling free(). The memory remains occupied and unusable by the operating system until the entire process terminates.

Analogy: The Lost Storage Locker Key

You rent a commercial storage locker and lock your belongings inside. You then throw the only physical key into a deep river without ending your rental contract. You cannot get your items back, and the warehouse cannot rent the locker to anyone else. You are billed forever.

DO NOT USE: Memory Leak Code
void leakMemory(void) {
    int *data = malloc(1000 * sizeof *data);
    /* Function ends: local pointer 'data' is destroyed on the stack,
       but the 4,000 heap bytes remain allocated forever! */
}
CORRECTED PATTERN
void safeMemory(void) {
    int *data = malloc(1000 * sizeof *data);
    if (data == NULL) return;
    
    /* Process data ... */
    
    free(data); /* Cleanly released before function exit */
    data = NULL;
}

B. Dangling Pointer

A pointer that continues to store the memory address of an object whose lifetime has already ended (such as after free()). Dereferencing it accesses invalid or re-allocated memory.

Prevention Pattern
free(ptr);
ptr = NULL; /* Ensures any subsequent dereference fails immediately */

C. Double Free

Calling free() twice on the exact same allocated pointer address. This corrupts the internal metadata structures (free-lists or bin headers) maintained by the heap allocator, leading to exploitable vulnerabilities or sudden runtime aborts.

DO NOT USE: Double Free
int *p = malloc(10 * sizeof *p);
free(p);
free(p); /* CRASH / HEAP CORRUPTION: p was already freed */

D. Use-After-Free (UAF)

Reading from or writing to a block of memory after calling free() on it. It is one of the most severe security vulnerabilities in computing because attackers can manipulate heap layouts to take over application control flow.

E. Uninitialized Memory

Reading values from a block allocated with malloc() before writing to them. Because malloc() does not clear memory, reading uninitialized values introduces non-deterministic bugs and logic glitches.

Prevention

Either use calloc() if zeroing is desired, or immediately populate all elements with a loop before any read operation.

F. Null Pointer Dereference

Assuming malloc(), calloc(), or realloc() always succeeds without checking whether the returned pointer is NULL. Accessing ptr[0] when ptr == NULL causes an instant OS access violation crash.

G. Out-of-Bounds Access (Buffer Overflow)

Writing or reading beyond the allocated boundaries of a heap chunk. If you allocate space for 5 elements (indices 0 through 4), writing to ptr[5] or ptr[-1] corrupts adjacent heap headers or other application variables.

H. Lost Pointer During realloc()

Writing ptr = realloc(ptr, new_size); directly. If reallocation fails, NULL is returned, instantly erasing your only pointer to the existing memory and causing a guaranteed memory leak. Always use the temporary pointer idiom.

Practical Program

10. Dynamic Arrays Based on User Input

In this complete program, the user specifies at runtime how many floating-point numbers they wish to store. The program rigorously validates input, guards against multiplication overflow, allocates memory dynamically, checks for NULL, computes statistical metrics, and frees memory on all paths:

dynamic_user_array.c 
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h> /* For SIZE_MAX */

int main(void)
{
    long long requested_count = 0;

    printf("Enter number of values to process: ");
    if (scanf("%lld", &requested_count) != 1 || requested_count <= 0)
    {
        printf("Error: Invalid or non-positive count entered.\n");
        return 1;
    }

    size_t n = (size_t)requested_count;

    /* Guard against multiplication overflow */
    if (n > SIZE_MAX / sizeof(double))
    {
        printf("Error: Requested size exceeds addressable memory.\n");
        return 1;
    }

    /* Allocate dynamic array on the heap */
    double *values = malloc(n * sizeof *values);
    if (values == NULL)
    {
        printf("Error: Memory allocation failed!\n");
        return 1;
    }

    /* Read elements from input */
    printf("Enter %zu floating-point numbers:\n", n);
    for (size_t i = 0; i < n; i++)
    {
        if (scanf("%lf", &values[i]) != 1)
        {
            printf("Error reading element %zu. Aborting.\n", i);
            free(values); /* Free memory before error exit */
            return 1;
        }
    }

    /* Process: Compute sum and average */
    double sum = 0.0;
    for (size_t i = 0; i < n; i++)
    {
        sum += values[i];
    }
    double average = sum / (double)n;

    /* Display results */
    printf("\n--- Results ---\n");
    printf("Count:   %zu\n", n);
    printf("Sum:     %.2f\n", sum);
    printf("Average: %.2f\n", average);

    /* Clean up heap storage */
    free(values);
    values = NULL;

    return 0;
}

Real-World Application

11. Real-Life Example: Student Marks Manager

A school examination department needs to record student scores. The number of students varies each semester. Using dynamic memory allocation, we dynamically allocate an array tailored exactly to the class size, validate score ranges (0–100), find the minimum and maximum scores, and calculate class performance:

student_marks_manager.c 
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int numStudents = 0;
    printf("Enter number of enrolled students: ");
    if (scanf("%d", &numStudents) != 1 || numStudents <= 0)
    {
        printf("Invalid student count.\n");
        return 1;
    }

    size_t count = (size_t)numStudents;
    int *marks = malloc(count * sizeof *marks);
    if (marks == NULL)
    {
        printf("Memory allocation failed for student records.\n");
        return 1;
    }

    printf("Enter marks (0 to 100) for each student:\n");
    for (size_t i = 0; i < count; i++)
    {
        int score = 0;
        printf("Student %zu: ", i + 1);
        if (scanf("%d", &score) != 1 || score < 0 || score > 100)
        {
            printf("Invalid score entered! Exiting.\n");
            free(marks);
            return 1;
        }
        marks[i] = score;
    }

    /* Compute Statistics */
    int total = 0;
    int highest = marks[0];
    int lowest = marks[0];

    for (size_t i = 0; i < count; i++)
    {
        total += marks[i];
        if (marks[i] > highest) highest = marks[i];
        if (marks[i] < lowest)  lowest = marks[i];
    }

    double classAverage = (double)total / (double)count;

    printf("\n====================================\n");
    printf("       CLASS PERFORMANCE REPORT     \n");
    printf("====================================\n");
    printf("Total Students: %zu\n", count);
    printf("Class Total:    %d\n", total);
    printf("Class Average:  %.2f\n", classAverage);
    printf("Highest Score:  %d\n", highest);
    printf("Lowest Score:   %d\n", lowest);

    /* Release dynamic memory */
    free(marks);
    marks = NULL;

    return 0;
}

Dynamic Growth

12. Real-Life Example: Dynamic Shopping Cart (Capacity Growth)

In modern web services and e-commerce applications, a customer adds items to their shopping cart one at a time. The program cannot know in advance how many products the user will choose.

12.1 The Three Crucial Metrics

  • Length (Size): The number of actual items currently stored in the cart.
  • Capacity: The maximum number of items the currently allocated memory block can hold without needing a resize.
  • Allocated Bytes: The physical heap memory consumed: Capacity * sizeof(Item).
Capacity Doubling Strategy

Instead of resizing by 1 item every single time (which causes expensive heap copying on every addition), standard libraries and dynamic arrays double their capacity when full (e.g., 2 → 4 → 8 → 16). This yields amortized \(O(1)\) constant time insertion!

dynamic_shopping_cart.c 
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

typedef struct {
    int *items;      /* Pointer to heap array of product IDs */
    size_t length;   /* Current count of items in cart */
    size_t capacity; /* Total slots allocated on heap */
} ShoppingCart;

int addToCart(ShoppingCart *cart, int productID) {
    if (cart->length == cart->capacity) {
        /* Array is full: double the capacity */
        size_t newCapacity = (cart->capacity == 0) ? 2 : cart->capacity * 2;

        /* Guard against overflow */
        if (newCapacity > SIZE_MAX / sizeof(int)) return 0;

        int *temp = realloc(cart->items, newCapacity * sizeof(int));
        if (temp == NULL) {
            fprintf(stderr, "Failed to expand cart memory!\n");
            return 0; /* Original cart remains safe */
        }
        cart->items = temp;
        cart->capacity = newCapacity;
        printf("[Resize] Capacity doubled to: %zu slots\n", cart->capacity);
    }

    cart->items[cart->length] = productID;
    cart->length++;
    return 1;
}

int main(void) {
    ShoppingCart cart = {NULL, 0, 0};

    printf("Adding products to shopping cart:\n");
    addToCart(&cart, 101); /* Product ID 101 */
    addToCart(&cart, 204); /* Product ID 204 */
    addToCart(&cart, 305); /* Triggers expansion */
    addToCart(&cart, 409); 
    addToCart(&cart, 512); /* Triggers expansion */

    }

    free(cart.items);
    cart.items = NULL;
    cart.length = 0;
    cart.capacity = 0;

        current = current->next;

    printf("NULL\n");

    free(second);
    free(first);
    first = NULL;
    second = NULL;

}

17. Practice Level 1: Beginner Fundamentals

Master the core concepts of runtime heap allocation, function prototypes, and pointer checking. Click each question to reveal the full answer and explanation.

Q1: What is Dynamic Memory Allocation (DMA), and what core problem does it solve in C?
ANSWER

Dynamic Memory Allocation is the process of requesting memory from the system's heap segment at runtime (while the program is running), rather than fixing all array and buffer sizes at compile time.

Problem it solves: It prevents memory wastage (over-allocating for the worst case) and prevents fatal buffer overflows (allocating too little memory when user input or data exceeds expectations).

Q2: What does malloc() do, and what type of pointer does it return?
ANSWER

malloc(size_t size) requests a single contiguous block of size bytes from the heap. It returns a generic pointer of type void * pointing to the first byte of the allocated memory block on success, or NULL if memory allocation fails.

Q3: Why is #include <stdlib.h> mandatory when using malloc(), calloc(), realloc(), or free()?
ANSWER

<stdlib.h> contains the official function prototypes for these memory functions and defines the NULL macro and the size_t type. Without it, older compilers assume functions return int, which truncates 64-bit memory addresses to 32 bits, causing catastrophic segmentation faults on modern operating systems.

Q4: What is the key difference between malloc() and calloc()?
ANSWER
  • malloc(size) takes 1 argument (total bytes) and leaves the allocated memory uninitialized (containing indeterminate garbage values).
  • calloc(num, size) takes 2 arguments (element count and element size) and initializes every allocated byte to all-bits-zero (0).
Q5: Why must a program always check if (ptr == NULL) after an allocation call?
ANSWER

Physical and virtual memory are finite. If the system is out of RAM or the requested block size exceeds address space limits, the allocation function returns NULL. If the program attempts to read or write to ptr when it is NULL (dereferencing address 0x0), the operating system immediately terminates the program with a Segmentation Fault (Access Violation).

Q6: What does free(ptr) do, and what happens if a program never calls it?
ANSWER

free(ptr) informs the runtime heap manager that the memory block starting at ptr is no longer needed, allowing it to be recycled for future allocations.

If a program fails to call free(), it creates a Memory Leak. The process consumes more and more RAM over time until the system runs out of memory, slowing down or crashing the host machine.

Q7: Identify the memory leak in this code snippet and provide the corrected version:
void compute(void) { int *arr = malloc(10 * sizeof *arr); /* do work */ return; }
ANALYSIS & FIX

The Leak: When compute() returns, the local pointer variable arr on the stack is destroyed, but the 40 bytes on the heap remain allocated with no remaining pointer to reach or free them.

Corrected Version:

void compute(void) {
    int *arr = malloc(10 * sizeof *arr);
    if (arr == NULL) return;

    /* do work ... */

    free(arr);   /* Release memory before returning */
    arr = NULL;
}
Q8: If you allocate memory using int *ptr = malloc(5 * sizeof *ptr);, why is accessing ptr[5] invalid?
ANSWER

In C, arrays and contiguous memory blocks are 0-indexed. An allocation of 5 elements provides valid indices ptr[0], ptr[1], ptr[2], ptr[3], and ptr[4]. ptr[5] represents the 6th element, which lies strictly outside the allocated boundary. Writing to it causes a Buffer Overflow, corrupting neighboring heap chunks.

Q7: Explain the dry run of allocating 3 integers, writing values [10, 20, 30], and doubling the block to 6 integers.
DRY RUN BREAKDOWN
  1. malloc(3 * sizeof(int)) assigns a 12-byte block at heap address $A$.
  2. Slots $0, 1, 2$ are written with 10, 20, and 30.
  3. realloc(ptr, 6 * sizeof(int)) checks if 12 additional contiguous bytes exist after address $A$.
  4. If yes, the boundary moves to 24 bytes (in-place). If no, a new 24-byte block is carved at address $B$, values 10, 20, 30 are copied, block $A$ is freed, and address $B$ is returned.
  5. Slots $3, 4, 5$ contain uninitialized bits until explicitly written.
Q8: Why is free(ptr); ptr = NULL; safer than just free(ptr); alone?
SAFETY ANALYSIS

Calling free(ptr) frees the memory block, but leaves the variable ptr containing the old numerical address (a dangling pointer). If code accidentally dereferences ptr later, it reads wild data. Setting ptr = NULL ensures that any subsequent dereference triggers an instant, catchable crash at address 0 during testing, and calling free(NULL) is safely ignored by C.

19.1 Problem 1: Amortized Constant-Time Dynamic Array (Vector)

Implement a self-resizing dynamic integer array with separate size and capacity that doubles when full:

dynamic_vector.c 
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;
    size_t size;
    size_t capacity;
} IntVector;

void vectorInit(IntVector *vec, size_t initialCapacity) {
    vec->size = 0;
    vec->capacity = initialCapacity > 0 ? initialCapacity : 2;
    vec->data = malloc(vec->capacity * sizeof *(vec->data));
}

void vectorPush(IntVector *vec, int value) {
    if (vec->data == NULL) return;
    if (vec->size == vec->capacity) {
        size_t newCap = vec->capacity * 2;
        int *temp = realloc(vec->data, newCap * sizeof *(vec->data));
        if (temp == NULL) {
            fprintf(stderr, "Vector resize failed!\n");
            return;
        }
        vec->data = temp;
        vec->capacity = newCap;
    }
    vec->data[vec->size++] = value;
}

void vectorFree(IntVector *vec) {
    free(vec->data);
    vec->data = NULL;
    vec->size = 0;
    vec->capacity = 0;
}

int main(void) {
    IntVector vec;
    vectorInit(&vec, 2);

    for (int i = 1; i <= 5; i++) {
        vectorPush(&vec, i * 11);
    }

    printf("Vector elements (Size: %zu, Capacity: %zu):\n", vec.size, vec.capacity);
    for (size_t i = 0; i < vec.size; i++) {
        printf("%d ", vec.data[i]);
    }
    printf("\n");

    vectorFree(&vec);
    return 0;
}

#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int id;
    int quantity;
    double unitPrice;
} Product;

    Product *records;
    size_t count;
    size_t capacity;

int addProduct(Inventory *inv, int id, int qty, double price) {
    if (inv->count == inv->capacity) {
        size_t newCap = (inv->capacity == 0) ? 2 : inv->capacity * 2;
        Product *temp = realloc(inv->records, newCap * sizeof *temp);
        if (temp == NULL) {
            fprintf(stderr, "Failed to resize inventory memory!\n");
            return 0;
        }
        inv->records = temp;
        inv->capacity = newCap;
    }

    inv->records[inv->count].id = id;
    inv->records[inv->count].quantity = qty;
    inv->records[inv->count].unitPrice = price;
    inv->count++;
    return 1;
}

void displayInventory(const Inventory *inv) {
    printf("\n%-8s %-12s %-12s %-12s\n", "ID", "Quantity", "Unit Price", "Total Value");
    printf("---------------------------------------------------\n");

        grandTotal += itemTotal;

               inv->records[i].id, 
               inv->records[i].quantity, 
               inv->records[i].unitPrice, 
               itemTotal);
    }
    printf("---------------------------------------------------\n");
    printf("TOTAL INVENTORY VALUATION: $%.2f\n", grandTotal);
}

int findProduct(const Inventory *inv, int targetID) {
    for (size_t i = 0; i < inv->count; i++) {
        if (inv->records[i].id == targetID) {
            return (int)i;
        }
    }
    return -1;
}

12 High-Yield Technical Viva Questions

1. What is the fundamental difference between stack and heap memory in C?
VIVA ANSWER

The stack manages local variables with automatic storage duration; memory is allocated and freed automatically as function calls push and pop stack frames. The heap provides dynamically allocated memory requested at runtime via malloc/calloc; its lifetime is controlled manually by the programmer and persists until free() is called.

2. Why is casting the result of malloc() unnecessary in C?
VIVA ANSWER

In standard C, a void * pointer implicitly and safely converts to any object pointer type without an explicit cast. Omission of the cast keeps the code clean and prevents masking the bug of forgetting to include <stdlib.h>.

3. What happens if malloc() cannot fulfill a memory request?
VIVA ANSWER

It returns NULL. If code attempts to access this returned pointer without checking, a segmentation fault (access violation crash) occurs.

4. What is a Memory Leak?
VIVA ANSWER

A memory leak occurs when dynamically allocated heap memory loses all pointer references before being released with free(). The memory remains occupied and unusable until the entire process terminates.

5. What is a Dangling Pointer?
VIVA ANSWER

A dangling pointer is a pointer that still holds the memory address of an object after that object's lifetime has ended (such as after free(ptr)). Dereferencing it leads to undefined behavior or security vulnerabilities.

6. Why is it recommended to set ptr = NULL; immediately after free(ptr);?
VIVA ANSWER

It neutralizes the dangling pointer. Any subsequent accidental dereference will cause an immediate, clean crash at address 0 during testing, and calling free(NULL) is guaranteed to be safe and harmless.

7. Why should you never write ptr = realloc(ptr, new_size); directly?
VIVA ANSWER

If realloc() fails, it returns NULL. Assigning NULL directly to ptr overwrites your only reference to the original memory block, causing an irrecoverable memory leak. Always assign to a temporary pointer first.

8. What is a Double Free error?
VIVA ANSWER

A double free occurs when free() is called twice on the exact same memory address without an intervening allocation. It corrupts the heap allocator's internal metadata structures, causing crashes or exploitable security holes.

9. Can you call free() on a pointer pointing to the stack (e.g., int x; free(&x);)?
VIVA ANSWER

No! Passing a pointer that was not returned by malloc, calloc, realloc, or that is not NULL invokes severe undefined behavior and crashes the runtime allocator.

10. Does free() erase the data inside the memory block?
VIVA ANSWER

No. free() merely marks the block as available in the allocator's free list; the existing data bytes typically remain untouched in physical RAM until overwritten by a subsequent allocation.

11. Why is sizeof *ptr safer than sizeof(type)?
VIVA ANSWER

Because sizeof *ptr automatically tracks the type of the pointer variable. If the pointer's declaration type changes in the future, the allocation size automatically updates without manual editing.

12. What is the difference between Array Length and Array Capacity?
VIVA ANSWER

Length is the count of actual active elements currently stored in the array. Capacity is the total number of element slots allocated in heap memory before a resize is required.
