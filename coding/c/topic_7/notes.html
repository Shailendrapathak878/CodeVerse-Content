Introduction to Conditional Statements & Decision Making

By default, a C program executes line by line from top to bottom in strict linear sequence. However, real-world software cannot be a simple one-way street. Programs must evaluate situations, test conditions, and choose different pathways dynamically—just like a human driver responding to traffic lights.

What is a Conditional Statement in C?

A conditional statement (or decision-making statement) is a control-flow construct that tests an expression (the condition) and determines which block of code to execute based on whether that condition evaluates to true or false.

What Does "True" and "False" Mean in C?

Unlike newer languages that have a mandatory separate Boolean primitive, C historically handles truth through numerical integer scalar values:

C Value / Expression Truthiness Interpretation C Program Execution Behavior
0 (Zero) FALSE The conditional block is skipped.
1 (Or ANY non-zero number) TRUE The conditional block is executed. (e.g. 5, -42, 100 are all True!).
Relational / Logical Result 1 (True) or 0 (False) Operators like >=, ==, && generate integer 1 if satisfied, 0 otherwise.
Real-Life Analogy: Student Exam Result

Think of grading an exam paper:

  • Condition: "Are the student's marks at least 40?" (marks >= 40).
  • If True (Marks = 65): Mark the report card as "Pass".
  • If False (Marks = 32): Mark the report card as "Fail".
if (marks >= 40) { printf("Pass"); }

The Simple if Statement

The if statement is the most fundamental decision-making construct in C. It represents a one-way decision: if the test condition is true, execute the block; if false, do nothing and continue.

Syntax of the if Statement:
if (condition)
{
    /* Statements executed ONLY when condition is TRUE */
}
  • The condition must always be enclosed in mandatory parentheses ().
  • If the condition evaluates to non-zero (True), the statements inside the braces {} execute.
  • If the condition evaluates to zero (False), the entire block is bypassed.

Example 1: True Condition (Voting Eligibility)

In this program, age is 20, which is greater than or equal to 18:

if_voting_true.c 
#include <stdio.h>

int main(void)
{
    int age = 20;

    /* Condition: 20 >= 18 evaluates to 1 (True) */
    if (age >= 18)
    {
        printf("You are eligible to vote.\n");
    }

    return 0;
}
Exact Expected Output:
You are eligible to vote.

Example 2: False Condition (Block is Skipped)

Now observe what happens when age is 15:

if_voting_false.c 
#include <stdio.h>

int main(void)
{
    int age = 15;

    /* Condition: 15 >= 18 evaluates to 0 (False) */
    if (age >= 18)
    {
        printf("You are eligible to vote.\n");
    }

    printf("Program finished successfully.\n");
    return 0;
}
Exact Expected Output:
Program finished successfully.

Notice that "You are eligible to vote." was NOT printed because the condition was false. Execution jumped directly to the next statement outside the block.

The Two-Way if-else Statement

When an application must choose between two mutually exclusive alternatives (e.g. Pass or Fail, Even or Odd, Access Granted or Access Denied), C provides the two-way if-else construct. Exactly one branch is guaranteed to execute.

Syntax of if-else:
if (condition)
{
    /* Executes if condition is TRUE (non-zero) */
}
else
{
    /* Executes if condition is FALSE (zero) */
}

Example 1: Pass or Fail Grade Threshold

if_else_pass_fail.c 
#include <stdio.h>

int main(void)
{
    int marks = 35;

    /* 35 >= 40 evaluates to 0 (False), so the else block executes */
    if (marks >= 40)
    {
        printf("Pass\n");
    }
    else
    {
        printf("Fail\n");
    }

    return 0;
}
Exact Expected Output:
Fail

Example 2: Even or Odd Number Checker

Using the remainder operator %, a number is even if dividing by 2 leaves a remainder of 0; otherwise it is odd:

if_else_even_odd.c 
#include <stdio.h>

int main(void)
{
    int number = 17;

    if (number % 2 == 0)
    {
        printf("%d is Even.\n", number);
    }
    else
    {
        printf("%d is Odd.\n", number);
    }

    return 0;
}
Exact Expected Output:
17 is Odd.

The Multi-Way else-if Ladder

When an application must test across three or more mutually exclusive possibilities (such as assigning letter grades, evaluating tax brackets, or classifying temperatures), C provides the else-if ladder.

Syntax of the else-if Ladder:
if (condition1)
{
    /* Executes if condition1 is TRUE */
}
else if (condition2)
{
    /* Executes if condition1 was FALSE and condition2 is TRUE */
}
else if (condition3)
{
    /* Executes if conditions 1 & 2 were FALSE and condition3 is TRUE */
}
else
{
    /* Default catch-all: executes if ALL conditions above were FALSE */
}

Execution Mechanics of the Ladder:

  1. Top-to-Bottom Evaluation: Conditions are tested sequentially in the exact order written.
  2. First Match Wins: As soon as one condition evaluates to True, its associated block executes.
  3. Early Exit: Once a block executes, all remaining else-if and else blocks are completely bypassed!
  4. Optional Final else: The final else is optional. It functions as a safe catch-all when none of the conditions match.

Real-Life Example: Student Grading System

Consider this standard illustrative academic grading scale (note: this is an educational reference, not a universal institutional policy):

  • 90 or above: Grade A
  • 75 to 89: Grade B
  • 60 to 74: Grade C
  • 40 to 59: Grade D
  • Below 40: Fail
else_if_grading_ladder.c 
#include <stdio.h>

int main(void)
{
    int marks = 78;

    printf("Student Marks: %d\n", marks);

    if (marks >= 90)
    {
        printf("Result: Grade A (Outstanding)\n");
    }
    else if (marks >= 75)
    {
        printf("Result: Grade B (Very Good)\n");
    }
    else if (marks >= 60)
    {
        printf("Result: Grade C (Good)\n");
    }
    else if (marks >= 40)
    {
        printf("Result: Grade D (Satisfactory)\n");
    }
    else
    {
        printf("Result: Fail (Needs Improvement)\n");
    }

    return 0;
}
Exact Expected Output:
Student Marks: 78
Result: Grade B (Very Good)
CRITICAL LOGIC RULE: Why the Highest Threshold Must Be Checked First!

Notice why we checked marks >= 90 first, then >= 75, and so on. If you inverted the ladder and wrote:

if (marks >= 40) { printf("Grade D"); } /* DISASTROUS LOGIC BUG */
else if (marks >= 90) { printf("Grade A"); }

If a genius student scored 98, the first check (98 >= 40) is True! The program would print Grade D and skip the rest of the ladder! Always arrange overlapping numeric thresholds from most restrictive to least restrictive.

Nested if Statements & Dependent Choices

Real-world decisions are frequently hierarchical: a second choice only becomes relevant after an initial qualifying condition has passed. When an if statement is placed entirely inside another if or else block, it is called a nested if statement.

What is Nesting?

Nesting means enclosing one control structure inside the body of another. The inner if statement is only reached and tested if the outer enclosing condition evaluates to true.

Real-Life Example: Merit-Cum-Means Scholarship

Consider an illustrative university scholarship award rule:

  1. First requirement: Student must achieve at least 80% marks.
  2. Second requirement (only if academic requirement is met): Annual family income must be below ₹3,00,000.
nested_if_scholarship.c 
#include <stdio.h>

int main(void)
{
    int marks = 85;
    int familyIncome = 240000; /* in INR */

    printf("Student Marks: %d%%, Family Income: INR %d\n", marks, familyIncome);

    /* Outer Condition: Academic Merit Check */
    if (marks >= 80)
    {
        /* Inner Condition: Financial Need Check */
        if (familyIncome < 300000)
        {
            printf("Status: APPROVED - Eligible for Full Scholarship.\n");
        }
        else
        {
            printf("Status: DENIED - Academic merit satisfied, but family income exceeds limit.\n");
        }
    }
    else
    {
        printf("Status: DENIED - Marks are below the required 80%% threshold.\n");
    }

    return 0;
}
Exact Expected Output:
Student Marks: 85%, Family Income: INR 240000
Status: APPROVED - Eligible for Full Scholarship.

The "Dangling Else" Trap in Nested Code: In C, an else always pairs with the closest unmatched preceding if within the same block scope. Always use explicit braces { } around outer and inner blocks so your code structure is unmistakably clear to the compiler and future engineers!
📚 Section 07 • Section F

The switch Statement & Fall-Through Mechanics

When a program must branch based on comparing a single integer expression against a fixed list of known constant values (such as selecting options from an interactive terminal menu), the switch statement provides a clean, elegant alternative to lengthy ladders.

Syntax of the switch Statement:
switch (integer_expression)
{
    case constant1:
        /* statements */
        break;
    case constant2:
        /* statements */
        break;
    default:
        /* optional default statements */
}

Standard C Rules for switch

  • Integer Types Only: The switch expression must evaluate to an integer type (int, char, short, long, or enum). Floating-point numbers (float, double) and strings are STRICTLY ILLEGAL in C switch statements!
  • Constant Case Labels: Each case label must be an integer constant expression (e.g. case 1:, case 'Q':, case 10 + 2:). You cannot write variables in case labels (e.g. case myVar: is invalid).
  • The break Statement: Stops execution inside the switch body and jumps immediately to the closing brace. Without break, execution falls through into subsequent cases!
  • The default Label: An optional catch-all that executes if no case label matches the expression value.

Real-Life Example: ATM Banking Console Menu

switch_banking_menu.c 
#include <stdio.h>

int main(void)
{
    int choice = 2; /* Simulated user input */

    printf("Selected Menu Option: %d\n", choice);

    switch (choice)
    {
        case 1:
            printf("Action: Displaying Current Account Balance...\n");
            break;

        case 2:
            printf("Action: Preparing Deposit Portal...\n");
            break;

        case 3:
            printf("Action: Dispensing Cash Withdrawal...\n");
            break;

        case 4:
            printf("Action: Session Ended. Goodbye!\n");
            break;

        default:
            printf("Error: Invalid selection! Please enter a choice between 1 and 4.\n");
            break;
    }

    return 0;
}
Exact Expected Output:
Selected Menu Option: 2
Action: Preparing Deposit Portal...
Understanding "Fall-Through" in switch:

If you omit the break statement after a case block, C will fall through and execute the code in the following case unconditionally, regardless of whether that case matches!

Intentional Fall-Through Example (Grouping Vowels):
case 'A': case 'E': case 'I': case 'O': case 'U': printf("Vowel"); break;
Here, stacking case labels deliberately shares a single action. But accidentally omitting break between distinct options is one of the most common beginner bugs in C!

📚 Section 08 • Section G

Conditional Operator (?:) vs. Statements

Beginners often ask: "When should I write an if-else statement, and when should I use the ternary operator (?:)?" Understanding the architectural difference between a statement and an expression is key.

Construct Best Suited For Code Example
Simple if A single optional action when a condition is met. if (score > highScore) highScore = score;
Two-Way if-else Choosing between two alternative execution blocks. if (balance >= bill) pay(); else reject();
else-if Ladder Testing multiple sequential ranges or conditions. if (m >= 90) .. else if (m >= 75) ..
Nested if Hierarchical decisions where choice B depends on A. if (hasAccount) { if (validPIN) .. }
switch Statement Branching among multiple discrete constant integers/chars. switch (choice) { case 1: .. break; }
Ternary (?:) Compact inline selection of an evaluated value. int max = (a > b) ? a : b;

Side-by-Side Comparison

Approach A: if-else Statement
int max;
if (a > b)
{
    max = a;
}
else
{
    max = b;
}

A control statement consisting of multiple branches and assignments.

Approach B: Ternary ?: Expression
int max = (a > b) ? a : b;

An expression that computes and yields a value directly on the right-hand side.

Combining Conditions with Logical Operators (&&, ||, !)

Instead of nesting multiple if statements, C allows you to combine multiple relational tests into a single elegant expression using logical operators.

Operator Meaning Required Condition C Example
&& Logical AND True only if ALL sub-conditions are true. marks >= 40 && attendance >= 75
|| Logical OR True if AT LEAST ONE sub-condition is true. isMember == 1 || hasCoupon == 1
! Logical NOT Inverts truth value (True → False, False → True). !isBlocked

Example 1: Logical AND (&&) — University Exam Eligibility

logical_and_exam.c 
#include <stdio.h>

int main(void)
{
    int marks = 65;
    int attendance = 80;

    /* Both conditions must evaluate to True (1) */
    if (marks >= 40 && attendance >= 75)
    {
        printf("Eligible for exam.\n");
    }
    else
    {
        printf("Not eligible for exam.\n");
    }

    return 0;
}
Exact Expected Output:
Eligible for exam.

Example 2: Logical OR (||) — Store Discount Qualification

A customer receives a special 15% discount if they are either a registered premium member OR possess a valid promotional coupon code:

logical_or_discount.c 
#include <stdio.h>

int main(void)
{
    int isRegisteredMember = 0; /* Not a member */
    int hasPromoCoupon = 1;     /* Has coupon */

    /* Either condition is sufficient to qualify */
    if (isRegisteredMember == 1 || hasPromoCoupon == 1)
    {
        printf("Discount applied: 15%% OFF your order!\n");
    }
    else
    {
        printf("Standard billing: Regular pricing applies.\n");
    }

    return 0;
}
Exact Expected Output:
Discount applied: 15% OFF your order!

Truthiness in C & Diagnostic Fixes for Common Traps

Mastering conditional logic requires understanding how C treats raw numbers inside if statements, and learning to spot the subtle syntax mistakes that confound beginners.

The Golden Rule of C Truthiness:

ZERO is FALSE. EVERYTHING ELSE IS TRUE.

  • if (0) → Never executes (0 is False).
  • if (5) → Always executes (5 is non-zero, hence True).
  • if (-42) → Always executes (even negative numbers are non-zero, hence True!).
  • Under ISO C (C99 and later), <stdbool.h> provides standard aliases: bool, true (1), and false (0).

Common Beginner Traps & How to Fix Them

Trap / Mistake Flawed Code & Why It Fails Corrected Code & Fix
1. Assignment instead of Equality if (x = 5)
Legal C, but unintended! Assigns 5 to x; evaluates to 5 (non-zero → always True!).		 if (x == 5)
Tests equality without modifying x.
2. Semicolon after condition if (age >= 18);
{ printf("Vote"); }
Semicolon forms empty statement! The block executes unconditionally!		 if (age >= 18)
{ printf("Vote"); }
Remove the stray semicolon after the closing parenthesis.
3. Missing braces with multiple lines if (pass)
  printf("Passed");
  printf("Congratulate!");
Second line runs even if pass is False!		 if (pass)
{
  printf("Passed");
  printf("Congratulate!");
}
4. Confusing && and || if (ch >= 'a' || ch <= 'z')
Always True for every ASCII character!		 if (ch >= 'a' && ch <= 'z')
Use AND to test within a bounded range.
5. Dangling else mismatch Assuming an else attaches to outer if when braces are omitted. Wrap outer and inner blocks in explicit braces { } to guarantee correct pairing.
6. Overlapping ranges in wrong order Checking marks >= 40 before marks >= 90 in an else-if ladder. Order conditions from highest/strictest threshold down to lowest.
7. Forgetting break in switch Accidental fall-through cascades into all remaining cases. Add break; at the end of every distinct case block.
8. Using strings/floats in switch switch (name) or case 3.14:
Compile Error! C switch only supports integer types.		 Use an if-else ladder with strcmp() for strings or comparison for floats.

Program 1: Citizen Voting Eligibility Checker

Problem Statement: Check whether an applicant meets the legal voting age requirement (18 years), and if underage, calculate how many years remain until eligibility.

program1_voting.c 
#include <stdio.h>

int main(void)
{
    int applicantAge = 16;
    const int VOTING_AGE = 18;

    printf("Applicant Age: %d years\n", applicantAge);

    if (applicantAge >= VOTING_AGE)
    {
        printf("Status: APPROVED - You are eligible to cast your vote.\n");
    }
    else
    {
        int yearsLeft = VOTING_AGE - applicantAge;
        printf("Status: NOT ELIGIBLE - Please wait %d more year(s) to register.\n", yearsLeft);
    }

    return 0;
}
Exact Expected Output:
Applicant Age: 16 years
Status: NOT ELIGIBLE - Please wait 2 more year(s) to register.

Program 6: Menu-Driven Calculator with Zero-Division Guard

Problem Statement: Build a menu-driven arithmetic calculator using switch, complete with defensive guards against zero denominator crashes.

program6_switch_calculator.c 
#include <stdio.h>

int main(void)
{
    int option = 4; /* Division */
    double a = 50.0;
    double b = 8.0;

    printf("Calculator Operation #%d with Operands: %.1f and %.1f\n", option, a, b);

    switch (option)
    {
        case 1:
            printf("Result: %.2f + %.2f = %.2f\n", a, b, a + b);
            break;

        case 2:
            printf("Result: %.2f - %.2f = %.2f\n", a, b, a - b);
            break;

        case 3:
            printf("Result: %.2f * %.2f = %.2f\n", a, b, a * b);
            break;

        case 4:
            if (b != 0.0)
            {
                printf("Result: %.2f / %.2f = %.2f\n", a, b, a / b);
            }
            else
            {
                printf("Error: Division by zero is mathematically undefined!\n");
            }
            break;

        default:
            printf("Error: Invalid calculator menu option!\n");
            break;
    }

    return 0;
}
Exact Expected Output:
Calculator Operation #4 with Operands: 50.0 and 8.0
Result: 50.00 / 8.00 = 6.25

📚 Section 13 • Section L

Comparing Conditional Constructs & Selection Guide

Software architecture requires selecting the right tool for the job. Use this definitive architectural comparison matrix and decision guide whenever designing conditional logic.

Construct Primary Purpose Main Advantage Limitation / Common Pitfall
Simple if One-way optional action. Simplest syntax; zero overhead. Missing braces can cause dangling statements.
Two-Way if-else Two mutually exclusive branches. Guarantees exactly one path executes. Becomes clumsy if expanded to 4+ outcomes.
else-if Ladder Multiple sequential range tests. Flexible; handles ranges, inequalities, and floats. Order matters critically; misplaced order causes logic bugs.
Nested if Hierarchical dependent decisions. Models real-world prerequisite workflows. Deep nesting (>3 levels) impairs code readability.
switch Statement Discrete constant multi-branching. Highly readable menu logic; compiler jump-table optimization. Only supports integer types; requires manual break.
Ternary (?:) Compact inline value selection. Returns an evaluated value directly in expressions. Hard to read and unmaintainable when nested deeply.
👉 Algorithmic Selection Guide: How to Pick Your Construct
• Exactly 1 optional decision? → Use if
• Exactly 2 mutually exclusive choices? → Use if-else

MCQ 1: What value does C consider as False inside an if condition?

Options:

  • (A) Any negative number
  • (B) Exactly integer 0
  • (C) NULL string only
  • (D) Any number below 10
Correct Answer: (B) Exactly integer 0

Explanation: In C, zero evaluates to False, while any non-zero value (including positive and negative numbers) evaluates to True.

MCQ 2: What is the output of if (-5) printf("Hello"); else printf("Bye");?

Options:

  • (A) Hello
  • (B) Bye
  • (C) Compilation Error
  • (D) Nothing is printed
Correct Answer: (A) Hello

Explanation: In C, any non-zero value is treated as True. Since -5 != 0, the condition evaluates to True, printing "Hello".

MCQ 3: What happens in if (x = 0) printf("True"); else printf("False");?

Options:

  • (A) Prints "True"
  • (B) Prints "False"
  • (C) Compiler syntax error
  • (D) Crashes at runtime
Correct Answer: (B) Prints "False"

Explanation: Single equals = is assignment. It assigns 0 to x. The expression evaluates to 0 (False), so the else branch executes.

MCQ 4: What is the effect of placing a semicolon immediately after if (a > b);?

Options:

  • (A) It terminates the if condition with an empty statement, so the following block executes unconditionally
  • (B) It causes a fatal compilation error
  • (C) It inverts the condition from true to false
  • (D) It makes the condition execute faster
Correct Answer: (A)

Explanation: The semicolon creates a null statement. The if attaches to this empty statement, leaving subsequent braced or unbraced blocks to execute unconditionally.

MCQ 5: How does an else-if ladder evaluate its conditions?

Options:

  • (A) All conditions are evaluated simultaneously
  • (B) Top-to-bottom sequentially; once a condition is True, remaining conditions are skipped
  • (C) Bottom-to-top in reverse order
  • (D) In random order determined by the compiler optimizer
Correct Answer: (B)

Explanation: C evaluates the ladder top-to-bottom. The first condition that evaluates to True executes its block and bypasses all subsequent else-if and else blocks.

MCQ 6: In nested if statements without braces, which if does an else pair with?

Options:

  • (A) The outermost if
  • (B) The nearest preceding unmatched if in the same block
  • (C) Any random if matching the indentation
  • (D) It causes an automatic compile error
Correct Answer: (B)

Explanation: Under the standard C grammar rule, an else always pairs with the closest preceding unmatched if within the same lexical scope.

MCQ 7: Which data types are strictly ILLEGAL as the controlling expression in a C switch?

Options:

  • (A) int and char
  • (B) float, double, and strings
  • (C) short and enum
  • (D) long int
Correct Answer: (B) float, double, and strings

Explanation: The C standard requires the switch controlling expression and case labels to be integer types. Floating-point numbers and strings are syntax errors.

MCQ 8: What happens in a switch statement if the break statement is omitted after a case?

Options:

  • (B) Execution falls through into the next case unconditionally
  • (C) Compiler generates a fatal syntax error
  • (D) Switch restarts from the beginning
Correct Answer: (B)

Explanation: Without break, execution cascades into following case blocks regardless of whether their labels match (fall-through).

MCQ 9: Can a case label inside a C switch contain a variable (e.g. case x:)?

Options:

  • (A) Yes, any integer variable is allowed
  • (B) No, case labels must be compile-time integer constant expressions
  • (C) Yes, if declared as const int
  • (D) Only in GCC compiler mode
Correct Answer: (B)

Explanation: In standard C, case labels must evaluate to compile-time integer constants (literals, macros, or integer expressions of constants). Ordinary variables are rejected.

MCQ 10: In an if-else ladder testing marks for grades, what occurs if marks >= 40 is placed before marks >= 90?

  • (B) A student with marks 95 will match >= 40 first and incorrectly receive the lowest passing grade
  • (C) The compiler flags a duplicate range error
  • (D) The program enters an infinite loop
Correct Answer: (B)

Explanation: Because ladders exit upon the first matching True condition, 95 satisfies >= 40, executing the lower grade block and bypassing >= 90.

MCQ 11: Which header file provides standard bool, true, and false in modern standard C (C99+)?

  • (C) <cbool.h>
  • (D) <logic.h>

Explanation: Standard C (ISO/IEC 9899:1999 onwards) defines bool, true (1), and false (0) in <stdbool.h>.

MCQ 12: Is the default: label mandatory inside a C switch statement?

Options:

  • (A) Yes, every switch must have a default label
  • (B) No, it is optional; if omitted and no cases match, switch simply terminates
  • (C) Only mandatory if there are more than 3 cases
  • (D) Mandatory only in embedded systems
Correct Answer: (B) No, it is optional

Explanation: The default: label is optional in standard C. If omitted and no case matches, execution skips past the switch closing brace.

MCQ 13: What is the primary advantage of the ternary operator ?: over if-else?

Options:

  • (A) It can execute multiple loops simultaneously
  • (B) It is an expression that yields a value directly on the right-hand side of assignments
  • (C) It runs faster than any CPU branch instruction
  • (D) It works with strings and arrays directly
Correct Answer: (B)

Explanation: Because ?: is an expression, it evaluates to a return value that can be directly assigned or passed into functions: int x = (a > b) ? a : b;.

MCQ 14: What does short-circuit evaluation guarantee in if (a != 0 && 100 / a > 5)?

Options:

  • (A) If a == 0, the division 100 / a is never evaluated, preventing a fatal crash
  • (B) Both conditions are evaluated simultaneously in parallel
  • (C) The division runs first before checking a != 0
  • (D) It forces the compiler to replace a with 1
Correct Answer: (A)

Explanation: Logical && evaluates left-to-right. If the left side (a != 0) is false, the right side is completely skipped, protecting against division by zero.

MCQ 15: Which statement about if (condition) is TRUE when braces {} are omitted?

Explanation: C ignores visual indentation. Without braces, only the single immediate statement forms the body of the if.

Part 2: Short-Answer Questions (8 SAQs)

SAQ 1: What is the fundamental purpose of conditional statements in C?
Answer: Conditional statements allow a program to branch its execution flow dynamically based on testing whether an expression evaluates to true (non-zero) or false (zero), enabling decision-making.
SAQ 2: Explain why zero represents False and non-zero represents True in C.
Answer: C handles Boolean logic at the scalar hardware level: integer value 0 represents False, while any non-zero value (such as 1, 5, -42) evaluates to True in conditional tests.
SAQ 3: Why should programmers always write curly braces { } even for single-line if statements?
Answer: To prevent "dangling statement" bugs. Without braces, if an engineer later adds a second line intended to be inside the condition, it will execute unconditionally regardless of the condition!
SAQ 4: What is the purpose of the default: label in a switch statement?
Answer: It provides a fallback catch-all action that executes if the controlling expression does not match any of the defined constant case labels.
SAQ 5: How does accidental fall-through occur in a switch statement?
Answer: If the programmer forgets to write a break; statement at the end of a case block, C cascades execution directly into the subsequent case block unconditionally.
SAQ 6: Why cannot floating-point numbers (float, double) be used in C switch cases?
Answer: switch is designed around exact discrete integer equality (often optimized via jump tables). Due to IEEE 754 precision representation limits, exact equality matching on floating-point numbers is unsafe and prohibited by C syntax.
SAQ 7: What is the difference between an else-if ladder and nested if statements?
Answer: An else-if ladder evaluates mutually exclusive sequential conditions. A nested if evaluates hierarchical, dependent decisions where the inner test only runs if the outer test passes.
SAQ 8: Why is writing if (x = 5) dangerous even though it compiles without syntax errors?
Answer: Because single equals = is assignment. It overwrites x with 5. Since 5 is non-zero, it always evaluates as True, executing the body every time and corrupting data.

Exercise 6: Menu-Driven Calculator Using switch

Task: Implement an arithmetic calculator with switch, checking against division by zero.

exercise6_calculator.c
#include <stdio.h>

int main(void)
{
    char op = '/';
    double num1 = 45.0, num2 = 9.0;

    switch (op)
    {
        case '+':
            printf("%.2f + %.2f = %.2f\n", num1, num2, num1 + num2);
            break;
        case '-':
            printf("%.2f - %.2f = %.2f\n", num1, num2, num1 - num2);
            break;
        case '*':
            printf("%.2f * %.2f = %.2f\n", num1, num2, num1 * num2);
            break;
        case '/':
            if (num2 != 0.0)
            {
                printf("%.2f / %.2f = %.2f\n", num1, num2, num1 / num2);
            }
            else
            {
                printf("Error: Zero division!\n");
            }
            break;
        default:
            printf("Error: Unknown operator '%c'\n", op);
            break;
    }

    return 0;
}
