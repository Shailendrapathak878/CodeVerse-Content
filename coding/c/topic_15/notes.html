Foundational Concept

01. What Is a Function Pointer?

Definition: A function pointer is a pointer variable that stores the memory address of executable function code rather than data. It allows programs to invoke functions dynamically at runtime, pass functions as arguments to other functions, and construct modular callback architectures.

In C, when your program compiles, every function (such as main or printf) is translated into binary CPU machine instructions. These instructions are loaded into a protected memory segment known as the Code Segment (or Text Segment). Just like a variable residing in the Stack or Heap has a numerical memory address, every compiled function has an entry-point memory address in the Code Segment.

1.1 Direct Function Calls vs. Dynamic Invocation

  • Direct Function Call: The function name is hardcoded at compile time (e.g., greet();). The compiler writes a fixed jump instruction to that specific location.
  • Function Pointer Call: The function address is stored in a pointer variable (e.g., funcPtr();). The program decides at runtime which function to jump to.
  • Not a Data Pointer: Unlike an int * or char * which points to storage cells holding numbers or letters, a function pointer points to executable instructions. It has a strict type defined by the function's return type and parameter list.

1.2 The Starter Example: An Ordinary Function

ordinary_function.c 
#include <stdio.h>

void greet(void)
{
    printf("Hello from a function!\n");
}

int main(void)
{
    /* Direct function call: determined at compile time */
    greet();
    return 0;
}
Exact Expected Output
Hello from a function!

Now, imagine your application needs to choose between greetEnglish(), greetSpanish(), and greetFrench() based on a user's language setting. Instead of repeating if/else chains everywhere, a single function pointer can point to whichever greeting function is currently active!

02. Understanding Function Addresses

In C, the name of a function acts as a function designator. When used in an expression, it automatically converts (decays) into a pointer to that function, in a manner very similar to array decay:

The Function Address Equivalence: For any function named greet:

greet ≡ &greet

Both expressions evaluate to a pointer to the function. Using the ampersand &greet makes your intention explicit, but writing just greet is standard idiomatic C.

2.1 Why Function Pointers Are Not Ordinary void * Pointers

A vital rule in the ISO C Standard (ISO C11 §6.3.2.3):

  • Object Pointers: Point to data in memory (e.g., int *, char *, void *).
  • Function Pointers: Point to executable instructions in code memory (e.g., void (*)(void)).
  • No Standard Interchangeability: The ISO C standard does not guarantee that a function pointer can be safely converted to void * or back. On some Harvard architectures, code memory and data memory use physically different buses, word widths, or address registers!
Architectural Rule: Never treat function pointers as general data pointers. Never perform pointer arithmetic (such as funcPtr++) on a function pointer; functions do not have an array-like byte stride!

03. Declaring Function Pointers

Declaring a function pointer requires precise syntax because operator precedence rules in C give parentheses higher priority than the asterisk.

General Function Pointer Declaration Syntax:

return_type (*pointer_name)(parameter_types);

3.2 Why the Parentheses Around (*funcPtr) Are Mandatory

Notice what happens if you omit the parentheses:

  • int (*funcPtr)(int, int); → The parentheses bind * to funcPtr first. This declares a pointer to a function.
  • int *funcPtr(int, int); → Without parentheses, function call () takes precedence over *. This declares an ordinary function that returns an integer pointer (int *)!

04. Assigning and Calling Functions via Pointers

Once declared, assigning a function address and calling it is straightforward and clean.

4.1 Complete Runnable Program

assign_and_call.c 
#include <stdio.h>

void greet(void)
{
    printf("Hello from greet!\n");
}

int main(void)
{
    /* 1. Declare and initialize function pointer */
    void (*funcPtr)(void) = greet;

    /* 2. Call form A: Modern concise syntax */
    funcPtr();

    /* 3. Call form B: Explicit dereference syntax */
    (*funcPtr)();

    return 0;
}
Exact Expected Output
Hello from greet! Hello from greet!

4.2 Two Valid Call Forms: funcPtr() vs. (*funcPtr)()

  • funcPtr();: Modern, concise, and widely preferred in modern C. Because funcPtr already holds a function pointer, the function call operator () invokes it directly.
  • (*funcPtr)();: Explicitly dereferences the pointer to retrieve the function designator, then calls it. Both forms produce identical machine code in all compliant C compilers.

4.3 Step-by-Step Dry-Run Execution Table

Step Code Executed State of funcPtr Action Performed by CPU Output Produced
1 void (*funcPtr)(void) = greet; Holds address of greet Function entry address stored in pointer variable. None
2 funcPtr(); Holds address of greet CPU jumps to address of greet, executes code, and returns. Hello from greet!
3 (*funcPtr)(); Holds address of greet Dereferences pointer, jumps to greet, and returns. Hello from greet!
Type Safety

05. Function Pointer Type Compatibility

In C, function pointers are strictly typed. The compiler verifies that the return type, number of parameters, and parameter types of the function match the declaration of the function pointer exactly.

type_compatibility.c 
int add(int a, int b)
{
    return a + b;
}

/* COMPATIBLE: Return type int, parameters (int, int) */
int (*operation)(int, int) = add; 

/* INCOMPATIBLE (Compiler Error/Warning): Return type mismatch! */
/* void (*badPtr)(int, int) = add; */

/* INCOMPATIBLE (Compiler Error/Warning): Parameter count mismatch! */
/* int (*badPtr2)(int) = add; */

5.1 Signatures and Their Corresponding Pointer Types

Target Function Prototype Compatible Function Pointer Declaration Usage Description
void reset(void); void (*p)(void); Takes no arguments, returns nothing.
int square(int x); int (*p)(int); Takes 1 integer, returns an integer.
int add(int a, int b); int (*p)(int, int); Takes 2 integers, returns an integer.
double compute(double val); double (*p)(double); Takes 1 double-precision float, returns a double.
The Danger of Type Punning / Unsafe Casts: Never use type casting (e.g., (int (*)(int))add) to silence compiler warnings for incompatible function signatures. If the CPU prepares stack registers for two arguments but the function only expects one, the call stack will be corrupted, resulting in hard-to-trace crashes!

06. Dynamic Reassignment: One Pointer, Multiple Functions

Because a function pointer is an independent variable, it can be redirected to point to any compatible function during execution. This empowers programs to swap behaviors on the fly:

reassign_function_pointer.c 
#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

int multiply(int a, int b)
{
    return a * b;
}

int main(void)
{
    /* 1. Point to add() */
    int (*operation)(int, int) = add;
    printf("%d\n", operation(5, 3));

    /* 2. Reassign to multiply() */
    operation = multiply;
    printf("%d\n", operation(5, 3));

    return 0;
}

Higher-Order Functions

07. Passing Functions as Arguments

In computer science, a function that accepts another function as an argument is called a Higher-Order Function. This technique allows a function to be generic and let the caller inject the specific algorithm or calculation to be performed.

7.1 The Higher-Order Dispatcher Program

higher_order_dispatch.c 
#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

int multiply(int a, int b)
{
    return a * b;
}

/* applyOperation accepts a function pointer as its 3rd parameter */
int applyOperation(int a, int b, int (*operation)(int, int))
{
    return operation(a, b);
}

int main(void)
{
    printf("%d\n", applyOperation(4, 3, add));
    printf("%d\n", applyOperation(4, 3, multiply));

    return 0;
}
Exact Expected Output
7 12

7.2 Execution Trace: How applyOperation Works

  1. main invokes applyOperation(4, 3, add). The function name add decays into its function pointer.
  2. The parameter operation in applyOperation receives the address of add.
  3. Inside applyOperation, operation(a, b) invokes add(4, 3), returning 7.
  4. main next invokes applyOperation(4, 3, multiply).
  5. The parameter operation now receives the address of multiply, invoking multiply(4, 3), returning 12.
Callback Architecture

08. Callbacks in C

Definition: A callback is a function passed as an argument to another function, which the receiving function invokes ("calls back") when a specific event occurs or during element-by-element processing.

Callbacks separate the mechanism of iteration from the policy of what to do with each item.

Real-Life Analogy: The Assembly Line Inspector

Imagine an automated conveyor belt moving 100 boxes. The conveyor motor (the processArray function) only knows how to move boxes forward one by one.

At the workstation, you can plug in different tools (the callback): on Monday, a stamp tool to print the box ID; on Tuesday, a barcode reader to scan the weight. The conveyor belt mechanism never needs to change!

8.1 Complete Array Processing Callback Program

callback_array_demo.c 
#include <stdio.h>
#include <stddef.h>

/* Callback A: Print value directly */
void printVal(int x)
{
    printf("%d ", x);
}

/* Callback B: Print square of value */
void printSquare(int x)
{
    printf("%d ", x * x);
}

/* Generic processing engine */
void processArray(const int *arr, size_t length, void (*callback)(int))
{
    const int *end = arr + length;
    while (arr < end) {
        callback(*arr); /* Invoke caller's chosen callback */
        arr++;
    }
    printf("\n");
}

int main(void)
{
    int data[] = {1, 2, 3, 4, 5};
    size_t count = sizeof(data) / sizeof(data[0]);

    printf("Original values: ");
    processArray(data, count, printVal);

    printf("Squared values:  ");
    processArray(data, count, printSquare);

    return 0;
}
Exact Expected Output
Original values: 1 2 3 4 5 Squared values: 1 4 9 16 25

09. Function Pointers and typedef Aliases

Raw function pointer declarations can quickly become cumbersome and difficult to parse when used repeatedly in codebases. In C, the typedef keyword creates a clean, reusable type alias for a function pointer signature.

The typedef Pattern: 
typedef int (*Operation)(int, int);

This statement defines Operation as a new type name representing a pointer to any function that accepts two integers and returns an integer.

9.1 Comparing Raw vs. typedef Declarations

Context Raw Function Pointer Syntax Clean typedef Equivalent
Variable Declaration int (*op)(int, int) = add; Operation op = add;
Function Parameter void exec(int (*op)(int, int)) void exec(Operation op)
Array of 4 Pointers int (*table[4])(int, int); Operation table[4];

9.2 Complete Calculator Program Using typedef

typedef_calculator.c 
#include <stdio.h>

typedef int (*Operation)(int, int);

int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }
int multiply(int a, int b) { return a * b; }
int divide(int a, int b) 
{ 
    if (b == 0) return 0; /* Guard against division by zero */
    return a / b;         /* Discards fractional part (integer division) */
}

void runCalculation(int x, int y, Operation op, const char *name)
{
    printf("%s(%d, %d) = %d\n", name, x, y, op(x, y));
}

int main(void)
{
    runCalculation(10, 5, add, "Add");
    runCalculation(10, 5, subtract, "Subtract");
    runCalculation(10, 5, multiply, "Multiply");
    runCalculation(10, 5, divide, "Divide");

    return 0;
}

Add(10, 5) = 15 Subtract(10, 5) = 5 Multiply(10, 5) = 50 Divide(10, 5) = 2
Jump Tables

10. Array of Function Pointers (Dispatch Tables)

Just as you can create an array of integers or strings, C allows you to construct an array of function pointers. In systems programming, this is known as a Dispatch Table or Jump Table.

10.1 Syntax Breakdown: int (*operations[4])(int, int);

  • operations[4]: An array containing 4 elements.
  • *: Each element is a pointer.
  • (int, int): Each pointer references a function accepting two integers.
  • int: The pointed-to function returns an integer.

10.2 Complete Dispatch Table Program

dispatch_table_demo.c 
#include <stdio.h>

int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }
int multiply(int a, int b) { return a * b; }
int maximum(int a, int b) { return (a > b) ? a : b; }

int main(void)
{
    /* Array of 4 function pointers */
    int (*operations[4])(int, int) = {add, subtract, multiply, maximum};

    int a = 12, b = 4;
    int choice;

    for (choice = 0; choice < 4; choice++) {
        /* Direct index lookup into dispatch table */
        int result = operations[choice](a, b);
        printf("Operation index %d on (%d, %d) yields: %d\n", choice, a, b, result);
    }

    return 0;
}
Exact Expected Output
Operation index 0 on (12, 4) yields: 16 Operation index 1 on (12, 4) yields: 8 Operation index 2 on (12, 4) yields: 48 Operation index 3 on (12, 4) yields: 12

10.3 Dispatch Tables vs. Switch Statements

Feature Dispatch Table (Array of Function Pointers) Switch Statement
Execution Mechanism $O(1)$ constant time indirect jump via index Sequential checks or compiler jump table
Extensibility Functions can be registered dynamically at runtime Hardcoded at compile time; cannot add cases dynamically
Readability for Simple Tasks Requires strict matching signatures and careful bounds checking Very simple and familiar for basic branching
Practical Engineering

11. Real-World Applications of Function Pointers

Function pointers form the architectural backbone of production C software, operating systems, and game engines:

  • Operating System Virtual File Systems (VFS): The Linux kernel defines file operation structures (struct file_operations) filled with function pointers (.read, .write, .open) so that devices like hard drives, keyboards, and network sockets can share a unified API.
  • GUI & Event Handlers: Button clicks, mouse moves, and network socket packets trigger registered callback functions dynamically.
  • Object-Oriented C (Polymorphism): Structures containing function pointers simulate C++ virtual method tables (vtables), allowing dynamic polymorphism in pure C.
  • Embedded State Machines: Finite State Machines (FSM) store states as function pointers, transitioning by simply executing currentState = nextState;.
Standard Library

12. Standard Library Comparators (qsort in Practice)

The most prominent example of a function pointer in the C Standard Library is the quicksort algorithm qsort() in <stdlib.h>:

The qsort Prototype: 
void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));

12.1 Comparator Contract Rules

The comparator callback must return an integer:

  • Negative (< 0): If the first element should precede the second element.
  • Zero (== 0): If both elements are equivalent.
  • Positive (> 0): If the first element should follow the second element.

12.2 Complete Runnable qsort Program

qsort_comparator_demo.c 
#include <stdio.h>
#include <stdlib.h>

/* Safe integer comparator: avoids subtraction overflow bug */
int compareInts(const void *a, const void *b)
{
    int valA = *(const int *)a;
    int valB = *(const int *)b;

    if (valA < valB) return -1;
    if (valA > valB) return 1;
    return 0;
}

int main(void)
{
    int numbers[] = {45, 12, 89, 7, 23, 56};
    size_t count = sizeof(numbers) / sizeof(numbers[0]);

    printf("Before sorting: ");
    for (size_t i = 0; i < count; i++) printf("%d ", numbers[i]);
    printf("\n");

    /* Pass compareInts function pointer into qsort */
    qsort(numbers, count, sizeof(int), compareInts);

    printf("After sorting:  ");
    for (size_t i = 0; i < count; i++) printf("%d ", numbers[i]);
    printf("\n");

    return 0;
}
Exact Expected Output
Before sorting: 45 12 89 7 23 56 After sorting: 7 12 23 45 56 89
The Subtraction Overflow Bug: A common rookie shortcut is writing return (*(int*)a - *(int*)b);. If *a = INT_MIN and *b = 1, subtraction overflows integer limits and returns positive, completely corrupting your sort order! Always use safe three-way comparison (<, >, ==).

13. Function Pointers vs. Other Pointer Types

Pointers in C fall into two fundamentally different categories: Object Pointers (which reference data stored in RAM) and Function Pointers (which reference executable machine code in the Code/Text segment).

Declaration Pointer Category Target in Memory Pointer Arithmetic Allowed? Portably Convertible to void *?
int *ptr; Data Pointer Single integer in Stack/Heap/Data segment YES (scaled by sizeof(int)) YES (guaranteed by ISO C)
int **ptr; Double Data Pointer A pointer variable storing an address YES (scaled by sizeof(int *)) YES (guaranteed by ISO C)
int (*ptr)[5]; Array Pointer An entire contiguous array of 5 integers YES (scaled by 5 * sizeof(int)) YES (guaranteed by ISO C)
int (*func)(int, int); Function Pointer Entry point of a function in Code Segment NO (illegal in C) NO (undefined in strict ISO C)

13.1 Visual Declaration-Parsing Guide (The Clockwise/Spiral Rule)

To read complex C declarations, start at the identifier and spiral outward:

  1. Find the identifier: func
  2. Look right: Hit by ), so look left: * → "func is a pointer to..."
  3. Move outside parentheses and look right: (int, int) → "...a function taking two ints..."
  4. Look left: int → "...and returning an int."
Safety & Diagnostics

14. Function Pointer Safety & 13 Common Mistakes

Calling an invalid function pointer causes the CPU instruction pointer to jump to an arbitrary memory address, instantly producing a catastrophic crash. Here are the 13 most common pitfalls and their fixes:

# Mistake Pattern Flawed Code Why It Fails Correct Industry Fix
1 Omitting Parentheses int *fp(int); Declares a function returning int *, not a function pointer. Use parentheses: int (*fp)(int);.
2 Mismatched Return Type void (*fp)() = add; add returns int; compiler warns or return register is misread. Match signature: int (*fp)(int, int) = add;.
3 Mismatched Parameters int (*fp)(int) = add; add requires 2 integers; calling passes too few arguments, corrupting stack. Match exact parameters: int (*fp)(int, int) = add;.
4 Calling Uninitialized Pointer void (*fp)(); fp(); Wild function pointer contains garbage; CPU jumps to random address (SIGSEGV). Initialize on declaration or assign before call.
5 Calling NULL Pointer void (*fp)() = NULL; fp(); Jumping to address 0 causes immediate fatal segmentation fault. Guard: if (fp != NULL) fp();.
6 Forgetting Arguments op(); (where op takes 2 ints) Compiler error; missing required arguments. Pass arguments: op(x, y);.
7 Capturing Void Return int res = voidFuncPtr(); A void function returns no value; compiler rejects with type error. Invoke as statement: voidFuncPtr();.
8 Callback Signature Mismatch void f(void (*cb)(int)); f(printStr); Callback takes int, but passed function expects char *. Ensure callback matches parameter type exactly.
9 Out-of-Bounds Dispatch Index ops[10](a, b); (size 4) Reads arbitrary memory beyond table as an address, then jumps there (crash!). Validate: if (idx >= 0 && idx < 4) ops[idx](a, b);.
10 Confusing with Object Pointer int *p = greet; Incompatible pointer assignment; object pointer cannot store function code. Use function pointer: void (*p)(void) = greet;.
11 Unsafe Function Cast ((void(*)())add)(); Suppresses type checker; stack parameters misaligned during call. Never cast function pointers to incompatible prototypes.
12 Unhandled Division by Zero divide(10, 0); Hardware division by zero generates an unrecoverable SIGFPE signal. Guard denominator: if (b == 0) return 0;.
13 Confusing Pointer with Declaration int (*add)(int, int) { ... } Syntax error; definitions do not include pointer parens around name. Define normally: int add(int a, int b) { ... }.

Q1: Which of the following declares a function pointer, and which declares a function returning a pointer? Explain the difference.
(A) int *func(int);   |   (B) int (*func)(int);
ANSWER & ANALYSIS

Declaration (B) int (*func)(int); is the function pointer.

  • In int *func(int);, the function call operator () binds before the pointer dereference operator * due to operator precedence. Therefore, func is an identifier for a function that accepts an int and returns an int * (a pointer to an integer).
  • In int (*func)(int);, the parentheses around (*func) force the pointer binding first. Therefore, func is a pointer variable capable of holding the memory address of a function that accepts an int and returns an int.
Q2: Deconstruct and explain every part of the declaration: int (*ptr)(int);
DECLARATION ANATOMY

Read from the inside out using the Right-Left Rule:

  1. (*ptr): ptr is a pointer variable.
  2. (int): Moving to the right, it points to a function accepting a single parameter of type int.
  3. int: Moving to the left, that pointed-to function returns an int.

Summary: ptr is a pointer to a function taking one int parameter and returning an int.

Q3: What is the exact output of this C program?
#include <stdio.h>

int doubleVal(int x) { return x * 2; }

int main(void) {
    int (*fp)(int) = doubleVal;
    printf("%d\n", fp(7));
    return 0;
}
EXACT OUTPUT 
14

Explanation: fp is initialized with the address of doubleVal. Calling fp(7) invokes doubleVal(7), which computes 7 * 2 = 14 and returns it to printf.

Q4: What is the fundamental difference between writing func and writing func() in a C expression?
EXPLANATION
  • func (without parentheses) is a function designator. In value expressions, it automatically decays into a pointer to the function (i.e., its starting address in the code segment).
  • func() (with parentheses) is a function call operator. It instructs the CPU to prepare stack arguments, jump to the function's entry point, execute its instructions, and return the resulting value.

Writing int (*ptr)(void) = func(); is a common beginner error: it attempts to assign the return value of func() instead of the function's address func.

Q5: Why does ISO C require strict signature matching between a function pointer and the target function?
CALLING CONVENTION & ABI

The function's return type and parameter types dictate the CPU Application Binary Interface (ABI) and calling convention:

  • Which CPU registers or stack offsets hold input arguments.
  • How floating-point numbers (passed in XMM/vector registers) vs. integers (passed in general-purpose registers) are delivered.
  • Whether the caller or the callee cleans up the stack frame.

If you call a function through an incompatible pointer type, the CPU pulls values from the wrong registers or offsets, resulting in stack corruption, garbage calculations, or immediate segmentation faults.

Q6: Write a valid C code snippet that assigns a function named squareRoot (which accepts a double and returns a double) to a function pointer named fn.
CORRECT C CODE 
/* 1. Prototype of the target function */
double squareRoot(double x);

/* 2. Declaration and initialization of the function pointer */
double (*fn)(double) = squareRoot;

/* Both 'squareRoot' and '&squareRoot' are valid and equivalent */
double (*fn2)(double) = &squareRoot;
Q7: Identify the syntax error in this code and explain how to fix it:
void *handler(int) = logMessage;
ERROR & CORRECTION

The error: Missing parentheses around *handler. The compiler parses void *handler(int) as a forward declaration of a function named handler that returns a generic data pointer (void *). You cannot initialize a function declaration with = logMessage.

Corrected version:

void (*handler)(int) = logMessage;
Q8: Explain the difference between calling ptr() and (*ptr)() when ptr is a function pointer. Are they equivalent?
EQUIVALENCE IN ISO C

Yes, they are 100% semantically equivalent in modern C.

  • (*ptr)() is the original K&R C style: dereferencing the pointer yields the function designator, and () invokes it.
  • ptr() is the modern ANSI/ISO C shorthand: the compiler automatically dereferences the function pointer when it encounters the call operator ().

Modern C code overwhelmingly prefers ptr() for cleanliness and readability.

Q2: How do you pass a function pointer to another function? Write the function prototype for executeTwice, which takes an integer and a function that transforms an integer.
PROTOTYPE & IMPLEMENTATION 
/* Prototype */
int executeTwice(int initial, int (*transform)(int));

/* Implementation */
int executeTwice(int initial, int (*transform)(int)) {
    int firstPass = transform(initial);
    return transform(firstPass);
}

Example: If square(x) = x * x is passed with initial = 3, firstPass = 9, and the return value is 81.

Q8: What happens if a program calls a function pointer that contains NULL? How must defensive code prevent this?
DEFENSIVE PROGRAMMING

Calling a NULL function pointer causes the CPU to attempt an instruction fetch at virtual address 0x0. On modern operating systems (Linux, Windows, macOS), page 0 is guarded, resulting in an immediate Segmentation Fault (Crash / EXCEPTION_ACCESS_VIOLATION).

Defensive Guard Pattern:

void invokeCallback(void (*cb)(int), int value) {
    if (cb != NULL) {
        cb(value); /* Safe invocation */
    } else {
        fprintf(stderr, "Warning: Null callback supplied. Skipped.\n");
    }
}

Build a high-performance operation dispatcher using an array of function pointers. It executes addition, subtraction, multiplication, and integer division in \(O(1)\) constant time without conditional branching.

int opSub(int a, int b) { return a - b; }
int opMul(int a, int b) { return a * b; }

    if (b == 0) {
        printf("Error: Division by zero! ");
        return 0;

    return a / b; 
}

19.3 Problem 3: Safe Multi-Criteria Sorting with qsort

Demonstrate custom sorting using the standard library qsort with two different comparators: ascending order and descending order. Use the three-way comparison idiom to avoid subtraction arithmetic overflow.

qsort_custom.c 
#include <stdio.h>
#include <stdlib.h>

/* Ascending comparator: returns negative if a < b, positive if a > b */
int cmpAsc(const void *p1, const void *p2) {
    int v1 = *(const int *)p1;
    int v2 = *(const int *)p2;
    if (v1 < v2) return -1;
    if (v1 > v2) return 1;
    return 0;
}

/* Descending comparator: returns positive if a < b, negative if a > b */
int cmpDesc(const void *p1, const void *p2) {
    int v1 = *(const int *)p1;
    int v2 = *(const int *)p2;
    if (v1 > v2) return -1;
    if (v1 < v2) return 1;
    return 0;
}

void printData(const int *arr, size_t n) {
    for (size_t i = 0; i < n; ++i) printf("%d ", arr[i]);
    printf("\n");
}

int main(void) {
    int data[] = {42, 7, -15, 100, 0, 88};
    size_t count = sizeof(data) / sizeof(data[0]);

    printf("Raw:        ");
    printData(data, count);

    qsort(data, count, sizeof(int), cmpAsc);
    printf("Ascending:  ");
    printData(data, count);

    qsort(data, count, sizeof(int), cmpDesc);
    printf("Descending: ");
    printData(data, count);

    return 0;
}

19.4 Problem 4: How Function Pointers Elevate Code Reuse

Consider finding elements in a data structure. Without function pointers, you must write separate search functions: findEven(), findNegative(), findGreaterThanTen(), each duplicating the exact same loop logic.

With function pointers, you write one single search function that accepts a Predicate callback. The traversal algorithm is written once and reused infinitely.

generic_search.c 
#include <stdio.h>
#include <stddef.h>

typedef int (*Predicate)(int);

/* Generic search algorithm: returns index of first match, or -1 */
int findFirst(const int *arr, size_t len, Predicate match) {
    for (size_t i = 0; i < len; ++i) {
        if (match(arr[i])) return (int)i;
    }
    return -1;
}

int isNegative(int x) { return x < 0; }
int isGreaterThanFifty(int x) { return x > 50; }

int main(void) {
    int nums[] = {12, 24, -5, 68, 90};
    size_t len = sizeof(nums) / sizeof(nums[0]);

    int idx1 = findFirst(nums, len, isNegative);
    int idx2 = findFirst(nums, len, isGreaterThanFifty);

    printf("First negative at index: %d (value %d)\n", idx1, nums[idx1]);
    printf("First > 50 at index:     %d (value %d)\n", idx2, nums[idx2]);
    return 0;
}

19.6 Problem 6: Text Command Dispatch System

In embedded systems, network daemons, and shell utilities, incoming string commands (like "start", "stop", "status") are mapped to handler functions via an array of command structs.

command_router.c 
#include <stdio.h>
#include <string.h>

typedef void (*CommandHandler)(void);

typedef struct {
    const char *name;
    CommandHandler handler;
} Command;

void cmdStart(void)  { printf("System: Engine started.\n"); }
void cmdStop(void)   { printf("System: Engine stopped.\n"); }
void cmdStatus(void) { printf("System: All systems nominal.\n"); }

int main(void) {
    Command cmdTable[] = {
        {"start",  cmdStart},
        {"stop",   cmdStop},
        {"status", cmdStatus}
    };
    size_t numCmds = sizeof(cmdTable) / sizeof(cmdTable[0]);

    const char *inputs[] = {"start", "status", "stop", "reboot"};

    for (int i = 0; i < 4; ++i) {
        const char *userCmd = inputs[i];
        int handled = 0;

        for (size_t c = 0; c < numCmds; ++c) {
            if (strcmp(userCmd, cmdTable[c].name) == 0) {
                cmdTable[c].handler();
                handled = 1;
                break;
            }
        }
        if (!handled) {
            printf("Error: Unknown command '%s'\n", userCmd);
        }
    }

    return 0;
}

20. Capstone Mini-Project: Callback-Based Calculator

This complete, professional mini-project demonstrates the real-world power of function pointers. It features:

  • Four compatible arithmetic functions: addition, subtraction, multiplication, and integer division.
  • A clean function pointer type alias: typedef int (*CalcOp)(int, int);.
  • A robust higher-order compute engine: executeCalculation(...).
  • Defensive division-by-zero protection before executing integer division.
  • Both interactive and deterministic execution paths.
callback_calculator_project.c 
#include <stdio.h>
#include <stdlib.h>

/* Step 1: Define the function-pointer type alias */
typedef int (*CalcOp)(int, int);

/* Step 2: Implement the four compatible operations */
int add(int a, int b) {
    return a + b;
}

int subtract(int a, int b) {
    return a - b;
}

int multiply(int a, int b) {
    return a * b;
}

int divide(int a, int b) {
    /* Safe division: check divisor */
    if (b == 0) {
        printf("Error: Division by zero is undefined! ");
        return 0;
    }
    return a / b; /* Integer division: truncates fractional part */
}

/* Step 3: Higher-order evaluation function */
void executeCalculation(int x, int y, CalcOp op, const char *opName) {
    if (op == NULL) {
        printf("Error: Invalid operation handler!\n");
        return;
    }

    /* Extra safety guard specifically for division */
    if (op == divide && y == 0) {
        printf("[%s] Cannot compute %d / %d (Zero Divisor Guard)\n", opName, x, y);
        return;
    }

    int result = op(x, y);
    printf("[%s] %d and %d → Result = %d\n", opName, x, y, result);
}

int main(void) {
    printf("==========================================\n");
    printf("   CODEVERSE CALLBACK CALCULATOR DEMO     \n");
    printf("==========================================\n\n");

    /* Deterministic test cases with predefined values */
    int valA = 24;
    int valB = 6;

    printf("Executing calculations with A = %d, B = %d:\n\n", valA, valB);
    executeCalculation(valA, valB, add, "ADDITION");
    executeCalculation(valA, valB, subtract, "SUBTRACTION");
    executeCalculation(valA, valB, multiply, "MULTIPLICATION");
    executeCalculation(valA, valB, divide, "INTEGER DIVISION");

    /* Test division by zero safety guard */
    printf("\nTesting Division-by-Zero Safety Guard with B = 0:\n");
    executeCalculation(valA, 0, divide, "INTEGER DIVISION");

    return 0;
}

Step-by-Step Program Walkthrough

  1. Type Definition: typedef int (*CalcOp)(int, int); defines CalcOp as an alias for any function pointer accepting two integers and returning an integer.
  2. Operation Functions: All four functions (add, subtract, multiply, divide) share the identical signature: (int, int) → int.
  3. Safe Division: Integer division truncates towards zero. If the denominator is 0, the defensive check intercepts execution before the hardware ALU triggers a fatal floating-point / division-by-zero hardware trap.

12 High-Yield Technical Viva Questions

1. What is a function pointer in C?
VIVA ANSWER

A function pointer is a variable that stores the starting memory address of executable instructions belonging to a function located in the Code (or Text) segment of memory, allowing that function to be called dynamically at runtime.

2. In which segment of memory does a function pointer point to?
VIVA ANSWER

It points to the Code Segment (also known as Text Segment), which contains compiled machine code instructions and is typically marked as read-only and executable.

3. Why are parentheses required around (*funcPtr) in declarations?
VIVA ANSWER

Because the function call operator () has higher precedence than the pointer dereference operator *. Without parentheses, int *func(int) declares a function returning a pointer to an int, rather than a pointer to a function.

4. Is there any difference between &func and func in C?
VIVA ANSWER

In standard C, both produce a pointer of the exact same function pointer type. The function designator func automatically decays to a pointer to that function in value expressions. Both fp = func; and fp = &func; are completely valid and equivalent.

5. Can a function pointer point to functions with different return types or parameters?
VIVA ANSWER

No. In C, a function pointer is strictly typed based on both its return type and its full parameter list. Pointing to or invoking an incompatible signature leads to undefined behavior and stack corruption.

6. What is a callback function?
VIVA ANSWER

A callback function is any function whose reference (pointer) is passed as an argument to another function, enabling the receiving function to call it back at a later point to customize behavior.

7. Can you perform pointer arithmetic on a function pointer (e.g., fp++)?
VIVA ANSWER

No. Pointer arithmetic requires knowledge of the size of the pointed-to object via sizeof. Functions do not have a defined object size in ISO C; hence, arithmetic on function pointers is strictly illegal and violates the standard.

8. Can you safely cast a function pointer to void * in ISO C?
VIVA ANSWER

No. In strict ISO C, void * is only guaranteed to hold pointers to data objects. Function pointers and object pointers may have different sizes or representations on Harvard architecture microcontrollers. (Note: POSIX requires this compatibility for dlsym, but standard C does not).

9. What happens if you invoke a function pointer that holds NULL?
VIVA ANSWER

It invokes undefined behavior, resulting in an immediate hardware access violation / segmentation fault (crash) on all modern protected-memory operating systems.

10. Why is typedef widely used with function pointers?
VIVA ANSWER

typedef creates clean, self-documenting type aliases (e.g., typedef int (*Action)(int);), which makes function signatures readable when declaring variables, parameter lists, or arrays of function pointers.

11. How does the standard C library function qsort use function pointers?
VIVA ANSWER

qsort accepts a comparator callback conforming to int (*)(const void *, const void *). This allows the sorting algorithm (QuickSort) to sort arbitrary data types without knowing their internal layout.

12. What is the difference between an array of function pointers and a pointer to a function array?
VIVA ANSWER

int (*arr[4])(int); is an array of 4 function pointers (each slot holds a pointer to a function). In contrast, int (*(*ptr)[4])(int); is a pointer to an entire array of 4 function pointers.
