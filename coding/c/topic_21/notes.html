Data Persistence

01. Introduction to File Handling

In all previous C programming topics, variables (integers, arrays, structures, pointers) were stored exclusively in system RAM (the stack, data segment, or heap).

The Fundamental Limitation of RAM: Volatility

RAM is volatile memory. The moment your program terminates or your computer loses power, every variable in memory vanishes instantly into thin air.

What Is a File and File Handling?

A File is a named, persistent collection of bytes stored on non-volatile secondary storage (such as an SSD, hard drive, or USB flash drive).

File Handling in C refers to the standard library capabilities that allow a program to create, open, read, write, append, and modify persistent files on storage media.

Real-Life Analogy: Whiteboard vs. Permanent Ledger

Imagine running a student admissions office:

  • Variables in RAM (The Whiteboard): You write today's applicants on an office whiteboard. It is fast to read and write. But at 5:00 PM when the office cleans up, the whiteboard is wiped completely clean!
  • Files on Disk (The Hardbound Ledger): You record the student names, roll numbers, and grades into a bound leather ledger stored in a fireproof filing cabinet. Even if the office closes for the weekend, the records remain permanently intact next week.

1.1 The Program-to-Storage Architecture

A C program does not manipulate raw magnetic platters or flash cells directly. Instead, file access follows a secure 4-layer hierarchy: 

C Program → [C Standard I/O Library (stdio.h)] 
          → [Operating System Kernel (Syscalls)] 
          → [File System Driver (NTFS/ext4/FAT32)] 
          → Physical Storage (SSD / HDD)

Because the Operating System controls file access, every file operation can fail if permissions are denied, the disk is full, or the path is invalid. Defensive error checking is therefore mandatory.

Stream Abstraction

02. Understanding FILE & File Pointers

In C, all file interactions operate through an opaque data type called FILE and its associated pointer:

File Pointer Declaration
#include <stdio.h>

FILE *fp;

2.1 What Is FILE?

  • FILE is a specialized structure defined in <stdio.h> that maintains the internal state of an active I/O stream.
  • It tracks the operating system file descriptor, the memory buffer used to batch read/write requests, current byte offset position, and error/EOF status flags.
  • The * means that fp is a pointer to this internal control block managed by the C runtime. It does not represent a physical disk sector address!
The Cardinal Rule: Always Check for NULL!

If the OS fails to open a requested file, fopen() returns NULL. Attempting to read or write through a NULL file pointer causes an immediate segmentation fault / program crash!

03. Opening Files with fopen() & Path Rules

The fopen() Prototype
FILE *fopen(const char *filename, const char *mode);

3.1 Relative vs. Absolute Paths

Path Type Example Syntax How It Resolves
Relative Path "data.txt" or "logs/app.log" Resolved relative to the program's Current Working Directory (CWD) at runtime.
Absolute Path "C:\\data\\records.txt" or "/var/log/sys.log" Specifies the complete, unambiguous path from the root drive. (In Windows C strings, backslashes must be escaped: \\\\).
The Current Working Directory Trap

Beginners often expect fopen("records.txt", "r") to look inside the folder containing their .c source code. In reality, the OS looks inside the working directory from which the executable was launched! If launched from an IDE or terminal in a different folder, the file will not be found!

3.2 Recommended Defensive File-Opening Pattern

safe_fopen_demo.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* Attempt to open file in read mode */
    FILE *fp = fopen("config.txt", "r");

    if (fp == NULL) {
        /* perror prints user message followed by OS error string */
        perror("[ERROR] Unable to open config.txt");
        return EXIT_FAILURE;
    }

    printf("File opened successfully!\n");

    /* Always close open stream */
    fclose(fp);
    return EXIT_SUCCESS;
}

Resource Cleanup

05. Closing Files with fclose() & Flushing

Every successfully opened file must be explicitly closed using fclose() when operations are finished:

The fclose() Prototype
int fclose(FILE *stream);

5.1 Why Is fclose() Crucial?

  1. Flushes Stream Buffers: When you write with fprintf() or fputs(), C batches the data in RAM buffers to maximize disk throughput. fclose() forces the buffer to flush out to the operating system.
  2. Releases OS File Handles: Operating systems enforce a strict limit on the maximum number of open files per process (e.g. 1024 or 4096). Failing to close files causes file descriptor leaks, leading to subsequent fopen() failures.
  3. Releases File Locks: In multi-process environments, unclosed files can lock other programs from modifying them.

5.2 Checking the Return Value of fclose()

fclose() returns 0 on success, and EOF (-1) on failure:

fclose_check.c 
if (fclose(fp) == EOF) {
    perror("[CRITICAL] Error flushing and closing file");
    return 1;
}
fp = NULL; /* Good practice: neutralize pointer */

06. Writing Text: fprintf(), fputs(), fputc()

Writing human-readable text to files is handled by three complementary functions in <stdio.h>:

Function Prototype Data Written Appends Newline?
fprintf() int fprintf(FILE *stream, const char *format, ...); Formatted text (numbers, strings, floats) Only if specified in format (\n)
fputs() int fputs(const char *s, FILE *stream); Null-terminated string NO (Unlike puts()!)
fputc() int fputc(int c, FILE *stream); Single character NO

6.1 Complete Text Writing Program

write_text_demo.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("student.txt", "w");

    if (fp == NULL) {
        perror("[ERROR] Failed to open student.txt for writing");
        return EXIT_FAILURE;
    }

    /* 1. Writing formatted text with fprintf */
    if (fprintf(fp, "Name: %s\nRollNo: %d\nMarks: %.2f\n", "Rahul Sharma", 101, 89.50) < 0) {
        perror("Error during fprintf");
        fclose(fp);
        return EXIT_FAILURE;
    }

    /* 2. Writing plain string with fputs */
    fputs("Status: Enrolled\n", fp);

    /* 3. Writing single character with fputc */
    fputc('*', fp);
    fputc('\n', fp);

    if (fclose(fp) == EOF) {
        perror("Error closing student.txt");
        return EXIT_FAILURE;
    }

    printf("Student record successfully written to disk!\n");
    return EXIT_SUCCESS;
}

Text Input

07. Reading Text: fgets() Line-by-Line & fgetc()

7.1 Reading Line-by-Line with fgets()

fgets() is the gold standard for reading text files line-by-line because it enforces a strict buffer boundary to prevent memory buffer overflows: 

char *fgets(char *str, int num, FILE *stream);
  • Reads up to num - 1 characters, or until a newline \n or EOF is encountered.
  • Preserves the newline character \n inside str if it fits.
  • Always appends a null terminator ('\0').
  • Returns str on success, or NULL on EOF or read error.
read_lines_fgets.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("student.txt", "r");
    char lineBuffer[128];

    if (fp == NULL) {
        perror("[ERROR] Unable to open student.txt");
        return EXIT_FAILURE;
    }

    printf("--- File Contents ---\n");
    /* Loop cleanly continues until fgets returns NULL */
    while (fgets(lineBuffer, sizeof(lineBuffer), fp) != NULL) {
        printf("%s", lineBuffer);
    }

    if (ferror(fp)) {
        perror("Error occurred while reading student.txt");
    }

    fclose(fp);
    return EXIT_SUCCESS;
}

7.2 Reading Character-by-Character with fgetc()

WHY MUST fgetc() BE STORED IN AN INT, NOT A CHAR?

The prototype of fgetc() is: 

int fgetc(FILE *stream);

It returns an int, not a char! Why? Because it must be capable of returning every valid 8-bit unsigned character byte (0 to 255) plus the special out-of-band indicator EOF (-1).

If you store the result in a char ch, on platforms where char is signed, a valid character like 0xFF (255) will be sign-extended to -1, prematurely stopping your read loop! On systems where char is unsigned, ch can never equal -1, creating an infinite loop!

read_chars_fgetc.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("student.txt", "r");
    int ch; /* Must be INT to hold EOF safely! */

    if (fp == NULL) {
        perror("student.txt");
        return EXIT_FAILURE;
    }

    while ((ch = fgetc(fp)) != EOF) {
        putchar(ch);
    }

    fclose(fp);
    return EXIT_SUCCESS;
}
Critical Anti-Pattern

08. Reading Text: fscanf() & The EOF Read Trap

fscanf() parses whitespace-separated fields from a file: 

int count = fscanf(fp, "%49s %d %f", name, &roll, &marks);
  • Return Value: Returns the number of items successfully parsed and assigned.
  • Field Width Security: When reading strings with %s, always include a maximum field width (e.g. %49s for a 50-byte array) to prevent stack buffer overflows!

8.1 The Dangerous while (!feof(fp)) Anti-Pattern

NEVER USE `while (!feof(fp))` AS YOUR READ LOOP!

The most widespread file bug written by C beginners is: 

/* WRONG - DUPLICATES THE LAST RECORD! */
while (!feof(fp)) {
    fscanf(fp, "%s %d", name, &score);
    printf("%s: %d\n", name, score);
}

Why this fails: In C, feof(fp) does NOT look into the future. It does not predict the end of the file. It returns true only AFTER an attempted read hits the end of the stream!

When the last line is reached, feof(fp) is still 0 (false). The loop body executes again, fscanf() fails to read anything new, the variables retain their previous values, and the last line is printed twice!

8.2 The Correct Read Loop Pattern

Always Test the Read Function's Return Value Directly!
/* CORRECT - Loop terminates immediately when read fails */
while (fscanf(fp, "%49s %d", name, &score) == 2) {
    printf("%s: %d\n", name, score);
}
Stream Diagnostics

09. End-of-File & Error Detection: EOF, feof(), ferror()

When a read function fails, you need to determine whether the stream simply reached the natural end of the file, or if a hardware/network I/O error occurred:

Indicator Type Meaning & Behavior
EOF Macro constant (typically -1) Returned directly by functions like fgetc() or getchar() when stream ends or fails.
feof(fp) Function returning non-zero if true Returns non-zero if an earlier read operation attempted to read past the end of the stream.
ferror(fp) Function returning non-zero if true Returns non-zero if an I/O error occurred on the stream (e.g. disk failure, network timeout).
clearerr(fp) Function Resets both the EOF and error indicator flags for the stream.

10. Appending Data to Files ("a" vs. "a+")

When you need to preserve existing records (such as appending a new transaction to an audit ledger), opening in "w" mode is disastrous. You must use "a" (Append Mode): 

FILE *fp = fopen("audit.log", "a");

10.1 Key Behaviors of Append Mode

  • If the file already exists, all existing content is preserved intact.
  • If the file does not exist, a brand-new file is created.
  • Forced End-of-File Writes: In append mode, every write operation is directed to the current end of the file, regardless of any fseek() positioning!
append_record.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* Open in append mode */
    FILE *fp = fopen("student.txt", "a");

    if (fp == NULL) {
        perror("Error opening student.txt for append");
        return EXIT_FAILURE;
    }

    /* Append a new student entry to the existing records */
    fprintf(fp, "Name: Ananya Roy\nRollNo: 102\nMarks: 94.20\nStatus: Enrolled\n*\n");

    fclose(fp);
    printf("New record successfully appended to student.txt!\n");
    return EXIT_SUCCESS;
}

In-Place Updates

11. Updating & Modifying Content ("r+", "w+")

The update modes ("r+", "w+", "a+") allow both reading and writing on the same file stream.

11.1 The C Standard Sequencing Rule for Update Streams

MANDATORY RULE (ISO C11 §7.21.5.3)

On an update stream (like "r+"), you cannot directly switch between input and output without an intervening positioning operation:

  • An output operation cannot be directly followed by an input operation without an intervening call to fflush(), fseek(), or rewind().
  • An input operation cannot be directly followed by an output operation without an intervening call to fseek(), fsetpos(), or rewind() (unless the input hit EOF).

11.2 In-Place Modification Does NOT Insert Characters

A file is an array of raw bytes on disk. If you seek to byte 10 and write 4 bytes, you overwrite the existing 4 bytes! File systems do not automatically shift subsequent bytes forward.

Random Access

12. File Positioning: fseek(), ftell(), rewind()

By default, file streams operate sequentially. C provides three functions to inspect and move the file pointer's internal byte cursor: 

int fseek(FILE *stream, long offset, int whence);
long ftell(FILE *stream);
void rewind(FILE *stream);

12.1 The Three fseek() Origins

Origin Macro Reference Point Common Use Case
SEEK_SET Beginning of the file Jump to absolute byte position (e.g. fseek(fp, 100L, SEEK_SET))
SEEK_CUR Current position Skip forward/backward by relative bytes (e.g. fseek(fp, 20L, SEEK_CUR))
SEEK_END End of the file Jump to end to compute size (e.g. fseek(fp, 0L, SEEK_END))

12.2 Practical Example: Measuring File Size in Bytes

file_size_seeker.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("student.txt", "rb"); /* Open in binary to count exact bytes */

    if (fp == NULL) {
        perror("student.txt");
        return EXIT_FAILURE;
    }

    /* 1. Seek to the very end of the file */
    fseek(fp, 0L, SEEK_END);

    /* 2. Read the byte position at the end */
    long fileSize = ftell(fp);

    /* 3. Rewind back to the beginning */
    rewind(fp);

    printf("Total File Size: %ld bytes\n", fileSize);

    fclose(fp);
    return EXIT_SUCCESS;
}

Binary Blocks

15. Binary File Handling with fread() & fwrite()

When working with raw data (arrays, multimedia, audio, network packets), converting numbers to text strings with fprintf() is slow and wastes disk space. C provides fread() and fwrite() for direct binary transfer:

Prototypes
size_t fwrite(const void *ptr, size_t size, size_t count, FILE *stream);
size_t fread(void *ptr, size_t size, size_t count, FILE *stream);

15.1 Parameters Explained

  1. ptr: Pointer to the memory buffer where data is stored or will be received.
  2. size: Size of each individual element in bytes (usually computed with sizeof(...)).
  3. count: Total number of elements to read or write.
  4. stream: The active FILE * stream (opened in binary mode, e.g. "wb" or "rb").
Return Value Counts Items, Not Bytes!

Both fread() and fwrite() return the number of complete items transferred, NOT the number of bytes! If you request 5 items and the function returns 3, you either hit end-of-file or encountered an I/O error.

binary_array_rw.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int writeData[5] = {10, 20, 30, 40, 50};
    int readData[5] = {0};
    size_t written, readCount;

    /* 1. Write binary data */
    FILE *fpWrite = fopen("numbers.bin", "wb");
    if (!fpWrite) { perror("numbers.bin"); return 1; }

    written = fwrite(writeData, sizeof(int), 5, fpWrite);
    fclose(fpWrite);
    printf("Successfully wrote %zu items to numbers.bin\n", written);

    /* 2. Read binary data back */
    FILE *fpRead = fopen("numbers.bin", "rb");
    if (!fpRead) { perror("numbers.bin"); return 1; }

    readCount = fread(readData, sizeof(int), 5, fpRead);
    fclose(fpRead);

    printf("Read %zu items back from disk:\n", readCount);
    for (int i = 0; i < 5; i++) {
        printf("readData[%d] = %d\n", i, readData[i]);
    }

    return 0;
}

15.2 The Perils of Binary Portability

NEVER SERIALIZE RAW POINTERS OR ASSUME CROSS-PLATFORM BINARIES!
  • Never Write Pointers: If a structure contains a pointer (e.g. char *name), writing the structure writes the RAM address number to disk. When the program restarts or runs tomorrow, that memory address is completely invalid!
  • Structure Padding: Compilers insert invisible padding bytes between struct members to align with CPU word boundaries. Different compilers or optimization levels create different layouts!
  • Endianness: Intel x86 is Little-Endian; network protocols and certain ARM chips can be Big-Endian. Writing binary numbers directly means other architectures read inverted byte orders!

17. Robust Buffered File Copy Program

Copying files byte-by-byte using fgetc() and fputc() is thousands of times slower than reading large chunks. Here is an industrial-strength file copy engine using a 4KB chunk buffer with full defensive error handling:

robust_file_copy.c 
#include <stdio.h>
#include <stdlib.h>

#define CHUNK_SIZE 4096

int copyFile(const char *srcPath, const char *destPath) {
    FILE *src = fopen(srcPath, "rb");
    if (src == NULL) {
        perror("[ERROR] Source file opening failed");
        return -1;
    }

    FILE *dest = fopen(destPath, "wb");
    if (dest == NULL) {
        perror("[ERROR] Destination file creation failed");
        fclose(src);
        return -1;
    }

    char buffer[CHUNK_SIZE];
    size_t bytesRead, bytesWritten;
    int success = 1;

    while ((bytesRead = fread(buffer, 1, sizeof(buffer), src)) > 0) {
        bytesWritten = fwrite(buffer, 1, bytesRead, dest);
        if (bytesWritten != bytesRead) {
            perror("[ERROR] Write failed to destination");
            success = 0;
            break;
        }
    }

    if (ferror(src)) {
        perror("[ERROR] Read error on source stream");
        success = 0;
    }

    if (fclose(src) == EOF) success = 0;
    if (fclose(dest) == EOF) success = 0;

    return success ? 0 : -1;
}

int main(void) {
    const char *source = "student.txt";
    const char *backup = "student_backup.txt";

    if (copyFile(source, backup) == 0) {
        printf("Successfully duplicated %s to %s\n", source, backup);
    } else {
        printf("Copy operation failed.\n");
    }

    return 0;
}

19.4 Program 4: Count Characters, Words, and Lines in a Text File

prog4_word_counter.c 
#include <stdio.h>
#include <ctype.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("notes.txt", "r");
    int ch;
    long characters = 0, words = 0, lines = 0;
    int inWord = 0;

    if (!fp) { perror("notes.txt"); return 1; }

    while ((ch = fgetc(fp)) != EOF) {
        characters++;
        if (ch == '\n') lines++;

        if (isspace(ch)) {
            inWord = 0;
        } else if (!inWord) {
            inWord = 1;
            words++;
        }
    }

    fclose(fp);
    printf("Characters: %ld | Words: %ld | Lines: %ld\n", characters, words, lines);
    return 0;
}

19.5 Program 5: Copy One File to Another

prog5_file_copy.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *src = fopen("notes.txt", "rb");
    FILE *dst = fopen("notes_copy.txt", "wb");
    char buffer[1024];
    size_t bytes;

    if (!src || !dst) {
        perror("File copy open error");
        if (src) fclose(src);
        if (dst) fclose(dst);
        return 1;
    }

    while ((bytes = fread(buffer, 1, sizeof(buffer), src)) > 0) {
        fwrite(buffer, 1, bytes, dst);
    }

    fclose(src);
    fclose(dst);
    printf("File copy operation completed successfully.\n");
    return 0;
}

19.7 Program 7: Demonstrate fseek(), ftell(), and rewind()

prog7_seek_demo.c 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("alphabet.txt", "w+b");
    if (!fp) { perror("alphabet.txt"); return 1; }

    /* Write ABCDEFGHIJKLMNOPQRSTUVWXYZ */
    fputs("ABCDEFGHIJKLMNOPQRSTUVWXYZ", fp);

    /* Seek to 10th character (index 10 = 'K') */
    fseek(fp, 10L, SEEK_SET);
    printf("Current Position: %ld, Char: '%c'\n", ftell(fp), fgetc(fp));

    /* Rewind to beginning */
    rewind(fp);
    printf("After rewind: Position: %ld, Char: '%c'\n", ftell(fp), fgetc(fp));

    fclose(fp);
    return 0;
}

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    float sensorReadings[4] = {98.6f, 101.3f, 97.4f, 99.1f};
    float loadedReadings[4] = {0.0f};

    FILE *fp = fopen("sensors.bin", "wb");
    if (!fp) { perror("sensors.bin"); return 1; }

    fclose(fp);

    fp = fopen("sensors.bin", "rb");
    if (!fp) { perror("sensors.bin"); return 1; }
    fread(loadedReadings, sizeof(float), 4, fp);
    fclose(fp);

    printf("Binary Floats Read:\n");
    for (int i = 0; i < 4; i++) {
        printf("  [Sensor %d] = %.1f F\n", i + 1, loadedReadings[i]);
    }

    return 0;
}

Industry Architecture

20. Real-Life Industrial Applications

20.1 Scenario A: Enterprise System Event Logging

High-throughput server daemons use append mode ("a") to write timestamped audit entries. Because append mode guarantees atomic end-of-file writes on POSIX filesystems, multiple processes can safely append log records without overwriting each other's data.

20.2 Scenario B: Application Configuration Files

Desktop applications and embedded firmware store persistent key-value configuration flags (e.g. theme=dark, volume=80) in plain text files. Reading via fgets() allows human operators to edit settings using any standard text editor.

20.3 Scenario C: High-Speed Sensor Telemetry Caching

Drones and IoT microcontrollers record high-frequency gyro telemetry (1000 samples per second) using binary mode ("wb") and fwrite(). Binary writes bypass expensive ASCII string conversions, conserving both battery power and memory bandwidth.

21. Common Interview Traps & Technical FAQs

1. What is the fundamental difference between "r", "w", and "a"?
ANSWER

"r" opens an existing file for reading (fails if file missing). "w" opens for writing, wiping any existing content to 0 bytes or creating a new file. "a" opens for writing, preserving existing content and directing all writes to EOF.

2. How do "r+", "w+", and "a+" differ?
ANSWER

All three allow reading and writing. "r+" preserves existing content and starts at the beginning. "w+" destroys existing content (truncates to 0 bytes). "a+" allows reading anywhere, but forces all writes to EOF.

3. Why should you never use `while (!feof(fp))`?
ANSWER

feof() only returns true after an attempted read operation fails. It cannot look ahead, leading to the common bug of processing the final record twice.

4. Why is `int ch` used for `fgetc()` instead of `char ch`?
ANSWER

fgetc() returns all 256 valid unsigned char values plus EOF (-1). A char cannot portably represent both without ambiguity.

5. What is the difference between text and binary mode on Windows?
ANSWER

In text mode, Windows translates \r\n on disk to \n in RAM during reading, and vice versa on writing. In binary mode ("b"), bytes are read and written directly with zero translation.

6. Why is writing a struct with pointers using `fwrite()` an error?
ANSWER

It saves the numeric memory address of the pointer to disk. When read back in another session, that address points to invalid or unmapped RAM.

ANSWER

ANSWER

Because feof() only returns true after an attempted read fails, resulting in duplicate processing of the last line.

ANSWER

0 (returns EOF on failure).

ANSWER

Q10: What does SEEK_END represent in fseek()?
ANSWER

The end of the file.

Technical Viva Interview Questions

1. What does the FILE pointer actually point to?
VIVA ANSWER

It points to an internal C runtime control block structure maintaining stream metadata, buffers, file descriptors, and stream position pointers.

2. Why can't you serialize raw pointers to a file?
VIVA ANSWER

Pointers contain virtual memory addresses unique to the running process. When read back in another session or machine, those addresses point to invalid RAM.

    fclose(fp);
}
