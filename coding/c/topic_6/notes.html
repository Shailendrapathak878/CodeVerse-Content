Introduction to Operators, Operands & Expressions

A computer is fundamentally an ultra-fast calculation and decision machine. In C, operators are the verbs of the language—the symbols that command the hardware to add numbers, compare values, test conditions, alter bits, and update memory locations.

The Three Foundational Definitions:
  • Operator: A specialized symbol or keyword (such as +, -, *, ==, &&) that instructs the C compiler to perform a specific mathematical, logical, or relational manipulation.
  • Operand: The raw data items, constants, variables, or sub-expression values upon which the operator acts.
  • Expression: A valid combination of operators, constants, and variables that the C compiler evaluates to compute and produce a single resulting value.

Anatomy of a C Expression

Consider this foundational statement in C:

  • + is an arithmetic operator that sums its two operands.
  • 10 + 5 forms an arithmetic expression that reduces to the value 15.
  • = is the assignment operator that copies the computed value 15 into the memory location allocated for variable result.
Real-Life Analogies: How Operators Mirror Everyday Situations

You use operators constantly in everyday life without even thinking about code:

  • Addition (+): Combining the prices of groceries: ₹40 milk + ₹35 bread = ₹75 total.
  • Subtraction (-): Checking remaining pocket money: ₹500 initial − ₹120 spent on lunch = ₹380 balance.
  • Comparison (>=): Checking if exam marks meet the passing threshold: marks >= 40 (Yes/No).
  • Logical Decisions (&&): ATM cash withdrawal: Account has sufficient funds AND entered PIN is correct.
  • Assignment (=): Writing down your new bank balance in a ledger book.

Arithmetic Operators & Modulo Realities

Arithmetic operators perform familiar mathematical computations such as addition, subtraction, multiplication, division, and remainder extraction on numeric values.

Operator Operation Name C Example Mathematical Meaning & Real-Life Usage
+ Addition total = price1 + price2; Sums two values. (e.g. Combining cart item prices).
- Subtraction remaining = cash - cost; Subtracts right operand from left operand. (e.g. Calculating change).
* Multiplication bill = qty * rate; Multiplies both operands. (e.g. Total cost for 5 tickets at ₹200).
/ Division avg = sum / count; Divides numerator by denominator. (Truncates decimals if both are int!).
% Remainder (Modulo) rem = dividend % divisor; Computes integer remainder after division. (Integer operands only!).
Real-Life Example: Shopkeeper, Notebooks & Change

Suppose a student walks into a stationary shop with ₹100 cash. Each premium notebook costs ₹30.

  • How many whole notebooks can the student buy?
    We use integer division: 100 / 30 = 3 whole notebooks.
  • How much spare change remains in the student's pocket?
    We use the modulo operator: 100 % 30 = 10 rupees remainder.
Verification Equation: $(3 \times 30) + 10 = 90 + 10 = 100$.

    printf("Subtraction: %d\n", a - b);

Multiplication: 30

CRITICAL HAZARD: Division or Remainder by Zero is Fatal!

In mathematics, division by zero is undefined. In C, executing x / 0 or x % 0 produces undefined behavior at runtime. On most operating systems, the CPU halts your program immediately with a fatal crash signal (SIGFPE: Floating point exception / integer division by zero).

Rule of thumb: Always validate that your denominator is not zero (if (b != 0)) before performing any division or modulo!

Modulo Restriction: The remainder operator % can only be used with integer types (char, int, short, long). Attempting to write 10.5 % 3.2 will cause a compile-time syntax error. For floating-point remainder, standard C provides the fmod() function in <math.h>.

Relational Operators & The True/False Flag

Relational operators compare two values to establish their relative relationship (greater, smaller, equal, or unequal). In C, relational expressions always produce an integer result: 1 for True and 0 for False.

Operator Meaning Example (with a = 10, b = 20) Evaluated Boolean Result
< Less than a < b (10 < 20) 1 (True)
> Greater than a > b (10 > 20) 0 (False)
<= Less than or equal to a <= 10 (10 <= 10) 1 (True)
>= Greater than or equal to b >= 25 (20 >= 25) 0 (False)
== Equal to a == 10 (10 == 10) 1 (True)
!= Not equal to a != b (10 != 20) 1 (True)

Real-Life Example: Student Exam Threshold

In a college examination, a student passes if their marks are at least 40. Let's inspect how C evaluates these relational checks:

relational_operators.c 
#include <stdio.h>

int main(void)
{
    int marks = 65;

    printf("Passed: %d\n", marks >= 40);
    printf("Perfect score: %d\n", marks == 100);
    printf("Failed: %d\n", marks < 40);

    return 0;
}
Exact Expected Output:
Passed: 1
Perfect score: 0
Failed: 0

Step-by-Step Result Tracing:

  1. marks >= 40: 65 is greater than or equal to 40. Condition is True, producing integer 1.
  2. marks == 100: 65 is not equal to 100. Condition is False, producing integer 0.
  3. marks < 40: 65 is not less than 40. Condition is False, producing integer 0.
THE MOST DANGEROUS BUG IN C: = (Assignment) vs. == (Equality)

Mixing up single equals (=) and double equals (==) is responsible for millions of critical software bugs:

  • == (Two equals) tests equality: if (marks == 100) checks if marks equals 100 without modifying anything.
  • = (Single equals) performs assignment: if (marks = 100) overwrites marks with 100, evaluates to 100 (which is non-zero, hence always TRUE), and enters the if-block every single time!

Tip: Modern compilers like GCC/Clang will warn you: "suggest parentheses around assignment used as truth value" if you accidentally write if (x = 5). Never ignore this warning!

Real-Life Example: Student Exam Eligibility

A student is permitted to sit for final semester examinations only if their subject marks are at least 40 AND their semester lecture attendance is at least 75%:

exam_eligibility.c 
#include <stdio.h>

int main(void)
{
    int marks = 65;
    int attendance = 80;

    /* Both conditions must evaluate to true (1) for eligible to be 1 */
    int eligible = (marks >= 40) && (attendance >= 75);

    printf("Eligible: %d\n", eligible);

    return 0;
}
Exact Expected Output:
Eligible: 1
CRITICAL CONCEPT: Short-Circuit Evaluation

The C standard mandates that logical && and || execute with short-circuit evaluation (strictly left-to-right):

  • In A && B: If expression A evaluates to false (0), the overall result can never be true! Therefore, C skips evaluating expression B entirely.
  • In A || B: If expression A evaluates to true (1), the overall result is already guaranteed true! Therefore, C skips evaluating expression B entirely.
Life-Saving Code Pattern (Zero Division Guard):
if (count != 0 && (sum / count) > 50)
If count is 0, the first condition is false. Thanks to short-circuiting, sum / count is never touched, completely avoiding a fatal division-by-zero crash!

Assignment Operators & Compound Equivalence

Assignment operators store values into variables. In addition to the simple assignment operator (=), C provides compound assignment operators (also known as shorthand or augmented operators) that combine an arithmetic operation with assignment in a concise syntax.

Compound Operator Example Syntax Equivalent Simple Form Result (Assuming Initial x = 10)
+= (Add & Assign) x += 5; x = x + 5; x becomes 15
-= (Subtract & Assign) x -= 3; x = x - 3; x becomes 7
*= (Multiply & Assign) x *= 2; x = x * 2; x becomes 20
/= (Divide & Assign) x /= 2; x = x / 2; x becomes 5
%= (Modulo & Assign) x %= 3; x = x % 3; x becomes 1
Real-Life Analogy: Digital Wallet Balance Tracking

Think of your personal mobile wallet:

  • Starting cash balance: ₹500.
  • Your friend transfers ₹200 for a movie ticket: balance += 200; → balance updates to ₹700.
  • You buy lunch for ₹100: balance -= 100; → balance updates to ₹600.
wallet_balance_demo.c 
#include <stdio.h>

int main(void)
{
    int wallet = 500;
    printf("Initial Balance:    INR %d\n", wallet);

    wallet += 200; /* Deposit: wallet = wallet + 200 */
    printf("After Adding 200:   INR %d\n", wallet);

    wallet -= 100; /* Spending: wallet = wallet - 100 */

}
Exact Expected Output:
Initial Balance:    INR 500
After Adding 200:   INR 700
After Spending 100: INR 600
Efficiency Benefit: In compound assignments like x += y, the target variable x is evaluated only once by the compiler. While identical for simple variable names, this avoids redundant computations when the target is an element of a complex array or data structure.
📚 Section 08 • Section G

Increment & Decrement Operators (Prefix vs. Postfix)

Adding 1 or subtracting 1 from a variable is the single most frequent operation in programming (e.g. counting loops, keeping score). C provides dedicated unary operators for this: ++ (Increment) and -- (Decrement).

Operator & Notation Type Execution Rule Expression Value
++x Prefix Increment Increments x by 1 first, then evaluates. Yields the NEW updated value.
x++ Postfix Increment Evaluates with original value first, then increments. Yields the OLD original value.
--x Prefix Decrement Decrements x by 1 first, then evaluates. Yields the NEW decremented value.
x-- Postfix Decrement Evaluates with original value first, then decrements. Yields the OLD original value.

Prefix vs. Postfix in Action

Study this complete program to see the exact difference between prefix and postfix evaluation:

prefix_postfix_demo.c 
#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = 5;

    /* Postfix: prints current value of a (5), then increments a to 6 */
    printf("Postfix: %d\n", a++);
    printf("After postfix: %d\n", a);

    /* Prefix: increments b to 6 first, then prints new value (6) */
    printf("Prefix: %d\n", ++b);
    printf("After prefix: %d\n", b);

    return 0;
}
Exact Expected Output:
Postfix: 5
After postfix: 6
Prefix: 6
After prefix: 6
👉 Visual Memory State Transition: a++ vs. ++b
POSTFIX (a++ where a = 5):
Step 1: Read memory location 'a' (Value = 5)
Step 2: Return 5 to calling expression → [Prints 5]
Step 3: Update memory location 'a' → a becomes 6 in RAM

PREFIX (++b where b = 5):
Step 1: Update memory location 'b' → b becomes 6 in RAM
Step 2: Read updated memory location 'b' (Value = 6)
Step 3: Return 6 to calling expression → [Prints 6]
CRITICAL SAFETY WARNING: Unsequenced Side Effects Are UNDEFINED!

Never write tricky expressions that modify the same variable more than once in a single expression! For example:

i = i++ + ++i; /* TOXIC CODE: UNDEFINED BEHAVIOR! */

Under the ISO C Standard (C99 §6.5#2), modifying a scalar object more than once between two consecutive sequence points creates Undefined Behavior. Different compilers (GCC, Clang, MSVC) and different CPU optimization levels will produce completely different, unpredictable numbers! Keep increment/decrement statements clean, simple, and isolated.

Operator Precedence & Associativity Table

When an expression contains multiple operators (e.g. 2 + 3 * 4), the C compiler must unambiguously determine which operator binds first. This is governed by two immutable rules: Precedence and Associativity.

Precedence vs. Associativity Explained:
  • Precedence: Determines the priority level of operators when operators are different. Operators with higher precedence are grouped before operators with lower precedence (e.g. * binds before +).
  • Associativity: Determines the grouping direction when two operators in an expression have the same precedence level. Most binary operators associate Left-to-Right (L → R), while unary and assignment operators associate Right-to-Left (R → L).

Why Parentheses Change Everything

Without Parentheses: 2 + 3 * 4
  1. Multiplication (*) has higher precedence than addition (+).
  2. Grouping: 2 + (3 * 4)
  3. Evaluates: 2 + 12 = 14
Result: 14
With Parentheses: (2 + 3) * 4
  1. Parentheses () have highest priority level 1.
  2. Grouping: (5) * 4
  3. Evaluates: 5 * 4 = 20
Result: 20

2 Unary Prefix ++x, --x, +, - (Sign), ! (Logical NOT), ~ (Bit NOT), (type), *ptr, &var, sizeof Right-to-Left (←)

CRITICAL NUANCE: Precedence ≠ Order of Evaluation!

Precedence specifies how operators and operands bind grammatically into an expression tree. It does NOT dictate the chronological order in which function calls or sub-operands are evaluated by the CPU.

For example, in f() + g() * h(), multiplication has higher precedence than addition, meaning the result will be f() + (g() * h()). However, the compiler is free to execute f(), g(), or h() in any chronological order it prefers! Only &&, ||, ?:, and , introduce sequence points that guarantee strict left-to-right evaluation order.

📚 Section 10 • Section I

Conditional Operator (Ternary ?:)

The conditional operator (written as ?:) is the only operator in C that accepts three operands. It acts as a compact, inline decision-maker that evaluates a condition and resolves to one of two alternative values.

Conditional Operator Syntax:
condition ? value_if_true : value_if_false
  • condition: Any expression that evaluates to true (non-zero) or false (0).
  • value_if_true: The value returned if the condition is non-zero (true).
  • value_if_false: The value returned if the condition is zero (false).

Real-Life Example: Pass or Fail Grade Classification

If a student scores 40 or higher, their result is "Pass"; otherwise, it is "Fail":

conditional_ternary_demo.c 
#include <stdio.h>

int main(void)
{
    int marks = 65;

    /* Ternary operator selects string literal based on condition */
    const char *result = (marks >= 40) ? "Pass" : "Fail";

    printf("Marks: %d\n", marks);
    printf("Result: %s\n", result);

    return 0;
}
Exact Expected Output:
Marks: 65
Result: Pass

Conditional Operator (?:) vs. if-else Statement

Comparison Metric Ternary Operator (?:) if-else Statement
Syntactic Nature An expression (computes and produces a value). A control-flow statement (executes blocks of code).
Assignment Integration Can be placed directly on the right-hand side of assignments. Requires separate assignment statements inside both branches.
Nesting & Readability Ideal for simple binary choices; messy when nested deeply. Clean and easily readable for multi-step complex branching.
Example int max = (a > b) ? a : b; if (a > b) max = a; else max = b;

Bitwise Operators & Binary Masking

Unlike arithmetic or logical operators that treat numbers as monolithic quantities, bitwise operators manipulate the individual binary bits (0s and 1s) within an integer variable. They are fundamental in embedded systems, device drivers, cryptography, and network packet parsing.

Operator Name Bit-Level Rule Example (a=5 [0101], b=3 [0011])
& Bitwise AND Result bit is 1 only if both operand bits are 1. 5 & 3 → 0001 (Decimal 1)
| Bitwise OR Result bit is 1 if at least one operand bit is 1. 5 | 3 → 0111 (Decimal 7)
^ Bitwise XOR Result bit is 1 if bits are different (one 0, one 1). 5 ^ 3 → 0110 (Decimal 6)
~ Bitwise NOT Unary: inverts all bits (0 becomes 1, 1 becomes 0). ~5 → ...11111010 (Two's comp: -6)
<< Left Shift Shifts bits left by $N$ positions; zero-fills on right. 5 << 1 → 1010 (Multiplies by 2 → 10)
>> Right Shift Shifts bits right by $N$ positions; discards low bits. 5 >> 1 → 0010 (Divides by 2 → 2)
👉 Visual 4-Bit Calculation: 5 (0101) and 3 (0011)

  0 1 0 1 (5)          0 1 0 1 (5)           0 1 0 1 (5)
& 0 0 1 1 (3)        | 0 0 1 1 (3)         ^ 0 0 1 1 (3)
───────────────      ───────────────      ───────────────
  0 0 0 1 = 1          0 1 1 1 = 7           0 1 1 0 = 6
bitwise_operations_demo.c 
#include <stdio.h>

int main(void)
{
    int a = 5; /* Binary: 0101 */

    printf("a & b:  %d\n", a & b);
    printf("a | b:  %d\n", a | b);
    printf("a ^ b:  %d\n", a ^ b);
    printf("a << 1: %d\n", a << 1);
    printf("a >> 1: %d\n", a >> 1);

    return 0;
}
Exact Expected Output:
a & b:  1
a | b:  7
a ^ b:  6
a << 1: 10
a >> 1: 2
DO NOT CONFUSE: && vs. & and || vs. |

Writing if (a & b) when you meant if (a && b) is a subtle, dangerous bug!

  • If a = 4 (0100) and b = 2 (0010):
  • a && b evaluates to 1 (True) because both 4 and 2 are non-zero truthy values!
  • a & b evaluates to 0 (False) because 0100 & 0010 = 0000!

sizeof & Type-Cast Operators

The sizeof operator inspects hardware memory usage, while the type-cast operator commands the compiler to convert data types explicitly.

The sizeof Operator

sizeof is a compile-time operator that returns the exact memory footprint (in bytes) occupied by a data type or variable in the current target architecture.

sizeof_operator_demo.c 
#include <stdio.h>

int main(void)
{
    int age = 18;

    /* %zu is the standard C99/C11 format specifier for size_t */
    printf("Size of int: %zu bytes\n", sizeof(int));
    printf("Size of age: %zu bytes\n", sizeof age);

    return 0;
}
Exact Expected Output (Standard 32/64-bit Systems):
Size of int: 4 bytes
Size of age: 4 bytes
Standard Format Specifier: %zu The result of sizeof is of type size_t (an unsigned integer type defined by standard C). Always print sizeof using %zu rather than %d to maintain 100% portable 64-bit compliance.

The Explicit Type-Cast Operator

As mastered in Topic 05, the cast operator (destination_type)expression forces an explicit conversion. It carries high precedence (Rank 2) and is most famously used to prevent unintended integer division:

cast_division_review.c 
#include <stdio.h>

int main(void)
{
    /* Casting 5 to double promotes division to floating-point math */
    double result = (double)5 / 2;

    printf("Result: %.2f\n", result);

    return 0;
}
Exact Expected Output:
Result: 2.50
📚 Section 13 • Section L

Comma Operator & Member Access Overview

C features several auxiliary operators that serve specialized roles in expressions, sequential statements, and compound data types.

The Comma Operator (,)

The comma operator has the lowest precedence in the entire C language (Rank 15). It links two or more expressions together, evaluating them strictly from left to right. The value and type of the entire comma expression are determined solely by the rightmost expression:

comma_operator_demo.c 
#include <stdio.h>

int main(void)
{
    int a, x;

    /* Left operand (a = 5) runs first; then right operand (a + 10) evaluates.
       The final evaluated value (15) is assigned to x. */
    x = (a = 5, a + 10);

    printf("a = %d, x = %d\n", a, x);

    return 0;
}
Exact Expected Output:
a = 5, x = 15
CRITICAL DISTINCTION: Comma Operator vs. Comma Separator

Not every comma in C is the comma operator!

  • In int x = 10, y = 20;: Commas are syntax separators in a variable declaration list.
  • In printf("%d %d", a, b);: Commas are function argument delimiters. (The compiler does not guarantee left-to-right evaluation between function arguments!).
  • In for (i = 0, j = 10; i < j; i++, j--): Commas are true comma operators executing multiple step statements sequentially.

Member Access Operators (Preview)

When you study Structures and Pointers in later chapters, you will encounter two member-access operators:

  • Dot Operator (.): Accesses a member of a structure directly (e.g. student.marks).
  • Arrow Operator (->): Accesses a member through a pointer to a structure (e.g. ptr->marks).

Expressions & Step-by-Step Evaluation Trees

A C expression is built by weaving variables and constants together with operators. To understand how complex expressions compute, we trace them step by step or visualize them as hierarchical evaluation trees.

Comparing Unparenthesized vs. Parenthesized Evaluation

Case 1: a + b * 2 (where a = 10, b = 5)

1. Look up precedence: * is Rank 3; + is Rank 4.
2. Multiplication groups first: b * 2 → 5 * 2 = 10.
3. Addition executes next: a + 10 → 10 + 10 = 20.

Final Evaluated Value: 20
Case 2: (a + b) * 2 (where a = 10, b = 5)

1. Look up precedence: Parentheses () have highest priority.
2. Sub-expression in parens evaluates: a + b → 10 + 5 = 15.
3. Multiplication executes next: 15 * 2 = 30.

Final Evaluated Value: 30

Common Beginner Mistakes & Debugging (14 Traps)

Operator bugs can be insidious because code often compiles cleanly without syntax errors, yet produces completely erroneous calculations or silent crashes at runtime. Master these 14 common traps:

Trap / Mistake Flawed Code & Why It Fails Corrected Code & Rationale
1. Confusing = with == if (marks = 100)
Overwrites marks to 100; evaluates to true unconditionally!		 if (marks == 100)
Tests equality without modifying variable value.
2. Using & instead of && if (a > 0 & b > 0)
Performs bitwise AND without short-circuiting; inefficient and prone to bitmask errors.		 if (a > 0 && b > 0)
Short-circuits if a > 0 is false.
3. Using | instead of || if (ptr == NULL | *ptr == 0)
CRASH! Evaluates right side even if pointer is NULL!		 if (ptr == NULL || *ptr == 0)
Safe! Short-circuits if pointer is NULL.
4. Expecting 5 / 2 to give 2.5 double d = 5 / 2;
Yields 2.00 due to integer truncation before assignment.		 double d = (double)5 / 2; or 5.0 / 2;
Yields 2.50 using floating division.
5. Misunderstanding % with floats float rem = 10.5 % 3.0;
Compile Error: % requires integer operands!		 Use fmod(10.5, 3.0) from <math.h> for floating-point remainder.
6. Assuming x++ and ++x are identical int y = x++; expecting y to receive incremented value. int y = ++x; if you need y to receive the updated incremented value.
7. Forgetting operator precedence int avg = a + b / 2;
Divides only b by 2!		 int avg = (a + b) / 2;
Parentheses force addition before division.
8. Missing parentheses in bitwise expressions if (status & MASK == 1)
== has higher precedence than &! Groups as status & (MASK == 1).		 if ((status & MASK) == 1)

10. Wrong printf format specifier printf("%d\n", 5.5);
Corrupted output (prints raw IEEE 754 bits as int).		 printf("%.2f\n", 5.5);

11. Unsequenced side-effects i = i++ + 1; or arr[i] = i++;
Undefined behavior!		 Separate increments into distinct standalone lines: i++;

Topic / Concept Standard C Rule Key Example & Takeaway
Operator vs. Operand Operators are symbols that act on data; operands are the data values. In 10 + 5: 10, 5 are operands, + is operator.

Part 2: Short-Answer Questions (8 SAQs)

SAQ 1: Differentiate between an operator, an operand, and an expression.
Answer: An operator is a symbol specifying an action (e.g. +); an operand is a data value acted upon (e.g. 10, 5); and an expression is a combination of operators and operands that evaluates to a single result (e.g. 10 + 5 yields 15).
SAQ 2: Why does integer division truncate toward zero in C?
Answer: Under the ISO C standard, dividing two integers always yields an integer. Any fractional remainder is strictly discarded toward zero (e.g. 7 / 2 = 3 and -7 / 2 = -3).
SAQ 3: Explain the difference between prefix increment (++x) and postfix increment (x++).
Answer: Prefix ++x increments the variable in memory first and returns the updated value to the expression. Postfix x++ returns the current value to the expression first, and then increments the variable in memory.
SAQ 4: What is short-circuit evaluation in C logical expressions?
Answer: In logical && and ||, the compiler evaluates operands left-to-right and halts evaluation as soon as the final truth outcome is guaranteed (e.g., if left of && is false, right operand is never evaluated).
SAQ 5: How does operator precedence differ from operator associativity?
Answer: Precedence determines which operator groups first when operators have different priorities. Associativity determines whether grouping proceeds Left-to-Right or Right-to-Left when operators share the same precedence level.
SAQ 6: Why is writing i = i++ + ++i; considered bad practice?
Answer: Modifying the same scalar variable multiple times within a single expression without an intervening sequence point creates Undefined Behavior under the C standard, leading to unpredictable, compiler-dependent bugs.
SAQ 7: What does the bitwise complement operator (~) do?
Answer: It is a unary operator that inverts every individual bit of an integer operand, converting all 1s to 0s and all 0s to 1s.
SAQ 8: When is a comma treated as a comma operator versus a syntactic separator?
Answer: In variable declarations (int a, b;) and function arguments (f(a, b);), commas are syntax delimiters. In expressions like x = (a = 5, a + 2); or loop steps for (..; ..; i++, j--), commas are comma operators that evaluate left-to-right.
