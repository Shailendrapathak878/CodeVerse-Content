Introduction to Type Conversion & Real-Life Concepts

In C programming, every piece of data stored in memory has a strictly declared data type (such as int, float, double, or char). However, realistic software calculations frequently require values of differing types to interact. Understanding how, why, and when C converts values between types is essential to writing accurate, bug-free programs.

Definition: What is a Data Type vs. Type Conversion?
  • Data Type: An attribute that tells the compiler how many bytes to allocate, how to interpret the binary bits in memory (integer two's complement vs. IEEE 754 floating-point), and which operations are mathematically valid.
  • Type Conversion: The process of transforming a data value from its current data type representation into an equivalent or approximating representation of another data type.

Why Does C Convert Values Between Types?

At the hardware level, the Central Processing Unit's Arithmetic Logic Unit (ALU) cannot directly add a 32-bit two's complement integer to a 64-bit IEEE 754 floating-point number. Both inputs must share an identical hardware representation before any arithmetic operation can execute. C automatically or explicitly converts values in three primary contexts:

Where Conversion Occurs C Language Example Underlying Mechanism
1. Assignment Statements double salary = 50000; The integer literal 50000 is converted to the floating-point value 50000.0 before storing it in the variable salary.
2. Mixed-Type Expressions double total = 10 + 2.5; The integer 10 is promoted to double (10.0) so floating-point addition can occur: 10.0 + 2.5 = 12.5.
3. Function Call Arguments sqrt(16); /* expects double */ The integer argument 16 is automatically converted to 16.0 (double) to match the function prototype's formal parameter type.
CRITICAL CONCEPT: Converting a Value vs. Changing Variable Type

In C, variables are statically typed. Once declared (for example, int count = 10;), the variable count will ALWAYS remain an int in memory until the program terminates.

When C performs a conversion (e.g., double x = count; or (double)count), C does NOT change the type of count itself. Instead, C reads the value stored inside count, creates a temporary converted copy in a CPU register, and uses that new copy for the operation. The original variable count remains completely untouched!

Real-Life Analogy: Measurement Units & Currency

Imagine you have a wooden ruler measuring 250 centimeters. If an architect requests the length in meters, you tell them 2.5 meters.

The physical piece of wood did not stretch, shrink, or change its physical reality—only the unit of measurement and numeric representation changed. Similarly, converting an integer 10 to a double 10.0 preserves the mathematical magnitude while altering the underlying binary representation to allow fractional calculations.

Two Main Types of Conversion: Implicit vs. Explicit

Type conversion in C is broadly divided into two major categories depending on whether the conversion happens automatically under the compiler's language rules, or is manually instructed by the programmer.

⚙️ 1. Implicit Type Conversion

Also called automatic type coercion or type promotion. Performed quietly by the C compiler without explicit instructions written in the source code.

  • Triggered by mixed expressions or type mismatch in assignments.
  • Usually moves from smaller/narrower types to wider types (e.g., int → double).
  • Zero extra syntax required in source code.

🖊️ 2. Explicit Type Casting

Also called type casting. Explicitly initiated by the programmer using the cast operator (target_type).

  • Programmer gives a direct command to convert an expression.
  • Used to prevent unintended integer division or force a narrower type.
  • Forces compiler compliance even when data loss may occur.

WARNING: Explicit Casting Does NOT Guarantee Safety or Zero Data Loss!

A very common misconception among beginners is believing that writing (int) makes a conversion "safe". It does not! A cast is merely an instruction that tells the compiler: "Trust me, convert this value right now."

If you explicitly cast a large number that cannot fit into the destination type, data truncation, overflow, or undefined behavior will still occur. You remain responsible for validating your data values!

📚 Section 04 • Section C

Implicit Type Conversion: Rules, Widening & Truncation

Implicit conversion occurs behind the scenes. When assigning a value of one type to a variable of another type, C automatically converts the right-hand value to match the left-hand variable's type.

Example 1: Integer to Floating-Point (Safe Widening)

When a smaller integer type is assigned to a floating-point type (such as float or double), C converts the integer into floating-point format. For ordinary integer values, this conversion is completely lossless.

implicit_int_to_double.c 
#include <stdio.h>

int main(void)
{
    int number = 10;
    double result = number; /* Implicit conversion: int to double */

    printf("Number: %d\n", number);
    printf("Result: %.1f\n", result);

    return 0;
}
Program Output:
Number: 10
Result: 10.0
Why is this conversion safe? An IEEE 754 64-bit double provides 53 bits of precision in its mantissa. A standard 32-bit signed int requires at most 31 bits of magnitude. Since 53 > 31, every possible 32-bit integer value can be represented exactly inside a double with zero mathematical loss!

Example 2: Floating-Point to Integer (Truncation Toward Zero)

When a finite floating-point value is converted to an integer type, the fractional part after the decimal point is completely discarded. This process is called truncation toward zero.

implicit_double_to_int.c 
#include <stdio.h>

int main(void)
{
    double value = 9.8;
    int number = value; /* Implicit conversion: double to int */

    printf("Original: %.1f\n", value);
    printf("Converted: %d\n", number);

    return 0;
}
Program Output:
Original: 9.8
Converted: 9
CRITICAL RULE: Truncation is NOT Rounding!

Notice that 9.8 became 9, NOT 10! In standard mathematics, 9.8 rounds up to 10. But in C type conversion, no rounding ever takes place. The fractional digits are simply stripped off. Even 9.999999 becomes 9 when converted to an integer.

Negative Floating-Point Values: Truncation Toward Zero

What happens when a negative floating-point number is converted to an integer? Consider:

negative_truncation_demo.c 
#include <stdio.h>

int main(void)
{
    double negValue = -9.8;
    int number = negValue;

    printf("Original: %.1f\n", negValue);
    printf("Converted: %d\n", number);

    return 0;
}
Program Output:
Original: -9.8
Converted: -9

Because the conversion rule is truncation toward zero, moving toward zero from -9.8 brings us to -9 (not -10). Both positive and negative numbers drop their decimal part directly towards zero.

Standard Range Requirement: Undefined Behavior on Out-of-Range Floats

Under the ISO C Standard (ISO/IEC 9899 §6.3.1.4), when a finite floating-point value is converted to an integer type, the value must be representable in that integer type.

If you attempt to convert a floating-point number that is too large or too small to fit into the destination integer (for example, assigning 1e15 to a 32-bit signed int whose maximum value is ~2.14 × 10^9), the behavior is completely undefined. The computer might produce garbage values, trigger hardware exceptions, or behave unpredictably. Never convert out-of-range floats!

📚 Section 05 • Section D

Explicit Type Casting & The Cast Operator

There are times when the compiler's automatic implicit conversion rules do not produce the result you need. In such cases, you can take explicit command of the conversion by using the cast operator.

Cast Operator Syntax:
(destination_type) expression
  • destination_type: The data type you want the evaluated value converted to (e.g., int, double, float, char), enclosed in required parentheses ().
  • expression: The variable, constant, or formula whose resulting value will be converted.
  • Operator Precedence: The cast operator is a unary operator with very high precedence (precedence level 2), meaning it binds tightly to the operand immediately following it.

Example 1: Explicitly Casting double to int

In financial or inventory calculations, you may want to extract the whole currency amount or item count while deliberately ignoring fractional cents or portions:

cast_double_to_int.c 
#include <stdio.h>

int main(void)
{
    double price = 99.75;
    int wholePrice = (int)price; /* Explicit cast: discards fractional .75 */

    printf("Original price: %.2f\n", price);
    printf("Casted price: %d\n", wholePrice);

    return 0;
}
Program Output:
Original price: 99.75
Casted price: 99

Example 2: Explicitly Casting int to double in Division

This is arguably the most famous and vital use case for explicit type casting in all of C programming. When two integers are divided, C performs integer division. To obtain an exact decimal answer, at least one operand must be cast to a floating-point type:

cast_int_division.c 
#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = 2;

    /* Explicitly cast 'a' to double before dividing */
    double result = (double)a / b;

    printf("Result: %.2f\n", result);

    return 0;
}
Program Output:
Result: 2.50
THE CLASSIC ROOKIE TRAP: Why double result = a / b; Fails!

Look closely at what happens if you omit the cast and write:

double result = a / b; /* a = 5, b = 2 */

Beginners frequently think: "Since result is a double, the division will give me 2.50!"
WRONG! In C, expressions are evaluated according to the types of their operands, completely unaware of what variable will receive the result later:

  1. Both a (5) and b (2) are integers.
  2. Therefore, a / b performs integer division first, discarding the fractional remainder: 5 / 2 = 2.
  3. Only AFTER the division is finished does C perform an assignment conversion of the integer 2 into double (2.0).
  4. Printing with %.2f produces 2.00, completely losing the 0.50!
📚 Section 06 • Section E

Integer Division vs. Floating-Point Division (Deep Dive)

One of the most frequent stumbling blocks for beginner programmers in C is predicting how the division operator (/) behaves. The exact same symbol / performs two fundamentally different operations depending on whether its operands are integers or floating-point numbers.

Division Expression Division Type Result What Actually Happens
5 / 2 Integer Division 2 Both operands are int. Quotient is 2; remainder 1 is completely discarded.
(double)5 / 2 Floating Division 2.50 Numerator cast to double (5.0). Denominator promoted to 2.0. Exact decimal division.
7 / 2 Integer Division 3 Both integers. 7 divided by 2 gives 3; the fractional .5 is lost.
(double)7 / 2 Floating Division 3.50 Casting 7 yields 7.0 / 2.0 = 3.50.
(double)(7 / 2) Truncated then Cast 3.00 TRAP! Parentheses force 7 / 2 first (yields 3), then (double)3 becomes 3.00.

Step-by-Step Execution Walkthrough

Let us trace exactly how the C compiler evaluates (double)a / b when a = 5 and b = 2:

  1. Operator Precedence: The cast operator (double) has higher precedence (level 2) than division / (level 3). Therefore, (double) binds to a first, before any division happens.
  2. Casting a: The value of a (5) is converted to a temporary double value: 5.0.
  3. Usual Arithmetic Conversions: The expression is now 5.0 / b. Because one operand is double and the other is int, C automatically promotes b from 2 to 2.0.
  4. Floating-Point Division: The hardware floating-point unit divides 5.0 / 2.0, resulting in the double value 2.5.
division_demonstration.c 
#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = 2;

    printf("Integer division (a / b):        %d\n", a / b);
    printf("Floating division ((double)a / b): %.2f\n", (double)a / b);
    printf("Alternate denominator cast (a / (double)b): %.2f\n", a / (double)b);

    return 0;
}
Program Output:
Integer division (a / b):        2
Floating division ((double)a / b): 2.50
Alternate denominator cast (a / (double)b): 2.50

Usual Arithmetic Conversions in Expressions

When an operator takes two operands of different arithmetic types, C applies a standardized set of conversion rules called the Usual Arithmetic Conversions. The primary objective is to bring both operands to a single common type so the operation can be performed accurately.

The General Rule of Usual Arithmetic Conversions:

In any binary arithmetic expression (such as +, -, *, /), if the operands have different types, C automatically promotes the "lower" or narrower type to match the "higher" or wider type before performing the calculation. The result of the expression inherits that higher type.

#include <stdio.h>

int main(void)
{
    int a = 10;
    double b = 2.5;

    /* 'a' is implicitly promoted to double before addition */
    double result = a + b;

    printf("Result: %.2f\n", result);

    return 0;
}
Program Output:
Result: 12.50
Remember: Order Does NOT Dictate Promotion! Whether you write a + b or b + a, C examines the types of both operands. Since double ranks higher than int, the int is always promoted to double regardless of which side it appears on.
📚 Section 08 • Section G

Data Loss, Precision Loss & Overflow Risks

Converting values is not always a free or lossless operation. While widening conversions (like int → double) preserve values reliably, narrowing conversions (like double → int or long → short) can cause truncation, loss of precision, sign corruption, or even undefined behavior.

Conversion Category Risk / Data Loss Type Standard C Behavior
double → int Loss of fractional digits (0.85, 0.99) Truncates toward zero (e.g. 7.9 → 7, -7.9 → -7).
Larger int to Narrower int Magnitude overflow (number too big for target) High-order bits discarded. For signed types, implementation-defined or signal; for unsigned, modulo arithmetic.
double → float Loss of precision (53 bits down to 24 bits) Least significant digits rounded to nearest representable float value.
Signed to Unsigned Negative values lose sign meaning Converted modulo $2^N$ (one more than type max). -1 → UINT_MAX.
Float Out-of-Range of int Catastrophic range overflow UNDEFINED BEHAVIOR under ISO C standard §6.3.1.4.

Unsigned Conversion & Modulo Arithmetic

In C, converting any integer value to an unsigned integer type is mathematically defined: the value is converted modulo $(M + 1)$, where $M$ is the maximum value representable by that unsigned type. Therefore, converting -1 to unsigned int produces exactly UINT_MAX on every portable standard C compiler:

unsigned_modulo_conversion.c 
#include <stdio.h>
#include <limits.h> /* Provides UINT_MAX portably */

int main(void)
{
    int negOne = -1;
    unsigned int u = (unsigned int)negOne;

    printf("Original signed value:  %d\n", negOne);
    printf("Converted unsigned value: %u\n", u);
    printf("Value of UINT_MAX:      %u\n", UINT_MAX);

    return 0;
}
Program Output (Standard 32-bit int platform):
Original signed value:  -1
Converted unsigned value: 4294967295
Value of UINT_MAX:      4294967295

Implicit vs. Explicit Conversion: Comprehensive Comparison

To master C type handling, programmers must clearly distinguish when to let the compiler perform implicit conversions automatically and when to explicitly step in with a cast.

Comparison Feature Implicit Conversion (Coercion) Explicit Casting (Cast Operator)
How It Is Requested Occurs automatically through standard C language rules. Programmer explicitly writes the cast operator: (type)expr.
Typical Code Syntax double x = 5;
double sum = 10 + 2.5;		 int whole = (int)5.8;
double ratio = (double)num / den;
Primary Purpose Ensures CPU hardware compatibility in mixed-type arithmetic and assignments. Overrides default behavior (e.g. forcing float division or discarding decimals).
Direction / Flow Usually widens (promotes from narrower type to wider type). Can convert in any direction (widening or narrowing).
Readability & Intent Silent and invisible in source code. Explicitly documents the programmer's intentional design choice.
Main Risk Silent precision loss or hidden unexpected conversions. Deliberately overriding safety checks; silencing valid compiler warnings.
BEST PRACTICE: Never Cast Just to Silence a Compiler Warning!

A dangerous habit among novice programmers is slapping (int) or (float) onto an expression merely to make a compiler warning disappear without understanding why the warning appeared.

If the compiler warns of a potential truncation, investigate whether your variable should have been declared as a double in the first place, or if your arithmetic formula is logically flawed. Adding a cast merely forces the compiler to be quiet—it does not fix logic errors!

Common Beginner Mistakes & Diagnostic Fixes

Type conversion errors frequently introduce silent logical bugs that compile without warnings but produce completely wrong mathematical calculations. Study these ten traps and their exact fixes.

Trap / Mistake Flawed Code & Why It Fails Corrected Code & Rationale
1. Expecting 5 / 2 to give 2.5 double r = 5 / 2;
Produces 2.00 because both operands are integer literals, discarding the 0.5.		 double r = 5.0 / 2; or (double)5 / 2;
Produces 2.50 by making at least one operand floating-point.
2. Assigning a / b to double expecting float division int a=5, b=2;
double avg = a / b;
Division evaluates first as integer math before assignment takes place.		 double avg = (double)a / b;
Cast executes before division, triggering floating-point division.
3. Believing (int)9.8 rounds to 10 int score = (int)9.8;
Becomes 9. C truncates toward zero; it never rounds.		 #include <math.h>
int score = (int)round(9.8);
Rounds to 10 using standard math library.
4. Forgetting negative truncation moves toward zero int n = (int)-9.8;
Assuming it rounds down to -10.
Actually yields -9.		 Understand that C truncation always discards fractional digits toward zero for both signs. Use floor() if floor semantics are needed.
5. Assuming conversions are always lossless float f = 16777217;
printf("%f\n", f);
Prints 16777216.0 due to float 24-bit significand limit.		 Use double (53 bits significand) when dealing with large integers needing decimal operations.

int n = (int)big;
Undefined behavior! Crashes or garbage output.		 Verify big >= INT_MIN && big <= INT_MAX before casting to signed int.

(double)x;
/* expects x to be double now */		 Variables in C are statically typed. x remains an int forever. Only the temporary evaluated value is converted.

printf("%d\n", val);
Prints corrupted binary garbage!		 printf("%.2f\n", val);
Always match specifiers: %d for int, %f for double/float.
9. Assuming integer widths are identical everywhere Assuming long is always 64 bits. On Windows x64, long is 32 bits; on Linux x64, long is 64 bits. Use <stdint.h> types like int32_t or int64_t when exact bit widths are required.
10. Casting blindly to silence warnings Writing (int)foo blindly to remove a compiler warning without analyzing potential truncation bugs. Analyze the diagnostic. Change variable declarations or refactor algorithms rather than masking bugs with blind casts.
📚 Section 12 • Section K (Program 1)

Program 1: Integer to Double Conversion

Problem Statement: Write a complete, portable C program that stores an integer quantity, converts that value to a double using both implicit assignment and explicit casting, and prints both the original integer and the converted floating-point representations with designated decimal formatting.

program1_int_to_double.c 
#include <stdio.h>

int main(void)
{
    /* Step 1: Declare and initialize an integer variable */
    int quantity = 42;

    /* Step 2: Implicit conversion upon assignment to a double variable */
    double implicitDouble = quantity;

    /* Step 3: Explicit type casting using the cast operator */
    double explicitDouble = (double)quantity;

    /* Step 4: Display the values using appropriate format specifiers */
    printf("Original Integer Value:     %d\n", quantity);
    printf("Implicitly Converted Double: %.2f\n", implicitDouble);
    printf("Explicitly Casted Double:   %.4f\n", explicitDouble);

    return 0;
}
Exact Expected Output:
Original Integer Value:     42
Implicitly Converted Double: 42.00
Explicitly Casted Double:   42.0000

Line-by-Line Explanation

  • int quantity = 42;: Allocates 4 bytes of integer storage and initializes it to 42 in standard two's complement binary.
  • double implicitDouble = quantity;: The C compiler automatically translates the 32-bit integer bits into a 64-bit IEEE 754 floating-point representation (42.0). Zero loss of precision occurs.
  • double explicitDouble = (double)quantity;: The programmer explicitly requests conversion via (double). While identical in machine result to the implicit line, it explicitly documents intent in complex formulas.
  • printf("... %.2f\n", implicitDouble);: Uses the %.2f format specifier to render the floating-point value to 2 decimal places (42.00).
Key Takeaway & Safe Limits: Converting int to double is safe for all standard 32-bit integer values because double has 53 bits of significand (exact up to $2^{53} \approx 9 \times 10^{15}$).
📚 Section 13 • Section K (Program 2)

Program 2: Decimal to Integer Truncation Toward Zero

Problem Statement: Write a standard C program demonstrating how floating-point numbers are converted to integers. Specifically verify that C performs truncation toward zero for both positive numbers (e.g. 9.75) and negative numbers (e.g. -9.75), rather than rounding.

program2_truncation_demo.c 
#include <stdio.h>

int main(void)
{
    /* Positive decimal demonstration */
    double positiveDecimal = 9.75;
    int posInt = (int)positiveDecimal;

    /* Negative decimal demonstration */
    double negativeDecimal = -9.75;
    int negInt = (int)negativeDecimal;

    /* Extreme decimal just under 10 */
    double nearTen = 9.999;
    int nearTenInt = (int)nearTen;

    printf("Positive original: %.2f  --> Converted integer: %d\n", positiveDecimal, posInt);
    printf("Negative original: %.2f --> Converted integer: %d\n", negativeDecimal, negInt);
    printf("Near-ten original: %.3f --> Converted integer: %d\n", nearTen, nearTenInt);

    return 0;
}
Exact Expected Output:
Positive original: 9.75  --> Converted integer: 9
Negative original: -9.75 --> Converted integer: -9
Near-ten original: 9.999 --> Converted integer: 9

Line-by-Line Explanation

  • int posInt = (int)positiveDecimal;: The fractional portion .75 is discarded. The value moves toward zero to produce 9.
  • int negInt = (int)negativeDecimal;: For -9.75, moving toward zero produces -9 (it does not round down to -10).
  • int nearTenInt = (int)nearTen;: Even though 9.999 is virtually indistinguishable from 10.0 in practical life, C truncates the fractional digits unconditionally, yielding 9.
Crucial Risk: If the floating-point number exceeds the maximum or minimum bounds representable by signed int (roughly $-2.14 \times 10^9$ to $+2.14 \times 10^9$), ISO C specifies that the behavior is undefined. Always ensure floats are within integer bounds before casting!

Program 3: Accurate Average Marks Calculation

Problem Statement: Write a program that stores three integer exam marks for a student. Compute the average two ways: first using naive division showing how integer division silently introduces errors, and second using explicit casting to preserve the exact fractional score.

program3_average_marks.c 
#include <stdio.h>

int main(void)
{
    /* Three student exam marks as integers */
    int mark1 = 85;
    int mark2 = 90;
    int mark3 = 88;

    int totalMarks = mark1 + mark2 + mark3; /* 85 + 90 + 88 = 263 */

    /* Flawed calculation: integer division stored in double */
    double flawedAverage = totalMarks / 3;

    /* Correct calculation: explicit cast forces floating-point division */
    double correctAverage = (double)totalMarks / 3;

    printf("Total Marks: %d (out of 300)\n", totalMarks);
    printf("Flawed Average (without cast):  %.2f\n", flawedAverage);
    printf("Correct Average (with cast):    %.2f\n", correctAverage);

    return 0;
}
Exact Expected Output:
Total Marks: 263 (out of 300)
Flawed Average (without cast):  87.00
Correct Average (with cast):    87.67

Line-by-Line Explanation & Mathematical Trace

  • int totalMarks = mark1 + mark2 + mark3;: Sums the three integer marks to 263.
  • double flawedAverage = totalMarks / 3;: Both 263 and 3 are integers. C calculates integer division: $263 \div 3 = 87$ remainder 2. The remainder is discarded. Then 87 is converted to 87.0 for assignment, completely losing 0.67!
  • double correctAverage = (double)totalMarks / 3;: The cast (double) converts 263 to 263.0. The division becomes $263.0 \div 3.0 = 87.66666...$, which prints as 87.67 under %.2f.
Academic Impact: A student receiving 87.00% instead of 87.67% could miss a grade cutoff or scholarship qualification entirely due to an un-casted integer division bug!

Program 5: Mixed-Type Physics / Geometry Formula

This program computes the volume of a cylinder ($V = \pi r^2 h$) where the radius is an integer, height is a float, and $\pi$ is a double constant.

program5_cylinder_volume.c 
#include <stdio.h>

int main(void)
{
    const double PI = 3.141592653589793;
    int radius = 5;          /* Integer radius */
    float height = 12.5f;    /* Float height */

    /* Mixed arithmetic: double * int * int * float
       Step 1: radius * radius -> int * int = 25 (int)
       Step 2: PI * 25 -> double * int -> 25 promoted to double -> 78.5398... (double)
       Step 3: 78.5398... * height -> double * float -> height promoted to double
       Final result is double */
    double volume = PI * (radius * radius) * height;

    printf("Cylinder Radius: %d units\n", radius);
    printf("Cylinder Height: %.1f units\n", height);
    printf("Calculated Volume: %.2f cubic units\n", volume);

    return 0;
}
Exact Expected Output:
Cylinder Radius: 5 units
Cylinder Height: 12.5 units
Calculated Volume: 981.75 cubic units

Quick Revision Sheet & Conversion Pipeline Matrix

A compact summary of all core type conversion rules, syntax patterns, division behaviors, and safety boundaries in C programming.

Concept / Term Standard C Rule & Syntax Key Example & Behavior
Type Conversion Translates a value from one data type representation to another. int 10 → double 10.0 (Representation changes; variable type does not).
Implicit Conversion Performed automatically by the compiler without source-code annotations. double d = 15; → promotes 15 to 15.0.
Explicit Type Casting Programmer overrides default types using (type)expression. (double)5 / 2 forces floating division yielding 2.50.
Integer Division When both operands are integers, fractional parts are truncated toward zero. 5 / 2 → 2; 7 / 2 → 3; -7 / 2 → -3.
Floating-Point Division When at least one operand is float or double, exact decimal math runs. 5.0 / 2 → 2.50; (double)7 / 2 → 3.50.
Truncation Toward Zero Floating-point conversion to integer discards all fractional digits toward zero. (int)9.8 → 9; (int)-9.8 → -9. (Not rounded!).
Precision Loss Converting higher-precision types to narrower types loses least significant digits. double (53 bits) down to float (24 bits) rounds to nearest float.
Range-Related Risks Converting a float that exceeds destination integer limits is UNDEFINED. (int)1e15 is undefined behavior under ISO C §6.3.1.4.
Mixed Arithmetic Operands promoted along hierarchy ladder (int → float → double). 10 + 2.5 promotes 10 to 10.0, result is 12.50.

Part 2: Short-Answer Questions (6 SAQs)

SAQ 1: What is the fundamental difference between type conversion and type casting?
Answer: Type conversion is the general umbrella term for translating a value between types, encompassing both automatic compiler rules (implicit conversion) and manual commands. Type casting specifically refers to explicit conversion requested directly by the programmer using the (type) operator.
SAQ 2: Why does C perform integer division when evaluating 7 / 2?
Answer: Because both operands (7 and 2) have integer types. In C, operator behavior is dictated entirely by operand types. Integer division computes the whole quotient and truncates any fractional remainder toward zero.
SAQ 3: Explain the concept of "truncation toward zero" with an example.
Answer: Truncation toward zero means discarding all fractional decimal digits such that the resulting integer moves towards zero on the number line. For example, 9.85 becomes 9 (moves left toward 0), while -9.85 becomes -9 (moves right toward 0). It is strictly not rounding.
SAQ 4: What are "Usual Arithmetic Conversions"?
Answer: A standardized set of C language rules applied to binary arithmetic operators (+, -, *, /) when their operands differ in type. The compiler automatically promotes the narrower operand type to match the wider operand type so hardware ALU operations can execute consistently.
SAQ 5: Why is converting a 32-bit integer to double considered safe, while converting to float might lose precision?
Answer: A 64-bit double has 53 bits of precision in its significand, which easily accommodates the 31 bits of magnitude of a 32-bit signed int without loss. Conversely, a 32-bit float has only 24 bits of significand, so integer values larger than $2^{24} = 16,777,216$ cannot always be represented exactly and will lose precision.
SAQ 6: Why should programmers avoid using type casts solely to silence compiler warnings?
Answer: Compiler warnings alert developers to unintended truncations, potential data loss, or type mismatches. Blindly adding a cast forces the compiler to suppress the warning without fixing the root cause, masking potential software defects and logical calculation bugs.
