Hough Transform & Geometric Detection

Edges sirf tooti-phooti boundary pixels dete hain. Hough Transform ek revolutionary parameter-space voting technique hai jo inhi scattered pixels ko mathematically combine karke straight lines, highway road lanes, aur circular coins/bearings detect karti hai!

⏱ ~6-8 min read 🎯 Target: OpenCV 4.x + Python 📊 Difficulty: Beginner to Intermediate 🔗 Requires: Topics 7, 8 & 10
01

What is the Hough Transform? (The Voting Analogy)

Imagine kijiye aap ek self-driving car ke liye camera image process kar rahe hain. Canny edge detector road ke kinaron par hazaron 1-pixel white dots nikaalta hai. Par computer ko kaise pata chalega ki kaunse dots milkar ek straight highway lane bana rahe hain?

Yahin par kaam aata hai Hough Transform:

🗻 1. Image Space to Parameter Space

Image ke har ek edge pixel (x, y) ko parameter space mein map kiya jata hai. Ek point se infinite lines guzar sakti hain!

🗳 2. The Accumulator Voting Process

Ek 2D voting grid (Accumulator) banti hai. Har edge pixel un sabhi lines ke liye ek "Vote" daalta hai jinpar wo lie karta hai.

🏆 3. Peak Voting Wins

Grid cell jisme sabse zyada votes jama hote hain, wo announce karti hai: "Mujhpar 200 edge pixels lie karte hain, main ek real straight line hoon!"

💡 Why Preprocessing is Mandatory:
Hough Transform direct raw BGR image par run nahi hota! Pehle Gaussian Blur se noise reduce karna hota hai, aur fir Canny Edge Detection se 1-pixel binary boundary map nikaalna padta hai. Agar image mein noise hoga to accumulator galat peaks (false lines) detect kar lega!
Figure 12.1: The 3-step Hough workflow: Original Scene → Canny 1-px Edge Map → Hough Accumulator Voting Space (θ vs ρ). Notice how bright peaks represent detected lines!
02

Line Detection: Standard Hough Lines (cv2.HoughLines)

School geometry mein hum line ki equation y = mx + c padhte hain. Lekin image processing mein ek problem hai: jab line bilkul vertical (khadi) hoti hai, to slope m → ∞ ho jata hai, jisse computer division by zero se crash ho sakta hai!

Isiliye Hough Transform Polar Coordinate System use karta hai:

ρ = x · cos(θ) + y · sin(θ)
  • ρ (rho): Origin (0, 0) se line tak ka perpendicular distance (in pixels).
  • θ (theta): Perpendicular line dwara horizontal X-axis ke saath banaya gaya angle (in radians, usually 0 to π).

🔍 Function Signature: cv2.HoughLines()

lines = cv2.HoughLines(edges, rho=1, theta=np.pi/180, threshold=100)
Parameter Meaning & Recommended Value Impact on Detection
rho Distance resolution (typically 1 pixel). Chhoti value zyada precision deti hai, badi value vote grouping fast karti hai.
theta Angle resolution (typically π / 180 = 1 degree in radians). Angle step size. 1 degree accuracy standard hai.
threshold Minimum votes needed in accumulator cell (e.g. 100 votes). Zyada threshold = sirf lambi/prominent lines; Kam threshold = noisy faint lines.
⚠ Note on Standard Hough Output:
cv2.HoughLines() finite line segments nahi deta! Ye infinite lines (anant rekhaayein) ke (ρ, θ) parameters return karta hai jo poori image ke cross pass hoti hain!
Figure 12.2: Standard cv2.HoughLines() output. Infinite green lines plotted across the canvas using polar equations.

Hands-on Code: Detect Straight Lines with cv2.HoughLines

import cv2 import numpy as np # 1. Image load karein aur Grayscale mein convert karein img = cv2.imread('grid_lines.png') gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY) # 2. Canny edge detector se 1-pixel boundary nikaalein edges = cv2.Canny(gray, 50, 150) # 3. Standard Hough Line Transform (rho=1 px, theta=1 deg, threshold=100 votes) lines = cv2.HoughLines(edges, rho=1, theta=np.pi/180, threshold=100) print(f"Kul {len(lines)} lines detect hui!") # 4. Infinite lines draw karne ke liye polar coordinates se do endpoints nikaalein output = img.copy() if lines is not None: for line in lines: rho, theta = line[0] a = np.cos(theta) b = np.sin(theta) x0 = a * rho y0 = b * rho # Line ko 1000 pixels aage-peeche extend karein x1 = int(x0 + 1000 * (-b)) y1 = int(y0 + 1000 * (a)) x2 = int(x0 - 1000 * (-b)) y2 = int(y0 - 1000 * (a)) cv2.line(output, (x1, y1), (x2, y2), (0, 255, 0), 2)
✔ Output Console: Kul 8 lines detect hui! (Thick lines ki dono boundaries capture hui)
03

Probabilistic Hough Lines (cv2.HoughLinesP)

Standard Hough algorithm slow hota hai kyunki wo har edge pixel ke liye voting compute karta hai. Saath hi, ye real-life line segments ke start aur end points nahi deta.

Probabilistic Hough Transform (cv2.HoughLinesP) iska perfect solution hai:

  • Random Sampling: Ye edge pixels ke random subset ko sample karta hai, jisse speed 10× fast ho jaati hai!
  • Exact Line Segments: Ye direct finite segment coordinates return karta hai: [x1, y1, x2, y2]!

🔍 Key Extra Parameters in HoughLinesP

lines = cv2.HoughLinesP(edges, 1, np.pi/180, threshold=50, minLineLength=40, maxLineGap=15)

minLineLength

Minimum pixel length. Isse chhoti lines reject ho jayengi. Chhote noisy dashes ko filter out karne ke liye useful hai.

maxLineGap

Maximum allowed gap between broken segments. Agar ek hi line ke do pieces beech mein 15 pixels se kam toote hain, to OpenCV unhe jodkar ek single segment bana dega!

Figure 12.3: Comparison on road lane markings. (Left) Standard Hough draws infinite orange rays. (Right) Probabilistic HoughLinesP accurately isolates finite green segments with cyan endpoints.

Hands-on Code: Lane Marking Detection with HoughLinesP

# Probabilistic Hough Line Transform run karein lines_p = cv2.HoughLinesP( edges, rho=1, theta=np.pi/180, threshold=30, # Accumulator threshold minLineLength=20, # Reject lines shorter than 20 px maxLineGap=15 # Connect broken dashed gaps up to 15 px ) output_p = img.copy() if lines_p is not None: for line in lines_p: x1, y1, x2, y2 = line[0] # Seedhe endpoints ke beech line segment draw karein cv2.line(output_p, (x1, y1), (x2, y2), (0, 230, 118), 3) # Endpoints par cyan dots banayein cv2.circle(output_p, (x1, y1), 4, (255, 255, 0), -1) cv2.circle(output_p, (x2, y2), 4, (255, 255, 0), -1)
✔ Output Console: Detected finite segments: (202, 261) → (202, 39), Length = 222.0 px

Circle Detection: Hough Circle Transform (cv2.HoughCircles)

Circle ki equation hoti hai: (x - xc)2 + (y - yc)2 = r2. Isme 3 unknowns hote hain: Center coordinates (xc, yc) aur Radius r.

Agar hum 3D voting accumulator banayein to memory blast ho jayegi! Isiliye OpenCV Hough Gradient Method use karta hai: edge gradient ki direction seedhe circle ke center ki taraf point karti hai, jisse calculation fast 2D space mein ho jaati hai.

🔍 Function Signature & Parameters:

circles = cv2.HoughCircles(blurred, cv2.HOUGH_GRADIENT, dp=1.2, minDist=80, param1=100, param2=35, minRadius=20, maxRadius=90)
Parameter Recommended Function & Practical Role
dp 1.0 ya 1.2 Inverse accumulator resolution. 1.0 par original image resolution jitni voting hoti hai.
minDist Distance in px (e.g. 80) Do alag-alag circle centers ke beech ka minimum distance. Ek hi coin par multiple duplicate circles avoid karta hai!
param1 100 Internal Canny edge detector ka higher threshold (lower threshold automatically param1 / 2 hoti hai).
param2 ★ 30 to 50 Accumulator voting threshold for center detection. Jitna chota hoga, utne zyada false ghost circles aayenge; jitna bada hoga, utne strict detections honge!
minRadius / maxRadius Expected size range Sirf specific size ke circles dhoondhne ke liye (e.g. coin ka radius 25px se 80px ke beech). Compute time bachta hai!
Figure 12.4: cv2.HoughCircles() successfully extracting exact center coordinates (Red dots), boundary rings (Green), and radius lengths (Yellow) for 3 synthetic coins.

⚗ Sensitivity Tuning: The Critical Impact of param2

Circle detection mein sabse common mistake param2 ko galat set karna hota hai:

Figure 12.5: Real test execution showing the effect of param2: (A) param2=18 causes false positive ghost circles; (B) param2=45 accurately isolates both real circles; (C) param2=85 is too strict and misses the faint left circle.

Hands-on Code: Circle Detection with Sensitivity Check

import cv2 import numpy as np img = cv2.imread('coins.png') gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY) # 1. Circle detection ke liye strong Gaussian blur zaroori hai! blurred = cv2.GaussianBlur(gray, (9, 9), 2) # 2. Hough Circles run karein circles = cv2.HoughCircles( blurred, cv2.HOUGH_GRADIENT, dp=1.2, minDist=80, param1=100, param2=35, minRadius=25, maxRadius=80 ) if circles is not None: circles = np.uint16(np.around(circles)) print(f"Kul {len(circles[0])} circles detect hue!") for pt in circles[0, :]: cx, cy, r = int(pt[0]), int(pt[1]), int(pt[2]) # Outer circle (Green) cv2.circle(img, (cx, cy), r, (0, 230, 118), 3) # Center point (Red dot) cv2.circle(img, (cx, cy), 4, (0, 0, 255), -1) print(f" Center: ({cx}, {cy}), Radius: {r} px")
✔ Output Console:
Kul 2 circles detect hue!
Center: (340, 151), Radius: 59 px
Center: (121, 151), Radius: 45 px

Combined Geometric Detection & Industry Applications

Real-world industrial vision systems mein scenes mein lines aur circles dono ek saath exist karte hain (jaise conveyor belt ke straight rails par aane wale cylindrical bearings ya cans):

Figure 12.6: Joint geometric detection: Yellow segments represent structural rails detected by HoughLinesP, while Magenta rings represent circular parts detected by HoughCircles.
Algorithm Technique Real-Life Industry Application Why Hough is Used
cv2.HoughLinesP() Autonomous Lane Keeping (ADAS) Road ki tooti hui dashed markings ko connect karke vehicle lane trajectory nikaalna.
cv2.HoughLines() Document Deskewing & OCR Scanned paper ke straight horizontal page borders detect karke tilt angle (θ) se image seedhi karna.
cv2.HoughCircles() Coin & Currency Sorters Fast processing mein coins ke accurate centers aur radii nikaalkar cash denomination count karna.
cv2.HoughCircles() Bottle Cap & Eye Iris Tracking Assembly lines par bottle caps ki sealing check karna aur biometric scanners mein pupil detect karna.
⚠ Practical Limitation in Modern Computer Vision:
Hough Transform ek mathematical feature extractor hai, koi full-fledged autonomous driving model ya general AI object detector (jaise YOLO) nahi hai! High lighting changes, curved bends ya cluttered backgrounds mein ise advanced filtering ya deep learning ke saath combine kiya jata hai.

Hands-on Code: Combined Geometric Fusion

# Conveyor scene par lines aur circles dono extract karein lines = cv2.HoughLinesP(edges, 1, np.pi/180, threshold=60, minLineLength=80, maxLineGap=10) circles = cv2.HoughCircles(blurred, cv2.HOUGH_GRADIENT, dp=1.2, minDist=50, param1=100, param2=30, minRadius=20, maxRadius=60) print(f"Conveyor rails: {len(lines)} line segments detected.") print(f"Moving items: {len(circles[0])} circular bearings detected.")
✔ Output Console:
Conveyor rails: 4 line segments detected.
Moving items: 1 circular wheel at center (200, 151) with radius 39 px detected.

Common Beginner Mistakes & Fixes

❌ Mistake 1: HoughCircles se pehle GaussianBlur skip karna
Problem: Camera image ke subtle high-frequency pixel noise par hundreds of fake ghost circles detect ho jate hain.
Solution: Hamesha cv2.GaussianBlur(gray, (9, 9), 2) ya median blur zaroor apply karein!
⚠ Mistake 2: Standard HoughLines mein minLineLength pass karna
Problem: TypeError: HoughLines() takes at most 4 arguments.
Solution: minLineLength aur maxLineGap sirf cv2.HoughLinesP() ke parameters hain! Standard HoughLines infinite lines return karta hai.
💡 Mistake 3: param1 aur param2 ko aapas mein confuse karna
Problem: param1 internal Canny edge detection sensitivity hai, jabki param2 circle center voting accumulator threshold hai! Agar circle detect nahi ho rahe, to pehle param2 ko dheere-dheere kam (e.g. 40 se 25) karein!

Mini Knowledge Check

❓ Q1: Image processing mein y = mx + c ke bajaye polar coordinates ρ = x cos(θ) + y sin(θ) kyun use karte hain?
  • A) Kyunki vertical lines par slope m → ∞ ho jata hai jisse divide by zero error aata hai.
  • B) Kyunki polar coordinates se image black and white ho jaati hai.
  • C) Kyunki Python mein slope calculate karna impossible hai.
  • D) Kyunki polar coordinates sirf circles detect karte hain.
✅ Correct Answer: A
Explanation: Vertical line (90°) ka slope mathematically infinite (∞) hota hai, jise digital memory store nahi kar sakti. Polar system mein vertical line simply θ = 90° ya 0° se cleanly represent ho jaati hai!
❓ Q2: cv2.HoughLines() aur cv2.HoughLinesP() ke output format mein kya mukhya antar hai?
  • A) HoughLines infinite line parameters (ρ, θ) deta hai, jabki HoughLinesP finite line segments ke coordinates (x1, y1, x2, y2) deta hai.
  • B) HoughLinesP sirf 3D video par chalta hai.
  • C) Dono identical output dete hain.
  • D) HoughLinesP circles return karta hai.
✅ Correct Answer: A
Explanation: cv2.HoughLinesP probabilistic random sampling use karke finite segment endpoints [x1, y1, x2, y2] return karta hai, jo road lanes draw karne ke liye perfect hain!
❓ Q3: Agar cv2.HoughCircles() run karne par image mein actual circle ke alawa bahut saare false "ghost circles" detect ho rahe hain, to kya karna chahiye?
  • A) param2 ki value badhaayein (e.g. 20 se 40 ya 50 karein).
  • B) param2 ko 0 kar dein.
  • C) Image ko delete kar dein.
  • D) OpenCV ko reinstall karein.
✅ Correct Answer: A) param2 ki value badhaayein
Explanation: param2 accumulator threshold hai. Ise badhane se sirf wahi centers pass honge jinhe bohot saare edge pixels vote karte hain, jisse false ghost circles filter out ho jaate hain!
