Section 01

Introduction to Classification

In machine learning, supervised learning tasks split into two primary branches: predicting continuous quantities (regression) and categorizing observations into distinct buckets (classification).

Every day, software systems make millions of instantaneous decisions:

  • Email spam detection: Does an incoming email belong in your inbox (Not Spam) or should it be diverted to junk (Spam)?
  • Financial fraud monitoring: Is a credit card swipe at 3:00 AM in a foreign city legitimate (Normal) or fraudulent (Fraud)?
  • Healthcare screening: Does an emergency room triage scan indicate a positive pathological abnormality (Positive) or a clear, benign scan (Negative)?
  • Customer churn prevention: Will an active SaaS subscriber renew their contract next month (Retained) or cancel their account (Churn)?
💡 Regression vs. Classification: Fundamental Contrast

In Regression (Topic 9), the target y is a continuous numerical measurement that can take infinitely many values on a real number scale (such as predicting a house selling price of $354,250.00, or a temperature of 24.6 °C).

In Classification, the target y is a categorical qualitative label. The model chooses between mutually exclusive categories or assigns a probability to each category.

Comparison Table: Regression vs Classification Tasks

Task Domain Input Features (X) Target Type Target Output (y) Learning Task
Real Estate Square footage, bedrooms, postal code Continuous Number $425,000.00 USD Regression
Email Security Keyword frequencies, sender reputation, links Categorical Label Spam vs. Not Spam Classification
Banking Fraud Transaction amount, merchant category, time Categorical Label Legitimate vs. Fraudulent Classification
Subscription SaaS Login frequency, open support tickets, days active Categorical Label Churn vs. Retained Classification
Automotive Engine displacement, vehicle weight, horsepower Continuous Number 32.4 Miles Per Gallon Regression

What Is Binary Classification?

When a classification task involves exactly two possible outcomes, it is called binary classification. By convention, machine learning engineers encode these two classes numerically as:

  • Class 0 (Negative Class): The baseline, standard, or unexceptional state (e.g., Not Spam, Legitimate Transaction, Healthy Scan, Retained Customer).
  • Class 1 (Positive Class): The event, alert, or anomaly of interest (e.g., Spam, Fraudulent Charge, Condition Detected, Customer Churned).
⚠ Critical Beginner Pitfall: The Meaning of Numbers 0 and 1

Do not confuse binary class labels 0 and 1 with mathematical quantities! A spam email is not “one unit greater” than a legitimate email.

The numerals 0 and 1 are purely discrete category identifiers. They represent qualitative states, not continuous points on a physical number line.

Section 02

What Is Logistic Regression?

Despite having the word “Regression” in its historic name, Logistic Regression is the world’s most foundational and widely deployed supervised algorithm for Classification.

Why is it called “regression” if it performs classification? The answer lies in its internal mathematical architecture:

📖 The Historic Paradox Explained

Internally, Logistic Regression computes a standard linear regression score:
z = β0 + β1x1 + β2x2 + ... + βpxp

However, instead of outputting this linear score directly as a final continuous quantity, it feeds z into a non-linear mathematical filter called the Sigmoid Activation Function. The sigmoid squashes the unbounded score into a strict probability between 0.0 and 1.0. A decision threshold then assigns the final class.

Foundational Vocabulary: Terms Defined Before Use

Term Plain-English Definition Concrete Example
Feature (X) A measurable property or input attribute used to make a prediction. Weekly study hours: x = 18.5
Target / Label (y) The true known ground-truth outcome in the dataset. Exam passed: y = 1; Exam failed: y = 0
Linear Score (z) The raw weighted sum of features plus an intercept bias. Unbounded: (-∞, +∞). z = -2.5 + (0.35 × 18.5) = +3.975
Class Probability (p) The model’s estimated likelihood that the observation belongs to Class 1. Bounded: (0, 1). p = P(y = 1 | x) = 0.9816 (98.16%)
Decision Threshold (τ) The cutoff probability separating Class 0 from Class 1. Default is 0.50. If p ≥ 0.50, predict ŷ = 1
Predicted Class (ŷ) The final categorical assignment made after applying the threshold. ŷ = 1 (Pass)
Model Coefficient (β) The learned slope reflecting how much the log-odds change per unit increase in that feature. βstudy = +0.35 (more hours increase pass odds)

A Relatable Concrete Example: Student Exam Pass/Fail

Suppose an academic department trains a Logistic Regression model to predict whether university students will pass a rigorous mathematics exam based on two features: weekly study hours and attendance percentage.

Student ID Study Hours Attendance Calculated Score (z) Estimated Probability (p) Threshold (τ=0.50) Predicted Class (ŷ) Actual Label (y)
STU-001 4.5 hrs 52.0% -2.14 0.1053 (10.5%) p < 0.50 0 (Fail) 0 (Fail) ✔
STU-002 12.0 hrs 78.5% +0.45 0.6106 (61.1%) p ≥ 0.50 1 (Pass) 1 (Pass) ✔
STU-003 22.5 hrs 95.0% +3.82 0.9786 (97.9%) p ≥ 0.50 1 (Pass) 1 (Pass) ✔
STU-004 8.0 hrs 68.0% -0.08 0.4800 (48.0%) p < 0.50 0 (Fail) 1 (Pass) ✘ (FN)

Notice student STU-004: their estimated probability was 48.0%, which is just below the 0.50 cutoff. The model predicted Fail, but the student actually passed. This reveals a vital machine learning principle:

🔴 Probabilities Are Model Estimates, Not Guarantees

A predicted probability of p = 0.85 does not mean the outcome is 100% guaranteed. It means that under the model’s learned parameters, similar students have an estimated 85% statistical likelihood of passing. In the real world, human performance and health outcomes always retain stochastic variability.

Section 03

Why Not Use Ordinary Linear Regression for Classification?

When beginners first encounter binary classification, a natural thought emerges: “Since labels are 0 and 1, why not just fit an Ordinary Least Squares (OLS) line through the points and round to the nearest whole number?”

While mathematically possible to fit an OLS line, doing so introduces severe structural flaws:

1

Out-of-Bounds Predictions: Probabilities Less Than 0 or Greater Than 1

An ordinary linear regression equation ŷ = β0 + β1x is a straight, unbounded line. For small or large feature values, the line extends to -∞ and +∞. A model that predicts a student has a -35% or +140% probability of passing violates fundamental probability axioms.

2

Extreme Vulnerability to Outliers in Feature Space

In linear regression, OLS minimizes squared residual errors. If you introduce a student who studied 50 hours and easily passed (a valid extreme positive point), OLS tilts the entire line to minimize the squared error on that far point. This slope tilt changes predictions for ordinary students in the middle, pushing previously passing students into the failing category!

3

Severe Heteroscedasticity (Non-Constant Variance)

In linear regression, residuals are assumed to have constant variance (σ2). In binary outcomes, the variance is Var(y | x) = p(x)(1 - p(x)). The variance is near zero when p ≈ 0 or p ≈ 1, and peaks at 0.25 when p = 0.5. Fitting a standard linear regression model directly violates Gauss-Markov assumptions, rendering standard OLS hypothesis testing and p-values invalid.

Figure 10.2: Straight Linear Fit vs. S-Curve Sigmoid Fit. The linear regression line (left) produces nonsense values below 0.0 and above 1.0. In contrast, Logistic Regression (right) smoothly squashes all predictions into the open interval (0, 1).
✔ Key takeaway: Logistic regression does not force a straight line through binary labels; it models the underlying probability using a bounded non-linear activation curve.
Section 04

Understanding the Sigmoid Function

The mathematical heartbeat of Logistic Regression is the Standard Logistic Function, universally known in machine learning as the Sigmoid Function.

🔢 The Standard Sigmoid Activation Formula
σ(z) = 1 / (1 + e-z)
z: The input linear score (weighted sum β0 + ∑ βjxj). Domain: (-∞, +∞).
e: Euler’s natural mathematical constant (≈ 2.7182818).
e-z: Exponential decay term (1 / ez).
σ(z): Sigmoid output probability. Range: strictly (0.0, 1.0).

Step-by-Step Numerical Calculations (Python Verified)

Let us calculate the exact output of the sigmoid function for five critical benchmark values of linear score z:

Linear Score (z) e-z Calculation Denominator: 1 + e-z Sigmoid σ(z) = 1 / (1 + e-z) Interpretation
z = 0.0 e-0.0 = 1.0000 1 + 1.0000 = 2.0000 1 / 2.0000 = 0.5000 (50.0%) Perfect 50/50 uncertainty (boundary center)
z = +1.8 e-1.8 = 0.1653 1 + 0.1653 = 1.1653 1 / 1.1653 = 0.8581 (85.81%) Moderate positive confidence
z = -1.8 e+1.8 = 6.0496 1 + 6.0496 = 7.0496 1 / 7.0496 = 0.1419 (14.19%) Moderate negative confidence
z = +5.0 e-5.0 = 0.00674 1 + 0.00674 = 1.00674 1 / 1.00674 = 0.9933 (99.33%) High positive confidence (near upper asymptote)
z = -5.0 e+5.0 = 148.413 1 + 148.413 = 149.413 1 / 149.413 = 0.0067 (0.67%) High negative confidence (near lower asymptote)
Figure 10.3: The Sigmoid Curve Geometry and Asymptotes. The function produces an S-shaped curve centered at (0, 0.5). Notice how values of z = +1.8 and z = -1.8 sum exactly to 1.0.
✔ Mathematical Elegance: σ(z) + σ(-z) = 1.0 for any real number z.

Three Architectural Superpowers of the Sigmoid

  1. Strict Bounded Range (0, 1): No matter how enormous a positive score becomes (e.g., z = +100), e-100 ≈ 0, so σ(100) ≈ 0.999999... < 1.0. Similarly, if z = -100, σ(-100) ≈ 0.00000... > 0.0. Probabilities can never cross 0 or 1.
  2. Maximum Sensitivity in the Center: The first derivative of the sigmoid is dσ/dz = σ(z) × (1 - σ(z)). At z = 0, the slope is 0.5 × (1 - 0.5) = 0.25 (its steepest rate of change). Small changes in input features create decisive shifts when the model is uncertain, but taper off safely when the model is already confident.
  3. Saturated Plateau at the Extremes: As |z| grows past 4, the curve flattens horizontally into asymptotes. This prevents extreme outliers from exerting disproportionate leverage on the decision boundary.
Section 05

The Logistic Regression Equation

Now that we understand both the linear score and the sigmoid curve, we assemble the complete mathematical formulation for binary logistic regression.

1. Single-Feature Formulation (Univariate)

When making a prediction based on one input feature x:

🔢 Single-Feature Logistic Model
P(y = 1 | x) = σ(β0 + β1x) = 1 / (1 + e-(β0 + β1x))
x: Input feature value (e.g., study hours).
β0: Intercept (bias) term. Determines baseline probability when x = 0.
β1: Slope coefficient. Controls steepness and direction of the S-curve.

2. Multiple-Feature Formulation (Multivariate)

In realistic machine learning applications, we predict outcomes using p input features x1, x2, ..., xp:

🔢 Multiple Logistic Regression Model
z = β0 + β1x1 + β2x2 + ... + βpxp = β0 + ∑j=1p βjxj
P(y = 1 | x) = σ(z) = 1 / (1 + e-z)

Complete Worked Arithmetic Walkthrough

Suppose an ad-tech company trains a multiple logistic regression model to predict whether a website visitor will click on a banner advertisement (y = 1) based on two features:

  • x1: Time spent on website (minutes).
  • x2: Number of previous purchases.

The learned model parameters are:
β0 = -3.20 (Intercept), β1 = +0.45, β2 = +0.60.

Now consider a visitor who spent 6 minutes on the site (x1 = 6.0) and has made 2 previous purchases (x2 = 2.0). Let us compute the prediction step-by-step:

1

Calculate the Linear Score (z)

z = β0 + β1x1 + β2x2
z = -3.20 + (0.45 × 6.0) + (0.60 × 2.0)
z = -3.20 + 2.70 + 1.20 = +0.70

2

Calculate the Exponential Term

e-z = e-0.70 ≈ 0.496585

3

Compute the Sigmoid Probability

P(Click = 1 | x) = 1 / (1 + 0.496585) = 1 / 1.496585 ≈ 0.6682 (66.82%)

4

Apply Decision Threshold and Classify

Using standard threshold τ = 0.50:
Since 0.6682 ≥ 0.50, the model outputs: Predicted Class ŷ = 1 (Visitor Will Click).

🐍 python_verification.py • Manual Arithmetic Check Python 
import numpy as np

# 1. Model parameters
beta_0 = -3.20
beta_1 = 0.45
beta_2 = 0.60

# 2. Input features
x1 = 6.0  # Time on site (minutes)
x2 = 2.0  # Prior purchases

# 3. Calculate linear score z
z = beta_0 + (beta_1 * x1) + (beta_2 * x2)
print(f"Linear score z: {z:.4f}")  # Expected: +0.7000

# 4. Apply Sigmoid function
prob = 1.0 / (1.0 + np.exp(-z))
print(f"Estimated Click Probability: {prob:.4%}")  # Expected: 66.82%

# 5. Apply threshold tau = 0.50
prediction = 1 if prob >= 0.50 else 0
print(f"Predicted Class: {prediction} (Will Click)")

assert np.isclose(prob, 0.6682, atol=0.001)

Section 06

Understanding Odds, Log-Odds and Logits

To truly understand how Logistic Regression connects linear algebra to probability, we must explore the mathematical bridge that links probabilities, odds, and log-odds (logits).

1. What Are Odds? (Probability vs. Odds)

In everyday conversation, people often treat the words “probability” and “odds” as interchangeable synonyms. In statistics and machine learning, they are strictly distinct mathematical quantities:

🔢 Probability vs. Odds Formulation
Probability (p) = Successes / Total Trials ∈ [0, 1]
Odds = p / (1 - p) = Successes / Failures ∈ [0, +∞)

Consider a student with an 80% probability of passing an exam (p = 0.80):

  • Probability: p = 0.80 (out of 10 attempts, 8 are passes and 2 are fails).
  • Odds: Odds = 0.80 / (1 - 0.80) = 0.80 / 0.20 = 4.0 (or “4 to 1” in favor of passing).

2. What Are Log-Odds (The Logit Function)?

Notice that Odds are bounded on the left at 0.0 (an impossible event has Odds = 0.0), but stretch infinitely to the right towards +∞. This asymmetry makes odds awkward for standard linear modeling.

To solve this asymmetry, we take the natural logarithm (ln) of the odds. This transformation is called the Logit Function:

🔢 The Logit (Log-Odds) Equation
logit(p) = ln(Odds) = ln(p / (1 - p)) ∈ (-∞, +∞)

Taking the log of odds maps the probability range (0, 1) onto the entire continuous real number line from -∞ to +∞!

Figure 10.4: The Three Representations of Likelihood. Probability p is bounded between 0 and 1; Odds range from 0 to +∞; Log-Odds (logit) are symmetric across the real line (-∞, +∞).
✔ The Core Insight: Logistic regression performs standard linear regression directly on the Log-Odds of the target event.

3. Interpreting Model Coefficients via the Odds Ratio (OR)

Because the model equation is:
ln(Odds) = β0 + β1x1 + ... + βpxp

If feature x1 increases by 1 unit while all other features remain constant:

🔢 The Odds Ratio (OR) Formula
Odds Ratio (OR) = eβj
OR > 1.0: Feature increases the odds of the outcome (positive coefficient).
OR = 1.0: Feature has zero effect on the odds (βj = 0).
OR < 1.0: Feature decreases the odds of the outcome (negative coefficient).

Concrete Example: In our student exam model, the coefficient for completed assignments was β = +1.20.
The Odds Ratio is: e1.20 = 3.3201.
Interpretation: Each additional assignment completed is associated with a 3.32-fold increase in the odds of passing the exam, assuming all other factors remain constant.

⚠ Critical Caution: Do Not Confuse Odds with Probability or Causality!

An odds ratio of 3.32 does NOT mean the student’s probability increased by 332%! Odds and probabilities scale differently.

Furthermore, learned coefficients represent statistical associations in observational training data, not proven causal mechanisms. A high coefficient does not prove that forcing a metric to change will automatically cause the outcome.

Section 07

Decision Threshold (τ) and Predicted Class

Logistic regression outputs a continuous probability p ∈ (0, 1). To turn that probability into an actionable binary classification decision (Class 0 or Class 1), we apply a Decision Threshold (τ).

🔢 Threshold Decision Rule
ŷ = 1   if   p ≥ τ   |   ŷ = 0   if   p < τ

The universal default threshold across software libraries (including scikit-learn) is τ = 0.50:

  • If P(y = 1 | x) ≥ 0.50, predict Class 1.
  • If P(y = 1 | x) < 0.50, predict Class 0.

Why 0.50 Is Not Always the Right Threshold

A threshold of 0.50 assumes that false positives and false negatives carry exactly identical costs. In the real world, this is rarely true!

Figure 10.5: Shifting Decision Thresholds Across 6 Sample Probabilities. Lowering the threshold to τ=0.30 classifies 5 samples as positive. Raising it to τ=0.70 classifies only 2 samples as positive.
✔ Trade-off Rule: Lowering τ increases Recall (catches more positive cases); Raising τ increases Precision (fewer false alarms).

🎯 Selecting the Right Operating Threshold

Scenario 1: Medical Cancer Screening (High Cost of False Negative)
Missing a malignant tumor (False Negative) can be fatal, while a false alarm (False Positive) is verified with a follow-up biopsy. Doctors intentionally lower the threshold to τ = 0.20 or 0.30 to maximize Recall.

Scenario 2: Email Spam Filter (High Cost of False Positive)
Accidentally sending an urgent job offer or court notice to the spam folder (False Positive) is unacceptable. Engineers raise the threshold to τ = 0.85 or 0.90 so only emails that are overwhelmingly likely to be junk are diverted.

Section 08

The Decision Boundary

A Decision Boundary is the geometric surface in feature space where the model’s estimated probability exactly equals the decision threshold: P(y = 1 | x) = τ.

Under the standard threshold τ = 0.50, the decision boundary occurs exactly when the linear score equals zero:
σ(z) = 0.50 ⇔ z = 0

🔢 Decision Boundary Equation (τ = 0.50)
β0 + β1x1 + β2x2 + ... + βpxp = 0
Figure 10.6: Geometric Decision Boundaries. In 1D feature space (left), the boundary is a single cutoff point x* = -β0 / β1. In 2D feature space (right), the boundary is a straight dividing line separating Class 0 and Class 1.
✔ Crucial Principle: Standard Logistic Regression creates a linear decision boundary in the original feature space.

How Feature Transformations Create Non-Linear Boundaries

Beginners often mistakenly believe that Logistic Regression can only ever separate linearly separable data. While the decision boundary is linear with respect to the input features, you can engineer polynomial or interaction terms:

🧪 Engineering Non-Linear Boundaries

If you add quadratic terms to the model:
z = β0 + β1x12 + β2x22 = 0

The decision boundary in the original (x1, x2) plane becomes an ellipse or circle! The model remains linear in its parameters (β), but its boundary in the raw input space curves around complex data patterns.

Section 09

How Does Logistic Regression Learn? (Maximum Likelihood Estimation)

In Linear Regression, we found optimal parameters using the closed-form Ordinary Least Squares (OLS) formula β = (XTX)-1XTy. In Logistic Regression, the presence of the non-linear sigmoid function makes a closed-form analytical solution impossible.

Instead, Logistic Regression learns its weights through an iterative optimization procedure grounded in Maximum Likelihood Estimation (MLE).

The 7-Step Training Lifecycle

1

Initialize Coefficients

Start with initial coefficient guesses (typically all zeros or small random weights).

2

Calculate Linear Scores

For each training observation i, compute zi = β0 + ∑ βjxij.

3

Apply Sigmoid Transformation

Compute estimated probabilities: pi = 1 / (1 + e-zi).

4

Evaluate Training Loss

Compare predicted probabilities pi against true binary labels yi using Binary Cross-Entropy (Log Loss).

5

Calculate the Gradient Error

Compute the gradient vector: ∇J = (1 / n) × XT(p - y). Notice how clean this gradient is: the error is simply the probability residual (pi - yi)!

6

Update Parameters via Numerical Solvers

Update weights to decrease loss. Production libraries (like scikit-learn) use second-order quasi-Newton algorithms (such as lbfgs or newton-cg) rather than basic gradient descent for rapid convergence.

7

Check Convergence Criteria

Repeat steps 2 through 6 until the gradient reaches near zero (tolerance tol = 1e-4) or maximum iterations are exhausted.

🔍 What Is Maximum Likelihood Estimation (MLE)?

Maximum Likelihood asks: “Out of all possible coefficient combinations (β), which specific set of weights makes the true training outcomes we actually observed most statistically probable?”

Because multiplying hundreds of probabilities between 0 and 1 causes floating-point underflow (approaching zero), mathematicians take the log of the likelihood function. Maximizing log-likelihood is mathematically equivalent to minimizing negative log-likelihood (Log Loss).

Section 10

Log Loss / Binary Cross-Entropy

The loss function that Logistic Regression minimizes during training is Binary Cross-Entropy, commonly referred to as Log Loss.

🔢 The Average Binary Log Loss Formula
J(β) = - (1 / n) ∑i=1n [ yi ln(pi) + (1 - yi) ln(1 - pi) ]
n: Number of training samples.
yi: Actual binary ground truth (0 or 1).
pi: Model’s predicted probability for Class 1 (between 0 and 1).
ln: Natural logarithm (base e).
J(β): Total average log loss (always ≥ 0). Lower is better!

How the Formula Adapts to Each Class

The beauty of the formula is how its two terms activate conditionally based on true label yi:

  • When actual label y = 1: The second term (1 - y) × ln(1 - p) becomes zero. The loss simplifies to:
    Loss = -ln(p)
  • When actual label y = 0: The first term y × ln(p) becomes zero. The loss simplifies to:
    Loss = -ln(1 - p)
Figure 10.7: Log Loss Curves for Positive (Left) and Negative (Right) Examples. Notice how predicting p = 0.10 when true y = 1 triggers a 2.303 penalty, compared to just 0.105 when predicting p = 0.90 (a 21.8× penalty!).
✔ Core Mechanism: Log Loss severely punishes confident, arrogant mistakes far more harshly than modest uncertainty.

🔧 Practical Numerical Handling: Epsilon Probability Clipping

In pure mathematics, ln(0) = -∞. If a model predicted exactly p = 0.0 on an observation whose true label was y = 1, the loss would evaluate to infinity, crashing numerical software.

To prevent this, production libraries like scikit-learn clip probabilities internally into a safe floating-point range: p = np.clip(p, 1e-15, 1 - 1e-15) before computing log loss.

Section 11

Simple and Multiple Logistic Regression

Just like linear models, Logistic Regression expands naturally from a single feature (simple) to multidimensional spaces containing dozens or hundreds of predictors (multiple).

Dimension Aspect Simple Logistic Regression (1 Feature) Multiple Logistic Regression (p Features)
Linear Score z = β0 + β1x z = β0 + ∑j=1p βjxj
Geometry 1D S-curve; decision cutoff is a point on a line. Multidimensional sigmoid manifold; decision boundary is a hyperplane.
Feature Interactions None; captures only isolated univariate effect. Jointly models multivariate predictors simultaneously.
Key Hazard Omitted variable bias (underfitting). Multicollinearity and curse of dimensionality.

1. Feature Scaling and Coefficient Comparability

In multiple logistic regression, each coefficient βj reflects the change in log-odds per one-unit increase in that feature’s specific measurement unit.

  • If study hours ranges from 0 to 30, a one-unit change is a 1-hour increase.
  • If student family income is measured in dollars (e.g., $10,000 to $150,000), a one-unit change is just a single $1.00 increase! Its raw coefficient might be +0.00004, appearing artificially tiny.
🛠 Best Practice: Standardize Features Before Interpreting Coefficients

Always apply StandardScaler so every feature has zero mean and unit variance (z-score). With standardized inputs, coefficient magnitudes directly reflect relative predictive importance across features!

2. Multicollinearity: The Problem with Redundant Features

When two or more predictor features are strongly correlated (e.g., total study hours and total study minutes, or attendance percentage and lectures attended), they contain redundant information.

Multicollinearity inflates the standard errors of the coefficients, causing weights to oscillate wildly and making individual coefficient signs unreliable. Regularization provides the primary defense.

Section 12

Regularization and Overfitting (The C Parameter)

When a dataset has many features relative to sample size, or when data is perfectly linearly separable, unconstrained Logistic Regression drives weights toward extreme values to force probabilities close to 0 and 1. This creates severe overfitting.

Regularization solves this by adding a penalty term to the loss function that discourages excessively large coefficients:

🔢 Regularized Loss Formulations
L2 Regularization (Ridge): Jreg = Jlogloss + λ ∑j=1p βj2
L1 Regularization (Lasso): Jreg = Jlogloss + λ ∑j=1p |βj|

Understanding Scikit-Learn’s Inverted C Parameter

In theoretical textbooks, regularization strength is denoted by λ (lambda), where larger λ means stronger penalty.
In scikit-learn, the LogisticRegression class uses parameter C, which is the inverse of regularization strength:

🔢 The Scikit-Learn Parameter Relationship
C = 1 / λ
Small C (e.g., C = 0.01): Huge penalty (λ=100). Aggressively shrinks weights towards zero. Fights overfitting.
Default C (C = 1.0): Standard balanced penalty (λ=1). Scikit-learn default.
Large C (e.g., C = 100.0): Tiny penalty (λ=0.01). Weights can grow freely. Risk of overfitting.
Figure 10.8: Weight Shrinkage Under Varying C Values. In our lab model, setting C = 0.01 shrinks the total weight vector norm to 0.4443, compared to 3.8803 at C = 1.0 and 7.7703 at C = 100.0.
✔ Critical Memory Rule: In scikit-learn, smaller C = stronger regularization.
🔧 Solver and Penalty Compatibility in Scikit-Learn

Not every optimization solver supports every penalty!

  • solver='lbfgs' (default): Supports L2 regularization and None. Extremely fast for dense tabular data.
  • solver='liblinear': Supports L1 and L2 penalties. Great for smaller datasets.
  • solver='saga': Supports ElasticNet, L1, and L2 penalties. Excellent for large sparse datasets.

Important Classification Metrics & The Confusion Matrix

In continuous regression, we measured model performance using MAE, MSE, and R2. In classification, performance evaluation starts with the Confusion Matrix.

Figure 10.9: The 2×2 Confusion Matrix for a 100-Patient Screening Clinic. The matrix breaks down the four possible outcomes between actual disease status and diagnostic predictions.
✔ Fundamental Rule: Always inspect the four confusion matrix cells before trusting a single summary number.

The Four Fundamental Outcomes Defined

Outcome Name Actual Class Model Prediction Clinic Example (N=100) Real-World Meaning
True Positive (TP) 1 (Sick) 1 (Sick) 18 Patients Correct detection: Patient has condition and gets treatment.
False Negative (FN) 1 (Sick) 0 (Healthy) 2 Patients Type II Error: Missed diagnosis. Patient sent home untreated!
False Positive (FP) 0 (Healthy) 1 (Sick) 6 Patients Type I Error: False alarm. Healthy patient receives stress & biopsy.
True Negative (TN) 0 (Healthy) 0 (Healthy) 74 Patients Correct clearance: Healthy person confirmed healthy.

The Four Core Classification Metrics

Using our verified 100-patient medical screening numbers (TP = 18, FN = 2, FP = 6, TN = 74), let us calculate each core metric:

🔢 1. Classification Accuracy
Accuracy = (TP + TN) / (TP + TN + FP + FN)

Accuracy = (18 + 74) / 100 = 92 / 100 = 92.00%
Meaning: Percentage of all predictions that were correct. Dangerous when classes are imbalanced!

🔢 2. Precision (Positive Predictive Value)
Precision = TP / (TP + FP)

Precision = 18 / (18 + 6) = 18 / 24 = 75.00%
Meaning: When the model predicts positive, how often is it actually right? (High precision means few false alarms).

🔢 3. Recall / Sensitivity (True Positive Rate)
Recall = TP / (TP + FN)

Recall = 18 / (18 + 2) = 18 / 20 = 90.00%
Meaning: Out of all truly positive cases, what percentage did the model catch? (High recall means few missed diseases).

🔢 4. F1-Score (Harmonic Mean of Precision and Recall)
F1 = 2 × (Precision × Recall) / (Precision + Recall)

F1 = 2 × (0.75 × 0.90) / (0.75 + 0.90) = 2 × 0.675 / 1.65 = 1.35 / 1.65 = 81.82%
Meaning: Balanced metric that heavily penalizes extreme asymmetry between precision and recall.

Section 14

ROC Curve and AUC (Receiver Operating Characteristic)

A single confusion matrix only shows performance at one specific operating threshold (like τ=0.50). To evaluate how well a model discriminates between classes across all possible thresholds simultaneously, machine learning practitioners use the ROC Curve.

🔢 The Two Axes of the ROC Curve
Y-Axis: True Positive Rate (TPR / Recall) = TP / (TP + FN)
X-Axis: False Positive Rate (FPR) = FP / (FP + TN) = 1 - Specificity
Figure 10.10: The Precision-Recall Trade-off Curve. As the decision threshold increases from 0.0 to 1.0, Recall decreases monotonically while Precision climbs. The curves intersect near the peak F1-score balance.
Figure 10.11: The Receiver Operating Characteristic (ROC) Curve. The curve plots TPR vs. FPR across all thresholds. The red diagonal line represents random guessing (AUC = 0.50). Our high-performing model achieves near-perfect discrimination (AUC ≈ 1.00).
✔ Interpretation: AUC measures ranking discrimination: the probability that the model ranks a randomly chosen positive sample higher than a randomly chosen negative sample.

Benchmark Guide for ROC AUC Values

AUC Score Range Discrimination Quality Diagnostic Utility
0.90 – 1.00 Outstanding Exceptional separation; model rarely confuses positive and negative cases.
0.80 – 0.90 Good / Strong Solid production-grade performance for business and engineering.
0.70 – 0.80 Fair Acceptable for exploratory modeling, but requires careful threshold tuning.
0.50 – 0.60 Poor / Coin Flip No better than random guessing. Model has learned no meaningful pattern.
Section 15

Class Imbalance and Threshold Selection

In real-world applications such as credit card fraud, cybersecurity intrusion detection, and rare disease diagnosis, the classes are severely imbalanced: 95% to 99.9% of samples belong to the negative class.

Figure 10.12: The 95% Accuracy Trap. A naive dummy classifier that unconditionally predicts “Normal” achieves 95% accuracy while completely missing all 5 fraud cases (Recall = 0.0%).
✔ Golden Rule: Never rely on Accuracy alone when evaluating models on imbalanced datasets!

Three Practical Techniques to Address Imbalance

1

Use Balanced Class Weights: class_weight='balanced'

In scikit-learn, setting LogisticRegression(class_weight='balanced') automatically weights the loss function inversely proportional to class frequencies. Misclassifying a rare positive sample incurs a much higher penalty than misclassifying an abundant negative sample.

2

Optimize Decision Threshold on Validation Data

Do not stick with the default 0.50 threshold. Lower the threshold to 0.15 or 0.25 on a validation split to maximize Recall or F1-score. Never tune the threshold on the final test set!

3

Evaluate Precision-Recall Curves (PR-AUC)

When positive cases are rare (e.g., 0.1%), ROC AUC can remain deceptively high because large true negatives dilute the FPR denominator. In contrast, Precision-Recall AUC (PR-AUC) focuses strictly on positive class performance.

Section 16

Calibration and Probability Interpretation

When a machine learning model outputs a prediction of p = 0.80, what does that number actually signify? Does it mean the positive outcome is guaranteed, or that the model is “80% sure”?

📖 The Strict Statistical Meaning of Calibration

A model is well-calibrated if predicted probabilities match empirical long-run frequencies.

Specifically: If you take 1,000 historical patients who were each assigned an estimated probability of p ≈ 0.80, exactly 800 of those patients should truly have the positive medical condition.

Figure 10.13: Probability Calibration Reliability Diagram. The diagonal dashed green line represents perfect calibration. Logistic Regression (purple line) naturally hugs this diagonal because it minimizes binary cross-entropy.
✔ Architectural Advantage: Because Logistic Regression minimizes Log Loss, its raw output probabilities are naturally well-calibrated compared to Naive Bayes or decision trees.

Discrimination vs. Calibration: Two Different Goals

A critical insight in advanced machine learning is that discrimination and calibration are two distinct model qualities:

  • Discrimination (Measured by ROC AUC): Can the model correctly rank positive cases above negative cases? A model that outputs p = 0.99 for all positives and p = 0.98 for all negatives has a perfect AUC of 1.00, but its probabilities are terribly uncalibrated!
  • Calibration (Measured by Brier Score / Log Loss): Do the numerical probabilities reflect real-world event frequencies? In clinical medicine, insurance pricing, and financial credit risk, calibration is mandatory.

🐍 topic10_logistic_regression_lab.py • Verified Production Code Python 3 
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.metrics import (
    accuracy_score, precision_score, recall_score, f1_score,
    confusion_matrix, roc_auc_score, classification_report
)

# =====================================================================
# 1. GENERATE REPRODUCIBLE DATASET (200 Students)
# =====================================================================
np.random.seed(42)
n_students = 200

# Continuous input features
study_hours = np.random.uniform(3.0, 28.0, n_students)       # Weekly study hours
attendance = np.random.uniform(45.0, 99.0, n_students)       # Lecture attendance %
prev_score = np.random.uniform(48.0, 95.0, n_students)       # Prior exam score
assignments = np.random.randint(1, 11, n_students)           # Completed homeworks (1-10)

# Latent log-odds model (intercept tuned to -11.0 for balanced classes)
z_latent = (
    -11.0
    + (0.18 * study_hours)
    + (0.045 * attendance)
    + (0.050 * prev_score)
    + (0.35 * assignments)
    + np.random.normal(0, 0.5, n_students)
)
true_probs = 1.0 / (1.0 + np.exp(-z_latent))
passed = (true_probs >= 0.50).astype(int)

df = pd.DataFrame({
    'Student_ID': [f'STU-{i:04d}' for i in range(1, n_students + 1)],
    'Study_Hours': np.round(study_hours, 1),
    'Attendance_Pct': np.round(attendance, 1),
    'Previous_Score': np.round(prev_score, 1),
    'Assignments_Done': assignments,
    'Passed_Exam': passed
})

print(f"Dataset Shape: {df.shape}")
print(f"Class Distribution: Fail = {np.sum(passed == 0)} ({np.mean(passed == 0):.1%}), "
      f"Pass = {np.sum(passed == 1)} ({np.mean(passed == 1):.1%})")

# =====================================================================
# 2. STRATIFIED TRAIN / TEST SPLIT (80% Train / 20% Test)
# =====================================================================
train_df, test_df = train_test_split(
    df, test_size=0.20, random_state=42, stratify=df['Passed_Exam']
)

# Assert zero leakage
overlap = set(train_df['Student_ID']).intersection(set(test_df['Student_ID']))
assert len(overlap) == 0, "Data Leakage: Overlapping student records!"

feature_cols = ['Study_Hours', 'Attendance_Pct', 'Previous_Score', 'Assignments_Done']
X_train, y_train = train_df[feature_cols], train_df['Passed_Exam']
X_test, y_test = test_df[feature_cols], test_df['Passed_Exam']

print(f"Train samples: {len(X_train)}, Test samples: {len(X_test)}")

# =====================================================================
# 3. BUILD LEAK-FREE PIPELINE (Scaler + Logistic Regression)
# =====================================================================
pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('logreg', LogisticRegression(random_state=42, C=1.0))
])

# Fit strictly on training data
pipe.fit(X_train, y_train)

# Assert scaler mean equals training mean (never touched test set!)
scaler = pipe.named_steps['scaler']
assert np.allclose(scaler.mean_, X_train.mean(axis=0))
print("[PASS] Scaler fitted strictly on training data.")

# =====================================================================
# 4. PREDICTIONS AND EVALUATION ON UNSEEN TEST SET
# =====================================================================
test_probs = pipe.predict_proba(X_test)[:, 1]
test_preds = pipe.predict(X_test)

# Verify probability bounds
assert np.all((test_probs >= 0.0) & (test_probs <= 1.0))

acc = accuracy_score(y_test, test_preds)
prec = precision_score(y_test, test_preds)
rec = recall_score(y_test, test_preds)
f1 = f1_score(y_test, test_preds)
auc = roc_auc_score(y_test, test_probs)
cm = confusion_matrix(y_test, test_preds)

print("\n" + "="*50)
print("TEST SET EVALUATION METRICS (N = 40)")
print("="*50)
print(f"Test Accuracy:  {acc:.4f} ({acc:.1%})")
print(f"Test Precision: {prec:.4f} ({prec:.1%})")
print(f"Test Recall:    {rec:.4f} ({rec:.1%})")
print(f"Test F1-Score:  {f1:.4f} ({f1:.1%})")
print(f"Test ROC AUC:   {auc:.4f} ({auc:.1%})")
print("\nTest Confusion Matrix:")
print(cm)

# =====================================================================
# 5. MODEL INTERPRETATION (Coefficients & Odds Ratios)
# =====================================================================
model = pipe.named_steps['logreg']
print(f"\nFitted Intercept (β0): {model.intercept_[0]:+.4f}")
print("Standardized Feature Coefficients:")
for col, coef in zip(feature_cols, model.coef_[0]):
    odds_ratio = np.exp(coef)
    print(f"  {col:18s}: {coef:+.4f} (Odds Ratio: {odds_ratio:.4f})")

# =====================================================================
# 6. REGULARIZATION COMPARISON (C Parameter)
# =====================================================================
pipe_c_small = Pipeline([('scaler', StandardScaler()), ('logreg', LogisticRegression(C=0.01, random_state=42))])
pipe_c_large = Pipeline([('scaler', StandardScaler()), ('logreg', LogisticRegression(C=100.0, random_state=42))])

pipe_c_small.fit(X_train, y_train)
pipe_c_large.fit(X_train, y_train)

w_small = np.linalg.norm(pipe_c_small.named_steps['logreg'].coef_[0])
w_mid = np.linalg.norm(model.coef_[0])
w_large = np.linalg.norm(pipe_c_large.named_steps['logreg'].coef_[0])

print(f"\nRegularization Weight Norms:")
print(f"  C = 0.01 (Heavy Penalty): ||w|| = {w_small:.4f}")
print(f"  C = 1.00 (Default):       ||w|| = {w_mid:.4f}")
print(f"  C = 100  (Weak Penalty):  ||w|| = {w_large:.4f}")
assert w_small < w_large, "Small C must produce smaller weight magnitude!"
print("[PASS] All practical lab pipeline tests passed successfully!")

18 Common Beginner Mistakes & How to Avoid Them

Avoid these eighteen frequent conceptual, mathematical, and implementation traps when building classification models:

1

Thinking Logistic Regression Is Ordinary Linear Regression

The Mistake: Assuming the model fits a straight line directly to binary target labels.

The Fix: Understand that Logistic Regression fits a linear equation to log-odds, which is transformed into probabilities via the non-linear sigmoid function.

2

Confusing Regression with Classification

The Mistake: Using Mean Squared Error (MSE) or R2 to evaluate classification quality.

The Fix: Use classification metrics: Accuracy, Precision, Recall, F1-Score, Confusion Matrix, and ROC AUC.

3

Assuming the Model Directly Outputs Discrete Hard Classes

The Mistake: Treating predictions as purely categorical without recognizing the underlying continuous probability.

The Fix: Use model.predict_proba(X) to access rich, calibrated class probabilities before applying thresholds.

4

Believing Sigmoid Output Equals a Guaranteed Outcome

The Mistake: Treating p = 0.90 as certainty.

The Fix: Recognize that probabilities represent statistical likelihoods under model assumptions; 10% of such cases will still fail.

5

Confusing Probability with Odds

The Mistake: Saying an odds of 4.0 means an 80% chance or vice-versa.

The Fix: Remember Odds = p / (1 - p). For p = 0.80, Odds = 4.0 (4 to 1).

6

Confusing Log-Odds with Probability

The Mistake: Interpreting linear score z = +1.386 directly as a percentage.

The Fix: Apply the sigmoid transformation σ(z) to convert log-odds into true probabilities.

7

Blindly Assuming τ = 0.50 Is Always the Best Threshold

The Mistake: Never adjusting the threshold in cost-sensitive domains like medical diagnosis or fraud.

The Fix: Tune the operating threshold on validation data to balance the real-world costs of False Positives vs. False Negatives.

8

Relying on Accuracy Alone for Imbalanced Datasets

The Mistake: Celebrating a 99% accuracy on a dataset where 99% of samples are negative.

The Fix: Evaluate Recall, Precision, PR-AUC, and the Confusion Matrix.

9

Confusing Precision with Recall

The Mistake: Forgetting which metric evaluates false alarms vs. missed positives.

The Fix: Precision = How clean are your alarms? (TP / (TP+FP)); Recall = Did you catch all positive cases? (TP / (TP+FN)).

10

Reversing False Positives and False Negatives

The Mistake: Swapping Type I and Type II errors during business reviews.

The Fix: False Positive = False Alarm (healthy labeled sick); False Negative = Missed Event (sick labeled healthy).

11

Calculating Evaluation Metrics on Training Data Only

The Mistake: Reporting training accuracy as expected production performance.

The Fix: Always evaluate on an untouched, holdout test dataset or via cross-validation.

12

Fitting Feature Scalers Before Splitting Data (Data Leakage)

The Mistake: Calling scaler.fit(df) on the entire dataset before train_test_split.

The Fix: Use a scikit-learn Pipeline so StandardScaler is fitted exclusively on training samples.

13

Tuning the Decision Threshold on the Test Set

The Mistake: Trying multiple thresholds on test data and picking the one with highest accuracy.

The Fix: This causes test-set overfitting! Optimize the threshold on a validation split, then test once on the test set.

14

Treating Model Coefficients as Proof of Causal Relationships

The Mistake: Claiming feature X causes outcome y because its coefficient is positive.

The Fix: Observational regression proves statistical association, not causality. Confounding variables may be present.

15

Assuming High ROC AUC Guarantees Good Probability Calibration

The Mistake: Believing a model with AUC = 0.95 outputs trustworthy probabilities.

The Fix: AUC measures ranking order only. Inspect reliability diagrams and Brier score to verify probability calibration.

16

Ignoring Regularization and Scikit-Learn’s C Parameter

The Mistake: Leaving C=1.0 unexamined when working with collinear or high-dimensional features.

The Fix: Tune C using GridSearchCV or LogisticRegressionCV to find the optimal regularization strength.

17

Interpreting Synthetic Benchmark Performance as Real-World Accuracy

The Mistake: Assuming a 95% test score on clean synthetic data guarantees 95% in messy production.

The Fix: Real-world data contains noise, missing entries, label errors, and distribution shifts. Always validate in shadow mode.

18

Ignoring the Unequal Business Costs of Classification Errors

The Mistake: Optimizing purely for mathematical symmetry when business losses are heavily asymmetric.

The Fix: Calculate expected cost: Cost = (FP × CostFP) + (FN × CostFN) and pick the threshold minimizing total dollar loss.

📝 10-Point Chapter Summary

  1. Classification vs Regression: Regression predicts continuous quantities; Classification categorizes observations into discrete qualitative classes.
  2. The Name Paradox: Logistic regression is a classification model that computes an internal linear regression score and filters it through a sigmoid function.
  3. The Sigmoid Function: σ(z) = 1 / (1 + e-z) compresses any real number into a valid probability strictly within (0, 1).
  4. Odds & Logits: Odds represent p / (1 - p). Taking the natural log yields the logit, which scales linearly with input features.
  5. Odds Ratio: eβj represents the multiplicative change in the odds of the positive outcome per unit increase in feature xj.
  6. Decision Boundary: Standard Logistic Regression produces a linear boundary in the original feature space: β0 + ∑ βjxj = 0.
  7. Log Loss (Binary Cross-Entropy): Minimizes negative log-likelihood, heavily penalizing confident wrong predictions exponentially.
  8. Confusion Matrix: Decomposes predictions into TP, FN, FP, and TN. Accuracy alone is dangerous on imbalanced datasets.
  9. ROC & AUC: Plots Recall vs. False Positive Rate across all thresholds. AUC measures ranking discrimination (0.5 = coin flip; 1.0 = perfect).
  10. Production Anti-Leakage: Always bundle feature scalers and models inside a scikit-learn Pipeline to prevent data leakage from test data.

🧮 12 Interactive Revision Questions & Solutions

Q1: Why is Logistic Regression called “regression” if it performs classification?

Answer: Internally, the model computes an unbounded continuous linear regression score (z = β0 + ∑ βjxj) representing the log-odds of the positive class. It transforms that continuous score into a bounded probability using the sigmoid function and classifies based on a threshold.

Q2 (Numerical): Calculate the exact sigmoid probability when the linear score is z = +1.8.

Step-by-step Solution:

  1. Formula: σ(z) = 1 / (1 + e-z)
  2. Calculate e-1.8 ≈ 0.165299
  3. Denominator: 1 + 0.165299 = 1.165299
  4. Sigmoid: 1 / 1.165299 = 0.8581 (85.81%)
Q3 (Numerical): An event has probability p = 0.80. What are its Odds and Log-Odds?

Step-by-step Solution:

  • Odds = p / (1 - p) = 0.80 / (1 - 0.80) = 0.80 / 0.20 = 4.0 (or “4 to 1”).
  • Log-Odds = ln(4.0) = +1.3863.
Q4: If a feature’s learned slope is β = +1.20, what is its Odds Ratio and plain-English interpretation?

Solution:

Odds Ratio = e1.20 = 3.3201.

Interpretation: Holding all other features fixed, a one-unit increase in this feature multiplies the odds of the outcome by approximately 3.32 (a 232% increase in odds, NOT probability).

Q5 (Numerical): Calculate Log Loss when actual label y = 1 and predicted probability is p = 0.90 vs. p = 0.10.

Solution:

  • When p = 0.90 (Confident Correct): Loss = -ln(0.90) = 0.1054.
  • When p = 0.10 (Confident WRONG): Loss = -ln(0.10) = 2.3026.
  • The confident incorrect prediction is penalized 21.8 times more severely (2.3026 / 0.1054 = 21.84)!
Q6 (Confusion Matrix Problem): In a cancer clinic test of 100 patients, TP=18, FN=2, FP=6, TN=74. Calculate Accuracy, Precision, Recall, and F1-score.

Step-by-step Solution:

  • Accuracy = (18 + 74) / 100 = 92 / 100 = 92.00%
  • Precision = 18 / (18 + 6) = 18 / 24 = 75.00%
  • Recall = 18 / (18 + 2) = 18 / 20 = 90.00%
  • F1 = 2 × (0.75 × 0.90) / (0.75 + 0.90) = 1.35 / 1.65 = 81.82%
Q7: Why does a threshold change from τ = 0.50 to τ = 0.30 increase Recall?

Answer: Lowering the bar makes it easier for samples to be classified as positive. Borderline positive cases with probabilities between 0.30 and 0.49 that were previously missed (False Negatives) are now captured as True Positives. Because Recall is TP / (TP + FN), capturing more positives increases Recall.

Q8: What is the geometric shape of the decision boundary in standard Logistic Regression with 2 input features?

Answer: A straight line in the 2D feature plane given by the equation: β0 + β1x1 + β2x2 = 0 (at threshold τ = 0.50).

Q9: In scikit-learn, does setting C = 0.01 increase or decrease regularization?

Answer: It greatly increases regularization. Parameter C is the inverse of regularization strength (C = 1 / λ). A tiny C value represents a massive penalty on large coefficients, shrinking weights aggressively towards zero.

Q10: Why does a dummy model on an imbalanced dataset (99% normal, 1% fraud) get 99% accuracy while being completely useless?

Answer: By always predicting “Normal”, the model is correct on all 99 normal transactions (99 / 100 = 99% accuracy). However, it detects exactly 0 fraud cases (Recall = 0.0%), failing its entire business purpose.

Q11 (Scenario Problem): An airport security scanner flags luggage for contraband. A false alarm causes a 2-minute manual bag search. A false negative lets an explosive onto an aircraft. Should you set τ high (0.80) or low (0.20)?

Answer: Set τ = 0.20 (low threshold). The cost of a False Negative (catastrophic disaster) vastly outweighs the minor inconvenience of a False Positive (a 2-minute inspection). You must maximize Recall!

from sklearn.pipeline import Pipeline
