1. Introduction to Mixins

In Topics 14, 15, and 16, we explored Object-Oriented Programming through classes, inheritance (extends), and interfaces (implements). While single inheritance creates clear "is-a" parent-child relationships, it has a major limitation: Dart only allows a class to extend one single superclass.

What happens when multiple completely unrelated classes need to share the exact same functionality without copying and pasting code? This is where Mixins shine!

Simple Definition
A Mixin in Dart is a reusable chunk of code (methods and properties) that can be "mixed into" multiple classes without using parent-child inheritance.
Figure 1.1: A single reusable CameraCapability mixin mixed into three distinct device classes.
Figure 1.2: Completely unrelated classes sharing flight behavior without forcing a common parent class.

2. Creating a Mixin in Dart

To declare a mixin, use the mixin keyword followed by the mixin name. To apply a mixin to a class, use the with keyword.

Figure 2.1: The CanFly mixin applied directly to Bird and Drone via the with keyword.
DART • CREATING AND APPLYING A MIXINcan_fly_demo.dart
DART Script
DART 
mixin CanFly {
  void fly() {
    print('Flying in the sky');
  }
}

class Bird with CanFly {}

class Drone with CanFly {}

void main() {
  Bird bird = Bird();
  Drone drone = Drone();

  bird.fly();
  drone.fly();
}
Console Output Flying in the sky
Flying in the sky

3. The with Keyword

The with keyword is Dart's dedicated syntax for mixing one or more mixins into a class. Unlike extends (which only accepts one class), with accepts a comma-separated list of mixins.

Figure 3.1: Combining two mixins into a single Athlete class using a comma-separated list.
DART • MULTIPLE MIXINS WITH WITHathlete_demo.dart
DART Script
DART 
mixin CanWalk {
  void walk() {
    print('Walking');
  }
}

mixin CanRun {
  void run() {
    print('Running');
  }
}

class Athlete with CanWalk, CanRun {}

void main() {
  Athlete athlete = Athlete();

  athlete.walk();
  athlete.run();
}
Console Output Walking
Running

4. Mixins with Properties and Methods

Mixins are not restricted to just void methods. A mixin can contain stateful properties (instance variables), final fields, getters, setters, and methods that manipulate that state.

Figure 4.1: Mixins contribute both mutable state and state-altering methods to recipient classes.
DART • STATEFUL MIXIN PROPERTIESbattery_demo.dart
DART Script
DART 
mixin Battery {
  int batteryLevel = 100;

  void showBattery() {
    print('Battery: $batteryLevel%');
  }

  void useBattery(int amount) {
    batteryLevel -= amount;
  }
}

class Smartphone with Battery {}

void main() {
  Smartphone phone = Smartphone();

  phone.showBattery();
  phone.useBattery(20);
  phone.showBattery();
}
Console Output Battery: 100%
Battery: 80%

6. Mixin Constraints with the on Keyword

Sometimes a mixin is not universal; it relies on methods or fields provided by a specific superclass. To enforce this, Dart provides the on keyword.

Figure 6.1: The 'on Animal' clause guarantees that CanPlay can only be applied to subclasses of Animal.
Figure 6.2: Dart's type system rejects classes that fail to satisfy the mixin superclass constraint.
DART • MIXIN ON CONSTRAINTmixin_on_constraint.dart
DART Script
DART 
class Animal {
  void eat() {
    print('Animal is eating');
  }
}

mixin CanPlay on Animal {
  void play() {
    print('Animal is playing');
  }

  void eatAndPlay() {
    eat();  // Safe to call because 'on Animal' guarantees eat() exists!
    play();
  }
}

class Dog extends Animal with CanPlay {}

void main() {
  Dog dog = Dog();
  dog.eatAndPlay();
}
Console Output Animal is eating
Animal is playing

7. Mixin Application Order and Method Resolution

What happens if two mixins define a method with the exact same signature? Dart resolves this deterministically through linearization (order of application).

The Golden Rule: Mixins are applied from left to right. The mixin listed later (furthest to the right) overrides any matching method from earlier mixins or superclasses.

Figure 7.1: Mixin linear order: SecondMessage appears after FirstMessage and takes precedence.
Figure 7.2: Reversed mixin application order: FirstMessage appears last, flipping the winner.
DART • METHOD RESOLUTION ORDERmixin_precedence.dart
DART Script
DART 
mixin FirstMessage {
  void showMessage() {
    print('Message from FirstMessage');
  }
}

mixin SecondMessage {
  void showMessage() {
    print('Message from SecondMessage');
  }
}

// Order 1: SecondMessage is last &rarr; It overrides FirstMessage
class Demo1 with FirstMessage, SecondMessage {}

// Order 2: FirstMessage is last &rarr; It overrides SecondMessage
class Demo2 with SecondMessage, FirstMessage {}

void main() {
  Demo1 d1 = Demo1();
  Demo2 d2 = Demo2();

  d1.showMessage();
  d2.showMessage();
}
Console Output Message from SecondMessage
Message from FirstMessage

8. The mixin class Declaration

In Dart 3, Google introduced class modifiers including mixin class. A regular mixin cannot be instantiated directly or extended with extends. A mixin class, however, serves a dual purpose:

  • It can be used as a standard class (instantiated with () or extended with extends).
  • It can also be mixed into another class using with.
Figure 8.1: A mixin class can be both applied with 'with' and extended with 'extends'.
Figure 8.2: Feature matrix distinguishing regular mixins from modern Dart 3 mixin classes.
DART • MIXIN CLASS SYNTAXmixin_class_demo.dart
DART Script
DART 
mixin class Logger {
  void log(String message) {
    print('LOG: $message');
  }
}

// Used as a mixin via 'with'
class AppService with Logger {}

// Used as a parent class via 'extends'
class UserService extends Logger {}

void main() {
  AppService app = AppService();
  UserService user = UserService();

  app.log('Application started');
  user.log('User loaded');
}
Console Output LOG: Application started
LOG: User loaded

9. Mixins vs Inheritance

Beginning Dart developers often ask: "When should I use inheritance (extends), and when should I use mixins (with)?"

Figure 9.1: Core architectural distinction between single inheritance and mixin capability composition.
Feature Inheritance (extends) Mixins (with)
Relationship "is-a" (e.g., Dog is an Animal) "can-do" (e.g., Bird can fly, Drone can fly)
Multiplicity Only 1 superclass allowed Multiple mixins allowed (with A, B, C)
Coupling Tight parent-child hierarchy Loose, modular, swappable capabilities

10. What Are Extensions?

Now let's explore the second superpower of modern Dart: Extension Methods (introduced in Dart 2.7).

Have you ever used Dart's built-in String class and wished it had a helper method like .toTitleCase() or .isPalindrome()? In older programming languages, you would have to write awkward utility classes like StringUtils.isPalindrome(myString). Extensions allow you to add new methods, getters, and setters directly to existing classes without editing their source code or subclassing them.

Figure 10.1: Extensions add convenient member methods directly onto existing classes.

11. Creating an Extension

An extension is declared using the extension keyword, an optional name, and the on keyword specifying the target type.

Inside the extension body, the special keyword this refers to the current value of the object on which the extension is called.

Figure 11.1: Extension declaration anatomy: name, target type (on String), and '$this' binding.
DART • EXTENSION DECLARATION & INVOCATIONstring_greeting.dart
DART Script
DART 
extension StringGreeting on String {
  String greet() {
    return 'Hello, $this!';
  }
}

void main() {
  String name = 'Shailendra';

  print(name.greet());
}
Console Output Hello, Shailendra!

12. Extension Methods on Built-in Types

You can write extensions for any Dart type, including numbers, collections, and dates.

Figure 12.1: Domain-specific extensions augmenting core primitives cleanly.
DART • EXTENSION ON BUILT-IN INTint_helpers.dart
DART Script
DART 
extension NumberHelpers on int {
  bool get isEvenNumber => this % 2 == 0;

  int square() {
    return this * this;
  }
}

void main() {
  int number = 6;

  print(number.isEvenNumber);
  print(number.square());
}
Console Output true
36

13. Extension Getters and Setters

Extensions can provide getters and setters just like regular classes.

  • Use an extension getter when computing a property that doesn't need arguments (e.g. text.characterCount instead of text.characterCount()).
  • Crucial Limitation: Extensions cannot add new stored memory fields to an existing class. A setter can only modify properties that the original object already has!
Figure 13.1: Extension methods perform actions; extension getters expose computed properties.
DART • EXTENSION GETTERSstring_details.dart
DART Script
DART 
extension StringDetails on String {
  int get characterCount => length;

  bool get isLong => length > 10;
}

void main() {
  String text = 'CodeVerse';

  print(text.characterCount);
  print(text.isLong);
}
Console Output 9
false

14. Named Extensions

Giving extensions explicit names allows you to disambiguate conflicts when two different extensions define members with identical names. You can invoke an extension explicitly like a wrapper: ExtensionName(object).method().

Figure 14.1: Named extensions enable explicit wrapper invocation to resolve ambiguous names.
DART • EXPLICIT NAMED EXTENSION CALLSnamed_extensions.dart
DART Script
DART 
extension StringTools on String {
  String makeUpper() {
    return toUpperCase();
  }
}

extension StringInfo on String {
  int get size {
    return length;
  }
}

void main() {
  String text = 'dart';

  // Explicit wrapper syntax cleanly eliminates ambiguity
  print(StringTools(text).makeUpper());
  print(StringInfo(text).size);
}
Console Output DART
4

15. Extension Scope and Static Resolution

Two essential technical rules govern Dart extensions:

  1. Scope: An extension is only accessible if it is in the current file or explicitly imported into your file.
  2. Static Resolution: Extensions are resolved at compile time based on the static type of the variable, NOT dynamically at runtime like polymorphism!
  3. Instance Precedence: If a class defines a method named save() and an extension also defines save(), the class's own method always wins.
Figure 15.1: Extensions rely on static type checking and never override existing class methods.

16. What Extensions Cannot Do

To write reliable code, you must understand the strict boundaries of extensions:

  • ✗ Cannot add new stored instance fields (memory layout of the class cannot be altered).
  • ✗ Cannot add new constructors to existing classes.
  • ✗ Cannot modify the original class source code.
  • ✗ Cannot participate in runtime virtual method overriding (polymorphism).
  • ✗ Cannot be called on variables of type dynamic.
Figure 16.1: Architectural boundaries: extensions enhance API ergonomics without modifying state.

17. Mixins vs Extensions

Both mixins and extensions facilitate code reusability, but they solve fundamentally different problems.

Figure 17.1: Mixins build new classes; extensions augment existing closed types.
Attribute Mixin (mixin / with) Extension (extension / on)
Primary Purpose Share reusable capabilities across your new classes Add helper methods/getters to existing types
Can Store State? ✓ Yes (instance variables) ✗ No (computed only)
Applied To Class declaration (class A with M) Any existing type (on String, on int)
Resolution Object prototype linearization Static compile-time dispatch

20. Common Mixins and Extensions Mistakes

Avoid these common traps when writing Dart mixins and extensions:

Figure 20.1: Compilation warnings and syntax traps in mixins and extensions.
Top 4 Gotchas to Memorize
1. Direct Mixin Instantiation: var m = MyMixin(); is a compile error. Mixins cannot be instantiated directly with constructors.
2. Extension Fields: extension on int { int count = 0; } fails because extensions cannot add memory storage.
3. Dynamic Variables: Extensions do not execute on variables typed as dynamic because extensions are resolved statically at compile time.
4. Mixin Linearization: Remember that later mixins in a with A, B clause will override methods in earlier ones!

21. Quick Revision

Figure 21.1: Master concept map synthesizing mixins and extensions in Dart.
  • mixin: Defines a reusable bundle of methods and variables.
  • with: Injects one or more mixins into a class (e.g., class C with M1, M2).
  • on: Enforces a superclass constraint on a mixin (e.g., mixin M on SuperClass).
  • mixin class: A Dart 3 dual-use declaration usable with both extends and with.
  • extension: Adds helper methods, getters, and setters to existing classes without editing them.
  • Static Resolution: Extensions are checked at compile time, not virtual runtime dispatch.
