Abstract Classes & Interfaces

Deepen your OOP architectural skills in Dart! Discover how abstract classes provide incomplete foundation blueprints with shared code, how implicit interfaces define rigid contracts via implements, and how to design extensible, professional software systems.

1. Introduction to Abstract Classes

In real-world software, certain high-level concepts exist only as ideas or categories rather than physical standalone objects. For instance, you can drive a Honda Civic or ride a Yamaha R15, but you cannot purchase a plain generic "Vehicle".

An abstract class represents an incomplete conceptual blueprint. It defines what child classes must do without dictating how every single action is done. It exists solely to be extended and specialized by concrete subclasses.

Real-Life Analogy: The Payment Gateway

Consider a modern checkout system. Every payment method shares one common responsibility: making a payment. However, the exact technical execution is completely different for UPI, Credit Card, and Net Banking. An abstract Payment class establishes the universal payment rule, while each payment type provides its own distinct implementation.

Figure 1.1: An abstract class serves as a conceptual parent enforcing shared responsibilities.

2. Creating an Abstract Class in Dart

In Dart, we declare an abstract class by prepending the abstract keyword before class. An abstract class cannot be directly instantiated using ClassName(); attempting to do so triggers a compile-time error.

Figure 2.1: Normal classes can be instantiated directly; abstract classes cannot.
Figure 2.2: Key fundamental differences between concrete and abstract classes.
DART • ABSTRACT CLASS DECLARATIONabstract_animal.dart
DART Script
DART 
// Declaring an abstract class
abstract class Animal {
  void makeSound(); // Abstract method (no body)
}

// Concrete subclass providing implementation
class Dog extends Animal {
  @override
  void makeSound() {
    print('Dog barks');
  }
}

void main() {
  // Valid: Instantiating the concrete subclass
  Dog dog = Dog();
  dog.makeSound();

  // INVALID: An abstract class cannot be instantiated directly!
  // Animal animal = Animal(); // Compile-time Error: 'Animal' is abstract
}
Expected Console Output Dog barks

3. Abstract Methods

An abstract method has a return type, a name, and parameter list, but no body (no curly braces {}). It ends with a semicolon ;. It acts as an unbreakable contract: every non-abstract child class extending this class must implement the method.

Figure 3.1: One abstract method signature enforced across multiple concrete child implementations.
DART • ABSTRACT METHODSshape_area.dart
DART Script
DART 
abstract class Shape {
  void calculateArea(); // Abstract method declaration
}

class Circle extends Shape {
  @override
  void calculateArea() {
    print('Calculating circle area');
  }
}

class Rectangle extends Shape {
  @override
  void calculateArea() {
    print('Calculating rectangle area');
  }
}

void main() {
  Circle circle = Circle();
  Rectangle rectangle = Rectangle();

  circle.calculateArea();
  rectangle.calculateArea();
}
Expected Console Output Calculating circle area
Calculating rectangle area

4. Concrete Methods Inside Abstract Classes

An abstract class does not need to be 100% abstract. It can contain concrete methods (methods with complete bodies { ... }). This allows developers to write shared logic once in the abstract parent, while still enforcing abstract requirements on subclasses.

Figure 4.1: Abstract classes seamlessly combine shared concrete code with abstract requirements.
DART • CONCRETE METHODS IN ABSTRACT CLASSvehicle_stop.dart
DART Script
DART 
abstract class Vehicle {
  // Abstract method: child must provide implementation
  void start();

  // Concrete method: shared reusable code
  void stop() {
    print('Vehicle stopped');
  }
}

class Car extends Vehicle {
  @override
  void start() {
    print('Car started');
  }
}

void main() {
  Car car = Car();
  car.start(); // Implemented in Car
  car.stop();  // Reused from Vehicle
}
Expected Console Output Car started
Vehicle stopped

5. Properties, Fields & Members in Abstract Classes

Abstract classes in Dart can contain virtually any member that a regular class contains:

  • Instance Variables & Final Fields: State held on behalf of subclasses.
  • Constructors: Executed by child classes to initialize fields.
  • Getters & Setters: Either abstract or concrete.
  • Static Variables & Methods: Utility logic belonging to the class type.
Figure 5.1: Abstract classes support full member variety including state, constructors, and logic.
DART • ABSTRACT CLASS MEMBERSemployee_demo.dart
DART Script
DART 
abstract class Employee {
  String name;

  // Abstract class constructor
  Employee(this.name);

  // Abstract method
  void work();

  // Concrete helper method
  void showName() {
    print('Employee: $name');
  }
}

class Developer extends Employee {
  Developer(String name) : super(name);

  @override
  void work() {
    print('$name writes code');
  }
}

void main() {
  Developer developer = Developer('Rahul');
  developer.showName();
  developer.work();
}
Expected Console Output Employee: Rahul
Rahul writes code

6. Constructors in Abstract Classes & Chaining

Beginners often ask: "If an abstract class cannot be instantiated, why can it have a constructor?"

An abstract class has a constructor so that its subclasses can initialize the abstract class's instance fields through constructor chaining using : super(...).

Figure 6.1: Subclasses chain parameters to initialize abstract superclass state.
Figure 6.2: Polymorphic dispatch handling multiple derived classes via abstract parent reference.
DART • CONSTRUCTOR CHAININGbank_account_ctor.dart
DART Script
DART 
abstract class BankAccount {
  String accountHolder;

  BankAccount(this.accountHolder);

  void withdraw(double amount);
}

class SavingsAccount extends BankAccount {
  double balance;

  // Chains to abstract parent constructor
  SavingsAccount(String accountHolder, this.balance)
      : super(accountHolder);

  @override
  void withdraw(double amount) {
    balance -= amount;
    print('Remaining balance: ₹$balance');
  }
}

void main() {
  SavingsAccount account = SavingsAccount('Amit', 5000);
  account.withdraw(1000);
}
Expected Console Output Remaining balance: ₹4000.0

7. What Is an Interface?

An interface is a formal contract in Object-Oriented Programming. It dictates what methods and properties a class must provide, without specifying any of the internal code implementation.

Figure 7.1: An interface enforces an identical contract on completely different classes.

8. How Dart Interfaces Work: The Implicit Interface

Unlike Java or C#, traditional Dart has no separate interface declaration keyword. In Dart, every single class implicitly defines an interface composed of all its instance members (methods, getters, setters, and fields).

When class B uses implements A, class B promises to satisfy A's interface, but does not inherit any of A's code.

Figure 8.1: Every class in Dart acts as an implicit interface for implements.
DART • IMPLICIT INTERFACE IMPLEMENTATIONimplicit_interface.dart
DART Script
DART 
// A normal concrete class
class Printer {
  void printDocument() {
    print('Printing document');
  }
}

// OfficePrinter treats Printer purely as an interface
class OfficePrinter implements Printer {
  @override
  void printDocument() {
    print('Office printer is printing');
  }
}

void main() {
  OfficePrinter printer = OfficePrinter();
  printer.printDocument();
}
Expected Console Output Office printer is printing

9. The implements Keyword

We use the implements keyword to indicate that a class agrees to fulfill an interface contract. Unlike extends, you can implement either an abstract class or a normal class, but you must provide implementations for all of its members.

Figure 9.1: Both abstract and concrete classes can be implemented via the implements keyword.
Figure 9.2: Unit testing pattern: Implementing a concrete class to create a mock double.
DART • IMPLEMENTS KEYWORDflyable_bird.dart
DART Script
DART 
abstract class Flyable {
  void fly();
}

class Bird implements Flyable {
  @override
  void fly() {
    print('Bird is flying');
  }
}

void main() {
  Bird bird = Bird();
  bird.fly();
}
Expected Console Output Bird is flying

10. Implementing Multiple Interfaces

While Dart strictly prohibits extending multiple classes with extends, a class can implement multiple interfaces simultaneously by separating them with commas: class Duck implements Flyable, Swimmable.

Figure 10.1: A class can fulfill multiple interface contracts at the same time.
DART • MULTIPLE INTERFACESduck_demo.dart
DART Script
DART 
abstract class Flyable {
  void fly();
}

abstract class Swimmable {
  void swim();
}

// Duck satisfies both contracts
class Duck implements Flyable, Swimmable {
  @override
  void fly() => print('Duck is flying');

  @override
  void swim() => print('Duck is swimming');
}

void main() {
  Duck duck = Duck();
  duck.fly();
  duck.swim();
}
Expected Console Output Duck is flying
Duck is swimming

12. extends vs implements

Remember this simple rule:

  • extends is for REUSE: You want to inherit ready-made code from a parent class.
  • implements is for CONTRACTS: You want to guarantee that a class conforms to a specific set of methods, even if you write every line from scratch.
Figure 12.1: extends inherits logic; implements requires new logic.
DART • EXTENDS VS IMPLEMENTSextends_vs_implements.dart
DART Script
DART 
class Animal {
  void eat() => print('Animal is eating');
}

// Reuses eat() from Animal
class Dog extends Animal {}

abstract class Flyable {
  void fly();
}

// Fulfills contract for fly()
class Bird implements Flyable {
  @override
  void fly() => print('Bird is flying');
}

void main() {
  Dog dog = Dog();
  Bird bird = Bird();

  dog.eat();
  bird.fly();
}
Expected Console Output Animal is eating
Bird is flying

14. Polymorphism with Abstract Classes & Interfaces

By typing variables or collections to an abstract class or interface (e.g. Notification), you can swap or mix concrete implementations effortlessly without changing caller code.

Figure 14.1: Polymorphism enables a single loop to dispatch to three completely different classes.
DART • POLYMORPHIC NOTIFICATIONSnotification_demo.dart
DART Script
DART 
abstract class Notification {
  void send();
}

class EmailNotification implements Notification {
  @override
  void send() => print('Email sent');
}

class SMSNotification implements Notification {
  @override
  void send() => print('SMS sent');
}

class PushNotification implements Notification {
  @override
  void send() => print('Push notification sent');
}

void main() {
  List notifications = [
    EmailNotification(),
    SMSNotification(),
    PushNotification(),
  ];

  for (Notification notification in notifications) {
    notification.send();
  }
}
Expected Console Output Email sent
SMS sent
Push notification sent

15. Dart Class Modifiers — Beginner Introduction

Figure 15.1: Dart 3 class modifiers control how other libraries can consume and inherit code.

Starting in Dart 3.0, Dart introduced formal class modifiers to give API authors strict control over how libraries may be used outside their original files:

  • interface class: Allows other libraries to construct or implement the class, but forbids other libraries from using extends on it.
  • abstract interface class: Combines abstract and interface, defining a pure contract that cannot be instantiated and cannot be extended outside its library.
DART 3 • CLASS MODIFIERSclass_modifiers.dart
DART Script
DART 
// Interface class (Cannot be extended outside its library)
interface class Logger {
  void log(String message) {
    print('Log: $message');
  }
}

// Pure interface contract
abstract interface class Repository {
  void save();
}

class SqlRepository implements Repository {
  @override
  void save() {
    print('Saved to SQL database');
  }
}

void main() {
  Logger logger = Logger();
  logger.log('Testing class modifiers');

  Repository repo = SqlRepository();
  repo.save();
}
Expected Console Output Log: Testing class modifiers
Saved to SQL database

17. Common Mistakes & Gotchas

Figure 17.1: Visualizing the two most common compile errors beginners encounter.
1. Directly Instantiating an Abstract Class

Why it fails: Abstract classes cannot have concrete instances created with new or ().

✗ Bad: Payment p = Payment(); // Compile error  •  ✓ Good: Payment p = UpiPayment();

2. Assuming implements Reuses Concrete Method Bodies

Why it fails: Implementing a class ignores all its code bodies; you must re-implement every method.

3. Forgetting to Implement All Interface Members

Why it fails: If an interface declares 3 methods and your class implements 2, Dart throws an error.

4. Assuming Dart Has a Standalone interface Declaration Keyword

Why it fails: In core Dart, interfaces are defined by classes and implemented via implements.

5. Trying to Extend Multiple Classes

Why it fails: Dart restricts extends to a single superclass. Use implements for multiple contracts.

Manage geometric calculations polymorphically through an abstract Shape class.

abstract class Shape {
  String name;

}

Program 5: File Storage Engine Contract

Swap between local and cloud storage providers with zero changes to caller code.

DART • STORAGE INTERFACEprog5_storage.dart
DART Script
DART 
abstract class StorageService {
  void saveFile(String filename, String content);
  String readFile(String filename);
}

class LocalStorageService implements StorageService {
  @override
  void saveFile(String filename, String content) {
    print('Saved "$filename" ($content) to local disk: /data/$filename');
  }

  @override
  String readFile(String filename) => 'Local content of $filename';
}

class CloudStorageService implements StorageService {
  String bucket;
  CloudStorageService(this.bucket);

  @override
  void saveFile(String filename, String content) {
    print('Uploaded "$filename" to S3 bucket "$bucket"');
  }

  @override
  String readFile(String filename) => 'Cloud content of $filename from $bucket';
}

void main() {
  StorageService localStore = LocalStorageService();
  StorageService cloudStore = CloudStorageService('codeverse-assets-prod');

  localStore.saveFile('user_config.json', '{"theme": "dark"}');
  cloudStore.saveFile('profile.png', 'binary_bytes');
}
Expected Console Output Saved "user_config.json" ({"theme": "dark"}) to local disk: /data/user_config.json
Uploaded "profile.png" to S3 bucket "codeverse-assets-prod"

Interactive Multiple Choice Questions

1. What happens if you try to execute Shape s = Shape(); on an abstract class?

A) Dart throws a compile-time error because abstract classes cannot be directly instantiated.
B) Dart creates a null object.
C) It instantiates without issue if there are no abstract methods.
D) It works only in release mode.

Correct Answer: A
Explanation: Abstract classes cannot be instantiated directly. You must instantiate a concrete subclass that implements all abstract methods.

2. How does implements differ from extends in Dart?

A) implements treats the class purely as an interface, requiring you to provide method bodies for all members without inheriting any code.
B) implements inherits concrete code, while extends does not.
C) extends allows multiple classes; implements allows only one.
D) They are exact aliases.

Correct Answer: A
Explanation: implements extracts the interface contract and receives zero implementation reuse from the target class.

3. Can an abstract class in Dart contain a constructor?

A) Yes, to initialize instance fields when concrete subclasses delegate via : super(...).
B) No, abstract classes are strictly forbidden from having constructors.
C) Only named constructors with zero parameters.
D) Only private constructors.

Correct Answer: A
Explanation: Abstract classes can declare constructors so child classes can initialize inherited fields during constructor chaining.

4. How do you implement multiple interfaces in a single Dart class?

A) List them separated by commas after the implements keyword.
B) Use multiple extends keywords.
C) Nest them inside braces.
D) Dart does not allow multiple interfaces.

Correct Answer: A
Explanation: Multiple interface implementation is supported using commas: class Duck implements Flyable, Swimmable.

5. What does the Dart 3 interface class modifier enforce?

A) Other libraries can construct or implement the class, but cannot extend it with extends.
B) All methods must be static.
C) The class cannot have any instance variables.
D) The class must be written in C++.

Correct Answer: A
Explanation: The `interface` class modifier in Dart 3 prevents external libraries from sub-classing via `extends`, preserving the author's internal implementation hierarchy.
