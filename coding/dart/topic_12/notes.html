Lists, Sets & Maps in Dart

Organize and manage multiple data items like a pro. Master Dart's core collection types: ordered indexable Lists, unique-value Sets, and associative key-value Maps, with complete modification, iteration, and null safety workflows.

1. Introduction to Collections

In programming, a collection is a data structure designed to group multiple values together under a single variable name.

Imagine building an online shopping app. Storing 1,000 cart items in separate variables (item1, item2, ... item1000) is impossible to maintain. Collections solve this by providing flexible, organized containers that can grow, shrink, search, and iterate dynamically.

Real-Life Analogy: The E-Commerce Store

In a shopping store, different data requires different containers:

  • Shopping Cart (List): An ordered list of products added one by one; you can buy 2 of the same item (duplicates allowed).
  • Category Filter (Set): A group of distinct categories like {'Electronics', 'Books', 'Clothing'} where each category appears only once (no duplicates).
  • Product Directory (Map): A lookup catalogue where unique product IDs point to detailed info (e.g., 'SKU-101' → 'Wireless Mouse').

2. What Is a List?

A List is an ordered collection of objects. In many languages, lists are referred to as arrays. Each element in a List occupies a numbered slot called an index.

Key properties of Dart Lists:

  • Zero-based indexing: The first element is always at index 0, the second at 1, and the last at length - 1.
  • Maintains order: Elements remain in the exact insertion order unless explicitly sorted or reordered.
  • Duplicates allowed: You can store identical values multiple times.

11. Creating and Accessing Sets

Sets use curly braces { }. However, because Map literals also use { }, an empty literal {} creates a Map by default. To create an empty Set, explicitly specify the type: <Type>{} or Set<Type>().

No Index Access in Sets

Sets do NOT support numeric index access: numbers[0] is a compile error! To read elements, use for-in, contains(), first, or last.

15. What Is a Map?

A Map is an associative collection composed of key-value pairs. Each key acts as an identifier to locate its corresponding value.

  • Keys are unique: A Map cannot contain duplicate keys.
  • Values can repeat: Two different keys can share the same value (e.g., two students can have the same grade 90).

24. Common Collection Mistakes

Avoid these 12 common pitfalls when manipulating collections in Dart:

1. Accessing List Using an Out-of-Bounds Index

Why it fails: The highest index in a list of length N is N - 1. Requesting list[N] throws RangeError.

// ❌ Bad Code
var list = ['A', 'B']; print(list[2]);
// ✅ Fixed Code
if (list.length > 2) print(list[2]);
2. Forgetting Zero-Based Indexing

Why it fails: The 1st item is at index 0, NOT 1.

// ❌ Bad (gets 2nd item)
var first = list[1];
// ✅ Fixed Code
var first = list.first; // or list[0]
3. Attempting Index Access on a Set

Why it fails: Sets do not have indexed ordering; the operator [] is not defined on Sets.

// ❌ Bad Code
Set s = {1, 2}; print(s[0]);
// ✅ Fixed Code
print(s.elementAt(0)); // or for-in
4. Assuming a Set Stores Duplicate Elements

Why it fails: Sets discard duplicates silently without expanding size.

// ❌ Flawed Assumption
var s = {'a', 'a'}; // s.length is 1!
// ✅ Correct List
var l = ['a', 'a']; // l.length is 2
5. Confusing Empty Set with Empty Map Literal

Why it fails: var x = {}; creates a Map<dynamic, dynamic>, not a Set.

// ❌ Creates a Map!
var mySet = {};
// ✅ True Empty Set
var mySet = <String>{};
6. Expecting Missing Map Keys to Throw Exceptions

Why it fails: Dart maps safely return null when a key is absent.

// ❌ Dangerous Assumption
int score = map['missing']; // null!
// ✅ Safe Handling
int score = map['missing'] ?? 0;
7. Modifying a Fixed-Length List with add() or remove()

Why it fails: List.filled() creates a fixed-size list. Modifying size triggers UnsupportedError.

// ❌ Bad Code
List.filled(3, 0).add(5); // Crash!
// ✅ Growable List
List.filled(3, 0, growable: true).add(5);
8. Confusing remove() with removeAt()

Why it fails: remove(val) searches by value; removeAt(idx) deletes the item at index position.

// ❌ Confusing
list.remove(0); // removes value 0, not index 0!
// ✅ Explicit
list.removeAt(0); // removes 1st item
9. Confusing Map Keys with Map Values

Why it fails: Looking up by value using bracket notation returns null.

// ❌ Bad Lookup
map['Rahul']; // 'Rahul' is the value, not key!
// ✅ Fixed Lookup
map['name']; // Look up by key
10. Calling String Methods on Nullable Collection Elements

Why it fails: Elements in List<String?> may be null, triggering null safety errors without checks.

// ❌ Bad Code
for (var s in list) print(s.length);
// ✅ Fixed Code
for (var s in list) print(s?.length ?? 0);
11. Mutating Collection While Iterating

Why it fails: Adding or removing items inside a for-in loop causes ConcurrentModificationError.

// ❌ Bad Code
for (var x in list) list.remove(x);
// ✅ Fixed Code
list.removeWhere((x) => condition);
12. Forgetting that Sets Are Unordered

Why it fails: Never rely on printed order of Sets across different implementations or serialization.

// ❌ Unreliable
Set order is not strictly indexed
// ✅ Reliable
Use List if insertion order is mandatory

25. Quick Revision

Concept Quick Definition Syntax Pattern
List Ordered collection with zero-based indexing and duplicates allowed. List<int> nums = [1, 2, 3];
Set Unordered collection of unique items. Duplicates discarded. Set<int> unique = {1, 2, 3};
Map Associative key-value pairs. Keys unique, values can repeat. Map<String, int> m = {'age': 20};
Growable List List that can dynamically expand or shrink. list.add('New');
Fixed List List with static capacity allocated at creation. List.filled(3, 0);
Union Combines elements from two sets into one unique set. setA.union(setB)
Intersection Keeps only elements common to both sets. setA.intersection(setB)
Difference Keeps elements in set A that do not exist in set B. setA.difference(setB)
Map Lookup Access by key; returns value or null if key absent. map['key'] ?? fallback

B) Set

A) The duplicate is ignored and the Set remains unchanged
B) Dart throws a DuplicateItemError
C) The entire Set is deleted
D) It converts the Set into a List

C) An empty string
