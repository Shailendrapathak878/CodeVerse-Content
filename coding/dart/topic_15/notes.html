Inheritance & Polymorphism

Master two foundational pillars of Object-Oriented Programming in Dart! Learn how classes share properties and methods via inheritance, and how polymorphism enables one uniform interface to execute diverse specialized behaviors at runtime.

1. Introduction to Inheritance

In software development, writing identical code across multiple classes is tedious, error-prone, and wasteful. Inheritance is an Object-Oriented Programming mechanism that enables a new class to automatically inherit the properties and methods of an existing class, establishing an "is-a" relationship.

Real-Life Analogy: The Vehicle Factory

Consider an automotive manufacturer producing both Cars and Bikes. Both share core traits: brand, speed, start(), and stop(). Instead of writing these four members twice, we define a common Vehicle class once. Both Car and Bike inherit the common functionality and only write their unique specialized details.

Figure 1.1: Common properties are placed in a parent class and inherited by specialized child classes.

2. Parent Class and Child Class

Inheritance connects two classes through a hierarchical relationship with specific industry terms:

  • Parent Class (Superclass / Base Class): The class whose properties and methods are being inherited.
  • Child Class (Subclass / Derived Class): The class that inherits and extends the superclass.
Figure 2.1: The Superclass provides general functionality, and Subclasses receive and specialize it.

3. The extends Keyword

In Dart, inheritance is declared using the extends keyword. Writing class Dog extends Animal informs the Dart compiler that Dog inherits all non-private members of Animal.

Figure 3.1: Syntax structure connecting subclass to superclass via extends.
DART • EXTENDS KEYWORDanimal_dog.dart
DART Script
DART 
class Animal {
  String name = 'Animal';

  void eat() {
    print('$name is eating');
  }
}

// Dog inherits all members from Animal
class Dog extends Animal {
  void bark() {
    print('Dog is barking');
  }
}

void main() {
  Dog dog = Dog();
  dog.eat();  // Inherited from Animal
  dog.bark(); // Defined inside Dog
}
Expected Console Output Animal is eating
Dog is barking

7. The super Keyword

The super keyword provides a reference to the immediate parent (superclass) instance. It allows a child class method to invoke the parent class's version of a method that has been overridden.

Figure 7.1: super.sound() delegates to the parent class implementation before or after child actions.
Figure 7.2: this operates on current scope; super targets parent scope.
DART • CALLING SUPER METHODSsuper_sound.dart
DART Script
DART 
class Animal {
  void sound() {
    print('Animal makes a sound');
  }
}

class Dog extends Animal {
  void sound() {
    super.sound(); // Calls parent Animal.sound()
    print('Dog barks');
  }
}

void main() {
  Dog dog = Dog();
  dog.sound();
}
Expected Console Output Animal makes a sound
Dog barks

8. Constructors in Inheritance & Constructor Chaining

Constructors are never inherited by child classes in Dart. When a subclass is instantiated, the superclass constructor must execute first to initialize parent fields before the child constructor body runs. We forward parameters to the parent using : super(...).

Figure 8.1: Construction lifecycle order: Superclass initializes before subclass body executes.
DART • CONSTRUCTOR CHAININGctor_chaining.dart
DART Script
DART 
class Animal {
  String name;

  Animal(this.name) {
    print('Animal constructor called');
  }
}

class Dog extends Animal {
  String breed;

  // Chains to parent constructor Animal(name) using super(name)
  Dog(String name, this.breed) : super(name) {
    print('Dog constructor called');
  }
}

void main() {
  Dog dog = Dog('Tommy', 'Labrador');
  print(dog.name);
  print(dog.breed);
}
Expected Console Output Animal constructor called
Dog constructor called
Tommy
Labrador

9. Method Overriding

Method overriding occurs when a subclass re-implements an inherited method to provide specialized behavior suited specifically for the child.

Figure 9.1: Each subclass overrides the general method with its own distinct implementation.

    print('Animal makes a sound');

  }
}

class Cat extends Animal {
  @override

  }
}

  Dog dog = Dog();
  Cat cat = Cat();

  dog.makeSound();
  cat.makeSound();
}

Cat meows

10. The @override Annotation

The @override annotation is a compiler directive placed immediately before an overridden method. It communicates intent to both fellow developers and the Dart static analyzer, which verifies that an eligible matching method actually exists in the superclass.

Figure 10.1: The @override annotation prevents unintended accidental additions.

11. What is Polymorphism?

The word polymorphism originates from Greek: poly (many) and morph (forms). In programming, it represents the ability of a single interface or parent reference to invoke diverse behaviors depending on the underlying concrete object.

Figure 11.1: Polymorphism: the identical method call produces specialized outputs per object.

12. Runtime Polymorphism & Dynamic Dispatch

In Dart, a variable declared with a superclass type (Animal animal) can hold an instance of any of its subclasses (Dog()). When you call animal.makeSound(), Dart dynamically inspects the actual object at runtime (dynamic dispatch) and executes the subclass's overridden implementation.

Figure 12.1: Declared reference type vs actual runtime object.
DART • RUNTIME POLYMORPHISMruntime_dispatch.dart
DART Script
DART 
class Animal {
  void makeSound() {
    print('Animal makes a sound');
  }
}

class Dog extends Animal {
  @override
  void makeSound() {
    print('Dog barks');
  }
}

class Cat extends Animal {
  @override
  void makeSound() {
    print('Cat meows');
  }
}

void main() {
  // Declared as Animal, instantiated as Dog and Cat
  Animal animal1 = Dog();
  Animal animal2 = Cat();

  animal1.makeSound();
  animal2.makeSound();
}
Expected Console Output Dog barks
Cat meows

14. Compile-Time vs Runtime Polymorphism

In general computer science, polymorphism is divided into compile-time (method overloading) and runtime (method overriding). Dart does not support traditional same-class method overloading. Instead, Dart uses optional parameters and named parameters to achieve flexible method calls cleanly.

Figure 14.1: Dart favors optional/named parameters over rigid method overloading.
DART • FLEXIBLE PARAMETERScalculator_demo.dart
DART Script
DART 
class Calculator {
  // Single method with optional parameter [int b = 0]
  int add(int a, [int b = 0]) {
    return a + b;
  }
}

void main() {
  Calculator calculator = Calculator();
  print(calculator.add(10));     // Uses default b = 0
  print(calculator.add(10, 20)); // Passes b = 20
}
Expected Console Output 10
30

15. Abstract Classes & Abstract Methods

An abstract class (defined using abstract class) represents an incomplete blueprint that cannot be instantiated directly. It often declares abstract methods (methods with a signature but no body: void pay(double amount);), forcing every concrete subclass to provide the actual implementation.

Figure 15.1: Abstract classes enforce concrete implementation in all subclasses.
DART • ABSTRACT CLASS & METHODSabstract_payment.dart
DART Script
DART 
abstract class Payment {
  // Abstract method (has no body {})
  void pay(double amount);
}

class UpiPayment extends Payment {
  @override
  void pay(double amount) {
    print('Paid ₹$amount using UPI');
  }
}

class CardPayment extends Payment {
  @override
  void pay(double amount) {
    print('Paid ₹$amount using Card');
  }
}

void main() {
  Payment payment1 = UpiPayment();
  Payment payment2 = CardPayment();

  payment1.pay(500);
  payment2.pay(1000);
}
Expected Console Output Paid ₹500.0 using UPI
Paid ₹1000.0 using Card

16. extends vs implements

In Dart, every class implicitly defines an interface. Understanding when to use extends versus implements is vital:

  • extends (Inheritance): Reuses implementation from a single superclass. You only override what you want to customize.
  • implements (Interface Contract): Treats the target class as a pure contract. You must provide your own implementation for every member, without inheriting any existing method bodies.
Figure 16.1: extends inherits behavior; implements enforces an interface contract.
DART • IMPLEMENTS INTERFACEflyable_bird.dart
DART Script
DART 
abstract class Flyable {
  void fly();
}

class Bird implements Flyable {
  @override
  void fly() {
    print('Bird is flying');
  }
}

void main() {
  Bird bird = Bird();
  bird.fly();
}
Expected Console Output Bird is flying

17. Type Checking with is & Type Casting with as

When working with parent references, you may occasionally need to check an object's specific child subtype:

  • is: Checks if an object is of a specific type (e.g. animal is Dog) and enables automatic type promotion.
  • is!: Checks if an object is NOT of a specific type.
  • as: Explicitly casts a reference to a subtype. Unsafe casts throw a runtime exception if the object is not compatible.
Figure 17.1: The is operator safely promotes parent references to child subtypes.
DART • TYPE CHECKING & PROMOTIONtype_check.dart
DART Script
DART 
class Animal {
  void eat() => print('Animal is eating');
}

class Dog extends Animal {
  void bark() => print('Dog is barking');
}

void main() {
  Animal animal = Dog();

  // Type check with automatic promotion
  if (animal is Dog) {
    animal.bark(); // Compiler promotes animal to Dog!
  }
}
Expected Console Output Dog is barking

19. Common Inheritance & Polymorphism Mistakes

Avoid these 18 frequent traps when working with inheritance in Dart:

1. Assuming Subclasses Automatically Inherit Constructors

Why it fails: In Dart, constructors are never inherited. You must explicitly define subclass constructors and delegate via : super(...).

✗ Bad: Dog dog = Dog('Rex'); // when Dog declared no constructor

✓ Good: Dog(String name) : super(name);

2. Attempting Multiple Class Inheritance with extends

Why it fails: Dart forbids extending more than one class directly (e.g. extends A, B).

✗ Bad: class Duck extends Swimmer, Flyer { }

✓ Good: class Duck extends Animal with Swimmer, Flyer { }

3. Directly Instantiating an Abstract Class

Why it fails: Abstract classes cannot have live instances created with ClassName().

✗ Bad: Payment p = Payment();

✓ Good: Payment p = UpiPayment();

4. Forgetting to Implement Abstract Methods in Subclasses

Why it fails: A concrete subclass must fulfill every abstract method contract inherited from its superclass.

✗ Bad: Omitting void pay(double amount) in UpiPayment.

5. Trying to Access Child-Only Members from a Parent-Type Reference

Why it fails: The compiler only allows calls to members declared on the variable's static type.

✗ Bad: Animal a = Dog(); a.bark(); // compile error

✓ Good: if (a is Dog) a.bark();

6. Confusing this with super

Why it fails: this.method() calls the current class's method (potentially causing infinite recursion if inside an override), while super.method() targets the parent implementation.

7. Unsafe Downcasting with as

Why it fails: animal as Dog throws a runtime CastError if animal is actually a Cat.

✓ Good: Always guard with if (animal is Dog) first.

8. Believing implements Reuses Concrete Method Bodies

Why it fails: implements extracts only the type interface; all method bodies from the target class are ignored and must be re-written.

21. Knowledge Check

Interactive Multiple Choice Questions

1. How many parent classes can a Dart class directly inherit using extends?

A) Exactly one (Dart supports only single class inheritance).
B) Up to two classes.
C) Unlimited classes separated by commas.
D) None; Dart does not support inheritance.

Correct Answer: A
Explanation: Dart strictly enforces single class inheritance for extends. Multiple interface contracts can be implemented using implements, but classes can only extend one superclass.

2. Are constructors automatically inherited by subclasses in Dart?

A) Yes, child classes automatically inherit all parent constructors.
B) No, child classes must declare their own constructors and chain via : super(...).
C) Only named constructors are inherited.
D) Only private constructors are inherited.

Correct Answer: B
Explanation: In Dart, constructors are never inherited. Subclasses must define their own constructors and invoke the superclass constructor using an initializer list.

3. If Animal a = Dog(); is declared, which method executes on a.makeSound()?

A) Dog's overridden version, because dynamic dispatch resolves methods based on the actual runtime object.
B) Animal's base version, because the variable's declared type is Animal.
C) Both methods run sequentially.
D) A runtime NoSuchMethodError is thrown.

Correct Answer: A
Explanation: This is runtime polymorphism. At runtime, Dart looks at the concrete object in memory (Dog), executing its overridden method.

4. What is a key difference between extends and implements?

A) extends reuses superclass method bodies; implements requires providing bodies for all members.
B) extends works on multiple classes; implements works on only one.
C) implements inherits constructors; extends does not.
D) They are exact synonyms.

Correct Answer: A
Explanation: extends provides code reusability from a parent. implements treats the class as an interface, requiring the child to implement every member.

5. What happens when you check if (animal is Dog) in Dart?

A) Dart checks the runtime type and automatically promotes animal to Dog inside the block.
B) It throws a compile error if animal is not a Dog.
C) It converts all Animals in memory to Dogs.
D) It deletes the animal variable.

Correct Answer: A
Explanation: Dart flow analysis automatically type-promotes animal to Dog within the true branch of the is check.
