Functions & Parameters

Master code reusability in Dart: learn how to declare, call, and structure functions with return types, positional parameters, optional parameters, named parameters, default values, and arrow syntax.

1. Introduction to Functions

A function is a self-contained block of reusable code designed to perform a specific task. Instead of writing the same instructions again and again, you bundle them inside a function and run that block whenever needed.

Why do we need functions? Without functions, our programs would suffer from massive code duplication, making software fragile, hard to read, and difficult to debug. Functions enforce the DRY principle (Don't Repeat Yourself).

Visual 1: Repeated Code vs Reusable Function (DRY Principle)
Real-Life Analogy: The Washing Machine
Think of a washing machine. You do not re-engineer motors and water valves every time you do laundry; you simply press the Start button. The machine executes its predefined sequence of washing, rinsing, and spinning. Similarly, defining a function sets up the instructions, and calling it executes them on command.

3. Understanding void Functions

In Dart, void is a keyword that specifies that a function does not return a useful value to its caller. It performs side-effects (like printing text, updating a database, or rendering a UI element) and then quietly hands control back.

Visual 5: void Function (Action Only) vs Returning Function (Value Delivery)
Crucial Beginner Rule: Printing ≠ Returning
Printing with print() writes characters onto your terminal screen so humans can read it. It does not send data back to your code. If you try to save a void function call into a variable (e.g. var x = showMessage();), Dart will report a compile-time error because nothing was returned.
void_example.dartAction Function
DART Script
DART 
void showMessage() {
  print('Welcome to CodeVerse');
}

void main() {
  showMessage();
}
> Console Output
Welcome to CodeVerse

4. Understanding Parameters and Arguments

Functions often need input data to do their job dynamically. The terms parameter and argument are closely linked but have precise technical roles:

  • Parameter: The variable declared inside the function's parentheses in its definition (the placeholder).
  • Argument: The actual value supplied into the function call when invoking it.
Visual 6: Parameter (Definition Placeholder) vs Argument (Actual Passed Value)

DART Script

  print('Hello, $name');
}

void main() {
  // 'Shailendra' is the argument
  greet('Shailendra');
}
> Console Output
Hello, Shailendra

6. Understanding Return Values

A return value is the final output data that a function produces and delivers back to the place where the function was called. The return keyword terminates function execution and hands the result back.

Visual 8: Return Value Delivery Cycle
return_value.dartReturning Data
DART Script
DART 
int add(int a, int b) {
  return a + b; // Sends 30 back to caller
}

void main() {
  // The returned value 30 is captured in the variable 'result'
  int result = add(10, 20);
  print(result); // Prints 30
}
> Console Output
30

7. Functions with Different Return Types

In Dart, every function specifies what type of data it returns. If a function declares a return type of int, it must return an integer. Returning a different type causes a compile-time error.

8. Positional Parameters

By default, function parameters in Dart are positional. When invoking the function, you must supply an argument for every parameter in the exact order declared.

DART Script
DART

  print('$name is $age years old');

  student('Rahul', 20); // Position 1: 'Rahul', Position 2: 20
}
> Console Output
Rahul is 20 years old

9. Optional Positional Parameters

Sometimes certain parameters are not always needed. In Dart, you wrap parameters in square brackets [...] at the end of the parameter list to make them optional. You can also assign a default value that is used whenever the caller omits that argument.

Visual 10: Optional Positional Parameters with Default Fallback
optional_positional.dartSquare Brackets
DART Script
DART 
void greet(String name, [String city = 'Lucknow']) {
  print('Hello $name from $city');
}

void main() {
  greet('Rahul');          // Uses default city 'Lucknow'
  greet('Aman', 'Delhi');  // Overrides with 'Delhi'
}
> Console Output
Hello Rahul from Lucknow
Hello Aman from Delhi

10. Named Parameters

As functions accept more inputs, remembering positional order becomes confusing and error-prone. Named parameters solve this by wrapping parameters in curly braces {...}. When calling the function, you specify each argument by its parameter name.

  print('Name: $name');
  print('Age: $age');
}

void main() {

  studentDetails(age: 22, name: 'Priya');

Name: Priya

14. Local Variables and Function Scope

A variable declared inside a function is a local variable. It exists only while that function is running and is strictly confined to that function's scope. Other functions cannot read or modify it.

Visual 15: Function Scope Isolation Barrier
scope_example.dartLocal Scope
DART Script
DART

  String message = 'Hello Dart'; // Local to showMessage
  print(message);
}

void main() {
  showMessage();
  // print(message); <-- This would cause a compile error: Undefined name 'message'
}
> Console Output
Hello Dart

17. Common Beginner Mistakes (and How to Fix Them)

1. Defining a Function but Forgetting to Call It

Defining a function only teaches Dart the instructions; it never executes unless called with ().

// BAD: Function defined but never called in main()
void run() { print("Running"); } void main() { } // Prints nothing!

// FIXED: Invoke it explicitly
void main() { run(); }
2. Confusing Parameters and Arguments

Passing a type declaration into a function call produces a syntax error.

// BAD: Trying to declare types inside the function call
greet(String 'Rahul'); // Compile error!

// FIXED: Pass only the concrete value as the argument
greet('Rahul');
3. Passing the Wrong Number of Positional Arguments

Positional parameters must receive the exact number of declared arguments.

// BAD: studentDetails expects 2 arguments
studentDetails('Rahul'); // Compile error: 2 arguments expected, 1 found.

// FIXED: Supply all required positional arguments
studentDetails('Rahul', 20);
4. Passing Arguments in the Wrong Order

Positional arguments map sequentially. Swapping them violates parameter types.

// BAD: Passing int where String is expected
studentDetails(20, 'Rahul'); // Compile error: The argument type 'int' can't be assigned to 'String'

// FIXED: Match positional order carefully
studentDetails('Rahul', 20);
5. Forgetting the Return Statement in Non-void Functions

Declaring a return type like int without a return statement causes a compile error.

// BAD: Missing return
int add(int a, int b) { int sum = a + b; } // Error: Must return a value

// FIXED: Include return statement
int add(int a, int b) { return a + b; }
6. Returning a Value with an Incompatible Type

Returning data that does not match the declared return type causes a type mismatch.

// BAD: Declared int but returning String
int getScore() { return "100"; } // Error: String can't be assigned to int

// FIXED: Return matching type
int getScore() { return 100; }
7. Confusing print() with return

Printing displays text on the terminal screen, but does not provide data back to the calling code.

// BAD: Trying to capture printed output
void printTotal() { print(10 + 20); }
int x = printTotal(); // Error: A value of type 'void' can't be assigned to 'int'

// FIXED: Use return
int getTotal() { return 10 + 20; } int x = getTotal();
8. Forgetting required Named Arguments

Omitting a named argument that was marked required prevents the program from compiling.

// BAD: Missing required email argument
createAccount(name: 'Rahul'); // Error: The named parameter 'email' is required

// FIXED: Supply all required named arguments
createAccount(name: 'Rahul', email: 'r@mail.com');
9. Incorrectly Placing Optional Positional Brackets

Optional positional parameters [...] must always appear at the end of the parameter list.

// BAD: Optional parameter placed before required parameter
void test([int a], int b) { } // Compile error!

// FIXED: Place optional parameters last
void test(int b, [int a = 0]) { }
10. Confusing Named {} and Positional [] Syntax

You cannot combine curly and square brackets for the same parameter.

// BAD: Mixing bracket types
void demo({[int a]}) { } // Syntax error!

// FIXED: Choose either named {int a = 0} OR optional positional [int a = 0]
11. Trying to Access a Local Variable Outside Its Scope

Variables created inside a function are destroyed when that function exits.

// BAD: 'temp' is not visible in main()
void calc() { int temp = 42; } void main() { print(temp); } // Error: Undefined name 'temp'

// FIXED: Return the value or declare it in main()
int calc() { int temp = 42; return temp; } void main() { print(calc()); }
12. Writing Multiple Statements After Arrow =>

Arrow functions accept only a single expression. Writing multiple lines or statements causes a syntax error.

// BAD: Arrow syntax cannot hold multiple statements or semicolons
int calc(int x) => print(x); return x * 2; // Syntax error!

// FIXED: Use standard braces { ... } for multi-statement functions
int calc(int x) { print(x); return x * 2; }

18. Quick Revision

Core Takeaways Checklist
  • Function: A named reusable block of code that performs a specific task.
  • main(): The mandatory entrypoint where every Dart application begins execution.
  • void: Return type signifying that the function performs an action but returns no data.
  • Parameter vs Argument: Parameter is the placeholder in definition; argument is the concrete value in call.
  • Return Value: Output delivered back to caller via the return keyword.
  • Positional Parameters: Arguments mapped strictly by left-to-right sequential order.
  • Optional Positional Parameters: Declared in square brackets [type x = default] at the end.
  • Named Parameters: Declared in curly braces {type? x}; called by name regardless of order.
  • required Keyword: Enforces that a named argument must be provided by the caller.
  • Default Values: Fallback values supplied with = when arguments are omitted.
  • Arrow Syntax (=>): Concise shorthand for one-line returning functions.
  • Local Scope: Variables declared inside a function are invisible and inaccessible outside.
