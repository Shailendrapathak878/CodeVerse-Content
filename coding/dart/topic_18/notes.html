Dart • Topic 18: Enums, Records & Pattern Matching

Master discrete fixed choices with enums, lightweight aggregate data structures with records, and structural inspection with Dart 3 pattern matching.

1. Introduction to Enums

In programming, we frequently deal with a fixed set of predefined choices. For instance, an e-commerce order can only be in one of a few exact states: Pending, Processing, Shipped, Delivered, or Cancelled.

Using raw strings like "shipped" or numbers like 2 is dangerous because typos like "shiped" cause silent runtime bugs. An enum (short for enumeration) defines a closed, strongly-typed collection of constant values.

Figure 1.1: OrderStatus represents exactly 5 discrete, compile-time verified choices.
Figure 1.2: Enums eliminate accidental typos and invalid states at compile time.
DART • ENUM DECLARATIONorder_status.dart
DART Script
DART 
enum OrderStatus {
  pending,
  processing,
  shipped,
  delivered,
  cancelled
}

void main() {
  OrderStatus status = OrderStatus.shipped;

  print(status);
}
Console Output OrderStatus.shipped

2. Creating and Using Enums

An enum is defined using the enum keyword. Enum values are accessed with dot notation: EnumName.value. They can be compared using == or tested inside if-else and switch constructs.

Figure 2.1: TrafficLight enum values mapped directly to clear driving actions.
DART • ENUM IN CONDITIONAL LOGICtraffic_light.dart
DART Script
DART 
enum TrafficLight {
  red,
  yellow,
  green
}

void main() {
  TrafficLight signal = TrafficLight.red;

  if (signal == TrafficLight.red) {
    print('Stop');
  } else if (signal == TrafficLight.yellow) {
    print('Get Ready');
  } else {
    print('Go');
  }
}
Console Output Stop

Architecture Tip: Never Persist Enum Indexes
Never save day.index in databases or send it over network APIs. If someone adds a new day or reorders items, the numeric index changes, silently corrupting stored data. Always persist day.name instead.

Rules: All instance fields must be declared final, and the constructor must be declared const.

Figure 4.1: Enhanced enums bind custom constant state directly to each enum value.

6. Enum Practical Use Cases

Enums model finite application states with zero ambiguity. A ubiquitous use case in mobile and web development is tracking asynchronous network request states.

7. Introduction to Records

Dart 3 introduced Records: an anonymous, immutable, aggregate type that groups multiple values into a single compound value without requiring you to declare a whole new class.

A record is created using comma-separated values inside parentheses: ('Amit', 101, 85.5).

Figure 7.1: Grouping heterogeneous values into a lightweight, immutable Record.

8. Positional Records

When fields in a record are defined without names, they are positional fields. Positional fields are 1-indexed and accessed with getters starting with $: $1, $2, $3, etc.

Figure 8.1: Positional fields are accessed via 1-based dollar indices ($1, $2, $3).
DART • POSITIONAL FIELD ACCESSpositional_record.dart
DART Script

  var student = ('Amit', 101, 85.5);

  print(student.$1);
  print(student.$2);
  print(student.$3);
}

Just as Dart functions support named parameters, records support named fields. Named fields make code dramatically more readable and self-documenting. They are accessed using standard dot notation: record.fieldName.

Figure 9.1: Named fields are accessed cleanly via dot notation instead of numeric indices.

14. Introduction to Pattern Matching

Dart 3 introduced first-class Pattern Matching. A pattern represents the shape of a value. When an input value matches that pattern, Dart automatically destructures (unpacks) and binds its internal values into local variables in one step.

Figure 14.1: The pattern matching pipeline: inspecting shape and extracting components simultaneously.

15. Pattern Matching with Switch Statements

In modern Dart, switch statements are powered by pattern matching. They are exhaustive by default for enums and sealed types, and cases no longer fall through or need break statements.

Figure 15.1: Pattern matching in switch statements: clean cases without break statements.
DART • SWITCH PATTERN STATEMENTswitch_statement.dart
DART Script
DART 
enum OrderStatus {
  pending,
  shipped,
  delivered
}

void showOrder(OrderStatus status) {
  switch (status) {
    case OrderStatus.pending:
      print('Order is pending');
    case OrderStatus.shipped:
      print('Order is on the way');
    case OrderStatus.delivered:
      print('Order delivered');
  }

void main() {
  showOrder(OrderStatus.shipped);
}
Console Output Order is on the way

16. Switch Expressions

A switch expression evaluates a value and returns a result directly using fat arrow => syntax. It can be assigned directly to a variable or returned from a function.

Figure 16.1: Switch expressions evaluate cases into concise return values.
Figure 16.2: Comparison between classic statement switch and modern expression switch.
DART • SWITCH EXPRESSIONswitch_expression.dart
DART Script
DART 
enum TrafficLight {
  red,
  yellow,
  green
}

void main() {
  TrafficLight signal = TrafficLight.green;

  String action = switch (signal) {
    TrafficLight.red => 'Stop',
    TrafficLight.yellow => 'Wait',
    TrafficLight.green => 'Go',
  };

  print(action);
}
Console Output Go

17. Record Patterns and Destructuring

Destructuring allows you to break apart a record and unpack its internal fields directly into individual local variables in one clean declaration.

  • Positional destructuring: var (name, roll) = student;
  • Named shorthand destructuring: var (:name, :age) = person;
Figure 17.1: Destructuring unpacking a record into distinct local variables.
DART • RECORD DESTRUCTURINGdestructuring_demo.dart
DART Script
DART 
void main() {
  // Positional destructuring
  var student = ('Amit', 101);
  var (name, rollNumber) = student;

  print(name);
  print(rollNumber);

  // Named destructuring with shorthand syntax (:name binds to variable 'name')
  var person = (
    name: 'Ravi',
    age: 20
  );
  var (:name, :age) = person;

  print(name);
  print(age);
}
Console Output Amit
101
Ravi
20

18. List Patterns

A List pattern matches a list's length and elements. You can use _ as a wildcard (matching any element) and ...var remaining as a rest pattern (matching and collecting zero or more trailing elements).

Figure 18.1: Rest patterns capture trailing elements into a newly sliced list.
DART • LIST PATTERNS & REST SYNTAXlist_patterns.dart
DART Script
DART 
void main() {
  var numbers = [10, 20, 30];

  switch (numbers) {
    case [10, 20, 30]:
      print('Exact match found');
    case [10, 20, _]:
      print('First two values matched');
    default:
      print('No match');
  }

  var numbers2 = [10, 20, 30, 40];
  switch (numbers2) {
    case [10, ...var remaining]:
      print(remaining);
    default:
      print('No match');
  }
}
Console Output Exact match found
[20, 30, 40]

19. Map Patterns

A Map pattern inspects a map for specific keys and extracts their values if present. This is extraordinarily powerful for parsing JSON payloads from REST APIs.

20. Object Patterns

An Object pattern matches an object's type and extracts properties using its getters. User(name: var name, age: var age) verifies that the object is a User instance and binds its fields.

Figure 20.1: Object patterns extract member properties directly using getters.

  final String name;
  final int age;

  User(this.name, this.age);

    case User(name: var name, age: var age):

      print(age);
  }

20

22. if-case and Pattern Matching in Conditions

The if-case statement marries an if condition with pattern matching. If the value matches the pattern, the condition evaluates to true and the extracted variables are immediately in scope inside the if body!

Figure 22.1: if-case tests structural matching and binds variables in one step.
DART • IF-CASE PATTERN MATCHINGif_case_demo.dart
DART Script
DART

  var user = ('Amit', 20);

  if (user case (String name, int age)) {
    print('Name: $name');
    print('Age: $age');
  }
}
Console Output Name: Amit
Age: 20

23. Null-Check and Null-Assert Patterns

Pattern matching integrates seamlessly with Dart's sound null safety system:

  • Null-Check Pattern (?): Matches only if the value is non-null, unwrapping it safely.
  • Null-Assert Pattern (!): Asserts that the value is non-null. If null is encountered, it throws an exception.
Figure 23.1: Handling nullable variables using declarative null-check patterns.
DART • NULL-CHECK PATTERNnull_pattern.dart
DART Script
DART 
void main() {
  String? name = 'Amit';

  switch (name) {
    case var value?:
      print(value);
    case null:
      print('Name is not available');
  }
}
Console Output Amit

24. Combining Records, Enums and Pattern Matching

When combined, records, enums, and pattern matching form a cohesive architectural triad. Below is a complete Student Result System demonstrating their synergy:

  analyzeResult(('Priya', 68));

26. Common Mistakes

Study these 28 frequent beginner mistakes to avoid compilation errors:

Figure 26.1: Common syntactic traps in records, enhanced enums, and patterns.
  1. Declaring enum values as strings: Write enum Status { pending }, never "pending".
  2. Comparing enums with raw strings: status == "shipped" is always false. Compare with OrderStatus.shipped.
  3. Forgetting the enum type name: var s = shipped; fails. Use OrderStatus.shipped.
  4. Relying on enum index for storage: If values are reordered, indexes break. Store .name.
  5. Unchecked byName() calls: OrderStatus.values.byName('invalid') throws an ArgumentError.
  6. Non-const constructor in enhanced enums: All enhanced enum constructors must be const.
  7. Non-final fields in enhanced enums: All enum state must be immutable (final).
  8. Omitting semicolon before methods: Enhanced enums must terminate their value list with a semicolon (;) before declaring fields or methods.
  9. Using $0 for positional records: Records start at $1, not $0!
  10. Accessing named fields with $: Named fields use record.name, not record.$1.
  11. Confusing records with lists: Records cannot be indexed dynamically like record[i].
  12. Confusing records with maps: Records are compile-time fixed shapes, not dynamic dictionary key-value lookups.
  13. Returning mismatched record shapes: A function typed (String, int) cannot return (int, String).
  14. Positional label confusion: Writing (String name, int age) as a type annotation does not make fields accessible as .name; they remain $1 and $2 unless wrapped in { ... }.
  15. Invalid type annotations: Named record types require curly braces: ({String name, int age}).
  16. Expecting patterns to match without checking shape: case [10, 20]: will not match a 3-element list.
  17. List length mismatch: A pattern like [var a, var b] strictly expects a list with exactly 2 elements.
  18. Forgetting that _ ignores data: _ is a wildcard and cannot be read or printed.
  19. Incorrect rest pattern placement: You cannot place two rest patterns (...) in the same list pattern.
  20. Invalid map pattern: A map pattern case {'id': int id} fails if the key is missing or has the wrong type.
  21. Confusing variable and type patterns: int x declares a variable pattern; int _ is a type pattern with wildcard.
  22. Using relational patterns outside switch/if-case: Relational patterns like >= 50 are pattern syntax, not standalone boolean expressions.
  23. Incorrect logical combinators: Remember that && and || in patterns combine pattern tests, not boolean values.
  24. Non-exhaustive switch expressions: Every switch expression must cover all possibilities, or the compiler throws an error.
  25. Confusing switch expressions with statements: Switch expressions produce a value and use case => value without break.
  26. Confusing if-case with normal if: if (x case pattern) checks structure; if (x == y) checks equality.
  27. Confusing null-check (?) and null-assert (!): ? safely filters out nulls; ! crashes if null is encountered.
  28. Using ! without null safety guarantees: Prefer null-check ? with an explicit case null: branch.

27. Quick Revision

Figure 27.1: Master synthesis mindmap of modern Dart 3 expressive constructs.
  • enum: Defines a closed set of discrete constant choices (e.g. OrderStatus).
  • Enhanced Enum: Enums with final fields, const constructors, and getters/methods.
  • Records: Anonymous immutable aggregate type with fixed compile-time shape.
  • Positional Fields: 1-indexed; accessed via $1, $2, $3.
  • Named Fields: Enclosed in { ... } in types; accessed via .fieldName.
  • Multiple Returns: Functions can return (int, String) without dummy wrapper classes.
  • Pattern Matching: Declarative inspection of structure and simultaneous extraction of data.
  • Switch Expression: Produces values with case => result syntax with mandatory exhaustiveness.
  • Destructuring: Unpacks record/list/map/object fields directly into local variables.
  • Wildcard (_): Matches any value while discarding it.
  • Rest Pattern (...var rest): Gathers remaining list elements into a sub-list.
  • if-case: Conditionally matches structure and brings variables into scope.
