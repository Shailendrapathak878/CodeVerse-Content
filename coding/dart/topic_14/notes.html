Classes & Objects

Step into Object-Oriented Programming (OOP) in Dart! Discover how classes act as structural blueprints and how objects bring real-world entities to life with state, behaviors, constructors, getters, setters, and static members.

1. Introduction to Object-Oriented Programming (OOP)

Computer programming is solving real-world problems by writing clear instructions. In small scripts, we can organize code into variables and functions. But when applications grow large—with thousands of users, orders, and products—grouping loose variables and functions together becomes difficult.

Object-Oriented Programming (OOP) solves this by organizing code around objects. An object bundles both data (properties) and actions (methods) together into a single cohesive package, exactly like real-world entities.

Real-Life Analogy: The College Student

Imagine a college campus. Each student has attributes (name, age, roll number, course) and can perform actions (attend class, study, pay fees). Rather than tracking loose lists of names and ages, OOP models a Student entity that holds its own data and actions.

Figure 1.1: The progression from a real-world concept to an active OOP object in Dart.

Dart is an object-oriented language where everything you touch—numbers, strings, lists, and functions—is an object. In this topic, we will master the foundations: classes, objects, constructors, and encapsulation.

2. What is a Class?

A class is a code template or blueprint that defines what data an object will hold and what operations it can perform. A class itself does not allocate room for individual data; it merely specifies the structure.

Figure 2.1: A class is the architectural drawing; the object is the actual constructed house.

Defining a Simple Class in Dart

DART • CLASS DECLARATIONstudent.dart
DART Script
DART 
class Student {
  // Properties (Instance variables)
  String name = 'Rahul';
  int age = 20;

  // Method (Action)
  void study() {
    print('$name is studying');
  }
}

Code breakdown:

  • class: Keyword used to announce a new custom data type.
  • Student: Class name, written in PascalCase by Dart convention.
  • name and age: Properties (data fields) that every student will hold.
  • study(): A method (function belonging to the class) specifying student behavior.

3. What is an Object?

An object is a concrete, living instance of a class stored in computer memory. If the class is the automotive blueprint, the car parked in your driveway is the object.

Figure 3.1: Instantiating the Car class produces a live in-memory object instance.
DART • CREATING AN OBJECTcar_demo.dart
DART Script
DART 
class Car {
  String brand = 'Toyota';
  String color = 'White';

  void start() {
    print('$brand car is starting');
  }
}

void main() {
  // Create an instance using ClassName()
  Car myCar = Car();

  // Access properties using the dot (.) operator
  print(myCar.brand);
  print(myCar.color);

  // Call object method
  myCar.start();
}
Expected Console Output Toyota
White
Toyota car is starting

8. What is a Constructor?

Manually assigning properties line-by-line right after creating an object is tedious and error-prone. A constructor is a special initialization function that runs automatically at the exact instant an object is born.

Figure 8.1: Constructor execution lifecycle during object instantiation.

Core rules of Dart constructors:

  • Its name matches the class name identically: Student().
  • It has no return type (not even void).
  • It runs exactly once per created instance.
DART • CONSTRUCTOR RUNTIMEctor_demo.dart
DART Script
DART 
class Student {
  // Explicit constructor
  Student() {
    print('Student object created');
  }
}

void main() {
  Student student = Student();
}
Expected Console Output Student object created

10. Parameterized Constructor

A parameterized constructor allows callers to supply custom values at the moment of object creation. Dart features an elegant shorthand known as initializing formals (this.propertyName), which automatically assigns constructor arguments to instance fields without repetitive boilerplate.

Figure 10.1: Initializing formals direct arguments straight into instance variables.

  student2.showDetails();

11. Understanding the this Keyword

The this keyword represents a reference to the current object instance. It disambiguates when a parameter name is identical to an instance variable name.

Figure 11.1: this.name specifically targets the instance variable on the current object.
DART • THIS DISAMBIGUATIONthis_demo.dart
DART Script
DART 
class Student {
  late String name;
  late int age;

  // Parameter names match field names
  Student(String name, int age) {
    this.name = name; // this.name is the field; name is the parameter
    this.age = age;
  }

  void showDetails() {
    print('$name is $age years old');
  }
}

void main() {
  Student student = Student('Aman', 20);
  student.showDetails();
}
Expected Console Output Aman is 20 years old
Pro Dart Tip: Initializing Formals

While assigning via this.name = name; inside the body works, standard Dart practice prefers the concise initializing formal syntax: Student(this.name, this.age);.

12. Named Constructors

Unlike languages like Java or C++ that support constructor overloading based on parameter signatures, Dart uses Named Constructors (syntax: ClassName.constructorName()) to provide multiple explicit creation paths.

Figure 12.1: Named constructors offer alternative doorways to configure an object.
DART • NAMED CONSTRUCTORnamed_ctor.dart
DART Script
DART 
class Student {
  String name;
  int age;

  // Standard unnamed constructor
  Student(this.name, this.age);

  // Named constructor using an initializer list
  Student.guest()
      : name = 'Guest',
        age = 18;

  void showDetails() {
    print('Name: $name, Age: $age');
  }
}

void main() {
  Student student1 = Student('Rahul', 20);
  Student student2 = Student.guest();

  student1.showDetails();
  student2.showDetails();
}
Expected Console Output Name: Rahul, Age: 20
Name: Guest, Age: 18

14. Getters in Dart

A getter is a special method that retrieves or calculates a value while appearing to the caller as an ordinary property (accessed without parentheses).

Figure 14.1: Getters compute and deliver values dynamically using clean property syntax.
DART • GETTER COMPUTATIONgetter_demo.dart
DART Script
DART 
class Rectangle {
  double width;
  double height;

  Rectangle(this.width, this.height);

  // Getter syntax: returnType get name => calculation;
  double get area => width * height;
}

void main() {
  Rectangle rectangle = Rectangle(10, 5);

  // Notice: NO parentheses when accessing a getter
  print(rectangle.area);
}
Expected Console Output 50.0

15. Setters in Dart

A setter intercepts property assignments, allowing you to validate, sanitize, or transform incoming data before saving it into an instance variable. Setters have no return type and are invoked via assignment (obj.property = value;).

Figure 15.1: Setters act as gatekeepers preventing invalid data entry.
DART • SETTER VALIDATIONsetter_demo.dart
DART Script
DART 
class Student {
  String name;

  Student(this.name);

  // Setter syntax: set name(parameter) { ... }
  set studentName(String newName) {
    if (newName.isNotEmpty) {
      name = newName;
    }
  }
}

void main() {
  Student student = Student('Rahul');

  // Assigned using standard property syntax
  student.studentName = 'Aman';

  print(student.name);
}
Expected Console Output Aman

16. Getters and Setters Together

Combining getters and setters with library-private fields provides true encapsulation. In Dart, prefixing an identifier with an underscore (_balance) makes it private to its containing library, preventing external unauthorized tampering.

Figure 16.1: Encapsulation protects internal state while exposing controlled getters and setters.
DART • ENCAPSULATION WITH GETTERS & SETTERSbank_account.dart
DART Script
DART 
class BankAccount {
  // Private field prefixed with underscore (_)
  double _balance;

  BankAccount(this._balance);

  // Public read access
  double get balance => _balance;

  // Public validated write access
  set deposit(double amount) {
    if (amount > 0) {
      _balance += amount;
    }
  }
}

void main() {
  BankAccount account = BankAccount(1000);

  // Controlled deposit
  account.deposit = 500;

  print(account.balance);
}
Expected Console Output 1500.0

18. Static Variables and Static Methods

When a piece of data or helper method belongs to the entire class rather than individual objects, we mark it with the static keyword. Only one shared copy exists across the entire program, and you access it directly using the class name (e.g., Student.college).

Figure 18.1: Static members reside at the class level and are shared among all instances.
DART • STATIC MEMBERSstatic_demo.dart
DART Script
DART 
class Student {
  // Static class-level variable
  static String college = 'BBD University';

  String name;

  Student(this.name);

  void showStudent() {
    print('$name studies at $college');
  }

  // Static utility method
  static void showCollege() {
    print(college);
  }
}

void main() {
  Student student1 = Student('Rahul');
  Student student2 = Student('Priya');

  student1.showStudent();
  student2.showStudent();

  // Access static members directly via the class name
  Student.showCollege();
}
Expected Console Output Rahul studies at BBD University
Priya studies at BBD University
BBD University
Important Rule: Static vs Instance Context

Static methods do NOT have access to this or individual instance fields because static methods execute at the class level without reference to any specific object instance.

19. Final Fields and Const Constructors

In modern Dart (and Flutter), creating immutable objects is standard practice for reliability and performance:

  • final fields: Can be set only once when initialized, preventing accidental mutations.
  • const constructors: Allow Dart to build canonical compile-time constants when supplied with constant arguments. All instance fields must be final.
Figure 19.1: Final instance variables enable rock-solid compile-time const constructors.
DART • FINAL & CONST CONSTRUCTORSimmutability_demo.dart
DART Script
DART 
class Student {
  final String name;
  final int rollNumber;

  Student(this.name, this.rollNumber);

  void showDetails() {
    print('$name - $rollNumber');
  }
}

class Point {
  final int x;
  final int y;

  // Const constructor requires all fields to be final
  const Point(this.x, this.y);
}

void main() {
  Student student = Student('Rahul', 101);
  student.showDetails();

  // Compile-time constant instance
  const point = Point(10, 20);
  print(point.x);
  print(point.y);
}
Expected Console Output Rahul - 101

20. Object Identity and Equality — Beginner Introduction

In Dart, the built-in identical(a, b) function checks identity: whether two variables point to the exact same address in memory. Even if two separately created objects have identical property values, they are two separate objects, so identical() evaluates to false.

Figure 20.1: Distinct memory allocations yield false for identical(), despite matching fields.
DART • OBJECT IDENTITYidentity_demo.dart
DART Script
DART 
class Student {
  String name;

  Student(this.name);
}

void main() {
  Student student1 = Student('Rahul');
  Student student2 = Student('Rahul');

  // Checks whether both variables reference the exact same memory address
  print(identical(student1, student2));
}
Expected Console Output false

22. Common Classes & Objects Mistakes

Watch out for these 16 frequent pitfalls when beginning with Dart OOP:

1. Confusing a Class with an Object

Why it fails: Calling instance methods or fields directly on the class blueprint without instantiating it with ().

✗ Bad: Car.start();  •  ✓ Good: Car myCar = Car(); myCar.start();

2. Writing a Return Type for a Constructor

Why it fails: Constructors must never declare a return type—not even void.

✗ Bad: void Student() {}  •  ✓ Good: Student() {}

3. Missing Initializing Formals or Null Safety Error

Why it fails: Declaring a non-nullable field without an initial value or constructor assignment.

✗ Bad: class S { String name; }  •  ✓ Good: class S { String name; S(this.name); }

4. Forgetting this When Shadowing Field Names

Why it fails: name = name; merely assigns a parameter to itself, leaving the instance field uninitialized.

✗ Bad: Student(String name) { name = name; }  •  ✓ Good: Student(this.name);

5. Calling a Getter with Parentheses

Why it fails: Getters represent property-like reads; calling them with () causes a compile-time error.

✗ Bad: print(rect.area());  •  ✓ Good: print(rect.area);

6. Giving a Return Type to a Setter

Why it fails: Dart setters cannot declare a return type.

✗ Bad: void set price(double p)  •  ✓ Good: set price(double p)

7. Accessing Instance Members Directly from a Static Method

Why it fails: Static methods execute without an object reference (no this pointer exists).

✗ Bad: static void test() { print(this.name); }  •  ✓ Good: Pass the object in or access only static fields.

8. Reassigning a final Field

Why it fails: Final variables are strictly write-once.

✗ Bad: final int roll; s.roll = 105;  •  ✓ Good: Set final fields only during object initialization.

9. Assuming identical() is True for Matching Values

Why it fails: identical() tests memory addresses, not structural value equality.

✗ Bad: Assuming identical(Student('A'), Student('A')) is true.

10. Expecting the Default Constructor After Declaring a Custom One

Why it fails: Writing Student(this.name); permanently removes the automatic Student() constructor unless you explicitly declare it.

24. Knowledge Check

Interactive Multiple Choice Questions

1. What is the fundamental difference between a Class and an Object?

A) A class is a blueprint; an object is a live instance allocated in memory.
B) An object is a blueprint; a class is an instance.
C) They are exact synonyms in Dart.
D) A class is a function; an object is an integer.

Correct Answer: A
Explanation: A class establishes the template (fields and methods). An object is the actual concrete instance created in RAM from that template.

2. What happens to Dart's implicit default constructor when you declare a custom constructor?

A) It remains available automatically.
B) It is removed; you must explicitly define an empty constructor if needed.
C) Dart raises a compile-time crash.
D) It converts into a static method.

Correct Answer: B
Explanation: Dart only provides an implicit no-argument constructor if NO other constructors are declared in the class.

3. How do callers read a getter defined as double get area => width * height;?

A) rect.area()
B) rect.area (without parentheses)
C) rect.getArea()
D) Rectangle.area

Correct Answer: B
Explanation: Getters in Dart are accessed using standard property syntax without parentheses.

4. Where do static variables and methods live?

A) Duplicated inside every individual object instance.
B) At the class level, accessed directly via ClassName.member.
C) Only inside the main() function.
D) Inside external packages.

Correct Answer: B
Explanation: Static members belong to the class itself. Only one single copy exists in memory, regardless of how many instances are created.

5. What does identical(s1, s2) evaluate to if s1 = Student('A'); and s2 = Student('A');?

A) true
B) false
C) null
D) Compile error

Correct Answer: B
Explanation: identical() tests memory addresses. Because s1 and s2 were instantiated separately, they occupy different memory addresses.
