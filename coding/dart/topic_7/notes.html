Loops & Iterations

Automate repetitive tasks in Dart with precision using for, while, do-while, for-in, forEach, and fine-tune execution flow with break and continue.

1. Introduction to Loops

In programming, a loop is a control flow structure that repeatedly executes a block of statements as long as a specified condition remains true. Each repetition of the loop is called an iteration.

Imagine sending 100 email notifications or printing numbers from 1 to 100. Writing 100 separate print() statements is exhausting, error-prone, and violates software engineering's golden rule: DRY (Don't Repeat Yourself). With a loop, you write the logic once and let Dart repeat it effortlessly.

Visual 1: Repeated Code vs The DRY Loop Pattern

The 4 Essential Components of Any Loop

Every standard loop consists of four key ingredients:

  1. Initialization: Sets up the starting state or counter variable before loop cycles begin (e.g., int i = 1;).
  2. Condition: A boolean test evaluated before or after each cycle. If true, the cycle runs; if false, the loop ends (e.g., i <= 5;).
  3. Body: The statements that do the real work during every iteration.
  4. Update (Step): Modifies the counter each turn (e.g., i++) so the condition will eventually evaluate to false, ensuring the loop safely terminates.

3. Understanding the while Loop

The while loop is a pre-tested loop. It evaluates its boolean condition before running the body. If the condition is true, the body runs; if false on the very first try, the body is skipped completely.

Use a while loop when you do not know the exact number of iterations in advance, but you know the condition that must stop it (e.g., waiting for user input, reading sensor packets, downloading a file).

Visual 3: while Loop Pre-Tested Decision Flow
example_while.dartPre-tested Loop
DART Script
DART 
void main() {
  int battery = 50;

  // Condition tested BEFORE entering each turn
  while (battery > 20) {
    print("Battery status: $battery% (Good)");
    battery -= 15; // Essential update to prevent infinite loops
  }

  print("Low battery alert: $battery% - Plug in charger!");
}
> Console Output
Battery status: 50% (Good)
Battery status: 35% (Good)
Low battery alert: 20% - Plug in charger!

4. Understanding the do-while Loop

The do-while loop is a post-tested loop. It executes the body first, and then evaluates the condition at the end.

Key Guarantee of do-while
The body of a do-while loop is guaranteed to execute at least once, even if the condition is completely false right from the start!
Visual 4: do-while Loop Post-Tested Flow
example_do_while.dartGuaranteed Run
DART Script
DART 
void main() {
  int attempt = 10;

  // Notice: attempt < 3 is FALSE initially, yet body still runs once!
  do {
    print("Inside do-while body! Current attempt: $attempt");
    attempt++;
  } while (attempt < 3);

  print("Finished loop with attempt = $attempt");
}
> Console Output
Inside do-while body! Current attempt: 10
Finished loop with attempt = 11

7. Understanding the forEach() Method

Dart collections provide a built-in higher-order method called .forEach(). It accepts an anonymous function (callback or lambda) and applies it to each element.

  List scores = [85, 92, 78];

  // Syntax 1: Using arrow lambda function
  scores.forEach((score) => print("Score: $score"));

  // Syntax 2: Using block callback
  scores.forEach((score) {
    int bonus = score + 5;
    print("With bonus: $bonus");
  });
}
> Console Output

Score: 92

Important forEach Limitation
You cannot use break or continue inside a forEach() lambda callback. If you need early termination or iteration skipping, always use a standard for-in loop or for loop instead.

8. Nested Loops

A nested loop is a loop placed completely inside the body of another loop.

  • Outer Loop: Controls the major iterations (e.g., rows, hours, or chapters).
  • Inner Loop: Runs completely from start to finish for each single turn of the outer loop (e.g., columns, minutes, or pages).
Visual 8: Nested Loop Dual-Axis Grid Matrix (Rows & Columns)

void main() {
  // Outer loop manages rows (1 to 2)
  for (int row = 1; row <= 2; row++) {
    // Inner loop manages columns (1 to 3)
    for (int col = 1; col <= 3; col++) {
      print("Cell [$row, $col]");
    }
  }
}

10. The continue Statement

While break cancels the entire loop permanently, continue only skips the remaining statements in the current iteration and jumps directly to the next turn (evaluating the loop update step in a for loop).

Visual 10: continue Statement Skip Iteration Flow
example_continue.dartSkipping Iterations
DART Script
DART 
void main() {
  // Print only even numbers by skipping odds
  for (int i = 1; i <= 6; i++) {
    if (i % 2 != 0) {
      continue; // Skips the print statement below for odd numbers
    }
    print("Processing even number: $i");
  }
}
> Console Output
Processing even number: 2
Processing even number: 4
Processing even number: 6

Side-by-Side: break vs continue

Feature break Statement continue Statement
Action Stops and terminates the entire loop forever Abandons only current turn; moves to next iteration
Subsequent Turns All future iterations are cancelled Future iterations execute normally

Primary Use Case Early exit upon finding a match or error condition Skipping invalid, blank, or unwanted elements

11. Infinite Loops — Causes, Dangers & Safety Fixes

An infinite loop occurs when a loop's condition never evaluates to false. As a result, the loop repeats endlessly, pegging the CPU at 100%, freezing the app, and ultimately causing the system or browser to become unresponsive.

Visual 11: Infinite Loop Danger vs Proper Safety Fix

3 Most Common Causes of Infinite Loops

  1. Missing Update: Forgetting to increment or decrement the variable inside a while or do-while block.
  2. Wrong Condition Direction: Writing for (int i = 0; i >= 0; i++) where i grows higher and stays non-negative forever.
  3. Intentional Server Loops Without Break: Using while (true) for listening to events but failing to provide a break condition when a shutdown or error flag is received.

12. Choosing the Right Loop

Use this quick decision guide whenever you are wondering which loop to reach for:

Visual 12: Loop Decision Tree & Selection Strategy
Loop Type Primary Characteristic When to Choose
for Index counter with built-in step expression When exact number of iterations is known before loop begins
while Condition tested prior to entering body When repetition depends on a boolean flag or dynamic state
do-while Condition tested after running body When the body must execute at least once (e.g., interactive menus)
for-in Clean collection traversal Traversing Lists, Sets, or Strings without manual index math
forEach Method taking an inline callback function Short functional operations where break is NOT needed

14. Common Beginner Mistakes (and How to Fix Them)

1. Off-by-One Boundary Errors (< vs <=)

Using <= list.length causes an IndexOutOfRangeException because valid List indices run from 0 to length - 1.

// BAD: Causes RangeError on last cycle
for (int i = 0; i <= list.length; i++) { ... }

// FIXED: Use < strictly
for (int i = 0; i < list.length; i++) { ... }
2. Forgetting to Increment Counter in a while Loop

Without advancing the counter variable, the condition remains true indefinitely, freezing your app.

// BAD: count never changes → Infinite Loop
while (count < 5) { print(count); }

// FIXED: Increment within loop body
while (count < 5) { print(count); count++; }
3. Accidental Semicolon After Loop Declaration

Putting a semicolon right after the parenthesis makes the loop execute an empty statement repeatedly!

// BAD: The semicolon terminates the loop prematurely
for (int i = 0; i < 5; i++);
{ print(i); } // Run only ONCE after loop finishes!

// FIXED: Never put semicolon directly after for(...) or while(...) header
for (int i = 0; i < 5; i++) { print(i); }
4. Modifying a List While Iterating with for-in

Adding or removing items from a collection during a for-in loop throws a ConcurrentModificationError.

// BAD: Throws ConcurrentModificationError
for (var item in list) { if (item == "remove") list.remove(item); }

// FIXED: Use list.removeWhere((item) => item == "remove");
5. Using break or continue Inside forEach()

Because forEach takes an independent callback function, break cannot cross function boundaries and results in a compilation error.

// BAD: Compile Error: 'break' cannot be used outside of a loop
list.forEach((item) { if (item == 2) break; });

// FIXED: Use a standard for-in loop if you need break
for (var item in list) { if (item == 2) break; }
6. Redeclaring Counter Variable Inside Loop Body

Declaring int i = 0; inside the loop body shadows or resets your tracking.

// BAD: Inner declaration causes confusion
for (int i = 0; i < 5; i++) { int i = 10; print(i); }

// FIXED: Rely on the loop header variable directly.
7. Wrong Comparison Operator Direction

Writing for (int i = 0; i > 5; i++) tests 0 > 5 immediately on step 1, which evaluates to false so the loop never runs even once!

// BAD: Condition false immediately
for (int i = 0; i > 5; i++) { print(i); }

// FIXED: Use correct inequality direction
for (int i = 0; i < 5; i++) { print(i); }
8. Accessing Loop Counter Outside Block Scope

A variable declared in for (int i = 0; ...) is scoped strictly to that loop block. Accessing i outside causes an undefined identifier error.

// BAD: 'i' is out of scope here
for (int i = 0; i < 5; i++) { }
print(i); // ERROR: Undefined name 'i'

// FIXED: Declare variable before loop if needed afterwards
int i; for (i = 0; i < 5; i++) { } print(i);
9. Assuming do-while Evaluates Condition First

Beginners often forget that do-while executes the body at least once before inspecting the condition.

int x = 100;
do { print("Runs!"); } while (x < 10); // Prints "Runs!" exactly once
10. Accumulating Strings Instead of Mathematical Numbers

Initializing a sum variable as empty string var sum = ""; causes string concatenation ("0123") instead of arithmetic addition.

// BAD: Produces "123"
var sum = ""; for (int i = 1; i <= 3; i++) { sum += "$i"; }

// FIXED: Use typed numeric accumulator
int sum = 0; for (int i = 1; i <= 3; i++) { sum += i; } // 6

15. Quick Revision Summary & Knowledge Check

Quick Revision Checklist
  • Loop: A block that repeats execution as long as a boolean condition remains true.
  • 4 Parts: Initialization, Condition test, Body, and Update step.
  • for Loop: Ideal when the iteration count is known in advance (definite loop).
  • while Loop: Pre-tested loop; body runs 0 or more times based on entry condition.
  • do-while Loop: Post-tested loop; body is guaranteed to run at least once.
  • for-in Loop: Cleanest way to traverse lists, sets, and iterables without index bugs.
  • forEach() Method: Callback-based iteration; cannot utilize break or continue.
  • break: Immediately exits the enclosing loop entirely.
  • continue: Immediately abandons current turn and proceeds to the next iteration.
  • Infinite Loops: Happen when condition never turns false; always verify your update step!

1. What is the minimum number of times a while loop can execute its body?
A) 0 times (if condition is initially false)
B) 1 time
C) 2 times
D) Infinite times
View Correct Answer & Explanation
Correct Answer: A
Because a while loop checks its condition before running the body (pre-tested), if the condition evaluates to false at the start, the body never executes (0 times).
2. Which loop guarantees that its body will run at least once?
A) for loop
B) while loop
C) do-while loop
D) for-in loop
View Correct Answer & Explanation
Correct Answer: C
A do-while loop tests its condition at the bottom after executing the body, guaranteeing at least one run.
3. What is the difference between break and continue?
A) break exits the entire loop; continue skips only the current iteration
B) break pauses for 1 second; continue runs faster
C) They are identical synonyms in Dart
D) break is only for switch statements, not loops
View Correct Answer & Explanation
Correct Answer: A
break terminates loop execution completely. continue immediately skips the remaining lines in the current iteration and begins the next iteration.
4. Why does writing break; inside a list's .forEach() callback cause a compile error?
A) forEach() takes a separate function callback, and control statements cannot cross function boundaries
B) Dart does not support lists
C) forEach() only works with strings
D) Dart has deprecated break
View Correct Answer & Explanation
Correct Answer: A
The lambda supplied to .forEach() is an independent closure function. break and continue cannot jump outside function scopes. Use a for-in loop if you need early exit.
5. In a nested loop where the outer loop iterates 3 times and the inner loop iterates 4 times, how many total times does the inner loop body run?
A) 12 times (3 x 4)
B) 7 times (3 + 4)
C) 4 times
D) 3 times
View Correct Answer & Explanation
Correct Answer: A
The inner loop runs completely (4 times) for every single iteration of the outer loop. Thus, 3 × 4 = 12 total executions.
