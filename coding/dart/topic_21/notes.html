Topic 21: Futures, async/await & Streams

Master non-blocking I/O, delayed computations, concurrent operations, and continuous real-time event streams in Dart.

1. Introduction to Asynchronous Programming

By default, computer programs execute synchronously: line 1 runs, then line 2, then line 3. If a task takes several seconds (such as downloading a large image or waiting for a server response), a synchronous program freezes completely, locking the user interface.

Asynchronous programming solves this by allowing long-running operations to happen in the background without blocking the surrounding code.

Restaurant Analogy:

  • Synchronous (Blocking): You order food at the counter and stand there frozen. Nobody behind you can order, and you cannot check your phone until the food is handed to you.
  • Asynchronous (Non-Blocking): You order food, receive a buzzer token, and sit at your table reading a book or chatting. When the food is ready, the token buzzes and you collect it.
Figure 21.1: Restaurant buzzer token analogy for non-blocking asynchronous programming.
Core Insight: Event Loop Architecture
Dart is single-threaded by default. Asynchronous code does not create multiple operating system threads; instead, Dart uses an Event Loop that schedules and processes tasks as results arrive.

3. What Is a Future?

A Future<T> represents the eventual result of an asynchronous operation. When you initiate an asynchronous task, Dart immediately returns an uncompleted Future object — like a parcel tracking number. It promises that at some point, it will produce a value of type T or an error.

Figure 21.3: The life cycle of a Future: Creation, background waiting, and then() fulfillment.
future_basic.dartDart 3.x
DART Script
DART 
Future getMessage() {
  return Future.delayed(
    Duration(milliseconds: 50),
    () => 'Hello from Future',
  );
}

void main() {
  getMessage().then((message) {
    print(message);
  });
}
Terminal Output Hello from Future

4. Future States

A Future exists in one of three conceptual states during its lifecycle:

  1. Uncompleted (Pending): The operation is underway in the background.
  2. Completed with Data: The operation succeeded, producing a concrete value.
  3. Completed with Error: The operation failed, producing an exception.
Figure 21.4: State transition graph: Pending transitions strictly once to either Value or Error.

6. Working with `then()`

The then() method registers a callback to be called when the Future completes successfully with a value. You can chain multiple then() calls sequentially:

Figure 21.6: Pipelining transformations by chaining then() callbacks.
then_chain.dartDart 3.x
DART Script
DART 
Future getNumber() => Future.value(10);

void main() {
  getNumber()
      .then((value) {
        print(value);
        return value * 2;
      })
      .then((result) {
        print(result);
      });
}
Terminal Output 10 20

7. Error Handling with `catchError()`

When working with Future callbacks, catchError() catches any error or unhandled exception emitted anywhere in the preceding Future chain.

Figure 21.7: Error propagation in Future chains intercepted by catchError().
catch_error.dartDart 3.x
DART Script
DART 
Future getNumber() {
  return Future.error(Exception('Something went wrong'));
}

void main() {
  getNumber()
      .then((value) => print(value))
      .catchError((error) => print('Error: $error'));
}
Terminal Output Error: Exception: Something went wrong

8. Using `whenComplete()`

Similar to the synchronous finally block, whenComplete() registers a callback that always executes when a Future finishes — regardless of whether it completed with a successful value or failed with an error.

Figure 21.8: whenComplete() executes upon both fulfillment and rejection.
when_complete.dartDart 3.x
DART Script
DART 
Future loadData() async {
  await Future.delayed(Duration(milliseconds: 20));
  print('Data loaded');
}

void main() {
  loadData().whenComplete(() {
    print('Operation finished');
  });
}
Terminal Output Data loaded Operation finished

9. Introduction to `async`

Marking a function with the async keyword accomplishes two things automatically:

  • Enables the use of the await keyword inside its body.
  • Automatically wraps the returned value in a Future. For example, returning a plain String from an async function yields a Future<String>.
Figure 21.9: Dart automatically encapsulates async return values inside a Future.
async_intro.dartDart 3.x
DART Script
DART 
Future getName() async {
  return 'Shailendra'; // Plain string wrapped in Future
}

void main() {
  getName().then((name) => print(name));
}
Terminal Output Shailendra

10. Introduction to `await`

The await keyword temporarily suspends execution of the current async function until the awaited Future completes. It extracts the raw underlying value cleanly without cumbersome callback nesting.

Figure 21.10: The pause-and-resume behavior of await: non-blocking function suspension.
await_demo.dartDart 3.x
DART Script
DART 
Future fetchData() async {
  await Future.delayed(Duration(milliseconds: 30));
  return 'Data received';
}

Future main() async {
  print('Request started');
  String result = await fetchData();
  print(result);
  print('Request completed');
}
Terminal Output Request started Data received Request completed

11. Difference Between `then()` and `async/await`

Both styles perform identical work under the hood. However, async/await is widely favored because it reads sequentially like synchronous code, eliminating "callback hell".

Figure 21.11: Comparison of callback chaining vs linear async/await syntax.

12. Error Handling with `async/await`

With async/await, you don't need catchError() callbacks. You can use standard try-catch-finally blocks directly around your awaited calls:

Figure 21.12: Asynchronous exception handling using standard try-catch-finally syntax.
async_try_catch.dartDart 3.x
DART Script
DART 
Future fetchData() async {
  throw Exception('Unable to fetch data');
}

Future main() async {
  try {
    String data = await fetchData();
    print(data);
  } catch (e) {
    print('Error: $e');
  } finally {
    print('Request finished');
  }
}
Terminal Output Error: Exception: Unable to fetch data Request finished

13. Future.delayed() and Duration

Future.delayed(Duration, computation) creates a Future that completes after the specified time interval. It is used for debouncing, timers, polling, and animations.

Figure 21.13: Non-blocking time delay scheduling via Duration.

14. Running Multiple Futures with Future.wait()

When you have independent asynchronous tasks (e.g. loading user profile AND loading product catalog), running them sequentially doubles total waiting time. Future.wait() runs multiple Futures concurrently and yields an aggregate List of results when all have completed.

Figure 21.14: Concurrent execution and input-order preservation with Future.wait().
future_wait.dartDart 3.x
DART Script
DART 
Future getUser() async {
  await Future.delayed(Duration(milliseconds: 30));
  return 'User loaded';
}

Future getPosts() async {
  await Future.delayed(Duration(milliseconds: 20));
  return 'Posts loaded';
}

Future main() async {
  List results = await Future.wait([getUser(), getPosts()]);
  print(results);
}
Terminal Output [User loaded, Posts loaded]

15. Sequential vs Concurrent Futures

Choose between sequential awaiting and concurrent execution based on dependencies:

  • Sequential: Task B requires the output of Task A (e.g. login first, then fetch user profile using the auth token).
  • Concurrent: Tasks are completely independent (e.g. fetching weather data and stock prices).
Figure 21.15: Wall-clock efficiency comparison between sequential and concurrent execution.

16. Introduction to Streams

While a Future delivers one single result and terminates, a Stream delivers a continuous sequence of asynchronous events over time. A Stream can emit multiple data events, report errors, and notify subscribers when completed.

Cricket Live Score Analogy:

  • Future: Like querying the final match result after the game finishes (one single answer: "India won by 4 wickets").
  • Stream: Like listening to ball-by-ball live updates (Over 1, Four!, Wicket, Fifty runs, Match Finished).
Figure 21.16: A Stream emitting multiple sequential data events before final completion.

19. Listening to Streams with `listen()`

The listen() method subscribes to a stream and accepts handlers for data, errors, and completion. It returns a StreamSubscription object, which can be paused, resumed, or cancelled.

Figure 21.19: Anatomy of stream subscription callbacks and subscription handle.
stream_listen.dartDart 3.x
DART Script
DART 
void main() {
  Stream numbers = Stream.fromIterable([1, 2, 3]);
  numbers.listen(
    (value) => print('Value: $value'),
    onDone: () => print('Stream completed'),
  );
}
Terminal Output Value: 1 Value: 2 Value: 3 Stream completed

22. StreamController (Producer & Consumer Pipeline)

A StreamController gives you full manual control over a stream. It provides a sink (where producers add values or errors) and a stream (where listeners receive updates).

Figure 21.22: Producer to Consumer pipeline via StreamController sink and stream.
stream_controller.dartDart 3.x
DART Script
DART 
import 'dart:async';

Future main() async {
  final controller = StreamController();

  final subscription = controller.stream.listen((value) {
    print('Received: $value');
  });

  controller.add(10);
  controller.add(20);
  controller.add(30);

  await controller.close();
  await subscription.cancel();
}
Terminal Output Received: 10 Received: 20 Received: 30

23. Single-Subscription vs Broadcast Streams

By default, a Stream allows only one listener. Attempting to attach a second listener throws a StateError. If multiple components in your app need to listen to the same stream (e.g. chat messages or notifications), create a Broadcast Stream using StreamController.broadcast().

Figure 21.23: Single listener constraint vs multi-subscriber broadcast distribution.

24. Stream Transformations

Streams provide powerful functional transformations similar to Iterable collections:

  • map(): Transforms every incoming event.
  • where(): Discards events that fail a boolean condition.
  • take(n): Receives only the first n events and completes.
  • skip(n): Ignores the first n events.
  • distinct(): Suppresses consecutive duplicate events.
Figure 21.24: Chaining stream operations to filter and transform real-time events.
stream_transforms.dartDart 3.x
DART Script
DART 
Future main() async {
  Stream numbers = Stream.fromIterable([1, 2, 3, 4, 5]);

  await for (int number in numbers
      .where((n) => n.isEven)
      .map((n) => n * 10)) {
    print(number);
  }
}
Terminal Output 20 40

27. Common Mistakes & Anti-Patterns

Figure 21.27: Avoiding common traps in asynchronous Dart programming.
  • Forgetting to await: Accessing profile.name directly on an unawaited Future<Profile> results in a compile error.
  • Thinking await blocks the app: await only suspends the current async function; the main event loop remains responsive.
  • Uncancelled Subscriptions: Forgetting to cancel stream subscriptions leads to memory leaks. Always call subscription.cancel() when done.
  • Adding to a Closed StreamController: Calling controller.add() after controller.close() throws a StateError.

Challenge 1: Future Delay and Non-Blocking Flow
DART Script

Explanation: 'A' prints synchronously. Future.delayed is scheduled on the event loop without an await. 'C' executes synchronously before the delayed timer fires 'B'.
Challenge 2: Async Try-Catch with Finally
DART Script
DART 
Future main() async {
  try {
    print('1');
    await Future.error(Exception('Failed'));
    print('2');
  } catch (e) {
    print('Caught');
  } finally {
    print('Finished');
  }
}
View Output & Explanation
Output: 1 then Caught then Finished
Explanation: '1' prints. The awaited error immediately jumps to catch, skipping '2'. The finally block executes reliably last.
