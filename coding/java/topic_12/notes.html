SECTION 01

1. What Is Inheritance?

In the physical world, inheritance describes how biological traits and assets pass from parents to children. A child inherits core human characteristics (like eye color or height), but also develops their own unique skills, personality, and talents.

In Java, inheritance is an object-oriented mechanism where a new class (called a subclass or child class) automatically acquires the accessible fields and methods of an existing class (called a superclass or parent class), while having the freedom to add specialized fields, declare new methods, or customize existing behavior.

💡 Core Definitions

Superclass (Parent / Base Class): The existing class whose properties and behaviors are inherited.

Subclass (Child / Derived Class): The new class that inherits from the superclass and adds specialized features.

Inheritance: The mechanism that models an "IS-A" relationship between classes (e.g., a Car IS A Vehicle, a Dog IS AN Animal).

Figure 1.1: Real-life vehicle hierarchy: Common behavior (start, stop) lives in the Vehicle superclass; Car and Motorcycle inherit this and add specialized features.

Important Myth to Avoid

Inheritance does not physically copy-paste the source code of the parent class into the child class's .java file. Instead, the Java compiler and JVM establish a logical parent-child relationship in bytecode and memory, allowing the child class to delegate calls to the parent's implementation.

SECTION 02

2. Why Do We Need Inheritance?

Without inheritance, software systems suffer from massive code duplication. Imagine building a transportation application with 20 different vehicle types (Car, Truck, Bus, Motorcycle, Van, ElectricScooter). Every single vehicle needs an engine ignition routine (start()), a braking system (stop()), and fuel level tracking (fuelLevel).

Figure 2.1: Before-and-after code duplication: Without inheritance, identical logic is copy-pasted across classes; with inheritance, shared behavior is declared once in the parent.

The 3 Key Benefits of Inheritance

  1. Code Reusability: Write common algorithms and fields once in the superclass. All subclasses immediately inherit them without rewriting a single line of code.
  2. Single Point of Maintenance: If you find a bug in start(), you fix it in one place (the parent class), and every child class instantly benefits from the fix.
  3. Polymorphic Extensibility: You can write general-purpose code that operates on the parent type (e.g. Vehicle[] fleet), and Java will seamlessly handle any existing or future subclass.
SECTION 03

3. Parent Class, Child Class, and the extends Keyword

In Java, inheritance is established using the extends keyword in the child class header declaration:

public class ChildClass extends ParentClass {
    // Child class body inherits accessible ParentClass members!
}
Figure 3.1: The extends relationship: The arrow points upward from the child (Dog) to the parent (Animal), denoting that Dog derives from Animal.

A Simple Animal and Dog Example

Let us write a complete, runnable Java program illustrating basic class extension:

AnimalApp.java 
// 1. Superclass (Parent)
class Animal {
    String name = "Generic Animal";

    void eat() {
        System.out.println("Animal is eating food.");
    }
}

// 2. Subclass (Child) using extends
class Dog extends Animal {
    void bark() {
        System.out.println("Dog is barking: Woof! Woof!");
    }
}

public class AnimalApp {
    public static void main(String[] args) {
        // Instantiate the child class
        Dog dog = new Dog();

        // Calling inherited method from Animal superclass
        dog.eat();

        // Calling specialized method declared in Dog subclass
        dog.bark();
    }
}
🖥 Console Output
Animal is eating food. Dog is barking: Woof! Woof!

Code Execution Trace: When dog.eat() is invoked, the Java compiler looks inside the Dog class. Because eat() is not defined in Dog, the compiler searches up the inheritance chain to Animal, finds the accessible eat() method, and executes it seamlessly!

SECTION 04

4. What Does a Child Class Inherit? (Access Modifier Rules)

A frequent point of confusion for beginners is assuming that a subclass inherits every single line of the parent class. In truth, inheritance is strictly governed by Java's access modifiers:

Figure 4.1: Member accessibility in subclasses: Public and protected members are accessible; package-private depends on package location; private is NEVER directly accessible.

Member Accessibility Summary

  • public: Inherited and directly accessible everywhere (same package or different package).
  • protected: Inherited and directly accessible to subclasses, even across package boundaries!
  • package-private (no modifier): Inherited and accessible only if the subclass resides in the exact same package.
  • private: NOT directly accessible by name in the subclass! (However, private fields still physically exist inside the parent portion of the object in memory and can be manipulated via inherited public/protected getters and setters).

Person and Student Example

PersonAccessDemo.java 
class Person {
    public String name = "Aman";
    protected int age = 20;
    private String password = "SecretPassword123";

    public String getPassword() {
        return password; // Public accessor allows controlled reading
    }
}

class Student extends Person {
    void showDetails() {
        System.out.println("Name: " + name); // Legal: public
        System.out.println("Age:  " + age);  // Legal: protected
        
        // System.out.println(password); // COMPILE ERROR: password has private access in Person!
        System.out.println("Password via getter: " + getPassword()); // Legal: public getter
    }
}
SECTION 05

5. Adding Fields and Methods in a Child Class

Subclasses are not limited to passive consumption of parent features. Their primary purpose is specialization: introducing fields and behaviors unique to the child domain.

Figure 5.1: Subclass Object Internal Anatomy: A Car instance in heap memory holds both the inherited Vehicle slice and its own specialized Car slice.
CarSpecializationDemo.java 
class Vehicle {
    String brand = "Toyota";

    void start() {
        System.out.println("Vehicle started.");
    }
}

class Car extends Vehicle {
    int doors = 4; // NEW specialized field

    // NEW specialized method
    void showCar() {
        System.out.println("Brand: " + brand); // Inherited from Vehicle
        System.out.println("Doors: " + doors); // Defined in Car
    }
}

public class CarSpecializationDemo {
    public static void main(String[] args) {
        Car car = new Car();
        car.start();   // Inherited method
        car.showCar(); // Specialized method
    }
}
🖥 Console Output
Vehicle started. Brand: Toyota Doors: 4
SECTION 06

6. Types of Inheritance Supported by Java Classes

Object-oriented design permits multiple topological arrangements of parent and child classes. However, Java strictly enforces rules on which patterns are permitted for classes vs. interfaces:

Figure 6.1: Single Inheritance: One child class directly extends exactly one parent class.
Figure 6.2: Multilevel Inheritance: A class extends a parent class that itself extends an ancestor class (inheritance chain).
Figure 6.3: Hierarchical Inheritance: Multiple distinct child classes directly extend the same common parent superclass.

Why Java Forbids Multiple Inheritance with Classes (The Diamond Problem)

In languages like C++, a class can extend two or more classes simultaneously (e.g., class Child extends Father, Mother). Java intentionally disallows multiple inheritance for classes to prevent deadly ambiguities known as the Diamond Problem.

Figure 6.4: The Diamond Problem: If Father and Mother both declare show(), which method should Child inherit? Java prevents this ambiguity by rejecting multiple class extends.

Multiple Inheritance of Type Through Interfaces

While a Java class cannot extend multiple classes, a class can implement multiple interfaces! Because traditional interfaces only declared abstract method signatures without concrete instance variables, there was no risk of state collision.

Figure 6.5: Multiple Inheritance of Type: A single Java class (Duck) can implement multiple interfaces (Swimmer, Flyer) safely.
Figure 6.6: Extends vs. Implements: Class inheritance provides code reuse and state sharing (limited to 1 parent); interface implementation provides capability contracts (unlimited).
SECTION 07

7. Method Overriding

Inheriting a method from a parent class does not mean you are permanently stuck with the parent's generic implementation. Method overriding occurs when a subclass defines an instance method that has the exact same method name, exact same parameter list, and a compatible return type as an inherited method in the superclass.

Figure 7.1: Method Overriding: The child class Dog overrides Animal's generic sound() with a dog-specific bark implementation.

The @Override Annotation

Always place the @Override annotation immediately above an overriding method. While technically optional, @Override instructs the Java compiler to verify that you are genuinely overriding an existing superclass method. If you make a typo (e.g., naming it sund() instead of sound()), the compiler will immediately raise an error, saving you hours of frustrating debugging!

OverridingDemo.java 
class Animal {
    void sound() {
        System.out.println("Animal makes a generic sound.");
    }
}

class Dog extends Animal {
    // Overriding the parent's sound() method
    @Override
    void sound() {
        System.out.println("Dog barks: Woof! Woof!");
    }
}

public class OverridingDemo {
    public static void main(String[] args) {
        Dog dog = new Dog();
        dog.sound(); // Executes Dog's overridden version!
    }
}
🖥 Console Output
Dog barks: Woof! Woof!
💡 4 Strict Rules for Method Overriding in Java
  1. Same Signature: Name and parameter types must match identically.
  2. Visibility Cannot Be Reduced: If the parent method is public, the overriding child method cannot be made protected or private. (It can only be equal or more accessible).
  3. Constructors Cannot Be Overridden: Constructors belong exclusively to their own declaring class.
  4. Static Methods Cannot Be Overridden: Static methods are bound at compile-time to the class type; if redeclared in a subclass, they are hidden, not overridden.
SECTION 08

8. Runtime Polymorphism & Dynamic Method Dispatch

Now we reach one of the crowning achievements of Object-Oriented Programming: Runtime Polymorphism (also known as Dynamic Method Dispatch).

In Java, a superclass reference variable can point to a subclass object:

Animal a = new Dog(); // Superclass reference pointing to Subclass object!
Figure 8.1: Dynamic Method Dispatch: The reference variable 'a' on the stack has type Animal, but points to a Dog object on the heap. When a.sound() is called, Dog's method runs!
Figure 8.2: Polymorphism resolution pipeline: At runtime, the JVM inspects the actual heap object to resolve the overridden method implementation.

Complete Polymorphism Demonstration

PolymorphismDemo.java 
class Animal {
    void sound() { System.out.println("Animal sound"); }
}

class Dog extends Animal {
    @Override
    void sound() { System.out.println("Dog barks"); }
}

class Cat extends Animal {
    @Override
    void sound() { System.out.println("Cat meows"); }
}

public class PolymorphismDemo {
    public static void main(String[] args) {
        // Parent-type reference holding child-type objects
        Animal a1 = new Dog();
        Animal a2 = new Cat();

        a1.sound(); // Dispatches to Dog.sound() at runtime!
        a2.sound(); // Dispatches to Cat.sound() at runtime!
    }
}
🖥 Console Output
Dog barks Cat meows
⚠ Critical Rule: Fields Do NOT Exhibit Polymorphism!

Dynamic method dispatch applies only to instance methods. In Java, variable fields are resolved at compile-time according to the reference type, not the runtime object type! If both parent and child declare int x, a1.x will access the parent's field.

SECTION 09

9. Constructors in Inheritance: The Execution Sequence

When you create an instance of a child class with new Child(), what actually happens inside the computer? Does the child constructor execute first, or does the parent constructor execute first?

Figure 9.1: Constructor execution sequence: The superclass constructor ALWAYS executes before the child constructor body begins.

Why Does the Parent Constructor Run First?

Think about building a house: you cannot frame the roof before pouring the concrete foundation! Because a child class inherits fields and state from its parent, the parent class must initialize its foundation data first. Otherwise, if the child constructor attempted to read an inherited variable, that variable would be uninitialized junk data!

ConstructorOrderDemo.java 
class Animal {
    Animal() {
        System.out.println("1. Animal (Superclass) constructor executes.");
    }
}

class Dog extends Animal {
    Dog() {
        // Java automatically inserts invisible super(); right here!
        System.out.println("2. Dog (Subclass) constructor executes.");
    }
}

public class ConstructorOrderDemo {
    public static void main(String[] args) {
        System.out.println("Creating a Dog instance...");
        Dog d = new Dog();
    }
}
🖥 Console Output
Creating a Dog instance... 1. Animal (Superclass) constructor executes. 2. Dog (Subclass) constructor executes.
SECTION 10

10. The super() Constructor Call (Parameterized Initialization)

If a parent class has a constructor with arguments (and no default no-arg constructor), the child class must explicitly call super(arguments) as the first statement in its constructor.

Figure 10.1: Passing parameters up the inheritance chain: Student receives (name, roll), passes name to super(name), and assigns roll locally.
StudentInheritanceApp.java 
class Person {
    String name;

    // Parameterized constructor in parent
    Person(String name) {
        this.name = name;
        System.out.println("Person initialized with name: " + name);
    }
}

class Student extends Person {
    int rollNumber;

    Student(String name, int rollNumber) {
        super(name); // MUST be first statement! Delegates name to Person
        this.rollNumber = rollNumber;
        System.out.println("Student initialized with rollNumber: " + rollNumber);
    }
}

public class StudentInheritanceApp {
    public static void main(String[] args) {
        Student s = new Student("Aman Sharma", 101);
        System.out.println("\nVerified Record:");
        System.out.println("Name: " + s.name + " | Roll: " + s.rollNumber);
    }
}
🖥 Console Output
Person initialized with name: Aman Sharma Student initialized with rollNumber: 101 Verified Record: Name: Aman Sharma | Roll: 101
SECTION 11

11. The super Keyword for Calling Parent Methods

When you override a method in a child class, the child's implementation completely replaces the parent's version during normal calls. But what if you want to reuse the parent's existing work and simply append extra functionality?

You can use super.methodName() to directly invoke the superclass's version from inside the child class:

Figure 11.1: Invoking parent implementation: super.sound() executes the original Animal code before Dog continues with its own output.
SuperMethodDemo.java 
class Animal {
    void sound() {
        System.out.println("Animal makes a generic sound.");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        super.sound(); // 1. Run the parent class logic
        System.out.println("Dog adds barking: Woof! Woof!"); // 2. Add child logic
    }
}

public class SuperMethodDemo {
    public static void main(String[] args) {
        Dog dog = new Dog();
        dog.sound();
    }
}
🖥 Console Output
Animal makes a generic sound. Dog adds barking: Woof! Woof!
SECTION 12

12. The final Keyword and Inheritance Restrictions

Java allows developers to selectively restrict or disable inheritance when building mission-critical security components or immutable classes:

Figure 12.1: The final keyword acts as an inheritance lock: Final classes cannot be subclassed; final methods cannot be overridden.

1. Final Classes

Marking a class final prevents any other class from extending it. Java's built-in java.lang.String is declared public final class String for immutability and security.

final class SecurityKey {}
// class CustomKey extends SecurityKey {} // COMPILE ERROR: cannot inherit from final SecurityKey

2. Final Methods

Marking an instance method final permits subclasses to inherit it, but strictly forbids them from overriding it.

class BankTransaction {
    final void auditLog() { System.out.println("Logging encrypted audit trail."); }
}
class WireTransfer extends BankTransaction {
    // void auditLog() {} // COMPILE ERROR: overridden method is final
}
SECTION 13

13. Inheritance vs. Composition ("IS-A" vs. "HAS-A")

As you design software, one of the most critical architectural decisions is choosing between inheritance and composition. Beginners often overuse inheritance simply to reuse a few lines of code, leading to brittle, inflexible hierarchies.

Figure 13.1: Inheritance ("IS-A") tightly couples parent and child; Composition ("HAS-A") loosely holds references to independent components.

The Golden Rule of OOP Design

💡 Effective Java Tip: "Favor Composition Over Inheritance"

Ask yourself two questions:

  1. Is Class B genuinely a specialized sub-type of Class A? (e.g., A Dog IS AN Animal → Use Inheritance).
  2. Or does Class B merely contain or use Class A as a part? (e.g., A Car HAS AN Engine → Use Composition!). A Car is not an engine; making Car extends Engine is terrible design.
CompositionDemo.java 
// 1. Independent component
class Engine {
    void ignite() { System.out.println("V8 Engine roaring to life!"); }
}

// 2. Class using composition ("HAS-A")
class Car {
    private Engine engine; // Car HAS AN Engine

    public Car() {
        this.engine = new Engine();
    }

    public void startCar() {
        engine.ignite();
        System.out.println("Car is moving smoothly.");
    }
}

14. Common Inheritance Mistakes & Debugging Guide

Study these 17 frequent pitfalls to spot, diagnose, and resolve inheritance compilation and logic errors instantly:

Figure 14.1: Inheritance debugging triage: recognizing compiler error signatures for private member access, superclass constructor missing, and illegal multiple extends.
✗ Mistake 1: Forgetting the 'extends' Keyword
class Dog Animal {} // Syntax error!

Cause: In Java, inheritance must be declared with extends.

✓ Proper Keyword Usage
class Dog extends Animal {}

Fix: Insert extends between child and parent.

✗ Mistake 2: Extending Multiple Classes
class Child extends Father, Mother {}

Cause: Java classes do not support multiple inheritance.

✓ Single Extension or Interfaces
class Child extends Father implements MotherInterface

Fix: Extend 1 class, implement interfaces.

✗ Mistake 3: Direct Access to Private Superclass Field
class P { private int x; }
class C extends P { void m() { x = 10; } }

Cause: x has private access in P.

✓ Access via Public / Protected Method
class P { protected int x; } // or public setX()

Fix: Use protected or a public setter.

✗ Mistake 4: Missing Superclass Constructor Call
class P { P(int x) {} }
class C extends P { C() {} } // Error!

Cause: P has no default no-arg constructor.

✓ Explicit super(val) Call
class C extends P { C() { super(10); } }

Fix: Explicitly invoke super(argument) as first line.

✗ Mistake 5: super() Not the First Statement
Child() {
    int a = 5;
    super(); // COMPILE ERROR!
}

Cause: Constructor call must be first statement in constructor.

✓ Place super() at Very Top
Child() {
    super(); // First statement!
    int a = 5;
}

Fix: Put super(...) on line 1 of constructor.

✗ Mistake 6: Mismatched Overriding Signature
class P { void sound(int volume) {} }
class C extends P {
    @Override void sound() {} // Error!
}

Cause: Missing parameter makes it an overload, not an override.

✓ Match Parameters Exactly
@Override void sound(int volume) {}

Fix: Keep method parameters identical.

✗ Mistake 7: Reducing Overridden Method Visibility
class P { public void run() {} }
class C extends P {
    void run() {} // Error: cannot reduce visibility
}

Cause: Overriding method cannot reduce access from public.

✓ Maintain Equal or Broader Visibility
public void run() {}

Fix: Keep public on overriding method.

✗ Mistake 8: Extending a Final Class
final class Base {}
class Sub extends Base {} // Compile error!

Cause: cannot inherit from final Base.

✓ Remove Final or Use Composition
class Sub { private Base base; }

Fix: Wrap final class using composition.

✗ Mistake 9: Overriding a Final Method
class P { final void log() {} }
class C extends P { void log() {} } // Error!

Cause: overridden method is final.

✓ Create New Distinct Method
void customLog() { ... }

Fix: Do not override methods locked as final.

✗ Mistake 10: Assuming Fields Exhibit Polymorphism
Animal a = new Dog();
System.out.println(a.name); // Prints Animal's name!

Cause: Fields are resolved by reference type at compile-time.

✓ Use Overridden Methods for Polymorphism
System.out.println(a.getName()); // Dynamic dispatch!

Fix: Access fields via overridden getter methods.

✗ Mistake 11: Confusing super() with super.method()
void test() { super(); } // Compile error!

Cause: super() is only valid inside constructors.

✓ Use super.method() in Regular Methods
void test() { super.test(); }

Fix: Use super.methodName() to call parent methods.

✗ Mistake 12: Assuming Static Methods are Overridden
Animal a = new Dog();
a.staticGreet(); // Calls Animal.staticGreet()!

Cause: Static methods are hidden, not dynamically dispatched.

✓ Call Static Methods via Class Name
Dog.staticGreet(); Animal.staticGreet();

Fix: Invoke static methods directly on the class name.

✗ Mistake 13: Using @Override on Non-Overridden Method
@Override void uniqueDogMethod() {} // Error!

Cause: Parent class does not declare this method.

✓ Remove @Override on New Methods
void uniqueDogMethod() {}

Fix: Use @Override only when matching parent signature.

✗ Mistake 14: Inheritance Without "IS-A" (Flawed Hierarchy)
class Car extends Engine {} // Antipattern!

Cause: A Car is NOT an Engine; violates conceptual integrity.

✓ Use Composition for "HAS-A"
class Car { private Engine engine; }

Fix: Hold an instance of the component.

✗ Mistake 15: Assuming Constructors are Inherited
Dog d = new Dog("Tommy"); // Error if Dog() has no string constructor!

Cause: Child does not automatically inherit parent's constructors.

✓ Declare Matching Constructor in Child
Dog(String n) { super(n); }

Fix: Explicitly declare the constructor in the child class.

✗ Mistake 16: Thinking Child Constructor Runs First
// Assuming child initializers run before super()

Cause: Java requires parent initialization before child.

✓ Understand True Execution Sequence
// 1. Parent constructor runs
// 2. Child constructor body executes

Fix: Always design child initializers aware of parent state.

✗ Mistake 17: Infinite Recursion with super.method()
void sound() {
    sound(); // Calls itself recursively! StackOverflow!
}

Cause: Forgetting the super. prefix calls the child method itself.

✓ Qualify with super.
void sound() {
    super.sound(); // Calls parent cleanly!
}

Fix: Prefix call with super. to reach parent implementation.

15. Real-World Mini Project: Polymorphic Vehicle Fleet

Let us integrate everything into an educational, self-contained vehicle fleet management application demonstrating inheritance, method overriding, and runtime polymorphism:

Figure 15.1: Mini Project Architecture: Base class Vehicle defines the fleet contract; Car and Bike specialize state and override displayType().

Project Requirements

  1. Base Class (Vehicle): Common brand field, constructor, start() method, and generic displayType() method.
  2. Subclass 1 (Car): Extends Vehicle, adds doors field, calls super(brand), overrides displayType(), adds openTrunk().
  3. Subclass 2 (Bike): Extends Vehicle, adds hasKickstand boolean, calls super(brand), overrides displayType().
  4. Fleet Runner: An array of Vehicle[] demonstrating runtime polymorphic dispatch across diverse vehicle types!
VehicleFleetApp.java 
public class VehicleFleetApp {

    // 1. Superclass
    static class Vehicle {
        protected String brand;

        public Vehicle(String brand) {
            this.brand = brand;
        }

        public void start() {
            System.out.println(brand + " ignition: Engine running.");
        }

        public String displayType() {
            return "Generic Vehicle (" + brand + ")";
        }
    }

    // 2. Car Subclass
    static class Car extends Vehicle {
        private int doors;

        public Car(String brand, int doors) {
            super(brand); // Invoke Vehicle constructor
            this.doors = doors;
        }

        public void openTrunk() {
            System.out.println("Opening trunk of " + brand + " (" + doors + " doors).");
        }

        @Override
        public String displayType() {
            return "Car: " + brand + " with " + doors + " doors";
        }
    }

    // 3. Bike Subclass
    static class Bike extends Vehicle {
        private boolean hasKickstand;

        public Bike(String brand, boolean hasKickstand) {
            super(brand); // Invoke Vehicle constructor
            this.hasKickstand = hasKickstand;
        }

        @Override
        public String displayType() {
            return "Bike: " + brand + " (Kickstand: " + hasKickstand + ")";
        }
    }

    public static void main(String[] args) {
        System.out.println("=== CODEVERSE VEHICLE FLEET SYSTEM ===");

        // Polymorphic fleet array: Vehicle-type references holding diverse subclasses!
        Vehicle[] fleet = new Vehicle[] {
            new Car("Toyota Camry", 4),
            new Bike("Yamaha MT-07", true),
            new Car("Porsche 911", 2)
        };

        System.out.println("\n1. Inspecting Fleet via Dynamic Method Dispatch:");
        for (Vehicle v : fleet) {
            // The JVM dynamically resolves the correct subclass displayType() at runtime!
            System.out.println("  • " + v.displayType());
        }

        System.out.println("\n2. Starting all vehicle engines:");
        for (Vehicle v : fleet) {
            v.start(); // Inherited from Vehicle
        }
    }
}
🖥 Console Output
=== CODEVERSE VEHICLE FLEET SYSTEM === 1. Inspecting Fleet via Dynamic Method Dispatch: • Car: Toyota Camry with 4 doors • Bike: Yamaha MT-07 (Kickstand: true) • Car: Porsche 911 with 2 doors 2. Starting all vehicle engines: Toyota Camry ignition: Engine running. Yamaha MT-07 ignition: Engine running. Porsche 911 ignition: Engine running.

    }

Explanation: Reuses existing parent login logic before adding two-factor checks.

📚 Example 12: Composition ("HAS-A") in Practice

    private Processor cpu = new Processor(); // Composition!
    void run() { cpu.compute(); }

Explanation: A Computer has a Processor; loose coupling permits swapping chips.

Question Quick Answer
1. What keyword triggers class inheritance? extends (e.g. class Car extends Vehicle).
