Foundations

01. The Java Development Toolchain

In Topic 01, we explored Java's architecture, bytecode, and the conceptual relationship between the JDK, JRE, and JVM. Now it is time to transition from theory to hands-on engineering.

To develop and execute Java applications on your personal computer, you require a specific set of tools working in harmony. This collection of tools is known as the Java Development Toolchain:

1. The JDK (Java Development Kit)

The master software bundle containing the compiler, runtime engine, standard class libraries, and diagnostics tools. As established in Topic 01, developers install the JDK, not merely a JRE or JVM.

2. The Compiler (javac)

The command-line tool located inside the JDK's bin directory. Its sole job is to parse your human-readable .java source code, enforce static type safety, and translate it into universal .class bytecode.

3. The JVM Runtime Launcher (java)

The command-line launcher that spins up the Java Virtual Machine, loads your compiled bytecode into memory, verifies security constraints, and executes the instructions via the Interpreter and JIT compiler.

4. Terminal / Command Prompt

The text-based command interface (PowerShell / Command Prompt on Windows, Terminal / zsh on macOS, Bash on Linux) where you invoke javac and java to build and run software.

5. Code Editor or IDE

The application where you author code. Beginners can use anything from a lightweight text editor (VS Code, Notepad, nano) to full-featured integrated development environments (IntelliJ IDEA, Eclipse).

6. Environment Variables (PATH & JAVA_HOME)

System-level configuration pointers that allow your operating system's terminal to recognize javac and java from any folder or directory on your drive.

Workflow Concepts

02. The Three-Phase Lifecycle: Write → Compile → Run

Unlike interpreted scripting languages where you execute raw script files directly (like Python executing .py), Java employs a disciplined, two-tier engineering model. Every beginner must internalize the distinction between these three distinct phases:

Phase Action Performed Tool Used Input → Output File
1. Writing Code Authoring human-readable Java syntax, statements, and class blueprints following language rules. Text Editor or IDE (VS Code, IntelliJ, Notepad) Outputs Main.java (plain text file)
2. Compiling Code Parsing syntax, verifying types, checking semantics, and generating platform-neutral bytecode. Java Compiler (javac) Main.java → Main.class (binary bytecode)
3. Running Code Launching the virtual machine, verifying bytecode integrity, and executing on the host CPU. Java Virtual Machine (java) Main.class → Program Output on Console
Real-Life Analogy: Architect Blueprint → Factory Mold → Final Product

Think of the three phases like manufacturing:

  • Writing (Source Code): You draw the architectural blueprint on paper (Main.java). Anyone who reads English can inspect it, but you cannot drive a paper drawing.
  • Compiling (Bytecode): An industrial machine translates that paper blueprint into a standardized precision mold (Main.class). If the blueprint had flaws, the compiler stops and reports an error before anything is stamped.
  • Running (Execution): The factory press (the JVM) stamps out the finished product and runs the engine.

Windows Workflow

04. Installing Java on Windows (Step-by-Step)

Windows is the most common operating system for new developers. Below is the standard, foolproof installation procedure using an MSI / EXE installer:

Windows Installation Steps
  1. Step 1: Download the Installer:
    Visit a reputable OpenJDK provider (such as Adoptium / Eclipse Temurin at adoptium.net or Oracle). Select Windows, Architecture x64, and Package Type JDK (version 21 or 17 LTS). Download the .msi installer file.
  2. Step 2: Run the Setup Wizard:
    Double-click the downloaded .msi file to launch the installation wizard. Click Next.
  3. Step 3: Enable Auto-Configuration (Crucial for Adoptium/Temurin):
    During the “Custom Setup” screen, click the dropdown icons and ensure that both:
    • “Set JAVA_HOME variable” → Select “Will be installed on local hard drive”
    • “Add to PATH” → Select “Will be installed on local hard drive”
    This eliminates 90% of beginner setup errors by configuring your system environment automatically!
  4. Step 4: Complete Installation:
    Click Install and grant administrator permission when prompted. The files will typically install to: 
    C:\Program Files\Eclipse Adoptium\jdk-21.x.x-hotspot\
# Or for Oracle JDK:
C:\Program Files\Java\jdk-21\
  5. Step 5: Close and Reopen Your Terminal:
    Crucial Rule: If you had a Command Prompt or PowerShell window open before installing, you must close it completely and open a fresh window. Environment variables only load when a new terminal session starts!
macOS Workflow

05. Installing Java on macOS (Intel & Apple Silicon)

macOS users must be attentive to their computer's processor architecture:

  • Apple Silicon (M1, M2, M3, M4 chips): Download the aarch64 / ARM64 package for maximum native speed and battery efficiency.
  • Intel-based Macs: Download the x64 package.

5.1 Method A: The Graphical PKG Installer (Recommended for Beginners)

  1. Download the .pkg installer from Adoptium Temurin or Oracle.
  2. Double-click the .pkg file and follow the standard macOS installation wizard.
  3. By default, macOS installs JDKs into the protected system location: 
    /Library/Java/JavaVirtualMachines/

5.2 Method B: Using Homebrew (Package Manager)

If you have Homebrew installed on your Mac, you can install the latest OpenJDK with a single terminal command:

Terminal Command
# Install OpenJDK 21 via Homebrew
brew install openjdk@21

# Link the OpenJDK to system Java wrappers so macOS finds it automatically:
sudo ln -sfn $(brew --prefix)/opt/openjdk@21/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk-21.jdk
Pro-Tip for macOS Users: The java_home Utility

macOS includes a built-in command to inspect all installed JDKs and print their exact paths: 

/usr/libexec/java_home -V

This utility is invaluable when multiple Java versions are installed on the same Mac.

Verification

07. Verifying Installation: java and javac

Once installation finishes, you must verify that both the runtime and the compiler are operational. Open a brand-new terminal window and run two separate commands:

7.1 Command 1: Verify the Java Runtime

Terminal Command
java -version
Typical Output (Eclipse Temurin / OpenJDK 21)
openjdk version "21.0.2" 2024-01-16
OpenJDK Runtime Environment Temurin-21.0.2+13 (build 21.0.2+13)
OpenJDK 64-Bit Server VM Temurin-21.0.2+13 (build 21.0.2+13, mixed mode, sharing)

7.2 Command 2: Verify the Java Compiler

Terminal Command
javac -version
Typical Output
javac 21.0.2
Why Checking Both Commands Separately Is Mandatory

Many beginners run java -version, see a version number, and assume everything is ready. However:

  • java -version only confirms that a Java Runtime (JVM) is detected.
  • javac -version confirms that the Java Compiler is present on your PATH.

If java -version works but javac -version fails with “'javac' is not recognized as an internal or external command”, you either only installed a bare JRE or the JDK's bin folder is missing from your system PATH!

System Architecture

08. Demystifying Environment Variables: JAVA_HOME & PATH

Few topics cause more initial anxiety for new programmers than “environment variables”. Let us demystify them completely using everyday logic:

What is an Environment Variable?

An Environment Variable is a global key-value pair maintained by your operating system that stores system-wide configuration information accessible to all running programs and terminal shells.

The Warehouse Analogy: JAVA_HOME vs. PATH
  • JAVA_HOME is the Master Factory Address:
    It tells other development tools (such as build systems like Maven, Gradle, Android Studio, and IDEs) the exact physical root folder where the JDK is installed on disk.
  • PATH is the Quick-Dial Speed List for the Terminal:
    When you type javac into your terminal, the operating system does not magically scan all 500 gigabytes of your hard drive. Instead, it looks exclusively inside the specific directory folders listed in your PATH variable. If the JDK's bin folder is in that list, the OS finds javac.exe and runs it immediately.
The Golden Rule of JAVA_HOME

JAVA_HOME must point to the ROOT directory of the JDK — NEVER directly to its bin folder!

Correct: C:\Program Files\Eclipse Adoptium\jdk-21.0.2.13-hotspot
Incorrect: C:\Program Files\Eclipse Adoptium\jdk-21.0.2.13-hotspot\bin ← (Will break tools like Maven and Gradle!)

Windows Configuration

09. Configuring JAVA_HOME & PATH on Windows

If your installer did not automatically configure environment variables, follow these manual steps to set them permanently:

Manual Windows Configuration Walkthrough
  1. Locate the Installed JDK Folder:
    Open File Explorer and verify your JDK folder path. Typical locations: 
    C:\Program Files\Eclipse Adoptium\jdk-21.0.2.13-hotspot\
# or
C:\Program Files\Java\jdk-21\
    Copy this full directory path.
  2. Open Environment Variables Dialog:
    Press Windows Key + S, type “env”, and select “Edit the system environment variables”. In the System Properties window, click the “Environment Variables...” button.
  3. Create the JAVA_HOME Variable:
    Under the bottom panel (System variables), click New...:
    • Variable name: JAVA_HOME
    • Variable value: (Paste your JDK path, e.g., C:\Program Files\Eclipse Adoptium\jdk-21.0.2.13-hotspot)
    Click OK.
  4. Add the bin Folder to Path:
    In the same System variables panel, select the variable named Path and click Edit.... Click New on the right side and type: 
    %JAVA_HOME%\bin
    Click OK.
  5. Confirm and Save:
    Click OK on the Environment Variables window, and OK on the System Properties window.
  6. Verify in a Fresh Terminal:
    Open a brand-new Command Prompt or PowerShell and run: 
    # In Command Prompt:
echo %JAVA_HOME%

# In PowerShell:
$env:JAVA_HOME
Unix Configuration

10. Configuring Environment Variables on macOS & Linux

On Unix-based operating systems (macOS and Linux), environment variables are maintained in hidden configuration files located inside your user home directory (~).

10.1 macOS (Zsh Shell Configuration)

Modern macOS versions use zsh as the default shell. Open Terminal and add the following lines to your ~/.zshrc file:

Terminal Commands (~/.zshrc)
# Open ~/.zshrc in nano text editor
nano ~/.zshrc

# Add these lines at the bottom of the file:
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH=$JAVA_HOME/bin:$PATH

# Save and exit (Ctrl+O, Enter, Ctrl+X in nano)

# Apply the changes immediately to the current shell:
source ~/.zshrc

10.2 Linux (Ubuntu / Debian / Fedora)

On Linux distributions using the Bash shell, add the export statements to ~/.bashrc:

Terminal Commands (~/.bashrc)
# Add export statements to ~/.bashrc:
echo 'export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64' >> ~/.bashrc
echo 'export PATH=$JAVA_HOME/bin:$PATH' >> ~/.bashrc

# Reload configuration:
source ~/.bashrc

# Verify:
echo $JAVA_HOME

First Program

12. Creating Your First Program: Main.java

Now that your Java Development Kit is verified and ready, it is time to write, save, compile, and execute your inaugural Java application.

12.1 Step 1: Create a Dedicated Project Folder

Never scatter your Java source files randomly on your Desktop. Open your terminal or file explorer and create a clean directory:

Terminal Commands
# Create a new directory for your Java practice
mkdir java_basics

# Navigate into the directory
cd java_basics

12.2 Step 2: Create and Save Main.java

Inside this folder, create a new text file named strictly Main.java (with a capital ‘M’). Type or paste the following program:

Main.java 
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, CodeVerse!");
    }
}
Warning for Windows Notepad Users: Hidden Extensions

If creating the file using Windows Notepad, Windows may silently append .txt, saving your file as Main.java.txt!

In File Explorer, click View → Show → File name extensions. Ensure the file is named Main.java and not Main.java.txt.

Code Dissection

13. Comprehensive Line-by-Line Anatomy

Every single character in your five-line program plays a vital structural role. Let us examine the exact purpose of each line:

Code Snippet Syntactic Component Engineering Purpose
public class Main Class Declaration public makes the class accessible from anywhere. class declares the blueprint. Main is the identifier. In Java, all application code must be housed inside a class.
{ (Line 1) Class Opening Brace Marks the opening boundary of the Main class body.
public static void main(...) Main Entry Point Method The standardized gateway where execution begins. The JVM requires this exact signature to launch your program.
public (Method) Access Modifier Allows the external JVM launcher to access and call the method from outside the class.
static Method Modifier Binds the method to the class itself. The JVM does not have to instantiate an object using new Main() just to start the program.
void Return Type Specifies that the main method returns nothing back to the JVM when it finishes.
main Method Identifier The reserved name recognized by the JVM launcher as the official starting point of execution.
String[] args Method Parameters An array of textual strings holding any command-line arguments passed when invoking the program.
System.out.println(...) Output Statement System is a core class; out is the standard console output stream; println() prints the text followed by a newline.
"Hello, CodeVerse!" String Literal The exact sequence of characters to be printed, delimited by double quotation marks.
; (Semicolon) Statement Terminator Tells the compiler that the statement is complete. Every executable Java statement must end with ;.
} (Line 4 & 5) Closing Braces Line 4 closes the main() method; Line 5 closes the Main class body.
Why the Public Class Name MUST Match the Filename

Java enforces a strict rule: If a class is declared public, the file containing it MUST be named identically to the class, including exact letter casing, followed by .java.

Therefore, public class Main must reside in Main.java. Naming the file main.java or Program.java will trigger a fatal compiler error: “class Main is public, should be declared in a file named Main.java”.

Language Grammar

14. Keywords, Identifiers, String Literals & Statements

To read and write Java fluently, you must recognize the four fundamental building blocks that comprise any Java source file:

1. Reserved Keywords

Words that have a fixed, predefined meaning in the Java compiler. Examples in our code: public, class, static, void. You cannot name your own variable, method, or class using a reserved keyword!

2. Identifiers

Names created by the programmer (or Java API authors) to identify classes, methods, or variables. Examples: Main, args, System, out, println. Identifiers are case-sensitive and cannot start with a digit.

3. String Literals

Constant data values written directly in the code. A String Literal consists of any text enclosed in double quotation marks (e.g., "Hello, CodeVerse!"). Single quotes ('A') are reserved strictly for single characters (char).

4. Statements

A complete unit of execution that commands the computer to perform an action. In Java, statements always terminate with a semicolon (;), representing an individual sentence of instruction.

CLI Execution

15. Compiling & Running via Command Line

Ensure your terminal's current working directory is the folder containing your Main.java file (use cd to navigate). Then execute the two foundational commands:

15.1 Step 1: Compile the Source Code

Terminal Compilation Command
javac Main.java

What happens: The Java Compiler parses Main.java. If there are zero errors, the command finishes silently and returns to the prompt. If you list your files (using dir on Windows or ls on Mac/Linux), you will see a newly generated binary file: Main.class.

15.2 Step 2: Execute the Bytecode Class

Terminal Execution Command
java Main
Console Output
Hello, CodeVerse!
CRITICAL: Never Add .class to the java Command!

Notice the fundamental difference between the two commands:

  • javac Main.java → You supply the file name including the .java extension to the compiler.
  • java Main → You supply the class name without any extension to the JVM launcher!

Typing java Main.class will cause the JVM to search for a nested class literally named class inside package Main, resulting in: “Error: Could not find or load main class Main.class”.

Modern Java Note: Single-File Source Code Launch (Java 11+)

Starting with Java 11, the JVM introduced a convenient shortcut for single-file scripts: 

java Main.java

When you pass a file ending in .java directly to java, the JVM compiles the file in memory and executes it immediately without generating a physical .class file on your disk.

While useful for rapid scratch testing, beginners must master the classic javac Main.java followed by java Main workflow first. Professional enterprise software, build tools (Maven, Gradle), and multi-file projects all rely on the two-stage compile-and-run model.

Error Taxonomy

16. Compilation Errors vs. Runtime Errors

In software development, bugs occur at different stages of the execution pipeline. Understanding the difference between a Compilation Error and a Runtime Error is critical:

Dimension Compilation Error (Compile-Time) Runtime Error (Exception)
When Detected? During the javac compilation phase, before the program ever runs. While the program is actively executing inside the JVM.
Is .class File Generated? No. The compiler halts immediately upon finding the first syntax flaw. Yes. The code was syntactically valid, but encountered an illegal operation.
Primary Causes Grammar and type rule violations: missing semicolons, unmatched braces, misspelled keywords, type mismatches. Logical and environmental crashes: dividing by zero (10 / 0), accessing an invalid array index, missing files.
Who Catches It? The Java Compiler (javac). The Java Virtual Machine (JVM).
Analogy Writing an English sentence with invalid spelling or grammar: the editor rejects it before publishing. A car with a perfect exterior blueprint that runs out of gas or crashes into a wall while driving.
IDE Workflows

17. Running Java in Modern IDEs (IntelliJ & VS Code)

While working in the terminal builds strong foundational discipline, professional developers typically use an Integrated Development Environment (IDE) to accelerate productivity.

17.1 Workflow in IntelliJ IDEA (Community Edition)

  1. Create a New Project: Launch IntelliJ IDEA → Click New Project → Select Java → Verify your installed JDK 21 is detected → Click Create.
  2. Create a Java Class: In the Project Explorer pane on the left, expand your project → right-click the src folder → select New → Java Class → type Main and press Enter.
  3. Use Productivity Live Templates:
    • Inside the class, type psvm and press Tab → IntelliJ automatically generates public static void main(String[] args)!
    • Inside main, type sout and press Tab → IntelliJ automatically generates System.out.println();!
  4. Run the Program: Click the green Play (▸) icon next to line 1 or press Shift + F10 (or Ctrl + R on macOS). IntelliJ compiles and runs the program, displaying the output in the bottom console panel.

17.2 Workflow in Visual Studio Code

  1. Install the official Extension Pack for Java by Microsoft from the Extensions tab (Ctrl + Shift + X).
  2. Open your java_basics folder in VS Code (File → Open Folder).
  3. Open Main.java. Notice that a small “Run | Debug” hyperlink appears directly above the main() method signature!
  4. Click Run or press F5. VS Code opens its integrated terminal and displays the output.
The Fundamental Truth About IDEs

Remember: When you click that green “Play” button, the IDE is not performing magic. Behind the scenes, it simply calls javac to compile your files into .class bytecode and then calls java to execute them!

Troubleshooting

18. Top 10 Common Beginner Errors & Solutions

Every software engineer encounters errors. In fact, troubleshooting is how real programming skill is forged. Below is the master diagnostic guide for the ten most frequent setup and beginner code errors:

1. 'java' is not recognized as an internal or external command (Windows)
C:\Users\User> java -version
'java' is not recognized as an internal or external command, operable program or batch file.

Root Cause: The JDK is either not installed, or its bin folder path has not been registered in your Windows PATH environment variable, or the terminal was not restarted after installation.

Solution: Close all terminals. Verify that your JDK directory exists in C:\Program Files\.... Add %JAVA_HOME%\bin to your System Path. Open a fresh terminal and retest.

2. 'javac' command not found / not recognized
$ javac Main.java
bash: javac: command not found

Root Cause: You have only installed a runtime environment (JRE) without the compiler, or your PATH only points to a JRE directory.

Solution: Install the full JDK package (e.g., sudo apt install openjdk-21-jdk on Ubuntu or download Temurin JDK on Windows). Verify with javac -version.

3. error: cannot find file: Main.java
C:\Users\User> javac Main.java
error: cannot find file: Main.java
Usage: javac <options> <source files>

Root Cause: You ran javac from a directory where Main.java does not physically exist (e.g., you are in C:\Users\User while your file is inside C:\Users\User\java_basics).

Solution: Use cd to navigate to the exact folder containing the file: 

cd java_basics
dir   # Check that Main.java is listed
javac Main.java

4. Class Name and Filename Mismatch
javac main.java
main.java:1: error: class Main is public, should be declared in a file named Main.java
public class Main {
       ^

Root Cause: The class is named Main (capital M), but the file on disk was named main.java (lowercase m). Java filenames are strictly case-sensitive.

Solution: Rename the physical file on your disk so that its spelling and capitalization match the public class name exactly: Main.java.

5. error: ';' expected (Missing Semicolon)
Main.java:3: error: ';' expected
        System.out.println("Hello, CodeVerse!")
                                               ^

Root Cause: An executable statement was not terminated with a semicolon.

Solution: Add the semicolon ; at the end of the line: 

System.out.println("Hello, CodeVerse!");

6. error: cannot find symbol (Incorrect Capitalization)
Main.java:3: error: cannot find symbol
        system.out.println("Hello, CodeVerse!");
        ^
  symbol:   variable system
  location: class Main

Root Cause: You wrote system with a lowercase ‘s’. Java is strictly case-sensitive; the standard library class is System with a capital ‘S’.

Solution: Correct the capitalization: System.out.println(...).

7. error: reached end of file while parsing (Unmatched Braces)
Main.java:5: error: reached end of file while parsing
}
 ^

Root Cause: An opening brace { was not paired with a corresponding closing brace }.

Solution: Count your opening and closing braces. If you opened two blocks (one for class Main { and one for main(...) {), you must have two closing braces } at the bottom.

8. Error: Could not find or load main class Main.class
C:\Users\User\java_basics> java Main.class
Error: Could not find or load main class Main.class
Caused by: java.lang.ClassNotFoundException: Main/class

Root Cause: You added .class to the java execution command.

Solution: Run with the class name only: 

java Main

9. Running java Command from the Wrong Directory
C:\Users\User> java Main
Error: Could not find or load main class Main

Root Cause: Main.class is located inside java_basics, but your terminal was currently located in your home folder. The JVM searches the current directory (the default classpath) for Main.class.

Solution: Navigate into the directory where Main.class resides before running: 

cd java_basics
java Main

10. JAVA_HOME Configured to bin Directory
Error: JAVA_HOME is set to an invalid directory: C:\Program Files\Java\jdk-21\bin

Root Cause: The JAVA_HOME environment variable was mistakenly pointed to the bin subfolder instead of the root JDK directory.

Solution: Remove \bin from JAVA_HOME. Set JAVA_HOME to C:\Program Files\Java\jdk-21, and add %JAVA_HOME%\bin to Path.

Chapter Summary

21. Revision, Checklist, Commands & Glossary

Executive Chapter Summary

Setting up Java requires installing a full, modern Long-Term Support (LTS) JDK distribution (such as Eclipse Temurin or Oracle JDK 21). System environment variables must be configured properly: JAVA_HOME specifies the master JDK root directory, while PATH ensures that javac and java can be invoked from any terminal directory. Java programs follow a strict two-stage model: human-readable .java files are compiled by javac into universal .class bytecode, which is subsequently executed by the JVM via java without the .class extension.

21.1 Setup Verification Checklist

✓
JDK Installed: A modern LTS JDK (Java 21 or 17) is installed in your program directory.
✓
JAVA_HOME Configured: Points to the JDK root folder (not to \bin).
✓
PATH Registered: Contains %JAVA_HOME%\bin (or $JAVA_HOME/bin).
✓
Terminal Reopened: A fresh terminal window was opened after configuring environment variables.
✓
Runtime Verified: java -version displays the expected JDK version.
✓
Compiler Verified: javac -version displays the matching compiler version.
✓
File Name Casing: public class Main resides in a file named exactly Main.java.
✓
Compiled & Run: javac Main.java produces Main.class, and java Main prints Hello, CodeVerse!.

21.2 Important Terminal Commands Reference

Command Action & Purpose Sample Expected Output
java -version Verifies the installed Java Virtual Machine runtime. openjdk version "21.0.2" ...
javac -version Verifies the Java compiler tool. javac 21.0.2
javac Main.java Compiles source code into Main.class bytecode. Silent on success (returns to prompt)
java Main Executes the compiled bytecode class. Hello, CodeVerse!
echo %JAVA_HOME% Prints the configured JAVA_HOME path on Windows CMD. C:\Program Files\Eclipse Adoptium\jdk-21...
echo $JAVA_HOME Prints the configured JAVA_HOME path on macOS / Linux. /Library/Java/JavaVirtualMachines/...

21.3 Top 5 Mistakes to Remember

  1. Never run java Main.class: Always execute with java Main.
  2. Never set JAVA_HOME to \bin: It must point to the parent JDK folder.
  3. Always restart your terminal: Environment variables only reload in new terminal sessions.
  4. Mind your casing: Main.java, System, String, and main must match their exact capitalization.
  5. Navigate before compiling: Use cd to enter the folder where your .java file resides before running javac.

21.4 Technical Glossary (14 Essential Terms)

1. JDK (Java Development Kit)

The master software bundle containing the compiler (javac), the JVM runtime, class libraries, and developer tools.

2. javac

The official Java compiler tool that translates human-readable .java source files into binary .class bytecode.

3. java (Launcher)

The command-line launcher utility that initializes the Java Virtual Machine and starts program execution.

4. JAVA_HOME

An operating system environment variable pointing to the root installation directory of the active JDK.

5. PATH

A system environment variable containing a list of directories where the terminal searches for executable commands (like javac and java).

6. Source File (.java)

A plain-text document containing human-written Java language code, class definitions, and statements.

7. Bytecode (.class)

The platform-independent binary instruction set generated by javac and consumed by the JVM.

8. IDE (Integrated Development Environment)

A software application (such as IntelliJ IDEA or Eclipse) combining a code editor, compiler automation, debugger, and terminal in a unified interface.

9. Identifier

A user-defined name given to a class, method, or variable in Java code (e.g., Main, args).

10. Keyword

A reserved vocabulary word with fixed compiler meaning that cannot be used as an identifier (e.g., public, class, static, void).

11. String Literal

A sequence of characters enclosed in double quotation marks representing constant textual data.

12. Statement

An executable instruction in Java ending with a semicolon (;) that performs an action.

13. Compilation Error

A syntax or semantic error caught by the javac compiler before the program is executed.

14. Runtime Error (Exception)

An unexpected failure or crash occurring while the program is actively running inside the JVM.
