Section 01

1. What Is Object-Oriented Programming (OOP)?

In everyday life, our world is not an assortment of disconnected variables and floating calculations. The world is made of objects — people, cars, phones, bank accounts, and books. Each object has two fundamental characteristics:

  • State (Data / Attributes): What the object knows or possesses. For a student, state includes name, roll number, and marks.
  • Behavior (Actions / Methods): What the object does or can perform. For a student, behavior includes studying, writing an exam, or displaying details.

Object-Oriented Programming (OOP) is a programming paradigm that organizes software design around these objects, binding their data and actions into single, cohesive, self-contained units.

📚 Core Definition

Object-Oriented Programming (OOP) is a methodology where programs are constructed using interacting entities called objects. Each object bundles together state (stored in variables called fields) and behavior (implemented in functions called methods).

Visual 1 & 4: An Object bundles State (fields) and Behavior (methods) inside one boundary.
💡 Good to Know: The Broader OOP Horizon

As you progress through Java, you will encounter the four major pillars of OOP: Encapsulation (protecting data), Inheritance (reusing code across parent-child classes), Polymorphism (taking many forms), and Abstraction (hiding internal complexity). For now, focus entirely on the bedrock of all OOP: Classes and Objects!

Section 02

2. What Is a Class? (The Blueprint)

Before you can construct a house, an architect draws an architectural blueprint. The blueprint defines how many rooms the house has, where the doors are placed, and where the plumbing connects.

However, you cannot live inside a blueprint. A blueprint is just paper and ink! It has no bricks, no physical weight, and occupies no real-world land. To live in a house, someone must use that blueprint to build an actual physical structure.

📚 Core Definition

A Class in Java is a user-defined blueprint, template, or prototype from which individual objects are created. It defines the names and types of the fields (data) and the signatures and code of the methods (behavior) that its instances will possess.

A Simple Class Declaration in Java

Student.java 
// Blueprint definition: No student exists in memory yet!
class Student {
    // 1. Instance Fields (State)
    String name;
    int age;

    // 2. Instance Method (Behavior)
    void study() {
        System.out.println(name + " is studying.");
    }
}

Let us dissect every keyword in this declaration:

  • class: The reserved Java keyword used to declare a new class.
  • Student: The identifier (name) of the class. By Java convention, class names use PascalCase (e.g., Student, BankAccount, CarModel).
  • String name; and int age;: Instance fields. Every student object created later will have its own name and age.
  • void study() { ... }: An instance method. Defines an action that every student object can execute.
Visual 2 & 3: A Class is purely a design blueprint — declaring a class does not instantiate any objects!
Section 03

3. What Is an Object? (The Instance)

If a class is the blueprint of a house, then an object is the actual house built from bricks and mortar on a plot of land. You can open its doors, paint its walls, and sleep in its bedrooms.

In Java, an object is a real entity created in the computer's memory (specifically in an area called the Heap) according to the specifications laid out in its class.

📚 Core Definition

An Object is a runtime instance of a class. It holds real data in its fields and can execute the methods declared in its class. Creating an object is formally known as instantiation.

Complete Runnable Code: Creating and Using an Object

Main.java 
class Student {
    String name;
    int age;
}

public class Main {
    public static void main(String[] args) {
        // Step 1: Create an instance of Student using 'new'
        Student s1 = new Student();

        // Step 2: Assign values to s1's fields
        s1.name = "Aman";
        s1.age = 19;

        // Step 3: Access and print the field values
        System.out.println(s1.name);
        System.out.println(s1.age);
    }
}
💻 Expected Output
Aman 19

Execution Order Breakdown

  1. Student s1; declares a reference variable named s1 of type Student on the Call Stack.
  2. new Student(); allocates a brand new memory block in the Heap, stamps out fields name (null) and age (0), runs the constructor, and yields an object reference.
  3. = assigns that object reference into s1, so s1 now points to the new Student object.
  4. s1.name = "Aman"; navigates through reference s1 and stores "Aman" in the object's name field.
  5. s1.age = 19; stores 19 into the object's age field.
  6. System.out.println(s1.name); reads and prints Aman.
  7. System.out.println(s1.age); reads and prints 19.
Visual 5: Lifecycle flow from Class Definition → new Keyword → Heap Object Instance → Reference Variable.

6. Creating Objects with the new Keyword

To bring a class definition to life, you use Java's universal object creation syntax:

📚 Syntax Formula

ClassName referenceVariable = new ClassName();

This single statement performs four coordinated steps behind the scenes:

Component Part of Statement What It Does in the JVM
1. Declaration ClassName referenceVariable Reserves space on the Call Stack for a reference variable that can point to a ClassName object.
2. Allocation new Allocates dynamic memory in the Heap for the new object and initializes all instance fields to their default values.
3. Initialization ClassName() Invokes the class constructor to perform initial setup on the freshly allocated object.
4. Assignment = Stores the heap object's reference address into the stack reference variable.
CarExample.java 
class Car {
    String brand;
}

public class CarExample {
    public static void main(String[] args) {
        // Step-by-step object creation
        Car car1 = new Car();
        car1.brand = "Toyota";

        System.out.println(car1.brand);
    }
}
💻 Expected Output
Toyota

7. Accessing Fields with the Dot Operator (.)

Once you have an object reference, how do you read from or write to its fields? You use the dot operator (.).

📚 Syntax Formula

objectReference.fieldName

You can use the dot operator in three primary ways:

  • Writing / Assigning: s1.name = "Riya"; (Stores data into the field)
  • Reading / Inspecting: System.out.println(s1.name); (Retrieves data from the field)
  • Mutating / Updating: s1.age = s1.age + 1; or s1.age++; (Modifies existing field data)
DotOperatorDemo.java 
class Student {
    String name;
    int age;
}

public class DotOperatorDemo {
    public static void main(String[] args) {
        Student s1 = new Student();

        // 1. Initial assignment
        s1.name = "Riya";
        s1.age = 20;

        System.out.println(s1.name); // Prints: Riya
        System.out.println(s1.age);  // Prints: 20

        // 2. Updating field value
        s1.age = 21;

        System.out.println(s1.age);  // Prints: 21
    }
}
💻 Expected Output
Riya 20 21
Visual 8: The Dot Operator navigates through reference s1 to mutate field age from 20 to 21.

An instance method defines an action or computation that belongs to objects of that class. Methods allow objects to process data, calculate results, and interact with the outside world.

Instance methods are invoked through an object reference using the dot operator:

10. Object State and Dynamic Behavior

The power of OOP shines when behavior alters state over time. Consider an everyday household appliance: an electric Fan.

  • State: Is the fan spinning or stopped? Stored as boolean isOn;.
  • Behavior: You can click buttons to turnOn() or turnOff().
FanStateDemo.java 
class Fan {
    boolean isOn; // Initially false (default)

    void turnOn() {
        isOn = true;
    }

    void turnOff() {
        isOn = false;
    }

    void displayStatus() {
        System.out.println(isOn ? "Fan is ON" : "Fan is OFF");
    }
}

public class FanStateDemo {
    public static void main(String[] args) {
        Fan fan = new Fan();

        fan.displayStatus(); // Initial State: OFF
        fan.turnOn();
        fan.displayStatus(); // Mutated State: ON
        fan.turnOff();
        fan.displayStatus(); // Mutated State: OFF
    }
}
💻 Expected Output
Fan is OFF Fan is ON Fan is OFF

11. Default Values of Instance Fields

In Java, whenever an object is instantiated with new, the JVM guarantees zero-initialization for every instance field that you do not explicitly assign.

Data Type Category Specific Java Type Automatic Default Value Stamped by JVM
Integer Primitives byte, short, int, long 0 (or 0L for long)
Floating-Point Primitives float, double 0.0f / 0.0d
Boolean Primitive boolean false
Character Primitive char '\u0000' (The null character, numeric value 0)
All Reference Types String, Arrays, Custom Classes null (Points to no object)
DefaultsDemo.java 
class Example {
    int number;
    double price;
    boolean active;
    char letter;
    String name;
}

public class DefaultsDemo {
    public static void main(String[] args) {
        Example e = new Example();

        System.out.println(e.number);        // 0
        System.out.println(e.price);         // 0.0
        System.out.println(e.active);        // false
        System.out.println((int) e.letter);   // 0 (casting '\u0000' to int reveals numeric 0)
        System.out.println(e.name);          // null
    }
}
💻 Expected Output
0 0.0 false 0 null
⚠ Critical Contrast: Instance Fields vs Local Variables

While instance fields get automatic default values, local variables declared inside a method NEVER receive default values! If you attempt to read an uninitialized local variable, the Java compiler halts with an error: variable might not have been initialized.

12. Constructors (Object Initialization)

Imagine ordering a custom laptop. Would you want it delivered with empty circuit boards, requiring you to manually solder the processor and RAM yourself? Of course not! You expect the factory to initialize the components during manufacturing.

In Java, a Constructor is that factory assembly line. It is a special member block that executes automatically whenever an object is instantiated using new, ensuring the object starts life in a valid, ready-to-use state.

📚 The 3 Golden Rules of Constructors
  1. A constructor must have the exact same name as its enclosing class.
  2. A constructor has NO return type — not even void!
  3. If you do not declare any constructor, the Java compiler automatically injects a hidden, no-argument default constructor for you.

1. No-Argument Constructor

NoArgDemo.java 
class Student {
    String name;

    // No-argument constructor
    Student() {
        name = "Unknown";
    }
}

2. Parameterized Constructor

A parameterized constructor allows you to pass custom values at the exact moment of creation:

ConstructorDemo.java 
class Student {
    String name;
    int age;

    // Parameterized constructor
    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }

    void display() {
        System.out.println(name + " - " + age);
    }
}

public class ConstructorDemo {
    public static void main(String[] args) {
        // Instant setup in a single elegant line!
        Student s1 = new Student("Aman", 19);
        Student s2 = new Student("Riya", 20);

        s1.display();
        s2.display();
    }
}
💻 Expected Output
Aman - 19 Riya - 20
Visual 12: Constructor lifecycle — receiving arguments, initializing instance fields, and yielding a ready object.
Section 13

13. The this Keyword Demystified

In professional Java code, developers prefer meaningful parameter names that match the field names: 

// Potential bug: Parameter shadowing!
Student(String name, int age) {
    name = name; // Which name is which?!
    age = age;
}

Here, Java's scoping rules give precedence to the local parameter. Writing name = name; merely assigns the parameter to itself, completely leaving the object's instance field unchanged (and at its default null)! This problem is called parameter shadowing.

To solve this, Java provides the this keyword. this is a reference to the current invoking object instance.

ThisDemo.java 
class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name; // this.name is the FIELD; name is the PARAMETER
        this.age = age;   // this.age is the FIELD; age is the PARAMETER
    }

    void display() {
        System.out.println(this.name + " - " + this.age);
    }
}

public class ThisDemo {
    public static void main(String[] args) {
        Student s = new Student("Aman", 19);
        s.display();
    }
}
💻 Expected Output
Aman - 19
Visual 13: this.name = name resolves parameter shadowing by targeting the object's instance field.

14. Local Variables vs Instance Fields

Variables in Java live in different parts of memory and follow fundamentally different lifecycles based on where they are declared:

Feature Instance Field Local Variable
Where Declared Inside class, but outside any method or constructor. Inside a method, constructor, or code block { ... }.
Memory Location Lives on the Heap as part of the object. Lives on the Call Stack within the method's frame.
Default Values Yes — JVM automatically assigns zero/false/null. No — Must be explicitly assigned before reading.
Scope Accessible throughout all non-static methods of the class. Only visible within the block where declared.
Lifetime Exists as long as the object lives in the Heap. Destroyed immediately when the enclosing method/block exits.

15. Instance Members vs static Members

So far, every field we created belonged to a specific object instance. But what if all students attend the exact same college? Should every student object store its own separate copy of "BBDU"? No! That would waste memory.

In Java, the static keyword creates members that belong to the class itself rather than to any individual object.

Property Instance Member Static Member (static)
Belongs to Each individual object instance. The entire class as a whole.
Memory Copies One copy per object created in the Heap. Exactly one shared copy in class memory.
Access Syntax objectRef.memberName ClassName.memberName
Can use this? Yes (refers to invoking instance). No (no current instance exists in static context).
StaticDemo.java 
class Student {
    String name;                  // Instance field: each student has their own name
    static String college = "BBDU"; // Static field: ALL students share this one college
}

public class StaticDemo {
    public static void main(String[] args) {
        Student s1 = new Student();
        Student s2 = new Student();

        s1.name = "Aman";
        s2.name = "Riya";

        System.out.println(s1.name);          // Aman
        System.out.println(s2.name);          // Riya
        System.out.println(Student.college);  // BBDU (Accessed via Class Name!)
    }
}
💻 Expected Output
Aman Riya BBDU
Visual 16: Two instances have independent name fields but share the single class-level college field.

16. Object References, Aliasing & null

In Java, a reference variable is not the object itself. Think of a reference variable as a remote control, and the object in the Heap as a television.

1. Reference Aliasing (Two Remotes, One TV)

When you write Student s2 = s1;, you are not making a copy of the object! You are simply copying the remote control. Both variables now point to the exact same heap instance:

AliasingDemo.java 
class Student {
    String name;
}

public class AliasingDemo {
    public static void main(String[] args) {
        Student s1 = new Student();
        s1.name = "Aman";

        Student s2 = s1; // Copies reference, NOT the object!
        s2.name = "Aman Kumar"; // Mutates the shared object

        System.out.println("s1.name: " + s1.name);
        System.out.println("s2.name: " + s2.name);
    }
}
💻 Expected Output
s1.name: Aman Kumar s2.name: Aman Kumar

2. The null Reference & Avoiding NullPointerException

If a reference variable does not point to any object in the Heap, it contains the special literal null. Attempting to use the dot operator on a null reference crashes your application with a NullPointerException!

NullSafetyDemo.java 
public class NullSafetyDemo {
    public static void main(String[] args) {
        Student s3 = null; // No object attached!

        // Safe defensive programming pattern: Always check before access!
        if (s3 != null) {
            System.out.println(s3.name);
        } else {
            System.out.println("No student object assigned.");
        }
    }
}
💻 Expected Output
No student object assigned.
Visual 11 & 17: Contrast between Aliasing (two references to one object) and a Null reference.

17. Arrays of Objects

In Topic 9, you learned how to store multiple integers in int[] numbers = new int[5];. In Java, you can also create arrays that hold references to objects!

⚠ The #1 Object Array Beginner Trap

Writing Student[] students = new Student[3]; DOES NOT create 3 Student objects! It merely creates an array containing 3 null references. You must still instantiate each individual object inside the array using new Student(...)!

ObjectArrayDemo.java 
class Student {
    String name;

    Student(String name) {
        this.name = name;
    }

    void display() {
        System.out.println(name);
    }
}

public class ObjectArrayDemo {
    public static void main(String[] args) {
        // Step 1: Create an array capable of holding 3 Student references
        Student[] students = new Student[3];

        // Step 2: Instantiate each individual object in its array slot
        students[0] = new Student("Aman");
        students[1] = new Student("Riya");
        students[2] = new Student("Karan");

        // Step 3: Traverse the array using an enhanced for-each loop
        for (Student student : students) {
            student.display();
        }
    }
}
💻 Expected Output
Aman Riya Karan
Visual 18: An array of objects is an array of memory references pointing to distinct Heap objects.

18. Visual Debugging Guide: 16 Common Beginner Mistakes

Learning OOP involves rewiring how you think about code. Below are the 16 most frequent mistakes made by Java students, along with visual corrections:

❌ Mistake 1: Declaring reference without 'new'
Student s; // Uninitialized
s.name = "Aman"; // COMPILER ERROR!

Problem: Local variable s was declared but no object was created in Heap.

✅ Correct: Allocate with 'new'
Student s = new Student(); // Created!
s.name = "Aman"; // Works perfectly!

Fix: Always call new ClassName() to construct the object in memory.

❌ Mistake 2: Forgetting 'new' keyword
Car c = Car(); // COMPILER ERROR!
// Looks like an undefined method call

Problem: Java requires the new keyword to invoke constructors for instantiation.

✅ Correct: Use 'new' keyword
Car c = new Car(); // Clean allocation!

Fix: Always precede constructor invocation with new.

❌ Mistake 3: Calling instance method on Class
class Dog { void bark() { ... } }
Dog.bark(); // COMPILER ERROR!

Problem: bark() is an instance method; it needs an actual Dog object to bark!

✅ Correct: Call on an Object Reference
Dog d = new Dog();
d.bark(); // Works! The dog barks.

Fix: Instantiate an object before invoking its instance methods.

❌ Mistake 4: Dereferencing 'null'
Student s = null;
s.display(); // NullPointerException!

Problem: Attempting to access fields or methods through a null reference crashes the app.

✅ Correct: Guard with null check
if (s != null) {
    s.display();
}

Fix: Ensure the reference is pointing to a live object before invoking members.

❌ Mistake 5: Writing return type on constructor
class Student {
    void Student() { ... } // BUG!
} // Becomes an ordinary method, NOT a constructor!

Problem: Putting void or a type turns it into a normal method.

✅ Correct: No return type whatsoever
class Student {
    Student() { ... } // Real constructor!
}

Fix: Constructors never declare any return type.

❌ Mistake 6: Constructor name mismatch
class Student {
    student() { ... } // Lowercase! ERROR!
}

Problem: Java is strictly case-sensitive. student() != Student().

✅ Correct: Exact matching case
class Student {
    Student() { ... } // Matches class name
}

Fix: Spell the constructor with the exact capitalization of the class.

❌ Mistake 7: Missing default constructor
class Student {
    Student(String name) { ... }
}
Student s = new Student(); // COMPILER ERROR!

Problem: Defining a parameterized constructor deletes Java's automatic default constructor.

✅ Correct: Explicitly add no-arg constructor
class Student {
    Student() { } // Added back manually!
    Student(String name) { ... }
}

Fix: If you need both, declare an explicit no-arg constructor.

❌ Mistake 8: Forgetting 'this' with shadowing
Student(String name) {
    name = name; // Self-assignment!
} // Field remains null!

Problem: Parameter shadows the field; instance field is never updated.

✅ Correct: Use this.fieldName
Student(String name) {
    this.name = name; // Target field updated!
}

Fix: Use this.name to target the instance field.

❌ Mistake 9: Assuming reference copy clones object
Student s2 = s1; // Both share ONE object!
s2.age = 30; // Unexpectedly mutates s1.age too!

Problem: Reference assignment copies the pointer, not the underlying object data.

✅ Correct: Create distinct instance if independent
Student s2 = new Student();
s2.name = s1.name;
s2.age = 30; // s1 remains untouched!

Fix: Use new if you desire an independent object in memory.

❌ Mistake 10: Accessing instance field in static main
public class Main {
    int score = 100;
    public static void main(String[] args) {
        System.out.println(score); // ERROR!
    }
}

Problem: static methods cannot directly touch non-static instance fields.

✅ Correct: Instantiate an object first
public class Main {
    int score = 100;
    public static void main(String[] args) {
        Main m = new Main();
        System.out.println(m.score); // Works!
    }
}

Fix: Create an instance of the class to access its non-static fields.

❌ Mistake 11: Uninitialized array elements
Student[] arr = new Student[5];
arr[0].name = "Aman"; // NullPointerException!

Problem: Array slots initially contain null, not Student objects.

✅ Correct: Instantiate array elements
Student[] arr = new Student[5];
arr[0] = new Student();
arr[0].name = "Aman"; // Safe & working!

Fix: Allocate each slot with new Student() before accessing its fields.

❌ Mistake 12: Expecting default values for locals
void test() {
    int x;
    System.out.println(x); // COMPILER ERROR!
}

Problem: Local variables never receive automatic defaults.

✅ Correct: Always initialize locals
void test() {
    int x = 0; // Explicitly initialized
    System.out.println(x); // Prints 0
}

Fix: Assign local variables before attempting to read them.

19. Mini Project: Student Record System

Let us consolidate everything we have learned — classes, fields, parameterized constructors, methods with calculations, object arrays, and loop traversal — into an educational console program:

Project Architecture

Visual 19: Architectural flowchart separating the Student entity model from the system driver logic.
StudentRecordSystem.java 
class Student {
    String name;
    int rollNumber;
    double marks;

    // Parameterized constructor using 'this'
    Student(String name, int rollNumber, double marks) {
        this.name = name;
        this.rollNumber = rollNumber;
        this.marks = marks;
    }

    // Method calculating letter grade based on marks
    String getGrade() {
        if (marks >= 90) return "A+";
        if (marks >= 75) return "A";
        if (marks >= 60) return "B";
        if (marks >= 50) return "C";
        return "F";
    }

    // Formatted display method
    void displayRecord() {
        System.out.printf("Roll: %-4d | Name: %-12s | Marks: %5.1f | Grade: %s%n",
            rollNumber, name, marks, getGrade());
    }
}

public class StudentRecordSystem {
    public static void main(String[] args) {
        System.out.println("================================================");
        System.out.println("        CODEVERSE STUDENT RECORD SYSTEM         ");
        System.out.println("================================================");

        // 1. Create an array of Student references
        Student[] roster = new Student[3];

        // 2. Instantiate each student
        roster[0] = new Student("Aman Sharma", 101, 88.5);
        roster[1] = new Student("Riya Patel", 102, 94.0);
        roster[2] = new Student("Karan Verma", 103, 67.5);

        double totalMarks = 0;
        Student topStudent = roster[0];

        // 3. Process records with a loop
        for (Student s : roster) {
            s.displayRecord();
            totalMarks += s.marks;

            if (s.marks > topStudent.marks) {
                topStudent = s;
            }
        }

        // 4. Summary metrics
        double average = totalMarks / roster.length;
        System.out.println("------------------------------------------------");
        System.out.printf("Total Students : %d%n", roster.length);
        System.out.printf("Class Average  : %.2f%n", average);
        System.out.printf("Top Scorer     : %s (%.1f marks)%n", topStudent.name, topStudent.marks);
        System.out.println("================================================");
    }
}
