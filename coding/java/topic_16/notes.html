Section 1

What Is a String in Java?

In Java, a String is an object that represents a sequence of characters. While primitive types like int, double, or char hold individual raw values (such as the single letter 'A' or the number 42), text in software almost always consists of multiple characters grouped together—such as names, messages, addresses, and email IDs.

📖 The Real-World Name Tag Analogy

Think of a String variable as a labelled name tag. The tag itself (the variable) is just a label pinned to a specific written message (the String object in memory). If you have a tag labelled name pointing to the text "Shailendra", the tag lets your program refer to, inspect, and use that written message whenever needed.

Visual 1: The String Conceptual Model (Variable → Reference Pointer → Heap Object)

Figure 1.1: The variable `name` stored on the Stack holds a memory reference pointing to the actual `"Shailendra"` text object stored in Heap memory.

FirstStringDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        // Declaring and initializing a String variable
        String name = "Shailendra";

        // Printing the String to the console
        System.out.println(name);
    }
}
▶ Program Output 
Shailendra

Step-by-Step Execution Trace

  1. String name = "Shailendra";: The JVM identifies the text literal "Shailendra" enclosed in double quotes. It ensures an immutable String object exists in memory and assigns its reference address to the variable name.
  2. System.out.println(name);: The JVM dereferences the pointer in name, retrieves the character sequence, and prints Shailendra followed by a newline.

Why Does Java Use a Full Class for Strings?

In languages like C, strings are merely null-terminated arrays of raw bytes (char[]) requiring manual memory tracking and prone to security buffer overflows.

In Java, java.lang.String is a first-class object with powerful benefits:

  • Rich Built-in Methods: Search, replace, slice, compare, and transform text using safe, pre-tested standard library methods.
  • Automatic Memory Management: You never have to manually allocate or deallocate string buffers; the JVM Garbage Collector manages memory safely.
  • Immutability & Security: Text objects cannot be corrupted after creation, safeguarding file paths, database URLs, and network credentials.
Section 2

Creating Strings: String Literals vs. new String()

In Java, there are two primary ways to create a String object: using a String literal or using the new keyword constructor. Understanding the difference is crucial for memory efficiency.

The Two Creation Approaches

  • Approach A — String Literal: String s = "Java";
    Enclosed in double quotes. The JVM checks the String Constant Pool. If an identical string already exists in the pool, it simply reuses the existing instance without allocating new memory!
  • Approach B — Using the new Constructor: String s = new String("Java");
    Forces the JVM to explicitly allocate a separate new object directly in regular Heap memory outside the pool, even if an identical literal already exists.
Visual 2: String Literal (Shared in Pool) vs. Constructor (Separate Heap Object)

Figure 2.1: `first` and `second` share the exact same pooled literal object, whereas `third` points to a distinct, independently allocated Heap object.

CreateStringsDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        // String Literals (Recommended)
        String first = "Java";
        String second = "Java";

        // Constructor Creation (Discouraged unless explicitly required)
        String third = new String("Java");

        System.out.println("first == second: " + (first == second)); // true (same reference)
        System.out.println("first == third:  " + (first == third));  // false (different objects)
        System.out.println("first.equals(third): " + first.equals(third)); // true (same text)
    }
}
▶ Program Output 
first == second: true
first == third:  false
first.equals(third): true

Reference Equality (==) true when comparing identical literals false when comparing separate objects

Section 3

The String Constant Pool (Memory Optimization)

The String Constant Pool (SCP) is a special dedicated cache inside the JVM Heap memory. Because strings are used ubiquitously across software, storing duplicate copies of identical strings would squander vast amounts of memory.

Visual 3: String Constant Pool Deduplication & Literal Reuse

Figure 3.1: Variables `s1`, `s2`, and `s3` all point to a single pooled instance of `"CodeVerse"`, avoiding redundant memory allocations.

StringPoolDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        String a = "CodeVerse";
        String b = "CodeVerse";
        String c = new String("CodeVerse");

        System.out.println(a == b);        // true (both share the pooled instance)
        System.out.println(a == c);        // false (c is a separate Heap object)
        System.out.println(a.equals(c));   // true (both contain identical text)
    }
}
▶ Program Output 
true
false
true
💡 The intern() Method

Java provides the method c.intern(). When called on a String object, intern() checks the pool:

  • If the pool already contains an identical string, it returns the pooled reference.
  • If not, it adds the string to the pool and returns that reference.
String c = new String("CodeVerse");
String pooledRef = c.intern();
System.out.println(a == pooledRef); // true!
Section 4

String Immutability (A Fundamental Architectural Pillar)

In Java, the String class is immutable. This means that once a String object is created in memory, its character contents can never be modified or rewritten.

⚠ The Real-World Printed Ticket Analogy

Imagine an airplane boarding pass printed with the flight destination "Mumbai". You cannot erase or overwrite the ink on that physical paper pass. If you change your flight to "Delhi", the airline cannot alter the existing pass in place; they must print a brand-new ticket and hand it to you.

Similarly, in Java, String methods like toUpperCase(), replace(), or concat() never modify the original string. Instead, they produce and return a completely new String object!

Visual 4: String Immutability and Reference Redirection

Figure 4.1: Calling `language.toUpperCase()` creates a new object `"JAVA"`. If not assigned back to `language`, the returned object is ignored and `language` still points to `"java"`.

ImmutabilityDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        String language = "java";

        // Experiment 1: Calling method without saving return value
        language.toUpperCase();
        System.out.println(language); // Prints "java" (original is unmodified!)

        // Experiment 2: Reassigning the variable to capture the new object
        language = language.toUpperCase();
        System.out.println(language); // Prints "JAVA" (variable points to new object)
    }
}
▶ Program Output 
java
JAVA
Visual 24: Four Architectural Reasons Why String Is Immutable in Java

Figure 4.2: Immutability enables string constant pool deduplication, guarantees system security, provides free multi-threaded safety, and caches hashCodes for blazing-fast HashMap lookups.

Comparison: Mutable vs. Immutable Objects

Property Immutable Object (e.g. String) Mutable Object (e.g. StringBuilder)

Transformation Methods Always return a new object Modify the existing internal buffer

Section 5

== Versus .equals(): Reference Identity vs. Content Equality

One of the most notorious mistakes for Java beginners is using == to compare text. In Java, == tests reference identity (whether two variables point to the exact same memory address), whereas .equals() tests character content equality.

Visual 5: `==` (Reference Identity) vs. `.equals()` (Character Content Equality)

Figure 5.1: `x` and `y` are two separate objects on the heap. `x == y` evaluates to false because their memory addresses differ, but `x.equals(y)` evaluates to true because their character sequences match identically.

EqualityComparisonDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        String x = new String("Java");
        String y = new String("Java");

        System.out.println("x == y: " + (x == y));             // false (different heap addresses)
        System.out.println("x.equals(y): " + x.equals(y));     // true (identical character sequences)
    }
}
▶ Program Output 
x == y: false
x.equals(y): true
⚠ Defensive Null-Safe Equality Check

If a String variable is null, invoking input.equals("Java") immediately throws a fatal NullPointerException.

The Pro Tip (Yoda Conditions): Always invoke .equals() on the guaranteed non-null literal! 

String input = null;

// RISKY: Throws NullPointerException if input is null
// if (input.equals("Java")) { ... }

// 100% SAFE: Evaluates to false cleanly without any exception!
System.out.println("Java".equals(input)); // Output: false
Section 6

String Length, Character Access & Zero-Based Indexing

Every character inside a String occupies a specific numerical position called an index. In Java, indexing is zero-based: the first character is always at index 0, and the last character is at index length() - 1.

Visual 6: Zero-Based Character Indexing Map for String "JAVA"

Figure 6.1: Valid character indexes for "JAVA" range strictly from 0 to 3. Attempting to access index 4 throws an out-of-bounds error.

CharAccessDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        String word = "JAVA";

        System.out.println("Total length: " + word.length());
        System.out.println("First character (index 0): " + word.charAt(0));
        System.out.println("Last character (index 3):  " + word.charAt(word.length() - 1));

        // The line below fails at runtime:
        // System.out.println(word.charAt(4)); 
        // Throws StringIndexOutOfBoundsException: Index 4 out of bounds for length 4
    }
}
▶ Program Output 
Total length: 4
First character (index 0): J
Last character (index 3):  A
Visual 7: UTF-16 Code Units vs. User-Perceived Characters (Emoji Surrogate Pairs)

Figure 6.2: Ordinary ASCII letters fit into one 16-bit `char`, but modern emojis (such as 🚀) require two 16-bit code units (a surrogate pair), making `emoji.length() == 2`.

Important Unicode Caveat for Modern Developers

In Java, the internal representation of characters uses UTF-16 code units. Because a char is strictly 16 bits (holding values up to 65,535), Unicode symbols with code points above U+FFFF (such as emojis, musical symbols, and historical scripts) are stored as two surrogate code units.

Therefore, "🚀".length() reports 2, not 1! For full Unicode code-point processing, Java provides codePointAt() and codePoints().

Section 7

Essential String Methods Explorer

The java.lang.String class provides over 60 built-in methods to inspect, search, compare, slice, and transform text. Because strings are immutable, remember that all transformation methods return a brand-new String object.

Visual 23: Essential String Method Categories

Figure 7.1: Overview of String method categories: Inspection, Searching, Comparison, and Transformation.

Visual 8: Substring Range Rule — substring(beginIndex, endIndex) [Inclusive, Exclusive)

Figure 7.2: For `"CODEVERSE"`, `substring(0, 4)` captures characters at index 0, 1, 2, and 3 ("CODE"). The character at endIndex (4) is excluded!

1. Basic Inspection Methods

  • int length(): Returns the total number of 16-bit code units in the string. 
    "CodeVerse".length(); // returns 9
  • boolean isEmpty(): Returns true if, and only if, length() == 0. 
    "".isEmpty();   // true
"  ".isEmpty(); // false (has spaces!)
  • boolean isBlank() (Java 11+): Returns true if the string is empty OR contains only whitespace code points. 
    "   ".isBlank(); // true (handles spaces, tabs, newlines!)

2. Character & Substring Access Methods

  • char charAt(int index): Returns the character at the specified zero-based index. 
    "Java".charAt(2); // returns 'v'
  • String substring(int beginIndex): Returns a new string from beginIndex all the way to the end. 
    "CodeVerse".substring(4); // returns "Verse"
  • String substring(int beginIndex, int endIndex): Returns text from beginIndex (inclusive) up to endIndex (exclusive). 
    "CodeVerse".substring(0, 4); // returns "Code"

3. Comparison Methods

  • boolean equals(Object anObject): Compares character-by-character content equality. Case-sensitive. 
    "java".equals("Java"); // false
  • boolean equalsIgnoreCase(String anotherString): Compares content ignoring uppercase/lowercase differences. 
    "java".equalsIgnoreCase("Java"); // true
  • int compareTo(String anotherString): Lexicographical (dictionary) comparison.
    • Returns a negative integer if this string precedes anotherString.
    • Returns zero if both strings have identical content.
    • Returns a positive integer if this string follows anotherString.
    "apple".compareTo("banana"); // negative (e.g. -1)
"cat".compareTo("cat");       // 0
"zebra".compareTo("apple");   // positive (e.g. 25)

4. Searching Methods

  • boolean contains(CharSequence s): Returns true if the specified substring exists anywhere within this string. 
    "CodeVerse".contains("Verse"); // true
  • int indexOf(String str): Returns the index of the first occurrence of the substring, or -1 if not found. 
    "banana".indexOf("na"); // returns 2
"banana".indexOf("xyz"); // returns -1
  • int lastIndexOf(String str): Returns the index of the last occurrence of the substring. 
    "banana".lastIndexOf("na"); // returns 4
  • boolean startsWith(String prefix): Checks if string begins with prefix. 
    "https://codeverse.com".startsWith("https://"); // true
  • boolean endsWith(String suffix): Checks if string ends with suffix. 
    "report.pdf".endsWith(".pdf"); // true

5. Transformation Methods (Returning New Strings)

  • String toUpperCase() / toLowerCase(): Returns a new copy with all letters converted to upper or lower case.
  • String trim(): Strips leading and trailing ASCII whitespace (characters <= U+0020).
  • String strip() (Java 11+): Modern Unicode-aware stripping; removes all Unicode whitespace characters.
  • String replace(CharSequence target, CharSequence replacement): Replaces all literal occurrences of a target sequence with a replacement. 
    "2026-10-25".replace("-", "/"); // "2026/10/25"
  • String replaceAll(String regex, String replacement): Replaces each substring matching the specified regular expression pattern. 
    "Order #123, Items: 4".replaceAll("\\d+", "[NUM]"); // "Order #[NUM], Items: [NUM]"
  • String concat(String str): Appends the specified string to the end of this string.

6. Splitting and Combining Methods

  • String[] split(String regex): Splits this string around matches of the given regular expression. 
    String[] fruits = "apple,banana,orange".split(",");
// fruits = ["apple", "banana", "orange"]
  • static String join(CharSequence delimiter, CharSequence... elements): Joins multiple strings together using a delimiter. 
    String csv = String.join(" - ", "Java", "Python", "Rust");
// "Java - Python - Rust"

Empty, Blank, and Null Strings: The Three Inactive States

Every Java programmer must distinguish between an empty string (""), a blank string (" "), and a null reference (null). Conflating these three states is a leading source of runtime bugs.

Visual 9: Comparing Empty String (""), Blank String (" "), and Null Reference

Figure 8.1: An empty string is a valid object with 0 characters; a blank string is a valid object containing only whitespace; null points to no object at all.

String b = " "; (Blank) Yes 3 false true
String c = null; (Null) No (Reference is empty) Throws NullPointerException Throws NullPointerException Throws NullPointerException
💡 The Robust Input Validation Pattern

To safely validate whether a user has provided meaningful input (such as an entered username or address), use short-circuit evaluation: 

public static boolean isInputValid(String input) {
    // 1. Checks if null first (prevents NullPointerException)
    // 2. Checks if blank (rejects empty or spaces-only text)
    return input != null && !input.isBlank();
}

String Concatenation: The + Operator & Evaluation Order

In Java, the plus operator (+) is overloaded: when applied to numbers, it performs arithmetic addition; when applied to at least one String, it performs String concatenation.

Visual 10: Left-to-Right Evaluation Order in String Concatenation

Figure 9.1: Expressions evaluate strictly from left to right unless overridden by parentheses.

ConcatEvaluationDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        // Line 1: String comes first -> 10 and 20 are converted to text sequentially
        System.out.println("Score: " + 10 + 20);

        // Line 2: Numbers come first -> 10 + 20 adds to 30 before string is encountered
        System.out.println(10 + 20 + " is the total");

        // Line 3: Parentheses force addition first
        System.out.println("Score: " + (10 + 20));
    }
}
▶ Program Output 
Score: 1020
30 is the total
Score: 30
⚠ The "Concatenation in Loops" Performance Trap

Never perform repeated + concatenation inside a loop over many iterations: 

// DANGEROUS: Allocates 10,000 intermediate String objects in Heap! O(N^2) time!
String result = "";
for (int i = 0; i < 10000; i++) {
    result += i;
}

Because String is immutable, each iteration creates a brand new string and copies all previous characters. For loops, always use StringBuilder!

StringBuilder: Mutable Character Buffers for High Performance

StringBuilder is a mutable sequence of characters. Unlike String, calling methods on a StringBuilder modifies its internal character buffer directly in place without allocating intermediate objects.

Visual 11: StringBuilder In-Place Mutation

Figure 10.1: `append()` and `insert()` mutate the existing buffer in memory, creating zero garbage collection overhead.

StringBuilderDemo.java Java 21 
public class Main {
    public static void main(String[] args) {
        StringBuilder message = new StringBuilder("Hello");

        message.append(" CodeVerse"); // Appends to end
        message.insert(5, ",");        // Inserts comma at index 5

        System.out.println(message);

        // Additional operations
        message.reverse();            // Reverses buffer in place
        System.out.println("Reversed: " + message);
    }
}
▶ Program Output 
Hello, CodeVerse
Reversed: esreVedoC ,olleH
Visual 12: StringBuilder Internal Array & Automatic Capacity Growth

Figure 10.2: StringBuilder begins with a default capacity of 16 characters. When capacity is exceeded, it automatically expands following `newCapacity = oldCapacity * 2 + 2`.

StringBuffer: Thread-Safe Synchronized Mutable Buffer

StringBuffer is identical in API to StringBuilder, with one crucial difference: almost all of its methods are marked with the synchronized keyword, making it thread-safe for concurrent multi-threaded environments.

Feature String StringBuilder StringBuffer
Mutability Immutable (Never changes in place) Mutable (Changes in place) Mutable (Changes in place)
Thread Safety Thread-Safe (Read-only immutable) Not Thread-Safe (No locks) Thread-Safe (Synchronized methods)
Performance Speed Fast for constants; Slow for loop concatenation Fastest (No synchronization overhead) Slower than StringBuilder due to locking
Introduced In Java 1.0 Java 5.0 Java 1.0

Section 16

Common Mistakes & Debugging Guide (14 Crucial Pitfalls)

Review these 14 common mistakes to avoid frustrating hours debugging string code.

Visual 21: Regex Escaping for split(".")

Figure 16.1: Passing unescaped `"."` to `split()` matches every character, returning an empty array! Always escape with `"\\."`.

Mistake 1

Using == to Compare Text Content

Comparing two String objects with == tests memory addresses, returning false even when the text is identical.

✗ Wrong 
if (input == "yes") { ... }
✓ Correct 
if ("yes".equalsIgnoreCase(input)) { ... }
Mistake 2

Forgetting That Strings Are Immutable

Assuming str.toUpperCase() alters str directly.

✗ Ignored Return Value 
String name = "aman";
name.toUpperCase(); // name is STILL "aman"!
✓ Reassign Result 
String name = "aman";
name = name.toUpperCase(); // now "AMAN"
Mistake 3

Using String Length as the Last Index

Calling str.charAt(str.length()) causes an immediate exception.

Fix: Remember zero-based indexing! The final index is always str.length() - 1.

Mistake 4

Assuming substring() End Index Is Included

Thinking str.substring(0, 3) returns 4 characters.

Rule: End index is exclusive. substring(0, 3) takes indexes 0, 1, and 2 (exactly 3 characters).

Mistake 5

Invoking Methods on a Null Reference

Calling str.length() or str.trim() when str == null crashes with NullPointerException.

Prevention: Always verify str != null before calling instance methods.

Mistake 6

Confusing isEmpty() with isBlank()

Checking " ".isEmpty() returns false because its length is 3!

Fix: Use " ".isBlank() (Java 11+) or str.trim().isEmpty().

Mistake 7

Naively Calling split(".") on a File Extension

In regular expressions, . matches any character. filename.split(".") consumes all characters.

Fix: Escape the dot: filename.split("\\.").

Mistake 8

Ignoring NumberFormatException During Parsing

Directly calling Integer.parseInt(userInput) without a try-catch block.

Fix: Always handle non-numeric inputs gracefully using try-catch.

Mistake 9

Assuming replaceAll() Is a Simple Literal Replacement

replace() performs literal replacement; replaceAll() interprets the target as a regular expression!

Rule: Use replace() unless you specifically need regex patterns.

Mistake 10

Expecting compareTo() to Return Only -1 or 1

Writing if (s1.compareTo(s2) == -1) is fragile because compareTo() can return any negative number (e.g. -32)!

Fix: Always check sign: if (s1.compareTo(s2) < 0).

Mistake 11

Using StringBuilder for Trivial One-Line Strings

Writing new StringBuilder().append("a").append("b").toString() for simple constants.

Rule: The Java compiler automatically optimizes simple constant concatenation into a single literal. Use StringBuilder only for loops!

Mistake 12

Concatenating in Loops with +=

Using += in a loop creates quadratic O(N²) memory allocations.

Fix: Instantiate StringBuilder before the loop and append.

Mistake 13

Assuming Every Unicode Glyph Is Exactly One char

Emojis and rare scripts take 2 char code units (surrogate pairs). charAt(0) extracts half an emoji!

Fix: Use code points API (s.codePoints()) for multi-byte Unicode.

Mistake 14

Misplaced Parentheses in String + Math

"Total: " + 10 + 20 evaluates to "Total: 1020".

Fix: Use parentheses: "Total: " + (10 + 20) → "Total: 30".

public class PalindromeDemo {
    public static boolean isPalindrome(String s) {
        if (s == null) return false;
        int left = 0, right = s.length() - 1;
        while (left < right) {
            if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right))) {
                return false;
            }
            left++;
            right--;
        }
        return true;
    }

Master Summary Cheat Sheet

  • Strings are Immutable: Once created, their contents never change. Transformation methods always return a new object.
  • String Pool: Literals are cached in memory for reuse; new String() forces separate allocations.
  • Equality Comparison: Always use .equals() for text content; == compares reference addresses.
  • Zero-Based Index: First character is charAt(0); last is charAt(length() - 1).
  • Substring Range: substring(start, end) is inclusive of start and exclusive of end.
  • StringBuilder: Mutable character buffer for high-performance string assembly in loops.
  • Defensive Null Safety: Call "target".equals(variable) to avoid NullPointerException.

Q1: What does String immutability mean in Java?

View Answer

Answer: It means that once a String object is created on the heap, its internal character sequence can never be modified. Any method that appears to modify a String actually returns a brand new String object.

Q2: What is the output of String s = "code"; s.toUpperCase(); System.out.println(s);?

View Answer

Answer: code. Because the return value of s.toUpperCase() was not reassigned back to s, s continues pointing to the original unmodified string.

Q3: Why does new String("Java") == new String("Java") evaluate to false?

View Answer

Answer: The == operator compares reference memory addresses. Each call to new String() allocates a distinct new object on the heap, so their references are different.

Q4: How does " ".isEmpty() differ from " ".isBlank()?

View Answer

Answer: isEmpty() returns false because length is 3. isBlank() (Java 11+) returns true because all 3 characters are whitespace.

Q5: What is the output of "Java".substring(1, 3)?

View Answer

Answer: "av". Index 1 ('a') and index 2 ('v') are included; index 3 ('a') is excluded.

Q6: What is printed by System.out.println("Result: " + 5 + 5);?

View Answer

Answer: Result: 55. Evaluation proceeds left to right: "Result: " + 5 produces "Result: 5", which then concatenates 5 to form "Result: 55".

Q7: What is the primary advantage of StringBuilder over String in loops?

View Answer

Answer: StringBuilder mutates its internal buffer in place without creating thousands of intermediate disposable String objects, avoiding O(N²) memory copying and GC pauses.

Q8: How does StringBuffer differ from StringBuilder?

View Answer

Answer: StringBuffer has synchronized methods, making it thread-safe for multi-threaded environments, but incurring locking performance overhead.

Q9: Why does "file.txt".split(".") return an empty array?

View Answer

Answer: split() accepts a regular expression, where unescaped . matches any character. Every character is treated as a delimiter. The correct code is "file.txt".split("\\.").

Q10: What exception occurs if you call Integer.parseInt("12.5")?

View Answer

Answer: NumberFormatException. parseInt expects an integer, not a floating-point decimal. Use Double.parseDouble("12.5") instead.

Q11: Why does an emoji like 🚀 have a length of 2 in Java?

View Answer

Answer: Java uses UTF-16 code units (16-bit char). Emojis exceed U+FFFF and must be represented using two surrogate code units.

Q12: How can you safely compare a variable str to "Admin" if str might be null?

View Answer

Answer: Write "Admin".equals(str). If str is null, it safely returns false without throwing a NullPointerException.

Q13: What does String.intern() do?

View Answer

Answer: It returns the canonical representation of the string from the String Constant Pool, adding it to the pool if it is not already present.

Q14: What is the output of "banana".indexOf("na", 3)?

View Answer

Answer: 4. The search starts from index 3, skipping the first "na" at index 2 and finding the second occurrence at index 4.

Q15: What format specifier formats a decimal number to 2 decimal places in String.format()?
