1. Introduction to Operators and Expressions

In Java, programs process, transform, and evaluate data through operators and expressions. Every calculation you make, every condition you check in an if statement, and every loop counter you increment relies fundamentally on this mechanism.

Core Definitions

Operator: A special symbol (such as +, -, *, >, ==) that commands the Java Virtual Machine (JVM) to perform a specific mathematical, relational, or logical manipulation.
Operand: The data item, variable, or literal value upon which an operator acts.
Expression: A syntactically valid construct composed of variables, literals, and operators that evaluates to a single value possessing a definite type.

Anatomy of an Expression

Consider the foundational Java declaration:

ExpressionAnatomy.java 
int result = 10 + 5;

Let us dissect every element of this statement:

  • 10 and 5 are operands (integer literals).
  • + is an arithmetic operator that instructs addition.
  • 10 + 5 is the expression. When evaluated by the JVM, it yields the single integer value 15.
  • = is the assignment operator, storing the evaluated result (15) into the variable result.
  • int result = 10 + 5; is a complete declaration statement terminated by a semicolon.
Figure 1.1: Conceptual breakdown of an expression: operands are combined by an operator to yield a typed result.

Expression vs. Statement: The Crucial Difference

Beginners frequently confuse expressions with statements. Understanding this distinction is vital for writing valid Java code:

Aspect Expression Statement
Definition A combination of tokens that computes and produces a single value. A complete sentence in Java that performs an execution step or action.
Value Yielded? Always. (e.g., 5 * 4 yields 20). Not necessarily. Represents an action, declaration, or control flow.
Semicolon Required? No semicolon by itself (e.g., x + 1). Terminated by a semicolon ; or enclosed in a block { }.
Where Usable? Anywhere a value of that type is expected (arguments, right-hand side of assignments, if conditions). As top-level executable instructions inside methods or initializer blocks.
Java Examples a > 10, Math.max(x, y), count++ int x = 10;, if (x > 5) { }, return;

Notice that some expressions can be made into statements simply by appending a semicolon. These are called expression statements in Java (such as assignment expressions x = 20;, increment/decrement expressions count++;, and method invocations System.out.println("Hi");).

2. Complete Classification of Java Operators

Java features a rich set of operators categorized along two distinct dimensions: by the number of operands they require, and by the semantic purpose of the operation.

Classification by Number of Operands

  • Unary Operators: Take exactly one operand (e.g., ++x, -y, !flag, ~mask).
  • Binary Operators: Take exactly two operands (e.g., a + b, x > y, p && q). The vast majority of Java operators are binary.
  • Ternary Operator: Takes exactly three operands (the conditional operator condition ? valueIfTrue : valueIfFalse). Java has exactly one ternary operator.
Categories Overlap by Design

Operator categories in Java are not mutually exclusive. For example, the logical NOT operator (!) is classified as both a unary operator (because it takes one operand) and a logical operator (because it inverts a boolean truth value). Similarly, & serves as a bitwise operator when applied to integers and a non-short-circuit logical operator when applied to booleans.

Overview of the 11 Major Operator Categories

The table below provides a panoramic view of all 11 operator categories defined in the Java Language Specification (JLS):

Category Operators Operands Primary Purpose Short Example
1. Arithmetic +, -, *, /, % Binary Performs standard mathematical computations and remainder division. int sum = 14 + 7;
2. Unary +, -, ++, --, !, ~ Unary Inverts signs, increments/decrements values, or negates bits and booleans. int next = ++count;
3. Relational <, >, <=, >= Binary Compares numerical magnitude, yielding a boolean result. boolean ok = age >= 18;
4. Equality ==, != Binary Tests equality or inequality of primitives or reference memory identities. if (score == 100)
5. Logical &&, ||, ! Binary / Unary Combines boolean expressions with short-circuit evaluation guarantees. if (valid && active)
6. Assignment = Binary Evaluates right-hand expression and assigns the result to a variable. int speed = 60;
7. Compound Assignment +=, -=, *=, /=, %=, &=, |=, ^=, <<=, >>=, >>>= Binary Applies operation and reassigns with an automatic implicit cast. balance += deposit;
8. Bitwise &, |, ^, ~ Binary / Unary Manipulates individual binary bits of integer types (byte, short, int, long, char). int masked = val & 0x0F;
9. Shift <<, >>, >>> Binary Shifts bits left, signed right (sign-extended), or unsigned right (zero-filled). int doubled = x << 1;
10. Conditional (Ternary) ?: Ternary Evaluates a boolean condition and returns one of two alternative expressions. int max = (a > b) ? a : b;
11. Type Comparison instanceof Binary Tests whether an object reference is an instance of a specified type. if (obj instanceof String)

3. Arithmetic Operators & Division Nuances

Java provides five core arithmetic operators for numerical calculations:

Operator Name Operation Performed Example (a = 10, b = 3) Result
+ Addition Adds two numeric operands; also concatenates strings. a + b 13
- Subtraction Subtracts the right operand from the left operand. a - b 7
* Multiplication Multiplies two numeric operands. a * b 30
/ Division Divides numerator by denominator (truncating if both operands are integers). a / b 3
% Remainder (Modulo) Computes the integer remainder left over after integer division. a % b 1

The Integer Division Trap

One of the most frequent beginner bugs in Java involves dividing two integer types. In Java, when both operands to / are integers (such as int, byte, short, or long), Java performs integer division.

Integer division discards (truncates) the fractional part entirely. It does not round to the nearest whole number:

DivisionComparison.java 
public class DivisionComparison {
    public static void main(String[] args) {
        System.out.println(10 / 3);     // Integer division: truncates to 3
        System.out.println(10.0 / 3);   // Floating-point division: 3.3333333333333335
        System.out.println(10 / 3.0);   // Floating-point division: 3.3333333333333335
        System.out.println(10 % 3);     // Remainder: 1
    }
}
Execution Output
3 3.3333333333333335 3.3333333333333335 1
The "Assigning to double" Myth

Writing double average = 10 / 3; still produces 3.0, NOT 3.3333! Why? Because Java evaluates the right-hand side expression 10 / 3 first using two integers, resulting in 3. Only after the division completes is 3 widened to 3.0.

The Fix: Ensure at least one operand is floating-point: double average = 10.0 / 3; or explicitly cast one operand: double average = (double) 10 / 3;.

The Remainder Operator (%) and Negative Operands

The % operator in Java yields the remainder of division, satisfying the formal mathematical identity:

a % b = a - (a / b) * b

A vital rule in Java is that the sign of the remainder is always identical to the sign of the left operand (the dividend). The sign of the right operand (the divisor) has zero effect on the result:

RemainderSigns.java 
public class RemainderSigns {
    public static void main(String[] args) {
        System.out.println(" 10 %  3 = " + ( 10 %  3));  //  1
        System.out.println(" 10 % -3 = " + ( 10 % -3));  //  1 (divisor sign ignored)
        System.out.println("-10 %  3 = " + (-10 %  3));  // -1 (follows dividend sign)
        System.out.println("-10 % -3 = " + (-10 % -3));  // -1 (follows dividend sign)
    }
}
Execution Output
10 % 3 = 1 10 % -3 = 1 -10 % 3 = -1 -10 % -3 = -1

Division by Zero: Integer vs. Floating-Point

How Java handles division by zero depends entirely on the data types involved:

  • Integer Division by Zero: If you divide an integer by literal 0 or an integer variable holding 0, Java throws an immediate runtime exception: java.lang.ArithmeticException: / by zero. Your program halts abruptly unless caught in a try-catch block.
  • Floating-Point Division by Zero: Java strictly implements IEEE 754 floating-point arithmetic. Dividing a floating-point number by 0.0 does not crash. Instead:
    • 10.0 / 0.0 evaluates to Infinity.
    • -10.0 / 0.0 evaluates to -Infinity.
    • 0.0 / 0.0 evaluates to NaN ("Not a Number").

Integer Overflow During Arithmetic

Java primitives have fixed bit-widths. A 32-bit signed int holds values from -2,147,483,648 to +2,147,483,647. If an arithmetic computation exceeds these boundaries, Java does not automatically promote the result to long. Instead, it wraps around silently according to two's-complement arithmetic:

OverflowDemo.java 
public class OverflowDemo {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE; // 2,147,483,647
        int overflowed = max + 1;
        System.out.println("Integer.MAX_VALUE: " + max);
        System.out.println("After adding 1:   " + overflowed);
    }
}
Execution Output
Integer.MAX_VALUE: 2147483647 After adding 1: -2147483648

To prevent overflow in calculations that exceed 2 billion, use long variables or explicitly cast operands: long bigResult = (long) a * b;.

Practical Example: Restaurant Bill & Tip Calculation

Here is a complete, runnable program applying arithmetic operators, remainder division, and floating-point promotion to compute an itemized bill:

RestaurantBill.java 
public class RestaurantBill {
    public static void main(String[] args) {
        int appetizerPrice = 18;
        int mainCoursePrice = 45;
        int dessertPrice = 12;

        int subtotal = appetizerPrice + mainCoursePrice + dessertPrice; // 75
        double taxRate = 0.085; // 8.5%
        double tipRate = 0.15;  // 15%

        double tax = subtotal * taxRate;
        double tip = subtotal * tipRate;
        double grandTotal = subtotal + tax + tip;

        int numberOfGuests = 4;
        double costPerGuest = grandTotal / numberOfGuests;

        System.out.println("Subtotal:       $" + subtotal);
        System.out.println("Sales Tax:      $" + tax);
        System.out.println("Tip (15%):      $" + tip);
        System.out.println("Grand Total:    $" + grandTotal);
        System.out.println("Cost Per Guest: $" + costPerGuest);

        // Splitting whole cookies among guests using remainder
        int totalCookies = 14;
        int cookiesPerGuest = totalCookies / numberOfGuests;
        int remainingCookies = totalCookies % numberOfGuests;

        System.out.println("Cookies Each:   " + cookiesPerGuest);
        System.out.println("Leftover Box:   " + remainingCookies);
    }
}
Execution Output
Subtotal: $75 Sales Tax: $6.375 Tip (15%): $11.25 Grand Total: $92.625 Cost Per Guest: $23.15625 Cookies Each: 3 Leftover Box: 2

4. Unary Operators & Prefix/Postfix Deep Dive

Unary operators operate on a single operand. They perform essential tasks such as sign inversion, incrementing/decrementing counters, logical negation, and bit inversion:

Operator Name Description Example (x = 5) Result
+ Unary Plus Indicates a positive value; performs unary numeric promotion to int. +x 5
- Unary Minus Negates the sign of an arithmetic expression. -x -5
++ Increment Increases the value of an integer or floating-point variable by 1. ++x or x++ 6
-- Decrement Decreases the value of an integer or floating-point variable by 1. --x or x-- 4
! Logical Complement Inverts the boolean truth value (true becomes false and vice versa). !(x > 0) false
~ Bitwise Complement Inverts all bits of an integral operand (in two's complement, ~x = -(x + 1)). ~x -6

Prefix vs. Postfix: The Mechanics of Increment and Decrement

Both prefix (++a) and postfix (a++) change the variable's value in memory by +1. The critical difference lies in when that change becomes visible to the enclosing expression:

The Golden Timing Rule

Prefix (++a, --a) — "Modify First, Then Use": The variable is incremented/decremented in memory before its value is fetched for evaluation in the surrounding expression.

Postfix (a++, a--) — "Use First, Then Modify": The variable's current original value is captured for use in the surrounding expression, and afterwards the variable in memory is incremented/decremented.

Let us verify this with two side-by-side programs and trace tables:

Case 1: Prefix Increment (++a)
int a = 5;
int b = ++a;

System.out.println("a: " + a);
System.out.println("b: " + b);
a: 6 b: 6
Case 2: Postfix Increment (a++)
int a = 5;
int b = a++;

System.out.println("a: " + a);
System.out.println("b: " + b);
a: 6 b: 5

Execution Trace Tables

Here is the exact step-by-step sequence executed inside the CPU and JVM stack for both cases:

Operation Step 1: Memory State Step 2: Value Provided to Expression Step 3: Variable Value in Memory Step 4: Variable b Receives
Prefix: b = ++a; a = 5 Increment executed first: a becomes 6 a = 6 b = 6
Postfix: b = a++; a = 5 Original value cached: yields 5 a increments to 6 b = 5

Tracing Complex Expressions: x++ + ++x

Consider this classic interview question:

IncrementExpressionTrace.java 
public class IncrementExpressionTrace {
    public static void main(String[] args) {
        int x = 5;
        int result = x++ + ++x;

        System.out.println("result: " + result);
        System.out.println("x:      " + x);
    }
}
Execution Output
result: 12 x: 7

Why is the result 12 and not 11 or 13? In Java, operands are strictly evaluated from left to right:

  1. Initially, x = 5.
  2. The addition operator + requires two operands: [LeftOperand] + [RightOperand].
  3. Evaluate Left Operand (x++): Because this is postfix, it evaluates to the current value of x (which is 5). Immediately following this evaluation, x increments in memory to 6.
  4. Evaluate Right Operand (++x): Now x is currently 6. Because this is prefix, x is immediately incremented to 7 in memory, and this new value (7) is yielded as the right operand.
  5. Compute Sum: The addition is performed: 5 + 7 = 12.
  6. The variable result is assigned 12, and x finishes with the value 7.
Software Engineering Best Practice

While Java guarantees deterministic left-to-right operand evaluation, writing expressions that modify and read the same variable multiple times (such as x++ + ++x) creates brittle, unreadable code. In professional production software, write separate, explicit statements:
x++; followed by int result = x + (x + 1);.

Variable Requirement (L-Value)

The increment and decrement operators can only be applied to a variable (a modifiable memory location). Applying them to literals, constants, or arbitrary expressions is a compile-time error:
5++; // COMPILE ERROR: unexpected type, required: variable, found: value
(x + 1)++; // COMPILE ERROR: unexpected type, required: variable, found: value

5. Relational and Equality Operators

Relational and equality operators test relationships between values, producing a boolean result (strictly true or false):

Operator Meaning True Condition Example (a = 20, b = 15) Result
< Less than Left operand is strictly smaller than right a < b false
> Greater than Left operand is strictly larger than right a > b true
<= Less than or equal to Left operand is smaller than or equal to right a <= 20 true
>= Greater than or equal to Left operand is larger than or equal to right b >= 18 false
== Equal to Both operands hold identical values or references a == 20 true
!= Not equal to Operands hold different values or references a != b true

The Critical Difference Between = and ==

Confusing assignment with equality is one of the most common beginner errors:

  • = is the assignment operator. It assigns the value on the right to the variable on the left (e.g., x = 10;).
  • == is the equality comparison operator. It compares two values and returns true or false (e.g., if (x == 10)).
Java's Type Safety Safeguard

In languages like C and C++, accidentally typing if (x = 5) silently overwrites x with 5 and evaluates to true (because 5 is non-zero).
In Java, this mistake is prevented at compile time! Because x = 5 produces an int, and Java strictly demands a boolean inside if (...), the Java compiler immediately rejects it with: "incompatible types: int cannot be converted to boolean".

Equality: Primitives vs. Reference Types

How == behaves depends entirely on whether you are comparing primitives or objects:

  • For Primitive Types: == compares literal bit patterns (values). 5 == 5 is true; 10.0 == 10 is true (due to promotion).
  • For Reference Types (Objects): == compares memory references (addresses), checking whether both reference variables point to the exact same object on the Heap!
StringComparisonDemo.java 
public class StringComparisonDemo {
    public static void main(String[] args) {
        String first = new String("Java");
        String second = new String("Java");

        // Reference identity comparison
        System.out.println("first == second:      " + (first == second));

        // Logical content comparison
        System.out.println("first.equals(second): " + first.equals(second));
    }
}
Execution Output
first == second: false first.equals(second): true
Never Use == for String Content

Even though first and second contain the identical text "Java", first == second is false because new String(...) allocated two distinct objects at different memory addresses on the Heap.

To check whether two strings contain the same characters, always use the .equals() method: first.equals(second).

6. Logical Operators & Short-Circuit Logic

Logical operators combine two or more boolean expressions to make compound decisions. Java provides three primary logical operators:

  • && (Conditional-AND / Short-circuit AND): Evaluates to true if and only if both operands are true.
  • || (Conditional-OR / Short-circuit OR): Evaluates to true if at least one operand is true.
  • ! (Logical NOT): Inverts the truth value of its single operand.

Complete Truth Tables

The tables below define the exact boolean outputs for all possible operand inputs:

Operand A Operand B A && B (AND) A || B (OR) !A (NOT)
true true true true false
true false false true false
false true false true true
false false false false true

Short-Circuit Evaluation: How Java Optimizes Decisions

In Java, the logical operators && and || employ short-circuit evaluation. This means the JVM evaluates the left operand first, and only evaluates the right operand if the overall outcome cannot be determined from the left operand alone:

  • Short-Circuit AND (&&): If the left operand is false, the entire expression cannot possibly be true. Therefore, Java immediately halts evaluation and returns false without evaluating the right operand!
  • Short-Circuit OR (||): If the left operand is true, the entire expression must be true. Therefore, Java immediately halts evaluation and returns true without evaluating the right operand!

The Classic Short-Circuit Guard: Preventing Division by Zero

Short-circuit evaluation is not just an optimization; it is a critical defensive programming tool used to safeguard against null pointers and division-by-zero crashes:

SafeDivisionGuard.java 
public class SafeDivisionGuard {
    public static void main(String[] args) {
        int number = 0;

        // SAFE: Short-circuiting prevents dividing by zero!
        if (number != 0 && (10 / number > 1)) {
            System.out.println("Condition is true");
        } else {
            System.out.println("Condition is false (Division avoided)");
        }
    }
}
Execution Output
Condition is false (Division avoided)

In the code above, number != 0 evaluates to false. Because && short-circuits, the right-hand operand (10 / number > 1) is never executed. If it were evaluated, the JVM would crash with an ArithmeticException: / by zero!

Short-Circuit (&&, ||) vs. Non-Short-Circuit (&, |)

Java also supports single ampersand (&) and single pipe (|) on boolean operands. When used with booleans, these are non-short-circuit logical operators:

Feature && and || (Conditional) & and | (Logical Boolean)
Short-Circuiting? Yes. Stops evaluating when outcome is certain. No. Always evaluates both operands unconditionally.
Safety Guards? Safe for null checks (str != null && str.length() > 0). Unsafe (would execute str.length() even if str == null).
Dual Role? Only works on boolean types. Works on boolean (logical) AND integer types (bitwise).
Recommended Use Standard choice for all conditional statements (if, while). Only when right-hand side side-effects are strictly required.

Real-World Example: Student Examination Eligibility

Here is a practical Java example combining multiple logical conditions:

ExamEligibility.java 
public class ExamEligibility {
    public static void main(String[] args) {
        int attendancePercentage = 82;
        boolean hasFeesPaid = true;
        boolean hasMedicalCertificate = false;

        // Eligible if fees are paid AND (attendance >= 75 OR medical certificate approved)
        boolean isEligible = hasFeesPaid && (attendancePercentage >= 75 || hasMedicalCertificate);

        System.out.println("Attendance:           " + attendancePercentage + "%");
        System.out.println("Fees Cleared:         " + hasFeesPaid);
        System.out.println("Medical Waiver:       " + hasMedicalCertificate);
        System.out.println("Exam Hall Clearance:  " + isEligible);
    }
}
Execution Output
Attendance: 82% Fees Cleared: true Medical Waiver: false Exam Hall Clearance: true

7. Assignment & Compound Assignment Operators

The assignment operator (=) is the fundamental operator used to store values into variables. It is right-associative, meaning the right-hand expression is evaluated completely before the resulting value is stored in the variable on the left: 

int x = 25; // 25 is evaluated and assigned to x
int a, b, c;
a = b = c = 50; // Evaluates right-to-left: c=50, then b=50, then a=50

Compound Assignment Operators

Java provides 11 compound assignment operators that combine a binary operation with assignment in a concise syntax:

Operator Name Usage Equivalent Longhand
+= Addition assignment x += y x = (type of x)(x + y)
-= Subtraction assignment x -= y x = (type of x)(x - y)
*= Multiplication assignment x *= y x = (type of x)(x * y)
/= Division assignment x /= y x = (type of x)(x / y)
%= Remainder assignment x %= y x = (type of x)(x % y)
&= Bitwise/Logical AND assignment x &= y x = (type of x)(x & y)
|= Bitwise/Logical OR assignment x |= y x = (type of x)(x | y)
^= Bitwise/Logical XOR assignment x ^= y x = (type of x)(x ^ y)
<<= Left shift assignment x <<= y x = (type of x)(x << y)
>>= Signed right shift assignment x >>= y x = (type of x)(x >> y)
>>>= Unsigned right shift assignment x >>>= y x = (type of x)(x >>> y)

The Vital Type Conversion Difference

Notice carefully in the table above that compound assignment is not simply a textual shorthand for x = x + y. According to the Java Language Specification (JLS §15.26.2), a compound assignment expression of the form:

E1 op= E2 is strictly equivalent to E1 = (T)((E1) op (E2))

where T is the type of variable E1. This means Java automatically inserts an implicit narrow cast back to the target type!

CompoundAssignmentCast.java 
public class CompoundAssignmentCast {
    public static void main(String[] args) {
        byte value = 10;

        // 1. Using compound assignment: COMPUTES CLEANLY!
        value += 5; // Java implicitly executes: value = (byte)(value + 5);
        System.out.println("value after += 5: " + value);

        // 2. Using explicit longhand: WILL NOT COMPILE!
        // value = value + 5; 
        // COMPILE ERROR: incompatible types: possible lossy conversion from int to byte
    }
}
Execution Output
value after += 5: 15

Why does value = value + 5 fail to compile? Because in Java, arithmetic on smaller integer types (byte, short, char) automatically promotes the operands to int. The sum value + 5 is an int, and Java prevents assigning a 32-bit int directly to an 8-bit byte without an explicit cast. However, value += 5 applies that cast automatically for you.

The Silent Overflow Hazard

Because compound assignment hides the narrowing cast, it can also hide unintended overflow:
byte b = 127;
b += 1; // Compiles cleanly, but b silently overflows to -128!

8. Bitwise Operators & Two's Complement

Bitwise operators act directly on the individual binary bits of integer primitives (byte, short, int, long, and char). In computer hardware and systems programming, bitwise operations are used for hardware registers, compression, graphics shaders, network protocols, and cryptographic ciphers:

Operator Name Bit Rule Example (a = 5, b = 3) Binary Result Decimal
& Bitwise AND 1 only if both bits are 1 a & b 0101 & 0011 = 0001 1
| Bitwise OR 1 if at least one bit is 1 a | b 0101 | 0011 = 0111 7
^ Bitwise XOR 1 if bits are different (exclusive) a ^ b 0101 ^ 0011 = 0110 6
~ Bitwise Complement Inverts all bits (0 → 1, 1 → 0) ~a ~(...0101) = ...1010 -6
Figure 1.2: Bit-level alignment and truth evaluation for 5 and 3 in Java.

Why Does ~5 Evaluate to -6? (Two's Complement Explained)

Every beginner is puzzled why inverting 5 does not yield -5. In Java, all integer types are signed and stored using Two's Complement:

  1. An int occupies 32 bits. The number 5 in binary is:
    00000000 00000000 00000000 00000101
  2. The bitwise NOT operator (~) flips every single bit (0 becomes 1, 1 becomes 0):
    11111111 11111111 11111111 11111010
  3. Notice that the leading bit (the sign bit) is now 1, meaning the value is a negative number.
  4. To find the decimal magnitude of a negative two's complement binary number, invert all bits and add 1:
    Invert: 00000000 00000000 00000000 00000101
    Add 1: 00000000 00000000 00000000 00000110 (which is 6).
  5. Since the sign bit was negative, the final value is -6.
Universal Formula for Bitwise Complement

For any integer x in Java:
~x = -(x + 1)
Therefore: ~5 = -(5 + 1) = -6, and ~(-10) = -(-10 + 1) = 9.

Section 09

9. Shift Operators (Signed vs. Unsigned)

Shift operators move the binary bit pattern of an integral operand to the left or right by a specified number of positions:

Operator Name Mechanism Positive Example (8) Negative Example (-8)
<< Left Shift Shifts bits left; fills vacated right positions with 0. (Equivalent to multiplying by 2n if no overflow occurs). 8 << 1 = 16 -8 << 1 = -16
>> Signed Right Shift (Arithmetic) Shifts bits right; preserves sign bit (fills vacated left positions with 0 if positive, 1 if negative). 8 >> 1 = 4 -8 >> 1 = -4
>>> Unsigned Right Shift (Logical) Shifts bits right; always fills left positions with 0 regardless of sign bit. 8 >>> 1 = 4 -8 >>> 1 = 2147483644

Signed Right Shift (>>) vs. Unsigned Right Shift (>>>)

The difference between >> and >>> becomes dramatically apparent when operating on negative integers:

ShiftComparisonDemo.java 
public class ShiftComparisonDemo {
    public static void main(String[] args) {
        int positive = 16;
        int negative = -16;

        System.out.println("positive >> 2:  " + (positive >> 2));   // 4
        System.out.println("positive >>> 2: " + (positive >>> 2));  // 4 (Identical for positive numbers)

        System.out.println("negative >> 2:  " + (negative >> 2));   // -4 (Sign preserved)
        System.out.println("negative >>> 2: " + (negative >>> 2));  // 1073741820 (Zero-filled!)
    }
}
Execution Output
positive >> 2: 4 positive >>> 2: 4 negative >> 2: -4 negative >>> 2: 1073741820

In negative >>> 2, shifting two zeros into the 31st and 30th bits turns the sign bit from 1 into 0, converting the negative number into an immense positive 32-bit integer!

The Shift Distance Masking Rule

What happens if you shift a 32-bit int by 32 positions (e.g., x << 32)? You might intuitively expect all bits to disappear, leaving 0. In Java, that is not what happens:

The JLS Masking Specification

For a 32-bit int, Java only uses the lowest 5 bits of the shift distance (equivalent to distance % 32).
For a 64-bit long, Java only uses the lowest 6 bits of the shift distance (equivalent to distance % 64).

Therefore:
5 << 32 is evaluated as 5 << (32 % 32) = 5 << 0 = 5 (completely unchanged!).
5 << 33 is evaluated as 5 << (33 % 32) = 5 << 1 = 10.

10. Conditional (Ternary) Operator

The conditional operator (?:) is the only operator in Java that accepts three operands. It acts as an inline, expression-based shorthand for an if-else construct:

booleanCondition ? expressionIfTrue : expressionIfFalse;

How Evaluation Works

  1. The booleanCondition is evaluated first.
  2. If true, expressionIfTrue is evaluated and becomes the overall result. expressionIfFalse is completely skipped.
  3. If false, expressionIfFalse is evaluated and becomes the overall result. expressionIfTrue is completely skipped.
TernaryDemo.java 
public class TernaryDemo {

12. Operator Precedence and Associativity

When an expression contains multiple operators, Java uses two fundamental rules to determine the exact order of calculation:

  • Precedence: Determines which operator is evaluated first when operators of different priority compete for operands (e.g., multiplication * binds tighter than addition +).
  • Associativity: Determines the order of evaluation when operators of equal precedence appear consecutively in an expression (either Left-to-Right or Right-to-Left).

Complete 15-Level Java Operator Precedence Hierarchy

The table below lists all Java operators ranked strictly from highest precedence (evaluated first) to lowest precedence (evaluated last):

Rank Category Operators Associativity
1 (Highest) Postfix expr++, expr-- Left to Right
2 Unary Prefix ++expr, --expr, +expr, -expr, ~, ! Right to Left
3 Cast & Object Creation (type), new Right to Left
4 Multiplicative *, /, % Left to Right
5 Additive +, - Left to Right
6 Shift <<, >>, >>> Left to Right
7 Relational <, >, <=, >=, instanceof Left to Right
8 Equality ==, != Left to Right
9 Bitwise AND & Left to Right
10 Bitwise XOR ^ Left to Right
11 Bitwise OR | Left to Right
12 Logical AND && Left to Right
13 Logical OR || Left to Right
14 Conditional (Ternary) ?: Right to Left
15 (Lowest) Assignment =, +=, -=, *=, /=, %=, &=, |=, ^=, <<=, >>=, >>>= Right to Left

Associativity: Left-to-Right vs. Right-to-Left

Notice that almost all binary operators in Java associate Left to Right. The only exceptions that associate Right to Left are:

  1. Unary prefix operators (e.g., ++ ++x is parsed right-to-left).
  2. The conditional ternary operator (e.g., a ? b : c ? d : e parses as a ? b : (c ? d : e)).
  3. All assignment operators (e.g., a = b = c = 10; assigns 10 to c, then b, then a).

Step-by-Step Expression Trace: 10 + 20 * 30 - 40 / 2

Let us trace how Java resolves an arithmetic expression with competing precedence:

Evaluation Step Sub-Expression Targeted Operation Reason Resulting Expression
Initial 10 + 20 * 30 - 40 / 2 Inspect operators: +, *, -, / 10 + 20 * 30 - 40 / 2
Step 1 20 * 30 * has higher precedence than + and - 10 + 600 - 40 / 2
Step 2 40 / 2 / has higher precedence than + and - 10 + 600 - 20
Step 3 10 + 600 + and - have equal precedence; evaluate Left-to-Right 610 - 20
Step 4 610 - 20 Perform remaining subtraction 590
The Power of Parentheses

Never force your team or future self to memorize 15 levels of precedence! Whenever an expression combines multiple operator categories, use explicit parentheses ( ). Parentheses remove all ambiguity and clearly document your programming intent:
int total = (quantity * unitPrice) + tax;

13. Type Promotion and Casting in Expressions

When operands of differing primitive types appear together in an expression, Java automatically performs Binary Numeric Promotion (JLS §5.6.2) to bring both operands to a common compatible type before performing the operation:

The 4 Strict JLS Numeric Promotion Rules
  1. If either operand is of type double, the other is converted to double.
  2. Otherwise, if either operand is of type float, the other is converted to float.
  3. Otherwise, if either operand is of type long, the other is converted to long.
  4. Otherwise, both operands are converted to int!

The byte + byte = int Trap

Notice Rule 4: even if both operands are smaller than int (i.e., byte, short, or char), Java unconditionally converts both of them to int before executing the operator!

14. Common Mistakes and Pitfalls

Here are 12 of the most pervasive bugs, syntax traps, and semantic misunderstandings encountered by Java developers working with operators:

1. Using == Instead of .equals() for String Comparison

The Mistake: Comparing string textual contents with == tests memory reference identity, not text equivalence.

Buggy Code: 
if (input == "yes") { ... } // Fails if input is a dynamic String
Correct Code: 
if ("yes".equals(input)) { ... } // Safe content check
2. Unintended Integer Division Truncation

The Mistake: Dividing two integer literals or variables discards fractional digits before assigning to a double.

Buggy Code: 
double avg = 10 / 4; // Yields 2.0, NOT 2.5!
Correct Code: 
double avg = 10.0 / 4; // Yields 2.5
3. Confusing Bitwise/Non-Short-Circuit (&) with Short-Circuit (&&)

The Mistake: Using & in conditional guards evaluates the right-hand operand even when the left check fails, causing crashes.

Buggy Code: 
if (str != null & str.length() > 0) // NullPointerException!
Correct Code: 
if (str != null && str.length() > 0) // Safe: short-circuits
4. Relying on Right-Hand Side Effects in Short-Circuit Expressions

The Mistake: Putting increment operations or method calls in the right operand of && or ||; they may never execute!

Buggy Code: 
if (false && ++count > 5) // count is NEVER incremented!
Correct Code: 
count++;
if (false && count > 5) // count reliably incremented first
5. The Self-Overwriting Postfix Trap: x = x++

The Mistake: Expecting x = x++; to increment x. In Java, it leaves x completely unchanged!

Buggy Code: 
int x = 5;
x = x++; // x evaluates to 5, increments to 6, then overwritten with 5!
Correct Code: 
int x = 5;
x++; // x becomes 6 cleanly
6. String Concatenation Precedence Trap

The Mistake: Forgetting that + evaluates Left-to-Right. If a String appears first, all subsequent + operations perform concatenation.

Buggy Code: 
System.out.println("Sum: " + 10 + 20); // Prints "Sum: 1020"
Correct Code: 
System.out.println("Sum: " + (10 + 20)); // Prints "Sum: 30"
7. Assuming ~x Evaluates to -x

The Mistake: Bitwise complement flips all bits in Two's Complement, which equals -(x + 1), not -x.

Faulty Expectation: 
int res = ~5; // Expecting -5
Actual Reality: 
int res = ~5; // Produces -6 because ~x = -(x + 1)
8. Silent Overflow in Compound Assignment

The Mistake: Compound operators insert implicit casts, masking dangerous arithmetic overflow across smaller numeric types.

Risky Code: 
byte b = 127;
b += 1; // Silently wraps to -128 without any warning!
Defensive Code: 
int sum = b + 1; // Preserve accuracy in int
if (sum <= Byte.MAX_VALUE) { b = (byte)sum; }
9. Byte/Short Arithmetic Without Casts

The Mistake: Forgetting that byte + byte evaluates to int.

Compile Error: 
byte a = 1, b = 2;
byte c = a + b; // Error: lossy conversion int to byte
Correct Code: 
byte a = 1, b = 2;
byte c = (byte)(a + b); // Explicit cast resolves it
10. Using >> When >>> is Needed for Negative Bitmasks

The Mistake: Signed right shift preserves the negative sign bit, creating infinite leading 1s instead of clearing bits.

Faulty Shift: 
int val = -8 >> 1; // Produces -4 (sign bit preserved)
Unsigned Shift: 
int val = -8 >>> 1; // Produces 2147483644 (zero-filled)
11. Shifting by 32 or More Positions

The Mistake: Expecting x << 32 to clear an integer to 0. Java applies shift % 32, leaving it completely unchanged.

Buggy Expectation: 
int cleared = 100 << 32; // Expecting 0
Actual Reality: 
int cleared = 100 << 32; // Produces 100 (100 << 0)
12. Assuming instanceof Throws NPE on Null

The Mistake: Writing redundant null checks before instanceof.

Redundant Code: 
if (obj != null && obj instanceof String) { ... }
Clean Idiomatic Code: 
if (obj instanceof String) { ... } // Inherently null-safe!

BitwisePermissionSystem.java 
public class BitwisePermissionSystem {
    // 4-bit permission flags (1, 2, 4, 8)
    public static final int READ    = 1 << 0; // 0001 (1)
    public static final int WRITE   = 1 << 1; // 0010 (2)
    public static final int EXECUTE = 1 << 2; // 0100 (4)
    public static final int DELETE  = 1 << 3; // 1000 (8)

    public static void main(String[] args) {
        // Grant READ and WRITE to editor
        int userPermissions = READ | WRITE; // 0001 | 0010 = 0011 (3)
        System.out.println("Initial user permissions bitmask: " + userPermissions);

        // Check for specific permissions using Bitwise AND
        boolean canRead = (userPermissions & READ) != 0;
        boolean canDelete = (userPermissions & DELETE) != 0;
        System.out.println("Can user READ?   " + canRead);
        System.out.println("Can user DELETE? " + canDelete);

        // Grant EXECUTE using Bitwise OR
        userPermissions |= EXECUTE; // 0011 | 0100 = 0111 (7)
        System.out.println("Permissions after adding EXECUTE: " + userPermissions);

        // Revoke WRITE using Bitwise AND with inverted mask
        userPermissions &= ~WRITE; // 0111 & ~(0010) = 0111 & 1101 = 0101 (5)
        System.out.println("Permissions after revoking WRITE: " + userPermissions);
    }
}

Correct Answer: 2147483647 (Integer.MAX_VALUE)

The binary for -1 in 32-bit two's complement is all 1s (11111111...). Shifting unsigned right by 1 replaces the leading sign bit with 0, resulting in 01111111 11111111 11111111 11111111, which is 231 - 1.

Because x > 5 is false, the && operator short-circuits. The right-hand operand ++y > 2 is never evaluated, leaving y unchanged at 5.

20. Summary and Key Takeaways

Mastery over Java operators enables you to write clean, predictable, and highly performant applications:

Essential Principles
  • Integer Division: Always truncates toward zero unless one operand is explicitly cast to double or float.
  • Prefix vs. Postfix: Prefix modifies then yields; postfix yields original value then modifies.
  • Equality: Use == for primitives; always use .equals() for object textual content.
  • Short-Circuiting: && and || skip evaluating right operands when left operand guarantees the result.
Architectural Rules
  • Numeric Promotion: Operations on byte, short, and char always promote to int first.
  • Compound Assignment: Automatically performs an implicit narrowing cast: E1 = (T)(E1 op E2).
  • Bitwise Complement: Inverts all 32 bits in two's complement, following ~x = -(x + 1).
  • Parentheses: Always disambiguate complex expressions with ( ) for clean, maintainable software.
