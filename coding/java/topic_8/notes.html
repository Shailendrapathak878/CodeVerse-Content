Section 01

1. Introduction to Loops and Iterations

Imagine you work at an e-commerce fulfillment warehouse. A delivery truck arrives with 500 packages. To process them, do you build 500 identical conveyor belts — one for each package? Of course not! You build one conveyor belt and run it repeatedly until all 500 packages are scanned.

In programming, that conveyor belt is a Loop. A loop allows you to write a block of code once and execute it dozens, thousands, or millions of times automatically.

📖 Core Definitions: Loop vs. Iteration

Loop: A control structure in Java that repeatedly executes a block of statements as long as a specified condition remains true.

Iteration: A single, complete pass or execution through the body of a loop. If a loop counts from 1 to 5, it performs exactly 5 iterations.

Why Manual Copy-Paste Code Fails at Scale

Suppose your task is to print the numbers 1 through 5. A beginner might write five separate lines:

ManualRepetition.java 
public class ManualRepetition {
    public static void main(String[] args) {
        System.out.println(1);
        System.out.println(2);
        System.out.println(3);
        System.out.println(4);
        System.out.println(5);
    }
}

Now imagine your instructor asks you to print numbers from 1 to 10,000! Would you copy and paste 10,000 lines? What if the requirement changes to print only even numbers? You would have to manually edit thousands of lines.

With a loop, the exact same task requires just 3 lines of code:

LoopRepetition.java 
public class LoopRepetition {
    public static void main(String[] args) {
        for (int i = 1; i <= 5; i++) {
            System.out.println(i);
        }
    }
}
💻 Expected Output
1 2 3 4 5

Every loop must have a defined stopping condition. Without a stopping condition, the conveyor belt runs endlessly, freezing your computer — an error known as an infinite loop.

Section 02

2. Anatomy of a Loop (The 4 Core Pillars)

Regardless of which loop type you use in Java — for, while, or do-while — every working loop relies on four foundational components:

  1. Initialization: Sets up the loop counter variable with its initial starting value (e.g. int i = 1;). This step runs only once at the very beginning.
  2. Condition: A boolean expression (e.g. i <= 5) evaluated before each iteration. If true, the loop body runs. If false, the loop terminates immediately.
  3. Loop Body: The set of statements enclosed within curly braces { ... } that perform the actual work during each iteration.
  4. Update Expression: Modifies the counter variable (e.g. i++) at the end of each iteration to move it progressively toward the termination condition.

The Step-by-Step Execution Sequence

Let us trace what Java's JVM does under the hood for for (int i = 1; i <= 5; i++) { System.out.println(i); }:

Iteration # i Before Body Condition (i <= 5) Action / Output Update (i++) i After Update
1 1 1 <= 5 → TRUE Prints 1 1 + 1 2
2 2 2 <= 5 → TRUE Prints 2 2 + 1 3
3 3 3 <= 5 → TRUE Prints 3 3 + 1 4
4 4 4 <= 5 → TRUE Prints 4 4 + 1 5
5 5 5 <= 5 → TRUE Prints 5 5 + 1 6
Exit Check 6 6 <= 5 → FALSE! Loop Body Skipped — 6 (Loop Terminates 🛑)
💡 Critical Beginner Takeaway

Notice row 6: When the loop stops, i has reached 6! The condition 6 <= 5 evaluates to false, which halts execution. The body ran exactly 5 times, but the counter variable reached 6.

Section 03

3. The while Loop (Entry-Controlled)

The while loop is an entry-controlled loop (also called a pre-test loop). It evaluates its boolean condition before entering the loop body. If the condition is true, the body runs; if false, the loop body is bypassed entirely.

Syntax of while

WhileSyntax.java 
// 1. Initialization (happens outside the loop)
int counter = 1;

// 2. Condition evaluated at the entry gate
while (counter <= 5) {
    // 3. Loop Body
    System.out.println(counter);

    // 4. Update (MUST be inside the body!)
    counter++;
}

Standard Counting Example

WhileCountDemo.java 
public class WhileCountDemo {
    public static void main(String[] args) {
        int i = 1;

        while (i <= 5) {
            System.out.println(i);
            i++;
        }
    }
}
💻 Expected Output
1 2 3 4 5

The Zero-Iteration Scenario

Because the while loop tests its condition at the entry gate, if the condition starts out false, the body will execute zero times:

ZeroIterationWhile.java 
public class ZeroIterationWhile {
    public static void main(String[] args) {
        int i = 10;

        while (i < 5) { // 10 < 5 is immediately FALSE!
            System.out.println("This will never print: " + i);
            i++;
        }

        System.out.println("Finished");
    }
}
💻 Expected Output
Finished
⚠ Common While Loop Pitfall: Forgetting Update

If you forget i++; inside the loop body, i will remain 1 forever. The condition 1 <= 5 will always be true, freezing your program in an infinite loop!

Section 04

4. The do-while Loop (Exit-Controlled)

The do-while loop is an exit-controlled loop (also called a post-test loop). Unlike while, it executes the loop body first and only checks the condition at the exit gate.

Because the check occurs at the end, a do-while loop is guaranteed to execute at least once, even if the condition is false right from the start!

Syntax of do-while

DoWhileSyntax.java 
int i = 1;

do {
    System.out.println(i);
    i++;
} while (i <= 5); // <-- NOTICE THE MANDATORY SEMICOLON!
⚠ Syntax Trap: The Semicolon is Mandatory!

In Java, standard while and for loops do NOT have semicolons after their conditions. However, the do-while loop must end with a semicolon after while (condition);. Forgetting this semicolon results in a compilation error: ';' expected.

Standard Counting with do-while

DoWhileCountDemo.java 
public class DoWhileCountDemo {
    public static void main(String[] args) {
        int i = 1;

        do {
            System.out.println(i);
            i++;
        } while (i <= 5);
    }
}
💻 Expected Output
1 2 3 4 5

The Essential Comparison: Initial False Condition

What happens if i = 10 and the condition is i < 5? Let us see the dramatic difference between while and do-while:

DoWhileAtLeastOnce.java 
public class DoWhileAtLeastOnce {
    public static void main(String[] args) {
        int i = 10;

        do {
            System.out.println("Executed once: " + i);
            i++;
        } while (i < 5);
    }
}
💻 Expected Output
Executed once: 10

When to use do-while: Perfect for situations where an action must happen at least once before asking the user whether to repeat — such as showing an interactive ATM menu or asking: "Enter your password:".

Section 05

5. The for Loop & Order of Execution

When you know in advance exactly how many times a loop should repeat, the for loop is the cleanest, most concise, and most popular choice in Java. It packages initialization, condition, and update together into a single readable header.

Syntax of for

ForSyntax.java 
for (initialization; condition; update) {
    // repeated statements
}

Forward Counting Example

ForCountDemo.java 
public class ForCountDemo {
    public static void main(String[] args) {
        for (int i = 1; i <= 5; i++) {
            System.out.println(i);
        }
    }
}
💻 Expected Output
1 2 3 4 5

Essential Variations of the for Loop

Variation A: Counting Backwards (Countdown)

Initialize to the high number, test with >=, and decrement with i--:

CountdownDemo.java 
for (int i = 5; i >= 1; i--) {
    System.out.println(i);
}
💻 Expected Output
5 4 3 2 1

Variation B: Stepping by Two (Even Numbers)

Instead of i++, update the counter with compound assignment i += 2:

StepTwoDemo.java 
for (int i = 2; i <= 10; i += 2) {
    System.out.println(i);
}
💻 Expected Output
2 4 6 8 10

Variation C: Zero-Based Counting (Array Index Preview)

Starting at 0 and running while i < 5 repeats exactly 5 times (indices 0, 1, 2, 3, 4):

ZeroBasedDemo.java 
for (int i = 0; i < 5; i++) {
    System.out.println("Index: " + i);
}
💻 Expected Output
Index: 0 Index: 1 Index: 2 Index: 3 Index: 4

6. Comparing for, while, and do-while

In Java, any problem that can be solved with one loop can theoretically be solved with any of the other two. However, each loop is optimized for specific use cases:

Feature for Loop while Loop do-while Loop
Control Type Entry-Controlled (Pre-test) Entry-Controlled (Pre-test) Exit-Controlled (Post-test)
Condition Check Before entering body Before entering body After executing body
Minimum Iterations 0 (can skip completely) 0 (can skip completely) 1 (guaranteed at least once)
Structure Compact: init, check, update in header Init before loop; update inside body Body runs first; check at end with ;
Best Used When... Exact iteration count is known in advance Repetition depends on an ongoing condition Action must run once before testing condition

Equivalent Code: Printing 1 to 3 in All Three Loops

Notice how all three produce the exact same console output:

For Loop (Best for counting)
for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}
While Loop (Flexible condition)
int i = 1;
while (i <= 3) {
    System.out.println(i);
    i++;
}
Do-While Loop (Guaranteed run)
int i = 1;
do {
    System.out.println(i);
    i++;
} while (i <= 3);
Section 07

7. Iteration-by-Iteration Tracing (Manual Memory Tracing)

The single most important superpower of a professional programmer is the ability to trace a loop on paper. Instead of guessing what a loop will do, you track variable values across each iteration row by row.

The Accumulator Example

AccumulatorTraceDemo.java 
public class AccumulatorTraceDemo {
    public static void main(String[] args) {
        int total = 0;

        for (int i = 1; i <= 4; i++) {
            total += i; // equivalent to: total = total + i;
        }

        System.out.println("Final total = " + total);
    }
}
💻 Expected Output
Final total = 10

Step-by-Step Manual Trace Table

Here is how Java tracks i and total across time:

Iteration Counter i total Before Body Operation Performed total After Body Next Condition (i <= 4)
Pre-loop — 0 (initial) Initialization: total = 0, i = 1 0 1 <= 4 → TRUE
Iteration 1 1 0 total = 0 + 1 1 2 <= 4 → TRUE
Iteration 2 2 1 total = 1 + 2 3 3 <= 4 → TRUE
Iteration 3 3 3 total = 3 + 3 6 4 <= 4 → TRUE
Iteration 4 4 6 total = 6 + 4 10 5 <= 4 → FALSE!
Loop Exit 5 10 Loop terminates — proceeds to println 10 Halts and prints 10
💡 Why is the output 10 and not 4?

Beginners sometimes mistake the loop counter (which finishes at 4 or 5) for the accumulated result. The variable total acts like a piggy bank: it keeps adding the current coin i to its previous sum, growing continuously: 0 → 1 → 3 → 6 → 10.

Section 08

8. Nested Loops (Multi-Dimensional Repetition)

A Nested Loop is simply a loop inside another loop. Think of an analog clock: for every single hour that passes on the hour hand, the minute hand must complete all 60 minutes!

The Golden Rule of Nested Loops: The inner loop completely restarts and runs through all its iterations for every single iteration of the outer loop.

NestedLoopDemo.java 
public class NestedLoopDemo {
    public static void main(String[] args) {
        // Outer loop controls ROWS (i = 1 to 3)
        for (int i = 1; i <= 3; i++) {
            // Inner loop controls COLUMNS (j = 1 to 2)
            for (int j = 1; j <= 2; j++) {
                System.out.println("i = " + i + ", j = " + j);
            }
        }
    }
}
💻 Expected Output
i = 1, j = 1 i = 1, j = 2 i = 2, j = 1 i = 2, j = 2 i = 3, j = 1 i = 3, j = 2

Calculating Total Executions

For simple nested loops without break, the total number of body executions is:

Total Executions = (Outer Iterations) × (Inner Iterations) = 3 × 2 = 6

⚠ Performance Caution: Nested Loop Explosions

Nested loops multiply computational work quickly! An outer loop of 1,000 steps containing an inner loop of 1,000 steps executes 1,000,000 times. Three nested loops of 1,000 steps would require 1,000,000,000 operations — enough to freeze a CPU for several seconds!

Section 09

9. The break Statement (Emergency Exit)

The break keyword immediately halts the execution of the nearest enclosing loop and transfers control to the first statement outside and after the loop block.

Think of pulling an emergency brake on a train: the train stops immediately right where it is, abandoning all remaining stops.

BreakDemo.java 
public class BreakDemo {
    public static void main(String[] args) {
        for (int i = 1; i <= 10; i++) {
            if (i == 5) {
                System.out.println("Breaking at i = " + i);
                break; // STOPS THE LOOP PERMANENTLY!
            }
            System.out.println(i);
        }

        System.out.println("Loop finished safely.");
    }
}
💻 Expected Output
1 2 3 4 Breaking at i = 5 Loop finished safely.

Important Nuances of break

  • 5 is NOT printed: The break statement triggered before System.out.println(i);, so 5 was never displayed.
  • Values 6 through 10 are completely skipped: The loop was permanently terminated, not merely paused.
  • Behavior in Nested Loops: break only exits the innermost loop in which it resides. The outer loop will continue with its next iteration unless labeled break is used!
Section 10

10. The continue Statement (Skip Current Step)

While break quits the loop entirely, the continue keyword only skips the remainder of the current iteration and jumps directly to prepare the next iteration.

Think of turning the page in a book: if you find page 3 boring, you skip to page 4 — you do not throw the book into the trash!

ContinueDemo.java 
public class ContinueDemo {
    public static void main(String[] args) {
        for (int i = 1; i <= 5; i++) {
            if (i == 3) {
                continue; // Skips printing 3!
            }
            System.out.println(i);
        }
    }
}
💻 Expected Output
1 2 4 5

Critical Loop-Specific Distinction for continue

Where does Java jump when continue is encountered?

  • In a for loop: Control jumps straight to the update expression (e.g. i++), and then checks the condition.
  • In a while or do-while loop: Control jumps straight to the condition check!
⚠ The Deadly While + Continue Infinite Loop Bug

In a while loop, if you put continue; before your counter update i++;, the counter will NEVER advance! 

int i = 1;
while (i <= 5) {
    if (i == 3) continue; // BUG: Jumps to (i <= 5) without executing i++!
    System.out.println(i);
    i++;
}

Because i remains 3, it loops endlessly. To fix this, always increment i++; before continue; in while loops.

Section 11

11. Infinite Loops and Safe Termination

An Infinite Loop occurs when a loop's stopping condition can never evaluate to false. As a result, the loop consumes 100% of a CPU core and will never stop on its own.

Top 5 Causes of Unintentional Infinite Loops

  1. Forgetting the counter update: while (i <= 5) { println(i); } (missing i++).
  2. Updating in the wrong direction: for (int i = 1; i <= 5; i--) (counting down moves further away from 5!).
  3. Accidental semicolon after loop header: while (i <= 5); (creates an empty loop body that spins endlessly).
  4. Impossible stopping condition: for (int i = 1; i != 10; i += 2) (starts at 1, goes 1, 3, 5, 7, 9, 11... never equals 10!).
  5. Continue skipping update in while loop (as demonstrated in Section 10).
🛡 5-Step Safe Loop Debugging Checklist
  • 1. Trace the start: Does the counter initialize to the right value?
  • 2. Inspect the update: Does i++ or i-- move *toward* the stopping threshold?
  • 3. Check the comparison operator: Are you using <= instead of != so it doesn't overshoot?
  • 4. Check loop headers: Ensure no stray ; appears directly after for (...) or while (...).
  • 5. Use safety limits during development: If code is risky, add if (loopCount > 1000) break; while debugging.
Section 12

12. Off-by-One Errors and Boundary Conditions

An Off-by-One Error (OBOE) is one of the most famous bugs in computer science. It occurs when a loop executes one time too many or one time too few due to a minor boundary mistake.

Comparing Strict Less-Than (<) vs. Less-Than-Equal (<=)

Consider counting starting at 1 up to 5:

Condition: i < 5 (Exclusive)
for (int i = 1; i < 5; i++) {
    System.out.print(i + " ");
}
// Output: 1 2 3 4 (Runs 4 times)

Excludes the endpoint 5.

Condition: i <= 5 (Inclusive)
for (int i = 1; i <= 5; i++) {
    System.out.print(i + " ");
}
// Output: 1 2 3 4 5 (Runs 5 times)

Includes the endpoint 5.

📏 The Boundary Rule of Thumb

If starting at 1 and wanting N iterations: use i = 1; i <= N; i++.

If starting at 0 (standard in arrays) and wanting N iterations: use i = 0; i < N; i++.

14. Accumulators and Counters

Beginners often confuse Counters with Accumulators. While both variables live outside the loop and update inside the loop, they serve completely different algorithmic purposes:

Concept Typical Purpose Common Starting Value Update Syntax Real-Life Analogy
Counter Counts occurrences (frequency) int count = 0; count++; (always +1) A hand tally counter counting attendees clicking through a door
Accumulator Computes running totals (sum / product) int sum = 0; (or 1 for product) sum += value; (adds dynamic data) A cash register drawer accumulating different price values

Combined Example: Count & Sum of Multiples of 3

CounterAccumulatorDemo.java 
public class CounterAccumulatorDemo {
    public static void main(String[] args) {
        int count = 0; // Counter
        int sum = 0;   // Accumulator

        for (int i = 1; i <= 20; i++) {
            if (i % 3 == 0) {
                count++;   // Increment event frequency
                sum += i;  // Accumulate the number value
            }
        }

        System.out.println("Multiples found: " + count);
        System.out.println("Total sum: " + sum);
    }
}
💻 Expected Output
Multiples found: 6 Total sum: 63

15. Pattern Printing with Loops (Visual Matrix Mastery)

Pattern printing is the ultimate training ground for mastering nested loops. It forces you to think about two-dimensional space in terms of Rows (Outer Loop i) and Columns (Inner Loop j).

Pattern A: Solid Square (4 × 4)

The column count is fixed: for every row i, print 4 stars.

PatternSquare.java
for (int i = 1; i <= 4; i++) {
    for (int j = 1; j <= 4; j++) {
        System.out.print("* ");
    }
    System.out.println(); // Move to next line after completing a row!
}
💻 Expected Output
* * * * * * * * * * * * * * * *

Pattern B: Growing Star Triangle

The column count is dynamic: row 1 gets 1 star, row 2 gets 2 stars, etc. (j <= i):

PatternTriangle.java
for (int i = 1; i <= 4; i++) {
    for (int j = 1; j <= i; j++) {
        System.out.print("* ");
    }
    System.out.println();
}
💻 Expected Output
* * * * * * * * * *

Pattern C: Number Triangle

Instead of printing "*", print the inner column counter j:

PatternNumberTriangle.java
for (int i = 1; i <= 4; i++) {
    for (int j = 1; j <= i; j++) {
        System.out.print(j + " ");
    }
    System.out.println();
}

16. Practical Loop Applications (6 Comprehensive Case Studies)

Let us put theory into practice with 6 independent, real-world algorithmic problems commonly encountered in Java programming.

Case Study 1: Print Numbers from 1 to N

Problem: Given a positive integer N = 5, print all numbers from 1 up to N on a single line separated by spaces.

PrintOneToN.java
public class PrintOneToN {
    public static void main(String[] args) {
        int n = 5;
        for (int i = 1; i <= n; i++) {
            System.out.print(i + " ");
        }
        System.out.println();
    }
}
💻 Output
1 2 3 4 5

Edge Case: If n <= 0, condition 1 <= n is false immediately and nothing prints.

Case Study 2: Sum of First N Natural Numbers

Problem: Compute the sum 1 + 2 + 3 + ... + N for N = 10.

SumNaturalNumbers.java
public class SumNaturalNumbers {
    public static void main(String[] args) {
        int n = 10;
        int sum = 0;
        for (int i = 1; i <= n; i++) {
            sum += i;
        }
        System.out.println("Sum of first " + n + " numbers = " + sum);
    }
}
💻 Output
Sum of first 10 numbers = 55

Edge Case: For very large N (e.g. 100,000), use long sum to avoid 32-bit integer overflow.

Case Study 3: Multiplication Table Generator

Problem: Print the multiplication table of 6 from 1 to 10.

MultiplicationTable.java
public class MultiplicationTable {
    public static void main(String[] args) {
        int num = 6;
        for (int i = 1; i <= 10; i++) {
            System.out.println(num + " x " + i + " = " + (num * i));
        }
    }
}
💻 Output
6 x 1 = 6 6 x 2 = 12 6 x 3 = 18 6 x 4 = 24 6 x 5 = 30 6 x 6 = 36 6 x 7 = 42 6 x 8 = 48 6 x 9 = 54 6 x 10 = 60

Case Study 4: Count Digits in an Integer

Problem: Count the number of decimal digits in 58249 (Output: 5 digits).

CountDigits.java
public class CountDigits {
    public static void main(String[] args) {
        int num = 58249;
        int count = 0;
        int temp = num;

        if (temp == 0) {
            count = 1;
        } else {
            while (temp > 0) {
                count++;
                temp /= 10; // Chops off the rightmost digit
            }
        }

        System.out.println("Number: " + num + " has " + count + " digits");
    }
}
💻 Output
Number: 58249 has 5 digits

Edge Case: Explicit check for 0: 0 has exactly 1 digit, but while (0 > 0) would return 0 without the special check.

Case Study 5: Reverse a Positive Integer

Problem: Reverse the digits of 12345 to produce 54321 using modulo and division.

ReverseNumber.java
public class ReverseNumber {
    public static void main(String[] args) {
        int num = 12345;
        int reversed = 0;
        int temp = num;

        while (temp > 0) {
            int lastDigit = temp % 10; // Extracts 5, 4, 3, 2, 1
            reversed = reversed * 10 + lastDigit; // Shifts left and adds digit
            temp /= 10; // Discards processed digit
        }

        System.out.println("Original: " + num + ", Reversed: " + reversed);
    }
}
💻 Output
Original: 12345, Reversed: 54321

Limitation: This arithmetic reversal assumes non-negative input and that the reversed value does not exceed Integer.MAX_VALUE (2,147,483,647).

Case Study 6: Factorial of a Non-Negative Integer

Problem: Calculate 5! = 5 × 4 × 3 × 2 × 1 = 120.

FactorialDemo.java
public class FactorialDemo {
    public static void main(String[] args) {
        int n = 5;
        long factorial = 1; // Initialized to 1 for multiplication!

        for (int i = 1; i <= n; i++) {
            factorial *= i;
        }

        System.out.println(n + "! = " + factorial);
    }
}
💻 Output
5! = 120

Crucial Edge Case & Overflow: 0! = 1 works because the loop 1 <= 0 runs 0 times and leaves factorial = 1. Factorials grow astronomically: int overflows beyond 12!, and long overflows beyond 20!.

Section 17

17. Visual Debugging Guide: 15 Common Loop Errors

Below is your essential debugging radar. Every developer has stumbled into these traps — study the fixes so you can resolve them in seconds:

✕ Mistake 1: Semicolon after loop header
for (int i = 1; i <= 5; i++); {
    System.out.println(i); // COMPILER ERROR or prints once!
}

Fix: Remove the semicolon after the header. Semicolon terminates the loop with an empty body.

✕ Mistake 2: Missing counter update in while
int i = 1;
while (i <= 5) {
    System.out.println(i);
    // Missing i++ !!
}

Fix: Add i++; inside the body to move toward the stopping threshold.

✕ Mistake 3: Off-by-one with < vs <=
// Want 5 iterations, but writes:
for (int i = 1; i < 5; i++) { ... }

Fix: Use i <= 5 if starting at 1, or i < 5 if starting at 0.

✕ Mistake 4: Updating in wrong direction
for (int i = 1; i <= 5; i--) { ... }

Fix: Counting forward requires i++, not i--.

✕ Mistake 5: Continue before update in while
while (i <= 5) {
    if (i == 3) continue; // Bypasses i++!
    i++;
}

Fix: Increment i++; before calling continue;.

✕ Mistake 6: Missing semicolon in do-while
do {
    i++;
} while (i <= 5) // Missing ';'

Fix: Add ; after while (condition);.

✕ Mistake 7: Nested loop variable typo
for (int i = 1; i <= 3; i++) {
    for (int j = 1; i <= 2; j++) // Typos 'i' instead of 'j'!
}

Fix: Always test the inner counter j <= 2 in the inner loop.

✕ Mistake 8: Accidental counter modification
for (int i = 1; i <= 5; i++) {
    i = 2; // Mutating counter inside body!
}

Fix: Do not reassign the loop counter manually inside the body unless intentionally skipping.

✕ Mistake 9: Initializing product accumulator to 0
int product = 0; // BUG!
for (int i = 1; i <= 5; i++) product *= i;

Fix: Product accumulator must be initialized to 1; anything × 0 is 0!

✕ Mistake 10: print vs println in pattern rows
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) System.out.println("*");
}

Fix: Use System.out.print() inside the inner loop and System.out.println() only after.

✕ Mistake 11: Floating point equality in condition
for (double d = 0.0; d != 1.0; d += 0.1)

Fix: Floating point precision can miss exact equality 1.0! Use d < 1.0.

✕ Mistake 12: Expecting break to exit outer loop
for (i...) {
    for (j...) {
        if (cond) break; // Only exits j loop!
    }
}

Fix: Standard break exits only the nearest loop. Use a boolean flag or labeled break for outer exit.

✕ Mistake 13: Scope leak of loop variable
for (int i = 0; i < 5; i++) { ... }
System.out.println(i); // Error: cannot find symbol 'i'

Fix: i is scoped strictly to the loop block. Declare outside if needed after.

✕ Mistake 14: Integer overflow in factorial
int fact = 1; // Overflows at 13!
for (int i = 1; i <= 13; i++) fact *= i;

Fix: Use long (safe up to 20!) or BigInteger for large calculations.

✕ Mistake 15: Empty range loop condition
for (int i = 5; i <= 1; i++) // Starts at 5, tests <= 1!

Fix: For countdown, use i >= 1; i--.

18. Loop Selection Guide: Which Loop Should You Use?

Choosing the right tool for the job makes your code clean, readable, and bug-free. Follow this visual decision tree whenever deciding which loop to write:

Scenario Recommended Loop Why This Loop is Best
Iterating 1 to N, or over known collections for Loop All iteration controls (init, condition, update) are contained neatly in a single line.
Interactive user menu or password prompt do-while Loop The prompt must be shown at least once before asking "Try again? (y/n)".
Processing data until an end marker (EOF, sensor input, condition) while Loop Number of iterations is unpredictable; repeats strictly as long as condition stays true.
Processing 2D grids, tables, seating charts, or image pixels Nested Loops Outer loop steps through rows; inner loop visits each column cell.

21. Quick Revision & 5 Golden Loop Rules

Keep this quick reference handy before practical lab tests, coding interviews, and examinations:

Syntax Summary Control Gate Execution Guarantees Typical Best Match
for (init; cond; update) Entry-Controlled 0 or more iterations Fixed counts, index-based loops
while (cond) Entry-Controlled 0 or more iterations Condition/state-based loops
do { ... } while (cond); Exit-Controlled At least 1 iteration User menus, retry inputs
👑 The 5 Golden Rules of Java Loops
  1. Every loop needs an exit strategy: Ensure the counter update moves progressively toward making the condition false.
  2. Watch your boundaries: i < N runs N times when starting at 0; i <= N runs N times when starting at 1.
  3. Never put a semicolon after a loop header: for (...); creates an empty loop body that causes subtle, maddening bugs!
  4. Know your emergency exits: Use break to quit the loop entirely; use continue to skip to the next iteration.
  5. Nested loops multiply: Inner loops completely reset and execute for every single step of the outer loop (Outer × Inner).
