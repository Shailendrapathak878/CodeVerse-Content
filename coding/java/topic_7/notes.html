SECTION 01

1. Introduction to Conditional Statements

Up to this point in your Java journey, every program you wrote executed sequentially: statement 1 ran, followed by statement 2, then statement 3, straight from top to bottom like a single-lane highway. But real-world software cannot operate on a one-track road. Real programs must make intelligent decisions based on real-time data.

💡 What is a Conditional Statement?

A conditional statement (also known as a selection statement or branching construct) is a control-flow mechanism that allows a program to test a condition and choose between two or more alternative execution paths. If the condition evaluates to true, one block of code runs; if it evaluates to false, a different block (or nothing at all) runs.

Real-World Analogy: The University Grading Portal

Imagine logging into your college academic portal to check your semester exam results. The server doesn't execute the same logic for every student:

  • If your marks are 40 or higher, the portal displays a green banner: "Congratulations! You Passed."
  • Otherwise, if your marks are below 40, the portal displays an amber notice: "Supplementary Exam Required."

Notice that the computer never runs both messages for the same student. It evaluates a single factual test, decides which branch is valid, and executes only that specific path.

Figure 1.1: Decision-making flowchart showing how a single condition forks execution into two mutually exclusive paths.

Sequential vs. Conditional Execution

Feature Sequential Execution Conditional (Branching) Execution
Execution Path Strictly linear: every line executes from top to bottom. Dynamic: code paths are skipped or selected based on runtime data.
Flexibility Rigid; produces the identical sequence of actions every run. Adaptive; behaves differently for varying inputs and user actions.

SECTION 02

2. Understanding Conditions and Boolean Expressions

In Java, decision-making is strictly governed by the boolean primitive type. Unlike languages like C, C++, or Python where numbers like 0, 1, or empty objects can act as "truthy" or "falsy" values, Java strictly requires an expression that evaluates to true or false.

⚠ The Strict Java Rule: No Integer "Truthiness"!

In C/C++, writing if (1) or if (count) is valid. In Java, this results in a mandatory compilation error (incompatible types: int cannot be converted to boolean). Every conditional statement in Java MUST evaluate to a pure boolean expression.

Figure 2.1: The 4-stage pipeline: Variables undergo relational tests to yield a boolean value that gates branch execution.

Relational and Equality Operators in Conditions

Operator Meaning Java Example Result when age = 20
> Greater than age > 18 true
< Less than age < 18 false
>= Greater than or equal to age >= 20 true
<= Less than or equal to age <= 15 false
== Equal to (value comparison) age == 20 true
!= Not equal to age != 20 false
BooleanExpressionDemo.java 
public class BooleanExpressionDemo {
    public static void main(String[] args) {
        int age = 20;
        
        // Evaluating condition into boolean variable
        boolean eligible = age >= 18;
        
        System.out.println("Age: " + age);
        System.out.println("Is eligible to vote? " + eligible);
        
        // Compound condition combining relational operators
        boolean inCollegeYears = age >= 18 && age <= 23;
        System.out.println("In typical college age range: " + inCollegeYears);
    }
}
🖥 Console Output
Age: 20 Is eligible to vote? true In typical college age range: true
SECTION 03

3. The if Statement (One-Way Selection)

The simplest conditional construct in Java is the single if statement. It represents a one-way fork: if the condition is satisfied, the enclosed block executes; otherwise, the block is completely bypassed and execution continues immediately with the next statement.

Figure 3.1: Flowchart of a single if statement showing the guarded execution path and the bypass path.

Syntax & Structure

SingleIfSyntax.java 
if (condition) {
    // Statements executed ONLY when condition evaluates to true
}
AdultCheckDemo.java 
public class AdultCheckDemo {
    public static void main(String[] args) {
        int age = 20;

        // Condition evaluates to true (20 >= 18)
        if (age >= 18) {
            System.out.println("You are an adult.");
            System.out.println("Registration access granted.");
        }

        System.out.println("Program continues normally.");
    }
}
🖥 Output with age = 20
You are an adult. Registration access granted. Program continues normally.

What Happens When Condition is False?

If we alter age = 16:

  1. The expression 16 >= 18 evaluates directly to false.
  2. The entire block inside { ... } is immediately bypassed.
  3. Only the following line runs: Program continues normally.
👑 Best Practice: Always Use Braces!

Java allows omitting curly braces if there is only one statement inside the if body. Never do this! Omitting braces is the leading cause of accidental "dangling statement" bugs when another developer later adds a second line expecting it to be part of the conditional block.

4. The if-else Statement (Two-Way Mutual Exclusion)

When an action must be taken in both outcomes of a decision, the if-else statement is the workhorse construct. It guarantees binary mutual exclusion: exactly one branch executes—never both, and never neither.

Figure 4.1: Flowchart of an if-else decision diamond routing execution to either the true or false branch.

Classic Parity Test: Even or Odd

EvenOddDemo.java 
public class EvenOddDemo {
    public static void main(String[] args) {
        int number = 7;

        // Modulo operator returns remainder when divided by 2
        if (number % 2 == 0) {
            System.out.println(number + " is Even.");
        } else {
            System.out.println(number + " is Odd.");
        }
    }
}
🖥 Output for number = 7
7 is Odd.

Detailed Execution Trace Table

Step Expression Evaluated Value Action Taken Final Output
1 int number = 7; 7 Variable allocated in stack memory -
2 number % 2 1 Remainder calculated (7 / 2 = 3 remainder 1) -
3 1 == 0 false Equality test fails; skips if block -
4 else branch - Directs control into else body 7 is Odd.
SECTION 05

5. The else-if Ladder (Multi-Way Categorization)

When you have three or more mutually exclusive conditions to test, chaining them into an else-if ladder creates a sequential evaluation cascade. The conditions are checked one by one from top to bottom.

👁 The Fundamental Rule of Ladders

The very first condition that evaluates to true wins! Its block executes, and Java immediately skips the remainder of the ladder entirely. The final else acts as the fallback default when all preceding checks evaluate to false.

Figure 5.1: The sequential else-if ladder waterfall: First match halts evaluation immediately.

Academic Grade Classification Example

GradeClassifier.java 
public class GradeClassifier {
    public static void main(String[] args) {
        int marks = 82;

        if (marks >= 90) {
            System.out.println("Grade A: Outstanding!");
        } else if (marks >= 80) {
            System.out.println("Grade B: Very Good!");
        } else if (marks >= 70) {
            System.out.println("Grade C: Good.");
        } else if (marks >= 60) {
            System.out.println("Grade D: Satisfactory.");
        } else {
            System.out.println("Grade F: Needs Improvement.");
        }
    }
}
🖥 Console Output for marks = 82
Grade B: Very Good!

Critical Boundary-Value Testing Table

Professional software engineers always test the "edge values" (boundaries). Notice how condition ordering guarantees precision without needing complex ranges like marks >= 80 && marks < 90:

Test Score First Evaluated Condition Outcome Next Evaluated Condition Final Assigned Grade
90 90 >= 90 true Skipped Grade A (Exact cutoff)
89 89 >= 90 false 89 >= 80 (true) Grade B (1 below A cutoff)
80 80 >= 90 false 80 >= 80 (true) Grade B (Exact cutoff)
79 79 >= 90, 79 >= 80 false 79 >= 70 (true) Grade C
59 All conditions fail false Falls through to else Grade F
SECTION 06

6. Nested if Statements (Hierarchical Decisions)

A nested if statement occurs when an if or else block contains another complete if statement inside it. Think of it as a two-stage security checkpoint: you must pass through the outer gate before the security guard at the inner door will even evaluate your credentials.

Figure 6.1: Hierarchical decision tree showing how the inner ID check depends entirely on passing the outer age gate.

VIP Event Admission Example

NestedIfDemo.java 
public class NestedIfDemo {
    public static void main(String[] args) {
        int age = 20;
        boolean hasId = true;

        // Outer Condition: Age verification
        if (age >= 18) {
            // Inner Condition: Identity verification
            if (hasId) {
                System.out.println("Status: Entry allowed.");
            } else {
                System.out.println("Status: Physical government ID required.");
            }
        } else {
            System.out.println("Status: Entry denied. Must be at least 18 years old.");
        }
    }
}
🖥 Output for age = 20, hasId = true
Status: Entry allowed.

Nested Decision State Matrix

Scenario age hasId Outer Check Result Inner Check Result Resulting Output
1 20 true true true Entry allowed.
2 20 false true false Physical government ID required.
3 16 true false Not evaluated! Entry denied. Must be at least 18.
💡 Nested If vs. Combined Conditions

If you don't need distinct error messages for each stage, you can flatten nested checks using the logical AND operator (&&):

if (age >= 18 && hasId) { ... }

Use nested if when each step requires distinct feedback or custom actions; use combined conditions when the outcome is simple and binary.

SECTION 07

7. The switch Statement (Multi-Way Jump Selection)

When you need to compare a single variable against many discrete, constant values (such as menu choices, days of the week, or protocol codes), an else-if ladder becomes tedious and repetitive. The Java switch statement provides a clean, high-performance direct jump table.

Figure 7.1: The switch statement directly branches to the matching case label using an efficient internal jump mechanism.

Syntax & Supported Selector Types

In traditional Java, the switch (expression) selector supports only specific primitive and reference types:

  • Integral Primitives: byte, short, char, int.
  • Wrapper Objects: Byte, Short, Character, Integer.
  • Strings: String (supported since Java 7).
  • Enumerations: Java enum types.
✕ What Types are NOT Supported in Traditional Switch?

Traditional Java switch statements do NOT accept long, float, double, or boolean. Attempting switch (doubleValue) causes a compilation error (incompatible types: possible lossy conversion from double to int).

Day of the Week Example with Break

DayOfWeekSwitch.java 
public class DayOfWeekSwitch {
    public static void main(String[] args) {
        int day = 3;

        switch (day) {
            case 1:
                System.out.println("Monday");
                break;
            case 2:
                System.out.println("Tuesday");
                break;
            case 3:
                System.out.println("Wednesday");
                break;
            case 4:
                System.out.println("Thursday");
                break;
            case 5:
                System.out.println("Friday");
                break;
            case 6:
                System.out.println("Saturday");
                break;
            case 7:
                System.out.println("Sunday");
                break;
            default:
                System.out.println("Invalid day number! Must be between 1 and 7.");
                break;
        }
    }
}
🖥 Output for day = 3
Wednesday

The Role of break & The Danger of Fall-Through

In traditional Java switch statements, case labels act as entry markers. Once execution jumps into a matching case, it continues downward through all subsequent statements regardless of case labels until it hits a break; statement or the closing curly brace }. This behavior is called fall-through.

SECTION 08

8. Modern Switch Expressions (Advanced Java 14+)

Starting with Java 14, Java introduced Switch Expressions with arrow syntax (->). This modern syntax eliminates traditional boilerplate, completely eliminates accidental fall-through, and allows the switch construct to yield a value directly into a variable.

Figure 8.1: Modern switch expression returning a String value directly into a variable using concise arrow syntax.
ModernSwitchDemo.java 
public class ModernSwitchDemo {
    public static void main(String[] args) {
        int day = 3;

        // Modern switch expression yields a value directly to 'dayType'
        String dayType = switch (day) {
            case 1, 2, 3, 4, 5 -> "Weekday";
            case 6, 7          -> "Weekend";
            default            -> "Invalid day";
        };

        System.out.println("Day " + day + " is a " + dayType);
    }
}
🖥 Console Output
Day 3 is a Weekday

Key Advantages of Modern Switch

  • No Fall-Through: Only the matched arrow branch runs. No break; needed!
  • Multi-Label Grouping: Group comma-separated cases in one line (case 1, 2, 3, 4, 5 ->).
  • Exhaustiveness Requirement: If used as an expression, the compiler forces you to handle all possible inputs (via default or exhaustive enum coverage).

9. if-else Versus switch: Decision Guide

Both constructs control program flow, but choosing the right tool for the job makes your code significantly cleaner, more readable, and less prone to edge-case bugs.

Figure 9.1: Strategic architectural guide: When to employ an if-else ladder vs. a switch statement.

Comprehensive Feature Comparison

Criteria if-else Ladder switch Statement

Range Checking Ideal (e.g. marks >= 80 && marks < 90). Awkward or impossible without listing every individual value.

SECTION 10

10. The Ternary Operator (? :) Versus Statements

Java provides a concise inline operator called the conditional (ternary) operator (? :). It is the only operator in Java that accepts three operands.

💡 Statements vs. Expressions

An if-else block is a statement: it executes an action or block of code, but does not itself evaluate to a value. The ternary operator is an expression: it evaluates to a single tangible value that can be directly assigned to a variable or passed into a method!

Figure 10.1: Ternary operator evaluation: Condition evaluates to yield either the true or false value directly.

Code Comparison: if-else vs. Ternary

Standard if-else Statement (5 Lines)
int age = 20;
String status;
if (age >= 18) {
    status = "Adult";
} else {
    status = "Minor";
}
✓ Concise Ternary Expression (1 Line)
int age = 20;
// (condition) ? valueIfTrue : valueIfFalse;
String status = (age >= 18) ? "Adult" : "Minor";
⚠ Readability Trap: Avoid Nested Ternary Operators!

While simple ternary expressions are clean, nesting multiple ternaries (e.g. a > b ? (a > c ? a : c) : (b > c ? b : c)) creates cryptic "write-only" code that confuses colleagues and causes bugs. Use an else-if ladder whenever multiple tiers of logic exist.

11. Combining Conditions with Logical Operators

Real-world decisions rarely depend on a single variable. For example, qualifying for a high-limit credit card might require that your income is high AND your credit score is strong, or that you have an established cosigner. In Java, we link boolean expressions using Logical Operators.

Logical Truth Tables

Operand A Operand B Logical AND (A && B) Logical OR (A || B) Logical NOT (!A)
true true true true false
true false false true false
false true false true true
false false false false true
Figure 11.1: Short-circuit evaluation halts redundant checks and guards against dangerous runtime crashes.

Defensive Coding with Short-Circuit Evaluation

Because Java guarantees left-to-right evaluation with short-circuiting, you can safely write defensive guards:

DefensiveShortCircuitDemo.java 
public class DefensiveShortCircuitDemo {
    public static void main(String[] args) {
        String username = null;

        // SAFE: If username is null, the left side is false.
        // Java immediately halts evaluation and NEVER calls .length() on null!
        if (username != null && username.length() > 0) {
            System.out.println("Valid username: " + username);
        } else {
            System.out.println("Username is null or empty.");
        }

        // DIVISION GUARD:
        int divisor = 0;
        int dividend = 100;
        if (divisor != 0 && (dividend / divisor > 5)) {
            System.out.println("Division successful.");
        } else {
            System.out.println("Division bypassed to prevent ArithmeticException (/ by zero)!");
        }
    }
}
🖥 Output
Username is null or empty. Division bypassed to prevent ArithmeticException (/ by zero)!
SECTION 12

12. Visual Debugging Guide: 14 Common Logic Mistakes

Even experienced developers occasionally trip over conditional subtleties. Study these 14 common pitfalls so you can recognize and fix them instantly.

Figure 12.1: Visual debugging of two subtle traps: The phantom semicolon and dangling else ambiguity.
✕ Mistake 1: Assignment (=) vs. Equality (==)
int x = 5;
// In C this compiles, but in Java:
if (x = 10) { ... } 
// ERROR: incompatible types: int cannot be converted to boolean

Fix: In Java, = assigns a value; == tests equality. Always use == for comparisons.

✓ Correct Approach
int x = 5;
if (x == 10) {
    System.out.println("Equal to 10");
}

Result: Compiles cleanly and tests boolean equality.

✕ Mistake 2: Phantom Semicolon After if Header
int age = 15;
if (age >= 18); // BUG! Semicolon terminates the if!
{
    System.out.println("Adult"); // ALWAYS EXECUTES!
}

Actual Output: Prints Adult even though age = 15!

✓ Correct Approach
int age = 15;
if (age >= 18) {
    System.out.println("Adult");
}

Result: Body is properly guarded by the condition.

✕ Mistake 3: Inverted Condition Ordering in Ladders
int score = 95;
if (score >= 60) {
    print("Pass"); // 95 is >= 60, so this MATCHES!
} else if (score >= 90) {
    print("Honors"); // DEAD CODE! Never reached!
}

Bug: Broad conditions placed before specific conditions swallow all matches.

✓ Correct Approach
int score = 95;
if (score >= 90) {
    print("Honors"); // Highest threshold first!
} else if (score >= 60) {
    print("Pass");
}

Result: Specific high thresholds are verified before broad fallbacks.

✕ Mistake 4: Dangling Else Ambiguity
if (isAdmin)
    if (isActive)
        print("Welcome");
else
    print("Access Denied"); // Belongs to isActive, NOT isAdmin!

Trap: Indentation does NOT bind an else. In Java, else binds to the closest unclosed if.

✓ Correct Approach with Braces
if (isAdmin) {
    if (isActive) {
        print("Welcome");
    }
} else {
    print("Access Denied");
}

Result: Curly braces make binding unambiguous and bug-proof.

✕ Mistake 5: Comparing Strings with ==
String input = new String("admin");
if (input == "admin") { // FAILS!
    print("Logged In");
}
// == compares heap memory addresses, NOT character content!
✓ Correct Content Comparison
String input = new String("admin");
if ("admin".equals(input)) {
    print("Logged In");
}
// .equals() compares actual character content safely!
✕ Mistake 6: Chained Comparison (Mathematical Notation)
int x = 15;
// In Python this works, but in Java:
if (10 < x < 20) { ... }
// ERROR: operator < cannot be applied to (boolean, int)
✓ Correct Compound Expression
int x = 15;
if (x > 10 && x < 20) {
    System.out.println("In range!");
}
✕ Mistake 7: Missing break in Switch
switch (status) {
    case 1: print("Pending"); // Missing break!
    case 2: print("Approved"); // Falls through!
}

Result: When status is 1, prints PendingApproved!

✓ Correct Break Usage
switch (status) {
    case 1: print("Pending"); break;
    case 2: print("Approved"); break;
}
✕ Mistake 8: Using Bitwise (&) Instead of Logical (&&)
// Bitwise & evaluates BOTH sides unconditionally!
if (str != null & str.length() > 0)
// If str is null, str.length() STILL RUNS → NullPointerException!
✓ Use Short-Circuit (&&)
if (str != null && str.length() > 0)
// Safe: Left side false aborts right side immediately!

Quick Debugging Checklist for Mistakes 9 through 14

Mistake Bad Pattern Danger / Symptom Correct Solution
9. Overlapping Ranges if (x > 10) ... else if (x > 5) inverted Lower range is shadowed and unreachable Sort descending for >, ascending for <
10. Missing Default switch with unhandled user codes Silent no-op failure on unexpected inputs Always provide a descriptive default: block
11. Floating-Point Equality if (0.1 + 0.2 == 0.3) Evaluates to false due to IEEE 754 precision Use tolerance delta: Math.abs(a - b) < 1e-9
12. Unhandled Boundaries Using > instead of >= for cutoffs Exact threshold value (e.g. 50% pass) fails Explicitly document inclusive vs exclusive cutoffs
13. Deeply Nested "Arrow" 5+ levels of indented if blocks Unmaintainable "Pyramid of Doom" Use early-exit guard clauses (if (!valid) return;)
14. Redundant Booleans if (isReady == true) Clutters code and exposes beginner syntax Simply write if (isReady) or if (!isReady)

Case Study 3: Leap Year Astronomical Calculator

The Astronomical Rule: A year is a leap year if it is divisible by 4, except if it is divisible by 100, in which case it must also be divisible by 400.

public class LeapYearChecker {

        }

Case Study 6: Four-Function Arithmetic Calculator

public class SimpleCalculator {

        double b = 6.0;
        char operator = '/';

        switch (operator) {
            case '+':
                System.out.printf("%.1f + %.1f = %.1f%n", a, b, (a + b));

                System.out.printf("%.1f - %.1f = %.1f%n", a, b, (a - b));

                    System.out.println("Error: Cannot divide by zero.");
                }
                break;
            default:
                System.out.println("Error: Unknown operator: " + operator);
                break;
        }
    }
}
