1. Introduction: Meet Your Dataset Before Analyzing It

Imagine kijiye ki aap ek college ke examination cell mein Data Analyst ke roop mein join karte hain. Aapke desk par Dean ek CSV file bhejte hain jisme 5,000 students ka semester performance data hai. Unka seedha sawaal hai: "Hamare college ka average pass percentage kya hai, aur kaun sa department top par hai?"

Ek novice programmer turant df['marks'].mean() calculate karne ki jaldbazi karega. Lekin ek professional data scientist janta hai ki uninspected data par direct calculations karna aag se khelne jaisa hai! Kyunki asal duniya ka raw data hamesha messy hota hai:

  • Missing Records: Kya kuch students ke exam marks enter hi nahi huye (NaN)? Agar hain, toh average unhe kaise treat kar raha hai?
  • Suspicious Values: Kya kisi student ke marks galti se 120 ya -5 type ho gaye hain? Ek single typing error poore college ka average distort kar dega!
  • Data Type Traps: Kya marks column numbers ke roop mein store hai, ya phir text string ('85') ke roop mein? Agar string hai, toh Pandas average calculate karne ke bajaye error throw karega!
  • Duplicate Entries: Kya kisi student ka record do baar enter ho gaya hai? Agar haan, toh us student ke marks do baar count ho jayenge!
  • Category Inconsistencies: Kya computer science department ko kahin 'CS', kahin 'CSE', aur kahin 'Computer Science' likha gaya hai?
Golden Rule of Data Science: Garbage In, Garbage Out (GIGO)
Agar aapke dataset ka input data corrupted, duplicate, ya invalid hai, toh aapka koi bhi complex statistical model ya machine learning algorithm sirf ek expensive mistake bankar reh jayega. Data Inspection is your first line of defense!

Exploratory Data Analysis (EDA) Workflow

2. head() & tail(): Preview the Dataset

Jab aap kisi nayi 100 MB ya 1 GB ki CSV file ko Pandas DataFrame mein load karte hain, toh agar aap poore DataFrame ko print karne ki koshish karenge, toh aapka terminal ya Jupyter notebook lakho rows se bhar jayega aur freeze ho sakta hai. Isliye sabse pehla command jo har data scientist chalata hai, woh hai df.head() aur df.tail().

Default Behavior aur Parameter 'n'

  • df.head(n=5): DataFrame ke shuruati n rows ko display karta hai. Agar aap koi number pass nahi karte, toh by default yeh top 5 rows return karta hai.
  • df.tail(n=5): DataFrame ke aakhiri n rows ko display karta hai. By default yeh bottom 5 rows return karta hai.
  • df.head(10) ya df.tail(3): Aap custom number of rows specify kar sakte hain.
Figure 6.2: Visualizing row selection in head() and tail() — Beginning vs End inspection.

3. shape, columns, index, and size

DataFrame ke basic geometry aur structural boundaries ko janne ke liye Pandas hume char foundational attributes (properties) deta hai. Dhyan rahe: yeh functions ya methods nahi hain, isliye inke aage parentheses () nahi lagate!

Figure 6.3: df.shape (2D Dimensions Tuple) vs df.size (Total Cell Count) breakdown.

The Four Key Properties

  • df.shape: Ek tuple return karta hai (n_rows, n_columns). Aap total rows janne ke liye df.shape[0] aur total columns janne ke liye df.shape[1] use karte hain.
  • df.columns: Ek Pandas Index object return karta hai jisme sabhi column headers ke naam hote hain. Aap df.columns.tolist() se ise standard Python list mein convert kar sakte hain.
  • df.index: DataFrame ke row labels ya range index ko return karta hai (jaise RangeIndex(start=0, stop=8, step=1)).
  • df.size: Poore DataFrame mein total kitne data cells (elements) hain, yeh return karta hai (Calculation: rows × columns). Yeh missing/null cells ko bhi count karta hai!

Example 1: Inspecting Student Dataset Dimensions & Columns

print(f"Column Headers: {df_students.columns.tolist()}")
print(f"Row Index: {df_students.index}")
print(f"Total Elements (size): {df_students.size}")

Common Junior Mistake: Calling df.shape()
Aksar beginners likh dete hain: df.shape() ya df.columns(). Isse turant error aata hai: TypeError: 'tuple' object is not callable! Yaad rakhiye: shape aur columns properties hain, functions nahi.

4. info(): Understand the Dataset Structure

Agar aapko dataset ka ek single comprehensive health checkup & diagnostic report chahiye, toh df.info() se behtar koi tool nahi hai. Yeh ek concise summary provide karta hai jo memory usage se lekar missing values tak sabkuch ek glance mein reveal kar deta hai.

Figure 6.4: Step-by-step breakdown of df.info() — Columns, Non-null counts, and Dtypes.

What df.info() Tells You

  1. Class type: Confirms it is a pandas.core.frame.DataFrame.
  2. RangeIndex: Total rows count aur index range (e.g., 8 entries, 0 to 7).
  3. Data columns: Total columns count.
  4. Column breakdown table:
    • #: Column ka numerical index (0-indexed).
    • Column: Column ka header name.
    • Non-Null Count: Kitne rows mein valid (non-missing) values hain. Agar kisi column ka count total entries se kam hai, toh iska matlab usme missing values hain!
    • Dtype: Stored data type (int64, float64, object/string, datetime64).
  5. dtypes summary: Har type ke kitne columns hain.
  6. Memory usage: DataFrame RAM mein kitni space le raha hai (e.g., 448.0+ bytes).

5. describe(): Understand Numerical Summaries

Jab aapke paas numerical data hota hai, toh har row ko alag se dekhne ke bajaye statistical aggregates dekhna zaroori hota hai. Method df.describe() numerical columns ke distribution ka ek instant 5-number summary plus mean, standard deviation, and count generate karta hai.

Figure 6.5: Complete breakdown of the 8 statistical metrics calculated by df.describe().

The 8 Statistical Measures Explained

Metric Definition Interpretation in Real Life
count Number of non-null observations Kitne students ke marks actually record huye hain (missing values excluded).
mean Arithmetic average (Sum of values / N) Batch ka overall performance average (outliers se sensitive hota hai).
std Standard deviation Data kitna spread out hai. High std = students ke marks mein bohot bada gap hai.
min Minimum value Batch mein sabse kam marks kis student ke aaye hain.
25% (Q1) 1st Quartile (25th percentile) 25% students ke marks is value se kam ya barabar hain.
50% (Q2) Median (50th percentile) Middle student ke marks. 50% data iske niche hai aur 50% upar. Outliers se immune hota hai.
75% (Q3) 3rd Quartile (75th percentile) 75% students iske niche hain, aur top 25% students iske upar hain.
max Maximum value Class topper ke marks.

Mean vs Median: The Skewness Trap

Aksar students sochte hain ki mean hamesha "typical" value represent karta hai. Yeh tabhi sach hota hai jab data symmetric ho! Agar dataset mein ek bhi extreme outlier ho, toh mean dramatically pull ho jaata hai, jabki median (50%) stable rehta hai:

Figure 6.6: Distribution showing how extreme salary outliers pull the mean away from the true median.

6. Inspect Individual Columns: value_counts(), nunique(), and unique()

Jab aapke paas categorical columns hote hain (jaise department, city, payment_method, product_category), toh unke unique classes aur unki frequencies dekhna sabse zaroori inspection step hota hai. Iske liye Pandas ke paas ek powerful inspection trio hai:

Figure 6.7: Visual comparison of unique() (array), nunique() (scalar count), and value_counts() (frequency series).

The Three Column Inspection Methods

  • df['col'].unique(): Column ke sabhi distinct values ka ek NumPy array return karta hai (agar NaN ho, toh woh bhi array mein shamil hota hai).
  • df['col'].nunique(): Total kitne distinct unique categories hain, unka count (integer) return karta hai. By default, yeh NaN ko count nahi karta (dropna=True).
  • df['col'].value_counts(): Sabse zyada use hone wala method! Yeh har unique category ki occurrence frequency count karta hai aur automatically descending order (highest to lowest) mein sort karke deta hai.
  • df['col'].value_counts(normalize=True): Absolute counts ke bajaye har category ka proportion (percentage as a decimal between 0 and 1) return karta hai!

Example 1: Analyzing College Departments

inspect_departments.py Python 3 • Pandas 
import pandas as pd

# 1. Inspect distinct departments
print("Unique Department Array:", df_students['department'].unique())
print("Total Unique Departments (nunique):", df_students['department'].nunique())

# 2. Count students per department
print("\n--- Frequency Count per Department ---")
print(df_students['department'].value_counts())

# 3. Calculate proportion of students per department
print("\n--- Department Proportions (Percentages) ---")
dept_pct = df_students['department'].value_counts(normalize=True) * 100
print(dept_pct.round(1))
Verified Execution Output:

7. Missing-Value Inspection: isna() and isnull()

Real-world datasets mein missing values sabse aam problem hain. Sensors fail ho sakte hain, survey form mein user ne field chhod di ho sakti hai, ya database migration mein value drop ho sakti hai. Pandas mein missing values ko standard roop se NaN (Not a Number) ya None se represent kiya jaata hai.

Figure 6.9: The 3-Step Missing Value Diagnostic Chain: isna() -> sum() -> mean() * 100.

Key Missing-Value Inspection Methods

  • df.isna() / df.isnull(): Yeh dono method 100% identical aliases hain. Yeh poore DataFrame ko ek boolean table mein badal dete hain jahan har missing cell True aur har valid cell False hota hai.
  • df.notna(): isna() ka opposite mask return karta hai (valid cells = True).
  • df.isna().sum(): Python mein True == 1 aur False == 0 hota hai. Isliye jab aap .sum() call karte hain, toh yeh har column ke True values ko jodkar exact missing rows count de deta hai!
  • df.isna().mean() * 100: Har column mein kitne percent rows missing hain, yeh calculate karta hai.

Example 1: Detecting Missing Marks and Attendance

inspect_missing_students.py Python 3 • Pandas 
import numpy as np
import pandas as pd

df_missing = pd.DataFrame({
    'student_id': ['S01', 'S02', 'S03', 'S04', 'S05', 'S06'],
    'name': ['Aarav', 'Diya', 'Rohan', 'Ananya', 'Kabir', 'Meera'],
    'marks': [85.0, np.nan, 72.0, 91.0, np.nan, 78.0],       # 2 Missing
    'attendance': [90.0, 95.0, np.nan, 88.0, 84.0, np.nan]    # 2 Missing
})

# 1. Absolute count of missing values per column
print("--- Missing Values Count per Column ---")
print(df_missing.isna().sum())

# 2. Percentage of missing values per column
print("\n--- Missing Values Percentage ---")
pct_missing = (df_missing.isna().mean() * 100).round(2)
print(pct_missing)
Verified Execution Output:
--- Missing Values Count per Column --- student_id 0 name 0 marks 2 attendance 2 dtype: int64 --- Missing Values Percentage --- student_id 0.00 name 0.00 marks 33.33 attendance 33.33 dtype: float64

Visualizing Missing Value Percentages

Diagnostic chart se turant pata chal jata hai ki kaun sa column sabse zyada affected hai:

Beginners aksar df.dropna() chala kar missing rows ko turant delete kar dete hain. Lekin agar kisi column mein 33% values missing hain, aur aapne dropna() kar diya, toh aap apne dataset ka ek-tihaai valuable hissa permanently lose kar denge! Inspection ka matlab sirf identify and measure karna hota hai; filling ya dropping ka decision domain rules ke hisaab se baad mein liya jaata hai.

8. Duplicate-Row Inspection: duplicated()

Data entry mistakes, system retries, ya multiple file mergers ke dauran duplicate records paida ho jaate hain. Duplicate rows aapke summary statistics (mean, total revenue, pass percentage) ko artificially inflate kar sakti hain.

Figure 6.11: Default keep='first' vs keep=False — Why keep=False is essential for viewing the entire duplicate group.

How df.duplicated() Works

  • df.duplicated(): Har row ke liye boolean return karta hai. By default (keep='first'), yeh pehli occurrence ko False (original) maanta hai aur uske baad aane wali matching rows ko True (duplicate) mark karta hai.
  • df.duplicated().sum(): Poore dataset mein total kitne extra duplicate rows hain, yeh count karta hai.
  • df.duplicated(keep=False): Sabse important parameter! Yeh all occurrences (including original and copies) ko True mark karta hai. Isse aap boolean filtering karke saari matching rows ko ek saath compare kar sakte hain!
  • df.duplicated(subset=['col_name']): Specific columns par duplicate check karta hai (jaise duplicate Student ID ya Order ID).

Example 1: Finding Repeated Student Records

inspect_duplicates.py Python 3 • Pandas 
import pandas as pd

df_with_dups = pd.DataFrame({
    'student_id': ['S101', 'S102', 'S103', 'S101', 'S104'],  # S101 is duplicated
    'name': ['Aarav', 'Diya', 'Rohan', 'Aarav', 'Ananya'],
    'marks': [88, 92, 75, 88, 85]
})

# 1. Total duplicate rows count
n_dups = df_with_dups.duplicated().sum()
print(f"Total redundant duplicate rows: {n_dups}")

# 2. View ALL matching duplicate rows side by side using keep=False
print("\n--- All Duplicate Records Displayed ---")
print(df_with_dups[df_with_dups.duplicated(keep=False)])
Verified Execution Output:
Total redundant duplicate rows: 1 --- All Duplicate Records Displayed --- student_id name marks 0 S101 Aarav 88 3 S101 Aarav 88

Full Row Duplicates vs Business Key Duplicates

Yeh distinction bohot critical hai: Ek Full Row Duplicate tab hota hai jab row ke sabhi columns identical hote hain (jaise upar Aarav ka record). Lekin ek Business Key Duplicate tab hota hai jab sirf primary key (jaise order_id) match karti hai, jabki baaki details alag hoti hain!

For example: Ek e-commerce order mein user ne do alag products khareede (Keyboard aur Mouse). Dono rows ka order_id 'ORD-204' hoga, lekin product alag hoga. Yeh duplicate nahi, balki valid multi-item order hai! Isliye duplicate delete karne se pehle domain context verify karna anivarya hai.

Detecting Suspicious Values with Domain Range Rules

Domain rules ke bina data quality check adhura hai. College marks hamesha 0 se 100 ke beech hone chahiye. Agar kisi row mein marks < 0 ya > 100 hain, toh woh definite suspicious data hai:

Figure 6.13: Domain range checking — Flagging values outside the valid [0, 100] interval.
detect_suspicious_values.py Python 3 • Pandas 
import pandas as pd

df_quality = pd.DataFrame({
    'student_id': ['S1', 'S2', 'S3', 'S4', 'S5'],
    'name': ['Aarav', 'Diya', 'Rohan', 'Ananya', 'Kabir'],
    'marks': [85, 120, -5, 90, 75]  # 120 and -5 are suspicious!
})

# Flag records outside 0 - 100
suspicious_mask = (df_quality['marks'] < 0) | (df_quality['marks'] > 100)
flagged_rows = df_quality[suspicious_mask]

print(f"Total Suspicious Records Detected: {len(flagged_rows)}")
print(flagged_rows)
Verified Execution Output:
Total Suspicious Records Detected: 2 student_id name marks 1 S2 Diya 120 2 S3 Rohan -5

Suspicious Value vs Proven Error: Diya ke marks 120 shayad typo ho sakte hain (100 ke bajaye 120 type ho gaya) ya extra credit assignment marks shamil hain. 10. Sorting and Examining Important Records: sort_values(), nlargest(), and sample()

Aksar datasets mein sabse interesting anomalies (jaise fraud transactions, abnormal medical readings, ya zero revenue orders) distribution ke extremes (highest aur lowest ends) par baithe hote hain. Inhe inspect karne ke liye Pandas hume sorting aur sampling methods deta hai.

Figure 6.14: Sorting methods comparison: df.sort_values() vs optimized nlargest() & nsmallest().

1. sort_values()

DataFrame ko kisi specific column ke hisaab se order karne ke liye df.sort_values(by='column_name', ascending=True/False) use kiya jaata hai. Default ascending=True hota hai (chote se bada).

2. nlargest() and nsmallest()

Jab aapke paas 10 lakh rows ka dataset ho aur aapko sirf top 5 highest ya lowest records dekhne ho, toh poore dataset ko sort karna wasteful hota hai. df.nlargest(n, 'col') aur df.nsmallest(n, 'col') heap-based algorithm use karke bina poore DataFrame ko sort kiye lightning speed se top/bottom rows return kar dete hain!

3. df.sample(): Defeating Top-of-File Bias

Datasets aksar logically grouped ya pre-sorted hote hain. Agar aap sirf head() dekhenge, toh aapko lag sakta hai ki sab kuch theek hai. df.sample(n=5, random_state=42) dataset ke har kone se random rows uthata hai, jisse hidden patterns aur unexpected values pakdi jaati hain.

14. Top 12 Beginner Mistakes & Pro Debugging Tips

Data exploration ke dauran beginners aksar in 12 traps mein phans jaate hain. Inhe dhyan se padhiye aur professional practices adopt kijiye:

# Common Mistake Why It Breaks Your Workflow Correct Pro Practice
1 Calling df.shape() or df.columns() Raises TypeError: 'tuple' object is not callable. Use properties without parentheses: df.shape and df.columns.
2 Assuming head() proves dataset health First 5 rows clean hote hain jabki aage dirty data ya NaNs hote hain. Always run df.info(), df.isna().sum(), aur df.sample(5).
3 Forgetting keep=False in duplicated() Aap sirf second copy dekh paate hain, original record nahi dikhta comparison ke liye. Use df[df.duplicated(keep=False)] to view both original and copy side by side.
4 Confusing count in describe() with total rows describe() count sirf non-null entries count karta hai, NaNs omit kar deta hai. Total rows ke liye len(df) ya df.shape[0] check karein.
5 Overlooking numerical columns stored as object Comma ('1,200') ya currency symbol ('$50') ke karan Pandas pura column string bana deta hai. Inspect df.dtypes! Clean strings and convert via pd.to_numeric().
6 Immediately running df.dropna() Dataset ka 20–40% critical data bina samjhe delete ho sakta hai. Always measure missingness first: df.isna().mean() * 100 before deciding.
7 Relying solely on mean without checking median Extreme outliers mean ko dramatically distort kar dete hain. Check both mean and median (50%) in describe(). Large gap = severe skewness!
8 Treating unique() and nunique() as identical unique() gives NumPy array of values; nunique() gives integer count. Use nunique() for counts and unique() for distinct lists.
9 Forgetting normalize=True in value_counts() Aapko manually frequency ko total rows se divide karna padta hai percentages ke liye. Pass normalize=True to directly get category proportions.
10 Deleting duplicate IDs without checking line items E-commerce multi-item carts mein same order_id multiple products ke liye hota hai. Distinguish full-row duplicates from repeated business keys.
11 Believing df.size equals number of rows df.size is total cells (rows * columns), not row count! Use len(df) or df.shape[0] for total rows.
12 Never using df.sample() Top-of-file bias leads to false confidence because files are often sorted. Always inspect random slices: df.sample(5, random_state=42).

Part D: Debugging Challenges (6 Challenges)

D1: Buggy Code: df.shape() throwing TypeError

Buggy Code:

print("Rows:", df.shape()[0])

Diagnosis: shape tuple property hai, function nahi. Parentheses () lagane se error aata hai.

Corrected Code:

print("Rows:", df.shape[0])
D2: Buggy Code: df.describe() missing text columns

Buggy Code:

print(df.describe())  # User wondering why 'department' column is absent!

Diagnosis: By default describe() sirf numeric columns summarize karta hai.

Corrected Code:

print(df.describe(include='all'))
D3: Buggy Code: Cannot calculate mean on string price column

Buggy Code:

avg_price = df['price'].mean()  # Raises TypeError: Could not convert '1200' to numeric

Diagnosis: price column ka dtype object hai text strings ke karan.

Corrected Code:

df['price'] = pd.to_numeric(df['price'].str.replace(',', ''))
avg_price = df['price'].mean()
D4: Buggy Code: Duplicates check returns empty DataFrame

Buggy Code:

dups = df[df.duplicated(keep='first')]  # Only showing second copy, context missing!

Diagnosis: keep='first' sirf extra redundant copy dikhata hai, comparison ke liye dono matching rows dekhna zaroori hai.

Corrected Code:

dups = df[df.duplicated(keep=False)]
D5: Buggy Code: df.isna() produces giant unreadable boolean table

Buggy Code:

print(df.isna())  # User flooded with 10,000 True/False booleans!

Diagnosis: User wants to know which columns have missing values, not raw cell booleans.

Corrected Code:

print(df.isna().sum())
D6: Buggy Code: Blindly dropping nulls deletes 50% of records

Buggy Code:

clean_df = df.dropna()  # Dropped 5,000 out of 10,000 rows without checking null percentage!

Diagnosis: A single optional column (jaise middle_name) had 50% nulls, causing half the rows to vanish!

Corrected Code:

# First inspect missing percentage per column:
print((df.isna().mean() * 100).round(2))
# Only drop if specific essential key column is null:
clean_df = df.dropna(subset=['student_id'])

Part E: Real-World Dataset Inspection Scenarios (3 Scenarios)

Scenario 1: Hospital Patient Vital Signs Dataset

Situation: Hospital ICU ke 2,000 patients ka dataset aaya hai jisme blood_pressure, heart_rate, aur temperature hai. Inspection mein kya check karenge?

Audit Checklist:

  1. Range check: heart_rate < 30 ya > 220 suspicious cardiac arrest ya sensor detachment ho sakta hai.
  2. temperature: < 90°F ya > 110°F typing error hai.
  3. Missing values: Kya kisi patient ka vital sign missing hai? High priority medical flag!
Scenario 2: Banking Loan Fraud Dataset

Situation: Bank loan applicants dataset mein annual_income ka mean Rs 15,00,000 dikha raha hai, lekin branch manager ka kehna hai ki unke typical customer middle-class hain (Rs 4–6 Lakhs).

Diagnostic Solution:

  1. df['annual_income'].describe() chala kar 50% (median) check karein.
  2. Box plot generate karein: 2 ya 3 ultra-wealthy HNIs (income Rs 50 Crore) ne poore branch ka arithmetic mean upar kheench liya hai!
  3. Manager ko explain karein ki true center median hai, mean nahi.
Scenario 3: Multi-Seller E-Commerce Delivery Tracking

Situation: 50,000 shipment tracking records mein 1,200 repeated tracking_id mile. Kya inhe delete kar dein?

Diagnostic Solution:

  1. Check karein: df[df.duplicated(subset=['tracking_id'], keep=False)].
  2. Notice hoga ki har row ek different shipment status checkpoint hai (e.g., "Shipped", "In Transit", "Out for Delivery", "Delivered") with timestamp!
  3. Yeh duplicate records nahi hain, balki ek single tracking event ki historical timeline hai! Inhe delete karna shipment tracking system ko crash kar dega.

Glossary of Essential Technical Terms

  • Exploratory Data Analysis (EDA): Pehla observational stage jahan data ke physical structure, health, missingness, aur patterns ko bina assumptions ke investigate kiya jaata hai.
  • Non-Null Count: Dataset ke kisi column mein un cells ki sankhya jisme actual valid value maujood hai (NaN ya None nahi hai).
  • Outlier: Ek aisi numerical observation jo dataset ke baaki typical values se abnormally bohot zyada badi ya choti hoti hai (1.5 × IQR rule).
  • Median (50th Percentile): Data ka exact middle value jab use ascending order mein sort kiya jaye. Yeh extreme outliers se 100% immune hota hai.
  • Standard Deviation (std): Ek measure jo batata hai ki observations arithmetic mean se average kitna spread ya disperse hain.
  • Business Key: Ek column (jaise order_id ya student_id) jo kisi business entity ko identify karta hai. Multi-item cart mein business key repeat ho sakti hai bina poori row duplicate huye.
  • Top-of-File Bias: Dataset ke shuruati rows ko dekhkar poore dataset ko clean maan lene ki cognitive galti. Isse bachne ke liye df.sample() zaroori hai.
  • Skewness: Data distribution ki asymmetry. Agar extreme high values mean ko right side kheenchti hain, toh use right-skewed ya positively skewed kehte hain.
