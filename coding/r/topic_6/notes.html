Conditional Statements in R

Learn how R programs make automated decisions: mastering the if, if...else, else if ladder, switch() dispatch, vectorized ifelse(), and real-world AI decision workflows.

1. What Are Conditional Statements?

In computer programming, a conditional statement allows your program to make decisions. Without conditions, a computer script would simply execute instructions blindly from top to bottom like a mechanical music box.

A condition is a question or logical comparison that evaluates to either TRUE or FALSE:

  • When TRUE: The program executes a designated block of instructions.
  • When FALSE: The program skips that block and either does nothing or runs an alternative fallback branch.

Real-Life Analogy: The Rainy Day Decision

Imagine waking up in the morning and looking out your bedroom window:

  • Question (Condition): Is it raining outside?
  • If TRUE (Yes): You grab your umbrella before walking to school or work.
  • If FALSE (No): You leave your umbrella at home and walk out freely.

Your First R Conditional Statement

Let's translate this decision-making logic directly into beginner-friendly R code:

temperature_check.RR
R Script
R 
# Store the current temperature in Celsius
temperature  30) {
  print("It is hot outside")
}
Console Output
R Script
R 
[1] "It is hot outside"

Step-by-step logic breakdown:

  1. temperature <- 35: Allocates memory and assigns the numeric value 35 to the variable temperature.
  2. if (temperature > 30): The keyword if tells R to inspect the expression inside parentheses. Since 35 is greater than 30, the condition evaluates to TRUE.
  3. { print("It is hot outside") }: Because the condition was TRUE, R opens the curly braces and executes the enclosed print statement.

2. Why Are Conditional Statements Important?

Conditional statements give software intelligence and adaptability. Real-world systems constantly make decisions based on changing inputs:

  • Student Pass/Fail Decisions: If marks >= 40, generate a certificate; otherwise, mark as re-examination.
  • Age Eligibility: If age >= 18, allow voter registration or grant a driver's license.
  • Bank Transaction Verification: If balance >= withdrawal_amount, dispense cash; otherwise, show "Insufficient funds".
  • Online Shopping Discounts: If cart_total >= 100, apply a 15% discount code automatically.
  • Weather Alerts: If wind_speed > 80, trigger a severe storm alert to citizens.
  • Medical Risk Analysis: If blood_sugar > 140, classify the patient into an elevated risk monitoring tier.
  • AI Prediction Decisions: If confidence_score >= 0.85, deploy the model output directly into production.
  • Machine Learning Classification: If spam_probability >= 0.80, route incoming emails to the junk folder.

3. The if Statement

An if statement is the simplest conditional construct in R. It executes an action only when its test condition is TRUE.

Formal Syntax:
if (condition) {
  # Code block runs ONLY when condition evaluates to TRUE
}

Syntax breakdown:

  • if: The reserved R keyword telling the interpreter to evaluate a condition.
  • (condition): The parentheses enclosing a relational or logical expression that evaluates to a single logical value (TRUE or FALSE).
  • { ... }: The curly braces enclosing the block of instructions to run when the condition is met.

4. The if...else Statement

An if...else statement gives your code a two-way branch. It allows your program to choose between two mutually exclusive actions: do Action A when the test is TRUE, or fallback to Action B when the test is FALSE.

Formal Syntax:
if (condition) {
  # Runs when condition is TRUE (Branch A)
} else {
  # Runs when condition is FALSE (Branch B)
}

Student Marks Evaluation Example

pass_fail.RR
R Script
R 
marks = 40) {
  print("Pass")
} else {
  print("Fail")
}
Console Output
R Script
R 
[1] "Fail"

If we test with marks <- 68, the condition 68 >= 40 evaluates to TRUE, so R prints "Pass" and completely skips the else branch.

5. The else if Statement

When your program must test multiple conditions sequentially, an else if ladder tests each condition one by one. The first condition that evaluates to TRUE executes its block, and R immediately bypasses all remaining branches.

Academic Grade Calculator

grade_calculator.RR
R Script
R 
marks = 90) {
  grade = 80) {
  grade = 70) {
  grade = 40) {
  grade <- "C"
} else {
  grade <- "Fail"
}

print(grade)
Console Output
R Script
R 
[1] "A"

Testing Multiple Input Marks:

Mark TestedCondition Path FollowedFinal Grade
95Matches marks >= 90 on the very first test."A+"
8595 test is FALSE; matches marks >= 80."A"
7590 and 80 tests are FALSE; matches marks >= 70."B"
4590, 80, 70 are FALSE; matches marks >= 40."C"
25All numeric conditions FALSE; enters final fallback else."Fail"
CRITICAL RULE — Order of Conditions Matters!
If you reverse the order and check marks >= 40 first, a student with 98 marks will test TRUE on >= 40 and immediately receive a grade of "C"! Always structure ladders from the most specific or highest threshold downward.

6. Nested if Statements

A nested if statement is an if statement placed inside another if or else block. It is used when an action depends on multiple hierarchical or prerequisite decisions.

Analogy: Examination Hall Entry Protocol

To sit for a university examination, two prerequisite checks must occur in sequence:

  1. Outer Check: Does the candidate have a verified admit card? (If no, entry is denied immediately).
  2. Inner Check: Did the candidate arrive before the entry deadline? (If yes, entry is permitted; if late, late entry is forbidden).
exam_entry_nested.RR
R Script
R 
has_admit_card  <- TRUE
arrived_on_time <- TRUE

if (has_admit_card) {
  if (arrived_on_time) {
    print("Entry allowed")
  } else {
    print("Late entry not allowed")
  }
} else {
  print("Admit card required")
}
Console Output
R Script
R 
[1] "Entry allowed"

Testing all critical combinations:

  • has_admit_card <- TRUE, arrived_on_time <- TRUE → "Entry allowed"
  • has_admit_card <- TRUE, arrived_on_time <- FALSE → "Late entry not allowed"
  • has_admit_card <- FALSE → "Admit card required" (Inner condition is never even evaluated!)

Readability Best Practice: While nested if blocks are powerful, nesting more than 2 or 3 levels deep makes code difficult to read. In many cases, combining conditions with logical operators (&&) provides a cleaner alternative.

7. The switch() Statement

The switch() function in R selects a value or executes an expression based on a matching key or numeric position. Think of it as choosing an exact dish from a café menu without needing a long chain of else if statements.

1. String Matching with Named Options

cafe_switch.RR
R Script
R 
choice <- "tea"

result <- switch(
  choice,
  "tea"    = "You selected Tea",
  "coffee" = "You selected Coffee",
  "juice"  = "You selected Juice",
  "Invalid choice"  # Default fallback item
)

print(result)
Console Output
R Script
R 
[1] "You selected Tea"

2. Positional Numeric Index Matching

If the first argument to switch() evaluates to a numeric integer, R selects the option by its 1-based numerical index position:

position_switch.RR
R Script
R 
choice <- 2

operation <- switch(
  choice,
  "Addition",        # Position 1
  "Subtraction",     # Position 2
  "Multiplication"   # Position 3
)

print(operation)
Console Output
R Script
R 
[1] "Subtraction"

When to use switch(): Use switch() when selecting from discrete, fixed categories (such as operational modes, calculator options, or customer service menus). Do not use switch() when evaluating continuous numeric ranges like marks >= 80.

8. The Vectorized ifelse() Function

In data science and statistics, data is stored in vectors containing hundreds or thousands of observations. Standard if statements can only evaluate a single scalar value. To evaluate conditions element-by-element across an entire vector at once, R provides the built-in ifelse() function.

Formal Syntax:
ifelse(test, yes, no)
• test: A logical vector condition.
• yes: Value or vector to return for elements where test is TRUE.
• no: Value or vector to return for elements where test is FALSE.

Vectorized Marks Classification Example

vectorized_grades.RR
R Script
R 
marks = 40, "Pass", "Fail")

print(result)
Console Output
R Script
R 
[1] "Fail" "Pass" "Pass" "Fail" "Pass"

Vectorized Weather Station Temperatures

temperatures  30, "Hot", "Normal")

print(status)
Console Output
R Script
R 
[1] "Normal" "Hot"    "Hot"    "Normal"
Important Caveat on ifelse():
1. ifelse() is NOT a direct replacement for multi-step control flow blocks containing statements, assignments, and loops.
2. ifelse() will coerce return types if the yes and no branches contain different data types (e.g. numbers mixed with strings).

9. Combining Conditions with Logical Operators

Often a real-world decision depends on multiple criteria simultaneously. We combine relational tests using R's logical operators: && (AND), || (OR), and ! (NOT).

1. Logical AND (&&)

Both conditions must be TRUE for the compound test to succeed.

}

2. Logical OR (||)

At least one condition must be TRUE for the decision to succeed.

logical_or.RR

  print("Contact information available")
} else {
  print("Contact information missing")
}
Console Output
R Script
R 
[1] "Contact information available"

3. Logical NOT (!)

Inverts the logical truth value: turns FALSE into TRUE and vice-versa.

logical_not.RR
R Script
R 
is_blocked <- FALSE

if (!is_blocked) {
  print("Account is active")
}
Console Output
R Script
R 
[1] "Account is active"
Scalar && vs Vectorized &: Always use double operators && and || in control-flow if statements because they perform short-circuit evaluation on single scalar truth values. Use single & and | when performing element-wise operations on vectors.

10. 10 Common Beginner Mistakes & Traps

Trap 1: Using Assignment = Instead of Equality ==

Incorrect (Syntax Error)R
R Script
R 
if (temperature = 30) { print("Warm") }
Why it fails: Single = attempts variable assignment inside the condition, which R syntax forbids.
CorrectR
R Script
R 
if (temperature == 30) { print("Warm") }

Trap 2: Forgetting Parentheses Around Condition

IncorrectR
R Script
R 
if age >= 18 { print("Adult") }
Why it fails: R requires test conditions to be enclosed in standard parentheses (...).

Trap 3: Missing Curly Braces for Multi-Line Blocks

Incorrect (Accidental Bug)R
R Script
R 
if (status == "admin")
  print("Granted")
  grant_system_access()  # Runs UNCONDITIONALLY!
Fix: Always enclose statement blocks inside { ... } even for one line.

Trap 4: Placing else on a New Line in Interactive Console

Incorrect (Fails in Console)R
R Script
R 
if (x > 0) {
  print("Positive")
}
else {  # Throws: Error: unexpected 'else'
  print("Negative")
}
Fix: Write } else { on the exact same line as the closing brace.

Trap 5: Writing Conditions in the Wrong Numerical Order

Checking broad thresholds (e.g. marks >= 40) before high distinctions (marks >= 90) causes high scores to enter lower branches. Always evaluate from strictest threshold downward.

Trap 6: Forgetting the Final else for Default Cases

If an input doesn't match any specific category (e.g. negative numbers or unexpected codes), omitting a final fallback leaves variables unassigned or unhandled.

Trap 7: Confusing Scalar if with Vectorized ifelse()

Passing a multi-element vector to if (v > 0) triggers: "the condition has length > 1 and only the first element will be used". Use ifelse() for vectors.

Trap 8: Using && on Vectors Instead of &

When filtering tabular datasets with multiple columns, using && only evaluates row 1. Always use & for vector masking.

Trap 9: Using & Where Scalar Short-Circuit && is Needed

In if (!is.null(x) && x > 0), && prevents error if x is NULL. Using & would evaluate both sides and throw an error.

Trap 10: Non-Scalar or Missing Condition in Base R if

If a condition evaluates to NA (missing value), R halts with: Error in if: missing value where TRUE/FALSE needed. Guard inputs against NA using !is.na().

Part 1: 8 Predict the Output Challenges

Challenge 1: Basic if...else evaluation

x <- 15; if (x %% 2 == 0) { print("A") } else { print("B") }
Output: [1] "B" (15 %% 2 is 1, not 0).

Challenge 2: Ladder condition precedence

m <- 75; if (m > 50) { res <- "Pass" } else if (m > 70) { res <- "Merit" }; print(res)
Output: [1] "Pass" (Order matters! Matches m > 50 first and bypasses subsequent branches).

Challenge 3: Nested if evaluation

Output: [1] 2 (Outer condition TRUE, inner condition FALSE).

Challenge 4: switch() string lookup

opt <- "beta"; switch(opt, alpha = 10, beta = 20, gamma = 30, 0)
Output: [1] 20 (Key 'beta' matches value 20).

Challenge 5: switch() positional index

switch(3, "Cat", "Dog", "Fish", "Bird")
Output: [1] "Fish" (Position 3 matches "Fish").

Challenge 6: Vectorized ifelse() output

v <- c(10, -5, 20); ifelse(v > 0, v * 2, 0)
Output: [1] 20 0 40 (Vector transformed element-by-element).

Challenge 7: Combined logical condition (AND)

14. Quick Revision & Key Takeaways

Construct Primary Syntax Target Input Key Principle & Behavior
if if (condition) { ... } Single scalar logical Executes block only when condition is TRUE; bypasses if FALSE.
if...else if (c) { ... } else { ... } Single scalar logical Two-way decision: runs Branch A if TRUE, Branch B if FALSE.
else if if (c1) ... else if (c2) ... else Single scalar logical Waterfall check: stops at first TRUE branch. Order is critical!
Nested if if (c1) { if (c2) { ... } } Hierarchical conditions Multi-level prerequisite validation. Inner test only runs if outer is TRUE.
switch() switch(expr, case1=val1, ...) Character key or integer Direct menu dispatch based on matching string key or 1-based index.
ifelse() ifelse(test, yes, no) Vector of any length Vectorized parallel selection. Returns vector matching input length.
Logical && / || c1 && c2, c1 || c2 Scalar logicals Short-circuit evaluation designed specifically for if statements.
