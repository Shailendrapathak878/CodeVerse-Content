Topic 16: Data Cleaning & Transformation in R

Master the Art of Converting Raw, Messy Data into High-Integrity Feature Sets for Analytics, Tidy Workflows & Production AI

1. Topic Introduction

In real-world data science, real data is never delivered clean, neat, and ready for machine learning algorithms. Industry surveys consistently report that data scientists and AI engineers spend 70% to 80% of their operational time preparing, cleaning, validating, and transforming raw records into dependable tabular formats.

Whether you receive hospital patient admissions, credit card transactions, IoT streaming sensor metrics, or customer e-commerce logs, raw feeds contain missing fields, misspelled cities, duplicate transactions, numbers mistakenly formatted as strings, and extreme anomalous values. If fed directly into analytical or AI models, these defects cause flawed statistical conclusions and broken algorithms—a phenomenon known as "Garbage In, Garbage Out".

Core Learning Theme: Data cleaning guarantees accuracy and integrity (getting the facts right), while data transformation ensures readiness and structure (shaping data for models).

2. Learning Objectives

By completing this topic, you will build end-to-end expertise across the entire data preparation lifecycle:

  • Audit & Diagnose: Rapidly inspect data frames using dim(), str(), head(), colSums(is.na()), and duplicated().
  • Tackle Missingness: Differentiate between na.omit() listwise deletion and resilient median/mode imputation.
  • Deduplicate Faithfully: Distinguish exact identical records from entity key duplicates using unique() and distinct().
  • Standardize Messy Text: Clean strings, remove whitespace with trimws(), unify casing via tolower(), and harmonize category labels with gsub().
  • Cast Types Correctly: Convert text numbers, parse calendar strings into Date objects, and map categorical values to factor.
  • Detect & Manage Outliers: Apply the Interquartile Range (IQR) rule and boxplots without blindly discarding valid rare events.
  • Transform via Base R & dplyr: Filter rows, select columns, compute derived features with mutate(), and aggregate via group_by() %>% summarise().
  • Restructure with tidyr: Pivot between wide spreadsheets and tidy long formats using pivot_longer() and pivot_wider().
  • Prevent ML Data Leakage: Fit imputation and scaling parameters on training data ONLY before applying to test sets.

3. What is Raw Data?

Raw data is information in its original recorded state, straight from external collection sources before any cleaning, validation, type conversions, or formatting have been applied.

Common real-life raw data streams include:

  • Customer Records: CRM records with mixed casing ("Lucknow", "lucknow", " LUCKNOW ") and unstandardized phone numbers.
  • Student Exam Marks: Excel score sheets where absent students have blank cells or text strings like "ABSENT" inside numeric mark columns.
  • Hospital EHR Records: Medical vital sensors where loose electrodes record negative blood pressure or 999.0 placeholder codes.
  • E-Commerce Transactions: Payment gateways containing double-clicked submission duplicate transactions.
  • IoT Sensor Telemetry: Weather stations experiencing transient signal drops that transmit NA or corrupted strings.

4. What is Data Cleaning?

Data cleaning (also known as data cleansing or data scrubbing) is the systematic process of discovering and correcting corrupt, inaccurate, incomplete, or irrelevant records from a dataset.

Consider this miniature customer profile table:

5. What is Data Transformation?

Data transformation is the process of converting data from one format, structure, or scale into another so that it becomes suitable for statistical evaluation, visualization, and machine learning models.

Core Transformations

  • Converting text into uniform lowercase
  • Casting strings to integer/factor/Date types
  • Deriving new features: total = qty * price

Structural Reshaping

  • Pivoting wide survey data into long format
  • Normalizing numeric ranges to $[0, 1]$ or Z-scores
  • Aggregating individual transactions by city/user

7. Handling Missing Values

In R, missing information is symbolized by the reserved constant NA (Not Available). It is not equal to zero, an empty string "", or boolean FALSE—it represents unrecorded reality.

R Script
R 
# Detecting missing values across the dataset
anyNA(raw_customers)
colSums(is.na(raw_customers))
complete.cases(raw_customers)
Expected Output:
[1] TRUE id name age city gender 0 0 1 0 0 amount purchase_date rating 0 0 0 [1] TRUE FALSE TRUE TRUE TRUE TRUE

Strategy A: Removing Incomplete Rows

na.omit() performs listwise deletion. If even one cell in a row is NA, the entire row is dropped. Use this only when missingness is rare or the missing variable is non-imputable (like patient death date).

R Script
R 
# Drops row 2 because age is NA
dropped_df <- na.omit(raw_customers)
nrow(dropped_df) # Reduced from 6 to 5

Strategy B: Imputation via Median

Rather than discarding observations, we replace NA with a central measure. When extreme values or skew are present, the median is far safer than the mean because it resists outlier distortion.

R Script
R 
# Calculating median age excluding NAs and outliers
valid_ages <- raw_customers$age[!is.na(raw_customers$age) & raw_customers$age <= 100]
median_age <- median(valid_ages)

# Imputing the missing value
raw_customers$age[is.na(raw_customers$age)] <- median_age
print(raw_customers$age)
Expected Output:
[1] 20.0 21.0 250.0 22.0 20.0 28.0
Machine Learning Imperative: In predictive modeling, NEVER compute imputation statistics on the entire dataset. Always partition your data into Train and Test sets first, compute the median on the Training set only, and use that training median to fill test NAs!

9. Handling Inconsistent Text Data

Because R is case-sensitive and literal, variations in whitespace and capitalization corrupt grouping operations. For instance, table() considers "Lucknow", "lucknow", "LUCKNOW", and " Lucknow " as four entirely separate markets!

R Script
R 
# 1. Remove leading and trailing whitespace
raw_customers$name <- trimws(raw_customers$name)
raw_customers$city <- trimws(raw_customers$city)

# 2. Standardize casing to lowercase
raw_customers$city <- tolower(raw_customers$city)

# 3. Standardize inconsistent gender category aliases using gsub
raw_customers$gender <- tolower(trimws(raw_customers$gender))
raw_customers$gender <- gsub("^m$|^male$", "Male", raw_customers$gender)
raw_customers$gender <- gsub("^f$|^female$", "Female", raw_customers$gender)

table(raw_customers$gender)
Expected Output:
Female Male 2 4

11. Handling Outliers & Invalid Values

An outlier is an observation that lies abnormally far from the central cluster of data. Outliers fall into two distinct categories: clerical errors (e.g. customer age = 250) and legitimate rare phenomena (e.g. a $50,000 corporate purchase).

The Interquartile Range (IQR) Method

Tukey's IQR rule defines statistical outlier boundaries based on the spread between the 25th percentile ($Q_1$) and 75th percentile ($Q_3$):

R Script
R 
# Detecting outliers in numeric vector
scores  upper_bound]
cat("Outliers detected:", outliers)
Expected Output:
Outliers detected: 140

prep_ml <- function(df, train_med=NULL) {
  df$income <- as.numeric(trimws(df$income))
  if (is.null(train_med)) train_med <- median(df$income, na.rm=TRUE)
  df$income[is.na(df$income)] <- train_med
  df$log_income <- log1p(df$income)
  return(list(data=df, learned_median=train_med))
}

Dropping rows whenever any optional question is NA deletes 70%+ of legitimate data.
