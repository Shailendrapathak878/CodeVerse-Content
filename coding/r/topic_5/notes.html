Operators & Expressions in R

A complete guide to arithmetic, relational, logical, assignment, and special operators (:, %in%, %*%, ?), precedence rules, and expression evaluation for Data Science & AI.

1. What Are Operators and Operands?

Imagine pressing keys on a physical pocket calculator. If you enter the numbers 10 and 20 and press the + button, the calculator adds them together to produce 30. In computer programming:

  • Operator: The action symbol or verb (such as +, -, *, /, ==) that commands R to perform a specific calculation or comparison.
  • Operands: The data values or variable inputs on which the operator acts.
  • Result: The single evaluated outcome generated by the operation.
R Script — Basic Operation R
R Script
R 
# 10 and 20 are operands; + is the arithmetic operator
result <- 10 + 20

print(result)
Console Output
R Script
R 
[1] 30

2. What Are Expressions?

An expression is any valid combination of variables, constants, and operators that R can evaluate to produce a single value. While a statement or command instructs R to perform an action, an expression always resolves to a value.

R Script — Arithmetic Expressions R
R Script
R 
10 + 20   # Evaluates to 30
50 - 15   # Evaluates to 35
5 * 4     # Evaluates to 20
100 / 5   # Evaluates to 20

# Capturing the expression's evaluated value into a variable
total <- 10 + 20
print(total)
Console Output
R Script
R 
[1] 30
[1] 35
[1] 20
[1] 20
[1] 30

4. Relational & Comparison Operators

Relational operators compare two values and produce an atomic boolean result: either TRUE or FALSE. They are fundamental to filtering rows in datasets, establishing business eligibility rules, and evaluating model accuracy.

⚠ Warning: == vs = in R

Never confuse == with =! age == 20 asks: "Is age equal to 20?" (returns TRUE/FALSE). In contrast, age = 20 assigns the value 20 to the variable age. Using single = inside a condition will overwrite your data!

D. Element-wise (&, |) vs. Short-Circuit (&&, ||)

R provides two distinct pairs of AND/OR operators with very different intended uses:

  • & and |: Vectorized Element-wise operators. They compare vectors element-by-element across columns in data frames.
  • && and ||: Short-circuit scalar operators. They evaluate only the first element of each operand and skip evaluating the right-hand side if the left operand already determines the result. Use these exclusively inside if() control flow statements.
Vector vs Scalar LogicR
R Script
R 
v1 <- c(TRUE, FALSE, TRUE)
v2 <- c(TRUE, TRUE, FALSE)

# Element-wise AND returns a vector of 3 results
print(v1 & v2)

# Short-circuit AND inspects ONLY the first element
print(v1 && v2)
Console Output
R Script
R 
[1]  TRUE FALSE FALSE
[1] TRUE

12. 8 Common Beginner Mistakes & Traps

Trap 1: Using = Instead of ==

Incorrect: if (status = "Active")
Fix: Use double equals for comparison: if (status == "Active").

Trap 2: Confusing / with %/%

Incorrect: Expecting 17 / 5 to return an integer quotient 3.
Fix: / returns 3.4; use 17 %/% 5 for integer 3.

Trap 3: Confusing % with %%

Incorrect: Writing 10 % 3 for remainder.
Fix: Modulus in R requires double percent signs: 10 %% 3.

Trap 4: Using && on Vectors

Incorrect: c(T, F) && c(T, T) (ignores remaining items).
Fix: Use vectorized & for element-wise comparisons.

Trap 5: Missing Parentheses

Incorrect: 10 + 5 * 2 expecting 30.
Fix: Group terms: (10 + 5) * 2.

Trap 6: Assuming += Exists in R

Incorrect: count += 1 (Syntax error!).
Fix: Reassign explicitly: count <- count + 1.

Trap 7: Negation Precedence

Incorrect: ! x > 5 (Not binds tightly).
Fix: Wrap relational term: ! (x > 5).

Trap 8: Expecting Numeric 1/0

Incorrect: Expecting 5 > 2 to output 1.
Fix: R comparisons strictly output logical TRUE or FALSE.

Part 1: Predict the Output Challenges

Challenge 1: Integer Division vs. Modulus

What will this code print?

R Script
R 
q <- 23 %/% 4
r <- 23 %% 4
cat(q, r)

Answer: 5 3

Explanation: 4 fits into 23 five times (4 * 5 = 20), leaving a remainder of 3 (23 - 20 = 3).

Challenge 2: Precedence Order

What will this code output?

R Script
R 
val <- 2 + 3 ^ 2 * 2
print(val)

Answer: [1] 20

Explanation: Exponentiation first: 3 ^ 2 = 9. Multiplication next: 9 * 2 = 18. Addition last: 2 + 18 = 20.

Challenge 3: Logical AND & OR Combination

What will this code output?

R Script
R 
res <- TRUE | FALSE & FALSE
print(res)

Answer: [1] TRUE

Explanation: In R, & has higher precedence than |. FALSE & FALSE evaluates to FALSE. Then TRUE | FALSE evaluates to TRUE.

Challenge 4: Negated Comparison

What will this code output?

R Script
R 
flag <- ! (15 <= 10)
print(flag)

Answer: [1] TRUE

Explanation: 15 <= 10 is FALSE. Inverting it with ! yields TRUE.

Challenge 5: Membership %in% Operator

What will this code output?

R Script
R 
x <- 7 %in% 1:5
print(x)

Answer: [1] FALSE

Explanation: 1:5 generates c(1, 2, 3, 4, 5). Since 7 is not in that sequence, it returns FALSE.

Challenge 6: Vectorized Comparison

What will this code output?

R Script
R

Answer: [1] FALSE TRUE TRUE

Explanation: Relational operators are vectorized in R, testing each element against 20 independently.

Challenge 7: Even Number Modulus Test

What will this code output?

R Script
R

Answer: [1] TRUE

Explanation: 18 %% 2 == 0 is TRUE and 18 > 10 is TRUE. TRUE & TRUE is TRUE.

Challenge 8: Precedence with Parentheses Override

What will this code output?

14. Quick Revision & Key Takeaways

Operator Category Operators Key Principle & Behavior
Arithmetic +, -, *, /, %%, %/%, ^ Calculate numbers. %% returns remainder; %/% returns integer quotient.
Relational ==, !=, >, <, >=, <= Compare values and return boolean TRUE or FALSE.
Logical (Vector) &, |, ! Vectorized element-wise boolean operations for dataset filtering.
Logical (Scalar) &&, || Short-circuit evaluation on single conditions inside if() blocks.
Assignment <-, =, -> Binds values to names. Reassignment: x <- x + 1 (no +=).
Special :, %in%, %*%, ? Sequence (1:5), membership (%in%), matrix multiply (%*%), help (?).
Precedence () > ^ > * / > + - > comparisons > logicals Parentheses always override default execution order.
