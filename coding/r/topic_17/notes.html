Topic 17: dplyr & Tidy Data in R

Master the Grammar of Data Manipulation, Relational Joins, Tidy Data Reshaping & Feature Pipelines for Modern Data Science & AI

1. Topic Introduction

In modern data science and machine learning, data preparation is governed by the tidyverse—an opinionated collection of R packages designed to make data science faster, more readable, and mathematically coherent. At the heart of this ecosystem lies dplyr, known as the "grammar of data manipulation", and the concept of Tidy Data developed by Hadley Wickham.

While Base R provides bracket indexing (df[rows, cols]), real-world data pipelines quickly become unreadable when operations are nested inside multiple brackets. dplyr replaces complex indexing with clear, expressive verbs that read like English prose: select(), filter(), arrange(), mutate(), summarise(), and relational joins.

Core Philosophy: Programs should be written for people to read, and only incidentally for machines to execute. The pipe operator (%>% or |>) lets you chain data operations into an intuitive assembly line.

2. Learning Objectives

Upon completing this comprehensive topic, you will be equipped to:

  • Master Core Verbs: Effortlessly filter rows with filter(), pick variables with select(), sort observations with arrange(), and engineer features with mutate().
  • Harness Pipes: Express multi-step data pipelines cleanly from left-to-right and top-to-bottom using %>% and the native R pipe |>.
  • Embrace Tidy Data: Understand the three sacred tidy data principles and distinguish between wide presentation tables and long tidy feature sets.
  • Execute Relational Joins: Combine disparate relational datasets safely using left_join(), inner_join(), full_join(), anti_join(), and semi_join() without suffering duplicate-key explosions.
  • Reshape Tables with tidyr: Fluidly pivot between wide and long representations using pivot_longer() and pivot_wider().
  • Aggregate Efficiently: Master the Split-Apply-Combine workflow via group_by() and summarise() to extract KPI summaries.
  • Prepare AI Feature Sets: Construct robust, leakage-free feature matrices ready for machine learning algorithms.

3. Introduction to dplyr

dplyr is an R package written by Hadley Wickham and Romain François that provides a fast, consistent set of verbs to solve common data manipulation challenges. Under the hood, critical operations are implemented in C++ via cpp11, giving you exceptional speed on multi-million-row datasets.

R Script
R

if (!requireNamespace("dplyr", quietly = TRUE)) {
  install.packages("dplyr")
}

Analogy: Think of a data table like an Excel spreadsheet. Base R is like writing nested formulas inside formula bars. dplyr is like a modern robotic conveyor belt where raw sheets glide smoothly through named workstations: Filter out defective items → Pick columns → Calculate totals → Sort by revenue.

4. The Tidy Data Principles

A dataset is formally defined as tidy when it conforms to three straightforward structural rules:

1. Variables are Columns

A variable is a measurable characteristic or attribute, such as age, gender, temperature, or exam score. In a tidy dataset, every distinct variable occupies exactly one vertical column.

2. Observations are Rows

An observation is a single data collection event or entity (e.g. one patient visit, one customer purchase, or one hourly sensor ping). Each observation forms its own horizontal row.

6. Understanding the Pipe Operators (%>% and |>)

When performing multiple data manipulation steps in Base R, code either requires deeply nested function calls (which evaluate from the inside out) or endless temporary variables that clutter RAM.

R Script
R 
# 1. Without Pipe (Nested, read inside-out):
res_nested = 80), name, math), desc(math))

# 2. With Pipe (Chained, read top-to-bottom):
res_piped %
  filter(math >= 80) %>%
  select(name, math) %>%
  arrange(desc(math))

print(res_piped)
Expected Output:
# A tibble: 2 × 2 name math <chr> <dbl> 1 Priya 95 2 Rahul 88

9. Arranging and Sorting Data

arrange() reorders observations based on one or more variables without changing the values or dropping rows. It defaults to ascending order; wrapping a column in desc() sorts it in descending order.

students %>%

10. Creating and Modifying Columns (mutate, case_when)

The mutate() verb creates new variables or transforms existing variables in place. Unlike Base R, freshly defined columns can be reused immediately in subsequent calculations within the same mutate() call.

R Script
R 
# Feature engineering with mutate() and case_when()
students_featured %
  mutate(
    percentage = (math / 100) * 100,
    grade = case_when(
      math >= 90 ~ "A+",
      math >= 80 ~ "A",
      math >= 70 ~ "B",
      TRUE ~ "C"
    ),
    is_honor_roll = math >= 85
  )

print(students_featured)
Expected Output:
# A tibble: 3 × 7 id name math city percentage grade is_honor_roll <int> <chr> <dbl> <chr> <dbl> <chr> <lgl> 1 101 Rahul 88 Lucknow 88 A TRUE 2 102 Priya 95 Delhi 95 A+ TRUE 3 103 Aman 76 Mumbai 76 B FALSE

12. Combining Datasets with Relational Joins

Real-world datasets are normalized across multiple tables. dplyr provides two families of joins: Mutating Joins (which append columns from another table) and Filtering Joins (which filter rows based on matches).

R Script
R 
# Demonstrating joins with customer & transaction tables
cust <- tibble(cust_id = c(1, 2, 3), name = c("Rahul", "Priya", "Aman"))
orders <- tibble(cust_id = c(1, 2, 4), amount = c(250, 400, 150))

# 1. Left Join: Keeps all customers
left_join(cust, orders, by = "cust_id")

# 2. Anti Join: Identifies customers with NO purchases (Aman)
anti_join(cust, orders, by = "cust_id")
Expected Output (Left Join):
# A tibble: 3 × 3 cust_id name amount <dbl> <chr> <dbl> 1 1 Rahul 250 2 2 Priya 400 3 3 Aman NA
Expected Output (Anti Join):
# A tibble: 1 × 2 cust_id name <dbl> <chr> 1 3 Aman

16. Complete End-to-End Tidy Data Workflow

This 12-step operational pipeline demonstrates the full journey: ingesting raw messy transaction logs, filtering, deriving features, reshaping, joining dimensions, and calculating summary metrics.

R Script
R 
# End-to-End Enterprise E-Commerce Data Wrangling Pipeline
raw_tx %
  # 1. Separate composite location
  separate(city_state, into = c("city", "state"), sep = "_") %>%
  # 2. Standardize text casing
  mutate(category = tolower(category)) %>%
  # 3. Engineer total line-item spend
  mutate(total_spend = price * qty) %>%
  # 4. Filter high-value transactions
  filter(total_spend >= 50) %>%
  # 5. Group by city and category to compute KPIs
  group_by(city, category) %>%
  summarise(
    revenue = sum(total_spend),
    tx_count = n(),
    .groups = "drop"
  ) %>%
  # 6. Sort results descending by revenue
  arrange(desc(revenue))

print(clean_sales_summary)
Expected Output:
# A tibble: 3 × 4 city category revenue tx_count <chr> <chr> <dbl> <int> 1 Delhi tech 1000 2 2 Mumbai clothing 240 1

19. Common Beginner Mistakes & Fixes (28 Cataloged Traps)

Mistake 1: Confusing select() with filter()

Using select(age >= 18) instead of filter(age >= 18).

Correct Fix:
R Script
R 
# filter() chooses horizontal rows; select() picks vertical columns
df %>% filter(age >= 18) %>% select(name, age)
Mistake 2: Confusing mutate() with summarise()

Expecting summarise() to keep all rows or mutate() to collapse the table.

Correct Fix:
R Script
R 
# mutate() preserves row count; summarise() collapses into 1 row per group
df %>% mutate(tax = price * 0.1)     # Keeps all rows
df %>% summarise(avg = mean(price))   # Collapses to 1 row
Mistake 3: Forgetting to Load dplyr in New Sessions

Calling df %>% filter(...) without library(dplyr) throws: could not find function "%>%".

Correct Fix:
R Script
R 
library(dplyr) # Always include at top of scripts
Mistake 4: Using Single Equals = Instead of Double Equals == in filter()

filter(city = "Delhi") throws an error because single equals is assignment.

Correct Fix:
R Script
R 
df %>% filter(city == "Delhi") # Use == for equality comparisons
Mistake 5: Misunderstanding Logical AND vs OR

Writing filter(city == "Delhi" & city == "Mumbai") which returns 0 rows since no single cell is both!

Correct Fix:
R Script
R 
df %>% filter(city == "Delhi" | city == "Mumbai") # or city %in% c(...)
Mistake 6: Forgetting ungroup() After Grouped Mutate

Subsequent verbs continue to operate within grouped categories silently.

Correct Fix:
R Script
R 
df %>% group_by(dept) %>% mutate(rel_sal = sal / sum(sal)) %>% ungroup()
Mistake 7: Calling n() Outside dplyr Context

Executing n() in standalone console returns Error: n() should only be called inside dplyr verbs.

Correct Fix:
R Script
R 
df %>% summarise(count = n()) # Use nrow(df) for standalone row count
Mistake 8: Missing Catch-All in case_when()

Unmatched observations silently become NA instead of a desired default string.

Correct Fix:
R Script
R 
case_when(score >= 90 ~ "A", TRUE ~ "Other") # Explicit TRUE ~ default
Mistake 9: Accidentally Creating Cartesian Explosion via Duplicate Keys

Joining two tables that both have duplicate primary keys causes runaway row duplication.

Correct Fix:
R Script
R 
# Ensure left or right table is deduplicated before join
right_table % distinct(id, .keep_all = TRUE)
left_join(left_table, right_table, by = "id")
Mistake 10: Using bind_cols() on Misaligned Data

Assuming rows match by identity when they only match by positional order.

Correct Fix:
R Script
R 
# Always prefer key-based joins:
left_join(df1, df2, by = "id")
Mistake 11: Misspecifying Columns in pivot_longer()

Pivoting primary keys like id into values by forgetting negative selection.

Correct Fix:
R Script
R 
df %>% pivot_longer(cols = -id, names_to = "metric", values_to = "value")
Mistake 12: Data Leakage in Preprocessing

Calculating mean or scaling bounds across the entire dataset before splitting train/test.

Correct Fix:
R Script
R 
# Split first; compute parameters on train; apply same parameters to test!

B. 20 Beginner Coding Exercises

Exercise 1: Create a Tibble: Construct a tibble containing employee names, departments, and salaries.

Hint: Use tibble(name=..., dept=..., salary=...).

Exercise 2: Pick Columns: Select only mpg and cyl from mtcars using dplyr.

Hint: mtcars %>% select(mpg, cyl).

Exercise 3: Exclude Columns: Drop the qsec and vs columns from mtcars.

Hint: mtcars %>% select(-qsec, -vs).

Exercise 4: Filter Powerful Cars: Extract cars with hp > 150 and cyl == 8.

Hint: mtcars %>% filter(hp > 150, cyl == 8).

Exercise 5: Range Filter: Filter cars with mpg between 20 and 30 inclusive.

Hint: filter(between(mpg, 20, 30)).

Exercise 6: Sort Descending: Sort mtcars by mpg from highest to lowest.

Hint: arrange(desc(mpg)).

Exercise 7: Top 3 Efficient Cars: Extract the top 3 highest mpg cars using slice.

Hint: slice_max(mpg, n = 3).

Exercise 8: Engineer Power-to-Weight: Calculate hp_per_wt = hp / wt.

Hint: mutate(hp_per_wt = hp / wt).

Exercise 9: Discretize Efficiency: Create a mileage_cat column using case_when().

Hint: case_when(mpg >= 25 ~ "High", mpg >= 18 ~ "Med", TRUE ~ "Low").

Exercise 10: Grouped Aggregation: Compute average horsepower and count per cylinder group.

Hint: group_by(cyl) %>% summarise(avg_hp = mean(hp), n = n()).

Exercise 11: Count Frequencies: Count cars by cylinder and transmission type (am).

Hint: count(cyl, am, sort = TRUE).

Exercise 12: Combine Sales Logs: Stack two monthly sales tibbles vertically.

Hint: bind_rows(sales_jan, sales_feb).

Exercise 13: Left Join Profiles: Join user profiles with their transaction history.

Hint: left_join(users, tx, by = "user_id").

Exercise 14: Find Inactive Users: Find users who have never placed an order.

Hint: anti_join(users, orders, by = "user_id").

Exercise 15: Pivot to Long: Reshape quarterly sales columns (Q1 to Q4) into stacked rows.

Hint: pivot_longer(starts_with("Q"), names_to = "quarter", values_to = "sales").

Exercise 16: Pivot to Wide: Spread product category revenues into distinct columns.

Hint: pivot_wider(names_from = category, values_from = revenue, values_fill = 0).

Exercise 17: Split City and State: Split a composite column "Dallas_TX" into two variables.

Hint: separate(city_state, into = c("city", "state"), sep = "_").

Exercise 18: Forward Fill Missing Vitals: Replace missing patient temperatures using LOCF.

Hint: fill(temperature, .direction = "down").

Exercise 19: Impute Missing Defaults: Replace missing discounts with 0 using replace_na().

Hint: replace_na(list(discount = 0)).

Exercise 20: Full AI Preparation: Filter, mutate, join catalog, and select training features.

Hint: Chain filter() → mutate() → left_join() → select().
