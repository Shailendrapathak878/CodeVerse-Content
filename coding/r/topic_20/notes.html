1. Introduction to R Projects & Workspace Architecture

In modern data science, professional developers never write isolated, disorganized scripts on their Desktop. An R Project is a self-contained, portable directory housing scripts, raw data, outputs, configuration, documentation, and dependencies.

Why R Projects Matter:
  • Portability: Uses project-relative paths; runs seamlessly on Windows, macOS, Linux, or Cloud CI/CD.
  • Root Working Directory: Opening an .Rproj file locks R's working directory to that specific folder automatically.
  • Isolated State: Prevents workspace variable bleeding between unrelated analysis projects.
Core Project Files:
  • .Rproj: RStudio project configuration anchor.
  • data/raw/: Immutable, read-only original ground-truth datasets.
  • R/: Reusable helper functions and modular transformations.
  • scripts/: Execution pipelines (e.g., main.R).
  • renv.lock: Exact version manifest of all project dependencies.
  • README.md: Human-readable documentation for replication.

4. Modular Code Architecture, source() & Secrets

Never write monolithic 2,000-line scripts. Decompose data pipelines into modular functional files inside R/ and execute them dynamically with source().

Secret Management Rule: Never hardcode passwords or API keys inside code files. Store them in a local .Renviron file (read via Sys.getenv("KEY")) and immediately add .Renviron to .gitignore!

6. renv: Project-Level Dependency Management & Lockfiles

The renv package provides an isolated sandbox library for each R project. It records the exact package versions in renv.lock, preventing the common problem where updating a package for Project A crashes Project B.

R Script
R 
# Core renv Workflow Commands
# 1. Initialize project-local library & lockfile
renv::init()

# 2. Check synchronization status
renv::status()

# 3. Snapshot active packages to renv.lock
renv::snapshot()

# 4. Recreate environment on a new computer
renv::restore()

11. 30 Common Beginner Mistakes & Best Practices

1. Using setwd() with hardcoded machine paths: setwd("C:/Users/me/...") breaks on other PCs. Use RStudio Projects & here::here().

2. Repeatedly installing packages inside scripts: Putting install.packages() at the top of a script reinstalls on every run. Install once in console or use renv::restore().

3. Confusing installing and loading: Installing downloads to disk; you must still call library(pkg) to use it.

4. Writing all code in one giant file: 3,000-line files are unmaintainable. Split into modular scripts in R/.

5. Modifying original raw data in Excel: Corrupts ground truth. Keep data/raw/ read-only; clean via script.

6. Forgetting set.seed() in ML: Omitting seeds makes train-test splits non-reproducible across reruns.

7. Committing API keys to Git: Exposes secrets publicly. Store in .Renviron and add to .gitignore.

8. Committing renv/library/ to Git: Adds gigabytes of binary bloat. Commit renv.lock instead.

9. Not committing renv.lock: Without the lockfile, collaborators cannot run renv::restore().

10. Forgetting package::function namespace syntax: Unintended masking between dplyr::filter and stats::filter.

11. Forgetting to record sessionInfo(): Deprecation changes in future package releases become untraceable.

12. Running scripts from the wrong working directory: Solved by using here("path", "to", "file").

13. Updating all packages mid-project: update.packages() can introduce breaking syntax changes.

14. Sharing generated PDF/HTML without source code: Without code and raw data, findings cannot be audited.

15. Manually editing renv.lock: JSON syntax errors break renv. Always update via renv::snapshot().

16. Using relative paths without a project anchor: Scripts in subfolders like scripts/ fail to find data/.

17. Believing set.seed() guarantees cross-platform equality: Different OS/BLAS compilers can have micro-differences.

18. Committing .Rhistory and .RData: Clutters Git history with personal session dumps. Put in .gitignore.

19. Using incorrect package names in install: Package names are strictly case-sensitive in R.

20. Overwriting processed datasets without versioning: Prevents backtracking if transformations are flawed.

21. Forgetting to test renv::restore() on clean machine: Verifying lockfile validity is essential before sharing.

22. Confusing renv::snapshot() with renv::restore(): Snapshot saves state; restore loads state.

23. Using absolute URLs in web scraping without cache: If site structure changes, analysis becomes unreproducible.

24. Missing README setup instructions: New developers don't know the execution order (e.g., run main.R first).

25. Not checking packageVersion() when bugs arise: First debugging step for conflicting behavior.

26. Hardcoding dates and timestamps: Dynamic timestamps can alter deterministic test outcomes.

27. Failing to set echo/warning options in Quarto: Unchecked diagnostic messages clutter final client reports.

28. Writing functions that rely on global variables: Pass all required data as explicit function parameters.

29. Using proprietary file formats when open formats work: Prefer CSV, Parquet, or RDS over Excel.

30. Ignoring git status before committing: Accidentally staging sensitive data files or temporary dumps.

13. 22 Output Prediction Challenges

1. Code: set.seed(10); r1 <- sample(10, 2); set.seed(10); r2 <- sample(10, 2); identical(r1, r2)
Prediction: [1] TRUE (Identical seed yields identical pseudorandom outputs).

2. Code: file.exists("non_existent_folder/file.csv")
Prediction: [1] FALSE (Returns logical FALSE without crashing).

3. Code: is.character(packageVersion("base"))
Prediction: [1] FALSE (Returns a package_version S3 object, not character).

4. Code: as.character(packageVersion("base"))
Prediction: Returns the current R version string (e.g. "4.3.2").

5. Code: set.seed(42); s1 <- runif(1); s2 <- runif(1); s1 == s2
Prediction: [1] FALSE (The PRNG state advances between successive calls).

6. Code: requireNamespace("base", quietly = TRUE)
Prediction: [1] TRUE (base is always installed in R).

7. Code: "package:stats" %in% search()
Prediction: [1] TRUE (stats is attached by default upon R launch).

8. Code: Sys.getenv("DEFINITELY_NOT_AN_ENV_VAR")
Prediction: [1] "" (Returns an empty string for undefined environment variables).

9. Code: length(list.files(pattern = "\.xyz123$"))
Prediction: [1] 0 (No matching files returns length 0 character vector).

10. Code: typeof(here::here)
Prediction: [1] "closure" (Functions in R are of type closure).

11. Code: length(source(textConnection("x <- 10; y <- 20"))$value)
Prediction: [1] 1 (source evaluates code in memory; returns evaluation list).

12. Code: set.seed(1); sample(10, 1)
Prediction: [1] 3 (With Mersenne-Twister seed 1, sample(10,1) is exactly 3).

13. Code: is.vector(sessionInfo()$loadedOnly)
Prediction: [1] TRUE (Loaded packages form an informative named list/vector).

14. Code: normalizePath(".", winslash = "/") == getwd()
Prediction: [1] TRUE (Dot '.' represents current working directory).

15. Code: grepl("/", "data/raw/file.csv")
Prediction: [1] TRUE (Detects standard forward slashes in relative paths).

16. Code: set.seed(5); s <- sample(10, 5); length(unique(s)) == 5
Prediction: [1] TRUE (Default sample() draws without replacement).

17. Code: set.seed(5); sample(5, 10, replace = TRUE)
Prediction: Generates 10 numbers from 1 to 5 with repetition permitted.

18. Code: exists("calculate_summary")
Prediction: [1] FALSE (Unless defined or sourced from an external file).

19. Code: R.version$language
Prediction: [1] "R" (System metadata identifier).

20. Code: basename("data/raw/dataset.csv")
Prediction: [1] "dataset.csv" (Extracts filename without path).

21. Code: dirname("data/raw/dataset.csv")
Prediction: [1] "data/raw" (Extracts parent directory path).

22. Code: file.path("data", "raw", "file.csv")
Prediction: [1] "data/raw/file.csv" (Constructs cross-platform file path).
